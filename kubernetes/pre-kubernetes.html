What WSL actually is, why you need it for Kubernetes, and getting Docker Desktop connected to your Ubuntu distro.

1. What is WSL?
💬 WSL stands for Windows Subsystem for Linux.
It lets you run a Linux environment inside Windows, without installing a separate Linux operating system.

If you're setting up WSL for the first time, you normally need to install a Linux distribution too — most people go with Ubuntu. Think of the layers stacking on top of each other:

WSL2 ↓ Linux environment / technology ↓ Ubuntu ↓ Your Linux terminal

In your case, you already have this stack running:

Windows │ └── WSL2 │ └── Ubuntu 22.04

And your terminal output proves it:

uname -a
GNU/Linux 6.6.114.1-microsoft-standard-WSL2
2. First-Time Setup

On a fresh Windows machine, one command handles everything:

PowerShell (Admin)
wsl --install
✅ This typically installs:
  • WSL
  • WSL2
  • A default Linux distribution (usually Ubuntu)
3. Why Do You Need It For Kubernetes?

4. What Does the "2" Mean?

There are two major architectures:

1️⃣
WSL1
Translates Linux system calls to Windows — lighter but less compatible with some Linux tooling.
2️⃣
WSL2 (you're on this)
Runs a real, lightweight Linux kernel in a fast virtual machine — much better compatibility, this is the one you want.

Your kernel string confirms it:

confirmed
6.6.114.1-microsoft-standard-WSL2
5. WSL Is Not the Same as Docker
⚠️ This distinction matters — these four tools each do one specific job, and none of them substitute for another.
🐧
WSL2
Gives Windows a Linux environment / terminal.
🐳
Docker
Runs and manages containers.
☸️
kind
Creates a Kubernetes cluster (using Docker containers as "nodes").
🎛️
kubectl
Communicates with the Kubernetes cluster.

Put together, your full Kubernetes learning stack looks like this:

Windows │ └── WSL2 │ └── Ubuntu │ ├── kubectl ├── kind └── helm │ ▼ Kubernetes Cluster │ ▼ Pods │ ▼ Containers
👍 You already have the WSL + Ubuntu part done. Next: check Docker, because kind needs a container runtime to actually create your Kubernetes cluster.
Ubuntu (WSL2)
docker --version

The command 'docker' could not be found in this WSL 2 distro.
We recommend to activate the WSL integration in Docker Desktop settings.

For details about using Docker Desktop with WSL 2, visit:
https://docs.docker.com/go/wsl2/

That's expected. WSL2 and Docker are separate — you have WSL2 + Ubuntu, but Docker isn't currently connected to that distribution.

💡 Since you're on Windows, the easiest path is Docker Desktop + WSL2 integration — you do not need to install Docker Engine manually inside Ubuntu.
6. Connect Docker Desktop to Ubuntu
1

Check Docker Desktop is installed & running

Open the Windows Start Menu and search:

🔍 Docker Desktop

If it's installed, open it and wait until Docker reports it's running (green whale icon in the system tray, "Docker Desktop is running" status).

2

Enable WSL integration

In Docker Desktop, navigate to:

Settings → Resources → WSL Integration

You should see your Ubuntu distribution listed:

Enable integration with my default WSL distroON
Ubuntu-22.04ON

Turn Ubuntu ON, then click Apply & Restart.

3

Go back to your WSL terminal

You can stay in PowerShell and run:

PowerShell
wsl

root@LAPTOP-XXXXX:/mnt/c/Users/YourName#

Now verify Docker is reachable from inside Ubuntu:

Ubuntu (WSL2)
docker --version
Docker version 27.x.x, build xxxxxxx

docker ps
CONTAINER ID   IMAGE   COMMAND   CREATED   STATUS   PORTS   NAMES

Both commands should now work — Docker Desktop is sharing its engine with your Ubuntu distro over the WSL2 integration.

✅ Once docker ps runs cleanly inside Ubuntu, you're ready to move on to kind create cluster and start working with Kubernetes.
