How to handle errors in React: Wrap API and async calls in try...catch so failed requests update state instead of crashing the app. Do the same inside event handlers, since Error Boundaries never catch those. Validate form input with simple state checks before it reaches the UI. Use optional chaining (?.) or conditional checks to avoid accessing properties on null/undefined data. For actual rendering errors, wrap the component tree in an Error Boundary using the react-error-boundary library.

🌐 Handling API Errors
📡 Fetch with try...catch

One of the most common cases — wrap the fetch call and update state instead of letting the app crash.

Users.jsx
import { useEffect, useState } from "react";

function Users() {
    const [users, setUsers] = useState([]);
    const [error, setError] = useState("");

    useEffect(() => {
        async function fetchUsers() {
            try {
                const response = await fetch("/api/users");

                if (!response.ok) {
                    throw new Error("Unable to fetch users");
                }

                const data = await response.json();
                setUsers(data);
            } catch (err) {
                setError(err.message);
            }
        }
        fetchUsers();
    }, []);

    if (error) return <h2>{error}</h2>;

    return (
        <>
            {users.map(user => <p key={user.id}>{user.name}</p>)}
        </>
    );
}
💡 Output: "Unable to fetch users" is shown instead of crashing the UI.
🖱️ Event Handler Errors
⚡ Not Caught by Error Boundaries
⚠️ Errors thrown inside click handlers (or any event handler) are not caught by Error Boundaries. Always wrap them in try...catch.
Payment.jsx
function Payment() {
    const handlePayment = () => {
        try {
            processPayment();
        } catch (error) {
            alert("Payment Failed");
        }
    };

    return (
        <button onClick={handlePayment}>
            Pay Now
        </button>
    );
}

    .then(res => res.json())
    .then(data => console.log(data))

    });

Loading + Error Together

A common real-world pattern combines loading, error, and success states in one component.

Products.jsx
function Products() {
    const [products, setProducts] = useState([]);
    const [loading, setLoading] = useState(true);
    const [error, setError] = useState("");

    useEffect(() => {
        async function fetchProducts() {
            try {
                const response = await fetch("/api/products");
                if (!response.ok) throw new Error("Failed to fetch products");
                const data = await response.json();
                setProducts(data);
            } catch (err) {
                setError(err.message);
            } finally {
                setLoading(false);
            }
        }
        fetchProducts();
    }, []);

    if (loading) return <h2>Loading...</h2>;
    if (error) return <h2>{error}</h2>;

    return <>{products.map(p => <p key={p.id}>{p.name}</p>)}</>;
}
📝 Form Validation & Safe Rendering
✅ Validate Before It Breaks
Login.jsx
function Login() {
    const [email, setEmail] = useState("");
    const [error, setError] = useState("");

    const handleSubmit = () => {
        if (!email.includes("@")) {
            setError("Invalid Email");
            return;
        }
        setError("");
    };

    return (
        <>
            <input value={email} onChange={(e) => setEmail(e.target.value)} />
            <button onClick={handleSubmit}>Login</button>
            {error && <p>{error}</p>}
        </>
    );
}

Prevent Rendering Errors

Never access nested properties directly on data that might not exist yet.

❌ Bad: <h2>{user.name}</h2> — throws if user is null.
✅ Good: <h2>{user?.name}</h2> or {user && <h2>{user.name}</h2>}
🎨 Rendering Errors Need an Error Boundary
🚧 Catching Errors That Happen During Render
Rendering errors are different from API, async, or event errors — they can crash the whole component tree if left uncaught. The fix is to wrap the tree in an Error Boundary using the react-error-boundary library, which gives functional components a clean, hook-friendly way to catch and recover from these errors.
📦 Error Handling with React.lazy()
🐢 Suspense + Error Boundary

Suspense shows a loading UI while a lazy component downloads. If it fails to load or throws while rendering, the Error Boundary catches it.

App.jsx
import { lazy, Suspense } from "react";

const Dashboard = lazy(() => import("./Dashboard"));

function App() {
    return (
        <ErrorBoundary>
            <Suspense fallback={<h2>Loading...</h2>}>
                <Dashboard />
            </Suspense>
        </ErrorBoundary>
    );
}

Fallback Component

ErrorFallback.jsx
function ErrorFallback({ error, resetErrorBoundary }) {
    return (
        <div>
            <h2>Something went wrong.</h2>
            <p>{error.message}</p>
            <button onClick={resetErrorBoundary}>Try Again</button>
        </div>
    );
}

Wrap Your Component

App.jsx
import { ErrorBoundary } from "react-error-boundary";

function App() {
    return (
        <ErrorBoundary FallbackComponent={ErrorFallback}>
            <Dashboard />
        </ErrorBoundary>
    );
}

useErrorBoundary Hook

Forward asynchronous or event-handler errors to the nearest Error Boundary manually.

Product.jsx
import { useErrorBoundary } from "react-error-boundary";

function Product() {
    const { showBoundary } = useErrorBoundary();

    const loadData = async () => {
        try {
            await fetchProducts();
        } catch (error) {
            showBoundary(error);
        }
    };

    return <button onClick={loadData}>Load Products</button>;
}
✅ Best Practices
🏆 Keep Your App From Crashing
🌐 Handle API requests with try...catch.
🖱️ Wrap event handler logic in try...catch when failures are possible.
🚦 Show loading, success, and error states separately.
🛡️ Use optional chaining (?.) or conditional rendering to avoid runtime errors from null/undefined.
📝 Validate user input before processing it.
🧩 Use react-error-boundary for a functional-friendly Error Boundary API.
📊 Log errors to monitoring services (Sentry, LogRocket) instead of only showing them to users.
🎯 Key takeaway: Functional components can handle API, async, and event errors directly with try...catch — but rendering errors still need an Error Boundary, which react-error-boundary makes easy to add without leaving functional components.
