📦 What is Redux?
Redux — Centralized State Management
Redux is a state management library used to store global/shared state in one central place called the Store. Instead of passing data through multiple components using props, any component can directly read or update the Store.

Redux is most beneficial in medium-to-large applications where many components need access to the same state — avoiding deep prop drilling across the component tree.

🧰 Why Redux Toolkit (RTK)?
RTK — The Official, Recommended Way

Traditional Redux required writing lots of boilerplate code: Action Types, Action Creators, Reducers, Store Configuration, and Switch Statements. Redux Toolkit automatically handles most of this, making the code shorter, cleaner, and easier to maintain.

❌ Traditional Redux

Around 50–100 lines just to create one feature.

        case ADD_ITEM:
            ...
    }

✅ Redux Toolkit

Everything is created in one place.

cartSlice.js
const cartSlice = createSlice({
    name: "cart",
    initialState,
    reducers: {
        addItem(state, action) {
            state.items.push(action.payload);
        }
    }
});

Much simpler.

  • Better developer experience
💡 Rule of Thumb: In modern React projects, you should always prefer Redux Toolkit over traditional Redux.

Step 2: Create a Slice

A Slice contains: State, Reducers, and Actions.

features/cart/cartSlice.js
import { createSlice } from "@reduxjs/toolkit";

const initialState = {
    items: []
};

const cartSlice = createSlice({
    name: "cart",
    initialState,

    reducers: {
        addItem(state, action) {
            state.items.push(action.payload);
        },

        removeItem(state, action) {
            state.items = state.items.filter(
                item => item.id !== action.payload
            );
        }
    }
});

export const { addItem, removeItem } = cartSlice.actions;

export default cartSlice.reducer;
📝 What happened here? createSlice() creates the reducer and automatically creates addItem() and removeItem() action creators. No switch statement is needed, and no action types need to be written manually.
Step 3: Create the Store
app/store.js
import { configureStore } from "@reduxjs/toolkit";
import cartReducer from "../features/cart/cartSlice";

export const store = configureStore({
    reducer: {
        cart: cartReducer
    }
});

Step 4: Connect Redux to React
main.jsx
import ReactDOM from "react-dom/client";
import { Provider } from "react-redux";
import { store } from "./app/store";
import App from "./App";

ReactDOM.createRoot(document.getElementById("root")).render(
    <Provider store={store}>
        <App />
    </Provider>
);

Now every component can access the Redux Store.

Step 5: Update State using useDispatch()

Suppose the user clicks Add To Cart.

Product.jsx
import { useDispatch } from "react-redux";
import { addItem } from "../features/cart/cartSlice";

function Product() {

    const dispatch = useDispatch();

    const product = {
        id: 1,
        name: "Laptop"
    };

    return (
        <button
            onClick={() => dispatch(addItem(product))}
        >
            Add To Cart
        </button>
    );
}
Button Click │ ▼ dispatch(addItem(product)) │ ▼ Reducer executes │ ▼ state.items.push(product) │ ▼ Store updates

Store becomes:

store shape
{
    cart: {
        items: [
            {
                id: 1,
                name: "Laptop"
            }
        ]
    }
}
Step 6: Read State using useSelector()

Navbar wants to display the cart count.

Navbar.jsx
import { useSelector } from "react-redux";

function Navbar() {

    const items = useSelector(
        state => state.cart.items
    );

    return (
        <h2>
            Cart ({items.length})
        </h2>
    );
}

Initially: Cart (0) — after clicking Add To Cart: Cart (1). No props are required.

⏳ Redux Thunk (Behind the Scenes)
How Redux Toolkit Handles Async Operations
Redux reducers can only perform synchronous state updates, so they cannot make API calls, use setTimeout, or perform any asynchronous operations. To handle async tasks, Redux uses Redux Thunk, a middleware placed between dispatch() and the reducer.

When using Redux Toolkit, you do not need to install or configure redux-thunk separately because configureStore() automatically adds it as one of its default middleware.

store.js
const store = configureStore({
    reducer: {
        products: productReducer
    }
});

Internally, Redux Toolkit creates the store similar to this:

internal-behavior.js
configureStore({
    reducer,
    middleware: (getDefaultMiddleware) =>
        getDefaultMiddleware() // Includes Redux Thunk
});
📝 Note: Redux Thunk is already active, even though you never import or configure it yourself.

When you dispatch an asynchronous action (usually created using createAsyncThunk()), Redux Thunk intercepts it, executes the async code (such as an API call), waits for the response, and then dispatches normal Redux actions like pending, fulfilled, or rejected to the reducer.

Component │ dispatch(fetchProducts()) │ Redux Thunk Middleware │ API Call │ Success / Failure │ dispatch(fulfilled/rejected) │ Reducer │ Redux Store Updated
💡 Key Point: You write asynchronous logic using createAsyncThunk(), but it works because Redux Thunk is already included inside Redux Toolkit. In traditional Redux, you had to install redux-thunk manually and configure it with applyMiddleware(thunk), whereas Redux Toolkit handles that setup automatically behind the scenes.
