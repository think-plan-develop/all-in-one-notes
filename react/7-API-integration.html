📘 Theory
1. Fetch API

The fetch() function is built into the browser (no install needed) and returns a Promise that resolves to a Response object. A key gotcha: fetch does not reject on HTTP error status codes (like 404 or 500) — it only rejects on network failure. You must check response.ok yourself.

useUsers.js
function useUsers() {
  const [users, setUsers] = useState([]);

  useEffect(() => {
    fetch('https://api.example.com/users')
      .then(async (res) => {
        // fetch only rejects on network errors — check .ok manually
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        return res.json();
      })
      .then(setUsers)
      .catch((err) => console.error(err));
  }, []);

  return users;
}
⚠️ Common interview trap: "Does fetch reject on a 404?" — No. You must manually throw based on response.ok or response.status.
2. Axios

Axios is a popular HTTP client that wraps XMLHttpRequest/fetch with a friendlier API. Unlike fetch, it automatically parses JSON and rejects the promise on non-2xx status codes, so a simple .catch() handles HTTP errors too.

useUsersAxios.js
import axios from 'axios';

const api = axios.create({
  baseURL: 'https://api.example.com',
  timeout: 8000,
});

// interceptor: attach auth token to every request
api.interceptors.request.use((config) => {
  config.headers.Authorization = `Bearer ${token}`;
  return config;
});

useEffect(() => {
  api.get('/users')
    .then((res) => setUsers(res.data)) // already parsed JSON
    .catch((err) => setError(err.message));
}, []);
✅ Axios advantages
  • Auto JSON parsing
  • Interceptors (auth, logging)
  • Rejects on HTTP error automatically
  • Built-in cancel tokens / AbortController support
❌ Fetch advantages
  • No extra dependency / bundle size
  • Native streaming support
  • Simpler for basic use cases
3. Loading State

Every async request needs a way to represent "in progress" so the UI can show a spinner or skeleton instead of a blank/stale screen. The most robust pattern uses a single status enum rather than multiple booleans, which avoids impossible states like loading: true and error: true at the same time.

useFetch.js
function useFetch(url) {
  const [state, setState] = useState({
    status: 'idle', // 'idle' | 'loading' | 'success' | 'error'
    data: null,
    error: null,
  });

  useEffect(() => {
    setState({ status: 'loading', data: null, error: null });
    fetch(url)
      .then((res) => res.json())
      .then((data) => setState({ status: 'success', data, error: null }))
      .catch((error) => setState({ status: 'error', data: null, error }));
  }, [url]);

  return state;
}
💡 Tip: with React 19 / Suspense-enabled data fetching, loading states can be handled declaratively via <Suspense fallback={...}> instead of manual booleans.
4. Error Handling

Good error handling covers three layers: network failures (offline, DNS, CORS), HTTP errors (4xx/5xx status codes), and rendering errors once the response is used in the UI (caught by an Error Boundary).

ErrorBoundary.jsx
class ErrorBoundary extends React.Component {
  state = { hasError: false };

  static getDerivedStateFromError() {
    return { hasError: true };
  }

  componentDidCatch(error, info) {
    logErrorToService(error, info);
  }

  render() {
    if (this.state.hasError) return <p>Something went wrong.</p>;
    return this.props.children;
  }
}

5. AbortController

AbortController lets you cancel a fetch request that's no longer needed — for example when a component unmounts, or when a new search query supersedes the previous one (avoids the classic race condition bug where an older, slower response overwrites a newer one).

useSearch.js
useEffect(() => {
  const controller = new AbortController();

  fetch(`/api/search?q=${query}`, { signal: controller.signal })
    .then((res) => res.json())
    .then(setResults)
    .catch((err) => {
      if (err.name === 'AbortError') return; // expected — ignore
      setError(err);
    });

  // cleanup: cancel the request if query changes or component unmounts
  return () => controller.abort();
}, [query]);
📌 With axios, pass { signal: controller.signal } in the config too — same native AbortController works for both.
6. Promise.all

Promise.all() runs multiple requests in parallel instead of sequentially with await one after another — much faster when the requests are independent. It rejects immediately if any promise rejects. Use Promise.allSettled() instead if you want all results regardless of individual failures.

useDashboard.js
useEffect(() => {
  async function loadDashboard() {
    try {
      const [userRes, ordersRes, statsRes] = await Promise.all([
        fetch('/api/user'),
        fetch('/api/orders'),
        fetch('/api/stats'),
      ]);
      const [user, orders, stats] = await Promise.all(
        [userRes, ordersRes, statsRes].map((r) => r.json())
      );
      setData({ user, orders, stats });
    } catch (err) {
      // if ANY request fails, we land here
      setError(err);
    }
  }
  loadDashboard();
}, []);
Promise.all
  • Fails fast on first rejection
  • Cleaner when all-or-nothing is correct
Promise.allSettled
  • Always resolves
  • Returns per-item status/value/reason
7. Pagination

Pagination fetches data in fixed-size chunks (pages) using query params like ?page=2&limit=20, so the UI stays fast and the server doesn't return huge payloads. State needed: current page, total pages/count, and the current page's data.

usePagination.js
function useUsersPage(page, limit = 10) {
  const [data, setData] = useState({ items: [], total: 0 });
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    setLoading(true);
    fetch(`/api/users?page=${page}&limit=${limit}`)
      .then((res) => res.json())
      .then((res) => setData({ items: res.data, total: res.total }))
      .finally(() => setLoading(false));
  }, [page, limit]);

  const totalPages = Math.ceil(data.total / limit);
  return { ...data, loading, totalPages };
}
📌 Two common styles: offset-based (page/limit — simple, but can skip/duplicate rows if data changes) vs cursor-based (after=lastId — more stable for real-time feeds, used by Twitter/GitHub APIs).
8. Infinite Scroll

Infinite scroll loads the next page automatically as the user nears the bottom of the list, appending results instead of replacing them. The most efficient trigger uses IntersectionObserver on a sentinel element rather than listening to scroll events (which fire constantly and hurt performance).

useInfiniteScroll.js
function useInfiniteScroll(fetchPage) {
  const [items, setItems] = useState([]);
  const [page, setPage] = useState(1);
  const [hasMore, setHasMore] = useState(true);
  const sentinelRef = useRef(null);

  useEffect(() => {
    const observer = new IntersectionObserver(([entry]) => {
      if (entry.isIntersecting && hasMore) {
        setPage((p) => p + 1);
      }
    });
    if (sentinelRef.current) observer.observe(sentinelRef.current);
    return () => observer.disconnect();
  }, [hasMore]);

  useEffect(() => {
    fetchPage(page).then((newItems) => {
      setItems((prev) => [...prev, ...newItems]);
      setHasMore(newItems.length > 0);
    });
  }, [page]);

  return { items, sentinelRef, hasMore };
}
✅ Interview soundbite: "Infinite scroll = pagination + IntersectionObserver + appending instead of replacing state."
💻 Coding — CRUD App
9. Full CRUD App (Create · Read · Update · Delete)

A common live-coding exercise: build a small app against a REST API (e.g. JSONPlaceholder or your own backend) that lists items, adds a new one, edits one inline, and deletes one — with loading/error state and an AbortController cleanup.

TodoApp.jsx
import { useState, useEffect } from 'react';

const API = 'https://jsonplaceholder.typicode.com/todos';

export default function TodoApp() {
  const [todos, setTodos] = useState([]);
  const [title, setTitle] = useState('');
  const [status, setStatus] = useState('idle');
  const [error, setError] = useState(null);

  // READ — load todos once, cancel on unmount
  useEffect(() => {
    const controller = new AbortController();
    setStatus('loading');
    fetch(`${API}?_limit=10`, { signal: controller.signal })
      .then((res) => {
        if (!res.ok) throw new Error('Failed to load todos');
        return res.json();
      })
      .then((data) => { setTodos(data); setStatus('success'); })
      .catch((err) => {
        if (err.name !== 'AbortError') { setError(err.message); setStatus('error'); }
      });
    return () => controller.abort();
  }, []);

  // CREATE
  const addTodo = async (e) => {
    e.preventDefault();
    if (!title.trim()) return;
    const res = await fetch(API, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ title, completed: false }),
    });
    const newTodo = await res.json();
    setTodos((prev) => [{ ...newTodo, id: Date.now() }, ...prev]);
    setTitle('');
  };

  // UPDATE — toggle completed
  const toggleTodo = async (todo) => {
    const updated = { ...todo, completed: !todo.completed };
    setTodos((prev) => prev.map((t) => (t.id === todo.id ? updated : t))); // optimistic update
    await fetch(`${API}/${todo.id}`, {
      method: 'PATCH',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ completed: updated.completed }),
    });
  };

  // DELETE
  const deleteTodo = async (id) => {
    setTodos((prev) => prev.filter((t) => t.id !== id)); // optimistic remove
    await fetch(`${API}/${id}`, { method: 'DELETE' });
  };

  if (status === 'loading') return <p>Loading todos…</p>;
  if (status === 'error')   return <p>Error: {error}</p>;

  return (
    <div>
      <form onSubmit={addTodo}>
        <input value={title} onChange={(e) => setTitle(e.target.value)} />
        <button type="submit">Add</button>
      </form>
      <ul>
        {todos.map((todo) => (
          <li key={todo.id}>
            <input
              type="checkbox"
              checked={todo.completed}
              onChange={() => toggleTodo(todo)}
            />
            {todo.title}
            <button onClick={() => deleteTodo(todo.id)}>Delete</button>
          </li>
        ))}
      </ul>
    </div>
  );
}
✅ Notice the pattern: optimistic updates for toggle/delete (update UI immediately, don't wait for the response) — a strong signal of senior-level React knowledge in interviews.
❓ Rapid-Fire Q&A
Quick Recall

Q: Does fetch() reject on a 404 response?

A: No — only on network failure. You must check response.ok and throw manually.

Q: Why use AbortController inside useEffect?

A: To cancel a stale request on unmount or dependency change, preventing race conditions and "set state on unmounted component" warnings.

Q: Promise.all vs Promise.allSettled?

A: Promise.all rejects as soon as one promise rejects; Promise.allSettled always resolves with the status of every promise, succeeded or failed.

Q: Offset pagination vs cursor pagination?

A: Offset (page/limit) is simple but can skip or duplicate items if the underlying data changes; cursor-based (using a stable pointer like last ID) stays consistent for frequently changing lists.

Q: What triggers infinite scroll efficiently?

A: An IntersectionObserver watching a sentinel element at the bottom of the list, instead of a scroll event listener.
