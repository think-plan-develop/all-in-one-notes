📘 What is Context API?
Context API — Built-in Global State Sharing
Context API is a built-in React feature used to share data between multiple components without passing props manually through every level (avoiding prop drilling).

It is mainly used to manage global or shared state such as:

  • Logged-in User
  • Theme (Light/Dark)
  • Language
  • Authentication
  • Notifications
📝 Note: Context API is built into React, so no external library is required.
Why Context API?

Suppose an application has the following component hierarchy:

App │ ├── Header │ ├── Dashboard │ │ │ ├── Sidebar │ │ │ │ │ └── UserProfile │ │ │ └── Content

The logged-in user's data is stored in App, but UserProfile needs it. Without Context API, the data must be passed through every intermediate component:

prop-drilling.jsx
<App user={user}>
    <Dashboard user={user}>
        <Sidebar user={user}>
            <UserProfile user={user} />
        </Sidebar>
    </Dashboard>
</App>

This is called Prop Drilling.

With Context API:

User Context ------------------ name : Shivam role : Admin ------------------ ↑ ↑ Header UserProfile

Any component can directly access the shared data.

⚙️ How Context API Works
Three Core Pieces

Context API mainly consists of three parts:

  • createContext() — Creates a Context object
  • Provider — Provides the data to all child components
  • useContext() — Reads the data from the Context
createContext() │ ▼ Provider │ ▼ Stores Shared Data │ ▼ useContext() │ ▼ Component Reads Data
Step 1: Create Context

Create a file named UserContext.js.

UserContext.js
import { createContext } from "react";

const UserContext = createContext();

export default UserContext;

Here, createContext() creates a Context object that will hold the shared data.

Step 2: Provide the Context

Wrap the application (or the required part) with the Provider.

App.jsx
import UserContext from "./UserContext";
import Dashboard from "./Dashboard";

function App() {

    const user = {
        name: "Shivam",
        role: "Admin"
    };

    return (
        <UserContext.Provider value={user}>
            <Dashboard />
        </UserContext.Provider>
    );
}

export default App;

The value prop contains the data that will be shared with child components.

Step 3: Consume the Context

Any child component can access the data using useContext().

UserProfile.jsx
import { useContext } from "react";
import UserContext from "./UserContext";

function UserProfile() {

    const user = useContext(UserContext);

    return (
        <>
            <h2>{user.name}</h2>
            <p>{user.role}</p>
        </>
    );
}

💡 Remember: No props are passed through intermediate components.
⚖️ Context API vs Redux Toolkit
Choosing the Right Tool

Both Context API and Redux Toolkit are used to share data between multiple React components, but they are designed for different use cases.

🔗 Context API
  • Best for sharing simple global data
  • Avoiding prop drilling
  • Built into React — no setup
🧰 Redux Toolkit
  • Best for complex application state
  • Better scalability and performance
  • Requires external library
FeatureContext APIRedux Toolkit

⚡ Most Important Difference (Performance)
Re-render Behavior Compared

This is the biggest difference between Context API and Redux Toolkit.

Suppose Context stores:

context-shape.js
{
    user,
    theme,
    language
}

Components:

ComponentUses
Headertheme
Profileuser
Footerlanguage

If only the theme changes:

action.js
setTheme("dark");

❌ Context API

Header ✅ Re-render  •  Profile ❌ Re-render  •  Footer ❌ Re-render

All components consuming the Context re-render because the Context value changed.

✅ Redux Toolkit

selector.js
const theme = useSelector(state => state.theme);

If only theme changes:

Header ✅ Re-render  •  Profile ❌ No Re-render  •  Footer ❌ No Re-render

Redux updates only the components that are subscribed to the changed state, making it more efficient for large applications.
⏳ Async Operations
Handling API Calls, File Uploads, Timers

Another major difference is handling asynchronous operations such as: API Calls, File Uploads, Timers (setTimeout), and Database Requests.

❌ Context API

Context API has no built-in support for asynchronous state management. You need to write the async logic manually using hooks like useEffect() and then update the state.

FetchUsers.jsx
useEffect(() => {
    async function fetchUsers() {
        const response = await fetch("/api/users");
        setUsers(await response.json());
    }

    fetchUsers();
}, []);

✅ Redux Toolkit

Redux Toolkit provides createAsyncThunk(), which is built on top of Redux Thunk. It automatically handles the complete lifecycle of an asynchronous request.

usersSlice.js
export const fetchUsers = createAsyncThunk(
    "users/fetchUsers",
    async () => {
        const response = await fetch("/api/users");
        return await response.json();
    }
);

When dispatched:

component.jsx
dispatch(fetchUsers());

Redux Toolkit automatically dispatches these actions:

fetchUsers.pending ↓ API Call ↓ fetchUsers.fulfilled or fetchUsers.rejected
💡 Remember: This makes loading, success, and error handling much easier compared to managing everything manually in Context API.
🎯 Which One Should You Choose?
Decision Guide
🔗 Use Context API
  • Simple shared state like Theme
  • Language preferences
  • User or Authentication data
🧰 Use Redux Toolkit
  • Complex applications with frequent state updates
  • API calls and middleware
  • Advanced debugging needs
🎯 Rule of Thumb: Context API = Simple Global State  •  Redux Toolkit = Complex Global State + Async
