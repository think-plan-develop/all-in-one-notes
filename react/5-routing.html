Routing Overview
What is React Router?
React Router is the standard client-side routing library for React SPAs. It enables navigation between different views/pages without full page reloads, using the browser's History API to change the URL.

Installation

npm install react-router-dom

BrowserRouter
BrowserRouter — The Router Provider
<BrowserRouter> wraps your entire application and enables React Router. It uses the HTML5 History API (pushState, replaceState) to keep the URL in sync with the UI without page reloads.
main.jsx
import { BrowserRouter } from 'react-router-dom';
import App from './App';

createRoot(document.getElementById('root')).render(
  <BrowserRouter>
    <App />
  </BrowserRouter>
);

Routes & Route
Routes & Route — Defining Pages
<Routes> is a container that looks at the current URL and renders the matching <Route>. Each Route maps a path to a component via the element prop.
App.jsx
import { Routes, Route } from 'react-router-dom';
import Home from './pages/Home';
import About from './pages/About';
import Products from './pages/Products';
import NotFound from './pages/NotFound';

function App() {
  return (
    <Routes>
      <Route path="/" element={<Home />} />
      <Route path="/about" element={<About />} />
      <Route path="/products" element={<Products />} />
      <Route path="*" element={<NotFound />} />  {/* 404 catch-all */}
    </Routes>
  );
}

Link & NavLink
Link — Navigation Without Reload
<Link> renders an <a> tag that navigates to a new route without triggering a full page reload. It uses the History API to update the URL and let React Router render the matching component.
Navbar.jsx
import { Link } from 'react-router-dom';

function Navbar() {
  return (
    <nav>
      <Link to="/">Home</Link>
      <Link to="/about">About</Link>
      <Link to="/products">Products</Link>
      <Link to="/contact" state={{ from: 'navbar' }}>Contact</Link>
    </nav>
  );
}

// ❌ DON'T use <a href="/about"> — causes full page reload!
// ✅ USE <Link to="/about"> — client-side navigation
⚠️ Never use <a href="..."> for internal navigation! It triggers a full page reload, losing all React state, Redux store, and re-fetching everything. Use <Link> for internal routes and <a> only for external URLs.
NavLink — Link with Active Styling
<NavLink> is just like <Link> but automatically adds an active class (or custom styling) when the current URL matches the link's to prop. Perfect for navigation menus.
Sidebar.jsx
import { NavLink } from 'react-router-dom';

function Sidebar() {
  return (
    <nav className="sidebar">
      {/* Method 1: className function */}
      <NavLink
        to="/"
        className={({ isActive }) =>
          isActive ? 'nav-link active' : 'nav-link'
        }
      >
        Home
      </NavLink>

      {/* Method 2: style function */}
      <NavLink
        to="/dashboard"
        style={({ isActive }) => ({
          color: isActive ? '#2563eb' : '#64748b',
          fontWeight: isActive ? 'bold' : 'normal',
          borderLeft: isActive ? '3px solid #2563eb' : 'none'
        })}
      >
        Dashboard
      </NavLink>

      {/* Method 3: end prop — exact match only */}
      <NavLink to="/products" end>All Products</NavLink>
      <NavLink to="/products/new">Add Product</NavLink>
    </nav>
  );
}

useNavigate
useNavigate — Programmatic Navigation
useNavigate() returns a function that lets you navigate programmatically — after form submission, after login, on button click, or conditionally in code. It replaces useHistory() from React Router v5.
const navigate = useNavigate();
LoginPage.jsx
import { useNavigate } from 'react-router-dom';

function LoginPage() {
  const navigate = useNavigate();

  const handleLogin = async (e) => {
    e.preventDefault();
    const success = await loginUser(email, password);

    if (success) {
      // Navigate to dashboard after successful login
      navigate('/dashboard');

      // OR replace history (can't go back to login)
      navigate('/dashboard', { replace: true });
    }
  };

  return (
    <form onSubmit={handleLogin}>
      {/* form fields */}
      <button type="submit">Login</button>
    </form>
  );
}

Declarative Redirect: <Navigate>

ProtectedRoute.jsx (preview — full version below)
import { Navigate } from 'react-router-dom';

// Redirect unauthenticated users
function ProtectedRoute({ children }) {
  const { isAuthenticated } = useAuth();

  if (!isAuthenticated) {
    // Declarative redirect — renders Navigate component
    return <Navigate to="/login" replace />;
  }

  return children;
}
📝 useNavigate vs Navigate: Use useNavigate() for programmatic navigation (in event handlers, after async operations). Use <Navigate> for declarative redirects (in JSX render logic, like auth guards). The full auth-aware version of ProtectedRoute is built out in the Protected Routes section below.
URL Parameters
URL Parameters — Dynamic Routes
URL Parameters (dynamic segments) let you create routes like /users/:id where :id can be any value. Access them with the useParams() hook inside the rendered component.
App.jsx + ProductDetail.jsx
// Route definition with :id parameter
<Routes>
  <Route path="/products" element={<ProductList />} />
  <Route path="/products/:productId" element={<ProductDetail />} />
  <Route path="/users/:userId/posts/:postId" element={<UserPost />} />
</Routes>

// ─────────────────────────────────────────────────
// Access params with useParams()
import { useParams } from 'react-router-dom';

function ProductDetail() {
  const { productId } = useParams();  // "42" from /products/42
  const [product, setProduct] = useState(null);

  useEffect(() => {
    fetch(`/api/products/${productId}`)
      .then(res => res.json())
      .then(data => setProduct(data));
  }, [productId]); // re-fetch when param changes

  if (!product) return <p>Loading...</p>;
  return <h1>{product.name} — ₹{product.price}</h1>;
}

Query Parameters (Search Params)

SearchPage.jsx
import { useSearchParams } from 'react-router-dom';

// URL: /search?q=laptop&category=electronics&page=2
function SearchPage() {
  const [searchParams, setSearchParams] = useSearchParams();

  // Read params
  const query = searchParams.get('q');         // "laptop"
  const category = searchParams.get('category'); // "electronics"
  const page = searchParams.get('page') || '1';  // "2"

  // Update params (updates URL without reload)
  const handlePageChange = (newPage) => {
    setSearchParams({ q: query, category, page: newPage });
  };

  return (
    <div>
      <p>Results for: {query} in {category}</p>
      <button onClick={() => handlePageChange(Number(page) + 1)}>
        Next Page
      </button>
    </div>
  );
}

Nested Routes
Nested Routes — Shared Layouts
Nested Routes let you create shared layouts where a parent route renders a persistent layout (header, sidebar) and child routes render inside it using the <Outlet> component. This is how you build dashboard layouts, settings pages, etc.
URL: /dashboard/analytics ┌─────────────────────────────────────────────┐ │ <DashboardLayout> (parent route) │ │ ┌───────┬────────────────────────────────┐ │ │ │ │ │ │ │ │ Side │ <Outlet /> │ │ │ │ bar │ ↓ │ │ │ │ │ Renders <Analytics /> │ │ │ │ • Home│ (child route) │ │ │ │ • Anal│ │ │ │ │ • Set │ │ │ │ │ │ │ │ │ └───────┴────────────────────────────────┘ │ └─────────────────────────────────────────────┘
App.jsx — Nested Route Definition
import { Routes, Route } from 'react-router-dom';

function App() {
  return (
    <Routes>
      <Route path="/" element={<Home />} />
      <Route path="/login" element={<Login />} />

      {/* Nested Routes — DashboardLayout wraps all children */}
      <Route path="/dashboard" element={<DashboardLayout />}>
        <Route index element={<DashboardHome />} />        {/* /dashboard */}
        <Route path="analytics" element={<Analytics />} />  {/* /dashboard/analytics */}
        <Route path="users" element={<Users />} />        {/* /dashboard/users */}
        <Route path="users/:id" element={<UserDetail />} /> {/* /dashboard/users/42 */}
        <Route path="settings" element={<Settings />} />  {/* /dashboard/settings */}
      </Route>

      <Route path="*" element={<NotFound />} />
    </Routes>
  );
}

Sharing Data with Nested Children — useOutletContext

Sometimes a child route needs data the parent layout already fetched (e.g. the logged-in user, a shared filter). Instead of prop-drilling, pass it through <Outlet context={...}> and read it in the child with useOutletContext().

DashboardLayout.jsx + Analytics.jsx
// Parent layout provides context to whatever child renders
function DashboardLayout() {
  const { user } = useAuth();
  return (
    <div>
      <Sidebar />
      <Outlet context={{ user }} />
    </div>
  );
}

// Child reads it without any prop being passed manually
import { useOutletContext } from 'react-router-dom';

function Analytics() {
  const { user } = useOutletContext();
  return <p>Analytics for {user.name}</p>;
}
💡 Remember: Child route paths are relative — no leading slash! path="analytics" (not "/analytics") automatically becomes /dashboard/analytics because the parent is /dashboard.
Authentication
Authentication Context — useAuth
Authentication state (current user, token, login/logout functions) is usually stored in a Context Provider near the top of the app, so route guards and any page can read "is this user logged in?" without prop drilling.
AuthContext.jsx
import { createContext, useContext, useState, useEffect } from 'react';

const AuthContext = createContext(null);

export function AuthProvider({ children }) {
  const [user, setUser] = useState(null);
  const [isLoading, setIsLoading] = useState(true); // checking existing session

  // On first load, check if a token already exists and restore the session
  useEffect(() => {
    const token = localStorage.getItem('token');
    if (!token) { setIsLoading(false); return; }

    fetch('/api/me', { headers: { Authorization: `Bearer ${token}` } })
      .then((res) => (res.ok ? res.json() : null))
      .then(setUser)
      .finally(() => setIsLoading(false));
  }, []);

  const login = async (credentials) => {
    const res = await fetch('/api/login', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(credentials),
    });
    if (!res.ok) throw new Error('Invalid credentials');
    const data = await res.json();
    localStorage.setItem('token', data.token);
    setUser(data.user);
  };

  const logout = () => {
    localStorage.removeItem('token');
    setUser(null);
  };

  return (
    <AuthContext.Provider value={{ user, isLoading, login, logout }}>
      {children}
    </AuthContext.Provider>
  );
}

export const useAuth = () => useContext(AuthContext);
main.jsx — wiring the provider in
<BrowserRouter>
  <AuthProvider>
    <App />
  </AuthProvider>
</BrowserRouter>
⚠️ localStorage token caveat: Storing a raw JWT in localStorage is common and simple, but it's readable by any script on the page, so it's exposed to XSS. Higher-security apps prefer an httpOnly cookie set by the server, which JavaScript can't read at all.
📝 Why track isLoading separately from user? On page refresh, there's a brief moment where you don't yet know if the user is logged in (the /api/me call hasn't returned). If a guard checks user === null during that window, it'll incorrectly redirect to login. Always gate redirects on isLoading finishing first — see the Protected Route section below.
Protected Routes
ProtectedRoute — Guarding Authenticated Pages
A Protected Route checks auth state before rendering a route's content. If the user isn't logged in, it redirects to /login — and remembers where they were trying to go, using location state, so it can send them back after they log in.
ProtectedRoute.jsx
import { Navigate, Outlet, useLocation } from 'react-router-dom';
import { useAuth } from './AuthContext';

function ProtectedRoute({ allowedRoles }) {
  const { user, isLoading } = useAuth();
  const location = useLocation();

  if (isLoading) {
    // still checking for an existing session — don't redirect yet
    return <p>Checking session…</p>;
  }

  if (!user) {
    // not logged in — send to login, remember where they came from
    return <Navigate to="/login" state={{ from: location }} replace />;
  }

  if (allowedRoles && !allowedRoles.includes(user.role)) {
    // logged in, but wrong role — role-based guard
    return <Navigate to="/unauthorized" replace />;
  }

  return <Outlet />; // authorized — render the matched nested route
}
App.jsx — wiring it up
<Routes>
  <Route path="/login" element={<Login />} />

  {/* everything nested inside here requires login */}
  <Route element={<ProtectedRoute />}>
    <Route path="/dashboard" element={<DashboardLayout />}>
      <Route index element={<DashboardHome />} />
      <Route path="orders" element={<Orders />} />
    </Route>
  </Route>

  {/* admin-only nested guard, stacked role check */}
  <Route element={<ProtectedRoute allowedRoles={['admin']} />}>
    <Route path="/admin" element={<AdminPanel />} />
  </Route>
</Routes>
💡 Tip: Notice the guard is just another route rendering <Outlet /> — the same nested-routing mechanism used for layouts is reused here to gate access instead of sharing UI.

Redirecting Back After Login

When ProtectedRoute redirects to /login, it passes the original location in state.from. The login page reads that and sends the user back where they wanted to go.

Login.jsx
import { useNavigate, useLocation } from 'react-router-dom';
import { useAuth } from './AuthContext';

function Login() {
  const { login } = useAuth();
  const navigate = useNavigate();
  const location = useLocation();
  const from = location.state?.from?.pathname || '/dashboard';

  const handleSubmit = async (e) => {
    e.preventDefault();
    await login({ email, password });
    navigate(from, { replace: true }); // back to where they wanted to go
  };

  return <form onSubmit={handleSubmit}>{/* email/password inputs */}</form>;
}

GuestOnly — Keep Logged-In Users off Login/Register

The mirror-image guard: if a user is already logged in, visiting /login or /register should bounce them to the dashboard instead.

GuestOnly.jsx
import { Navigate, Outlet } from 'react-router-dom';
import { useAuth } from './AuthContext';

function GuestOnly() {
  const { user, isLoading } = useAuth();
  if (isLoading) return null;
  if (user) return <Navigate to="/dashboard" replace />;
  return <Outlet />;
}

// usage:
<Route element={<GuestOnly />}>
  <Route path="/login" element={<Login />} />
  <Route path="/register" element={<Register />} />
</Route>

Full E-Commerce Routing Setup (Lazy Loading + Auth Guards)

App.jsx — Full Routing Setup
import { Routes, Route, Navigate } from 'react-router-dom';
import { lazy, Suspense } from 'react';

// Lazy-loaded pages (code splitting)
const Home = lazy(() => import('./pages/Home'));
const Products = lazy(() => import('./pages/Products'));
const ProductDetail = lazy(() => import('./pages/ProductDetail'));
const Cart = lazy(() => import('./pages/Cart'));
const Dashboard = lazy(() => import('./pages/Dashboard'));

function App() {
  return (
    <Suspense fallback={<LoadingSpinner />}>
      <Routes>
        {/* Public Routes */}
        <Route path="/" element={<MainLayout />}>
          <Route index element={<Home />} />
          <Route path="products" element={<Products />} />
          <Route path="products/:id" element={<ProductDetail />} />
          <Route path="cart" element={<Cart />} />
          <Route path="about" element={<About />} />
        </Route>

        {/* Guest-only Routes (redirect if already logged in) */}
        <Route element={<GuestOnly />}>
          <Route path="/login" element={<Login />} />
          <Route path="/register" element={<Register />} />
        </Route>

        {/* Protected Routes (requires login) */}
        <Route element={<ProtectedRoute />}>
          <Route path="/dashboard" element={<DashboardLayout />}>
            <Route index element={<Dashboard />} />
            <Route path="orders" element={<Orders />} />
            <Route path="orders/:orderId" element={<OrderDetail />} />
            <Route path="settings" element={<SettingsLayout />}>
              <Route index element={<Navigate to="profile" replace />} />
              <Route path="profile" element={<ProfileSettings />} />
              <Route path="security" element={<SecuritySettings />} />
            </Route>
          </Route>
        </Route>

        {/* Admin-only Routes (role-based) */}
        <Route element={<ProtectedRoute allowedRoles={['admin']} />}>
          <Route path="/admin" element={<AdminPanel />} />
        </Route>

        {/* 404 */}
        <Route path="*" element={<NotFound />} />
      </Routes>
    </Suspense>
  );
}
💡 Production Patterns Used:
• Lazy loading: Each page loaded only when needed (code splitting)
• Protected routes: Auth guard redirects to login, remembers destination
• Guest-only routes: Login/Register redirect to dashboard if already logged in
• Role-based guard: Admin panel requires role === 'admin'
• Nested layouts: MainLayout (header/footer), DashboardLayout (sidebar), SettingsLayout (tabs)
• Index redirect: /dashboard/settings → auto-redirects to /dashboard/settings/profile
Interview Q&A
Routing Interview Questions
Q: What is React Router and why is it needed?
A: React Router is a client-side routing library for React SPAs. It's needed because React itself has no built-in routing. It enables: (1) Navigation between views without page reload, (2) URL synchronization with UI state, (3) Browser back/forward button support, (4) Deep linking (shareable URLs), (5) Nested layouts with shared UI elements.
Q: What is the difference between Link and NavLink?
A: Both navigate without page reload. <Link> is a basic navigation component. <NavLink> adds automatic active styling — it applies an active class (or custom className/style) when the current URL matches its to prop. Use NavLink for navigation menus/sidebars, Link for inline links.
Q: What's the difference between useParams and useSearchParams?
A: useParams() reads path parameters defined with :param in the route (e.g., /users/:id → {id: "42"}). These are required — the route won't match without them. useSearchParams() reads query string parameters (e.g., ?page=2&sort=name). These are optional and don't affect route matching.
Q: What are nested routes and how does Outlet work?
A: Nested routes let you define child routes inside a parent route. The parent renders a shared layout (header, sidebar), and <Outlet /> is a placeholder where the matched child route's component renders. This creates persistent layouts — the sidebar stays while inner content changes. Child paths are relative to the parent path.
Q: What is the difference between useNavigate and Navigate component?
A: useNavigate() is a hook that returns a function for programmatic navigation — used in event handlers, after async operations (login, form submit). <Navigate> is a declarative component that redirects when rendered — used in JSX for conditional redirects (auth guards, default routes). Both achieve the same result, different usage patterns.
Q: How do you implement lazy loading with React Router?
A: Use React.lazy() for dynamic imports and <Suspense> for loading state: const Page = lazy(() => import('./Page')). Wrap Routes with <Suspense fallback={<Spinner/>}>. This enables code splitting — each page's JS loads only when the user navigates to it, reducing initial bundle size significantly.
Q: How do you handle 404 pages in React Router?
A: Add a catch-all route at the end of your Routes: <Route path="*" element={<NotFound />} />. The * wildcard matches any URL that doesn't match previous routes. Place it last because Routes matches top-to-bottom. You can also add catch-all routes inside nested layouts for section-specific 404 pages.
Authentication & Protected Route Interview Questions
Q: How do you implement a protected route in React Router v6?
A: Create a guard component that reads auth state and returns <Outlet /> when authorized, or <Navigate to="/login" /> when not. Wrap it around the protected routes as a parent route: <Route element={<ProtectedRoute />}>...protected children...</Route>. This is the same nested-routing/Outlet mechanism used for layouts, repurposed as a gate.
Q: Where should authentication state live?
A: In a Context Provider (e.g. AuthProvider using createContext) wrapping the app, or in a global state library. This lets both pages and route guards read user without prop drilling, and centralizes login/logout logic in one place.
Q: How do you send a user back to the page they wanted after login?
A: When ProtectedRoute redirects, pass the current location as state: <Navigate to="/login" state={{ from: location }} />. On the login page, read location.state?.from?.pathname and call navigate(from, { replace: true }) after a successful login.
Q: Why check a loading flag before redirecting in a protected route?
A: On page refresh, the app doesn't yet know if a session exists until an async check (e.g. GET /api/me) resolves. If the guard redirects the instant user is null, it will incorrectly bounce a logged-in user to login during that brief window. Track an isLoading flag and wait for it to finish before deciding.
Q: How do you build role-based access control (e.g. admin-only routes)?
A: Extend the protected route guard to accept an allowedRoles prop. After confirming the user is logged in, check allowedRoles.includes(user.role); if it fails, redirect to an "/unauthorized" page instead of "/login" (the user is authenticated, just not authorized for this resource).
Q: What is a "guest-only" route and why is it needed?
A: It's the inverse guard — it redirects an already-logged-in user away from pages like /login or /register (usually to /dashboard), preventing a logged-in user from seeing the login form again.
Q: Is storing a JWT in localStorage safe?
A: It's common and simple, but any JavaScript on the page (including from an XSS vulnerability) can read it. Higher-security apps prefer an httpOnly, secure cookie set by the server, which client-side JS can't access, paired with CSRF protection.
