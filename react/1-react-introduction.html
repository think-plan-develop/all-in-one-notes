1. What is React?
Definition
React is an open-source, front-end JavaScript library created by Facebook (Meta) in 2013 for building fast, interactive user interfaces (UIs) using reusable components.

React is not a full framework — it focuses only on the View layer (the "V" in MVC). It lets you build encapsulated components that manage their own state, then compose them to create complex UIs.

  • Declarative: Design simple views for each state, React updates the DOM efficiently

  • Huge Ecosystem: Thousands of libraries, tools, and community support
  • Backed by Meta: Used in production by Facebook, Instagram, WhatsApp
💡 Remember: React is a library, not a framework. It handles only the UI layer. For routing, state management, etc., you combine it with other libraries (React Router, Redux, etc.).

Interview Q&A — What is React?

Q: What is React and why is it used?

A: React is a JavaScript library for building user interfaces. It's used because it allows developers to create large web applications that can update and render efficiently in response to data changes, using a component-based architecture and Virtual DOM.

Q: Is React a framework or a library?

A: React is a library, not a framework. Unlike Angular (which is a full framework), React focuses only on the view layer. You need additional libraries for routing, state management, and HTTP calls.

Q: Who created React and when?

A: React was created by Jordan Walke, a software engineer at Facebook. It was first deployed on Facebook's News Feed in 2011 and open-sourced in May 2013.

2. Features of React
Core Features Overview
React provides a powerful set of features including Virtual DOM, JSX, Component-Based Architecture, One-Way Data Binding, and a rich ecosystem — making it efficient, modular, and easy to maintain.

1 Virtual DOM

React creates a lightweight copy of the real DOM. It compares changes and updates only what's necessary, making rendering extremely fast.

2 JSX (JavaScript XML)

JSX allows writing HTML-like syntax directly in JavaScript, making the code more readable and easier to debug.

3 Component-Based

Everything in React is a component — reusable, self-contained pieces of UI that can be composed together.

4 One-Way Data Binding

Data flows in one direction (parent → child) via props, making data flow predictable and easier to debug.

5 Declarative UI

You describe what the UI should look like for each state, and React handles the DOM updates automatically.

6 React Hooks

Hooks let you use state and lifecycle features in functional components without writing class components.

7 Conditional Rendering

Render different UI elements based on conditions using JavaScript operators like ternary and logical AND.

8 Rich Ecosystem

Large community with tools like React Router, Redux, Next.js, React Native, and thousands of third-party libraries.

JSX is a syntax extension that looks like HTML but actually compiles to JavaScript function calls. It makes React code more readable and expressive.

React breaks the UI into independent, reusable components. Each component has its own logic, state, and rendering:

Interview Q&A — Features

Q: What are the main features of React?

A: The main features are: (1) Virtual DOM for efficient rendering, (2) JSX for writing UI in JavaScript, (3) Component-based architecture for reusability, (4) Unidirectional data flow for predictability, (5) React Hooks for state in functional components, (6) Declarative UI approach, and (7) Rich ecosystem with tools and libraries.

A: JSX (JavaScript XML) is a syntax extension for JavaScript that allows you to write HTML-like code within JavaScript. It gets transpiled to React.createElement() calls by Babel. JSX makes React code more readable and allows embedding JavaScript expressions using curly braces {}.

Q: What is one-way data binding in React?

A: One-way data binding means data flows in a single direction — from parent to child components via props. Child components cannot directly modify parent data; instead, they communicate back via callback functions. This makes the data flow predictable and easier to debug.

3. Virtual DOM
What is Virtual DOM?
The Virtual DOM: is a lightweight JavaScript representation (copy) of the Real DOM. React uses it to minimize direct DOM manipulations by calculating the minimum number of changes needed and batching updates.

The Real DOM is the browser's tree representation of the HTML page. Every time you change something in the DOM, the browser has to recalculate CSS, layout, and repaint — which is slow. React solves this with the Virtual DOM approach.

Diffing Algorithm & React Fiber
Big idea: Reconciliation finds what changed, and Fiber decides how React should process it without freezing the UI.

Diffing Algorithm & Reconciliation

What is Reconciliation?

Reconciliation: is React's update process for spotting changes when a component's state or props change. When data changes, React builds a new Virtual DOM tree and compares it with the previous one. That comparison shows exactly what changed, so React updates only the affected parts of the real DOM. React uses the Diffing Algorithm: to make this comparison fast, efficient, and predictable.

In short: Reconciliation tells React what changed, the Diffing Algorithm finds those changes, and Fiber helps React process them efficiently without blocking the UI.

How does the Diffing Algorithm work?

React keeps comparisons fast by following two simple rules:

  • Different element types: If two elements have different types, React treats them as different UI structures and replaces the entire subtree.
<div>Hello</div> becomes <span>Hello</span>
Because <div> and <span> are different types, React replaces the old subtree instead of checking every child.
  • Stable keys for lists: When rendering lists, React uses the key prop to identify each item consistently.
users.map(user => ( <UserCard key={user.id} user={user} /> ))
Keys help React track:
  • Which items stay the same
  • Which items are added
  • Which items are removed
  • Which items move to a new position

Stable, unique keys help React update lists efficiently while preserving component state.

Best practice: Avoid using the array index as a key when items can be added, removed, or reordered. It can lead to incorrect UI updates.
<div>Hello</div>
Why it matters: Without reconciliation, React would have to rebuild the whole UI on every change. With it, React updates only what changed, which improves performance and keeps the experience smooth.

React Fiber (React 16+)

Fiber at a glance: React Fiber is the engine that makes reconciliation interruptible, prioritized, and responsive, so it can handle the changes found by the Diffing Algorithm more smoothly.

What is React Fiber?

React Fiber: is React's internal rendering engine for powering reconciliation. Before React 16, reconciliation was synchronous, so React had to finish all rendering work before the browser could respond. Large updates could block the UI and make apps feel slow. Fiber breaks rendering into small units of work, letting React pause, resume, and prioritize tasks. You can think of Fiber as React's scheduler or work manager deciding how and when rendering should happen.

Fiber powers: incremental rendering, priority-based updates, pause and resume, and the foundation for concurrent rendering.

What features does React Fiber enable?

Fiber enables incremental rendering, priority-based updates, pause and resume behavior, and the foundation for concurrent rendering.

  • Incremental Rendering: Fiber splits rendering into smaller chunks so the browser stays responsive.
  • Priority-Based Updates: Urgent work like typing or clicking is handled before lower-priority tasks such as large list rendering.
  • Pause and Resume: If something urgent appears, Fiber can pause the current work, handle it, and then continue.
  • Foundation for Concurrent Features: Fiber is the base for React 18's concurrent rendering, helping React prepare updates in the background.
Comparison: Reconciliation answers what changed. Fiber answers how and when React should handle it.

Reconciliation vs. React Fiber

These concepts are closely related, but they do different jobs.

Reconciliation React Fiber
Compares the old and new Virtual DOM to identify changes. Provides the internal architecture that makes reconciliation efficient.
Focuses on what changed. Focuses on how and when the changes are processed.
Simple analogy:

Reconciliation is like comparing two document versions to spot the differences. React Fiber is the project manager that decides the best way to handle those differences without interrupting other important work.

💡 Remember: Always use stable, unique key props for list items. Using the array index as a key can cause bugs when items are reordered, added, or deleted.
Interview Q&A — Virtual DOM

Q: What is Virtual DOM and how does it work?

A: Virtual DOM is a lightweight JavaScript object that is a copy of the Real DOM.

  • When state changes, a new Virtual DOM tree is created
  • It is compared with the previous Virtual DOM using a diffing algorithm
  • Only the differences, or patches, are applied to the Real DOM
  • This minimizes expensive DOM operations and improves performance

Q: What is Reconciliation in React?

A: Reconciliation is React's decision-making process for updates. When state or props change, React compares the new element tree with the previous one, identifies what actually changed, and then applies the smallest possible set of DOM updates.

Q: Why are keys important in React lists?

A: Keys help React identify which items in a list have changed, been added, or removed during reconciliation. Without keys, React re-renders all list items. With stable unique keys, React can efficiently match old and new elements, reorder DOM nodes instead of recreating them, and maintain component state correctly.

Q: What is React Fiber?

A: React Fiber is the architecture that powers React's modern reconciliation. It breaks rendering into small units of work, lets React prioritize urgent updates, and can pause and resume rendering so the UI stays responsive. This is what makes concurrent features possible in React 18.

React 18 — Automatic Batching & Concurrent Rendering
★ Automatic Batching (React 18)
Automatic Batching means React 18 groups multiple state updates into a single re-render, no matter where they happen — inside event handlers, promises, setTimeout, or native event listeners.

What is Batching?

Batching is when React groups multiple state updates together and processes them in one render cycle instead of re-rendering after every single setState call. This avoids unnecessary renders and improves performance.

Before React 18 (React 17 and earlier)

React only batched updates inside React event handlers. Updates inside promises, setTimeout, or native events triggered separate re-renders for each state update.

React 17 — No batching outside event handlers 
// React 17: Each setState inside setTimeout triggers a separate re-render
function handleClick() {
  setTimeout(() => {
    setCount(c => c + 1);  // Re-render 1
    setFlag(f => !f);      // Re-render 2
  }, 1000);
}
// Total: 2 re-renders ❌

React 18 — Automatic Batching Everywhere

React 18 batches all state updates automatically, regardless of where they originate. This means fewer renders, better performance, and consistent behavior.

React 18 — Automatic batching everywhere 
// React 18: All updates are batched into one re-render
function handleClick() {
  setTimeout(() => {
    setCount(c => c + 1);  // Batched
    setFlag(f => !f);      // Batched
  }, 1000);
}
// Total: 1 re-render ✅ (both updates batched together)

// Also batched in promises:
async function fetchData() {
  const data = await fetch('/api/user');
  setUser(data);           // Batched
  setLoading(false);      // Batched
}
// Total: 1 re-render ✅
📝 Opt-out: If you need a state update to trigger an immediate re-render (rare case), use flushSync(): 
import { flushSync } from 'react-dom';

flushSync(() => {
  setCount(c => c + 1);
});
// DOM is updated immediately here
flushSync(() => {
  setFlag(f => !f);
});
// DOM is updated again here

★ Concurrent Rendering (React 18)
Concurrent Rendering is React 18's ability to prepare multiple versions of the UI at the same time. React can start rendering an update, pause it to handle something more urgent, and then resume — keeping the app responsive at all times.

What is Concurrency in React?

Concurrency means React can work on multiple tasks simultaneously. It does not mean things happen at the exact same time (that's parallelism). Instead, React can interrupt a low-priority render to handle a high-priority update (like user input), then come back and finish the interrupted work.

How Concurrent Rendering Works

┌─────────────────────────────────────────────────────────┐ │ CONCURRENT RENDERING │ ├─────────────────────────────────────────────────────────┤ │ │ │ Without Concurrency (React 17): │ │ ┌──────────────────────────────────────┐ │ │ │ Render A (blocking) │ → UI frozen │ │ └──────────────────────────────────────┘ │ │ │ │ With Concurrency (React 18): │ │ ┌─────────┐ ┌───┐ ┌─────────────────┐ │ │ │ Render A │ │ B │ │ Resume A │ → UI stays │ │ │ (pause) │ │ │ │ (continue) │ responsive │ │ └─────────┘ └───┘ └─────────────────┘ │ │ ↑ ↑ │ │ │ └── Urgent update (e.g., user typing) │ │ └── Low-priority update (e.g., search results) │ │ │ └─────────────────────────────────────────────────────────┘

useTransition Example

SearchComponent.jsx 
import { useState, useTransition } from 'react';

function SearchComponent() {
  const [input, setInput] = useState('');
  const [results, setResults] = useState([]);
  const [isPending, startTransition] = useTransition();

  function handleChange(e) {
    setInput(e.target.value);          // Urgent: update input immediately

    startTransition(() => {
      setResults(filterData(e.target.value)); // Non-urgent: can be interrupted
    });
  }

  return (
    <div>
      <input value={input} onChange={handleChange} />
      {isPending && <p>Loading...</p>}
      <ResultsList results={results} />
    </div>
  );
}
💡 Key Difference: useTransition tells React "this update is not urgent — handle user input first." The UI stays interactive even when processing expensive updates like filtering large lists.

createRoot — Enabling React 18 Features

index.js — React 18 setup 
// ❌ React 17 (old way — no concurrent features)
ReactDOM.render(<App />, document.getElementById('root'));

// ✅ React 18 (new way — enables all React 18 features)
import { createRoot } from 'react-dom/client';
const root = createRoot(document.getElementById('root'));
root.render(<App />);
⚠️ Important: Concurrent rendering is opt-in per feature. Simply using createRoot does not make your entire app concurrent. You explicitly opt in by using useTransition, useDeferredValue, or Suspense where needed.
Interview Q&A — React 18 Features

Q: What is Automatic Batching in React 18?

A: Automatic Batching means React 18 groups multiple state updates into a single re-render automatically, regardless of where they occur — inside event handlers, promises, setTimeout, or native events. In React 17, batching only worked inside React event handlers. This reduces unnecessary re-renders and improves performance.

Q: What is Concurrent Rendering in React 18?

A: Concurrent Rendering allows React to work on multiple UI updates simultaneously. React can start rendering a low-priority update, pause it when something urgent happens (like user input), handle the urgent update first, and then resume. This keeps the UI responsive even during heavy computations.

Q: What is useTransition and when would you use it?

A: useTransition is a hook that lets you mark a state update as non-urgent. React will keep the UI responsive (showing the old state) while processing the transition in the background. Use it when you have expensive state updates (like filtering large lists) that shouldn't block user input.

Q: What is the difference between useTransition and useDeferredValue?

A: useTransition wraps the state-setting code and gives you an isPending flag. useDeferredValue wraps a value and returns a deferred version that lags behind. Use useTransition when you control the state update; use useDeferredValue when you receive a value from a parent and want to defer its effect on an expensive child component.

Q: How do you enable React 18 features?

A: Use createRoot from react-dom/client instead of the legacy ReactDOM.render. This single change enables automatic batching, concurrent rendering, and all other React 18 features.

4. SPA (Single Page Application)
What is a SPA?
A Single Page Application (SPA) is a web application that loads a single HTML page and dynamically updates content as the user interacts with it — without requiring full page reloads from the server.

In a traditional website (MPA), every navigation triggers a full page reload. In a SPA, the initial load fetches the HTML, CSS, and JavaScript bundle. After that, all navigation and content updates happen on the client side by dynamically rewriting the current page.

SPA vs MPA

✅ SPA (Single Page Application)

  • Single HTML page loaded once
  • Dynamic content updates (no reload)
  • Faster navigation after initial load
  • App-like user experience
  • Client-side routing
  • Examples: Gmail, Facebook, Twitter

📑 MPA (Multi-Page Application)

  • Multiple HTML pages from server
  • Full page reload on navigation
  • Better initial SEO (server-rendered)
  • Traditional web experience
  • Server-side routing
  • Examples: Amazon, eBay, Wikipedia

Interview Q&A — SPA

Q: What is a Single Page Application (SPA)?

A: A SPA is a web application that loads a single HTML document and dynamically updates the page content using JavaScript without full page reloads. Navigation is handled client-side via React Router while data is fetched asynchronously via API calls. Examples: Gmail, Facebook, Twitter.

Q: What are the advantages and disadvantages of SPAs?

A:

  • Advantages: Faster navigation after initial load
  • Smooth UX
  • Reduced server load
  • Offline capability
  • Disadvantages: Larger initial load time
  • SEO challenges
  • Browser history complexity
  • Potential memory leaks
  • JavaScript dependency

Q: How does routing work in a React SPA?

A: React uses React Router for client-side routing. It uses the browser's History API to change the URL without triggering a server request. Components are conditionally rendered based on the current URL path using <BrowserRouter>, <Routes>, and <Route> components.

Interview Q&A — React vs Others

Q: What is the difference between React and Angular?

A: React is a library (view layer only) using Virtual DOM, one-way data binding, and JSX. Angular is a full framework with everything built-in, uses Real DOM with change detection, two-way data binding, and TypeScript. React is more flexible; Angular provides a complete but opinionated solution.

Q: Why would you choose React over Vue?

A:

  • Choose React for:
  • Larger ecosystem and more libraries
  • Better job market
  • React Native for mobile
  • More community support
  • Better tooling for large-scale apps
  • Choose Vue for:
  • Smaller projects
  • Faster prototyping
  • Simpler syntax

Q: What is the difference between a library and a framework?

A: A library (React) — you call it, you control the flow. A framework (Angular) — it calls your code, it controls the flow (Inversion of Control). React gives freedom to choose your architecture; Angular prescribes one.
