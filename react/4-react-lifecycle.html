🔄 React Component Lifecycle

📌 Quick Summary
🧬
Mounting: The component is created and inserted into the DOM for the first time.
🔁
Updating: The component re-renders because its props or state changed.
🗑️
Unmounting: The component is removed from the DOM and its resources are cleaned up.
🪝
Structure below: Class component walks through all three phases first, then the functional/Hooks version walks through all three phases on its own.
1

Class Component — Complete Lifecycle

Mounting → Updating → Unmounting, all shown on the same component

1.1 Mounting
Mounting Methods runs once

Mounting is when React creates the component instance and inserts it into the DOM for the first time. The methods fire in this order:

  1. constructor() — initialize state and bind methods
  2. static getDerivedStateFromProps() — rarely used, syncs state from props
  3. render() — returns JSX
  4. componentDidMount() — DOM is ready; fetch data, set subscriptions, start timers
1.2 Updating
Updating Methods runs on prop/state change

Updating happens whenever props or state change. The relevant methods, in order:

  1. static getDerivedStateFromProps()
  2. shouldComponentUpdate() — return false to skip re-render (performance)
  3. render()
  4. getSnapshotBeforeUpdate() — capture info (like scroll position) before DOM updates
  5. componentDidUpdate(prevProps, prevState) — DOM has updated; good place for side effects that depend on the new props/state
1.3 Unmounting
Unmounting Method runs once, on removal

componentWillUnmount() fires right before the component is removed from the DOM. Use it to clean up anything that would otherwise leak: timers, subscriptions, event listeners, open sockets.

1.4 Full Class Example — All Phases in One Component
Timer.jsx — Class Component mount + update + unmount
Timer.jsx (Class)
class Timer extends React.Component {
  constructor(props) {
    super(props);
    this.state = { seconds: 0 };
    console.log('MOUNT 1: constructor');
  }

  // ── MOUNTING ──────────────────────────────
  componentDidMount() {
    console.log('MOUNT 2: componentDidMount — start timer');
    this.intervalId = setInterval(() => {
      this.setState({ seconds: this.state.seconds + 1 });
    }, 1000);
  }

  // ── UPDATING ──────────────────────────────
  shouldComponentUpdate(nextProps, nextState) {
    console.log('UPDATE 1: shouldComponentUpdate');
    return true; // return false here to skip a re-render
  }

  componentDidUpdate(prevProps, prevState) {
    console.log(`UPDATE 2: componentDidUpdate — was ${prevState.seconds}, now ${this.state.seconds}`);
  }

  // ── UNMOUNTING ────────────────────────────
  componentWillUnmount() {
    console.log('UNMOUNT: clearing interval');
    clearInterval(this.intervalId); // prevent memory leak
  }

  render() {
    console.log('RENDER: render()');
    return <p>{this.state.seconds}s</p>;
  }
}
Order you'd see in the console: constructor → render → componentDidMount → (every second) shouldComponentUpdate → render → componentDidUpdate → ... → componentWillUnmount (when the component is removed, e.g. navigating away).
2

Functional Component — Complete Lifecycle (Hooks)

Same Mounting → Updating → Unmounting phases, rebuilt using useState / useEffect

2.1 Mounting
Mounting with Hooks runs once

Functional components use useEffect with an empty dependency array [] to replicate componentDidMount — the code inside runs exactly once, right after the first render commits to the DOM.

2.2 Updating
Updating with Hooks runs on dependency change

useEffect with a dependency array containing values replicates componentDidUpdate — it re-runs whenever any listed dependency changes. React.memo replicates shouldComponentUpdate by skipping re-renders when props are shallowly equal.

2.3 Unmounting
Unmounting with Hooks cleanup function

The function returned from inside useEffect is the cleanup function. React calls it right before the component unmounts — and also before every re-run of the effect.

2.4 Full Functional Example — All Phases in One Component
Timer.jsx — Functional Component mount + update + unmount
Timer.jsx (Functional)
import { useState, useEffect } from 'react';

function Timer() {
  const [seconds, setSeconds] = useState(0);
  console.log('RENDER: function body runs');

  // ── MOUNTING + UNMOUNTING (empty deps array) ──
  useEffect(() => {
    console.log('MOUNT: useEffect (once) — start timer');
    const intervalId = setInterval(() => {
      setSeconds(s => s + 1);
    }, 1000);

    return () => {
      console.log('UNMOUNT: cleanup — clearing interval');
      clearInterval(intervalId);
    };
  }, []); {/* [] = mount once, cleanup on unmount only */}

  // ── UPDATING (deps array with a value) ──
  useEffect(() => {
    console.log(`UPDATE: seconds changed to ${seconds}`);
  }, [seconds]); {/* re-runs every time "seconds" changes */}

  return <p>{seconds}s</p>;
}
Common bug: Forgetting the cleanup return in useEffect is the functional-component equivalent of forgetting componentWillUnmount — timers keep running and state updates fire on unmounted components.
Tip: Notice this example uses two separate useEffect calls — one for mount/unmount (empty array), one for updates ([seconds]). Splitting concerns like this is idiomatic; a class component would have to mix all of this into componentDidMount / componentDidUpdate / componentWillUnmount.
3. Class ↔ Hooks Mapping
Side-by-Side Reference
Class Lifecycle MethodFunctional Hook EquivalentPhase
constructor()useState() initial valueMounting
componentDidMount()useEffect(() => {...}, [])Mounting
componentDidUpdate()useEffect(() => {...}, [deps])Updating
componentWillUnmount()useEffect cleanup (return () => {...})Unmounting
shouldComponentUpdate()React.memo() / useMemo()Updating
getDerivedStateFromProps()Calculate value directly in the render body, or useEffectMounting & Updating
componentDidCatch()No hook equivalent — still needs a class (Error Boundary)Error handling
✅ Why Hooks are preferred today
  • Less boilerplate than class syntax
  • Related logic lives together in one useEffect, instead of split across lifecycle methods
  • Custom hooks let you reuse "lifecycle" logic across components
⚠️ Where classes still matter
  • Error Boundaries (componentDidCatch) have no hook equivalent
  • Legacy codebases still use class components extensively
  • useEffect timing can be trickier to reason about than named lifecycle methods
Interview Q&A
Interview Q&A — React Lifecycle

Q: What are the three phases of a React component's lifecycle?

A: Mounting (component is created and inserted into the DOM), Updating (component re-renders due to changed props or state), and Unmounting (component is removed from the DOM).

Q: How do you replicate componentDidMount in a functional component?

A: Use useEffect with an empty dependency array []. The effect callback runs exactly once, right after the first render commits to the DOM.

Q: How does useEffect handle cleanup, and when does it run?

A: The function returned from inside useEffect is the cleanup function. It runs before the component unmounts, and also before the effect re-runs on a dependency change — so it prevents leftover timers, subscriptions, or listeners from a previous run.

Q: What is the functional equivalent of shouldComponentUpdate?

A: Wrapping a component in React.memo() skips re-rendering when props are shallowly equal, similar to returning false from shouldComponentUpdate. useMemo and useCallback help avoid unnecessary recalculations and re-renders further down.

Q: Why can't functional components be Error Boundaries?

A: React doesn't provide a Hook for catching rendering errors — only the class lifecycle method componentDidCatch (along with static getDerivedStateFromError) can catch errors in a child component tree, so Error Boundaries must still be class components.

Q: What happens if you forget the dependency array in useEffect?

A: Omitting the array entirely makes the effect run after every render — mounting and every update — which is rarely what you want and can cause performance issues or infinite loops if the effect also updates state.
