🔑 Key Terms at a Glance
⚛️
State: Internal component data that can change over time. Mutable means it can change; in React, state is updated through setState or useState.
📦
Props: Read-only data passed from parent to child. Immutable means it should not be changed directly; props are controlled by the parent component.
🛠️
Controlled vs Uncontrolled: Controlled inputs are managed by React state, while uncontrolled inputs keep their own internal DOM state.
State vs Props
What are State & Props?
State is internal, mutable data managed within a component. Props are external, read-only data passed from parent to child. Together they control what a component renders.
Mutable: data that can change during the component's life, like state.
Immutable: data that should not be changed directly, like props.
StateVsProps.jsx
function Counter({ title }) {
  const [count, setCount] = useState(0);

  return (
    <div>
      <h3>{title}</h3>  {/* prop: immutable */}
      <p>Count: {count}</p>   {/* state: mutable */}
      <button onClick={() => setCount(count + 1)}>
        Increase
      </button>
    </div>
  );
}

🔄 State

  • Internal to the component
  • Mutable (via setState / useState)
  • Managed by the component itself
  • Triggers re-render on change
  • Not accessible by other components
  • Used for dynamic/interactive data

📦 Props

  • External — passed from parent
  • Immutable (read-only)
  • Managed by the parent component
  • Re-render when parent updates them
  • Accessible by child components
  • Used for configuration/data passing

Interview Q&A — State vs Props
Q: What is the difference between State and Props in React?
A: State is internal, mutable data owned and managed by the component itself using useState or setState. Props are external, immutable data passed from parent to child. State triggers re-renders when updated; props cause re-renders when the parent sends new values. State is for dynamic/interactive data; props are for configuration and data transfer.
Q: Can you modify props inside a child component?
A: No. Props are read-only in React. If a child needs to change data, the parent should pass a callback function as a prop. The child calls this callback, which updates the parent's state, and the new state flows back down as updated props.
Q: When does a component re-render?
A:
  • Its state changes via setState or a useState setter
  • Its props change because the parent passes new values
  • Its parent re-renders, even if the props are the same, unless it is wrapped in React.memo
  • Context changes, if the component uses useContext
Q: What is "lifting state up" in React?
A: Lifting state up means moving shared state to the closest common ancestor (parent) of the components that need it. The parent holds the state and passes it down as props. This pattern is used when multiple sibling components need to share and sync data.
Forms — Controlled Components
What are Controlled Components?
A Controlled Component is a form element whose value is controlled by React state. The component's state is the "single source of truth" — every input change goes through a state update handler.

In a controlled component:

  1. Form element value is bound to state → value={state}
  2. Every change triggers an event handler → onChange={handler}
  3. Handler updates state → setState(newValue)
  4. React re-renders with new value

Controlled Component Examples

Basic Text Input

ControlledInput.jsx
import { useState } from 'react';

function ControlledInput() {
  const [name, setName] = useState('');

  const handleChange = (e) => {
    setName(e.target.value);
  };

  return (
    <form>
      <label>Name:</label>
      <input
        type="text"
        value={name}
        onChange={handleChange}
      />
      <p>Hello, {name}!</p>
    </form>
  );
}

Full Controlled Form (Multiple Fields)

RegistrationForm.jsx
import { useState } from 'react';

function RegistrationForm() {
  const [formData, setFormData] = useState({
    username: '',
    email: '',
    password: '',
    role: 'user',
    agree: false
  });

  const handleChange = (e) => {
    const { name, value, type, checked } = e.target;
    setFormData(prev => ({
      ...prev,
      [name]: type === 'checkbox' ? checked : value
    }));
  };

  const handleSubmit = (e) => {
    e.preventDefault();
    console.log(formData);
  };

  return (
    <form onSubmit={handleSubmit}>
      <input name="username" value={formData.username}
             onChange={handleChange} />
      <input name="email" type="email" value={formData.email}
             onChange={handleChange} />
      <input name="password" type="password" value={formData.password}
             onChange={handleChange} />
      <select name="role" value={formData.role} onChange={handleChange}>
        <option value="user">User</option>
        <option value="admin">Admin</option>
      </select>
      <input name="agree" type="checkbox" checked={formData.agree}
             onChange={handleChange} />
      <button type="submit">Register</button>
    </form>
  );
}
💡 Tip: Use a single handleChange with [e.target.name] computed property to handle multiple form fields instead of writing a separate handler for each input.
Forms — Uncontrolled Components
What are Uncontrolled Components?
An Uncontrolled Component is a form element that stores its own state internally in the DOM. Instead of using React state, you access values using a ref (useRef) when needed (e.g., on submit).

In an uncontrolled component:

  1. No value binding to state
  2. Use defaultValue for initial value
  3. Access current value via ref.current.value
  4. DOM is the source of truth (not React state)
Uncontrolled Component Example
UncontrolledForm.jsx
import { useRef } from 'react';

function UncontrolledForm() {
  const nameRef = useRef(null);
  const emailRef = useRef(null);

  const handleSubmit = (e) => {
    e.preventDefault();
    // Access DOM values directly via ref
    console.log('Name:', nameRef.current.value);
    console.log('Email:', emailRef.current.value);
  };

  return (
    <form onSubmit={handleSubmit}>
      <input
        type="text"
        defaultValue="John"
        ref={nameRef}
      />
      <input
        type="email"
        defaultValue=""
        ref={emailRef}
      />
      <button type="submit">Submit</button>
    </form>
  );
}
Controlled vs Uncontrolled — Comparison

✅ Controlled (Recommended)

  • React state is source of truth
  • Uses value + onChange
  • Instant validation possible
  • Easy to manipulate input values
  • Conditional disable/submit
  • More React "idiomatic"

⚡ Uncontrolled (Simpler)

  • DOM is source of truth
  • Uses defaultValue + ref
  • Less code for simple forms
  • Better for file inputs
  • Easier integration with non-React code
  • No re-render on every keystroke

Custom Validation Example
ValidatedForm.jsx
import { useState } from 'react';

function ValidatedForm() {
  const [formData, setFormData] = useState({
    email: '', password: ''
  });
  const [errors, setErrors] = useState({});

  const validate = () => {
    const newErrors = {};

    // Email validation
    if (!formData.email) {
      newErrors.email = 'Email is required';
    } else if (!/\S+@\S+\.\S+/.test(formData.email)) {
      newErrors.email = 'Email is invalid';
    }

    // Password validation
    if (!formData.password) {
      newErrors.password = 'Password is required';
    } else if (formData.password.length < 6) {
      newErrors.password = 'Password must be at least 6 chars';
    }

    setErrors(newErrors);
    return Object.keys(newErrors).length === 0;
  };

  const handleSubmit = (e) => {
    e.preventDefault();
    if (validate()) {
      console.log('Form submitted!', formData);
    }
  };

  const handleChange = (e) => {
    setFormData({ ...formData, [e.target.name]: e.target.value });
  };

  return (
    <form onSubmit={handleSubmit}>
      <input name="email" value={formData.email}
             onChange={handleChange} placeholder="Email" />
      {errors.email && <span style={{color:'red'}}>{errors.email}</span>}

      <input name="password" type="password"
             value={formData.password}
             onChange={handleChange} placeholder="Password" />
      {errors.password && <span style={{color:'red'}}>{errors.password}</span>}

      <button type="submit">Login</button>
    </form>
  );
}
Real-Time Validation (onChange)
RealTimeValidation.jsx
const handleChange = (e) => {
  const { name, value } = e.target;
  setFormData(prev => ({ ...prev, [name]: value }));

  // Real-time validation
  let error = '';
  if (name === 'email' && value && !/\S+@\S+\.\S+/.test(value)) {
    error = 'Invalid email format';
  }
  if (name === 'password' && value && value.length < 6) {
    error = 'Min 6 characters';
  }

  setErrors(prev => ({ ...prev, [name]: error }));
};
📝 Note: Real-time validation provides instant feedback but can be annoying if too aggressive. A good UX pattern: validate on onBlur (when user leaves the field) and clear errors on onChange.
Validation with React Hook Form (Library)
HookFormExample.jsx
import { useForm } from 'react-hook-form';

function HookFormExample() {
  const {
    register,
    handleSubmit,
    formState: { errors }
  } = useForm();

  const onSubmit = (data) => console.log(data);

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input
        {...register('email', {
          required: 'Email is required',
          pattern: {
            value: /\S+@\S+\.\S+/,
            message: 'Invalid email'
          }
        })}
      />
      {errors.email && <p>{errors.email.message}</p>}

      <input
        type="password"
        {...register('password', {
          required: 'Password is required',
          minLength: { value: 6, message: 'Min 6 chars' }
        })}
      />
      {errors.password && <p>{errors.password.message}</p>}

      <button type="submit">Submit</button>
    </form>
  );
}
💡 Remember: React Hook Form uses uncontrolled components internally (refs) for performance — fewer re-renders. But it provides the same control as controlled components via its API. It's the most popular form library in React.

Interview Q&A — Forms
Q: What is the difference between Controlled and Uncontrolled Components?
A: In a Controlled component, form data is handled by React state (value + onChange). React is the source of truth. In an Uncontrolled component, form data is stored in the DOM itself, accessed via refs. DOM is the source of truth. Controlled gives more control (validation, formatting); Uncontrolled has fewer re-renders and less code.
Q: Why is Controlled Component preferred in React?
A: Controlled components are preferred because: (1) Single source of truth (React state), (2) Real-time validation possible, (3) Can conditionally disable submit button, (4) Easy to modify/format input (uppercase, trim), (5) Predictable behavior aligned with React's declarative model. They give full programmatic control over form inputs.
Q: How do you handle form validation in React?
A: Three approaches: (1) Custom validation — maintain an errors state object, validate in onChange/onSubmit, display error messages conditionally. (2) HTML5 attributes — use required, pattern, minLength for basic browser validation. (3) Libraries — React Hook Form (performance-focused), Formik + Yup/Zod (schema-based validation).
Q: What is React Hook Form and why use it?
A: React Hook Form is a performant form library that uses uncontrolled components (refs) internally to minimize re-renders. Benefits: (1) Less code than manual validation, (2) Built-in validation rules, (3) Excellent performance (isolates re-renders), (4) Easy integration with schema validators (Yup, Zod), (5) Small bundle size (~9KB).
Q: When would you use an Uncontrolled Component?
A: Use uncontrolled components when: (1) Handling file inputs (must use ref), (2) Integrating with non-React libraries, (3) Simple forms where you only need the value on submit, (4) Performance is critical and you want to avoid re-renders on every keystroke. React Hook Form uses this pattern internally.
