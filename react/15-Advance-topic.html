1. React.memo
What is React.memo?
React.memo is a higher-order component that memoizes a functional component. If the component's props stay the same, React skips re-rendering it.
🛒 Real-world example — Product Cards: An e-commerce page shows 200+ product cards. When the user updates the cart or changes filters, only affected cards should re-render. Wrapping ProductCard with React.memo prevents hundreds of unnecessary re-renders because each card's props (name, price, image) haven't changed.

It is mainly used to optimize performance in components that re-render often with the same props. It does a shallow comparison of props by default.

When to use it

  • When a component renders often with the same props
  • When the component is expensive to render
  • When you want to reduce unnecessary child re-renders

Real-World Example — E-commerce Product Card

ProductCard.jsx 
import React, { memo, useCallback } from 'react';

// ✅ Memoized — won't re-render when cart/filter state changes in parent
const ProductCard = memo(function ProductCard({ id, name, price, image, onAddToCart }) {
  console.log(`Rendering: ${name}`); // only logs when THIS card's props change
  return (
    <div className="product-card">
      <img src={image} alt={name} />
      <h3>{name}</h3>
      <p>₹{price}</p>
      <button onClick={() => onAddToCart(id)}>Add to Cart</button>
    </div>
  );
});

// Parent — Product Listing Page
function ProductList({ products }) {
  const [cart, setCart] = useState([]);
  const [filter, setFilter] = useState('');

  // ✅ Stable function ref — prevents memo from breaking
  const handleAddToCart = useCallback((id) => {
    setCart(prev => [...prev, id]);
  }, []);

  return (
    <div>
      <input value={filter} onChange={e => setFilter(e.target.value)} />
      {/* When filter/cart changes, only matching cards re-render */}
      {products.map(p => (
        <ProductCard key={p.id} {...p} onAddToCart={handleAddToCart} />
      ))}
      <p>Cart items: {cart.length}</p>
    </div>
  );
}
Tip: Always pair React.memo with useCallback for function props — otherwise a new function reference on every render defeats memoization.

Simple Example — Chat App Message Bubble

MessageBubble.jsx 
import React, { memo, useState } from 'react';

// ✅ Memoized — old messages won't re-render when new ones arrive
const MessageBubble = memo(function MessageBubble({ text, sender, time }) {
  console.log(`Rendering message from ${sender}`);
  return (
    <div className={`bubble ${sender === 'me' ? 'sent' : 'received'}`}>
      <p>{text}</p>
      <span className="time">{time}</span>
    </div>
  );
});

// Parent — Chat Window
function ChatWindow() {
  const [messages, setMessages] = useState([
    { id: 1, text: 'Hey!', sender: 'friend', time: '10:01' },
    { id: 2, text: 'Hi, how are you?', sender: 'me', time: '10:02' },
  ]);
  const [input, setInput] = useState('');

  const sendMessage = () => {
    setMessages(prev => [...prev, {
      id: Date.now(), text: input, sender: 'me', time: 'now'
    }]);
    setInput('');
  };

  return (
    <div>
      {/* Only the NEW message renders — old ones are skipped */}
      {messages.map(msg => (
        <MessageBubble key={msg.id} {...msg} />
      ))}
      <input value={input} onChange={e => setInput(e.target.value)} />
      <button onClick={sendMessage}>Send</button>
    </div>
  );
}
Result: In a chat with 500 messages, typing and sending a new message only renders 1 new bubble instead of re-rendering all 500. Huge performance win.
2. Error Boundaries
What is an Error Boundary?
An Error Boundary is a React class component that catches JavaScript errors in its child component tree and displays a fallback UI.
Error Boundaries in Functional Components: Modern React apps are usually built with functional components, but functional components cannot act as Error Boundaries because React does not provide a Hook for catching rendering errors.

To handle rendering errors in functional-component projects, you usually choose one of two approaches: a reusable class-based Error Boundary, or the react-error-boundary package.

1. Class-based Error Boundary

This is the most common approach. Create one reusable Error Boundary class and wrap any functional component tree with it.

App.jsx 
import ErrorBoundary from './ErrorBoundary';

function App() {
  return (
    <ErrorBoundary>
      <Dashboard />
    </ErrorBoundary>
  );
}

2. react-error-boundary Package

Many modern projects use react-error-boundary because it gives functional components a simple API while still using a class-based boundary internally.

App.jsx 
import { ErrorBoundary } from 'react-error-boundary';

function ErrorFallback({ error, resetErrorBoundary }) {
  return (
    <div>
      <p>Something went wrong: {error.message}</p>
      <button onClick={resetErrorBoundary}>Try again</button>
    </div>
  );
}

function App() {
  return (
    <ErrorBoundary FallbackComponent={ErrorFallback}>
      <Dashboard />
    </ErrorBoundary>
  );
}
🛒 Real-world example — Product Cards: On a product listing page, if one ProductCard crashes (e.g., missing image URL causes a render error), the Error Boundary catches it and shows "Unable to load this product" for that card only — the rest of the page keeps working normally instead of the entire app going blank.

Error boundaries do not catch errors inside event handlers, async code, or server-side rendering. They are meant to protect the UI from rendering crashes.

Real-World Example — Product Grid with Fallback

ProductErrorBoundary.jsx 
import React from 'react';

class ProductErrorBoundary extends React.Component {
  constructor(props) {
    super(props);
    this.state = { hasError: false, error: null };
  }

  static getDerivedStateFromError(error) {
    return { hasError: true, error };
  }

  componentDidCatch(error, info) {
    // Send to error tracking (Sentry, LogRocket, etc.)
    logErrorToService(error, info.componentStack);
  }

  render() {
    if (this.state.hasError) {
      return (
        <div className="error-card">
          <p>⚠️ Unable to load this product</p>
          <button onClick={() => this.setState({ hasError: false })}>
            Retry
          </button>
        </div>
      );
    }
    return this.props.children;
  }
}

// Usage — wrap each product card individually
function ProductGrid({ products }) {
  return (
    <div className="grid">
      {products.map(p => (
        {/* If one card crashes, only that card shows fallback */}
        <ProductErrorBoundary key={p.id}>
          <ProductCard {...p} />
        </ProductErrorBoundary>
      ))}
    </div>
  );
}
Remember: Error boundaries must be class components. Wrap individual items (not the whole list) so one crash doesn't take down the entire page.
3. Higher-Order Component (HOC)
What is an HOC?
A Higher-Order Component (HOC) is a function that takes a component and returns a new component with added behavior.
🔐 Real-world example: Reuse authentication, authorization, analytics, and permission logic across many pages. Instead of adding if (!user) redirect('/login') in every page component, wrap them with withAuth(DashboardPage) — one HOC handles auth check for all protected routes.

HOCs are used to reuse component logic. They are a pattern, not a React API. Common examples include authentication wrappers, loading state wrappers, and analytics wrappers.

Real-World Example — Auth Protection HOC

withAuth.jsx 
import { Navigate } from 'react-router-dom';
import { useAuth } from './hooks/useAuth';

// HOC that protects any page — reuse across entire app
function withAuth(WrappedComponent, requiredRole) {
  return function ProtectedComponent(props) {
    const { user, isLoading } = useAuth();

    if (isLoading) return <p>Loading...</p>;
    if (!user) return <Navigate to="/login" />;
    if (requiredRole && user.role !== requiredRole) {
      return <Navigate to="/unauthorized" />;
    }

    return <WrappedComponent {...props} user={user} />;
  };
}

// Usage — wrap any page in one line
const Dashboard = withAuth(DashboardPage);           // any logged-in user
const AdminPanel = withAuth(AdminPage, 'admin');  // admin only
const Settings   = withAuth(SettingsPage);          // any logged-in user
Tip: In modern React, many HOC use cases can also be solved with custom hooks, but HOCs are still common in older codebases and useful for route-level protection.

Real-World Example — Loading State HOC

1) UserList.jsx 
import React from "react";

function UserList({ users }) {
  return (
    <div>
      {users.map((user) => (
        <p key={user.id}>{user.id} - {user.name}</p>
      ))}
    </div>
  );
}

export default UserList;
2) withLoading.js 
import React from "react";

function withLoading(Component) {
  return function WrappedComponent({ isLoading, ...props }) {
    if (isLoading) {
      return <h2>Loading...</h2>;
    }
    return <Component {...props} />;
  };
}

export default withLoading;
3) UserListWithLoading.jsx 
import React from "react";
import UserList from "./UserList";
import withLoading from "./withLoading";

const UserListWithLoading = withLoading(UserList);

export default UserListWithLoading;
4) App.jsx 
import React, { useState, useEffect } from "react";
import UserListWithLoading from "./UserListWithLoading";

function App() {
  const [users, setUsers] = useState([]);
  const [isLoading, setIsLoading] = useState(true);

  useEffect(() => {
    setTimeout(() => {
      setUsers([
        { id: 1, name: "John" },
        { id: 2, name: "Emma" },
        { id: 3, name: "Alex" }
      ]);
      setIsLoading(false);
    }, 2000);
  }, []);

  return (
    <div>
      <UserListWithLoading isLoading={isLoading} users={users} />
    </div>
  );
}

Simple Explanation:
  • UserList → UI component that shows users
  • withLoading → HOC that adds loading behavior
  • UserListWithLoading → enhanced component
  • App → passes data and loading state
4. Custom Hooks
Custom Hooks — Brief Explanation
Custom Hooks are functions that start with use and bundle reusable stateful logic. They can call other hooks and return values directly, so multiple components can reuse the same logic without HOCs or wrapper components.
🔄 Real-world example: Reuse common logic such as API calls (useFetch), authentication (useAuth), online status (useOnlineStatus), local storage (useLocalStorage), and theme handling (useTheme) — write once, use in any component without duplicating code.

Common examples are useFetch, useLocalStorage, useDebounce, and useAuth. Each component gets its own isolated hook state.

Real-World Example — useFetch (API calls)

hooks/useFetch.js 
import { useState, useEffect } from 'react';

// Reusable hook for any API call across the app
function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    const controller = new AbortController();
    setLoading(true);

    fetch(url, { signal: controller.signal })
      .then(res => res.json())
      .then(json => { setData(json); setLoading(false); })
      .catch(err => {
        if (err.name !== 'AbortError') setError(err);
        setLoading(false);
      });

    return () => controller.abort(); // cleanup on unmount
  }, [url]);

  return { data, loading, error };
}

// Usage in any component — Products, Users, Orders, etc.
function ProductList() {
  const { data, loading, error } = useFetch('/api/products');
  if (loading) return <p>Loading...</p>;
  if (error) return <p>Error: {error.message}</p>;
  return data.map(p => <ProductCard key={p.id} {...p} />);
}

function UserProfile({ userId }) {
  const { data: user } = useFetch(`/api/users/${userId}`);
  return user && <h1>{user.name}</h1>;
}

More Real-World Custom Hooks

hooks/useLocalStorage.js + useOnlineStatus.js 
// 1. useLocalStorage — persist theme, preferences, tokens
function useLocalStorage(key, initialValue) {
  const [value, setValue] = useState(() => {
    const stored = localStorage.getItem(key);
    return stored ? JSON.parse(stored) : initialValue;
  });

  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);

  return [value, setValue];
}

// Usage: const [theme, setTheme] = useLocalStorage('theme', 'dark');

// 2. useOnlineStatus — show offline banner
function useOnlineStatus() {
  const [isOnline, setIsOnline] = useState(navigator.onLine);

  useEffect(() => {
    const goOnline = () => setIsOnline(true);
    const goOffline = () => setIsOnline(false);
    window.addEventListener('online', goOnline);
    window.addEventListener('offline', goOffline);
    return () => {
      window.removeEventListener('online', goOnline);
      window.removeEventListener('offline', goOffline);
    };
  }, []);

  return isOnline;
}

// Usage: const isOnline = useOnlineStatus();
//        {!isOnline && <Banner>You are offline</Banner>}
Remember: Custom Hooks share logic, not state. Two components using the same hook get independent state copies. Write the hook once → use in Products, Users, Orders, Settings — anywhere.
Interview Q&A
Interview Q&A — Optimization & Patterns
Q: What is React.memo and when should you use it?
A: React.memo is a performance optimization that memoizes a functional component. It skips re-rendering when props are shallowly equal. Use it for expensive components or components that often receive the same props.
Q: What is an Error Boundary in React?
A: An Error Boundary is a class component that catches rendering errors in its child tree and shows a fallback UI instead of crashing the app. It does not catch errors in event handlers, async code, or server-side rendering.
Q: What is a Higher-Order Component (HOC)?
A: A Higher-Order Component is a function that takes a component and returns a new enhanced component. It is used to reuse logic such as authentication, loading states, or permissions.
Q: What is the difference between React.memo and HOC?
A: React.memo is specifically for memoizing functional components to avoid unnecessary re-renders. HOC is a broader pattern for enhancing a component by wrapping it with extra behavior.
Q: What is the difference between a Higher-Order Component (HOC) and a Custom Hook?
A: A HOC wraps a component and returns an enhanced component, so it is useful when you want to add behavior at the component level such as loading states, auth, or analytics. A Custom Hook extracts reusable logic into a function that starts with use, so it is better for sharing stateful logic like fetching data, local storage, theme handling, or online status without adding wrapper components.
Q: What are Custom Hooks?
A: Custom Hooks are reusable functions that start with use and contain shared hook logic like fetching data, storing values, or debouncing input. They make components cleaner and easier to reuse.
