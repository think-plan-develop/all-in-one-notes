1️⃣2️⃣ useEffect vs useLayoutEffect
What's the difference between useEffect and useLayoutEffect?
Both are used to perform side effects in React. The main difference is when they execute: useEffect runs after the browser paints the UI, while useLayoutEffect runs synchronously after the DOM is updated but before the browser paints.

🔁 React Rendering Flow

State / Props Change │ ▼ Component Render │ ▼ Virtual DOM Created │ ▼ Real DOM Updated │ ├──────────────► useLayoutEffect │ (Runs Before Paint) ▼ Browser Paint │ ▼ useEffect (Runs After Paint)

⚡ useEffect

Used for non-blocking side effects: API Calls, Timers, Event Listeners, Local Storage, WebSocket Connections.

App.jsx
import { useEffect } from "react";

function App() {
    useEffect(() => {
        console.log("API Called");
    }, []);

    return <h1>Dashboard</h1>;
}
Render Component ↓ Paint Screen ↓ Run useEffect

🖼️ useLayoutEffect

Runs immediately after DOM updates but before the screen is painted. Used to measure DOM elements, read element sizes, scroll positioning, prevent UI flickering.

App.jsx
import { useLayoutEffect, useRef } from "react";

function App() {
    const boxRef = useRef();

    useLayoutEffect(() => {
        console.log(boxRef.current.offsetHeight);
    }, []);

    return <div ref={boxRef}>Hello React</div>;
}

🌍 Real-world Example

❌ Without useLayoutEffect:

flicker.js
useEffect(() => {
    element.style.height = "300px";
}, []);

The user briefly sees the old height before it updates (UI flicker).

✅ With useLayoutEffect:

no-flicker.js
useLayoutEffect(() => {
    element.style.height = "300px";
}, []);

The height changes before the browser paints, so no flicker is visible.

⚖️ Comparison

useEffectuseLayoutEffect
Runs after browser paintRuns before browser paint
Non-blockingBlocks painting until complete
Best for API calls and subscriptionsBest for DOM measurements and layout updates
Preferred in most casesUse only when necessary
🎯 Interview Tip: Use useEffect by default. Choose useLayoutEffect only when you need to read or modify the DOM before the browser paints.
1️⃣3️⃣ Controlled vs Uncontrolled
What are Controlled vs Uncontrolled Components?

🎛️ Controlled Component

A controlled component is an input whose value is managed by React state. React becomes the single source of truth.

LoginForm.jsx
import { useState } from "react";

function LoginForm() {
    const [email, setEmail] = useState("");

    return (
        <input
            value={email}
            onChange={(e) => setEmail(e.target.value)}
            placeholder="Enter Email"
        />
    );
}
User Types │ ▼ onChange Event │ ▼ Update React State │ ▼ Re-render Input

🗄️ Uncontrolled Component

An uncontrolled component stores its value inside the DOM. React accesses the value using a ref.

LoginForm.jsx
import { useRef } from "react";

function LoginForm() {
    const inputRef = useRef();

    function handleSubmit() {
        console.log(inputRef.current.value);
    }

    return (
        <>
            <input ref={inputRef} />

            <button onClick={handleSubmit}>
                Submit
            </button>
        </>
    );
}
User Types │ ▼ Value Stored in DOM │ ▼ Read Using Ref

⚖️ Comparison

ControlledUncontrolled
Managed by React stateManaged by DOM
Uses valueUses ref
Easier validationLess code
Re-renders on every changeDoesn't re-render while typing
Preferred for formsUseful for simple forms or third-party libraries
🎛️ Controlled Usage
  • Login Form
  • Registration Form
  • Search Box
  • Dynamic Validation
  • Multi-step Form
🗄️ Uncontrolled Usage
  • File Upload (<input type="file">)
  • Simple Search Input
  • Third-party UI libraries
  • Legacy HTML Forms
1️⃣4️⃣ useCallback vs useMemo
What is useCallback and how is it different from useMemo?

🔗 What is useCallback?

useCallback memoizes a function, so React returns the same function reference between renders unless its dependencies change. This helps prevent unnecessary re-renders when passing functions to child components.

syntax.js
const memoizedFunction = useCallback(() => {
    // logic
}, [dependencies]);

❌ Example Without useCallback

Parent.jsx
function Parent() {
    const [count, setCount] = useState(0);

    function handleClick() {
        console.log("Clicked");
    }

    return (
        <>
            <button onClick={() => setCount(count + 1)}>
                Increment
            </button>

            <Child onClick={handleClick} />
        </>
    );
}

Every render creates a new handleClick function, so Child receives a new prop and re-renders.

✅ With useCallback

Parent.jsx
import { useCallback, useState } from "react";

function Parent() {
    const [count, setCount] = useState(0);

    const handleClick = useCallback(() => {
        console.log("Clicked");
    }, []);

    return (
        <>
            <button onClick={() => setCount(count + 1)}>
                Increment
            </button>

            <Child onClick={handleClick} />
        </>
    );
}

Now handleClick keeps the same reference, helping React.memo avoid unnecessary child re-renders.

🧠 What is useMemo?

useMemo memoizes the result of an expensive calculation, so it is recomputed only when its dependencies change.

syntax.js
const memoizedValue = useMemo(() => {
    return expensiveCalculation();
}, [dependencies]);
Products.jsx
import { useMemo } from "react";

function Products({ items }) {
    const totalPrice = useMemo(() => {
        return items.reduce((sum, item) => sum + item.price, 0);
    }, [items]);

    return <h2>Total: {totalPrice}</h2>;
}

The total is recalculated only when items changes.

⚖️ useCallback vs useMemo

useCallbackuseMemo
Memoizes a functionMemoizes a value
Returns a functionReturns a computed result
Used for event handlers and callbacksUsed for expensive calculations
Prevents unnecessary child re-rendersPrevents repeated computations
🔗 useCallback Examples
  • Add to Cart button
  • Delete User action
  • Search handler
  • Pagination buttons
  • Form submit handler
🧠 useMemo Examples
  • Product filtering
  • Product sorting
  • Dashboard analytics
  • Student progress calculation
  • Large table filtering
🎯 Interview Tip: Remember this rule — useCallback → Memoizes a function. useMemo → Memoizes a computed value. Use them only when they solve a real performance issue, as unnecessary memoization can add complexity without improving performance.
1️⃣5️⃣ Higher-Order Components
What are Higher-Order Components (HOCs)?
A Higher-Order Component (HOC) is a function that takes a component as input and returns a new component with additional functionality. It is used to reuse component logic without modifying the original component. HOC = Component → Enhanced Component
syntax.js
const EnhancedComponent = withFeature(OriginalComponent);

🎯 Common Use Cases

  • Authentication
  • Authorization
  • Logging
  • Error Handling
  • Loading State
✅ Advantages
  • Reusable logic
  • Separation of concerns
  • Cleaner components
⚠️ Disadvantages
  • Wrapper hell (multiple nested HOCs)
  • Harder debugging
  • Mostly replaced by Custom Hooks

⚖️ HOC vs Custom Hook

HOCCustom Hook
Wraps a componentReuses logic inside a component
Returns a new componentReturns state and functions
Older React patternModern React pattern
🎯 Interview Tip: HOCs are common in legacy React codebases, while Custom Hooks are the preferred approach in modern React.
1️⃣6️⃣ Render Props Pattern
What is the Render Props Pattern?
The Render Props Pattern is a technique where a component shares logic by accepting a function as a prop. That function returns the UI to render. Render Prop = A prop whose value is a function that returns JSX.
MouseTracker.jsx
function MouseTracker({ render }) {
    const position = { x: 100, y: 200 };

    return render(position);
}

Usage:

App.jsx
<MouseTracker
    render={(position) => (
        <h2>
            X: {position.x} Y: {position.y}
        </h2>
    )}
/>

⚙️ How It Works

Reusable Component │ ▼ Contains Logic │ ▼ Calls render(data) │ ▼ Parent Returns JSX
✅ Advantages
  • Reusable logic
  • Flexible UI rendering
  • Separation of logic and presentation
⚠️ Disadvantages
  • Nested JSX (callback hell)
  • Harder to read
  • Mostly replaced by Custom Hooks

⚖️ Render Props vs HOC

Render PropsHOC
Uses a function propWraps a component
Parent controls UIHOC controls UI
Flexible renderingSimpler API

⚖️ Render Props vs Custom Hook

Render PropsCustom Hook
Uses a function propUses a hook
Returns JSXReturns state and functions
Older patternModern React pattern
🎯 Interview Tip: Before Hooks, HOCs and Render Props were the primary patterns for code reuse. Today, Custom Hooks are the recommended approach in modern React.
1️⃣7️⃣ React Router
How does React Router work, and what's the difference between BrowserRouter and HashRouter?

React Router enables client-side routing, allowing navigation between pages without reloading the browser. It listens to URL changes and renders the matching component.

App.jsx
import {
  BrowserRouter,
  Routes,
  Route,
} from "react-router-dom";

function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
      </Routes>
    </BrowserRouter>
  );
}

⚖️ BrowserRouter vs HashRouter

BrowserRouterHashRouter
Uses HTML5 History APIUses URL hash (#)
Clean URLs (/about)URLs contain # (/#/about)
Requires server configurationNo server configuration needed
Better for SEONot SEO friendly
Preferred for productionUseful for static hosting
💡 When to Use: BrowserRouter → Modern React applications with server support. HashRouter → Static hosting (GitHub Pages, older servers).
1️⃣8️⃣ SSR vs CSR & Next.js
What is SSR vs CSR, and how does Next.js fit in?

💻 Client-Side Rendering (CSR)

The browser downloads a minimal HTML page and JavaScript bundle. React renders the UI in the browser.

Browser │ Download HTML │ Download JS │ React Builds UI
✅ Advantages
  • Fast page transitions
  • Rich interactivity
  • Less server load
⚠️ Disadvantages
  • Slower first load
  • Poor SEO
  • Blank page until JavaScript loads

🖥️ Server-Side Rendering (SSR)

The server renders the HTML first, then sends it to the browser.

Browser │ Request Page │ Server Renders HTML │ HTML Sent to Browser │ React Hydrates
✅ Advantages
  • Better SEO
  • Faster first contentful paint
  • Better performance for initial load
⚠️ Disadvantages
  • More server work
  • Slightly slower navigation after first page

⚡ How Next.js Fits In

Next.js is a React framework that supports multiple rendering strategies: CSR, SSR, SSG (Static Site Generation), and ISR (Incremental Static Regeneration). It also provides file-based routing, API Routes, image optimization, code splitting, and SEO optimization.

⚖️ CSR vs SSR

CSRSSR
UI rendered in browserUI rendered on server
Poor SEOExcellent SEO
Slower first loadFaster first load
Better for dashboardsBetter for public websites
1️⃣9️⃣ Server vs Client Components
What are React Server Components, and how do they differ from Client Components?

🖥️ React Server Components (RSC)

Server Components are rendered on the server and send HTML to the browser. They cannot use client-side hooks such as useState or useEffect.

  • Run only on the server
  • Reduce JavaScript sent to the client
  • Better performance
  • Can directly fetch server-side data

💻 Client Components

Client Components run in the browser and support useState, useEffect, event handlers, and browser APIs.

To mark a component as a Client Component in Next.js:

Counter.jsx
"use client";

function Counter() {
    return <button>Click</button>;
}

📝 Server Component Example

Products.jsx
async function Products() {
    const products = await fetchProducts();

    return <ProductList products={products} />;
}

⚖️ Server vs Client Components

Server ComponentClient Component
Runs on serverRuns in browser
Cannot use Hooks like useStateCan use all React Hooks
Smaller JS bundleLarger JS bundle
Better performanceInteractive UI
Best for data fetchingBest for user interaction
🖥️ Server Components
  • Product Listing
  • Blog Pages
  • Dashboard Data
  • SEO Pages
💻 Client Components
  • Forms
  • Buttons
  • Search
  • Modals
  • Interactive UI
