1️⃣ State vs Props
What is State and how does it differ from Props?

🔢 State

State is data owned and managed by a component. It is mutable and can change over time. When state changes, React re-renders that component.

Counter.jsx
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <>
      <h2>{count}</h2>

      <button onClick={() => setCount(count + 1)}>
        Increment
      </button>
    </>
  );
}

📦 Props

Props (Properties) are read-only values passed from a parent component to a child component. A child component cannot modify props directly.

Child.jsx
function Child({ name }) {
  return <h2>Hello {name}</h2>;
}

function App() {
  return <Child name="Shivam" />;
}

⚖️ State vs Props

StateProps
Managed inside componentPassed by parent
MutableImmutable (Read-only)
Can change using setterCannot be modified by child
Triggers re-renderNew props from parent trigger re-render
Local to componentShared between components
🔢 When to use State
  • Form Inputs
  • Counter
  • Toggle
  • API Response
  • Modal Open/Close
  • Loading State
📦 When to use Props
  • Passing data
  • Passing callbacks
  • Reusable Components
  • Parent → Child Communication
2️⃣ Virtual DOM
What is the Virtual DOM and how does it work?
The Virtual DOM (VDOM) is a lightweight JavaScript representation of the Real DOM. Instead of updating the browser DOM directly, React creates a Virtual DOM, compares the new one with the previous one (Diffing), and updates only the changed elements in the Real DOM.

❌ Without React

Every update directly manipulates the browser DOM — direct DOM manipulation is expensive.

vanilla.js
document.getElementById("count").innerText = count;

✅ With React

Counter.jsx
const [count, setCount] = useState(0);

return <h1>{count}</h1>;

React updates only the text node that changed.

🔁 Working Process

State Changes │ ▼ Render Function Executes │ ▼ Creates New Virtual DOM │ ▼ Compare with Old Virtual DOM │ ▼ Find Differences (Diffing) │ ▼ Update Only Changed Nodes │ ▼ Browser Paint

📝 Example

Initial Render: <h1>Hello</h1> → After Update: <h1>Hello Shivam</h1>

React changes only the text node instead of recreating the entire <h1> element.

💡 Benefits: Faster updates, fewer DOM operations, better performance, declarative UI.
3️⃣ Why the key Prop?
Why do we need a key prop when rendering lists?
A key is a unique identifier that helps React identify which list items were added, removed, updated, or reordered. Without keys, React cannot efficiently match old and new elements during reconciliation.

✅ Example

UserList.jsx
const users = [
  { id: 1, name: "John" },
  { id: 2, name: "Alice" },
  { id: 3, name: "Bob" }
];

function UserList() {
  return (
    <ul>
      {users.map(user => (
        <li key={user.id}>
          {user.name}
        </li>
      ))}
    </ul>
  );
}

❌ Incorrect

bad-example.jsx
users.map((user, index) => (
    <li key={index}>{user.name}</li>
));

Using the array index as a key can cause problems when items are inserted, removed, or reordered.

📊 Insertion Example

Before Insert 1 John 0 Mike 2 Alice 1 John 3 Bob 2 Alice 3 Bob

With index keys, React may think every item changed and unnecessarily re-render the list. With unique IDs, React correctly identifies only the new item.

✅ Good Keys
  • key={user.id}
  • key={product.productId}
  • key={email}
❌ Bad Keys
  • key={index}
  • key={Math.random()}
  • key={Date.now()}
💡 Best Practices: Use stable, unique IDs from your data. Avoid generating new keys on every render. Use the array index only for static lists that never change order or content.
4️⃣ Conditional Rendering
How does Conditional Rendering work in React?
Conditional rendering means displaying different UI based on a condition, similar to JavaScript if, else, or ternary operators.

Using if

Greeting.jsx
function Greeting({ isLoggedIn }) {
  if (isLoggedIn) {
    return <h2>Welcome Back</h2>;
  }

  return <h2>Please Login</h2>;
}

Using Ternary Operator

App.jsx
function App() {
  const isLoggedIn = true;

  return (
    <>
      {isLoggedIn
        ? <h2>Dashboard</h2>
        : <h2>Login Page</h2>}
    </>
  );
}

Using Logical AND (&&)

App.jsx
function App() {
  const isAdmin = true;

  return (
    <>
      {isAdmin && <button>Delete User</button>}
    </>
  );
}

The right-hand side is rendered only when the condition is truthy.

Returning null

Loader.jsx
function Loader({ loading }) {
  if (!loading) return null;

  return <p>Loading...</p>;
}

Returning null renders nothing.

Real-World Example

Profile.jsx
function Profile({ user }) {
  return (
    <>
      {user ? (
        <h2>Welcome {user.name}</h2>
      ) : (
        <button>Login</button>
      )}
    </>
  );
}
5️⃣ Fragment vs div
What is the difference between React.Fragment and a div wrapper?

div Wrapper

A <div> creates an extra node in the Real DOM.

App.jsx
function App() {
  return (
    <div>
      <h1>React</h1>
      <p>Learning React</p>
    </div>
  );
}

Rendered HTML:

output.html
<div>
  <h1>React</h1>
  <p>Learning React</p>
</div>

React.Fragment

A Fragment groups multiple elements without adding an extra DOM node.

App.jsx
import { Fragment } from "react";

function App() {
  return (
    <Fragment>
      <h1>React</h1>
      <p>Learning React</p>
    </Fragment>
  );
}

Or the shorthand syntax:

App.jsx
function App() {
  return (
    <>
      <h1>React</h1>
      <p>Learning React</p>
    </>
  );
}

Rendered HTML:

output.html
<h1>React</h1>
<p>Learning React</p>

6️⃣ Lifting State Up
How do you lift state up in React?
Lifting state up means moving shared state from child components to their closest common parent so multiple components can access and update the same data. This enables one-way data flow, where the parent owns the state and passes it down as props.

❌ Without Lifting State

Each child has its own state, so updates are isolated.

Child.jsx
function Child() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      {count}
    </button>
  );
}

Two Child components would maintain separate counters.

✅ With Lifting State

The parent owns the state and passes it to children.

App.jsx
import { useState } from "react";

function Counter({ count, onIncrement }) {
  return (
    <button onClick={onIncrement}>
      Count: {count}
    </button>
  );
}

function App() {
  const [count, setCount] = useState(0);

  const handleIncrement = () => {
    setCount(prev => prev + 1);
  };

  return (
    <>
      <Counter
        count={count}
        onIncrement={handleIncrement}
      />

      <Counter
        count={count}
        onIncrement={handleIncrement}
      />
    </>
  );
}

Both Counter components display and update the same value because the state lives in the parent.

💡 Benefits: Single source of truth, consistent data across components, easier synchronization, simpler debugging, promotes reusable child components.
7️⃣ Reconciliation & Diffing
What is Reconciliation, and how does React's Diffing Algorithm work?
Reconciliation is the process React uses to compare the previous Virtual DOM with the new Virtual DOM after a state or prop change. Based on the differences, React updates only the necessary parts of the Real DOM using a Diffing Algorithm.

🔁 Working Process

State / Props Change │ ▼ Component Re-renders │ ▼ New Virtual DOM Created │ ▼ Compare with Previous Virtual DOM │ ▼ Find Differences (Diffing) │ ▼ Update Only Changed Nodes │ ▼ Browser Paint

1. Different Element Types

If two elements have different types, React destroys the old tree and creates a new one.

diff-types.jsx
// Before
<div>Hello</div>

// After
<span>Hello</span>

React removes <div> and creates a new <span>.

2. Same Element Type

If the element type is the same, React updates only the changed attributes or content.

diff-attrs.jsx
// Before
<button className="primary">Save</button>

// After
<button className="danger">Save</button>

Only the className changes; the <button> element is reused.

3. Lists Use Keys

React uses key values to efficiently identify list items.

list.jsx
users.map(user => (
    <li key={user.id}>{user.name}</li>
));

Without stable keys, React may unnecessarily re-render or recreate list items.

📝 Example

App.jsx
function App() {
    const [count, setCount] = useState(0);

    return (
        <>
            <h1>{count}</h1>

            <button onClick={() => setCount(count + 1)}>
                Increment
            </button>
        </>
    );
}

When count changes: component re-renders, new Virtual DOM is created, React compares old and new Virtual DOM, only the text inside <h1> changes, and the button remains unchanged.

💡 Benefits: Faster UI updates, fewer DOM manipulations, better performance, efficient rendering.
8️⃣ React Fiber
What is React Fiber, and how did it change React's Rendering Architecture?
React Fiber is the rendering engine introduced in React 16. It replaced the old synchronous rendering algorithm with an architecture that allows React to pause, prioritize, resume, and interrupt rendering work. Before Fiber, rendering was synchronous — a large update could block the main thread, causing the UI to freeze. Fiber enables incremental rendering, making applications more responsive.

❌ Before React Fiber

State Update │ ▼ Render Entire Component Tree │ ▼ Update DOM

Problems: cannot pause rendering, cannot prioritize urgent updates, large component trees block the UI.

✅ After React Fiber

State Update │ ▼ Split Work into Small Units (Fibers) │ ▼ Assign Priorities │ ▼ Pause / Resume / Interrupt Work │ ▼ Commit Changes to DOM

🔑 Key Features of Fiber

Incremental Rendering — React breaks rendering into small tasks instead of one large task.

Prioritized Updates — e.g. user typing / button click → High Priority; API response → Medium Priority; background rendering → Low Priority.

Interruptible Rendering — if the user clicks a button while React is rendering a large list, React can pause the list rendering, process the click, then continue.

Concurrent Rendering (React 18) — Fiber made features like Concurrent Rendering, startTransition(), Suspense, and Selective Hydration possible.

📝 Example

Search.jsx
import { useState, startTransition } from "react";

function Search() {
    const [text, setText] = useState("");

    function handleChange(e) {
        setText(e.target.value);

        startTransition(() => {
            // Expensive filtering
        });
    }

    return <input onChange={handleChange} />;
}

Typing remains responsive because expensive work is scheduled with lower priority.

💡 Benefits: Better responsiveness, smooth user experience, prioritized rendering, concurrent features, reduced UI blocking.
9️⃣ Unnecessary Re-renders
How do you identify and fix unnecessary re-renders?

A re-render occurs whenever: state changes, props change, the parent re-renders, or context value changes. Not every re-render is bad, but unnecessary re-renders can slow large applications.

❌ Common Cause: Parent Re-render

Parent.jsx
function Parent() {
    const [count, setCount] = useState(0);

    return (
        <>
            <button onClick={() => setCount(count + 1)}>
                Increment
            </button>

            <Child />
        </>
    );
}

Even if Child doesn't use count, it still re-renders because the parent re-rendered.

✅ Fix with React.memo

Child.jsx
const Child = React.memo(function Child() {
    console.log("Rendered");
    return <h2>Child</h2>;
});

❌ Function Props

example.jsx
<Child onClick={() => console.log("Click")} />

A new function is created on every render.

✅ Fix with useCallback

example.jsx
const handleClick = useCallback(() => {
    console.log("Click");
}, []);

<Child onClick={handleClick} />

❌ Expensive Calculations

example.jsx
const total = products.reduce(...);

Runs on every render.

✅ Fix with useMemo

example.jsx
const total = useMemo(() => {
    return products.reduce(...);
}, [products]);

🔍 How to Detect Re-renders

  • React Developer Tools → Highlight Updates
  • React DevTools Profiler
  • console.log("Rendered")
  • React Profiler API
💡 Optimization Techniques: React.memo(), useMemo(), useCallback(), stable keys, avoid unnecessary state, split large components.
🔟 Synthetic Events & Delegation
Explain how React handles Synthetic Events and Event Delegation

⚡ Synthetic Events

React does not use browser events directly. Instead, it wraps native browser events inside a SyntheticEvent, which provides a consistent API across all browsers.

App.jsx
function App() {
    function handleClick(event) {
        console.log(event.type);
    }

    return (
        <button onClick={handleClick}>
            Click
        </button>
    );
}

event is a SyntheticEvent, not the native DOM event. To access the native event: event.nativeEvent.

📝 Why Synthetic Events? Cross-browser compatibility, consistent behavior, simplified event handling, better integration with React.

🔗 Event Delegation

Instead of attaching event listeners to every element, React attaches a single listener at the root and delegates events internally.

Without delegation With delegation 1000 Buttons 1000 Buttons │ │ 1000 Event Listeners Single Event Listener │ React Determines Target

This reduces memory usage and improves performance.

🫧 Event Bubbling Example

App.jsx
function App() {
    return (
        <div onClick={() => console.log("Parent")}>
            <button onClick={() => console.log("Button")}>
                Click
            </button>
        </div>
    );
}

Output:

console
Button
Parent

🛑 Stop Propagation

App.jsx
function App() {
    function handleClick(e) {
        e.stopPropagation();
    }

    return (
        <div onClick={() => console.log("Parent")}>
            <button onClick={handleClick}>
                Click
            </button>
        </div>
    );
}

Only the button handler runs.

1️⃣1️⃣ React Portals
What is a React Portal?
A Portal allows React to render a component outside its parent DOM hierarchy while keeping it part of the same React component tree. Portals are useful for UI elements that should appear above the rest of the application — Modals, Dialogs, Tooltips, Dropdowns, Toast Notifications.

❌ Without Portal

App └── Card └── Modal

The modal may be clipped by overflow: hidden, z-index, or parent positioning.

✅ With Portal

React Tree DOM Tree App <body> └── Card <div id="root"></div> └── Modal <div id="modal-root"> Modal </div> </body>

The modal is rendered into #modal-root, outside the parent DOM.

🌐 HTML

index.html
<body>
    <div id="root"></div>
    <div id="modal-root"></div>
</body>

⚛️ React Code

Modal.jsx
import { createPortal } from "react-dom";

function Modal({ children }) {
    return createPortal(
        <div className="modal">
            {children}
        </div>,
        document.getElementById("modal-root")
    );
}

Usage:

App.jsx
function App() {
    return (
        <>
            <h1>Dashboard</h1>

            <Modal>
                <h2>Delete Confirmation</h2>
            </Modal>
        </>
    );
}
💡 Benefits: Avoids CSS overflow and stacking issues, better support for modals and overlays, keeps React state/props/context intact, and events still bubble through the React component tree even though the DOM node is rendered elsewhere.
