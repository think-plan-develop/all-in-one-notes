🔄 Reconciliation

How does React's reconciliation algorithm work?

Reconciliation is the process React uses to figure out what changed between renders. When state or props update, React builds a new Virtual DOM tree and compares (diffs) it against the previous tree using a heuristic O(n) algorithm rather than a full O(n³) tree comparison. It compares elements level by level: if the element type changes, React tears down the old subtree and builds a new one; if the type stays the same, React updates only the changed attributes and recurses into children. Keys on list items help React match children between renders so it can reorder, insert, or remove efficiently instead of re-creating everything.

🌳 Virtual DOM

What is the Virtual DOM?

The Virtual DOM is a lightweight, in-memory JavaScript representation of the actual DOM. Instead of directly mutating the real DOM (which is slow), React creates a virtual tree of elements, diffs it against the previous virtual tree during reconciliation, and computes the minimal set of real DOM operations needed. Those changes are then applied in a single batch, which is much faster than manipulating the DOM node by node for every update.

⚙️ Memoization Hooks

What is the difference between useMemo, useCallback, and React.memo?

useMemo memoizes a computed value and recalculates it only when its dependencies change — useful for expensive calculations. useCallback memoizes a function reference itself, so the same function identity is preserved across renders unless dependencies change — useful when passing callbacks to memoized children. React.memo is a higher-order component that wraps a component and skips re-rendering it if its props haven't changed (shallow comparison). They're often used together: React.memo prevents a child from re-rendering, while useCallback/useMemo keep the props passed to it stable.

📌 useRef vs useState

When should you use useRef instead of useState?

Use useRef when you need to persist a mutable value across renders without triggering a re-render when it changes — for example, storing a DOM node reference, a timer/interval ID, previous prop values, or any "instance variable" that doesn't affect what's rendered. Use useState when the value directly affects the UI and updating it should cause React to re-render the component. The key distinction: updating a ref is silent and synchronous; updating state schedules a re-render.

🔁 Re-renders

What causes a component to re-render?

A component re-renders when its own state changes (via useState/useReducer setters), when it receives new props from its parent, when its parent re-renders (by default, children re-render too unless memoized), when a consumed context value changes, or when it's forced to update via mechanisms like key changes that cause React to remount it. Note that a re-render doesn't always mean the DOM changes — it just means the component function runs again and React diffs the result.

🛑 Preventing Re-renders

How do you prevent unnecessary re-renders?

Common techniques include wrapping components in React.memo to skip re-rendering when props are shallowly equal, using useCallback and useMemo to keep function and object references stable across renders, splitting large components into smaller ones so state changes affect a smaller tree, lifting state down (colocating state closer to where it's used) instead of keeping it high up, using the key prop correctly to avoid accidental remounts, and avoiding creating new objects/arrays/functions inline as props when they'll be passed to memoized children.

🖱️ Synthetic Events

Explain how React handles synthetic events and event delegation.

React wraps native browser events in a cross-browser wrapper called a SyntheticEvent, which normalizes event behavior across different browsers and provides a consistent API. Rather than attaching listeners to each individual DOM node, React (since v17) attaches a single listener at the root of the rendered tree and relies on event bubbling — this is event delegation. When an event fires, React determines which component's handler should run based on the event target and its position in the virtual tree, then dispatches synthetic events through its own batching and priority system, which also enables features like automatic batching of state updates.

📦 Code Splitting

What is code-splitting, and how do you implement it with React.lazy and Suspense?

Code-splitting breaks a large JavaScript bundle into smaller chunks that load on demand, reducing the initial load time. React.lazy lets you define a component that is loaded via a dynamic import() only when it's actually rendered, returning a promise that resolves to the component module. Because that loading is asynchronous, the lazy component must be wrapped in a Suspense boundary, which shows a fallback UI (like a spinner) while the chunk is being fetched. This is commonly used for route-based splitting, so each page's code only loads when the user navigates to it.

🧩 Fragment vs div

What's the difference between React.Fragment and a div wrapper?

React.Fragment (or the shorthand <></>) lets you group multiple children without adding an extra node to the actual DOM, whereas a div wrapper introduces a real, visible element. This matters because extra divs can break CSS layouts (like flex or grid relationships between siblings), add unnecessary nesting, and hurt semantic HTML/accessibility. Fragments are purely a React-level grouping mechanism with zero DOM footprint, and the keyed version (<React.Fragment key={...}>) is useful when rendering lists of grouped elements.

🧠 useReducer

What is useReducer, and when would you prefer it over useState?

useReducer is a hook that manages state using a reducer function — a pure function that takes the current state and an action, and returns the new state, similar to Redux. It's preferable over useState when state logic is complex, involves multiple sub-values that update together, or when the next state depends heavily on the previous one and the transition logic benefits from being centralized in one place. It also makes state updates easier to test and reason about since all transitions live in a single reducer function, and it pairs well with passing dispatch down through context instead of many individual setter callbacks.

🌐 useContext

What is useContext, and how does it help avoid prop drilling?

useContext lets a component subscribe to a React Context and read its current value directly, without needing that value passed down manually through every intermediate component's props. Prop drilling happens when data has to be threaded through several layers of components that don't actually use it themselves, just to reach a deeply nested child. By wrapping a part of the tree in a Context.Provider and calling useContext in any descendant, you can access shared data (like theme, auth state, or locale) directly, keeping intermediate components clean. The tradeoff is that any component consuming the context re-renders whenever the context value changes, so it's best used for data that doesn't change too frequently or is split into smaller, more targeted contexts.
