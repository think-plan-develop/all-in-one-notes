What are React Hooks?
Hooks are special functions introduced in React 16.8 that let you use state, lifecycle, context, and other React features in functional components — without writing class components.

Rules of Hooks

  1. Only call Hooks at the top level — NOT inside loops, conditions, or nested functions
  2. Only call Hooks from React functions — functional components or custom hooks
HookPurposeCommon Use Case
useStateManage local stateForm inputs, toggles, counters
useEffectSide effectsAPI calls, subscriptions, timers
useContextConsume contextTheme, auth, language
useRefMutable ref / DOM accessFocus input, store prev value
useMemoMemoize valueExpensive calculations
useCallbackMemoize functionPrevent child re-renders
useReducerComplex state logicForms, state machines
useLayoutEffectSync DOM mutationsMeasure DOM, animations
⚠️ Important: Never call hooks conditionally! React relies on the order of hook calls being the same on every render to correctly associate state with each hook.
useState
useState — Managing Local State
useState returns a stateful value and a setter function. When the setter is called, the component re-renders with the new value.
const [state, setState] = useState(initialValue);
Counter.jsx 
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
      <button onClick={() => setCount(prev => prev - 1)}>-1</button>
    </div>
  );
}

useState with Objects

UserForm.jsx 
const [user, setUser] = useState({ name: '', age: 0 });

// ❌ WRONG — mutates state directly
user.name = 'John';

// ✅ CORRECT — spread + update
setUser({ ...user, name: 'John' });

// ✅ CORRECT — functional update (safest)
setUser(prev => ({ ...prev, name: 'John' }));

Lazy Initialization

LazyInit.jsx 
// ❌ Runs on EVERY render (expensive)
const [data, setData] = useState(expensiveComputation());

// ✅ Runs only on FIRST render (lazy)
const [data, setData] = useState(() => expensiveComputation());
💡 Remember: setState is asynchronous and batched. Use the functional form setState(prev => ...) when the new state depends on the previous state — especially in event handlers or timeouts.
useEffect
useEffect — Side Effects
useEffect lets you perform side effects (API calls, subscriptions, DOM manipulation, timers) after render. It replaces componentDidMount, componentDidUpdate, and componentWillUnmount.
useEffect(() => { /* effect */ return () => { /* cleanup */ }; }, [dependencies]);

Dependency Array Variants

SyntaxRuns WhenEquivalent Lifecycle
useEffect(() => {})Every rendercomponentDidUpdate (every)
useEffect(() => {}, [])Only on mount (once)componentDidMount
useEffect(() => {}, [a, b])When a or b changescomponentDidUpdate (conditional)
return () => {}On unmount / before re-runcomponentWillUnmount
FetchData.jsx 
import { useState, useEffect } from 'react';

function FetchUsers() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    // Runs once on mount
    fetch('https://jsonplaceholder.typicode.com/users')
      .then(res => res.json())
      .then(data => {
        setUsers(data);
        setLoading(false);
      });
  }, []); // ← empty array = mount only

  if (loading) return <p>Loading...</p>;
  return <ul>{users.map(u => <li key={u.id}>{u.name}</li>)}</ul>;
}

Cleanup Example (Timer / Subscription)

Timer.jsx 
useEffect(() => {
  const interval = setInterval(() => {
    setSeconds(prev => prev + 1);
  }, 1000);

  // Cleanup: runs on unmount
  return () => clearInterval(interval);
}, []); // mount + unmount only
⚠️ Common Mistakes:
1. Missing dependency → stale closures
2. Object/array in deps → infinite loop (use useMemo or compare values)
3. Forgetting cleanup → memory leaks (subscriptions, timers, event listeners)
useContext
useContext — Consuming Context
useContext lets you read and subscribe to context values without nesting Consumer components. It solves prop drilling — passing props through many intermediate components.
const value = useContext(MyContext);
ThemeContext.jsx 
import { createContext, useContext, useState } from 'react';

// 1. Create context
const ThemeContext = createContext('light');

// 2. Provider (wraps app)
function App() {
  const [theme, setTheme] = useState('light');
  return (
    <ThemeContext.Provider value={{ theme, setTheme }}>
      <Navbar />
      <Content />
    </ThemeContext.Provider>
  );
}

// 3. Consume anywhere (no prop drilling!)
function Navbar() {
  const { theme, setTheme } = useContext(ThemeContext);
  return (
    <nav style={{ background: theme === 'dark' ? '#1e293b' : '#fff' }}>
      <button onClick={() => setTheme(theme === 'dark' ? 'light' : 'dark')}>
        Toggle Theme
      </button>
    </nav>
  );
}
WITHOUT Context (Prop Drilling): WITH Context: App → Navbar → Menu → Button (theme) App [Provider] ↓ props at every ↓ context level! Button [useContext] ← direct access!
📝 Note: All components using useContext will re-render when the context value changes. For large apps with frequent updates, consider splitting contexts or using state management libraries (Redux, Zustand).
useRef
useRef — Mutable References & DOM Access
useRef returns a mutable object { current: value } that persists across renders. It does NOT trigger re-renders when changed. Used for DOM access and storing mutable values.
const ref = useRef(initialValue); // ref.current = initialValue

Use Case 1: DOM Access

FocusInput.jsx 
import { useRef } from 'react';

function FocusInput() {
  const inputRef = useRef(null);

  const handleClick = () => {
    inputRef.current.focus();  // directly access DOM
    inputRef.current.style.borderColor = '#6366f1';
  };

  return (
    <div>
      <input ref={inputRef} placeholder="Click button to focus" />
      <button onClick={handleClick}>Focus Input</button>
    </div>
  );
}

Use Case 2: Store Previous Value

PreviousValue.jsx 
function Counter() {
  const [count, setCount] = useState(0);
  const prevCountRef = useRef(0);

  useEffect(() => {
    prevCountRef.current = count; // update after render
  });

  return (
    <p>Now: {count}, Before: {prevCountRef.current}</p>
  );
}
💡 Remember: useRef vs useState: Both persist across renders. But useRef does NOT trigger re-render when updated. Use ref for values you need to track silently (timers, previous state, DOM elements).
useMemo
useMemo — Memoize Expensive Computations
useMemo caches (memoizes) the result of an expensive calculation and only recomputes it when its dependencies change. It returns a value.
const memoizedValue = useMemo(() => computeExpensive(a, b), [a, b]);
ExpensiveList.jsx 
import { useState, useMemo } from 'react';

function ExpensiveList({ items }) {
  const [filter, setFilter] = useState('');
  const [darkMode, setDarkMode] = useState(false);

  // ✅ Only recalculates when items or filter changes
  // NOT when darkMode toggles
  const filteredItems = useMemo(() => {
    console.log('Filtering...'); // expensive!
    return items.filter(item =>
      item.name.toLowerCase().includes(filter.toLowerCase())
    );
  }, [items, filter]); // ← dependencies

  return (
    <div>
      <input value={filter} onChange={e => setFilter(e.target.value)} />
      <button onClick={() => setDarkMode(!darkMode)}>Toggle Theme</button>
      {filteredItems.map(item => <p key={item.id}>{item.name}</p>)}
    </div>
  );
}
💡 Tip: Don't overuse useMemo! Only use it when: (1) Computation is actually expensive, (2) Dependencies change rarely compared to renders. Premature memoization adds complexity for no performance gain.
useCallback
useCallback — Memoize Functions
useCallback returns a memoized version of a callback function that only changes when its dependencies change. It prevents unnecessary re-renders of child components that receive the function as a prop.
const memoizedFn = useCallback(() => { doSomething(a) }, [a]);

useMemo vs useCallback

HookReturnsMemoizesUse When
useMemoValue (result)Computation resultExpensive calculations

ParentChild.jsx 
import { useState, useCallback, memo } from 'react';

// Child wrapped with React.memo
const Button = memo(({ onClick, label }) => {
  console.log('Button rendered:', label);
  return <button onClick={onClick}>{label}</button>;
});

function Parent() {
  const [count, setCount] = useState(0);
  const [text, setText] = useState('');

  // ✅ Memoized — Button won't re-render when text changes
  const increment = useCallback(() => {
    setCount(prev => prev + 1);
  }, []); // no deps — never changes

  return (
    <div>
      <Button onClick={increment} label="Increment" />
      <input value={text} onChange={e => setText(e.target.value)} />
      <p>Count: {count}</p>
    </div>
  );
}
📝 Note: useCallback is only useful when combined with React.memo on child components. Without memo, the child re-renders regardless because parent re-render triggers all children.
Real Project Example 1: Search with Debounced API Call

In an e-commerce app, the search bar calls an API on every keystroke. Without useCallback, the debounced function gets recreated every render, breaking debounce logic.

ProductSearch.jsx 
import { useState, useCallback } from 'react';
import { debounce } from 'lodash';
import { searchProducts } from '../services/api';

function ProductSearch() {
  const [query, setQuery] = useState('');
  const [results, setResults] = useState([]);
  const [loading, setLoading] = useState(false);

  // ✅ Memoized debounced API call — won't be recreated on every render
  const debouncedSearch = useCallback(
    debounce(async (searchTerm) => {
      if (!searchTerm.trim()) { setResults([]); return; }
      setLoading(true);
      const data = await searchProducts(searchTerm);
      setResults(data);
      setLoading(false);
    }, 400),
    [] // never recreated — debounce timer persists
  );

  const handleChange = (e) => {
    setQuery(e.target.value);
    debouncedSearch(e.target.value);
  };

  return (
    <div className="search-container">
      <input value={query} onChange={handleChange}
             placeholder="Search products..." />
      {loading && <span>Searching...</span>}
      {results.map(p => <ProductCard key={p.id} product={p} />)}
    </div>
  );
}
💡 Why useCallback matters here: Without it, debounce() creates a NEW debounced function on every render. The old timer gets lost, so debouncing never works — every keystroke fires an API call immediately.
Real Project Example 2: Infinite Scroll with Event Listener

Social media feed with infinite scroll. The scroll handler is passed to addEventListener — if it changes reference, you'd need to remove and re-add the listener every render.

InfiniteScrollFeed.jsx 
import { useState, useCallback, useEffect, useRef } from 'react';

function InfiniteScrollFeed() {
  const [posts, setPosts] = useState([]);
  const [page, setPage] = useState(1);
  const [hasMore, setHasMore] = useState(true);
  const loadingRef = useRef(false);

  // ✅ Stable reference — safe to use in addEventListener
  const handleScroll = useCallback(() => {
    if (loadingRef.current || !hasMore) return;

    const { scrollTop, scrollHeight, clientHeight } = 
      document.documentElement;

    if (scrollTop + clientHeight >= scrollHeight - 200) {
      setPage(prev => prev + 1);
    }
  }, [hasMore]);

  useEffect(() => {
    window.addEventListener('scroll', handleScroll);
    return () => window.removeEventListener('scroll', handleScroll);
  }, [handleScroll]); // only re-attaches when hasMore changes

  useEffect(() => {
    loadingRef.current = true;
    fetch(`/api/posts?page=${page}`)
      .then(r => r.json())
      .then(data => {
        setPosts(prev => [...prev, ...data.posts]);
        setHasMore(data.hasMore);
        loadingRef.current = false;
      });
  }, [page]);

  return (
    <div>
      {posts.map(post => <PostCard key={post.id} post={post} />)}
      {!hasMore && <p>No more posts</p>}
    </div>
  );
}
Real Project Example 3: Data Table with Sortable Columns

Admin dashboard with a table of 1000+ rows. Each column header is a memoized child component. Without useCallback, clicking sort on one column re-renders ALL column headers.

DataTable.jsx 
import { useState, useCallback, useMemo, memo } from 'react';

// Memoized column header — won't re-render unless its props change
const ColumnHeader = memo(({ column, sortBy, sortDir, onSort }) => {
  console.log('Render:', column); // check re-renders
  return (
    <th onClick={() => onSort(column)}>
      {column} {sortBy === column ? (sortDir === 'asc' ? '▲' : '▼') : ''}
    </th>
  );
});

function DataTable({ data, columns }) {
  const [sortBy, setSortBy] = useState('');
  const [sortDir, setSortDir] = useState('asc');
  const [filter, setFilter] = useState('');

  // ✅ Stable sort handler — ColumnHeaders don't re-render on filter change
  const handleSort = useCallback((column) => {
    setSortBy(prev => {
      if (prev === column) {
        setSortDir(d => d === 'asc' ? 'desc' : 'asc');
      } else {
        setSortDir('asc');
      }
      return column;
    });
  }, []); // no deps — uses functional updates

  const sortedData = useMemo(() => {
    let filtered = data.filter(row =>
      Object.values(row).some(v =>
        String(v).toLowerCase().includes(filter.toLowerCase())
      )
    );
    if (sortBy) {
      filtered.sort((a, b) => {
        const cmp = String(a[sortBy]).localeCompare(String(b[sortBy]));
        return sortDir === 'asc' ? cmp : -cmp;
      });
    }
    return filtered;
  }, [data, filter, sortBy, sortDir]);

  return (
    <div>
      <input value={filter} onChange={e => setFilter(e.target.value)}
             placeholder="Filter table..." />
      <table>
        <thead><tr>
          {columns.map(col => (
            <ColumnHeader key={col} column={col}
              sortBy={sortBy} sortDir={sortDir} onSort={handleSort} />
          ))}
        </tr></thead>
        <tbody>
          {sortedData.map(row => (
            <tr key={row.id}>
              {columns.map(col => <td key={col}>{row[col]}</td>)}
            </tr>
          ))}
        </tbody>
      </table>
    </div>
  );
}
💡 Real Impact: With 15 columns and 1000 rows, typing in the filter box WITHOUT useCallback re-renders all 15 ColumnHeader components on every keystroke. WITH useCallback + memo, only the table body updates — headers stay frozen.
useReducer
useReducer — Complex State Logic
useReducer is an alternative to useState for complex state logic. It uses a reducer function (like Redux) with actions and a dispatch function. Best when state has multiple sub-values or next state depends on previous.
const [state, dispatch] = useReducer(reducer, initialState);
TodoReducer.jsx 
import { useReducer } from 'react';

// Reducer function
function todoReducer(state, action) {
  switch (action.type) {
    case 'ADD':
      return [...state, { id: Date.now(), text: action.payload, done: false }];
    case 'TOGGLE':
      return state.map(t =>
        t.id === action.payload ? { ...t, done: !t.done } : t
      );
    case 'DELETE':
      return state.filter(t => t.id !== action.payload);
    default:
      return state;
  }
}

function TodoApp() {
  const [todos, dispatch] = useReducer(todoReducer, []);

  const addTodo = (text) => {
    dispatch({ type: 'ADD', payload: text });
  };

  return (
    <div>
      {todos.map(todo => (
        <div key={todo.id}>
          <span onClick={() => dispatch({type:'TOGGLE', payload:todo.id})}>
            {todo.done ? '✅' : '⬜'} {todo.text}
          </span>
          <button onClick={() => dispatch({type:'DELETE', payload:todo.id})}>🗑</button>
        </div>
      ))}
    </div>
  );
}

useLayoutEffect
useLayoutEffect — Synchronous DOM Mutations
useLayoutEffect fires synchronously after DOM mutations but before the browser paints. Use it when you need to read layout (dimensions, positions) or make DOM changes that must be visible immediately without flickering.
useLayoutEffect(() => { /* sync after DOM update, before paint */ }, [deps]);

useEffect vs useLayoutEffect

FeatureuseEffectuseLayoutEffect
TimingAfter paint (async)Before paint (sync)
Blocks painting?NoYes (can cause lag if heavy)
Use caseAPI calls, subscriptions, timersDOM measurements, prevent flicker
Default choice✅ Use this 99% of the timeOnly when needed
Render → DOM Update → useLayoutEffect (sync) → Browser Paints → useEffect (async) ↑ ↑ fires HERE (before user sees) fires HERE (after user sees)
MeasureElement.jsx 
import { useLayoutEffect, useRef, useState } from 'react';

function Tooltip({ text }) {
  const ref = useRef(null);
  const [width, setWidth] = useState(0);

  useLayoutEffect(() => {
    // Measure DOM before browser paints — no flicker!
    const rect = ref.current.getBoundingClientRect();
    setWidth(rect.width);
  }, [text]);

  return (
    <div ref={ref} style={{ marginLeft: -width / 2 }}>
      {text}
    </div>
  );
}
⚠️ Warning: Only use useLayoutEffect when you actually see visual flickering with useEffect. It blocks the browser from painting, so heavy computations inside it will make your UI feel laggy.
Real Project Example 1: Auto-Resizing Textarea

Chat app textarea that auto-grows as the user types. Using useEffect causes a visible flicker — the textarea briefly shows the wrong height before adjusting.

AutoResizeTextarea.jsx 
import { useState, useLayoutEffect, useRef } from 'react';

function AutoResizeTextarea({ onSend }) {
  const [message, setMessage] = useState('');
  const textareaRef = useRef(null);

  // ✅ useLayoutEffect — resize BEFORE browser paints (no flicker)
  useLayoutEffect(() => {
    const el = textareaRef.current;
    el.style.height = 'auto'; // reset to recalculate
    el.style.height = el.scrollHeight + 'px'; // set to content height
  }, [message]); // runs every time message changes

  return (
    <div className="chat-input">
      <textarea
        ref={textareaRef}
        value={message}
        onChange={(e) => setMessage(e.target.value)}
        placeholder="Type a message..."
        rows={1}
        style={{ overflow: 'hidden', resize: 'none', minHeight: '40px', maxHeight: '200px' }}
      />
      <button onClick={() => { onSend(message); setMessage(''); }}>
        Send
      </button>
    </div>
  );
}

// ❌ With useEffect: textarea briefly shows old height → then snaps to new height (FLICKER)
// ✅ With useLayoutEffect: height updates BEFORE paint → user sees correct height instantly
Real Project Example 2: Dropdown Menu Positioning

A dropdown menu that opens upward or downward depending on available viewport space. Must measure the element position BEFORE paint to avoid the dropdown appearing in wrong position first.

SmartDropdown.jsx 
import { useState, useLayoutEffect, useRef } from 'react';

function SmartDropdown({ trigger, items }) {
  const [isOpen, setIsOpen] = useState(false);
  const [position, setPosition] = useState('below'); // 'below' or 'above'
  const triggerRef = useRef(null);
  const menuRef = useRef(null);

  // ✅ Measure and reposition BEFORE user sees the dropdown
  useLayoutEffect(() => {
    if (!isOpen || !triggerRef.current || !menuRef.current) return;

    const triggerRect = triggerRef.current.getBoundingClientRect();
    const menuHeight = menuRef.current.offsetHeight;
    const viewportHeight = window.innerHeight;

    // If not enough space below, flip to above
    const spaceBelow = viewportHeight - triggerRect.bottom;
    if (spaceBelow < menuHeight && triggerRect.top > menuHeight) {
      setPosition('above');
    } else {
      setPosition('below');
    }
  }, [isOpen]);

  return (
    <div className="dropdown-wrapper" style={{ position: 'relative' }}>
      <button ref={triggerRef} onClick={() => setIsOpen(!isOpen)}>
        {trigger}
      </button>

      {isOpen && (
        <ul
          ref={menuRef}
          style={{
            position: 'absolute',
            [position === 'above' ? 'bottom' : 'top']: '100%',
            left: 0,
            minWidth: '180px',
            boxShadow: '0 4px 20px rgba(0,0,0,.15)'
          }}
        >
          {items.map(item => (
            <li key={item.id} onClick={item.action}>{item.label}</li>
          ))}
        </ul>
      )}
    </div>
  );
}

// Real usage: notification menu, user profile dropdown, context menus
💡 Why useLayoutEffect: With useEffect, the user would see the dropdown appear BELOW, then jump ABOVE in the next frame — a visible jank. useLayoutEffect calculates position synchronously before paint, so the dropdown appears in the correct place immediately.
Custom Hooks
Custom Hooks — Reusable Logic
A Custom Hook is a JavaScript function whose name starts with use that can call other hooks. It lets you extract and reuse stateful logic across multiple components without duplicating code.

Rules for Custom Hooks

  • Name MUST start with use (e.g., useFetch, useAuth)
  • Can call other hooks (useState, useEffect, etc.)
  • Each component using the hook gets its own isolated state
  • Can return anything: value, array, object

Example 1: useFetch

useFetch.js 
import { useState, useEffect } from 'react';

function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    const controller = new AbortController();

    setLoading(true);
    fetch(url, { signal: controller.signal })
      .then(res => res.json())
      .then(data => { setData(data); setLoading(false); })
      .catch(err => {
        if (err.name !== 'AbortError') {
          setError(err.message);
          setLoading(false);
        }
      });

    return () => controller.abort(); // cleanup
  }, [url]);

  return { data, loading, error };
}

// Usage:
function UserList() {
  const { data, loading, error } = useFetch('/api/users');
  if (loading) return <p>Loading...</p>;
  if (error) return <p>Error: {error}</p>;
  return <ul>{data.map(u => <li key={u.id}>{u.name}</li>)}</ul>;
}

Example 2: useLocalStorage

useLocalStorage.js 
function useLocalStorage(key, initialValue) {
  const [value, setValue] = useState(() => {
    const stored = localStorage.getItem(key);
    return stored ? JSON.parse(stored) : initialValue;
  });

  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);

  return [value, setValue];
}

// Usage:
const [theme, setTheme] = useLocalStorage('theme', 'light');

Example 3: useDebounce

useDebounce.js 
function useDebounce(value, delay = 500) {
  const [debouncedValue, setDebouncedValue] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => {
      setDebouncedValue(value);
    }, delay);

    return () => clearTimeout(timer);
  }, [value, delay]);

  return debouncedValue;
}

// Usage: search input
const [search, setSearch] = useState('');
const debouncedSearch = useDebounce(search, 300);

useEffect(() => {
  // API call only fires 300ms after user stops typing
  fetchResults(debouncedSearch);
}, [debouncedSearch]);
💡 Remember: Custom hooks are just a convention, not a React feature. Any function starting with use that calls hooks IS a custom hook. They let you share logic (not state) between components — each component gets its own copy of the state.
Real Project Example: useAuth — Authentication Hook

A production-level custom hook used across every protected page in an app — handles login, logout, token refresh, and auth state. Used in real projects with JWT authentication.

hooks/useAuth.js 
import { useState, useEffect, useCallback, createContext, useContext } from 'react';
import { authApi } from '../services/api';

const AuthContext = createContext(null);

// Provider component — wraps the entire app
export function AuthProvider({ children }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  // Check if user is already logged in (token in localStorage)
  useEffect(() => {
    const token = localStorage.getItem('authToken');
    if (token) {
      authApi.getProfile(token)
        .then(userData => setUser(userData))
        .catch(() => localStorage.removeItem('authToken'))
        .finally(() => setLoading(false));
    } else {
      setLoading(false);
    }
  }, []);

  const login = useCallback(async (email, password) => {
    try {
      setError(null);
      setLoading(true);
      const { token, user: userData } = await authApi.login(email, password);
      localStorage.setItem('authToken', token);
      setUser(userData);
    } catch (err) {
      setError(err.message || 'Login failed');
      throw err;
    } finally {
      setLoading(false);
    }
  }, []);

  const logout = useCallback(() => {
    localStorage.removeItem('authToken');
    setUser(null);
    window.location.href = '/login';
  }, []);

  const value = {
    user,
    loading,
    error,
    isAuthenticated: !!user,
    login,
    logout,
  };

  return (
    <AuthContext.Provider value={value}>
      {children}
    </AuthContext.Provider>
  );
}

// Custom Hook — use in any component
export function useAuth() {
  const context = useContext(AuthContext);
  if (!context) {
    throw new Error('useAuth must be used within AuthProvider');
  }
  return context;
}

// LoginPage.jsx
function LoginPage() {
  const { login, loading, error } = useAuth();
  const [email, setEmail] = useState('');
  const [password, setPassword] = useState('');

  const handleSubmit = async (e) => {
    e.preventDefault();
    await login(email, password);
    navigate('/dashboard');
  };

  return (
    <form onSubmit={handleSubmit}>
      {error && <div className="error">{error}</div>}
      <input value={email} onChange={e => setEmail(e.target.value)} />
      <input type="password" value={password} onChange={e => setPassword(e.target.value)} />
      <button disabled={loading}>{loading ? 'Logging in...' : 'Login'}</button>
    </form>
  );
}

// ─────────────────────────────────────────────
// Dashboard.jsx — protected page
function Dashboard() {
  const { user, logout, isAuthenticated } = useAuth();

  if (!isAuthenticated) return <Navigate to="/login" />;

  return (
    <div>
      <h1>Welcome, {user.name}!</h1>
      <button onClick={logout}>Logout</button>
    </div>
  );
}

Interview Q&A
Hook Interview Questions
Q: What are React Hooks and why were they introduced?
A: Hooks are functions that let you use React state and lifecycle in functional components. Introduced in React 16.8 to solve: (1) Reusing stateful logic was hard (HOCs/render props were complex), (2) Complex class components were hard to understand, (3) Classes confuse both people and machines (this binding, minification issues).
Q: What are the rules of Hooks?
A: Two rules: (1) Only call at the top level — never inside loops, conditions, or nested functions. React relies on call order. (2) Only call from React functions — functional components or custom hooks. Not from regular JS functions or class components.
Q: What's the difference between useMemo and useCallback?
A: useMemo(() => value, [deps]) memoizes a computed value (result of expensive calculation). useCallback(() => {}, [deps]) memoizes a function reference (prevents recreation on every render). Essentially: useCallback(fn, deps) equals useMemo(() => fn, deps).
Q: When would you use useReducer over useState?
A: Use useReducer when: (1) State has multiple sub-values that update together, (2) Next state depends on previous state in complex ways, (3) You want to separate update logic from the component, (4) State transitions are complex (state machines). For simple, independent state values, useState is simpler.
Q: What is a Custom Hook? Give an example.
A: A custom hook is a function starting with use that calls other hooks to encapsulate reusable stateful logic. Example: useFetch(url) returns {data, loading, error} by internally using useState and useEffect. Each component using useFetch gets independent state — the logic is shared, not the state.
Q: What's the difference between useEffect and useLayoutEffect?
A: useEffect runs asynchronously after paint — doesn't block visual updates. useLayoutEffect runs synchronously before paint — blocks rendering until complete. Use useLayoutEffect only when you need to measure DOM or prevent visual flickering (e.g., tooltip positioning, animations).
Q: How do you prevent infinite loops in useEffect?
A: Infinite loops happen when: (1) No dependency array → runs every render, (2) Updating state that's also a dependency, (3) Objects/arrays in deps (new reference each render). Solutions: Add correct deps array, use functional setState, memoize objects with useMemo, or use useRef to track values without triggering re-renders.
Q: What is the purpose of the cleanup function in useEffect?
A: The cleanup function runs: (1) Before the effect re-runs (when deps change), and (2) When the component unmounts. It's used to prevent memory leaks by cleaning up subscriptions, timers, event listeners, and aborting pending fetch requests. Without cleanup, these continue running after the component is gone.
