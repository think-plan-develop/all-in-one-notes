🧩 useMemo at a Glance
💾
Caches: The result of an expensive computation between renders.
🔁
Recomputes: Only when one of its dependencies actually changes.
⚖️
Returns: A memoized value — not a function (that's useCallback).
🎯
Use when: Computation is genuinely expensive and deps change rarely.
🧠 useMemo
useMemo — Memoize Expensive Computations
useMemo caches (memoizes) the result of an expensive calculation and only recomputes it when its dependencies change. It returns a value.
const memoizedValue = useMemo(() => computeExpensive(a, b), [a, b]);
💡 Tip: Don't overuse useMemo! Only use it when: (1) Computation is actually expensive, (2) Dependencies change rarely compared to renders. Premature memoization adds complexity for no performance gain.
🛒 Real-World Example 1
Product Filtering & Sorting (E-commerce)

📋 Scenario

An e-commerce website displays 10,000+ products. Users can search products, filter by category, filter by price, and sort by price or rating. Every time the parent component re-renders (e.g., opening a sidebar or toggling dark mode), filtering and sorting all products again is expensive.

❌ Without useMemo

ProductList.jsx 
const filteredProducts = products
  .filter(product =>
    product.name.toLowerCase().includes(search.toLowerCase())
  )
  .sort((a, b) => a.price - b.price);

// This runs on every render.

✅ With useMemo

ProductList.jsx 
const filteredProducts = useMemo(() => {
  return products
    .filter(product =>
      product.name.toLowerCase().includes(search.toLowerCase())
    )
    .sort((a, b) => a.price - b.price);
}, [products, search]);
💡 Interview Answer: In my e-commerce project, I used useMemo to memoize filtered and sorted products. This prevented recalculating thousands of products whenever unrelated state changed.
🗂️ Real-World Example 2
DataGrid Filtering (Admin Panel)

📋 Scenario

A DataGrid contains 50,000 employees. It needs a search box, a department filter, and a status filter. Recomputing the filtered list on every render (e.g., when the admin toggles a sidebar or opens a modal) would be slow.

❌ Without useMemo

EmployeeGrid.jsx 
const filteredEmployees = employees.filter(emp => {
  const matchesSearch = emp.name.toLowerCase().includes(search.toLowerCase());
  const matchesDept = department === 'All' || emp.department === department;
  const matchesStatus = status === 'All' || emp.status === status;
  return matchesSearch && matchesDept && matchesStatus;
});

// Runs on every render — even unrelated ones (e.g. sidebar toggle)

✅ With useMemo

EmployeeGrid.jsx 
import { useState, useMemo } from 'react';

function EmployeeGrid({ employees }) {
  const [search, setSearch] = useState('');
  const [department, setDepartment] = useState('All');
  const [status, setStatus] = useState('All');

  // ✅ Only recalculates when employees, search, department or status change
  const filteredEmployees = useMemo(() => {
    return employees.filter(emp => {
      const matchesSearch = emp.name.toLowerCase().includes(search.toLowerCase());
      const matchesDept = department === 'All' || emp.department === department;
      const matchesStatus = status === 'All' || emp.status === status;
      return matchesSearch && matchesDept && matchesStatus;
    });
  }, [employees, search, department, status]);

  return (
    <div>
      <input value={search} onChange={e => setSearch(e.target.value)}
             placeholder="Search employees..." />
      {filteredEmployees.map(emp => <p key={emp.id}>{emp.name}</p>)}
    </div>
  );
}
💡 Interview Answer: On a 50,000-row DataGrid, I used useMemo to memoize the filtered list based on search, department, and status. This kept filtering fast and avoided recomputation when unrelated UI state changed.
