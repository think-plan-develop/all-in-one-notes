Performance Overview
Why Performance Optimization Matters
React re-renders components whenever state or props change. In large apps, unnecessary re-renders cause lag, stuttering, and poor UX. Performance optimization prevents wasted renders, reduces bundle size, and ensures smooth 60fps interactions.

📝 Rule of Thumb: Don't optimize prematurely. First build it correctly, then measure with React DevTools Profiler, then optimize the actual bottlenecks. Premature optimization adds complexity without real benefit.
React.memo
React.memo — Prevent Unnecessary Re-renders
React.memo() is a Higher Order Component (HOC) that wraps a component and skips re-rendering if its props haven't changed. It does a shallow comparison of previous and next props.
const MemoizedComponent = React.memo(MyComponent);

Basic Usage

ExpensiveList.jsx 
import { memo } from 'react';

// ❌ Without memo — re-renders EVERY time parent renders
function ProductCard({ name, price, image }) {
  console.log('ProductCard rendered:', name);
  return (
    <div className="card">
      <img src={image} alt={name} />
      <h3>{name}</h3>
      <p>₹{price}</p>
    </div>
  );
}

// ✅ With memo — only re-renders if name, price, or image changes
const MemoizedProductCard = memo(ProductCard);

// Parent component
function ProductList() {
  const [searchTerm, setSearchTerm] = useState('');
  const products = useProducts();

  return (
    <div>
      <input value={searchTerm} onChange={e => setSearchTerm(e.target.value)} />
      {/* Each card WON'T re-render when searchTerm changes */}
      {products.map(p => (
        <MemoizedProductCard key={p.id} name={p.name} price={p.price} image={p.img} />
      ))}
    </div>
  );
}

Custom Comparison Function

CustomComparison.jsx 
// Custom areEqual function for deep/partial comparison
const UserCard = memo(
  function UserCard({ user, onSelect }) {
    return <div onClick={() => onSelect(user.id)}>{user.name}</div>;
  },
  // Second argument: custom comparison
  (prevProps, nextProps) => {
    // Return TRUE = DON'T re-render (props are "equal")
    // Return FALSE = DO re-render (props changed)
    return prevProps.user.id === nextProps.user.id
        && prevProps.user.name === nextProps.user.name;
  }
);

When React.memo Breaks (Common Pitfall)

MemoBreaks.jsx 
function Parent() {
  const [count, setCount] = useState(0);

  // ❌ New object reference every render → memo useless!
  const style = { color: 'red' };
  
  // ❌ New function reference every render → memo useless!
  const handleClick = () => console.log('clicked');

  return (
    <div>
      <button onClick={() => setCount(count + 1)}>Count: {count}</button>
      {/* ❌ MemoChild re-renders because style/onClick are NEW refs */}
      <MemoChild style={style} onClick={handleClick} />
    </div>
  );
}

// ✅ FIX: Use useMemo for objects, useCallback for functions
function ParentFixed() {
  const [count, setCount] = useState(0);
  const style = useMemo(() => ({ color: 'red' }), []);
  const handleClick = useCallback(() => console.log('clicked'), []);

  return (
    <div>
      <button onClick={() => setCount(count + 1)}>Count: {count}</button>
      {/* ✅ MemoChild skips re-render — same refs */}
      <MemoChild style={style} onClick={handleClick} />
    </div>
  );
}
⚠️ React.memo is useless if you pass:
• Inline objects: style={{ color: 'red' }} — new ref each render
• Inline functions: onClick={() => doSomething()} — new ref each render
• Spread props: {...props} — new object
Fix: Combine memo with useMemo (objects) and useCallback (functions).
useMemo
useMemo — Cache Expensive Computations
useMemo() caches the result of a computation and only recalculates when its dependencies change. Use it for expensive calculations (filtering, sorting large arrays, complex math) that don't need to run every render.
const cachedValue = useMemo(() => computeExpensiveValue(a, b), [a, b]);
FilteredProducts.jsx 
import { useMemo, useState } from 'react';

function ProductList({ products }) {
  const [search, setSearch] = useState('');
  const [sortBy, setSortBy] = useState('name');
  const [theme, setTheme] = useState('light'); // unrelated state

  // ❌ Without useMemo — runs EVERY render (even theme change!)
  // const filtered = products.filter(...).sort(...);

  // ✅ With useMemo — only recalculates when search/sortBy/products change
  const filteredProducts = useMemo(() => {
    console.log('Filtering 10,000 products...'); // only runs when deps change
    return products
      .filter(p => p.name.toLowerCase().includes(search.toLowerCase()))
      .sort((a, b) => {
        if (sortBy === 'name') return a.name.localeCompare(b.name);
        if (sortBy === 'price') return a.price - b.price;
        return 0;
      });
  }, [products, search, sortBy]); // Dependencies

  return (
    <div>
      <input value={search} onChange={e => setSearch(e.target.value)} />
      <button onClick={() => setTheme(theme === 'light' ? 'dark' : 'light')}>Toggle</button>
      {filteredProducts.map(p => <ProductCard key={p.id} {...p} />)}
    </div>
  );
}

When to Use useMemo

✅ Use When❌ Don't Use When

Complex mathematical computationsCreating simple strings or numbers
Creating derived state from expensive transformsThe component rarely re-renders anyway

💡 Remember: useMemo caches values, useCallback caches functions. They both use the same dependency array pattern. useCallback(fn, deps) is identical to useMemo(() => fn, deps).
useCallback
useCallback — Cache Function References
useCallback() returns a memoized version of a function that only changes when its dependencies change. Its primary purpose is to prevent child components (wrapped in React.memo) from re-rendering due to new function references.
const memoizedFn = useCallback(() => { doSomething(a, b); }, [a, b]);
TodoApp.jsx 
import { useState, useCallback, memo } from 'react';

// Memoized child — skips re-render if props unchanged
const TodoItem = memo(function TodoItem({ todo, onToggle, onDelete }) {
  console.log('Rendering:', todo.text);
  return (
    <li>
      <input type="checkbox" checked={todo.done} onChange={() => onToggle(todo.id)} />
      <span>{todo.text}</span>
      <button onClick={() => onDelete(todo.id)}>🗑️</button>
    </li>
  );
});

function TodoApp() {
  const [todos, setTodos] = useState([]);
  const [input, setInput] = useState('');

  // ✅ Stable function reference — TodoItem won't re-render unnecessarily
  const handleToggle = useCallback((id) => {
    setTodos(prev => prev.map(t =>
      t.id === id ? { ...t, done: !t.done } : t
    ));
  }, []); // No deps — uses functional updater

  const handleDelete = useCallback((id) => {
    setTodos(prev => prev.filter(t => t.id !== id));
  }, []);

  const handleAdd = useCallback(() => {
    if (!input.trim()) return;
    setTodos(prev => [...prev, { id: Date.now(), text: input, done: false }]);
    setInput('');
  }, [input]); // depends on input value

  return (
    <div>
      <input value={input} onChange={e => setInput(e.target.value)} />
      <button onClick={handleAdd}>Add</button>
      <ul>
        {todos.map(todo => (
          <TodoItem
            key={todo.id}
            todo={todo}
            onToggle={handleToggle}
            onDelete={handleDelete}
          />
        ))}
      </ul>
    </div>
  );
}

Lazy Loading
React.lazy() — Load Components On Demand
React.lazy() lets you define a component that is loaded dynamically — its code is fetched only when it's first rendered. This reduces the initial bundle size by splitting code into smaller chunks that load on demand.
const LazyComponent = React.lazy(() => import('./HeavyComponent'));
App.jsx — Lazy Loading Pages 
import { lazy, Suspense } from 'react';
import { Routes, Route } from 'react-router-dom';

// These components load ONLY when their route is visited
const Home = lazy(() => import('./pages/Home'));
const Dashboard = lazy(() => import('./pages/Dashboard'));
const Analytics = lazy(() => import('./pages/Analytics'));
const Settings = lazy(() => import('./pages/Settings'));

function App() {
  return (
    <Suspense fallback={<LoadingSpinner />}>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/dashboard" element={<Dashboard />} />
        <Route path="/analytics" element={<Analytics />} />
        <Route path="/settings" element={<Settings />} />
      </Routes>
    </Suspense>
  );
}

📝 Requirements: React.lazy() only works with default exports. If your component uses named exports, create a re-export file: export { MyComponent as default } from './MyComponent'.
Suspense
Suspense — Loading Fallback UI
<Suspense> wraps lazy-loaded components and displays a fallback UI (spinner, skeleton, placeholder) while the component's code is being loaded. Without Suspense, lazy components throw an error.
SuspenseExamples.jsx 
import { lazy, Suspense } from 'react';

const HeavyChart = lazy(() => import('./HeavyChart'));
const DataTable = lazy(() => import('./DataTable'));

// ─── Example 1: Single Suspense for whole page ───
function DashboardPage() {
  return (
    <Suspense fallback={<PageSkeleton />}>
      <HeavyChart />
      <DataTable />
    </Suspense>
  );
}

// ─── Example 2: Granular Suspense boundaries ───
function DashboardPageGranular() {
  return (
    <div>
      <h1>Dashboard</h1>
      
      {/* Chart loads independently */}
      <Suspense fallback={<ChartSkeleton />}>
        <HeavyChart />
      </Suspense>

      {/* Table loads independently */}
      <Suspense fallback={<TableSkeleton />}>
        <DataTable />
      </Suspense>
    </div>
  );
}

// ─── Example 3: Loading spinner component ───
function LoadingSpinner() {
  return (
    <div className="spinner-container">
      <div className="spinner" />
      <p>Loading...</p>
    </div>
  );
}

Code Splitting
Code Splitting — Smaller Bundles, Faster Loads
Code Splitting breaks your app into smaller JavaScript chunks that load on demand. Instead of shipping one massive bundle, the browser downloads only what's needed for the current page. Achieved via React.lazy() + dynamic import().

Code Splitting Strategies

Strategy 1: Route-based Splitting 
// Most common — split by ROUTE (page-level)
const Home = lazy(() => import('./pages/Home'));
const Shop = lazy(() => import('./pages/Shop'));
const Admin = lazy(() => import('./pages/Admin'));

// Each page = separate chunk file
// → home.chunk.js, shop.chunk.js, admin.chunk.js
Strategy 2: Component-based Splitting 
// Split heavy components (charts, editors, PDF viewers)
const RichTextEditor = lazy(() => import('./components/RichTextEditor'));
const PdfViewer = lazy(() => import('./components/PdfViewer'));
const MapWidget = lazy(() => import('./components/MapWidget'));

function DocumentPage({ showEditor }) {
  return (
    <div>
      <h1>Document</h1>
      {showEditor && (
        <Suspense fallback={<p>Loading editor...</p>}>
          <RichTextEditor />
        </Suspense>
      )}
    </div>
  );
}
Strategy 3: Conditional / Feature-based Splitting 
// Load features only when user needs them
function Dashboard() {
  const [showReport, setShowReport] = useState(false);

  const handleGenerateReport = async () => {
    // Dynamic import on user action
    const { generatePDF } = await import('./utils/pdfGenerator');
    const pdf = generatePDF(data);
    downloadFile(pdf);
  };

  return (
    <div>
      <button onClick={handleGenerateReport}>Generate PDF Report</button>
    </div>
  );
}

Image Optimization
Image Optimization in React
Images are often the largest assets on a page (60-70% of total page weight). Optimizing images means: using modern formats (WebP/AVIF), lazy loading offscreen images, responsive sizes, and proper compression — resulting in dramatically faster page loads.

1. Lazy Loading Images (Native)

LazyImage.jsx 
// ✅ Native browser lazy loading — simplest approach
function ProductCard({ product }) {
  return (
    <div className="product-card">
      <img
        src={product.image}
        alt={product.name}
        loading="lazy"           {/* ← Browser handles lazy load */}
        width={300}
        height={200}            {/* ← Prevents layout shift (CLS) */}
        decoding="async"        {/* ← Non-blocking decode */}
      />
      <h3>{product.name}</h3>
    </div>
  );
}

// ⚠️ DON'T lazy load above-the-fold images (hero, logo)
// Use loading="eager" (default) for critical images

3. Intersection Observer (Custom Lazy Load)

useLazyImage.js — Custom Hook 
import { useState, useEffect, useRef } from 'react';

function useLazyImage(src, placeholder = '') {
  const [imageSrc, setImageSrc] = useState(placeholder);
  const [isLoaded, setIsLoaded] = useState(false);
  const imgRef = useRef(null);

  useEffect(() => {
    const observer = new IntersectionObserver(
      ([entry]) => {
        if (entry.isIntersecting) {
          // Image is in viewport — start loading
          const img = new Image();
          img.src = src;
          img.onload = () => {
            setImageSrc(src);
            setIsLoaded(true);
          };
          observer.disconnect();
        }
      },
      { rootMargin: '200px' } // Start loading 200px before visible
    );

    if (imgRef.current) observer.observe(imgRef.current);
    return () => observer.disconnect();
  }, [src]);

  return { imgRef, imageSrc, isLoaded };
}

// Usage:
function LazyImage({ src, alt, placeholder }) {
  const { imgRef, imageSrc, isLoaded } = useLazyImage(src, placeholder);
  return (
    <img
      ref={imgRef}
      src={imageSrc}
      alt={alt}
      style={{ opacity: isLoaded ? 1 : 0.5, transition: 'opacity 0.3s' }}
    />
  );
}

5. Preventing Layout Shift (CLS)

PreventCLS.jsx 
// ❌ BAD — No dimensions → layout jumps when image loads
<img src="photo.jpg" alt="Product" />

// ✅ GOOD — Fixed dimensions → space reserved
<img src="photo.jpg" alt="Product" width={400} height={300} />

// ✅ GOOD — CSS aspect ratio container
<div style={{ aspectRatio: '16/9', overflow: 'hidden' }}>
  <img src="photo.jpg" style={{ width: '100%', height: '100%', objectFit: 'cover' }} />
</div>

// ✅ GOOD — Blur-up placeholder (like Medium/Instagram)
function BlurImage({ src, blurSrc, alt }) {
  const [loaded, setLoaded] = useState(false);
  return (
    <div style={{ position: 'relative' }}>
      <img
        src={blurSrc}  {/* tiny 20px blurred placeholder */}
        style={{ filter: loaded ? 'none' : 'blur(20px)', transition: 'filter 0.5s' }}
      />
      <img
        src={src}
        alt={alt}
        onLoad={() => setLoaded(true)}
        style={{ position: 'absolute', top: 0, opacity: loaded ? 1 : 0 }}
      />
    </div>
  );
}

6. Image Optimization Checklist

✅ Production Image Checklist:
• Use WebP/AVIF with JPEG fallback via <picture>
• Always set width/height or aspect-ratio (prevent CLS)
• Lazy load below-the-fold images (loading="lazy")
• Eager load above-the-fold (hero, logo, LCP image)
• Use srcSet for responsive sizes (don't serve 2000px on mobile)
• Compress images (TinyPNG, Squoosh, Sharp)
• Use CDN with auto-format/resize (Cloudinary, imgix, Vercel Image)
• Use SVG for icons/logos (infinitely scalable, tiny size)
• Add decoding="async" for non-critical images
• Preload critical images: <link rel="preload" as="image" href="hero.webp">
Real Project Example
Real Project: Optimized E-Commerce Product Grid

Combining all performance techniques: memo, useCallback, lazy loading, virtualization, and image optimization for a product listing with 1000+ items.

OptimizedProductGrid.jsx 
import { useState, useMemo, useCallback, memo, lazy, Suspense } from 'react';

// Lazy-load the detail modal (heavy: images, reviews, charts)
const ProductDetailModal = lazy(() => import('./ProductDetailModal'));

// ─── Memoized Product Card ───
const ProductCard = memo(function ProductCard({ product, onAddToCart, onViewDetail }) {
  console.log('Render:', product.name); // only logs when THIS card's data changes
  return (
    <div className="product-card">
      <img
        src={product.thumbnail}
        alt={product.name}
        loading="lazy"
        width={280}
        height={280}
        decoding="async"
      />
      <h3>{product.name}</h3>
      <p>₹{product.price.toLocaleString()}</p>
      <button onClick={() => onAddToCart(product.id)}>Add to Cart</button>
      <button onClick={() => onViewDetail(product.id)}>View</button>
    </div>
  );
});

// ─── Main Grid Component ───
function ProductGrid({ products }) {
  const [search, setSearch] = useState('');
  const [sortBy, setSortBy] = useState('relevance');
  const [selectedId, setSelectedId] = useState(null);

  // ✅ useMemo: expensive filter+sort on 1000+ products
  const filteredProducts = useMemo(() => {
    let result = products.filter(p =>
      p.name.toLowerCase().includes(search.toLowerCase())
    );
    if (sortBy === 'price-asc') result.sort((a,b) => a.price - b.price);
    if (sortBy === 'price-desc') result.sort((a,b) => b.price - a.price);
    if (sortBy === 'rating') result.sort((a,b) => b.rating - a.rating);
    return result;
  }, [products, search, sortBy]);

  // ✅ useCallback: stable references for memo'd children
  const handleAddToCart = useCallback((productId) => {
    dispatch({ type: 'ADD_TO_CART', payload: productId });
  }, []);

  const handleViewDetail = useCallback((id) => {
    setSelectedId(id);
  }, []);

  return (
    <div>
      <input
        placeholder="Search products..."
        value={search}
        onChange={e => setSearch(e.target.value)}
      />
      <select value={sortBy} onChange={e => setSortBy(e.target.value)}>
        <option value="relevance">Relevance</option>
        <option value="price-asc">Price: Low to High</option>
        <option value="price-desc">Price: High to Low</option>
        <option value="rating">Top Rated</option>
      </select>

      <div className="grid">
        {filteredProducts.map(product => (
          <ProductCard
            key={product.id}
            product={product}
            onAddToCart={handleAddToCart}
            onViewDetail={handleViewDetail}
          />
        ))}
      </div>

      {/* Lazy-loaded modal — only fetches JS when user clicks "View" */}
      {selectedId && (
        <Suspense fallback={<ModalSkeleton />}>
          <ProductDetailModal
            productId={selectedId}
            onClose={() => setSelectedId(null)}
          />
        </Suspense>
      )}
    </div>
  );
}
Interview Q&A
Performance Interview Questions
Q: What is React.memo and when should you use it?
A: React.memo() is a HOC that memoizes a component — it skips re-rendering if props haven't changed (shallow comparison). Use it for: (1) Components that receive the same props frequently, (2) Components that are expensive to render (large lists, complex UI), (3) Components that re-render often due to parent updates. Don't use it for components that almost always receive new props.
Q: What's the difference between useMemo and useCallback?
A: useMemo caches a computed value (runs the function and stores the result). useCallback caches the function itself (stores the function reference without executing it). useCallback(fn, deps) is equivalent to useMemo(() => fn, deps). Use useMemo for expensive calculations, useCallback for stabilizing function references passed to memo'd children.
Q: Why does passing inline functions break React.memo?
A: Because () => doSomething() creates a new function reference on every render. React.memo does shallow comparison — different reference = different prop = re-render. Fix: wrap the function with useCallback to maintain a stable reference across renders.
Q: What is code splitting and how does React implement it?
A: Code splitting breaks a large bundle into smaller chunks loaded on demand. React implements it via React.lazy() + dynamic import(). When a lazy component is first rendered, its chunk is fetched from the server. Combined with <Suspense> for loading states. The bundler (Webpack/Vite) automatically creates separate files for each import() call.
Q: What is the purpose of Suspense in React?
A: <Suspense> provides a fallback UI while waiting for lazy-loaded components (or data in React 18+). It catches the "suspending" state and displays a placeholder (spinner/skeleton) until the async content is ready. Without Suspense, lazy components throw an error. You can have multiple Suspense boundaries for granular loading.
Q: How do you prevent layout shift (CLS) with images?
A: Always specify width and height attributes on images (or use CSS aspect-ratio). This reserves space before the image loads, preventing content from jumping. Also use blur-up placeholders (tiny base64 preview) or skeleton containers with fixed dimensions. This directly improves Core Web Vitals CLS score.
Q: What are the best image formats for web and when to use each?
A: WebP: best default for all images (25-35% smaller than JPEG, 96% browser support). AVIF: best compression for photos (50% smaller, ~90% support). SVG: for icons/logos (vector, infinitely scalable, tiny size). PNG: only when transparency is needed and WebP isn't supported. Use <picture> with AVIF source → WebP source → JPEG fallback.
Q: When should you NOT use useMemo/useCallback?
A: Don't use them for: (1) Simple/cheap calculations (a + b, string concat), (2) Values that change every render (all deps change), (3) Components that don't pass functions to memo'd children, (4) Premature optimization without measuring first. They have overhead (storing previous values, comparing deps). Only optimize when you've measured a real performance problem with React DevTools Profiler.
Q: How do you measure React performance?
A: (1) React DevTools Profiler: records renders, shows which components re-rendered and why. (2) Chrome DevTools Performance tab: flame chart of JS execution. (3) Lighthouse: Core Web Vitals (LCP, FID, CLS). (4) why-did-you-render: library that logs unnecessary re-renders. (5) Bundle analyzer: visualize chunk sizes. Always measure before and after optimizing.
