CRUD Deep Dive

$set vs Direct Assignment

$set updates only the specified fields, preserving everything else. Without it, MongoDB replaces the entire document — any omitted fields are lost. Always use $set for partial updates.

// Safe
db.users.updateOne(
  { _id: id },
  { $set: { age: 25 } }
);

// Unsafe — replaces entire document
db.users.updateOne(
  { _id: id },
  { age: 25 }
);

Upsert

Combines Update + Insert. With upsert: true, MongoDB updates a matching document, or inserts a new one if none exists.

db.users.updateOne(
  { email: "john@example.com" },
  { $set: { name: "John" } },
  { upsert: true }
);

Soft Delete Pattern

Instead of permanently deleting, mark documents with isDeleted / deletedAt. Enables recovery, keeps audit history, and prevents accidental data loss.

db.users.updateOne(
  { _id: id },
  { $set: { isDeleted: true, deletedAt: new Date() } }
);

// Read only active users
db.users.find({ isDeleted: { $ne: true } });

Pagination

Return data in chunks with .skip() + .limit(), combined with .sort() for consistent ordering. Use countDocuments() for totals.

User.find()
  .sort({ createdAt: -1 })
  .skip((page - 1) * limit)
  .limit(limit);

const total = await User.countDocuments();

populate()

Replaces an ObjectId reference with the actual document from another collection — similar to a SQL JOIN.

Post.find().populate("author");

Duplicate Key Errors

Occurs when a unique index is violated (e.g. duplicate email). MongoDB returns error code 11000 — handle it gracefully.

try {
  await User.create(data);
} catch (err) {
  if (err.code === 11000) {
    return res.status(409).json({ message: "Email already exists" });
  }
}

CRUD Best Practices

Return the Updated Document

findByIdAndUpdate() returns the old document by default. Pass { new: true } to get the updated one.

User.findByIdAndUpdate(id, updateData, { new: true });

Enable Validation During Updates

Mongoose validators don't run on updates unless runValidators: true is set.

User.findByIdAndUpdate(id, updateData, { new: true, runValidators: true });

Hide Sensitive Fields

Never expose passwords or tokens in API responses — exclude them with .select().

User.find().select("-password -refreshToken");

Index Frequently Queried Fields

Indexes speed up lookups on fields like email, username, or userId.

userSchema.index({ email: 1 });

Return Only Required Fields

Fetch only what the client needs — improves performance and reduces bandwidth.

User.find().select("name email");

Validate Before DB Operations

Validate input with a library like Joi or Zod before touching the database.

const { error } = schema.validate(req.body);
if (error) return res.status(400).json(error.details);

Handle Errors & Check for Missing Documents

Wrap async DB calls in try/catch, and remember methods like findById() return null when nothing matches.

const user = await User.findById(id);
if (!user) return res.status(404).json({ message: "User not found" });

Common CRUD Mistakes

Replacing the Whole Document

Updating without $set replaces the entire document, silently deleting existing fields.

Returning Huge Datasets Without Pagination

Fetching thousands of records at once spikes memory usage and slows the API. Always paginate large collections.

Queries Directly in Controllers

Business logic belongs in service/repository layers — not controllers — for maintainability and testability.

Running Queries Inside Loops — the N+1 Problem

Calling findOne()/findById() inside a loop causes excessive DB calls. Batch with $in instead.

✕ Bad
for (const id of ids) {
  await User.findById(id);
}
✓ Good
User.find({ _id: { $in: ids } });

Returning Sensitive Data

Never expose passwords, tokens, OTPs, or other internal fields in API responses.

CRUD Debugging Tips

Enable Mongoose Debug Mode

Logs every MongoDB query Mongoose executes.

mongoose.set("debug", true);

Verify Index Usage

Use .explain("executionStats") to check whether a query is actually using an index.

db.users.find({ email: "john@example.com" }).explain("executionStats");

Validate ObjectId Before Querying

Prevents a CastError from an invalid ID.

if (!mongoose.isValidObjectId(id)) {
  return res.status(400).json({ message: "Invalid ID" });
}

Log Query Filters

Log the filter object before running a query to catch incorrect or undefined values.

console.log(filter);
User.find(filter);

Test APIs Independently & Register JSON Middleware

Verify requests with Postman before debugging the frontend, and make sure body parsing is enabled — otherwise req.body is undefined.

app.use(express.json());

Frequently Asked Questions

Can all Mongoose CRUD methods be used with async/await?

Yes — every Mongoose query method returns a promise (or thenable), so they all work with async/await.

What happens if an invalid ObjectId is passed?

Mongoose throws a CastError. Validate the ID first with mongoose.isValidObjectId(id).

Is deleteMany({}) safe in production?

No — it deletes every document in the collection. Always provide a filter, or use the soft delete pattern instead.

How do I return only specific fields?

Use .select() to include or exclude fields, e.g. .select("name email -_id").

What is the N+1 Query Problem?

One query followed by many more inside a loop, causing poor performance. Fetch related records in a single query using $in.
