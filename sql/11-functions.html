Part 1 — Functions

Reusable SQL logic stored in the database. Called on demand, return a value or table, encapsulate business rules.

1 What is a Function? & Why do we use them?

A function is a named, reusable block of SQL (or PL/pgSQL) logic stored in the database. You call it with a name, pass optional parameters, and it returns a value — a scalar, a table, or nothing.

✅ One-liner A function is like a method/procedure saved inside PostgreSQL. You write the logic once, call it anywhere — in SELECT, WHERE, triggers, or other functions.

Why use functions?

1
Reusability

Write once, use in queries, triggers, other functions. Change it once — all callers benefit.

2
Encapsulate business logic

Tax calculation, discount rules, age computation — lives in DB, not scattered across apps.

3
Security

Grant EXECUTE on a function instead of SELECT on tables. Users call the function without seeing the tables.

4
Reduce network round-trips

Execute complex multi-step logic in one DB call instead of many back-and-forth queries from the app.

5
Used in Triggers

Every trigger calls a trigger function. Functions are the engine behind trigger logic.

why_functions.sql
PostgreSQL
-- Without function: repeated everywhere
SELECT name, (price * 1.18) AS price_with_gst
FROM products;

-- With function: logic in one place
CREATE OR REPLACE FUNCTION add_gst(price NUMERIC)
RETURNS NUMERIC AS $$
  SELECT price * 1.18;
$$ LANGUAGE sql;

SELECT name, add_gst(price) AS price_with_gst
FROM products;

-- Change GST rate once — all queries update
2 CREATE FUNCTION — Syntax, Parameters, Return Types, Calling

Full anatomy of a function

function_anatomy.sql
PostgreSQL
CREATE OR REPLACE FUNCTION function_name (
  param1  data_type,             -- IN param (default)
  param2  data_type  DEFAULT 0, -- optional param with default
  OUT result data_type           -- OUT param (alternate return style)
)
RETURNS return_type             -- NUMERIC, TEXT, TABLE, VOID, SETOF ...
LANGUAGE plpgsql                -- sql | plpgsql | python | javascript
SECURITY DEFINER                -- run as owner (INVOKER = run as caller)
STABLE                          -- VOLATILE | STABLE | IMMUTABLE
AS $$
  -- function body here
  DECLARE
    var1 NUMERIC;               -- local variables
  BEGIN
    -- logic
    RETURN var1;
  END;
$$;

LANGUAGEsql, plpgsql, plpython3uLanguage the body is written in

Parameters — IN, OUT, INOUT, DEFAULT

function_params.sql
PostgreSQL
-- IN param (default) — input only
CREATE OR REPLACE FUNCTION square(n NUMERIC)
RETURNS NUMERIC LANGUAGE sql AS $$
  SELECT n * n;
$$;
SELECT square(5);  -- 25

-- DEFAULT param — optional
CREATE OR REPLACE FUNCTION greet(name TEXT, greeting TEXT DEFAULT 'Hello')
RETURNS TEXT LANGUAGE sql AS $$
  SELECT greeting || ', ' || name || '!';
$$;
SELECT greet('Aman');              -- 'Hello, Aman!'
SELECT greet('Aman', 'Namaste');  -- 'Namaste, Aman!'

-- OUT params — multiple return values without a composite type
CREATE OR REPLACE FUNCTION min_max(
  arr    NUMERIC[],
  OUT minimum NUMERIC,
  OUT maximum NUMERIC
) LANGUAGE sql AS $$
  SELECT MIN(x), MAX(x) FROM unnest(arr) x;
$$;
SELECT * FROM min_max(ARRAY[3,1,7,2]);  -- minimum=1, maximum=7

Calling functions

calling_functions.sql
PostgreSQL
-- In SELECT
SELECT add_gst(price) FROM products;
SELECT UPPER(name), square(age) FROM users;

-- In WHERE
SELECT * FROM products WHERE add_gst(price) < 1000;

-- Standalone call (VOID functions or table-returning)
SELECT my_void_function();
SELECT * FROM get_active_users();

-- Named parameter style
SELECT greet(name => 'Aman', greeting => 'Hey');

-- Drop function
DROP FUNCTION IF EXISTS square(NUMERIC);
DROP FUNCTION IF EXISTS greet(TEXT, TEXT);  -- must specify param types if overloaded
3 Function Types — Scalar, Table-Returning, Void, Aggregate
🔢 Scalar Function — returns one value
Returns a single value of any type. Used in SELECT, WHERE, expressions. Most common type.
scalar.sql
PostgreSQL
CREATE OR REPLACE FUNCTION
  full_name(first TEXT, last TEXT)
RETURNS TEXT
LANGUAGE sql IMMUTABLE AS $$
  SELECT first || ' ' || last;
$$;

SELECT full_name('Aman', 'Sharma');
-- → 'Aman Sharma'

CREATE OR REPLACE FUNCTION
  age_in_years(dob DATE)
RETURNS INT
LANGUAGE sql STABLE AS $$
  SELECT DATE_PART('year',
    AGE(CURRENT_DATE, dob))::INT;
$$;
📋 Table-Returning Function — returns rows
Returns a result set. Used with SELECT * FROM fn(). Two styles: RETURNS TABLE or RETURNS SETOF.
table_fn.sql
PostgreSQL
-- RETURNS TABLE style
CREATE OR REPLACE FUNCTION
  get_user_orders(uid INT)
RETURNS TABLE(
  order_id INT,
  total    NUMERIC,
  status   TEXT
)
LANGUAGE sql AS $$
  SELECT id, total, status
  FROM   orders
  WHERE  user_id = uid;
$$;

SELECT * FROM get_user_orders(42);
-- Returns multiple rows like a table
🔇 Void Function — returns nothing
Performs an action (INSERT, UPDATE, logging) and returns nothing. Like a "procedure" in other languages.
void_fn.sql
PostgreSQL
CREATE OR REPLACE FUNCTION
  archive_old_orders(days INT)
RETURNS VOID
LANGUAGE plpgsql AS $$
BEGIN
  INSERT INTO orders_archive
  SELECT * FROM orders
  WHERE created_at < NOW()
       - (days || ' days')::INTERVAL;

  DELETE FROM orders
  WHERE created_at < NOW()
       - (days || ' days')::INTERVAL;
END;
$$;

SELECT archive_old_orders(90);
📊 PL/pgSQL Function — multi-step logic
Full procedural language with variables, IF/ELSE, loops, exception handling. Required for complex logic beyond a single SQL statement.
plpgsql_fn.sql
PostgreSQL
CREATE OR REPLACE FUNCTION
  classify_order(amount NUMERIC)
RETURNS TEXT
LANGUAGE plpgsql IMMUTABLE AS $$
DECLARE
  category TEXT;
BEGIN
  IF    amount >= 10000 THEN category := 'Premium';
  ELSIF amount >= 1000  THEN category := 'Standard';
  ELSE                       category := 'Small';
  END IF;
  RETURN category;
END;
$$;
