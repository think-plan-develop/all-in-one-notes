A stored procedure in PostgreSQL is a set of SQL statements stored inside the database that you can execute whenever required. It is used to perform business operations involving multiple SQL statements — inserting, updating and deleting records together. Unlike triggers, stored procedures are called explicitly using the CALL statement.

1. Why do we use Stored Procedures?

Common industry use cases:

AreaExample
BankingTransfer money between two accounts.
E-commerceProcess an order and update inventory.
Employee managementUpdate employee salaries in bulk.
Transaction managementExecute multiple operations with transaction control.
Data processingPerform bulk insertions or updates.
2. Create a Stored Procedure

Syntax

syntax.sql
CREATE OR REPLACE PROCEDURE procedure_name()
LANGUAGE plpgsql
AS $$
BEGIN

    -- SQL statements

END;
$$;

Example

increase_salary.sql
CREATE OR REPLACE PROCEDURE increase_salary()
LANGUAGE plpgsql
AS $$
BEGIN
    UPDATE employees
    SET salary = salary + 5000;
END;
$$;

Call the procedure:

call.sql
CALL increase_salary();

This increases the salary of every employee by 5000.

Notice that we use CALL, not SELECT, to execute a procedure.
3. Parameters in Stored Procedures

Procedures support three important parameter types.

ParameterPurpose
INReceives input
OUTReturns output
INOUTReceives input and returns modified output

A. IN parameter — pass a value into the procedure

update_employee_salary.sql
CREATE OR REPLACE PROCEDURE update_employee_salary(
    IN emp_id INT,
    IN new_salary NUMERIC
)
LANGUAGE plpgsql
AS $$
BEGIN
    UPDATE employees
    SET salary = new_salary
    WHERE employee_id = emp_id;
END;
$$;

-- Call
CALL update_employee_salary(1, 85000);
  • emp_id receives employee ID.
  • new_salary receives the new salary.

B. OUT parameter — return a value from the procedure

get_employee_count.sql
CREATE OR REPLACE PROCEDURE get_employee_count(
    OUT total_employees INT
)
LANGUAGE plpgsql
AS $$
BEGIN
    SELECT COUNT(*)
    INTO total_employees
    FROM employees;
END;
$$;

-- Call
CALL get_employee_count(NULL);

The procedure returns the employee count through its OUT parameter.

C. INOUT parameter — receive, modify and return

calculate_bonus.sql
CREATE OR REPLACE PROCEDURE calculate_bonus(
    INOUT salary NUMERIC
)
LANGUAGE plpgsql
AS $$
BEGIN
    salary := salary + 5000;
END;
$$;

-- Call
CALL calculate_bonus(50000);   -- Output: 55000
4. Real Industry Example — Bank Money Transfer

A customer transfers ₹5,000 from Account A to Account B. Two operations are needed: deduct ₹5,000 from Account A, and add ₹5,000 to Account B. Both should succeed together — if one fails, neither should be committed.

Step 1 — create table

bank_accounts.sql
CREATE TABLE bank_accounts (
    account_id INT PRIMARY KEY,
    account_holder VARCHAR(100),
    balance NUMERIC(12,2)
);

INSERT INTO bank_accounts VALUES
(1, 'Rahul', 50000),
(2, 'Amit', 30000);

Step 2 — create procedure

transfer_money.sql
CREATE OR REPLACE PROCEDURE transfer_money(
    IN sender_id INT,
    IN receiver_id INT,
    IN amount NUMERIC
)
LANGUAGE plpgsql
AS $$
BEGIN

    -- Validate amount
    IF amount <= 0 THEN
        RAISE EXCEPTION 'Invalid transfer amount';
    END IF;

    -- Check sender balance
    IF NOT EXISTS (
        SELECT 1
        FROM bank_accounts
        WHERE account_id = sender_id
        AND balance >= amount
    ) THEN
        RAISE EXCEPTION 'Insufficient balance or invalid sender';
    END IF;

    -- Deduct from sender
    UPDATE bank_accounts
    SET balance = balance - amount
    WHERE account_id = sender_id;

    -- Add to receiver
    UPDATE bank_accounts
    SET balance = balance + amount
    WHERE account_id = receiver_id;

    IF NOT FOUND THEN
        RAISE EXCEPTION 'Invalid receiver account';
    END IF;

END;
$$;

Step 3 — call procedure

call.sql
CALL transfer_money(1, 2, 5000);

Step 4 — check balances

check.sql
SELECT * FROM bank_accounts;

Expected result:

AccountBeforeAfter
Rahul50,00045,000
Amit30,00035,000
Important: the example uses PostgreSQL’s default transaction behavior. If an error occurs, the current transaction is aborted, so both updates are rolled back when the transaction is rolled back. For concurrent banking transfers, production code also needs proper row locking and additional validation.
5. Transaction Control in Stored Procedures

One important advantage of PostgreSQL procedures is that they can use transaction control in supported execution contexts.

CommandPurpose
BEGINStarts a transaction (SQL transaction command)
COMMITSaves changes
ROLLBACKReverts changes
SAVEPOINTCreates a rollback point
transaction.sql
BEGIN;

UPDATE employees
SET salary = 50000
WHERE employee_id = 1;

ROLLBACK;

The salary change is reverted.

Important: PostgreSQL procedures can use COMMIT and ROLLBACK in permitted contexts, such as a top-level CALL outside an explicit transaction block. Functions cannot perform transaction control.

7. Useful Commands
commands.sql
-- Call procedure
CALL increase_salary();

-- Delete procedure
DROP PROCEDURE increase_salary();

-- View procedures
SELECT routine_name
FROM information_schema.routines
WHERE routine_type = 'PROCEDURE';

-- View procedure definition
SELECT pg_get_functiondef(
    'increase_salary()'::regprocedure
);

TypeRoleExample
