🔴 Step 1 — What is JSONB? (Plain English)

JSONB 1 JSONB from Scratch — The Simple Explanation
🔴 Start HereBeginner

Normally, a database table has fixed columns: name, age, email. Every row has the same structure.

But what if different rows need different fields? A laptop has RAM and CPU. A shirt has size and colour. You'd need a different table for every product type — messy.

JSONB solves this — it lets you store a flexible JSON document inside one column. Each row can have completely different fields inside that column.

🧠 Analogy: A regular column is a printed form — every person fills the same boxes. JSONB is a sticky note — each person can write whatever they need, in any format.
jsonb_intro.sql
-- Create a table with ONE flexible JSONB column CREATE TABLE products ( id SERIAL PRIMARY KEY, name TEXT, details JSONB -- ← the flexible column ); -- Each row can have completely different fields inside 'details' INSERT INTO products (name, details) VALUES ('Laptop', '{"brand":"Dell","ram":16,"cpu":"i7","tags":["work","portable"]}'), ('T-Shirt', '{"brand":"Nike","size":"M","colour":"blue","tags":["fashion"]}'), ('Phone', '{"brand":"Apple","storage":256,"colour":"black","specs":{"camera":"12MP"}}'); -- See the data SELECT name, details FROM products;
✅ JSONB = a flexible document stored inside a database column. PostgreSQL understands its structure — you can query, filter, and index it.
JSON vs JSONB in one line: JSON stores as plain text (slower reads). JSONB stores as binary (faster reads, supports indexes). Always use JSONB.

🔴 Step 2 — Reading Data: The 4 Operators

JSONB 2 The 4 Operators — How to Read JSONB Values
🔴 CriticalOperators

Think of JSONB operators as ways to reach inside the JSON and pull out a value. There are 4 operators — two for single keys, two for deep/nested paths.

->
Get value — stays as JSONB
Use to navigate or chain. Output has quotes around strings.
details->'brand' → "Dell" (JSONB)
->>
Get value — converts to TEXT
Use for final output or WHERE comparison. No quotes around strings.
details->>'brand' → Dell (TEXT)
#>
Get nested value — stays JSONB
Navigate deep into nested objects using a path array.
details#>'{specs,camera}' → "12MP"
#>>
Get nested value — converts to TEXT
Navigate deep and get as TEXT. Best for WHERE filters on nested keys.
details#>>'{specs,camera}' → 12MP
When to use which: -> and #> = navigating / chaining further operations (result is JSONB) ->> and #>> = getting the final value to display or compare (result is TEXT) Simple: one key → use -> or ->> Nested: deep key → use #> or #>>
operators_simple.sql
-- Our data: {"brand":"Dell","ram":16,"specs":{"cpu":"i7"},"tags":["work","portable"]} -- → : get brand as JSONB (notice the quotes in result) SELECT details->'brand' FROM products WHERE name = 'Laptop'; -- Result: "Dell" ← JSONB (has quotes) -- ->> : get brand as TEXT (no quotes, ready to compare) SELECT details->>'brand' FROM products WHERE name = 'Laptop'; -- Result: Dell ← TEXT (no quotes) -- Get nested value: specs → cpu SELECT details#>>'{specs,cpu}' FROM products WHERE name = 'Laptop'; -- Result: i7 -- Get array element by index (0-based for -> on arrays) SELECT details->'tags'->0 FROM products WHERE name = 'Laptop'; -- Result: "work" -- Chain -> to navigate step by step SELECT details->'specs'->>'cpu' FROM products; -- Same as: details#>>'{specs,cpu}'
💡 Simple memory trick: One arrow (->) = JSONB out. Two arrows (->>) = TEXT out. Use ->> in WHERE clauses.

🟡 Step 3 — Filtering Rows by JSONB Values

JSONB 3 WHERE Filters on JSONB — Step by Step
🔴 CriticalFiltering

To filter rows based on values inside JSONB, use ->> (gets value as TEXT) in your WHERE clause. For numbers, you need to cast the TEXT result to a number type.

1
Filter by a string value

Use ->> to extract as TEXT, then compare with =

2
Filter by a number

Extract with ->>, then cast to INT or NUMERIC before comparing

3
Filter by nested value

Use #>> with the path to reach deep keys

4
Check if a key exists at all

Use the ? operator — no value extraction needed

filtering.sql
-- Step 1: Filter by string value SELECT name FROM products WHERE details->>'brand' = 'Dell'; -- Step 2: Filter by number (must cast!) SELECT name FROM products WHERE (details->>'ram')::INT >= 16; -- Notice the cast ::INT — without it "16" > "8" works but "9" > "16" in text! -- Step 3: Filter by nested value SELECT name FROM products WHERE details#>>'{specs,camera}' = '12MP'; -- Step 4: Check if a key exists (? operator) SELECT name FROM products WHERE details ? 'ram'; -- only products that HAVE a 'ram' key -- Combine filters freely SELECT name FROM products WHERE details->>'brand' = 'Dell' AND (details->>'ram')::INT > 8;
⚠️ Most common mistake: Comparing numbers without casting. ->> always returns TEXT, so '9' > '16' is TRUE in text order (alphabetical). Always cast: (col->>'price')::NUMERIC > 100

🟡 Step 4 — Updating JSONB Values

JSONB 4 How to Update JSONB — 3 Tools
🟡 High ImpactUpdate

You have 3 ways to update JSONB. Choose based on what you need:

ToolWhen to useRisk
jsonb_set()Update ONE specific key (anywhere in the object)Safe — touches only that key
|| (merge)Add/overwrite top-level keys⚠️ Replaces nested objects entirely
- (delete)Remove a key from the objectPermanent — key gone
updating.sql
-- Our data: {"brand":"Dell","ram":16,"specs":{"cpu":"i7","cores":8}} ── TOOL 1: jsonb_set — surgical update ────────────────────────── -- Syntax: jsonb_set(column, '{path}', new_value, create_if_missing) -- Update top-level key 'ram' from 16 to 32 UPDATE products SET details = jsonb_set(details, '{ram}', '32'::jsonb) WHERE name = 'Laptop'; -- Result: {"brand":"Dell","ram":32,"specs":{"cpu":"i7","cores":8}} -- Update NESTED key: specs → cpu UPDATE products SET details = jsonb_set(details, '{specs,cpu}', '"i9"'::jsonb) WHERE name = 'Laptop'; -- Result: {"brand":"Dell","ram":32,"specs":{"cpu":"i9","cores":8}} ✅ -- Notice: cores is still there! jsonb_set only touches what you specify. -- Add a new key (4th arg = true means create if not exists) UPDATE products SET details = jsonb_set(details, '{colour}', '"silver"'::jsonb, true) WHERE name = 'Laptop'; ── TOOL 2: || merge — add/overwrite top-level keys ────────────── UPDATE products SET details = details || '{"ram":64,"colour":"black"}'::jsonb WHERE name = 'Laptop'; -- ram updated, colour added, everything else kept -- ⚠️ WARNING: || replaces nested objects entirely! UPDATE products SET details = details || '{"specs":{"cpu":"i9"}}'::jsonb WHERE name = 'Laptop'; -- Result: specs = {"cpu":"i9"} ← "cores" is GONE! || replaces whole sub-object ── TOOL 3: - delete a key ──────────────────────────────────────── UPDATE products SET details = details - 'colour' WHERE name = 'Laptop'; -- Delete at a nested path UPDATE products SET details = details #- '{specs,cores}' WHERE name = 'Laptop';
⚠️ Key gotcha with ||: If you do details || '{"specs":{"cpu":"i9"}}', the entire specs sub-object is replaced. Only the keys you write will survive. Use jsonb_set for nested updates.
✅ Rule of thumb: Always use jsonb_set when updating nested keys. Use || only for top-level key additions/overwrites.

🟡 Step 5 — JSONB Arrays

JSONB 5 Working with Arrays inside JSONB
🟡 High ImpactArrays

JSONB arrays are JSON lists like ["work","portable","gaming"]. You can access elements by index, expand them into rows, append, or remove items.

jsonb_arrays.sql
-- Our data: details = {"brand":"Dell","tags":["work","portable"]} -- Get first element (0-based for array index with ->) SELECT details->'tags'->0 FROM products; -- "work" (JSONB) SELECT details->'tags'->>0 FROM products; -- work (TEXT) SELECT details->'tags'->>-1 FROM products; -- portable (last element) -- Count elements in the array SELECT jsonb_array_length(details->'tags') FROM products; -- → 2 -- Expand array: one row per element SELECT name, tag FROM products, jsonb_array_elements_text(details->'tags') AS tag; -- Laptop | work -- Laptop | portable -- Append a new tag to the array UPDATE products SET details = jsonb_set( details, '{tags}', (details->'tags') || '["gaming"]'::jsonb ) WHERE name = 'Laptop'; -- tags is now: ["work","portable","gaming"] -- Remove "portable" from the array UPDATE products SET details = jsonb_set( details, '{tags}', (SELECT jsonb_agg(t) FROM jsonb_array_elements(details->'tags') t WHERE t::text != '"portable"') ) WHERE name = 'Laptop';
💡 jsonb_array_elements_text() is your best friend for turning a JSONB array into a regular SQL result set you can filter and join with.

🟡 Step 6 — Containment Operators (The Powerful JSONB Ones)

JSONB 6 @>, <@, ?, ?|, ?& — JSONB Superpowers
🔴 CriticalOperators

These operators are unique to JSONB (not available on plain JSON). They work with GIN indexes, making them extremely fast even on millions of rows.

🧠 Analogy: @> is like asking "does this bag contain these specific items?" — you don't care what else is in the bag, just whether those items are present.
OperatorPlain EnglishExample
@>"Contains this sub-document?"details @> '{"brand":"Dell"}'
<@"Is contained inside this?"'{"brand":"Dell"}' <@ details
?"Does this key exist?"details ? 'ram'
?|"Does ANY of these keys exist?"details ?| ARRAY['ram','cpu']
?&"Do ALL of these keys exist?"details ?& ARRAY['ram','brand']
containment.sql
-- @> : Does details contain {"brand":"Dell"} ? SELECT name FROM products WHERE details @> '{"brand":"Dell"}'; -- @> also works on nested objects SELECT name FROM products WHERE details @> '{"specs":{"cpu":"i7"}}'; -- @> also works on arrays: does tags contain "work"? SELECT name FROM products WHERE details @> '{"tags":["work"]}'; -- ? : does 'ram' key exist? SELECT name FROM products WHERE details ? 'ram'; -- ?| : has 'ram' OR 'storage' key? SELECT name FROM products WHERE details ?| ARRAY['ram', 'storage']; -- ?& : must have BOTH 'brand' AND 'tags' SELECT name FROM products WHERE details ?& ARRAY['brand', 'tags'];
✅ @> is the most useful JSONB operator. It checks if a value contains a subset — works on objects, nested objects, and arrays. And it uses GIN indexes automatically.

-- Expand array into rows (most common use) SELECT name, tag FROM products, jsonb_array_elements_text(details->'tags') AS tag; -- See all key-value pairs of a JSONB object SELECT key, value FROM products, jsonb_each_text(details) WHERE name = 'Laptop'; -- Build JSONB from scratch (safe — handles escaping) SELECT jsonb_build_object('name', 'Alice', 'age', 30); -- → {"age": 30, "name": "Alice"} -- Check the type of a JSONB field SELECT jsonb_typeof(details->'tags') FROM products; -- array SELECT jsonb_typeof(details->'ram') FROM products; -- number SELECT jsonb_typeof(details->'brand') FROM products; -- string -- Remove null-value keys SELECT jsonb_strip_nulls('{"a":1,"b":null,"c":3}'::jsonb); -- → {"a": 1, "c": 3} -- Aggregate multiple rows into one JSON array SELECT jsonb_agg(jsonb_build_object('id', id, 'name', name)) FROM products; -- → [{"id":1,"name":"Laptop"},{"id":2,"name":"T-Shirt"},...]

🟡 Step 8 — Indexing JSONB for Speed

JSONB 8 Indexes — How to Make JSONB Queries Fast
🔴 CriticalPerformance

Without an index, PostgreSQL reads every row to find matches — slow on large tables. JSONB supports two index strategies. Choose based on how you query:

1
GIN index on the whole column

Best when you use @>, ?, ?|, ?& on many different keys. One index covers all of them.

2
B-tree index on a specific key

Best when you always filter on the same key with = or range operators. Smaller and faster than GIN for one key.

3
Generated column + B-tree (best of both)

Extract a frequently-used JSONB key into a Generated Column, then put a regular index on it. Lightning fast for that one key.

indexing.sql
── Strategy 1: GIN on whole column ───────────────────────────────── -- Covers: @>, <@, ?, ?|, ?& CREATE INDEX idx_products_details ON products USING GIN (details); -- Now this is fast (GIN used automatically): SELECT * FROM products WHERE details @> '{"brand":"Dell"}'; ── Strategy 2: B-tree on one extracted key ───────────────────────── -- Good when you always filter on 'brand' with = CREATE INDEX idx_products_brand ON products ((details->>'brand')); -- Now this is fast: SELECT * FROM products WHERE details->>'brand' = 'Dell'; ── Strategy 3: Generated Column + B-tree (best for one key) ──────── ALTER TABLE products ADD COLUMN brand TEXT GENERATED ALWAYS AS (details->>'brand') STORED; CREATE INDEX idx_products_brand_gen ON products (brand); -- Very fast — reads a plain column, not JSONB at all: SELECT * FROM products WHERE brand = 'Dell'; ── Check if your query is using the index ────────────────────────── EXPLAIN ANALYZE SELECT * FROM products WHERE details @> '{"brand":"Dell"}'; -- Look for "Bitmap Index Scan" or "Index Scan" (not "Seq Scan")
Index TypeCoversSizeBest for
GIN (default)@>, ?, ?|, ?&LargeMany different keys queried
B-tree (functional)= < > on one keySmallOne frequently-filtered key
Generated + B-tree= < > on one keySmallSame as above but cleaner

⭐ JSONB Interview Scenarios — Real-World Problems Simplified

Scenario 1 — Find users with dark theme (use GIN index)

Q: Users table has a preferences JSONB column. Find all dark-theme users efficiently.

A: Use @> containment — it uses the GIN index. The ->> approach also works but doesn't use GIN.

s1_dark_theme.sql
CREATE INDEX idx_user_prefs ON users USING GIN (preferences); -- ✅ Fast — uses GIN index SELECT id, email FROM users WHERE preferences @> '{"theme":"dark"}'; -- ⚠️ Slower — does NOT use GIN index by default SELECT id, email FROM users WHERE preferences->>'theme' = 'dark';

Scenario 2 — Update nested key safely

Q: Change only the address.city inside a user's profile without losing other address fields.

A: Use jsonb_set with the full path. Never use || for nested updates — it replaces the whole sub-object.

s2_nested_update.sql
-- profile: {"name":"Alice","address":{"city":"Mumbai","country":"India"}} -- ❌ WRONG — destroys 'country' UPDATE users SET profile = profile || '{"address":{"city":"Delhi"}}'; -- Result: {"address":{"city":"Delhi"}} ← country is gone! -- ✅ CORRECT — only city changes UPDATE users SET profile = jsonb_set(profile, '{address,city}', '"Delhi"') WHERE id = 1; -- Result: {"name":"Alice","address":{"city":"Delhi","country":"India"}} ✅

Scenario 3 — Count users per theme setting

Q: Group users by their preferences.theme value and count them.

A: Extract the value with ->> and use GROUP BY on it.

s3_count_theme.sql
SELECT preferences->>'theme' AS theme, COUNT(*) AS total_users FROM users WHERE preferences ? 'theme' -- only rows that have this key GROUP BY preferences->>'theme' ORDER BY total_users DESC;

Scenario 4 — The gotcha: JSON null vs SQL NULL

Q: What is the difference between NULL in SQL and null in JSON when stored in JSONB?

A: SQL NULL means the column has no value at all. JSON null means the column has a JSONB value — and that value is the JSON literal null. The ->> operator returns SQL NULL for both a missing key AND a JSON null value.

s4_null_gotcha.sql
INSERT INTO products (name, details) VALUES ('A', NULL), -- SQL NULL (no JSONB at all) ('B', 'null'::jsonb), -- JSON null (JSONB value that is null) ('C', '{"brand":null}'); -- JSONB object with a null field -- ->> returns SQL NULL for both missing key and json null! SELECT name, details->>'brand' FROM products; -- A: NULL (no jsonb column at all) -- B: NULL (jsonb is null — no 'brand' key) -- C: NULL (brand key exists but its value is json null) -- Detect JSON null specifically with jsonb_typeof SELECT name, jsonb_typeof(details->'brand') FROM products; -- A: NULL (no jsonb) -- B: NULL (jsonb is null, no 'brand' key) -- C: 'null' (key exists, value is json null)
⚠️ This is the #1 JSONB interview trap. Always use jsonb_typeof(col->'key') = 'null' if you need to distinguish a JSON null value from a missing key.

Scenario 5 — Build JSON from relational data

Q: You have orders and order_items tables. Return each order as a single JSON object with an array of its items.

A: Use jsonb_agg + jsonb_build_object with GROUP BY.

s5_build_json.sql
SELECT o.id AS order_id, o.total, jsonb_agg( jsonb_build_object( 'product', oi.product_name, 'qty', oi.quantity, 'price', oi.unit_price ) ) AS items FROM orders o JOIN order_items oi ON oi.order_id = o.id GROUP BY o.id, o.total; -- Result per row: -- order_id: 1 | total: 250 -- items: [{"product":"Laptop","qty":1,"price":250}]
