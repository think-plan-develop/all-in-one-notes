PostgreSQL functions let you write reusable SQL logic that can accept parameters, perform database operations, apply conditions, and return results.

Why use functions?

  • Reuse business logic instead of writing the same SQL repeatedly.
  • Perform multiple database operations in one place.
  • Validate data before inserting or updating.
  • Return calculated results or complete datasets.
  • Keep application code cleaner.
1. Create and Call a Function

Use CREATE FUNCTION to create a function and SELECT to execute it.

Syntax

syntax.sql
CREATE OR REPLACE FUNCTION function_name()
RETURNS data_type
LANGUAGE plpgsql
AS $$
BEGIN
    -- SQL logic
    RETURN value;
END;
$$;

Example

get_total_employees.sql
CREATE OR REPLACE FUNCTION get_total_employees()
RETURNS INTEGER
LANGUAGE plpgsql
AS $$
DECLARE
    total INTEGER;
BEGIN
    SELECT COUNT(*) INTO total
    FROM employees;

    RETURN total;
END;
$$;

Call the function:

call.sql
SELECT get_total_employees();

Important

  • CREATE OR REPLACE creates or updates a function.
  • LANGUAGE plpgsql enables procedural SQL.
  • BEGIN and END contain the function logic.
  • RETURN sends the result back.
2. Parameters (IN, OUT, INOUT)

Parameters let you pass values into functions or get values back.

ParameterPurpose
INAccepts input (default).
OUTReturns output.
INOUTAccepts input and returns modified output.

A. IN — input parameter

get_employee.sql
CREATE OR REPLACE FUNCTION get_employee(emp_id INT)
RETURNS TEXT
LANGUAGE plpgsql
AS $$
DECLARE
    emp_name TEXT;
BEGIN
    SELECT employee_name INTO emp_name
    FROM employees
    WHERE employee_id = emp_id;

    RETURN emp_name;
END;
$$;

-- Call
SELECT get_employee(1);

B. OUT — output parameter

get_employee_count.sql
CREATE OR REPLACE FUNCTION get_employee_count(OUT total INT)
LANGUAGE plpgsql
AS $$
BEGIN
    SELECT COUNT(*) INTO total
    FROM employees;
END;
$$;

-- Call
SELECT get_employee_count();

C. INOUT — input + output

increase_salary.sql
CREATE OR REPLACE FUNCTION increase_salary(INOUT salary INT)
LANGUAGE plpgsql
AS $$
BEGIN
    salary := salary + 5000;
END;
$$;

-- Call
SELECT increase_salary(20000);
Remember: IN receives values, OUT sends values, and INOUT does both.
3. Return Types (RETURNS TABLE)

A function can return different types of results.

Return typePurpose
RETURNS INTReturns an integer.
RETURNS TEXTReturns text.
RETURNS BOOLEANReturns true or false.
RETURNS NUMERICReturns decimal values.
RETURNS TABLEReturns multiple rows and columns.
RETURNS SETOFReturns multiple values or rows of a specified type.

A. RETURNS — single value

get_salary.sql
CREATE FUNCTION get_salary()
RETURNS NUMERIC
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN 50000;
END;
$$;

B. RETURNS TABLE — multiple rows and columns

This is especially important for real projects.

get_employees.sql
CREATE OR REPLACE FUNCTION get_employees()
RETURNS TABLE (
    emp_id INT,
    emp_name TEXT,
    emp_salary NUMERIC
)
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN QUERY
    SELECT employee_id, employee_name, salary
    FROM employees;
END;
$$;

-- Call
SELECT * FROM get_employees();

You can also filter the returned data:

filter.sql
SELECT *
FROM get_employees()
WHERE emp_salary > 50000;

Why use RETURNS TABLE?

  • Return multiple rows and columns.
  • Create reusable database queries.
  • Use function results like a table in a query.
  • Useful for reports, dashboards and APIs.
4. Variables and SELECT INTO

Variables store temporary values inside a function.

syntax.sql
DECLARE
    variable_name DATA_TYPE;
get_employee_salary.sql
CREATE OR REPLACE FUNCTION get_employee_salary(emp_id INT)
RETURNS NUMERIC
LANGUAGE plpgsql
AS $$
DECLARE
    emp_salary NUMERIC;
BEGIN
    SELECT salary INTO emp_salary
    FROM employees
    WHERE employee_id = emp_id;

    RETURN emp_salary;
END;
$$;

Understanding SELECT INTO

select-into.sql
SELECT salary INTO emp_salary
FROM employees
WHERE employee_id = 1;
  • Fetch the employee’s salary.
  • Store the result in emp_salary.
  • Use that variable later in the function.
Important: if no row is found, the variable becomes NULL unless you handle it. If multiple rows are returned, only the first row is assigned (without guaranteed ordering).
5. Conditions

Conditions let functions make decisions. PostgreSQL supports IF, ELSIF, ELSE and CASE.

A. IF / ELSE

check_salary.sql
CREATE OR REPLACE FUNCTION check_salary(salary NUMERIC)
RETURNS TEXT
LANGUAGE plpgsql
AS $$
BEGIN
    IF salary >= 70000 THEN
        RETURN 'High Salary';

    ELSE
        RETURN 'Normal Salary';
    END IF;
END;
$$;

B. IF / ELSIF / ELSE

elsif.sql
IF salary >= 70000 THEN
    result := 'High';

ELSIF salary >= 30000 THEN
    result := 'Medium';

ELSE
    result := 'Low';
END IF;

C. CASE

case.sql
CASE
    WHEN salary >= 70000 THEN
        result := 'High';

    WHEN salary >= 30000 THEN
        result := 'Medium';

    ELSE
        result := 'Low';
END CASE;

Use conditions for: salary classification, order status validation, discount calculation, payment verification.

6. Database Operations (CRUD)

Functions can perform INSERT, SELECT, UPDATE and DELETE operations.

A. INSERT

add_employee.sql
CREATE OR REPLACE FUNCTION add_employee(
    emp_name TEXT,
    emp_salary NUMERIC
)
RETURNS TEXT
LANGUAGE plpgsql
AS $$
BEGIN
    INSERT INTO employees(employee_name, salary)
    VALUES (emp_name, emp_salary);

    RETURN 'Employee added successfully';
END;
$$;

-- Call
SELECT add_employee('Rahul', 50000);

B. SELECT

select.sql
SELECT salary INTO emp_salary
FROM employees
WHERE employee_id = 1;

C. UPDATE

update.sql
UPDATE employees
SET salary = salary + 5000
WHERE employee_id = 1;

D. DELETE

delete.sql
DELETE FROM employees
WHERE employee_id = 1;
Practical use: you can combine validation, conditions and CRUD operations in a single function.
7. Return Statements

RETURN sends a result back to the caller.

StatementPurpose
RETURN valueReturns a single value.
RETURN NEXTAdds one row/value to the result.
RETURN QUERYAdds results from a query.
RETURN;Exits a function without returning a value explicitly.

A. RETURN

return.sql
RETURN 'Success';

B. RETURN QUERY

Used with RETURNS TABLE or compatible set-returning functions.

return-query.sql
RETURN QUERY
SELECT employee_id, employee_name, salary
FROM employees;

C. RETURN NEXT

get_employee_ids.sql
CREATE OR REPLACE FUNCTION get_employee_ids()
RETURNS SETOF INT
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN NEXT 1;
    RETURN NEXT 2;
    RETURN NEXT 3;
END;
$$;

-- Call
SELECT * FROM get_employee_ids();
Important: RETURN QUERY and RETURN NEXT add rows to the result; they do not immediately terminate the function. A final RETURN can end execution.
8. Exception Handling

Exception handling manages errors without abruptly terminating the function. Use EXCEPTION with WHEN.

syntax.sql
BEGIN
    -- SQL logic

EXCEPTION
    WHEN exception_name THEN
        -- Error handling
END;
divide_numbers.sql
CREATE OR REPLACE FUNCTION divide_numbers(a NUMERIC, b NUMERIC)
RETURNS NUMERIC
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN a / b;

EXCEPTION
    WHEN division_by_zero THEN
        RETURN 0;
END;
$$;

-- Call
SELECT divide_numbers(10, 0);   -- Output: 0

Common exceptions

ExceptionMeaning
division_by_zeroDivision by zero.
unique_violationDuplicate unique value.
foreign_key_violationForeign key constraint failure.
no_data_foundNo row found with SELECT INTO STRICT.
othersCatches other errors.
others.sql
EXCEPTION
    WHEN OTHERS THEN
        RAISE NOTICE 'Error: %', SQLERRM;
        RETURN 0;

SQLERRM provides the error message.

Note: a block with an exception handler rolls back database changes made inside that block before executing the handler.
9. Loops

Loops execute SQL statements repeatedly. PostgreSQL supports LOOP, WHILE and FOR.

A. LOOP

loop.sql
DECLARE
    counter INT := 1;
BEGIN
    LOOP
        EXIT WHEN counter > 5;

        RAISE NOTICE '%', counter;

        counter := counter + 1;
    END LOOP;
END;

B. WHILE LOOP

while.sql
DECLARE
    counter INT := 1;
BEGIN
    WHILE counter <= 5 LOOP
        RAISE NOTICE '%', counter;

        counter := counter + 1;
    END LOOP;
END;

C. FOR LOOP

for.sql
BEGIN
    FOR counter IN 1..5 LOOP
        RAISE NOTICE '%', counter;
    END LOOP;
END;

Important keywords

  • EXIT – stop the loop.
  • CONTINUE – skip the current iteration.
  • RAISE NOTICE – display a message.
Loops are useful when processing records one by one, but prefer SQL-based operations such as UPDATE and INSERT ... SELECT when possible.
10. Practical Business Functions

Common real-world examples where functions are useful.

A. Calculate discount

calculate_discount.sql
CREATE OR REPLACE FUNCTION calculate_discount(
    amount NUMERIC,
    discount_percent NUMERIC
)
RETURNS NUMERIC
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN amount - (amount * discount_percent / 100);
END;
$$;

-- Call
SELECT calculate_discount(10000, 10);   -- Output: 9000

B. Check order status

check_order_status.sql
CREATE OR REPLACE FUNCTION check_order_status(order_id INT)
RETURNS TEXT
LANGUAGE plpgsql
AS $$
DECLARE
    status TEXT;
BEGIN
    SELECT orders.status INTO status
    FROM orders
    WHERE orders.order_id = check_order_status.order_id;

    IF status IS NULL THEN
        RETURN 'Order not found';
    END IF;

    RETURN status;
END;
$$;

C. Transfer money between accounts

A simplified example:

transfer_money.sql
CREATE OR REPLACE FUNCTION transfer_money(
    from_id INT,
    to_id INT,
    amount NUMERIC
)
RETURNS TEXT
LANGUAGE plpgsql
AS $$
BEGIN
    IF amount <= 0 THEN
        RETURN 'Invalid amount';
    END IF;

    UPDATE accounts
    SET balance = balance - amount
    WHERE account_id = from_id
      AND balance >= amount;

    IF NOT FOUND THEN
        RETURN 'Insufficient balance or account not found';
    END IF;

    UPDATE accounts
    SET balance = balance + amount
    WHERE account_id = to_id;

    IF NOT FOUND THEN
        RAISE EXCEPTION 'Destination account not found';
    END IF;

    RETURN 'Transfer successful';
END;
$$;
This example demonstrates business logic, but a production money-transfer function should also validate both accounts, lock rows against concurrent transfers, and handle transaction failures safely.
11. Medium / Intermediate Concepts

Additional concepts worth learning after the basics.

ConceptExplanation
FOUNDChecks whether the last SQL statement affected or returned any rows.
RAISE NOTICEDisplays debugging messages.
RAISE EXCEPTIONThrows an error and stops normal execution.
SQLERRMGets the current exception message.
GET DIAGNOSTICSRetrieves information such as affected row count.
STRICTRequires a query to return exactly one row for SELECT INTO.
RETURNINGReturns inserted, updated or deleted row data.
PERFORMExecutes a query when you don’t need its result.
EXECUTEExecutes dynamically constructed SQL.
SECURITY DEFINERRuns a function with the privileges of its owner.
VOLATILE / STABLE / IMMUTABLEDescribes how a function behaves regarding changes and repeated calls.

A. FOUND

found.sql
UPDATE employees
SET salary = salary + 5000
WHERE employee_id = 1;

IF FOUND THEN
    RAISE NOTICE 'Employee updated';
ELSE
    RAISE NOTICE 'Employee not found';
END IF;

B. GET DIAGNOSTICS

diagnostics.sql
DECLARE
    affected_rows INT;
BEGIN
    UPDATE employees
    SET salary = salary + 1000
    WHERE department_id = 1;

    GET DIAGNOSTICS affected_rows = ROW_COUNT;

    RAISE NOTICE 'Updated rows: %', affected_rows;
END;

C. RETURNING

returning.sql
INSERT INTO employees(employee_name, salary)
VALUES ('Amit', 50000)
RETURNING employee_id INTO new_id;

Useful when you need the newly generated ID after inserting a record.

D. PERFORM

perform.sql
PERFORM COUNT(*)
FROM employees;

Executes a query without storing or returning its result.
