🔤 1. Core Data Types
Numbers, Text, Time, Booleans & Network Types
These are the types you'll reach for in almost every table: whole numbers and exact/approximate decimals, text variants with different length behavior, booleans, date/time types (note the timezone distinction), binary data, and network address types.
TypePurpose & Example
SMALLINT / INTEGER / BIGINTWhole numbers; 2 / 4 / 8 bytes. quantity INTEGER. SMALLINT range: −32,768 to 32,767.
NUMERIC(p,s) / DECIMAL(p,s)Exact decimal; p = total digits, s = decimal places. NUMERIC(10,2) allows 8 digits before the decimal.
REAL / DOUBLE PRECISIONApproximate decimals; about 6 / 15 significant digits. Use for measurements, not exact currency calculations.
TEXT / VARCHAR(n) / CHAR(n)TEXT has no declared length limit; VARCHAR(n) limits characters; CHAR(n) pads spaces. TEXT is not literally unlimited.
BOOLEANTRUE, FALSE or NULL. is_active BOOLEAN NOT NULL DEFAULT TRUE.
DATE / TIMEDate only / time of day. DATE '2026-09-27'; TIME '09:30'.
TIMESTAMP / TIMESTAMPTZLocal date and time / an instant displayed in the session timezone. TIMESTAMPTZ does not retain the original zone name.
INTERVALDuration or calendar interval. INTERVAL '2 hours' or INTERVAL '1 month'.
BYTEARaw bytes. decode('deadbeef', 'hex'). For large files, consider object storage plus a stored reference.
INET / CIDR / MACADDRIP address / network / hardware address. '192.168.1.5', '192.168.1.0/24', '08:00:2b:01:02:03'.

📋 Less common types

POINT, LINE, LSEG, BOX, PATH, POLYGON and CIRCLE represent planar geometry. For geographic coordinates and Earth distances, consider PostGIS. XML stores XML; TSVECTOR and TSQUERY support full text search. MONEY is locale dependent — NUMERIC gives explicit precision. OID identifies database objects; VOID is a function return pseudo-type, not a table column type.

📝 Remember: Prefer NUMERIC over REAL/DOUBLE PRECISION for money. Prefer TIMESTAMPTZ over TIMESTAMP unless you specifically need timezone-naive local times.
🔑 2. Keys & Automatic Values
IDENTITY, SERIAL & UUID
IDENTITY generates integer IDs; SERIAL and BIGSERIAL are older sequence-based shorthand for the same idea. Neither ID generation alone nor a DEFAULT guarantees uniqueness — you still need PRIMARY KEY or UNIQUE. UUID is a 128-bit identifier; collisions are extremely unlikely, not impossible.

UUIDs are useful when IDs need to be generated independently (e.g. client-side, or across services, before a row is inserted); integer IDs also work fine in scalable systems and are smaller to index.

⚠️ Common mistake: writing id INTEGER GENERATED ALWAYS AS IDENTITY and assuming that alone makes it a valid row identifier. Without PRIMARY KEY (or a separate UNIQUE constraint), nothing stops duplicate values from being inserted directly.
🧱 3. Basic Table Creation
customers — Identity, Text, Numbers, Dates, Booleans & Constraints
A single table that exercises the fundamentals: an IDENTITY primary key, required and unique text, a DATE column, a constrained NUMERIC with a CHECK, a BOOLEAN default, and a TIMESTAMPTZ default. Run this first — the advanced table below references it via foreign key.
basic-table.sql 
CREATE TABLE customers (
  customer_id BIGINT GENERATED ALWAYS AS IDENTITY
    PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(255) NOT NULL UNIQUE,
  birth_date DATE,
  credit_limit NUMERIC(10,2) NOT NULL DEFAULT 0
    CHECK (credit_limit >= 0),
  is_active BOOLEAN NOT NULL DEFAULT TRUE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

INSERT INTO customers (name, email, birth_date)
VALUES ('Shivam', 'shivam@example.com', '1998-06-15');

SELECT customer_id, name, credit_limit
FROM customers WHERE is_active;

🧷 Constraints to remember

ConstraintWhat It Enforces
PRIMARY KEYUnique and non-null row identifier; may span columns.
NOT NULL / UNIQUERequired value / no duplicate non-null values by default.
CHECKRejects FALSE. NULL can pass, so add NOT NULL when required.
FOREIGN KEYValue must match a referenced key, unless NULL is allowed.
DEFAULTUsed when the column is omitted or DEFAULT is supplied; explicit NULL is not replaced.
🐘 4. PostgreSQL-Specific Features
ENUM, ARRAY, JSON/JSONB & Generated Columns
The features that go beyond plain ANSI SQL: a named ENUM type for a fixed set of labels, native ARRAY columns, the JSON vs JSONB tradeoff, and generated columns computed from other columns in the same row.

🏷️ ENUM

A named set of allowed labels. Create the type before the table. Labels are case sensitive and sort in declaration order. Values can be added or renamed; removing a value requires a migration. TEXT with a CHECK constraint is a more flexible alternative.

📚 ARRAY

A list of one element type, such as TEXT[]. Ordinary arrays start at index 1, though custom lower bounds are possible. Use a child table instead when elements need foreign keys or independent records.

🔄 JSON vs JSONB

JSON preserves input text formatting and duplicate keys. JSONB stores a parsed representation, discards formatting, and keeps the last duplicate key. Prefer JSONB for querying and indexing — both validate JSON syntax, not your business schema.

🧮 Generated columns

Calculated from other columns in the same row. STORED recalculates on writes and saves the result. Expressions must be immutable, with no subqueries or references to other generated columns. PostgreSQL 18 also supports virtual generated columns.

💡 Rule of thumb: reach for JSONB by default unless you specifically need to preserve exact input formatting or duplicate keys — the indexing and query-operator support make JSONB the better fit almost every time.
⚙️ 5. Advanced Table Creation
purchases — UUID, ENUM, Foreign Key, ARRAY, JSON/JSONB, INET & Generated Total
One purchase line that combines everything above: a UUID primary key, an ENUM status, a FOREIGN KEY back to customers, CHECK-constrained numbers, a STORED generated column for the total, a TEXT[] array, both JSONB and JSON columns, an INET address, and two GIN indexes.
advanced-table.sql 
CREATE TYPE purchase_status AS ENUM
  ('pending', 'paid', 'cancelled');

CREATE TABLE purchases (
  purchase_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  customer_id BIGINT NOT NULL
    REFERENCES customers(customer_id) ON DELETE RESTRICT,
  status purchase_status NOT NULL DEFAULT 'pending',
  quantity INTEGER NOT NULL CHECK (quantity > 0),
  unit_price NUMERIC(10,2) NOT NULL CHECK (unit_price >= 0),
  total NUMERIC(20,2) GENERATED ALWAYS AS
    (quantity * unit_price) STORED,
  tags TEXT[] NOT NULL DEFAULT '{}'::TEXT[],
  metadata JSONB NOT NULL DEFAULT '{}'::JSONB
    CHECK (jsonb_typeof(metadata) = 'object'),
  raw_payload JSON,
  client_ip INET,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX purchases_customer_idx ON purchases(customer_id);
CREATE INDEX purchases_metadata_idx ON purchases USING GIN (metadata);
CREATE INDEX purchases_tags_idx ON purchases USING GIN (tags);

INSERT INTO purchases
  (customer_id, quantity, unit_price, tags, metadata,
   raw_payload, client_ip)
SELECT customer_id, 2, 499.50, ARRAY['online', 'priority'],
  '{"city":"Noida","gift":true}'::JSONB,
  '{ "source": "web" }'::JSON, '192.168.1.5'::INET
FROM customers WHERE email = 'shivam@example.com';

SELECT total, metadata->>'city' AS city, tags[1] AS first_tag
FROM purchases
WHERE metadata @> '{"gift":true}'::JSONB
  AND tags @> ARRAY['online'];
-- Result: total 999.00, city Noida, first_tag online
💡 Don't supply total on insert — PostgreSQL calculates it from quantity * unit_price automatically since it's a STORED generated column. Supplying a value for it manually raises an error.
📌 6. Query & Design Reminders
Operators & Common Gotchas
A handful of operators cover most JSONB and array querying: -> / ->> for JSON access, @> for containment on both JSONB and arrays, ? for a top-level JSONB key, && for array overlap, and unnest() to expand an array into rows.

🔍 JSON & array operators

-> returns JSON/JSONB; ->> returns text; @> tests JSONB containment; ? tests a top-level key. Arrays use @> for containment, && for overlap, and unnest() to expand elements. GIN supports containment searches — scalar = ANY(array) is not directly a GIN array search.

⚠️ Easy-to-miss gotchas

A foreign key does not automatically index its referencing column — you add that index yourself, as done above for customer_id. DEFAULT NOW() sets an insertion-time value; it does not maintain an updated_at column on later updates (that needs a trigger). Index availability does not guarantee the planner will actually use it.

🎯 Practice: try inserting a purchase with a negative unit_price and one with a nonexistent customer_id — both should be rejected. Then insert with quantity = 3 and unit_price = 499.50 and confirm total = 1498.50.
