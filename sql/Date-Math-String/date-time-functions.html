Your four queries show how date functions are used in real-world applications, not just how individual functions work. Each is explained step by step.

1. Find Today’s Orders
today.sql
SELECT *
FROM orders
WHERE order_date::date = CURRENT_DATE;

Understanding the query

Step 1: CURRENT_DATE returns today’s date without the time.

q.sql
SELECT CURRENT_DATE;
-- 2026-11-08

Step 2: order_date::date converts a timestamp into a date by removing its time portion.

order_dateorder_date::date
2026-11-08 10:30:002026-11-08
2026-11-08 15:45:002026-11-08
2026-11-07 18:20:002026-11-07

Step 3: WHERE order_date::date = CURRENT_DATE compares the date portion of each order with today’s date, so only orders placed today are returned.

Better approach for production

Instead of converting every order_date value into a date, use a date range.

better.sql
SELECT *
FROM orders
WHERE order_date >= CURRENT_DATE
  AND order_date < CURRENT_DATE + 1;
  • It avoids applying a function to the column.
  • It can make better use of an index on order_date.
  • It correctly includes all times today.
Remember: when filtering timestamp columns, prefer a range condition.
2. Find Orders From the Last 30 Days
last30.sql
SELECT *
FROM orders
WHERE order_date >= CURRENT_DATE - 30;

Understanding the query

PostgreSQL allows you to subtract an integer from a DATE. CURRENT_DATE - 30 subtracts 30 days from the current date. If today is 2026-11-08:

q.sql
SELECT CURRENT_DATE - 30;
-- 2026-10-09

The condition becomes WHERE order_date >= DATE '2026-10-09': return orders on or after October 9.

Two interpretations of “last 30 days”

A. Last 30 calendar days, including today — today and the previous 29 calendar dates.

a.sql
SELECT *
FROM orders
WHERE order_date >= CURRENT_DATE - 29
  AND order_date < CURRENT_DATE + 1;

B. Last 30 × 24 hours (rolling period) — exact rolling period from the current time. If it is November 8, 8:30 PM, the condition starts October 9, 8:30 PM.

b.sql
SELECT *
FROM orders
WHERE order_date >= NOW() - INTERVAL '30 days';
Important: use INTERVAL when you want date/time arithmetic with hours, days, months, etc.

More examples:

interval.sql
NOW() - INTERVAL '1 day'
NOW() - INTERVAL '7 days'
NOW() - INTERVAL '2 months'
NOW() + INTERVAL '5 hours'
3. Find Employee Experience Using AGE()
age.sql
SELECT
    employee_name,
    AGE(CURRENT_DATE, hire_date) AS experience
FROM employees;

Understanding the query

Suppose the employees table contains:

employee_namehire_date
Rahul2020-05-15
Priya2022-03-10
Amit2024-01-01

Step 1: AGE() calculates the difference between two dates.

syntax.sql
AGE(end_date, start_date)
q.sql
SELECT AGE(
    DATE '2026-11-08',
    DATE '2020-05-15'
);
-- 6 years 5 mons 24 days (illustrative)

Step 2: in AGE(CURRENT_DATE, hire_date), CURRENT_DATE is today and hire_date is the joining date, so PostgreSQL calculates how long each employee has worked.

Step 3: AS experience gives the calculated result a column name.

Practical variations

A. Completed years only

a.sql
SELECT
    employee_name,
    EXTRACT(YEAR FROM AGE(CURRENT_DATE, hire_date)) AS experience_years
FROM employees;
employee_nameexperience_years
Rahul6
Priya4
Amit2

B. Employees with more than 3 years of experience

b.sql
SELECT
    employee_name,
    AGE(CURRENT_DATE, hire_date) AS experience
FROM employees
WHERE hire_date <= CURRENT_DATE - INTERVAL '3 years';

C. Total experience in days — subtracting two DATE values returns the difference in days as an integer.

c.sql
SELECT
    employee_name,
    CURRENT_DATE - hire_date AS experience_days
FROM employees;

Important differences

RequirementApproach
Experience in years, months and daysAGE()
Completed yearsEXTRACT(YEAR FROM AGE(...))
Difference in daysCURRENT_DATE - hire_date
Employees with 3+ yearsDate comparison with INTERVAL
Remember: AGE() returns an INTERVAL, not an integer. EXTRACT(YEAR FROM AGE(...)) gives the completed year component, not total days divided by 365.
4. Count Orders By Year Using EXTRACT()
by-year.sql
SELECT
    EXTRACT(YEAR FROM order_date) AS order_year,
    COUNT(*) AS total_orders
FROM orders
GROUP BY EXTRACT(YEAR FROM order_date)
ORDER BY order_year;

This query combines three concepts: EXTRACT() extracts the year, GROUP BY groups orders from the same year, and COUNT() counts orders in each group.

Understanding the query step by step

Suppose the orders table contains:

order_idorder_date
12024-01-15
22024-05-20
32024-09-10
42025-02-15
52025-06-20
62026-01-10

Step 1: extract the year

s1.sql
SELECT
    EXTRACT(YEAR FROM order_date)
FROM orders;
-- 2024, 2024, 2024, 2025, 2025, 2026

Step 2: group by year — PostgreSQL creates separate groups for 2024, 2025 and 2026.

s2.sql
SELECT
    EXTRACT(YEAR FROM order_date) AS order_year
FROM orders
GROUP BY EXTRACT(YEAR FROM order_date);

Step 3: count records in each group

order_yeartotal_orders
20243
20252
20261

Step 4: sort the result — ORDER BY order_year; sorts the groups by year in ascending order.

Why GROUP BY? Because we want one result per year, not one result per order. Without it, PostgreSQL cannot calculate separate yearly counts while selecting the extracted year.

Practical variations

A. Count orders by month — groups January from every year together, February from every year together, and so on.

a.sql
SELECT
    EXTRACT(MONTH FROM order_date) AS order_month,
    COUNT(*) AS total_orders
FROM orders
GROUP BY EXTRACT(MONTH FROM order_date)
ORDER BY order_month;

B. Count orders by year and month — separate results for November 2024, November 2025 and November 2026.

b.sql
SELECT
    EXTRACT(YEAR FROM order_date) AS order_year,
    EXTRACT(MONTH FROM order_date) AS order_month,
    COUNT(*) AS total_orders
FROM orders
GROUP BY
    EXTRACT(YEAR FROM order_date),
    EXTRACT(MONTH FROM order_date)
ORDER BY order_year, order_month;
5. EXTRACT() vs DATE_TRUNC()

Both are useful for grouping records by time, but they return different results. Suppose order_date = 2026-11-08 15:30:45:

FunctionOutput
EXTRACT(YEAR FROM order_date)2026
EXTRACT(MONTH FROM order_date)11
DATE_TRUNC('year', order_date)2026-01-01 00:00:00
DATE_TRUNC('month', order_date)2026-11-01 00:00:00
DATE_TRUNC('day', order_date)2026-11-08 00:00:00

Practical difference

extract.sql
SELECT
    EXTRACT(YEAR FROM order_date) AS order_year,
    COUNT(*) AS total_orders
FROM orders
GROUP BY EXTRACT(YEAR FROM order_date);
date_trunc.sql
SELECT
    DATE_TRUNC('year', order_date) AS order_year,
    COUNT(*) AS total_orders
FROM orders
GROUP BY DATE_TRUNC('year', order_date)
ORDER BY order_year;

Both group orders by year. However:

  • EXTRACT() returns a numeric component.
  • DATE_TRUNC() returns a timestamp representing the beginning of the specified period.
  • DATE_TRUNC() is particularly useful for monthly and yearly reporting, e.g. monthly sales reports use DATE_TRUNC('month', order_date).
6. Updated notes — important syntax to remember

Date arithmetic

OperationExample
Subtract daysCURRENT_DATE - 7
Add daysCURRENT_DATE + 7
Subtract monthsNOW() - INTERVAL '2 months'
Add hoursNOW() + INTERVAL '5 hours'
Subtract yearsCURRENT_DATE - INTERVAL '1 year'
Difference between datesend_date - start_date

Date filtering patterns

patterns.sql
-- Today's records
WHERE order_date >= CURRENT_DATE
  AND order_date < CURRENT_DATE + 1

-- Last 7 days (rolling period)
WHERE order_date >= NOW() - INTERVAL '7 days'

-- Records from 2025
WHERE order_date >= DATE '2025-01-01'
  AND order_date < DATE '2026-01-01'

-- Records from November 2026
WHERE order_date >= DATE '2026-11-01'
  AND order_date < DATE '2026-12-01'

Important rules

  1. CURRENT_DATE - 30 subtracts 30 calendar days.
  2. NOW() - INTERVAL '30 days' calculates a rolling time period.
  3. AGE() returns years, months and days as an interval.
  4. EXTRACT() returns a numeric date/time component.
  5. DATE_TRUNC() returns the beginning of a specified time period.
  6. For timestamp filtering, prefer date ranges instead of casting the column using ::date.
  7. When grouping by month, include the year too if you want to distinguish the same month across different years.
