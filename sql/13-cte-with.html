SQL CTEs — Compact Notes

A practical guide to Common Table Expressions: make complex SQL easier to read by naming intermediate result sets and building queries in clear, logical steps.

📌 In short: A CTE (Common Table Expression) is a temporary, named result set defined with WITH. It exists for one SQL statement and helps split complicated query logic into readable steps.

01Basic CTE — WITH

🧱

Define a named result set

START HERE

Use when: You want to simplify a query, reuse an intermediate result within one statement, or filter aggregated data.

basic-cte.sql
WITH dept_avg AS (
    SELECT department, AVG(salary) AS avg_salary
    FROM employees
    GROUP BY department
)
SELECT *
FROM dept_avg
WHERE avg_salary > 60000;

How it works

1WITH dept_avg AS (...) defines the CTE.
2The CTE calculates the average salary for each department.
3The main query returns departments whose average salary is above 60,000.

General syntax

cte-template.sql
WITH cte_name AS (
    SELECT ...
)
SELECT *
FROM cte_name;
💡 Think of a CTE as a named step that makes the main query easier to understand.

02Multiple CTEs

🪜

Build a query in dependent steps

CHAIN LOGIC

Use when: A query has multiple dependent steps, such as calculating totals and then filtering results.

multiple-ctes.sql
WITH dept_totals AS (
    SELECT department, SUM(salary) AS total_salary
    FROM employees
    GROUP BY department
),
high_salary_depts AS (
    SELECT *
    FROM dept_totals
    WHERE total_salary > 200000
)
SELECT *
FROM high_salary_depts;

Key points

  • Separate CTE definitions with commas.
  • Later CTEs can reference earlier CTEs.
  • Keep each CTE focused on one logical step.
✓ Read it from top to bottom: calculate department totals first, filter those totals next, then select the final result.

03Recursive CTEs

🔁

Repeat a step until the condition stops it

ITERATION

Use when: You need to process hierarchical data or generate sequences, such as employee-manager trees or category hierarchies.

recursive-cte.sql
WITH RECURSIVE numbers AS (
    -- Anchor: starting value
    SELECT 1 AS n

    UNION ALL

    -- Recursive step
    SELECT n + 1
    FROM numbers
    WHERE n < 5
)
SELECT n
FROM numbers;
Output: 1, 2, 3, 4, 5

How recursion works

1Anchor query: Starts the result with 1.
2Recursive query: Generates the next value using n + 1.
3Stopping condition: WHERE n < 5 stops the sequence after 5.
⚠️ Always define a valid stopping condition to prevent unbounded recursion.
Database syntax: PostgreSQL and MySQL use WITH RECURSIVE; SQL Server uses WITH without the RECURSIVE keyword.

✓Remember

  • A CTE is not necessarily a physical temporary table; the database decides how to execute it.
  • A CTE exists for one SQL statement.
  • Use UNION ALL in recursive CTEs when you want to retain generated rows.
  • Always define a valid stopping condition for recursion.
  • Learn in this order: Basic CTE → Multiple CTEs → Recursive CTEs.
Learning path: start with one named result, chain multiple logical steps, then move on to recursion.
SQL CTEs — final takeaway
Use WITH to make query logic clearer, multiple CTEs to organize dependent steps, and recursive CTEs for sequences or hierarchical relationships. Keep each step focused and recursion bounded.
