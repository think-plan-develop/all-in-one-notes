A CTE (Common Table Expression) is a temporary, named result set defined using WITH. It makes complex SQL queries easier to read by breaking them into steps.

1. Basic CTE — WITH

Use when: you want to simplify a query, reuse an intermediate result within one statement, or filter aggregated data.

basic-cte.sql
WITH dept_avg AS (
    SELECT department, AVG(salary) AS avg_salary
    FROM employees
    GROUP BY department
)
SELECT *
FROM dept_avg
WHERE avg_salary > 60000;

How it works

  1. WITH dept_avg AS (...) defines the CTE.
  2. The CTE calculates average salary per department.
  3. The main query filters departments with an average above 60,000.

Syntax

syntax.sql
WITH cte_name AS (
    SELECT ...
)
SELECT *
FROM cte_name;
2. Multiple CTEs

Use when: a query has multiple dependent steps, such as calculating totals and then filtering results.

multiple-ctes.sql
WITH dept_totals AS (
    SELECT department, SUM(salary) AS total_salary
    FROM employees
    GROUP BY department
),
high_salary_depts AS (
    SELECT *
    FROM dept_totals
    WHERE total_salary > 200000
)
SELECT *
FROM high_salary_depts;

Key points

  • Separate CTEs with commas.
  • Later CTEs can reference earlier CTEs.
  • Keep each CTE focused on one logical step.
3. Recursive CTEs

Use when: you need to process hierarchical data or generate sequences, such as employee-manager trees or category hierarchies.

recursive-cte.sql
WITH RECURSIVE numbers AS (
    -- Anchor: starting value
    SELECT 1 AS n

    UNION ALL

    -- Recursive step
    SELECT n + 1
    FROM numbers
    WHERE n < 5
)
SELECT n
FROM numbers;

Output: 1, 2, 3, 4, 5

How recursion works

  1. Anchor query: starts the result (1).
  2. Recursive query: generates the next value (n + 1).
  3. Stopping condition: WHERE n < 5 prevents infinite recursion.
Important: PostgreSQL and MySQL use WITH RECURSIVE; SQL Server uses WITH without the RECURSIVE keyword.

Remember
  • A CTE is not necessarily a physical temporary table; the database decides how to execute it.
  • A CTE exists for one SQL statement.
  • Use UNION ALL in recursive CTEs when you want to retain generated rows.
  • Always define a valid stopping condition for recursion.
  • Learn in this order: Basic CTE → Multiple CTEs → Recursive CTEs.
