Window functions perform calculations across a set of related rows without combining those rows into a single row. They are especially useful in reporting, analytics, dashboards and data analysis.

  • Rank employees based on salary.
  • Find the highest or lowest salary in a department.
  • Calculate running totals.
  • Calculate average salary department-wise.
  • Compare the current row with the previous or next row.
  • Find top 3 employees in each department.
  • Calculate month-over-month sales.
1. What is a Window Function?

Suppose we have an employees table:

employee_idemployee_namedepartmentsalary
1AmitIT80000
2RahulIT60000
3PriyaIT90000
4NehaHR50000
5SnehaHR70000

Requirement: display each employee along with their department’s average salary.

Using GROUP BY

group-by.sql
SELECT
    department,
    AVG(salary) AS avg_salary
FROM employees
GROUP BY department;
departmentavg_salary
IT76666.67
HR60000

Problem: GROUP BY combines multiple rows into one row per department. We lose individual employee records in this result.

Using a window function

window.sql
SELECT
    employee_name,
    department,
    salary,
    AVG(salary) OVER(
        PARTITION BY department
    ) AS avg_salary
FROM employees;
employee_namedepartmentsalaryavg_salary
AmitIT8000076666.67
RahulIT6000076666.67
PriyaIT9000076666.67
NehaHR5000060000
SnehaHR7000060000
  • Each employee record is preserved.
  • Average salary is calculated separately for each department.
  • The department average is added as an extra column.
Important: GROUP BY reduces rows, whereas a window function preserves individual rows.
2. Window Function Syntax
syntax.sql
SELECT
    column1,
    column2,
    WINDOW_FUNCTION() OVER (
        PARTITION BY column_name
        ORDER BY column_name
        ROWS BETWEEN ...
    ) AS result
FROM table_name;
PartMeaning
WINDOW_FUNCTION()The calculation to perform, such as SUM, AVG, RANK
OVER()Defines the window over which the function operates
PARTITION BYDivides rows into groups
ORDER BYDefines the order of rows inside each group
ROWS BETWEENDefines which rows are included in the calculation

You don’t need all these clauses every time. Their usage depends on the requirement.

3. PARTITION BY

What: divides records into groups and performs calculations separately for each group. It is similar to GROUP BY, but it does not combine rows.

Example: calculate average salary department-wise.

partition.sql
SELECT
    employee_name,
    department,
    salary,
    AVG(salary) OVER(
        PARTITION BY department
    ) AS department_avg
FROM employees;
  • IT employees form one partition.
  • HR employees form another partition.
  • Average salary is calculated independently in each partition.

Without PARTITION BY:

no-partition.sql
SELECT
    employee_name,
    salary,
    AVG(salary) OVER() AS company_avg
FROM employees;

This calculates the average salary across all employees.

Remember: OVER() → entire result set. OVER(PARTITION BY department) → separate calculation per department.
4. ORDER BY in Window Functions

What: defines the order in which rows are processed inside a window. Example: calculate a running salary total.

running-total.sql
SELECT
    employee_name,
    salary,
    SUM(salary) OVER(
        ORDER BY employee_id
    ) AS running_total
FROM employees;
employee_namesalaryrunning_total
Amit8000080000
Rahul60000140000
Priya90000230000
Neha50000280000
Sneha70000350000

The total keeps increasing as each row is processed.

Important: in aggregate window functions, adding ORDER BY generally introduces a running or cumulative calculation because of the default window frame.
5. Types of Window Functions

PostgreSQL window functions fall into three major categories.

A. Ranking Functions

These assign a rank or row number to records based on a specified order. Four are commonly used.

1. ROW_NUMBER()

Assigns a unique sequential number to every row. Example: number employees by salary, highest first.

row_number.sql
SELECT
    employee_name,
    salary,
    ROW_NUMBER() OVER(
        ORDER BY salary DESC
    ) AS row_num
FROM employees;
employee_namesalaryrow_num
Priya900001
Amit800002
Sneha700003
Rahul600004
Neha500005

When to use: assign unique row numbers, implement pagination, find the latest record per customer, remove duplicate records using a CTE.

2. RANK()

Assigns ranks based on values. If two rows have the same value, they receive the same rank, and the next rank is skipped.

rank.sql
SELECT
    employee_name,
    salary,
    RANK() OVER(
        ORDER BY salary DESC
    ) AS salary_rank
FROM employees;
EmployeeSalaryRank
Priya900001
Amit800002
Sneha800002
Rahul600004

Notice: rank 3 is skipped because two employees share rank 2.

3. DENSE_RANK()

Similar to RANK(), but it does not skip ranks when duplicate values occur.

dense_rank.sql
SELECT
    employee_name,
    salary,
    DENSE_RANK() OVER(
        ORDER BY salary DESC
    ) AS salary_rank
FROM employees;
EmployeeSalaryDense Rank
Priya900001
Amit800002
Sneha800002
Rahul600003

RANK vs DENSE_RANK vs ROW_NUMBER (interview important)

FunctionDuplicate valuesSkips ranks?
ROW_NUMBER()Always unique numberNo
RANK()Same rankYes
DENSE_RANK()Same rankNo

4. NTILE()

Divides ordered records into a specified number of approximately equal groups (buckets). Example: divide employees into 2 salary groups.

ntile.sql
SELECT
    employee_name,
    salary,
    NTILE(2) OVER(
        ORDER BY salary DESC
    ) AS salary_group
FROM employees;
EmployeeSalaryGroup
Priya900001
Amit800001
Sneha700001
Rahul600002
Neha500002

When to use: divide customers into segments, create performance groups, divide employees into salary bands, quartile analysis using NTILE(4).

B. Aggregate Window Functions

These are normal aggregate functions used with OVER().

FunctionPurpose
SUM()Calculate total
AVG()Calculate average
COUNT()Count records
MIN()Find minimum
MAX()Find maximum

1. SUM() — running total

sum.sql
SELECT
    employee_name,
    salary,
    SUM(salary) OVER(
        ORDER BY employee_id
    ) AS running_total
FROM employees;

Calculates cumulative salary as rows are processed.

2. AVG() — department average

avg.sql
SELECT
    employee_name,
    department,
    salary,
    AVG(salary) OVER(
        PARTITION BY department
    ) AS department_avg
FROM employees;

Calculates average salary for each department without grouping rows together.

3. COUNT() — department employee count

count.sql
SELECT
    employee_name,
    department,
    COUNT(*) OVER(
        PARTITION BY department
    ) AS total_employees
FROM employees;

Every employee gets the total number of employees in their department.

4. MIN() and MAX()

min-max.sql
SELECT
    employee_name,
    department,
    salary,

    MIN(salary) OVER(
        PARTITION BY department
    ) AS min_salary,

    MAX(salary) OVER(
        PARTITION BY department
    ) AS max_salary

FROM employees;

Displays the minimum and maximum salary for each department alongside individual employee records.

C. Value / Navigation Window Functions

These help you access values from other rows without performing a self-join.

1. LAG()

Retrieves a value from a previous row. Example: display the previous employee’s salary.

lag.sql
SELECT
    employee_name,
    salary,
    LAG(salary) OVER(
        ORDER BY employee_id
    ) AS previous_salary
FROM employees;
EmployeeSalaryPrevious Salary
Amit80000NULL
Rahul6000080000
Priya9000060000
Neha5000090000
Sneha7000050000

The first row returns NULL because there is no previous row. When to use: compare current month sales with previous month, find salary changes, compare consecutive transaction amounts. You can also look back several rows:

lag2.sql
LAG(salary, 2) OVER(ORDER BY employee_id)

This retrieves the salary from two rows earlier.

2. LEAD()

Retrieves a value from the next row.

lead.sql
SELECT
    employee_name,
    salary,
    LEAD(salary) OVER(
        ORDER BY employee_id
    ) AS next_salary
FROM employees;

The last row returns NULL because there is no next row. When to use: compare current month with next month, check upcoming transactions, compare consecutive records.

3. FIRST_VALUE()

Returns the first value in the window frame.

first_value.sql
SELECT
    employee_name,
    department,
    salary,
    FIRST_VALUE(salary) OVER(
        PARTITION BY department
        ORDER BY salary DESC
    ) AS highest_salary
FROM employees;

Returns the highest salary in each department for every employee.

4. LAST_VALUE()

Returns the last value in the current window frame.

last_value.sql
SELECT
    employee_name,
    department,
    salary,
    LAST_VALUE(salary) OVER(
        PARTITION BY department
        ORDER BY salary DESC
        ROWS BETWEEN UNBOUNDED PRECEDING
        AND UNBOUNDED FOLLOWING
    ) AS lowest_salary
FROM employees;

The frame includes the entire department partition, so the result is the lowest salary in that department.

Important: LAST_VALUE() can be confusing because its default frame usually ends at the current row’s last peer. To get the last value of the entire partition, explicitly specify UNBOUNDED FOLLOWING.
6. ROWS BETWEEN — Window Frame

What: defines exactly which rows are considered when calculating a window aggregate or value function. For example, you may want the total of all previous rows, a running total up to the current row, the average of the current and previous two records, or the total of all rows in a department.

Common frame keywords

KeywordMeaning
UNBOUNDED PRECEDINGStart from the first row
CURRENT ROWCurrent row
UNBOUNDED FOLLOWINGContinue until the last row
1 PRECEDINGOne row before current row
1 FOLLOWINGOne row after current row

Example 1: Running total

e1.sql
SELECT
    employee_name,
    salary,
    SUM(salary) OVER(
        ORDER BY employee_id
        ROWS BETWEEN UNBOUNDED PRECEDING
        AND CURRENT ROW
    ) AS running_total
FROM employees;
  • Start from the first row.
  • Include every row up to the current row.
  • Calculate the total.

Example 2: Moving average

Average salary of the current employee and the previous two employees.

e2.sql
SELECT
    employee_name,
    salary,
    AVG(salary) OVER(
        ORDER BY employee_id
        ROWS BETWEEN 2 PRECEDING
        AND CURRENT ROW
    ) AS moving_avg
FROM employees;

Example 3: Total of entire department

e3.sql
SELECT
    employee_name,
    department,
    salary,
    SUM(salary) OVER(
        PARTITION BY department
        ROWS BETWEEN UNBOUNDED PRECEDING
        AND UNBOUNDED FOLLOWING
    ) AS department_total
FROM employees;

Every employee gets the total salary of their department.

7. PARTITION BY vs ORDER BY vs ROWS BETWEEN

These three are important to understand together.

ClauseMain responsibility
PARTITION BYDecides how to divide records into groups
ORDER BYDecides the sequence of records
ROWS BETWEENDecides which rows are included in the calculation
combined.sql
SELECT
    employee_name,
    department,
    salary,

    SUM(salary) OVER(
        PARTITION BY department
        ORDER BY salary DESC
        ROWS BETWEEN UNBOUNDED PRECEDING
        AND CURRENT ROW
    ) AS running_department_salary

FROM employees;

How it works

  1. PARTITION BY department — separates employees by department.
  2. ORDER BY salary DESC — sorts employees from highest to lowest salary.
  3. ROWS BETWEEN — calculates a running total from the highest salary to the current employee’s salary.
8. PARTITION BY with Ranking Functions

One of the most useful combinations is PARTITION BY with RANK(), DENSE_RANK() or ROW_NUMBER(). Requirement: find the highest-paid employee in each department.

rank-per-dept.sql
SELECT
    employee_name,
    department,
    salary,
    RANK() OVER(
        PARTITION BY department
        ORDER BY salary DESC
    ) AS salary_rank
FROM employees;
  • Employees are separated by department.
  • Salary is sorted from highest to lowest within each department.
  • Ranking starts again from 1 for every department.

Real-world example: top 3 employees per department

top3.sql
WITH employee_ranks AS (
    SELECT
        employee_name,
        department,
        salary,
        DENSE_RANK() OVER(
            PARTITION BY department
            ORDER BY salary DESC
        ) AS salary_rank
    FROM employees
)

SELECT *
FROM employee_ranks
WHERE salary_rank <= 3;

Why use a CTE? You cannot directly use a window function in the WHERE clause at the same query level. So calculate rankings inside the CTE, filter them in the outer query, and return the top 3 salary ranks per department.

Important: DENSE_RANK() <= 3 can return more than three employees if multiple employees have the same salary. Use ROW_NUMBER() if you need exactly three rows per department (assuming at least three employees).

Example: find the latest order for each customer

Assume an orders table has order_id, customer_id, order_date, status.

latest-order.sql
WITH ranked_orders AS (
    SELECT
        *,
        ROW_NUMBER() OVER(
            PARTITION BY customer_id
            ORDER BY order_date DESC, order_id DESC
        ) AS rn
    FROM orders
)

SELECT *
FROM ranked_orders
WHERE rn = 1;
  • PARTITION BY customer_id → separates orders by customer.
  • ORDER BY order_date DESC → latest order comes first.
  • ROW_NUMBER() → assigns 1 to the latest order.
  • WHERE rn = 1 → returns one latest order per customer.

This is a very common backend development requirement.

10. Important Rules and Mistakes
RuleExplanation
OVER() is requiredA window function needs an OVER() clause
PARTITION BY is optionalUse it when calculations should be separated into groups
ORDER BY is optionalUse it when sequence or ranking matters
ROWS BETWEEN is optionalUse it when you need a specific frame
WHERE cannot directly filter window resultsUse a CTE or subquery
Window functions preserve rowsUnlike GROUP BY, they do not collapse rows
Ties matterChoose ROW_NUMBER, RANK or DENSE_RANK according to the requirement

Common mistakes

Mistake 1: using a window function directly in WHERE

wrong.sql
-- Incorrect
SELECT *
FROM employees
WHERE ROW_NUMBER() OVER(
    ORDER BY salary DESC
) = 1;
right.sql
-- Correct
WITH ranked AS (
    SELECT *,
        ROW_NUMBER() OVER(
            ORDER BY salary DESC
        ) AS rn
    FROM employees
)
SELECT *
FROM ranked
WHERE rn = 1;

Mistake 2: confusing GROUP BY and PARTITION BY

group-by.sql
-- GROUP BY: one row per department
SELECT department, AVG(salary)
FROM employees
GROUP BY department;
partition-by.sql
-- PARTITION BY: every employee with their department average
SELECT *,
    AVG(salary) OVER(
        PARTITION BY department
    )
FROM employees;

Mistake 3: forgetting ORDER BY

ROW_NUMBER() without an ORDER BY still assigns row numbers, but the order is not guaranteed. If you need a meaningful sequence, always specify an appropriate ordering column.

Mistake 4: assuming ORDER BY inside OVER sorts the final output

m4.sql
SELECT
    employee_name,
    salary,
    ROW_NUMBER() OVER(
        ORDER BY salary DESC
    ) AS rn
FROM employees;

The window ORDER BY determines row numbering, not the final result order. For final output sorting, use:

final-order.sql
ORDER BY salary DESC;

13. What to Learn First

For practical backend development and SQL interviews, learn in this order:

  1. OVER() and PARTITION BY
  2. ROW_NUMBER(), RANK() and DENSE_RANK()
  3. Aggregate functions with window functions.
  4. LAG() and LEAD().
  5. ROWS BETWEEN and moving averages.
  6. CTE + window functions (real-world queries).
Recommendation: pay particular attention to ROW_NUMBER(), PARTITION BY, LAG(), and DENSE_RANK(). These are especially useful when writing backend APIs involving pagination, latest records, rankings, and analytics.
