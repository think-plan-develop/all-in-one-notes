A complete reference for SQL DISTINCT — removing duplicate rows from query results, finding unique values across multiple columns, counting distinct values, combining DISTINCT with WHERE and ORDER BY, and understanding DISTINCT versus GROUP BY.

1. Key Concepts at a Glance
  • DISTINCT removes duplicate rows from the query result.
  • SELECT DISTINCT column returns unique values for that column.
  • SELECT DISTINCT column1, column2 returns unique combinations of both columns.
  • DISTINCT does not delete or modify records in the original table.
  • COUNT(DISTINCT column) counts unique non-NULL values.
  • DISTINCT can be combined with WHERE and ORDER BY.
  • GROUP BY groups rows and is commonly used with aggregate functions.
  • In most SQL databases, SELECT DISTINCT treats NULL values as one distinct value.
  • DISTINCT applies to all selected columns together, not independently to each column.
  • DISTINCT is supported by PostgreSQL, MySQL, SQL Server, and Oracle.
2. DISTINCT — Basic Usage

DISTINCT returns unique rows by eliminating duplicate combinations of values from the selected columns. It affects the query result only and does not change the underlying table.

SELECT DISTINCT

Returns only unique values for the selected column or unique combinations of selected columns.

example.sql
-- Without DISTINCT: duplicates remain
SELECT department
FROM employees;

-- With DISTINCT: duplicate departments removed
SELECT DISTINCT department
FROM employees;

DISTINCT with multiple values

DISTINCT considers the complete selected row when identifying duplicates. Duplicate combinations appear only once.

example.sql
SELECT DISTINCT department, city
FROM employees;

DISTINCT with NULL

In most SQL databases, multiple NULL values in a selected column produce one NULL entry in SELECT DISTINCT results.

example.sql
SELECT DISTINCT phone
FROM users;
3. DISTINCT Across Multiple Columns

When multiple columns are selected, DISTINCT removes duplicate combinations. It does not independently make each column unique.

Unique column combinations

Returns each department-city pair only once. The same city can appear in different departments.

example.sql
SELECT DISTINCT department, city
FROM employee_locations;

Why column order matters

The selected column order determines the output column order. Uniqueness is based on the combination of selected values.

example.sql
SELECT DISTINCT city, department
FROM employee_locations;

DISTINCT does not mean unique per column

A result can contain repeated department values when paired with different cities.

example.sql
SELECT DISTINCT department, city
FROM employee_locations;

-- IT + Hyderabad and IT + Bangalore
-- are different combinations.
4. COUNT(DISTINCT column)

COUNT(DISTINCT column) counts unique non-NULL values. It is useful for calculating unique users, customers, departments, cities, and categories.

Count unique values

Counts each distinct non-NULL value once.

example.sql
SELECT COUNT(DISTINCT customer_id) AS unique_customers
FROM orders;

Count distinct values after filtering

WHERE filters rows before the distinct count is calculated.

example.sql
SELECT COUNT(DISTINCT customer_id) AS unique_customers
FROM orders
WHERE status = 'completed';

DISTINCT versus COUNT(*)

COUNT(*) counts rows, including rows containing NULL values. COUNT(DISTINCT column) counts unique non-NULL values in the specified column.

example.sql
SELECT
  COUNT(*) AS total_rows,
  COUNT(customer_id) AS non_null_ids,
  COUNT(DISTINCT customer_id) AS unique_customers
FROM orders;
5. DISTINCT with WHERE and ORDER BY

DISTINCT works with WHERE to filter records and ORDER BY to sort the resulting unique values.

DISTINCT with WHERE

Filters rows first, then returns unique values from the remaining rows.

example.sql
SELECT DISTINCT department
FROM employees
WHERE salary > 50000;

DISTINCT with ORDER BY

Returns unique values and sorts them in ascending or descending order.

example.sql
SELECT DISTINCT department
FROM employees
ORDER BY department ASC;

DISTINCT with multiple conditions

Combines filtering, unique-value selection, and sorting in one query.

example.sql
SELECT DISTINCT city
FROM customers
WHERE status = 'active'
  AND city IS NOT NULL
ORDER BY city;
Logical Query Processing: For a typical SELECT query, FROM identifies the source, WHERE filters rows, SELECT expressions are evaluated, DISTINCT removes duplicate result rows, and ORDER BY sorts the results. The exact logical processing rules have database-specific details.

-- DISTINCT: unique departments
SELECT DISTINCT department
FROM employees;

-- GROUP BY: employee count per department
SELECT department, COUNT(*) AS employee_count
FROM employees

8. Best Practices
✓ Do
  • Select only the columns needed when using DISTINCT.
  • Remember that DISTINCT evaluates the combination of every selected column.
  • Use COUNT(DISTINCT column) when you need a count of unique non-NULL values.
  • Use GROUP BY when you need aggregates such as counts or sums for each group.
  • Use WHERE to filter rows before DISTINCT is applied.
  • Do not assume DISTINCT chooses the latest or highest record for each user.
  • For the latest record per user, use ROW_NUMBER() with PARTITION BY and ORDER BY in a CTE.
  • On large tables, consider query plans and indexes if DISTINCT is slow.
9. Common Mistakes
✕ Avoid
  • Assuming SELECT DISTINCT department, city makes department values unique independently.
  • Using DISTINCT to permanently delete duplicate records — it only changes query output.
  • Confusing COUNT(DISTINCT column) with COUNT(*).
  • Assuming COUNT(DISTINCT column) includes NULL — standard COUNT ignores NULL values.
  • Using DISTINCT to choose the latest record without defining which row should win.
  • Selecting unnecessary columns, which can prevent otherwise duplicate rows from being considered duplicates.
  • Using DISTINCT to hide incorrect JOIN logic instead of fixing the join.
10. DISTINCT Interview Questions
QuestionAnswer
What is DISTINCT in SQL?DISTINCT removes duplicate rows from the query result based on all selected columns, returning only unique values or combinations.
What is the difference between DISTINCT and GROUP BY?DISTINCT removes duplicate result combinations. GROUP BY groups rows and is commonly used with aggregate functions such as COUNT, SUM, and AVG.
How do you count unique customers?Use SELECT COUNT(DISTINCT customer_id) FROM orders. COUNT(DISTINCT) ignores NULL values.
What happens when DISTINCT is used on two columns?SQL returns unique combinations of both columns. A value in the first column can repeat if it is paired with a different value in the second column.
Does DISTINCT modify the original table?No. DISTINCT only affects the query result. It does not delete or modify any stored rows.
Can DISTINCT be combined with WHERE and ORDER BY?Yes. WHERE filters the source rows, DISTINCT removes duplicate result combinations, and ORDER BY sorts the resulting rows.
Does COUNT(DISTINCT column) count NULL?No. COUNT(DISTINCT column) counts unique non-NULL values.
Can DISTINCT return the latest row for each user?Not reliably by itself. Use ROW_NUMBER() OVER(PARTITION BY user_id ORDER BY created_at DESC) in a CTE and filter for rn = 1.

  • COUNT(DISTINCT column) counts unique non-NULL values.
  • WHERE filters rows before duplicate removal.
