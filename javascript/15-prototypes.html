🧬 Prototype Object

Every object in JavaScript has a hidden internal link to another object called its prototype. When you try to read a property that doesn't exist directly on the object, JavaScript automatically looks it up on the prototype instead — and if it's not there either, it keeps looking up the prototype's own prototype, and so on. This is how methods like .toString() or .map() are available on every object/array without being copied onto each one individually.

prototype-object.js
const obj = {};
console.log(obj.toString()); // "[object Object]"
// obj doesn't define toString() itself —
// it's found on obj's prototype: Object.prototype

console.log(Object.getPrototypeOf(obj) === Object.prototype); // true
📌 Note: The prototype itself is just a normal object — it can have its own prototype too, forming a chain that eventually ends at null.
🔗 Prototype Chain

The prototype chain is the sequence of linked objects JavaScript walks through when looking up a property: the object itself, then its prototype, then that prototype's prototype, and so on, until it finds the property or reaches null (the end of every chain).

prototype-chain.js
const animal = { eats: true };
const dog = Object.create(animal);  // dog's prototype is 'animal'
dog.barks = true;

console.log(dog.barks); // true -> found directly on dog
console.log(dog.eats);  // true -> not on dog, found on animal (its prototype)

// Chain: dog -> animal -> Object.prototype -> null
console.log(Object.getPrototypeOf(animal) === Object.prototype); // true
console.log(Object.getPrototypeOf(Object.prototype));         // null -> end of chain
⚠️ Warning: Long prototype chains make property lookups slower (JS has to walk further before giving up or finding the value) — keep chains shallow where performance matters.
🔍 __proto__

__proto__ is an accessor property (getter/setter) available on almost every object that exposes its internal prototype link directly, letting you read or set it. It's the historical, informal way to interact with the prototype chain — the modern, standard alternatives are Object.getPrototypeOf() and Object.setPrototypeOf().

dunder-proto.js
const animal = { eats: true };
const dog = {};

dog.__proto__ = animal;          // old-school way to set the prototype
console.log(dog.eats);       // true (inherited via __proto__ link)

// Preferred modern equivalents:
Object.setPrototypeOf(dog, animal);
console.log(Object.getPrototypeOf(dog) === animal); // true
💡 Tip: Avoid using __proto__ in real code — it was only standardized for legacy browser compatibility. Use Object.getPrototypeOf() / Object.setPrototypeOf() instead, and prefer Object.create() when setting up the prototype at creation time (faster than setting it afterward).
🏗️ prototype

prototype is different from __proto__ — it's a regular property that exists only on functions (specifically ones meant to be used as constructors), not on plain objects. It's the object that will become the __proto__ of every instance created with new. This is how shared methods get attached once and used by every instance, instead of being duplicated on each one.

dot-prototype.js
function Dog(name) {
  this.name = name;
}

Dog.prototype.bark = function() {   // shared by every instance
  console.log(this.name + " says woof!");
};

const rex = new Dog("Rex");
rex.bark();  // "Rex says woof!"

console.log(rex.__proto__ === Dog.prototype); // true
console.log(rex.hasOwnProperty("bark"));   // false -> bark lives on Dog.prototype, not on rex itself

🧑‍🤝‍🧑 Inheritance

JavaScript implements inheritance through the prototype chain rather than classical class-copying: an object "inherits" by having another object as its prototype, so it can use that object's properties/methods as if they were its own. ES6 class syntax with extends and super is just a cleaner way to write this same prototype-based mechanism.

Constructor-function style (pre-ES6)

inheritance-constructor.js
function Animal(name) {
  this.name = name;
}
Animal.prototype.eat = function() {
  console.log(this.name + " is eating");
};

function Dog(name) {
  Animal.call(this, name);   // borrow Animal's constructor logic
}
Dog.prototype = Object.create(Animal.prototype); // link Dog's prototype to Animal's
Dog.prototype.constructor = Dog;

const rex = new Dog("Rex");
rex.eat(); // "Rex is eating" -> inherited from Animal.prototype

Modern class style (same mechanism, cleaner syntax)

inheritance-class.js
class Animal {
  constructor(name) {
    this.name = name;
  }
  eat() {
    console.log(this.name + " is eating");
  }
}

class Dog extends Animal {
  bark() {
    console.log(this.name + " says woof!");
  }
}

const rex = new Dog("Rex");
rex.eat();  // "Rex is eating" -> inherited from Animal
rex.bark(); // "Rex says woof!" -> defined on Dog

console.log(rex instanceof Animal); // true -> Dog.prototype's prototype is Animal.prototype
✅ Benefit: Under the hood, class ... extends just wires up the prototype chain automatically (Dog.prototype.__proto__ === Animal.prototype) — it's syntax sugar over the exact same prototype-based inheritance shown above, not a different inheritance model.
Interview Questions
🎤 Prototype Interview Questions

1. What is a prototype in JavaScript? Explain the Prototype object and how JavaScript uses it for inheritance.

A prototype is an object that other objects can inherit properties and methods from. Every object carries an internal link to its prototype, and when you access a property that isn't found directly on the object, JavaScript automatically looks it up on the prototype instead. This lookup mechanism is JavaScript's inheritance model: rather than copying members into every instance, instances share a single prototype object and read shared behavior from it on demand.

2. What is the difference between __proto__, prototype, and [[Prototype]]? Frequently Asked

These three terms are often confused, but they describe three distinct things:

TermWhat it is
[[Prototype]]The actual internal slot every object has, holding the real link to its prototype. It's not directly accessible by that name in code — it's a spec-level concept.
__proto__A legacy accessor property (getter/setter) exposed on object instances that lets you read or set their [[Prototype]] from regular code.
prototypeA plain property that exists only on functions/classes used as constructors. It's the object that becomes the [[Prototype]] (and therefore the __proto__) of every instance created with new.
💡 Tip: A clean way to phrase it in an interview: "prototype is on the constructor and decides what instances will inherit; __proto__ is on the instance and shows what it actually inherited; [[Prototype]] is the internal mechanism both of those are just interfaces to."

3. How does the Prototype Chain work in JavaScript?

When you access a property on an object, the engine first checks the object itself. If it isn't found there, it moves to the object's [[Prototype]], then that object's own prototype, and so on — this sequence of linked objects is the prototype chain. The search stops as soon as a match is found (an "own" property closer to the object always shadows one further up the chain), or continues until the chain ends at null, at which point the property is undefined.

4. How do you add methods to all instances of a constructor function? Why put them on Constructor.prototype instead of inside the constructor?

Attach the method to Constructor.prototype so it's defined once and shared by every instance through the prototype chain, rather than defining it inside the constructor function body with this.method = function(){...}, which would recreate a brand-new function object on every single instantiation. For thousands of instances, that's thousands of duplicate function objects wasting memory — prototype methods avoid that entirely, and also make it possible to patch or extend behavior for all existing instances at once.

5. What is the difference between prototype inheritance and classical inheritance? Compare with Java or C#.

In classical languages like Java or C#, inheritance is based on classes: a class is a fixed, compile-time blueprint, and objects are instances built from it — the hierarchy is static and defined ahead of time. JavaScript's prototypal model has objects inherit directly from other objects at runtime; there's no separate "blueprint" concept, prototypes can be reassigned or modified dynamically even after objects exist, and the inheritance chain is just a live series of object references. ES6 class syntax makes JS look classical, but underneath it's still prototype links — there's no true class-based mechanism running the show.

6. What is the relationship between Object.create() and prototypes? How does it create an object with a specified prototype?

Object.create(proto) creates a brand-new, empty object whose [[Prototype]] is set directly to whatever object you pass in — no constructor function or new keyword involved. It's the most direct way to express "make an object that inherits from this other object," which is useful for pure prototypal inheritance patterns without the ceremony of constructor functions or classes.

object-create.js
const animal = { eats: true };
const dog = Object.create(animal); // dog's [[Prototype]] is set to 'animal' directly
console.log(dog.eats);       // true -> inherited
console.log(Object.getPrototypeOf(dog) === animal); // true

7. Can you modify the prototype of built-in objects like Array or String? Should you?

Technically yes — you can add to Array.prototype or String.prototype and every array or string in your program instantly gets that new method, a practice called monkey-patching or prototype extension. It's generally discouraged, though: a future JavaScript version might add a native method with the same name and different behavior, silently breaking your code; different libraries patching the same built-in can collide and overwrite each other; and added properties can unexpectedly show up in for...in loops over arrays/objects if not made non-enumerable. Safer alternatives are writing standalone utility functions or extending your own custom classes instead of built-ins.

8. How do ES6 classes use prototypes internally?

class syntax is syntactic sugar over the exact same prototype system that existed before ES6 — it doesn't introduce a new inheritance model. Methods written inside a class body are attached to ClassName.prototype automatically (and made non-enumerable, unlike manually-added prototype properties). When you write class Dog extends Animal, JavaScript wires up two links behind the scenes: Dog.prototype's own prototype is set to Animal.prototype (so instances inherit instance methods), and Dog itself is linked to Animal (so static methods are inherited too). super() inside the constructor is just a controlled call to the parent constructor function, and super.method() looks up the method starting from the parent's prototype instead of the child's.

📌 Note: You can verify this yourself: Object.getPrototypeOf(Dog.prototype) === Animal.prototype is true for any class Dog extends Animal.
