1. Debouncing
⏳

Wait for a Pause Before Reacting

Performance

Debouncing means waiting for a short delay before updating state or running a function. If the trigger fires again before the delay ends, the previous timer is cancelled and a new one starts — so only the last call in a burst actually runs.

React Example

debounce-search.js
const [searchTerm, setSearchTerm] = useState("");

let typing;

const searchInputHandle = (value) => {
  clearTimeout(typing);

  typing = setTimeout(() => {
    setSearchTerm(value);
  }, 400);

  if (!value) {
    setSearchTerm("");
    clearTimeout(typing);
  }
};
💡 Every keystroke cancels the pending timer and starts a fresh one — setSearchTerm only actually runs once typing pauses for 400ms.

Where React Debouncing Shows Up

Use CaseWhy
Search-as-you-type inputsAvoid firing an API call on every keystroke
Form field validationValidate once the user pauses, not on every character
Auto-save draftsPersist only after edits settle down
Window resize-driven layout stateRecalculate once resizing stops, inside a useEffect
⚠️ Always clean up the timer in the useEffect return function. Without it, a component that unmounts mid-delay can trigger a "state update on an unmounted component" warning.
2. Throttling
🚦

Run at Most Once Every Interval

Performance

Throttling limits how often a function can run — it allows execution at most once within a given time interval. If the interval is 1000ms, the function runs only once every second, no matter how many times it's called during that window.

📌 Why "throttle"? The word comes from a vehicle's throttle, which controls how much fuel/air enters the engine. In programming, throttling means controlling or limiting the rate of execution the same way.

A Simple Throttle Implementation

throttle.js
function throttle(fn, delay) {
  let waiting = false;

  return function () {
    if (waiting) return; // ignore extra calls

    fn(); // run function
    waiting = true;

    setTimeout(() => {
      waiting = false; // allow next call after delay
    }, delay);
  };
}

const sayHello = throttle(() => {
  console.log('Hello');
}, 2000);

sayHello(); // Hello
sayHello(); // ignored
sayHello(); // ignored

// After 2 seconds:
sayHello(); // Hello
DebounceThrottle
Waits for a pause in activityRuns at a steady, capped rate
Good for: search input, form validationGood for: scroll, resize, drag, mouse-move handlers
⚠️ Always clean up event listeners or timers tied to a throttled handler — an un-removed scroll or resize listener is a common source of memory leaks.
3. Currying
🍛

Configure Once, Reuse Many Times

Functional

Currying is a technique where a function that takes multiple arguments is transformed into a sequence of functions, where each function takes one argument at a time.

When Should You Use It?

  • Create reusable pre-configured functions
  • Avoid repeating the same arguments
  • Build pipelines of small, composable functions
  • Delay execution until all required information is available

Tax Calculator

tax-calculator.js
function tax(rate) {
  return function (amount) {
    return amount + amount * rate;
  };
}

const addGST = tax(0.18);

console.log(addGST(1000)); // 1180
console.log(addGST(5000)); // 5900

Real Example — API URL Builder

Imagine a frontend application making multiple API calls.

Without currying:

without-currying.js
function buildUrl(baseUrl, version, endpoint) {
  return `${baseUrl}/api/${version}/${endpoint}`;
}

buildUrl('https://myapp.com', 'v1', 'users');
buildUrl('https://myapp.com', 'v1', 'orders');
buildUrl('https://myapp.com', 'v1', 'payments');
buildUrl('https://myapp.com', 'v1', 'reports');
⚠️ The base URL and API version are repeated in every call. This violates the DRY (Don't Repeat Yourself) principle and makes the code harder to maintain.

With currying:

with-currying.js
function buildUrl(baseUrl) {
  return function (version) {
    return function (endpoint) {
      return `${baseUrl}/api/${version}/${endpoint}`;
    };
  };
}

const appApi = buildUrl('https://myapp.com');
const v1Api = appApi('v1');

// Reuse the configured function
v1Api('users');
v1Api('orders');
v1Api('payments');
v1Api('reports');

console.log(v1Api('users'));
// https://myapp.com/api/v1/users

console.log(v1Api('orders'));
// https://myapp.com/api/v1/orders
✅ Now the repeated configuration is removed — you configure the base URL once, the API version once, and use only the endpoint for every request. This makes the code cleaner, easier to maintain, and less error-prone.

Interview Explanation

Currying is a technique where a function with multiple parameters is converted into a sequence of functions that take one parameter at a time. It's useful for creating reusable pre-configured functions, reducing argument repetition, and improving function composition. In real-world applications, it's commonly used in scenarios such as tax calculators, API URL builders, and configurable utility functions.

💡 Remember: Currying = configure once, reuse many times.
4. Partial Application
🧩

Fix Some Arguments Now, Rest Later

Functional

Partial application means fixing some arguments of a function in advance and creating a new function that only needs the remaining arguments. Unlike currying, you can pass multiple arguments at once.

partial-application.js
// 🔹 Normal function
function greet(greeting, name, punctuation) {
  return `${greeting}, ${name}${punctuation}`;
}

// 🔹 Partial helper
function partial(fn, ...presetArgs) {
  return function (...remainingArgs) {
    return fn(...presetArgs, ...remainingArgs);
  };
}

// Pre-fill only the greeting
const sayHello = partial(greet, "Hello");
console.log(sayHello("Sam", "!")); // Hello, Sam!

// Pre-fill greeting and name
const sayHelloToSam = partial(greet, "Hello", "Sam");
console.log(sayHelloToSam(".")); // Hello, Sam.

What Is Happening?

StepMeaning
partial(greet, "Hello")Creates a new function with greeting already fixed.
sayHello("Sam", "!")Passes only the remaining arguments.
partial(greet, "Hello", "Sam")Fixes both greeting and name.
sayHelloToSam(".")Only punctuation is left to provide.

Why Use Partial Application?

  • Avoid repeating common arguments
  • Create reusable pre-configured functions
  • Make code easier to read
  • Useful for event handlers, API clients, and logging utilities
💡 Think of it as: configure some arguments now, use the remaining arguments later.
5. Function Composition
🧵

Combining Small Functions Into a Pipeline

Functional

Function composition means combining multiple small functions into one pipeline, where the output of one function becomes the input of the next function.

compose.js
// Small reusable functions
function double(n) {
  return n * 2;
}

function addOne(n) {
  return n + 1;
}

function square(n) {
  return n * n;
}

// compose() helper (right → left)
function compose(...fns) {
  return function (value) {
    return fns.reduceRight((acc, fn) => fn(acc), value);
  };
}

// Create a pipeline
const calculate = compose(square, addOne, double);

// Run it
console.log(calculate(3)); // 49

Execution Flow

  • double(3) → 6
  • addOne(6) → 7
  • square(7) → 49

So the pipeline is: 3 → double → addOne → square → 49

Why Use It?

  • Break complex logic into small reusable functions
  • Make code cleaner and easier to test
  • Build data transformation pipelines
💡 Interview one-liner: Function composition combines small functions so that the output of one function becomes the input of the next, creating reusable and maintainable pipelines.
6. Memoization
🗃️

Caching Results to Skip Repeated Work (React)

Performance

In React, memoization means avoiding expensive recalculations or unnecessary re-renders. React ships three built-in tools for it: useMemo, useCallback, and React.memo.

useMemo — Cache an Expensive Calculated Value

UseMemoExample.jsx
import { useMemo, useState } from "react";

function ProductList({ products, query }) {
  const [sortOrder, setSortOrder] = useState("asc");

  // Only recompute filteredProducts when products or query change
  const filteredProducts = useMemo(() => {
    return products.filter(p =>
      p.name.toLowerCase().includes(query.toLowerCase())
    );
  }, [products, query]);

  return filteredProducts;
}
ToolMemoizesUse When
useMemoA computed valueAn expensive calculation shouldn't rerun every render
useCallbackA function referencePassing a stable callback to a memoized child, or as a dependency
React.memoAn entire component's outputA component re-renders often but its props rarely actually change
⚠️ useMemo/useCallback aren't free — they carry their own overhead. Reach for them when profiling shows an actual bottleneck, not as a default habit on every value and function.
7. Interview Questions & Answers

Basic Level 1

1

What is debouncing?

Debouncing delays a function's execution until a specified time has passed without it being called again — resetting the timer on every new call.

2

What is throttling?

Throttling limits a function to run at most once within a fixed time interval, regardless of how many times it's triggered.

3

Difference between debouncing and throttling.

DebouncingThrottling
Runs once after activity stopsRuns at a steady, limited rate during activity
Delays execution repeatedly on each callIgnores extra calls until the interval passes
4

What is currying?

Currying transforms a function that takes multiple arguments into a sequence of functions that each accept a single argument, returning a new function until all arguments are supplied.

what-is-currying.js
const add = a => b => a + b;
add(2)(3); // 5
5

What is memoization?

Memoization is an optimization technique that caches the results of expensive function calls, returning the cached result when the same inputs occur again.

Intermediate Level 2

6

How would you implement a simple debounce function?

simple-debounce.js
function debounce(fn, delay) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}
7

How would you implement a simple throttle function?

simple-throttle.js
function throttle(fn, interval) {
  let waiting = false;
  return (...args) => {
    if (waiting) return;
    fn(...args);
    waiting = true;
    setTimeout(() => (waiting = false), interval);
  };
}
8

Difference between currying and partial application.

CurryingPartial Application
Always one argument per callAny number of arguments per call
Returns nested single-argument functionsPre-fills some arguments, returns a function for the rest
9

What is function composition?

Function composition combines multiple simple functions into one, where each function's output feeds into the next function as input.

10

Why does memoization only work reliably on pure functions?

A pure function always returns the same output for the same input, so caching by input is safe. A function with side effects or that reads changing external state could return a stale, incorrect cached value.

Advanced Level 3

11

Why do currying, memoization, debouncing, and throttling all rely on closures?

Each pattern needs to preserve state — collected arguments, a cache, a timer ID, or a waiting flag — across multiple separate function calls. A closure is exactly what lets a returned function keep a live reference to that state instead of losing it when the outer function finishes.

12

What's a real trade-off of memoization?

Memory usage grows unboundedly as more unique argument combinations are cached, since the cache is never automatically cleared. For functions called with many distinct inputs, this can leak memory — consider capping cache size or using a WeakMap for object keys so entries can be garbage collected.

13

Leading vs. trailing edge in debounce/throttle implementations.

A "trailing edge" debounce (the common version) fires after the pause. A "leading edge" version fires immediately on the first call, then ignores subsequent calls until the wait period passes — useful when you want instant feedback but still want to prevent rapid re-firing.

14

Guess the Output — Throttle Timing

throttle-timing.js
const log = throttle(() => console.log("tick"), 1000);

log(); // "tick" — runs immediately
log(); // ignored — still within the 1000ms window
log(); // ignored — still within the 1000ms window
