🟨 JavaScript Fundamentals

What JavaScript is and why it behaves the way it does, its 8 built-in data types, primitive vs. reference values, and how type conversion & coercion work under the hood

Introduction Features of JS Data Types Primitive vs Reference Type Conversion
📌 In short: JavaScript is a high-level, interpreted, dynamically typed, single-threaded, prototype-based language that handles long-running work asynchronously and reacts to events. It has 8 built-in data types — 7 primitives plus Object. Primitives are copied by value; objects are copied by reference. Values convert between types either explicitly (you call String()/Number()/Boolean()) or implicitly (JavaScript coerces them for you, sometimes with surprising results).
🔑 Key Terms at a Glance
🧵
Single-Threaded: JavaScript runs on one Call Stack and executes one instruction at a time.
⏳
Asynchronous: Long-running work (timers, network calls) runs in the background so the rest of the program keeps executing.
🧬
Primitive vs Reference: Primitives store the actual value and are copied by value; objects store a memory reference and are copied by reference.
🔄
Type Coercion: JavaScript's automatic, sometimes surprising, conversion of a value from one type to another.
🧩
Prototype-Based: Objects inherit directly from other objects via prototypes, rather than strictly from classes.
Introduction to JavaScript
What is JavaScript?
JavaScript (JS) is a high-level, interpreted, dynamically typed, prototype-based, single-threaded, asynchronous, and event-driven programming language used to build interactive web applications.

It was originally created to make web pages interactive. Today it powers a lot more than that:

  • Frontend Development (React, Angular, Vue)
  • Backend Development (Node.js)
  • Mobile Apps (React Native)
  • Desktop Apps (Electron)
  • Games
  • APIs & Microservices
  • Browser Extensions
  • IoT Applications

Features of JavaScript
📖

High-Level Language

JavaScript is a high-level programming language, meaning it's easier for humans to read and write.

Characteristics

  • Syntax is close to human language.
  • Automatic memory management (Garbage Collection).
  • Developers don't need to manage memory manually.
  • Less control over hardware compared to low-level languages.
high-level.js
let message = "Hello World";
console.log(message);
⚡

Interpreted Language

JavaScript is generally considered an interpreted language. Instead of compiling the entire program before execution, it executes code as it runs — modern engines like V8 internally use Just-In-Time (JIT) compilation for optimization.

Characteristics

  • Executes code immediately.
  • No separate compilation step required.
  • Errors are usually discovered during execution (runtime).
interpreted.js
console.log("Hello");

let x = 10;

console.log(x);
🔀

Dynamically Typed Language

JavaScript is dynamically typed, meaning you don't need to declare the data type of a variable — it's decided automatically based on the assigned value, and the same variable can hold different types over its lifetime.

dynamic-typing.js
let x = 5;          // Number

x = "Hello";        // String

x = true;           // Boolean
🧵

Single-Threaded Language

JavaScript is single-threaded, meaning it executes one task at a time on its main thread. It has one Call Stack, and instructions are executed one after another.

single-threaded.js
console.log("A");

console.log("B");

console.log("C");

// Output:
// A
// B
// C

Why is JavaScript single-threaded?

  • Prevents race conditions.
  • Prevents multiple threads from modifying the DOM simultaneously.
  • Makes execution predictable and easier to manage.

Problem: blocking code

Since JavaScript executes one task at a time, a long-running task blocks everything else.

blocking.js
while (true) {
  // Infinite loop
}
⚠️ The browser becomes unresponsive because the Call Stack never gets empty.
🧩

Object-Based (Prototype-Based)

JavaScript is an object-based language that follows prototype-based inheritance. Instead of creating objects strictly from classes, objects can inherit directly from other objects using prototypes.

Characteristics

  • Objects are created from other objects.
  • Inheritance happens through prototypes.
  • Objects can share methods and properties.
📌 Note: ES6 introduced the class syntax, but JavaScript classes are simply a cleaner syntax built on top of the prototype system.
⏳

Asynchronous (Non-Blocking)

Although JavaScript is single-threaded, it can perform long-running operations without stopping the rest of the program — API calls, timers, file operations, database requests. It achieves this using callbacks, Promises, and async/await.

async.js
console.log("Start");

setTimeout(() => {
  console.log("Done");
}, 2000);

console.log("End");

// Output:
// Start
// End
// Done
✅ Notice that JavaScript continues executing other code instead of waiting for the timer.
🖱️

Event-Driven Language

JavaScript is event-driven, meaning it waits for events and executes code only when those events occur — button clicks, mouse movement, keyboard input, form submission, page load.

event-driven.js
button.addEventListener("click", () => {
  console.log("Button clicked");
});

Instead of continuously checking for user actions, JavaScript waits for an event and responds only when needed.

Data Types

What are Data Types?

A data type defines the kind of value a variable can store. It tells JavaScript how the value should be stored and what operations can be performed on it.

data-types.js
let name = "Shivam";   // String
let age = 25;          // Number
let isAdmin = true;    // Boolean

JavaScript is a dynamically typed language, so variables don't require explicit type declarations — the same variable can be reassigned to a different type entirely.

reassign.js
let value = 10;        // Number
value = "Hello";       // String
value = false;        // Boolean
⚖️

🔎

typeof Operator

The typeof operator checks the data type of a value.

typeof.js
typeof "Hello";      // "string"
typeof 100;          // "number"
typeof true;         // "boolean"
typeof undefined;    // "undefined"
typeof Symbol();     // "symbol"
typeof 10n;          // "bigint"
typeof {};           // "object"
typeof [];           // "object"
typeof function(){}; // "function"

The typeof null bug

typeof-null.js
typeof null; // "object"

This is a historical JavaScript bug. Although null is a primitive data type, typeof null returns "object" for backward compatibility. To correctly check for null, compare directly:

null-check.js
value === null
💡 Tip: Use Array.isArray() to check if a value is an array, since typeof [] returns "object".
is-array.js
Array.isArray([]);   // true
🔢

Number Special Values

NaN (Not a Number)

NaN represents an invalid numeric result.

nan.js
Number("Hello"); // NaN
0 / 0;           // NaN

Check for NaN using:

is-nan.js
Number.isNaN(value);

Infinity

Represents a value larger than any finite number.

infinity.js
10 / 0;   // Infinity
-10 / 0;  // -Infinity
🧿

Symbol

A Symbol is a unique and immutable primitive value, commonly used as unique object property keys.

symbol.js
const id1 = Symbol("id");
const id2 = Symbol("id");

console.log(id1 === id2); // false
🔟

BigInt

BigInt is used to store integers larger than the safe limit of the Number type (9007199254740991).

bigint.js
const big = 123456789012345678901234567890n;
📌 Note: A BigInt value always ends with the n suffix.

Primitive vs Reference Types
📐

Definition & Memory Storage

Primitive values store the actual value. Reference values store the memory address of an object.

primitive.js
let age = 25; // stored directly in memory
reference.js
const user = {
    name: "John"
};
// stored in the Heap, the variable only holds a reference to it
📚

Stack vs Heap

Stack — stores primitive values. Fast, fixed size, stores actual values.

age → 25 name → "John"

Heap — stores objects. Variables on the Stack store only the memory reference.

user ─────► Object { name: "John" }
📋

Primitive Copy vs Reference Copy

Copying a primitive creates an independent value.

primitive-copy.js
let a = 10;

let b = a;

b = 20;

console.log(a); // 10
console.log(b); // 20

Objects, on the other hand, share the same memory reference.

reference-copy.js
const user1 = {
    name: "John"
};

const user2 = user1;

user2.name = "Mike";

console.log(user1.name); // "Mike"
⚠️ Changing user2 changed user1 too — they're two variables pointing at the exact same object in the Heap.
✏️

Object Mutation

Objects are mutable — updating a property modifies the existing object rather than creating a new one.

mutation.js
const user = {
    age: 20
};

user.age = 25;
🗂️

Shallow Copy vs Deep Copy

A shallow copy copies only the first level — nested objects remain shared.

shallow-copy.js
const obj1 = {
    name: "John",
    address: {
        city: "Delhi"
    }
};

const obj2 = { ...obj1 };

// Changing obj2.address.city also changes obj1.address.city

A deep copy creates completely independent copies, including nested objects. The modern, recommended approach is structuredClone():

deep-copy.js
const copy = structuredClone(original);
// supports nested objects, arrays, Maps, Sets, Dates, etc.

The spread operator and Object.assign() both only go one level deep:

shallow-methods.js
const copyA = { ...original };
const copyB = Object.assign({}, original);
// both are shallow copies

Type Conversion

What is Type Conversion?

Type conversion is the process of converting a value from one data type to another. There are two kinds: explicit conversion and implicit conversion (type coercion).

explicit.js
String(100);

Number("100");

Boolean(1);

Done automatically by JavaScript instead:

implicit.js
"5" + 1;  // "51"
"5" - 1;  // 4
🔤

String() & Number()

string.js
String(100);
// Output: "100"
number.js
Number("100");
// Output: 100

Number("Hello");
// Output: NaN
☑️

Boolean() & Falsy Values

Falsy values: false, 0, -0, 0n, "", null, undefined, NaN. Everything else is truthy.

boolean.js
Boolean("");
// Output: false
🔟

parseInt() & parseFloat()

parseInt() extracts the integer part; parseFloat() extracts decimal numbers.

parse-int.js
parseInt("25px");
// Output: 25
parse-float.js
parseFloat("10.75px");
// Output: 10.75
🎲

Common Type Coercion Rules

coercion-rules.js
"5" + 1;       // "51"

"5" - 1;       // 4

true + 1;      // 2

false + 1;     // 1

null + 1;      // 1

undefined + 1; // NaN

[] + [];       // ""

[] + {};       // "[object Object]"

{} + [];       // 0 (in some contexts)
💡 Tip: coercion rules like these are a common source of bugs — when in doubt, convert explicitly instead of relying on JavaScript to guess.
🚫

NaN

NaN stands for Not-a-Number, but its type is still "number".

nan-type.js
typeof NaN;
// Output: "number"

Checking for NaN:

is-nan-check.js
Number.isNaN(value);
⚠️ Avoid the global isNaN() — it performs type coercion first, which can give misleading results. Prefer Number.isNaN().
