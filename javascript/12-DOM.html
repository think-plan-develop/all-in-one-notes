🌳 DOM Tree

The DOM (Document Object Model) is a tree-shaped representation of an HTML page that JavaScript can read and manipulate. Every tag becomes an element node, every piece of text becomes a text node, and the whole tree starts from a single root: document. Nodes are connected as parents, children, and siblings — exactly like a family tree.

dom-tree.html
<!-- This HTML... -->
<div id="app">
  <h1>Hello</h1>
  <p>World</p>
</div>

// ...becomes this tree:
// document
//   └── html
//         └── body
//               └── div#app
//                     ├── h1 → "Hello"
//                     └── p  → "World"
📌 Note: document is the entry point to the entire tree — every selection or traversal method you use ultimately starts from it.
🔍 Selecting Elements

Before you can change anything on a page, you need to grab a reference to it. Modern JS mostly relies on querySelector/querySelectorAll (CSS-selector syntax), while the older methods are still common in legacy code.

selecting.js
document.getElementById("app");            // single element by id
document.getElementsByClassName("card");    // live HTMLCollection
document.getElementsByTagName("li");        // live HTMLCollection
document.querySelector(".card h4");         // first match, any CSS selector
document.querySelectorAll(".card");          // static NodeList of ALL matches
💡 Tip: getElementsBy* methods return a live collection (auto-updates as the DOM changes); querySelectorAll returns a static snapshot taken at call time.
🧭 Traversing the DOM

Once you have one element, you often need to move to related elements — its parent, children, or siblings — without running another query.

traversing.js
const el = document.querySelector("#app");

el.parentElement;             // closest parent (Element only)
el.children;                  // HTMLCollection of child elements
el.childNodes;                // NodeList, includes text/comment nodes too
el.firstElementChild;         // first child element
el.lastElementChild;          // last child element
el.nextElementSibling;        // next sibling element
el.previousElementSibling;    // previous sibling element
📌 Note: Prefer the *Element* versions (firstElementChild, nextElementSibling...) over the plain versions (firstChild, nextSibling) — the plain ones also match whitespace/text nodes, which trips people up.
➕ Creating Elements

New elements are built with document.createElement() and then attached somewhere in the tree with appendChild, append, prepend, or insertBefore.

creating.js
const li = document.createElement("li");
li.textContent = "New item";
li.classList.add("todo-item");

const list = document.querySelector("#todo-list");
list.appendChild(li);                 // adds at the end
list.prepend(li);                    // adds at the start
list.insertBefore(li, list.firstElementChild); // insert at a specific spot
list.insertAdjacentHTML("beforeend", "<li>Quick item</li>");
⚠️ Warning: insertAdjacentHTML (and setting innerHTML) with untrusted input opens the door to XSS — never inject raw user input this way.
🗑️ Removing Elements

Elements can remove themselves directly with .remove(), or a parent can remove a specific child with removeChild().

removing.js
const item = document.querySelector(".todo-item");
item.remove();                        // modern, simplest way

const list = document.querySelector("#todo-list");
list.removeChild(list.firstElementChild); // older, needs the parent
💡 Tip: Avoid list.innerHTML = "" to "remove everything" on large trees if you've attached listeners inside — it silently discards them without cleanup and can cause subtle memory issues in long-lived apps.
✏️ Updating Elements

You can update text, HTML, attributes, classes, or inline styles of an existing element without recreating it.

updating.js
el.textContent = "Plain text only";        // safe, no HTML parsing
el.innerHTML = "<b>Bold</b>";             // parses HTML, XSS risk with user input

el.setAttribute("data-id", "42");
el.getAttribute("data-id");              // "42"
el.removeAttribute("data-id");

el.classList.add("active");
el.classList.remove("active");
el.classList.toggle("active");
el.classList.contains("active");      // true/false

el.style.color = "crimson";
🖱️ Event Handling

addEventListener() attaches a function that runs when a given event fires on an element. It's preferred over inline onclick="..." attributes because it cleanly separates markup from behavior and allows multiple listeners on the same element.

event-handling.js
const btn = document.querySelector("#saveBtn");

function handleClick(event) {
  console.log("Clicked:", event.target);
}

btn.addEventListener("click", handleClick);
btn.removeEventListener("click", handleClick); // must pass the same function reference
📌 Note: The event object gives you event.target (what was actually clicked), event.currentTarget (the element the listener is attached to), and methods like preventDefault() and stopPropagation().
🫧 Event Bubbling

When an event fires on an element, it doesn't just run there — it then bubbles up through every ancestor, triggering their listeners for the same event type too, all the way to document. This is the default phase most listeners run in.

bubbling.js
// <div id="outer"><div id="inner"><button id="btn">Click</button></div></div>

document.querySelector("#outer").addEventListener("click", () => console.log("outer"));
document.querySelector("#inner").addEventListener("click", () => console.log("inner"));
document.querySelector("#btn").addEventListener("click", () => console.log("btn"));

// Clicking the button logs: "btn" -> "inner" -> "outer"
// (target first, then upward through each ancestor)
💡 Tip: Call event.stopPropagation() inside a listener to stop the event from bubbling any further up.
🎯 Event Capturing

Capturing is the opposite direction of bubbling: the event travels down from document toward the target first, before the bubbling phase happens. Listeners only run during capturing if you explicitly opt in by passing true (or { capture: true }) as the third argument to addEventListener.

capturing.js
document.querySelector("#outer").addEventListener("click", () => console.log("outer (capture)"), true);
document.querySelector("#inner").addEventListener("click", () => console.log("inner (capture)"), true);
document.querySelector("#btn").addEventListener("click", () => console.log("btn"));

// Clicking the button logs: "outer (capture)" -> "inner (capture)" -> "btn"
// capturing runs top-down BEFORE the target's own bubbling listener fires

🪄 Event Delegation

Event delegation means attaching a single listener to a common parent instead of one listener per child, and using event.target inside it to figure out which child was actually interacted with. It relies entirely on bubbling.

delegation.js
// Instead of adding a click listener to every <li>...
const list = document.querySelector("#todo-list");

list.addEventListener("click", (event) => {
  if (event.target.matches("li")) {
    console.log("Clicked item:", event.target.textContent);
  }
});

// Works even for <li> elements added to the list LATER —
// no need to re-attach a listener to new items.
✔ Why delegate
  • One listener instead of hundreds — better performance
  • Automatically works for dynamically added children
  • Less memory usage, easier cleanup
✘ Watch out for
  • Need to check event.target carefully (use .matches()/.closest())
  • Doesn't work for non-bubbling events (e.g. focus, blur)
  • Deeply nested markup can make target-matching tricky
DOM Interview Questions
🎤 DOM Interview Questions

1. What is the DOM?

A tree-structured, in-memory representation of an HTML document that JavaScript can read and modify. Every element, attribute, and piece of text becomes a node in this tree, rooted at document.

2. What's the difference between querySelector and getElementById?

getElementById only matches by id and is marginally faster, while querySelector accepts any CSS selector (class, attribute, combinator, pseudo-class) but only returns the first match.

3. What's the difference between a live collection and a static NodeList?

A live collection (from getElementsByClassName/getElementsByTagName) automatically reflects later DOM changes. A static NodeList (from querySelectorAll) is a snapshot — it won't update even if matching elements are added or removed afterward.

4. What's the difference between innerHTML, textContent, and innerText?

innerHTML parses and renders a string as HTML (risk of XSS with untrusted input). textContent sets/gets raw text without parsing HTML and includes hidden elements' text. innerText is similar to textContent but is aware of CSS styling (ignores hidden elements, triggers a reflow — so it's slower).

5. How do you check if an element has a class, and how do you add/remove one?

Use the classList API: el.classList.contains("x"), el.classList.add("x"), el.classList.remove("x"), and el.classList.toggle("x") to flip it based on its current state.

6. What's the difference between event.target and event.currentTarget?

event.target is the actual element the event originated from (e.g. the exact button clicked). event.currentTarget is the element the listener is currently attached to and running on — during bubbling, these can differ.

7. What is event propagation, and what are its two phases?

Propagation is how an event travels through the DOM tree relative to its target: the capturing phase (document down to the target) happens first, followed by the target phase, then the bubbling phase (target back up to document).

8. How do you stop an event from bubbling further?

Call event.stopPropagation() inside the handler. Use event.stopImmediatePropagation() if you also want to prevent any other listeners registered on that same element for the same event from running.

9. What is event delegation and why is it useful?

Attaching one listener to a shared ancestor and using event.target to identify which descendant triggered it, instead of attaching a listener to every descendant individually. It scales better and automatically covers elements added to the DOM later.

10. How would you prevent a link or form from performing its default action?

Call event.preventDefault() inside the event handler — e.g. to stop a link from navigating or a form from submitting, so you can handle the logic in JavaScript instead.

DOM Scenario-Based Coding Questions
🧩 Scenario-Based Coding — Event Handling, Bubbling, Capturing & Delegation Applied

1. You have a list of 1,000 <li> items. Adding a click listener to each one feels wasteful — how do you fix it?

Use event delegation: attach a single listener to the parent <ul> and inspect event.target to know which item was clicked.

scenario-1.js
const list = document.querySelector("#big-list");
list.addEventListener("click", (e) => {
  if (e.target.matches("li")) {
    console.log("Selected:", e.target.textContent);
  }
});
// 1 listener total, instead of 1,000

2. You have a card with a nested "Delete" button. Clicking Delete should NOT also trigger the card's own "open details" click handler. How do you fix it?

Because of bubbling, a click on the button also fires the card's listener. Call event.stopPropagation() inside the button's handler so the click never reaches the card.

scenario-2.js
// <div class="card">...<button class="delete-btn">Delete</button></div>
document.querySelector(".card").addEventListener("click", () => {
  console.log("Opening card details...");
});

document.querySelector(".delete-btn").addEventListener("click", (e) => {
  e.stopPropagation();  // stops it from bubbling up to .card
  console.log("Deleting item...");
});

3. You need a global "click outside to close" behavior for a dropdown menu. How do you implement it using bubbling?

Attach a click listener on document that closes the dropdown by default, but ignore clicks that originated inside the dropdown itself (checked via closest()).

scenario-3.js
document.addEventListener("click", (e) => {
  const dropdown = document.querySelector("#dropdown");
  if (!e.target.closest("#dropdown")) {
    dropdown.classList.remove("open");  // click landed outside -> close it
  }
});

4. A parent container needs to intercept and log every click BEFORE any child's own handler runs — including third-party child scripts you don't control. How?

Use the capturing phase, since it always fires before the target's own bubbling-phase listeners, regardless of what the child script does.

scenario-4.js
document.querySelector("#app").addEventListener(
  "click",
  (e) => console.log("Intercepted before target handler:", e.target),
  true  // capture: true -> runs on the way DOWN, before the target's listener
);

5. You render a dynamic todo list where items (with a delete button each) get added and removed at runtime. Deleting should work for items added after the page loaded too, without re-binding listeners. How?

Delegate a single click listener to the list container, and use event.target.closest(".delete-btn") to detect the delete button even inside nested markup, then remove that item's row from the DOM.

scenario-5.js
const list = document.querySelector("#todo-list");

list.addEventListener("click", (e) => {
  const deleteBtn = e.target.closest(".delete-btn");
  if (deleteBtn) {
    deleteBtn.closest("li").remove();
  }
});

// New items added later are covered automatically —
// no need to attach a new listener per item.

6. Two nested elements both listen for click — one in the capturing phase, one in the bubbling phase. What's the exact firing order when the innermost element is clicked?

Capturing listeners on ancestors fire first, top-down, then the target's own listener(s) fire, then bubbling listeners on ancestors fire, bottom-up. So for a capture listener on the outer element and a normal (bubbling) listener on the inner element: outer (capture) → inner (target).

📌 Note: If the outer element also had a normal bubbling listener, the full order clicking the inner element would be: outer (capture) → inner (target) → outer (bubble).
