1. JavaScript Basics
🧩 Foundations of the Language

1. What is JavaScript?

JavaScript is a high-level, interpreted (or just-in-time compiled) programming language that was originally built to make web pages interactive. Unlike HTML and CSS, which describe structure and appearance, JavaScript adds behavior — it can respond to clicks, validate forms, fetch data from a server, and update the page without a reload. It is dynamically typed, prototype-based, and multi-paradigm, meaning it supports procedural, object-oriented, and functional styles of coding. Today, thanks to engines like V8 and runtimes like Node.js, JavaScript runs far beyond the browser — on servers, mobile apps, desktop apps, and even embedded devices.

2. What are the different data types in JavaScript?

JavaScript data types fall into two groups: primitives and reference (object) types. The primitives are String, Number, Boolean, undefined, null, Symbol, and BigInt — these are immutable and stored directly by value. The reference type is Object, which includes arrays, functions, dates, and plain objects; these are stored by reference, meaning a variable holds a pointer to the actual data in memory rather than the data itself.

types.js
let name = "Aisha";      // string
let age = 28;             // number
let isActive = true;       // boolean
let id;                       // undefined
let empty = null;         // null
let user = { name, age };    // object (reference)

3. What is the difference between var, let, and const?

var is function-scoped, gets hoisted and initialized with undefined, and can be redeclared — which historically caused subtle bugs. let and const are block-scoped, meaning they only exist inside the { } they were declared in, and they live in the Temporal Dead Zone until their line of declaration is reached. The difference between the two is that let allows reassignment, while const locks the binding — though for objects and arrays declared with const, the contents can still be mutated; only the reference itself cannot be reassigned.

4. What is the difference between primitive and reference data types?

Primitive values are copied by value — when you assign one primitive variable to another, JavaScript duplicates the actual data, so changing one has no effect on the other. Reference types are copied by reference — assigning an object or array to a new variable copies the memory address, so both variables point to the same underlying data, and mutating it through one variable is visible through the other.

5. What is type coercion?

Type coercion is JavaScript's automatic conversion of a value from one data type to another, usually to make an operation possible. It happens implicitly, such as when a number is combined with a string using the + operator (producing a string), or when a value is evaluated in a boolean context like an if statement. Coercion can also be explicit, using functions like String(), Number(), or Boolean() to convert deliberately.

Example: "5" + 2 results in "52" (string concatenation), while "5" - 2 results in 3 (numeric coercion), since the minus operator has no string meaning.

6. What is the difference between == and ===?

== is the loose equality operator — it compares two values after converting them to a common type, which can produce surprising results like "5" == 5 being true. === is the strict equality operator — it compares both value and type without any conversion, so "5" === 5 is false. Most style guides and teams recommend always using === to avoid the unpredictability that coercion introduces.

7. What are truthy and falsy values?

Every value in JavaScript is treated as either truthy or falsy when evaluated in a boolean context, such as inside an if condition. There are exactly six falsy values: false, 0, "" (empty string), null, undefined, and NaN. Everything else — including empty arrays [], empty objects {}, and the string "0" — is truthy, which often surprises developers coming from other languages.

8. What is the difference between null and undefined?

undefined means a variable has been declared but has not yet been assigned a value — it's the default state JavaScript gives things. null, on the other hand, is an intentional assignment that represents "no value" or "empty," deliberately set by the developer. In practice, undefined usually signals something JavaScript did automatically, while null signals something a programmer explicitly chose.

9. What is NaN, and how do you check for it?

NaN stands for "Not a Number," and despite its name, its type is actually "number". It appears when a mathematical operation fails to produce a meaningful numeric result, such as dividing zero by zero or parsing a non-numeric string with parseInt(). The tricky part is that NaN is the only value in JavaScript that is not equal to itself, so NaN === NaN returns false. To check for it reliably, use Number.isNaN(value) rather than the older global isNaN(), which coerces its argument first and can give false positives.

10. What is strict mode ('use strict')?

Strict mode is an opt-in setting that makes JavaScript enforce a stricter set of rules, catching common mistakes and unsafe actions that are normally allowed silently. Adding "use strict" at the top of a file or function prevents accidental creation of global variables, throws errors on assignments to read-only properties, and disallows some legacy syntax. ES6 modules and classes run in strict mode automatically, which is one reason modern JavaScript code tends to be safer by default.

2. Functions
⚙️ Functions in Depth

1. What is a function in JavaScript?

A function is a reusable, self-contained block of code designed to perform a specific task. It can accept input through parameters, execute a series of statements, and optionally return a value using the return keyword. Functions are central to organizing logic, avoiding repetition, and — because JavaScript treats them as first-class citizens — they can also be stored, passed around, and manipulated just like any other value.

2. What is the difference between a function declaration and a function expression?

A function declaration uses the function keyword followed by a name at the statement level, and it is fully hoisted — meaning it can be called before its definition appears in the code. A function expression assigns a function to a variable, and while the variable name is hoisted, the function assignment itself is not, so calling it before the line it's defined on throws an error.

functions.js
// Declaration — hoisted fully
function greet(name) {
  return `Hello, ${name}`;
}

// Expression — not usable before this line
const greetAgain = function(name) {
  return `Hi, ${name}`;
};

3. What are arrow functions? How are they different from regular functions?

Arrow functions offer a shorter syntax for writing functions, using => instead of the function keyword, and they automatically return single expressions without needing an explicit return. The more meaningful difference is behavioral: arrow functions don't have their own this, arguments, or super — they inherit these from the enclosing lexical scope. This makes them unsuitable as object methods or constructors, but ideal for callbacks where you want this to stay tied to the surrounding context.

4. What are callback functions?

A callback function is a function passed as an argument into another function, intended to be invoked later — either immediately after some synchronous logic, or asynchronously once a task like a network request or timer finishes. Callbacks are the foundation of asynchronous JavaScript, powering everything from setTimeout to array methods like map and event handlers like addEventListener.

5. What are higher-order functions?

A higher-order function is any function that either accepts another function as an argument, returns a function, or both. They allow behavior to be abstracted and reused — instead of writing separate loops for filtering, transforming, and summing an array, you can pass different functions into filter, map, and reduce to reuse the same iteration logic with different behavior.

6. What are first-class functions?

Saying JavaScript has "first-class functions" means functions are treated as regular values, just like numbers or strings. They can be assigned to variables, stored in arrays or objects, passed as arguments, and returned from other functions. This property is what makes higher-order functions, callbacks, and functional programming patterns possible in JavaScript.

7. What is an IIFE? Why is it used?

An IIFE (Immediately Invoked Function Expression) is a function that is defined and executed at the same moment it's created, typically written as (function() { ... })(). It was historically used to create a private scope, preventing variables from leaking into the global namespace and protecting code from naming collisions — a concern that modules and block scoping have since reduced, but IIFEs are still useful for one-off setup logic or isolating a script.

iife.js
(function () {
  const secret = "hidden from outside";
  console.log(secret);
})();

8. Can functions be passed as arguments and returned from other functions?

Yes — this is a direct consequence of functions being first-class values. Passing a function as an argument is how callbacks and array methods work, while returning a function from another function is the basis of closures, currying, and function factories, where an outer function configures behavior that an inner returned function later executes.

9. What is currying?

Currying is the technique of transforming a function that takes multiple arguments into a sequence of functions, each taking a single argument, so that calling them one after another eventually produces the final result. It relies on closures to remember earlier arguments while waiting for the rest, and it's commonly used to create specialized, reusable versions of a general function.

curry.js
const multiply = a => b => c => a * b * c;

multiply(2)(3)(4); // 24

10. What is function composition?

Function composition is the practice of combining two or more functions to produce a new function, where the output of one becomes the input of the next. It encourages building complex behavior out of small, single-purpose functions, and libraries like Lodash or Ramda provide helpers like compose or pipe to chain these transformations cleanly instead of nesting function calls manually.

3. Scope & Hoisting
🧭 Scope, Hoisting & Execution

1. What is scope in JavaScript?

Scope defines the region of code where a particular variable or function is accessible. JavaScript has three levels of scope: global scope, where a variable is visible everywhere; function scope, where a variable declared with var is confined to the function it's in; and block scope, where variables declared with let or const are confined to the nearest enclosing { }. Scope is what prevents variables in one part of a program from unintentionally colliding with variables in another.

2. What is lexical scope?

Lexical scope means that a variable's accessibility is determined by where it is physically written in the source code, not by how or where the function is called. A function defined inside another function has access to its parent's variables simply because of its position in the code — this positional relationship is fixed at the time the code is written, which is why it's called "lexical."

3. What is the scope chain?

The scope chain is the path JavaScript follows when looking up a variable: it starts in the current scope, and if the variable isn't found, it moves outward to the parent scope, then that scope's parent, and so on until it reaches the global scope. If the variable still isn't found anywhere along that chain, a ReferenceError is thrown. This chain is built based on lexical scope, so it reflects the nesting structure of the code, not the call structure.

4. What is hoisting?

Hoisting is JavaScript's behavior of processing variable and function declarations before executing any code, effectively moving them to the top of their scope during the compilation phase. Function declarations are hoisted completely, including their body, so they can be called before they appear in the code. var declarations are hoisted but initialized as undefined, while let and const are hoisted but remain uninitialized until their declaration line runs.

5. What is the Temporal Dead Zone (TDZ)?

The Temporal Dead Zone is the period between the start of a scope and the point where a let or const variable is actually declared. During this window, the variable technically exists in memory but cannot be accessed — attempting to reference it throws a ReferenceError rather than returning undefined. The TDZ exists to catch bugs where a variable is used before its intended initialization.

Example: console.log(x); let x = 5; throws ReferenceError: Cannot access 'x' before initialization — this is the TDZ in action.

6. What is an execution context?

An execution context is the environment in which JavaScript code is evaluated and run — it holds information such as variable bindings, the value of this, and a reference to the outer (lexical) environment. There are three kinds: the global execution context created once when a script starts, function execution contexts created every time a function is called, and eval contexts for code run inside eval(). Each context goes through a creation phase (where hoisting happens) and an execution phase (where code actually runs line by line).

7. How does the call stack work?

The call stack is a data structure JavaScript uses to keep track of function calls, following a last-in-first-out order. When a function is invoked, a new execution context is pushed onto the stack; when that function returns, its context is popped off. Because JavaScript is single-threaded, only one thing can run at a time, and a deeply nested or infinite chain of calls without a base case will exhaust the stack, producing a "Maximum call stack size exceeded" error.

4. Closures
🔒 Closures

1. What is a closure?

A closure is formed when a function retains access to the variables of its outer (enclosing) scope even after that outer function has finished executing. In practice, this happens whenever a function is defined inside another function and is then returned or passed elsewhere — the inner function keeps a live reference to the variables around it, rather than a snapshot of their values at the time.

closure.js
function counter() {
  let count = 0;
  return function() {
    count++;
    return count;
  };
}

const increment = counter();
increment(); // 1
increment(); // 2 — count is remembered between calls

2. Where are closures used in real-world applications?

Closures show up constantly in everyday JavaScript. They power data privacy patterns like the module pattern, where internal variables are hidden and only exposed through specific returned functions. They're behind memoization, where a cache variable is preserved across calls to avoid repeating expensive work. They're essential to event handlers and callbacks that need access to variables from when they were set up, and they're the mechanism behind React's useState hook, which relies on closures to remember state between renders.

3. What are the advantages and disadvantages of closures?

Closures are powerful because they enable data encapsulation without classes, allow state to persist across function calls, and make patterns like currying, memoization, and callbacks possible. However, that same persistence has a cost: because closures keep their outer variables alive in memory, careless use — such as closures inside loops holding onto large objects, or event listeners that are never removed — can lead to memory leaks and unnecessarily high memory usage if not managed carefully.

✅ Advantages
  • Enables private variables without classes
  • Preserves state across function calls
  • Powers currying, memoization & callbacks
  • Foundation of the module pattern
⚠️ Disadvantages
  • Can cause memory leaks if references linger
  • Overuse can make debugging harder
  • Loops with closures need care (var vs let pitfalls)
  • Slightly higher memory footprint per closure
