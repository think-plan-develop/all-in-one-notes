1. Destructuring
📦 Array & Object Destructuring

1. What is Destructuring?

Destructuring is an ES6 syntax that lets you unpack values from arrays or properties from objects directly into individual variables — in a single, clean line instead of accessing them one by one. It doesn't mutate the original array or object; it simply creates new local variables bound to those values. Destructuring is ubiquitous in modern JavaScript and appears constantly in React props, API response handling, and function parameters.

Array Destructuring

Elements are extracted based on their position in the array. You can skip positions using commas, and supply default values that activate only when an element is undefined.

array-destructuring.js
const colors = ["Red", "Green", "Blue"];

const [first, second] = colors;
console.log(first);   // "Red"
console.log(second);  // "Green"

// Skip elements using commas
const [a, , c] = [10, 20, 30];
console.log(a); // 10
console.log(c); // 30

// Default values (only apply when value is undefined)
const [x, y = 100] = [10];
console.log(x); // 10
console.log(y); // 100 — used the default

Object Destructuring

Properties are extracted by name rather than position. You can rename an extracted property on the fly, set defaults for missing keys, and even destructure deeply nested structures in one expression.

object-destructuring.js
const user = { name: "John", age: 25 };

// Basic extraction
const { name, age } = user;

// Rename while extracting
const { name: fullName } = user;
console.log(fullName); // "John"

// Nested destructuring
const employee = { name: "John", address: { city: "Delhi" } };
const { address: { city } } = employee;
console.log(city); // "Delhi"

// Inline in function parameters — very common in React
function displayUser({ name, age }) {
  console.log(name, age);
}
displayUser({ name: "John", age: 25 });
Why it matters in interviews: Destructuring shows up in almost every React codebase (destructuring props, state, hook returns), API response handling, and configuration objects — interviewers use it to check ES6 fluency.
2. Spread & Rest Operators
🔀 Spread ( ... ) vs Rest ( ... )

2. What is the difference between the Spread and Rest operators?

Both use identical ... syntax, but they do opposite things depending on where they appear. Spread expands an array or object into individual elements — it blows things apart. Rest gathers multiple individual values into a single array — it pulls things together. The context tells you which one you're looking at: spread appears in array literals, object literals, and function call arguments; rest appears in function parameter lists and destructuring patterns.

FeatureSpreadRest
PurposeExpands values into individual elementsCollects individual values into one array
Used inArray literals, Object literals, Function callsFunction parameters, Destructuring
Memory tipSpread → explodeRest → collect

Spread in Action

spread.js
// Copy an array (no shared reference)
const arr = [1, 2, 3];
const copy = [...arr];

// Merge two arrays
const a = [1, 2];
const b = [3, 4];
const result = [...a, ...b]; // [1, 2, 3, 4]

// Clone an object
const user = { name: "John" };
const clone = { ...user };

// Spread into function arguments
const nums = [10, 20, 30];
console.log(Math.max(...nums)); // 30

Rest in Action

rest.js
// Collect any number of arguments into an array
function sum(...numbers) {
  return numbers.reduce((a, b) => a + b, 0);
}
console.log(sum(10, 20, 30)); // 60

// Grab the first property, collect the rest
const user = { name: "John", age: 25, city: "Delhi" };
const { name, ...others } = user;
console.log(others); // { age: 25, city: "Delhi" }
Quick memory trick: Spread is in the position of values being used (call site / literal). Rest is in the position of a parameter being defined.
3. Template Literals
✍️ Template Literals

3. What are Template Literals?

Template literals are string literals enclosed in backticks (` `) rather than single or double quotes. They solve three painful problems with regular strings: they natively support multi-line content without escape characters, they allow variable and expression interpolation inline using ${ } instead of concatenation, and they make the intent of dynamic strings far easier to read and maintain.

template-literals.js
const name = "John";
const price = 50000;
const product = "Laptop";

// Old way — ugly concatenation
console.log("Hello " + name);

// ES6 — clean interpolation
console.log(`Hello ${name}`);
console.log(`${product} costs ₹${price}`);

// Expressions inside ${}
console.log(`Sum = ${10 + 20}`);  // "Sum = 30"

// Multi-line strings — no \n needed
const message = `
Hello
Welcome to JavaScript
`;
console.log(message);
Template literals can also be used as tagged templates — a function placed before the backtick receives the string parts and interpolated values separately, which is how libraries like styled-components and GraphQL's gql work.
4. Default Parameters
🎛️ Default Parameters

4. What are Default Parameters?

Default parameters let you assign a fallback value directly in the function signature, used whenever the caller either omits that argument entirely or explicitly passes undefined. Before ES6, developers had to simulate this with name = name || "Guest" inside the function body, which had the side effect of replacing any falsy value — including valid ones like 0 or false. Default parameters are more precise: they only activate for undefined, not for null, 0, "", or false.

default-params.js
function greet(name = "Guest") {
  console.log(name);
}

greet();           // "Guest" — default used
greet("John");    // "John"  — default skipped
greet(null);      // null    — null is NOT undefined, so default is NOT used

// Multiple defaults
function add(a = 0, b = 0) {
  return a + b;
}
console.log(add(5));  // 5 (b defaults to 0)
Key interview point: Default parameters only activate for undefined — passing null explicitly does NOT trigger the default. This is a frequent trick question.
5. Optional Chaining
🔗 Optional Chaining ( ?. )

5. What is Optional Chaining (?.)?

Optional chaining is a safe-access operator that short-circuits the evaluation of a property chain the moment it encounters a null or undefined, returning undefined instead of throwing a TypeError. Before it existed, safely accessing a deeply nested property like response.data.user.name required multiple && checks or if statements as guards. Optional chaining removes that boilerplate entirely while keeping the code readable.

optional-chaining.js
const user = {};

// Without optional chaining — throws TypeError
// console.log(user.address.city);

// With optional chaining — safely returns undefined
console.log(user.address?.city);   // undefined

// Safe method call
user.sayHello?.();

// Safe array element access
const users = [];
console.log(users[0]?.name);      // undefined

// Real-world: API response traversal
const response = { data: { user: { name: "John" } } };
console.log(response.data?.user?.name); // "John"
Real-world importance: Optional chaining is indispensable when working with API responses where fields may or may not exist, or with user-provided data where shapes aren't guaranteed.
6. Nullish Coalescing
❓ Nullish Coalescing ( ?? )

6. What is Nullish Coalescing (??)?

The nullish coalescing operator returns its right-hand side value only if the left-hand side is strictly null or undefined. This is a crucial distinction from the logical OR operator (||), which triggers its fallback for any falsy value — meaning 0, false, and "" would incorrectly activate it even when those are legitimate values you want to keep.

Expression|| result?? result
null || "default""default""default"
undefined ?? "default""default""default"
0 || 1010 ❌ (loses valid 0)0 ✅
false ?? truetrue ❌false ✅
"" ?? "Hello""Hello" ❌"" ✅
nullish.js
const name = null;
console.log(name ?? "Guest"); // "Guest"

const count = 0;
console.log(count || 10);  // 10 — wrong! 0 was a valid value
console.log(count ?? 10);  // 0  — correct behavior

// Common pattern: combine with optional chaining
const user = {};
const city = user.address?.city ?? "Unknown";
console.log(city); // "Unknown"
Use ?? over || whenever 0, false, or "" are valid, meaningful values in your data — otherwise || will silently override them with the fallback.
7 – 8. JavaScript Modules
📁 Modules — import, export, Named & Default

7. What are JavaScript Modules?

Modules are the official ES6 way to organize JavaScript code across multiple files, where each file defines its own scope — nothing leaks to the global object by default. A module explicitly declares what it shares with the rest of the codebase using export, and other files pull in exactly what they need using import. Modules are loaded asynchronously by the browser, cached after the first load so they never run twice, and always execute in strict mode. They make large codebases manageable and enable tree shaking — the tooling-level process of removing exported code that no file ever imports.

math.js → app.js
// math.js — exporting
export function add(a, b) {
  return a + b;
}

// app.js — importing
import { add } from "./math.js";
console.log(add(2, 3)); // 5

8. What is the difference between Named Export and Default Export?

A file can have any number of named exports — each is a distinct, labeled item. When importing, you must use curly braces and match the name exactly (though you can alias with as). A file can have only one default export — it represents the primary thing that file provides. When importing a default export, there are no curly braces and you can give it any local name you like.

Named ExportDefault Export
Number allowed per fileMultipleOne only
Export syntaxexport const x = ...export default function ...
Import syntaximport { x } from "..."import x from "..."
Curly braces in import✅ Required❌ Not used
Rename during importUse as keywordAny name freely
named-and-default.js
// ── Named exports ──────────────────────────────
export const PI = 3.14;
export function add(a, b) { return a + b; }

// ── Default export ─────────────────────────────
export default function multiply(a, b) { return a * b; }

// ── Importing both in the same statement ───────
import multiply, { PI, add } from "./math.js";

// ── Rename a named export ──────────────────────
import { PI as VALUE } from "./math.js";

// ── Rename a default export (any name is fine) ─
import calculate from "./math.js";
Convention: use default exports for the main thing a file is about (a component, a class, a service), and named exports for utilities and constants that a file exposes alongside its primary purpose.
