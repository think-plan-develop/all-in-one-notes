🌐 Web APIs & the window Object

How the browser extends plain JavaScript with fetch, timers, storage, and more — and why it's all really just window

What are Web APIs The window Object DOM vs BOM Common Categories of Web APIs Web APIs + Event Loop
📌 In short: Web APIs are browser-provided features — not part of JavaScript itself — that let your JS code talk to the page, the network, storage, and more. Nearly all of them live on the window object.
🔑 Key Terms at a Glance
🌐
Web API: A browser-provided feature (fetch, DOM, timers, storage) — not part of the JS language itself.
🪟
window: The global object in browser JS — the root that holds nearly every Web API.
📄

🔁
Event Loop: The mechanism that hands async Web API results back to JS without blocking the main thread.
What are Web APIs?
1

Browser-Provided Features, Not JavaScript Itself

Web APIs are browser-provided features that allow JavaScript to interact with the browser and the outside world.

JavaScript itself (ECMAScript) provides things like variables, functions, arrays, and promises. Features such as setTimeout, DOM manipulation, fetch, localStorage, and location are not part of JavaScript — they're provided by the browser through the window object.

JavaScript + Browser Web APIs + Event Loop = Asynchronous behavior in the browser
2

Why They Exist

The JS engine (like V8) only understands core language syntax. The browser wraps that engine with extra objects and functions so your code can interact with the page, the network, storage, and more. These extra tools are the Web APIs.

window is actually the root of most Web APIs in the browser.
The window Object
1

What window Is

window is the global object in browser JavaScript. It represents the browser tab/window itself, and it's the top-level container that holds:

  • All global JS variables/functions (implicitly)
  • All Web APIs
window.js
console.log(window);
2

The Key Insight — Everything Is window.something

Almost everything you think of as a "global" thing in browser JS is actually a property of window:

window-shorthand.js
document.getElementById("x")
// is really:
window.document.getElementById("x")

setTimeout(() => {}, 1000)
// is really:
window.setTimeout(() => {}, 1000)

localStorage.setItem("a", "1")
// is really:
window.localStorage.setItem("a", "1")

alert("hi")
// is really:
window.alert("hi")
JavaScript lets you drop the window. prefix because it's the global scope — so you can call these directly.
3

Where window Fits in the Picture

window (global object / BOM - Browser Object Model) │ ├── document → DOM API ├── fetch() → Fetch API ├── setTimeout() → Timer API ├── localStorage → Storage API ├── navigator → Device/browser info API ├── location → URL/navigation API ├── history → History API └── console → Console API

window itself is often called part of the BOM (Browser Object Model) — a broader concept than the DOM. It represents the browser window, and it exposes nearly every Web API as its properties.

Key Concept: JS + Web APIs + Event Loop
1

How Async Web APIs Avoid Blocking JS

Web APIs often work asynchronously. For example, setTimeout or fetch hand off work to the browser, which runs it separately, and returns results back to JS via the callback queue / event loop — without blocking the main thread.

Your JS Code → calls Web API (e.g. fetch) │ ▼ Browser handles it in background │ ▼ Result placed in callback/microtask queue │ ▼ Event loop pushes it back into JS when call stack is empty
💡 Why this matters: This is exactly why setTimeout(fn, 0) doesn't run immediately, and why a slow fetch call doesn't freeze the page — the browser, not the single-threaded JS engine, is doing the waiting.
Web APIs = everything the browser gives JS beyond core language syntax · Almost all of them live on window, which you can call without the prefix · DOM = page content, BOM = browser window itself, Web APIs = the umbrella covering both · Async Web APIs hand work off to the browser and return results through the event loop, keeping the main thread unblocked.
