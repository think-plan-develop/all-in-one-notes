🧬 prototype, __proto__ & the Prototype Chain

Starting from a function's shared toolbox, through what "new" actually does, to the hidden link every object carries

prototype The new keyword __proto__ Comparison Prototype Chain Walkthroughs Lookup Process & Summary Interview Q&A Polyfills 30-Second Summary
📌 In short: A function's prototype is a shared toolbox of methods. When you call it with new, the new object gets a hidden link — __proto__ — back to that toolbox. Property lookups walk this link outward until found or until null — and that same mechanism is exactly how a polyfill added to Function.prototype becomes available on every function.

What is prototype? (Start Here)

Only Functions Have a prototype Property

Start Here
prototype belongs to a function. JavaScript uses it whenever new creates an object from that function.
function-prototype.js
function Person() {}

console.log(Person.prototype);
// Output: {}

Why Does prototype Exist?

Imagine you create 100 Person objects. Should each object get its own private copy of greet()? That would waste memory 100 times over.

Instead, JavaScript stores greet() once, inside Person.prototype. Every object created from Person shares that same method.

shared-toolbox.js
function Person(name) {
    this.name = name;
}

Person.prototype.greet = function() {
    console.log("Hello, I'm " + this.name);
};

// 100 objects, but only ONE greet() in memory
const p1 = new Person("Asha");
const p2 = new Person("Ravi");
p1.greet(); // "Hello, I'm Asha" — uses the shared greet()
💡 Think of prototype as a shared toolbox, not just a blueprint. A blueprint explains how something is built once; a toolbox explains why 100 objects can all reach for the same tools without each carrying their own copy.

What is __proto__?

The Hidden Link Every Object Has

__proto__ belongs to an object. It remembers which toolbox (prototype) that object was created from.

Every object remembers where it inherited its properties from. That link is available through __proto__.

proto-basic.js
const obj = {};

console.log(obj.__proto__); // "Show me this object's prototype."

Internally this link is stored as [[Prototype]] — a hidden engine property. The double underscores in __proto__ aren't a keyword; they just signal "this is special," and browsers expose it as a convenience for reading that internal link.

The Relationship, Visually

When you write:

new-person.js
new Person()

JavaScript automatically does:

under-the-hood.js
newObject.__proto__ = Person.prototype;

Should We Use __proto__ Directly?

No
No. Although browsers still support it, __proto__ is deprecated for direct use.

Avoid code like:

avoid.js
obj.__proto__;
obj.__proto__ = anotherObject;

Instead use the official APIs:

recommended.js
Object.getPrototypeOf(obj);

Object.setPrototypeOf(obj, anotherObject);

Why should __proto__ be avoided?

  • Slow performance — changing an object's prototype at runtime forces the engine to re-optimize it, which can slow down your code.
  • Legacy feature — __proto__ exists mainly for browser compatibility; modern JavaScript recommends Object.getPrototypeOf()/setPrototypeOf() instead.
  • Harder to understand — obj.__proto__ = person; doesn't clearly express intent, while Object.setPrototypeOf(obj, person); reads like exactly what it does.

Prototype Chain Walkthroughs

Array Prototype

Example 1
array-proto.js
const arr = [1, 2, 3];

console.log(arr.__proto__ === Array.prototype); // true

Every array inherits from Array.prototype, so arr.__proto__ and Array.prototype print the same object.

array-chain-walk.js
arr.__proto__.__proto__;
// Object.prototype — because arrays are objects too

arr.__proto__.__proto__.__proto__;
// null — the prototype chain ends here
arr ↓ Array.prototype ↓ Object.prototype ↓ null

Object Prototype

Example 2
object-proto.js
const obj = {};

obj.__proto__;              // Object.prototype
obj.__proto__.__proto__;    // null
obj ↓ Object.prototype ↓ null

Function Prototype

Example 3

Functions are also objects, so they too inherit from a prototype — specifically Function.prototype.

function-proto.js
function hello() {}

console.log(hello.__proto__);
// Output: Function.prototype

hello.__proto__.__proto__;  // Object.prototype
hello.__proto__.__proto__.__proto__; // null
hello ↓ Function.prototype ↓ Object.prototype ↓ null

Prototypal Inheritance in Practice

Example 4
prototypal-inheritance.js
let object = {
    name: "Akshay",
    city: "Dehradun",

    getIntro() {
        console.log(this.name + " from " + this.city);
    }
};

let object2 = {
    name: "Aditya"
};

object2.__proto__ = object;
object2 ↓ object ↓ Object.prototype ↓ null

Looking up object2.city

JavaScript searches object2 first — not found. It walks up to object — found city — returns "Dehradun".

Calling object2.getIntro()

getIntro() itself is found on object, but this still points to object2 — the object the method was called on. So this.name comes from object2 ("Aditya"), while this.city is found by walking up to object ("Dehradun").

Output: Aditya from Dehradun
Property Lookup Process & Summary

How Property Lookup Works

When JavaScript accesses a property like obj.name, it searches in this order:

Object ↓ Prototype ↓ Prototype's Prototype ↓ ... ↓ null

If the property is found at any step, JavaScript returns it immediately. If the search reaches null without finding it, the result is undefined.

Interview Questions
💡 Interview Q&A
Is __proto__ the same as prototype?
No. prototype belongs to constructor functions — it's the shared toolbox handed to objects created with new. __proto__ belongs to objects — it's the live link to the toolbox they were created from.
Do arrays have prototypes?
Yes. Arrays inherit from Array.prototype, which in turn inherits from Object.prototype, which inherits from null.
Are functions objects?
Yes. Every function is also an object, so it inherits from Function.prototype, which in turn inherits from Object.prototype.
Why is __proto__ discouraged?
Because it's a legacy accessor, can hurt performance when used to modify prototypes at runtime, and modern JavaScript provides clearer APIs: Object.getPrototypeOf(obj) and Object.setPrototypeOf(obj, prototype).
Polyfills

What is a Polyfill?

A polyfill is a piece of JavaScript code that adds support for a feature that is missing in an older browser or JavaScript environment. In simple words: a polyfill recreates a built-in JavaScript feature if it doesn't already exist.

For example, if an old browser doesn't support Array.prototype.includes(), you can write your own implementation so your code still works there.

Why are polyfills needed?

Suppose JavaScript did not have a bind() method. You could create your own version by adding it to Function.prototype. Since every function inherits from Function.prototype, all functions would immediately gain access to the new method.

Example — A Custom myBind()

polyfill-mybind.js
Function.prototype.myBind = function () {
    console.log("Custom bind() called");
};

function fun() {}
function fun2() {}

fun.myBind();
fun2.myBind();

// Output:
// Custom bind() called
// Custom bind() called

How Does It Work?

When JavaScript executes fun.myBind(), it first searches inside fun itself — not found — then walks up to Function.prototype, where myBind is found and executed.

fun │ ├── myBind ❌ Not Found │ ▼ Function.prototype │ ├── myBind ✅ Found

The exact same lookup happens for fun2 — it also has no myBind of its own, so the engine walks up to the shared Function.prototype and finds it there too.

fun2 │ ├── myBind ❌ Not Found │ ▼ Function.prototype │ ├── myBind ✅ Found

Why Add It to Function.prototype?

Because every function automatically inherits from Function.prototype:

fun ↓ Function.prototype ↓ Object.prototype ↓ null fun2 ↓ Function.prototype ↓ Object.prototype ↓ null

Adding a method once to Function.prototype makes it available to every function, without touching each one individually — that's the same mechanism the prototype chain uses for everything else.

Another Simple Example

polyfill-sayhello.js
Function.prototype.sayHello = function () {
    console.log("Hello from all functions!");
};

function add() {}
function multiply() {}

add.sayHello();
multiply.sayHello();

// Output:
// Hello from all functions!
// Hello from all functions!
📌 Important note: These examples demonstrate how polyfills work. In real applications, a polyfill is usually written only when a built-in JavaScript method is missing in some environment — but creating simple methods like myBind() or sayHello() is a great way to understand how JavaScript's prototype system actually operates.
