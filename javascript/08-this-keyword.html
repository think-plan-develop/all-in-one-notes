🧭 JavaScript this Keyword

this is a special keyword that refers to the object that is currently executing the function. Its value is determined at runtime based on how the function is called — except for arrow functions, which inherit this from their surrounding scope.

1️⃣ this in Global Scope

🌐 Global Scope: Browser vs Node.js

In the global scope, this refers to the global object. In browsers it is window, while in Node.js CommonJS modules it refers to module.exports.

Browser

In the browser, the global object is window.

browser console 
console.log(this);
// Output: Window {...}

this === window // true

Node.js

At the top level of a CommonJS module:

module.js 
console.log(this);
// Output: {}
Here, this refers to module.exports, not the global object. The global object in Node.js is global.

💬 Interview Definition

In the global scope, this refers to the global object. In browsers it is window, while in Node.js CommonJS modules it refers to module.exports.

2️⃣ this Inside an Object Method

🧩 Object Method

When a function is called as an object's method, this refers to the object that called the method.
app.js 
const user = {
    name: "Shivam",

    show() {
        console.log(this.name);
    }
};

user.show();
// Output: Shivam

Diagram

user.show() │ ▼ this ─────────► user │ ▼ name = "Shivam"

Here, this.name is the same as user.name.

💬 Interview Definition

Inside an object method, this refers to the object that invoked the method.

3️⃣ this Inside a Regular Function

⚙️ Regular Function

A regular function has its own this.

Non-Strict Mode

app.js 
function show() {
    console.log(this);
}

show();
// Browser Output: Window

Strict Mode

app.js 
"use strict";

function show() {
    console.log(this);
}

show();
// Output: undefined
⚠️ In non-strict mode, this falls back to the global object. In strict mode, it stays undefined.

💬 Interview Definition

In a regular function, this depends on how the function is called. In non-strict mode it refers to the global object, while in strict mode it is undefined.

4️⃣ this Inside an Arrow Function

🏹 Arrow Function

Arrow functions do not have their own this. They inherit this from their surrounding (lexical) scope.
app.js 
const user = {
    name: "Shivam",

    show() {
        const greet = () => {
            console.log(this.name);
        };

        greet();
    }
};

user.show();
// Output: Shivam

Diagram

user.show() │ ▼ this = user │ ▼ Arrow Function │ ▼ inherits this │ ▼ user

Wrong Usage

app.js 
const user = {
    name: "Shivam",

    show: () => {
        console.log(this.name);
    }
};

user.show();
// Output: undefined
⚠️ Because the arrow function inherits this from its outer scope instead of the user object.

💬 Interview Definition

Arrow functions do not create their own this; they inherit it from the surrounding lexical scope.

🔄 Object → Primitive Conversion

🔄 valueOf() and toString()

Sometimes JavaScript needs to convert an object into a primitive value.

console.log("Hello " + obj);

Since a string is involved, JavaScript converts obj to a primitive.

Conversion Order

Need Primitive │ ▼ Try valueOf() │ ├── Returns Primitive? ── Yes → Use it │ ▼ No Try toString() │ ├── Returns Primitive? ── Yes → Use it │ ▼ No TypeError

Example

app.js 
const obj = {
    valueOf() {
        return {};
    },

    toString() {
        return "10";
    }
};

console.log(obj + 5);
// Output: 105

valueOf() returns an object (not a primitive), so JavaScript calls toString().

Default Object Behavior

app.js 
const obj = {};

console.log("Hello " + obj);
// Output: Hello [object Object]

JavaScript tries:

1. valueOf() → Returns an object ❌
2. toString() → Returns "[object Object]" ✅

🧠 Output-Based Questions: Closures
1

❓ Guess the Output

app.js
function outer() {
    let a = 10;

    function inner() {
        console.log(a);
    }

    return inner;
}

const fn = outer();

fn();

Output

console
10
Why? inner() forms a closure over a. Even after outer() finishes, a is preserved.
