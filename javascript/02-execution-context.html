Overview
1

What Happens When We Run a JavaScript Program?

💡 In one line: The JS Engine creates a Global Execution Context, pushes it onto the Call Stack, runs your code in two phases (Memory Creation → Code Execution), and creates a brand-new Function Execution Context — pushed and popped off the same stack — every time a function is called.

Everything else on this page is really just zooming into one of the four moving parts in that sentence: the Engine, the Execution Context, the Call Stack, and the Memory Heap.

2

What is the JavaScript Engine?

The JavaScript Engine is the program that actually executes your JS code. It acts as an orchestrator by:

  • Creating Execution Contexts
  • Executing JavaScript code
  • Managing the Call Stack
  • Allocating memory
  • Removing execution contexts after execution
Execution Context
1

What is an Execution Context?

An Execution Context (EC) is the environment where JavaScript code is evaluated and executed. It contains variables, functions, scope information, this, and references to objects stored in memory.

Every Execution Context goes through two phases: the Memory Creation Phase and the Code Execution Phase.
2

Phase 1 — Memory Creation Phase

Before executing any code, JavaScript allocates memory:

  • Memory is allocated for variables and functions
  • var variables are initialized with undefined
  • Function declarations are stored completely in memory
  • let and const are allocated but remain in the Temporal Dead Zone (TDZ) until initialized
example.js
console.log(a);
var a = 10;
Memory Creation: a → undefined Code Execution: a → 10
3

Phase 2 — Code Execution Phase

After memory allocation, the engine runs the code line by line:

  • Code executes line by line
  • Variables receive their actual values
  • Functions are invoked
  • Expressions are evaluated
Global vs Function Execution Context
1

Global Execution Context (GEC)

Whenever a JavaScript program starts:

  • The JS engine first creates the Global Execution Context
  • It is the first execution context created
  • It is pushed onto the Call Stack
  • It stays at the bottom of the stack until the entire program finishes
The GEC contains: global variables, global functions, the global object (window in browsers, global in Node.js), and this (points to the global object in non-module scripts).
2

Function Execution Context (FEC)

Whenever a function is called:

  • A new Function Execution Context is created
  • It has its own variables, parameters, scope, and this
  • It is pushed onto the Call Stack
  • After execution, it is removed (popped)
Remember: Every single function call creates a brand-new Execution Context — even recursive calls to the same function.
Call Stack
1

What is the Call Stack?

The JS engine has its own Call Stack, responsible for creating execution contexts, managing execution order, and deleting execution contexts after execution.

It follows the LIFO (Last In, First Out) principle. The Call Stack stores Execution Contexts, not functions directly, and the engine always executes whichever context is at the top of the stack.
Top ----------------- | Function EC | ← Currently executing ----------------- | Function EC | ----------------- | Global EC | ← Created first ----------------- Bottom
2

How the Call Stack Works — Step by Step

Step 1 — Program Starts

------------- | Global EC | -------------

Step 2 — Function Invocation

------------- | one() EC | ------------- | Global EC | -------------

Step 3 — Nested Function Calls

------------- | two() EC | ------------- | one() EC | ------------- | Global EC | -------------

Step 4 — Function Completion

------------- | one() EC | ------------- | Global EC | -------------

Step 5 — Program Ends

After all Function Execution Contexts are removed, only the Global Execution Context remains. When the program finishes, the GEC is removed too.

The JavaScript Call Stack

1. What is the Call Stack?

The JS engine uses a Call Stack to keep track of where in the code we are. It manages Execution Contexts—the environment in which your code runs—to track execution order.

Core Principle: LIFO (Last In, First Out)

Think of it like a stack of plates. You add new Execution Contexts to the top and remove them once finished. The engine always executes whatever is at the very top.

2. The Lifecycle of an Execution

  • Program Start: The Global Execution Context (GEC) is pushed to the stack.
  • Invocation: When a function is called, a new Execution Context is created and pushed to the top.
  • Execution: The engine executes the function at the top.
  • Completion: Once a function finishes, its context is "popped" off the stack, and the engine resumes the context below it.
  • Termination: Once the stack is empty (except for the GEC), the program ends.

3. Walkthrough Example

function one() { two(); }
function two() { three(); }
function three() { console.log("Done"); }

one();
Action Stack State (Top → Bottom)
InitialGlobal EC
Call one()one() → Global EC
Call two()two() → one() → Global EC
Call three()three() → two() → one() → Global EC
Finish three()two() → one() → Global EC

Note: Each time a function returns, it is removed from the top, allowing the engine to resume the parent function immediately.

Memory Heap & Single-Threaded
1

What is the Memory Heap?

The Memory Heap is a large, unstructured memory area where JavaScript stores objects, arrays, functions, classes, and large reference-type data.

The Call Stack stores only references (memory addresses) to these objects — not the objects themselves.
heap-example.js
const user = {
    name: "Shivam"
};
Call Stack user ------> 0x101 Memory Heap 0x101 { name: "Shivam" }
2

What Does Single-Threaded Mean?

JavaScript has only one Call Stack. Only one task executes at a time, a long-running function blocks the Call Stack, and the next task starts only after the current task finishes.

blocking.js
console.log("Start");

while(true){}

console.log("End");
// Output: Start (only — "End" never runs)
"End" never executes because the infinite loop blocks the Call Stack forever.

Interview Summary (1 Minute)
1

The 1-Minute Answer

"When a JavaScript program starts, the JavaScript engine creates the Global Execution Context and pushes it onto the Call Stack. Every Execution Context has two phases: the Memory Creation Phase, where memory is allocated (var gets undefined, function declarations are stored, and let/const remain in the TDZ), and the Code Execution Phase, where code runs line by line. Whenever a function is called, a new Function Execution Context is created and pushed onto the Call Stack. Since the Call Stack follows the LIFO principle, the most recently called function executes first and is removed after completion, returning control to the previous context. The Memory Heap stores objects, arrays, and other reference-type data, while the Call Stack stores references to them. JavaScript is single-threaded, meaning it has only one Call Stack and executes one task at a time."
Interview Q&A — JavaScript Engine Execution
💡 Interview Q&A
What happens when we run a JavaScript program?
The JS engine creates a Global Execution Context and pushes it onto the Call Stack. The context runs through the Memory Creation Phase and then the Code Execution Phase. Every function call creates a new Function Execution Context, which is pushed onto the Call Stack and popped once the function returns.
What is an Execution Context?
An Execution Context is the environment in which JavaScript code is evaluated and executed. It holds variables, functions, scope information, and this, and goes through a Memory Creation Phase followed by a Code Execution Phase.
What is the difference between the Global Execution Context and a Function Execution Context?
The GEC is created once, when the program starts, and stays at the bottom of the Call Stack until the program ends. A FEC is created fresh every time a function is invoked, and is removed from the stack once that function finishes executing.
What is the Call Stack and why does it matter?
The Call Stack is a LIFO data structure that stores execution contexts and controls the order code runs in. It matters because it explains synchronous execution order, why a deeply recursive function can cause a "stack overflow," and why one blocking task freezes the entire program.
What's the difference between the Call Stack and the Memory Heap?
The Call Stack manages execution order and stores execution contexts (with references to data). The Memory Heap is where the actual objects, arrays, and functions are stored. Primitive values often live directly on the stack, while reference types are allocated in the heap and accessed via a reference.
Why is JavaScript called single-threaded?
Because it has exactly one Call Stack, so it can only execute one piece of code at a time. A long-running synchronous task (like an infinite loop) blocks that single stack and prevents any other code — including UI updates — from running until it finishes.
What is the Temporal Dead Zone (TDZ)?
The TDZ is the period between when a let/const variable is hoisted (memory allocated) and when it's actually initialized with a value. Accessing the variable during this window throws a ReferenceError, unlike var, which simply returns undefined.
