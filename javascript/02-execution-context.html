What happens when we run a JavaScript program?
The Short Answer
💡 In one line: The JS Engine creates a Global Execution Context, pushes it onto the Call Stack, runs your code in two phases (Memory Creation → Code Execution), and creates a brand-new Function Execution Context — pushed and popped off the same stack — every time a function is called.

Everything else on this page is really just zooming into one of the four moving parts in that sentence: the Engine, the Execution Context, the Call Stack, and the Memory Heap.

The JavaScript Engine
What is the JavaScript Engine?

The JavaScript Engine is the program that actually executes your JS code. It acts as an orchestrator by:

  • Creating Execution Contexts
  • Executing JavaScript code
  • Managing the Call Stack
  • Allocating memory
  • Removing execution contexts after execution

When a program starts, the engine builds an environment to run the code using three major components:

  • Execution Context
  • Call Stack
  • Memory Heap
Execution Context
What is an Execution Context?
An Execution Context (EC) is the environment where JavaScript code is evaluated and executed.

It contains:

  • Variables
  • Functions
  • Scope information
  • this keyword
  • References to objects stored in memory
Every Execution Context goes through two phases: the Memory Creation Phase and the Code Execution Phase.
Phase 1 — Memory Creation Phase

Before executing any code, JavaScript allocates memory:

  • Memory is allocated for variables and functions
  • var variables are initialized with undefined
  • Function declarations are stored completely in memory
  • let and const are allocated but remain in the Temporal Dead Zone (TDZ) until initialized
example.js 
console.log(a);
var a = 10;
Memory Creation: a → undefined Code Execution: a → 10
Phase 2 — Code Execution Phase

After memory allocation, the engine runs the code line by line:

  • Code executes line by line
  • Variables receive their actual values
  • Functions are invoked
  • Expressions are evaluated
Global Execution Context (GEC)
What is the GEC?

Whenever a JavaScript program starts:

  • The JS engine first creates the Global Execution Context
  • It is the first execution context created
  • It is pushed onto the Call Stack
  • It stays at the bottom of the stack until the entire program finishes
The GEC contains: global variables, global functions, the global object (window in browsers, global in Node.js), and this (points to the global object in non-module scripts).
Function Execution Context (FEC)
What is the FEC?

Whenever a function is called:

  • A new Function Execution Context is created
  • It has its own variables, parameters, scope, and this
  • It is pushed onto the Call Stack
  • After execution, it is removed (popped)
Remember: Every single function call creates a brand-new Execution Context — even recursive calls to the same function.
Call Stack
What is the Call Stack?

The JS engine has its own Call Stack, responsible for:

  • Creating execution contexts
  • Managing execution order
  • Deleting execution contexts after execution
It follows the LIFO (Last In, First Out) principle. The Call Stack stores Execution Contexts, not functions directly, and the engine always executes whichever context is at the top of the stack.
Top ----------------- | Function EC | ← Currently executing ----------------- | Function EC | ----------------- | Global EC | ← Created first ----------------- Bottom
How the Call Stack Works — Step by Step

Step 1 — Program Starts

The engine creates the Global Execution Context and pushes it onto the stack.

------------- | Global EC | -------------

Step 2 — Function Invocation

Whenever a function is invoked, a new Function Execution Context is pushed on top.

------------- | one() EC | ------------- | Global EC | -------------

Step 3 — Nested Function Calls

If another function is called inside the current one, another execution context is pushed.

------------- | two() EC | ------------- | one() EC | ------------- | Global EC | -------------

Step 4 — Function Completion

When the current function finishes, its execution context is popped, and control returns to the previous context.

------------- | one() EC | ------------- | Global EC | -------------

Step 5 — Program Ends

After all Function Execution Contexts are removed, only the Global Execution Context remains. When the program finishes, the GEC is removed too.

Call Stack Walkthrough Example
callstack.js 
function one() {
    two();
}

function two() {
    three();
}

function three() {
    console.log("Hello");
}

one();

Initial State

------------- | Global EC | -------------

After one()

------------- | one() EC | ------------- | Global EC | -------------

After two()

------------- | two() EC | ------------- | one() EC | ------------- | Global EC | -------------

After three()

------------- | three() EC| ------------- | two() EC | ------------- | one() EC | ------------- | Global EC | -------------

After three() finishes

------------- | two() EC | ------------- | one() EC | ------------- | Global EC | -------------
Eventually, all Function Execution Contexts are popped, leaving only the Global Execution Context until the program ends.
Memory Heap
What is the Memory Heap?

The Memory Heap is a large, unstructured memory area where JavaScript stores:

  • Objects
  • Arrays
  • Functions
  • Classes
  • Large reference-type data
The Call Stack stores only references (memory addresses) to these objects — not the objects themselves.
heap-example.js 
const user = {
    name: "Shivam"
};
Call Stack user ------> 0x101 Memory Heap 0x101 { name: "Shivam" }
JavaScript is Single-Threaded
What Does Single-Threaded Mean?

JavaScript has only one Call Stack. This means:

  • Only one task executes at a time
  • A long-running function blocks the Call Stack
  • The next task starts only after the current task finishes
blocking.js 
console.log("Start");

while(true){}

console.log("End");
Output: Start
"End" never executes because the infinite loop blocks the Call Stack forever.

Interview Summary (1 Minute)
The 1-Minute Answer
"When a JavaScript program starts, the JavaScript engine creates the Global Execution Context and pushes it onto the Call Stack. Every Execution Context has two phases: the Memory Creation Phase, where memory is allocated (var gets undefined, function declarations are stored, and let/const remain in the TDZ), and the Code Execution Phase, where code runs line by line. Whenever a function is called, a new Function Execution Context is created and pushed onto the Call Stack. Since the Call Stack follows the LIFO principle, the most recently called function executes first and is removed after completion, returning control to the previous context. The Memory Heap stores objects, arrays, and other reference-type data, while the Call Stack stores references to them. JavaScript is single-threaded, meaning it has only one Call Stack and executes one task at a time."
Interview Q&A — JavaScript Engine Execution
Interview Q&A

Q: What happens when we run a JavaScript program?

A: The JS engine creates a Global Execution Context and pushes it onto the Call Stack. The context runs through the Memory Creation Phase and then the Code Execution Phase. Every function call creates a new Function Execution Context, which is pushed onto the Call Stack and popped once the function returns.

Q: What is an Execution Context?

A: An Execution Context is the environment in which JavaScript code is evaluated and executed. It holds variables, functions, scope information, and this, and goes through a Memory Creation Phase followed by a Code Execution Phase.

Q: What is the difference between the Global Execution Context and a Function Execution Context?

A: The GEC is created once, when the program starts, and stays at the bottom of the Call Stack until the program ends. A FEC is created fresh every time a function is invoked, and is removed from the stack once that function finishes executing.

Q: What is the Call Stack and why does it matter?

A: The Call Stack is a LIFO data structure that stores execution contexts and controls the order code runs in. It matters because it explains synchronous execution order, why a deeply recursive function can cause a "stack overflow," and why one blocking task freezes the entire program.

Q: What's the difference between the Call Stack and the Memory Heap?

A: The Call Stack manages execution order and stores execution contexts (with references to data). The Memory Heap is where the actual objects, arrays, and functions are stored. Primitive values often live directly on the stack, while reference types are allocated in the heap and accessed via a reference.

Q: Why is JavaScript called single-threaded?

A: Because it has exactly one Call Stack, so it can only execute one piece of code at a time. A long-running synchronous task (like an infinite loop) blocks that single stack and prevents any other code — including UI updates — from running until it finishes.

Q: What is the Temporal Dead Zone (TDZ)?

A: The TDZ is the period between when a let/const variable is hoisted (memory allocated) and when it's actually initialized with a value. Accessing the variable during this window throws a ReferenceError, unlike var, which simply returns undefined.
