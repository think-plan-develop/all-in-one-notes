🌐 Fetch API

The Fetch API provides a modern, promise-based interface for making HTTP requests in the browser. It replaces the older XMLHttpRequest with cleaner syntax and better integration with async/await.

How Fetch Works

Calling fetch(url, options) returns a Promise that resolves to a Response object. You then call methods like .json(), .text(), or .blob() on that response to extract the actual data — which itself returns another Promise.

fetch-basic.js 
// GET request
async function getUsers() {
  try {
    const res = await fetch("https://api.example.com/users");
    if (!res.ok) throw new Error(`HTTP error: ${res.status}`);
    const data = await res.json();
    console.log(data);
  } catch (err) {
    console.error("Fetch failed:", err);
  }
}

// POST request with JSON body
fetch("https://api.example.com/users", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ name: "John", age: 28 })
})
  .then(res => res.json())
  .then(data => console.log(data));

Key Points

fetch() only rejects on network failure — a 404 or 500 response is still a "successful" fetch. Always check res.ok or res.status to catch HTTP errors.

✅ Best for: Any client-server communication — REST APIs, file downloads, form submissions, and streaming responses.
⚠️ Watch out: Fetch doesn't reject on HTTP error codes, and it has no built-in timeout — pair it with AbortController for that.
Pros
  • Clean, promise-based syntax
  • Works great with async/await
  • Supports streaming response bodies
  • Built into all modern browsers
Cons
  • No automatic JSON parsing on error responses
  • No native request timeout or cancellation
  • Doesn't reject on 4xx/5xx status codes
  • Slightly more verbose than libraries like Axios
🛑 AbortController

AbortController lets you cancel in-progress asynchronous operations — most commonly a fetch() request. It's the standard way to implement request timeouts, cancel-on-unmount behavior in UI components, or "cancel search" features.

How AbortController Works

You create an AbortController instance, pass its .signal into the fetch options, and call .abort() whenever you want to cancel the request. The fetch Promise then rejects with an AbortError.

abort-controller.js 
const controller = new AbortController();
const { signal } = controller;

fetch("https://api.example.com/search?q=js", { signal })
  .then(res => res.json())
  .then(data => console.log(data))
  .catch(err => {
    if (err.name === "AbortError") {
      console.log("Request was cancelled");
    }
  });

// Cancel the request manually (e.g. user typed something new)
controller.abort();

// Common pattern: auto-timeout after 5 seconds
const timeoutController = new AbortController();
setTimeout(() => timeoutController.abort(), 5000);
fetch("https://api.example.com/slow", { signal: timeoutController.signal });

Common Use Cases

Search-as-you-type (cancel the previous request when a new keystroke happens), request timeouts, cancelling requests when a React/Vue component unmounts, and cancelling multiple related fetches at once using a single shared signal.

💡 Tip: One AbortController can cancel multiple fetch calls at once if they all share the same signal — useful for aborting a whole batch of requests together.
📝 Note: Once a controller is aborted, it cannot be reused. You must create a new AbortController for the next request.
Pros
  • Native, no external library needed
  • Works with fetch and other abortable APIs
  • One signal can cancel multiple requests
  • Prevents race conditions from stale requests
Cons
  • Controller instance is single-use
  • Doesn't stop server-side processing, just the client listener
  • Requires manual timeout logic (no built-in timeout option)
🔗 URL API

The URL API provides an object-based way to parse, build, and manipulate URLs, rather than manually concatenating and splitting strings. It also includes URLSearchParams for working with query strings.

How the URL API Works

Creating a new URL(...) instance gives you structured access to every part of the URL — protocol, hostname, pathname, and query parameters — all as readable/writable properties.

url-api.js 
const url = new URL("https://example.com/products?category=shoes&sort=price");

console.log(url.hostname);   // "example.com"
console.log(url.pathname);   // "/products"
console.log(url.search);     // "?category=shoes&sort=price"

// Working with query params
console.log(url.searchParams.get("category")); // "shoes"

url.searchParams.set("sort", "newest");
url.searchParams.append("page", "2");

console.log(url.toString());
// "https://example.com/products?category=shoes&sort=newest&page=2"

// Building query params from scratch
const params = new URLSearchParams({ q: "laptop", page: "1" });
console.log(params.toString()); // "q=laptop&page=1"

Common Use Cases

Reading and updating query parameters, validating URLs, building API request URLs dynamically, and extracting parts of the current page's address via window.location.href.

✅ Best for: Any situation involving reading, building, or modifying URLs and query strings — pagination, filters, and search parameters.
💡 Tip: Use URLSearchParams instead of manually building query strings with string concatenation — it automatically handles encoding special characters.
Pros
  • No need for manual string splitting/regex
  • Automatic URL encoding/decoding
  • Built-in, no dependencies
  • Works with relative URLs (with a base)
Cons
  • Throws an error on invalid URLs (must be caught)
  • Slightly unfamiliar API for beginners
  • Requires a base URL for relative paths
📋 Clipboard API

The Clipboard API lets web pages read from and write to the system clipboard, enabling "Copy to Clipboard" buttons and paste functionality — replacing the older, less reliable document.execCommand("copy").

How the Clipboard API Works

It's accessed via navigator.clipboard and is asynchronous (Promise-based). Most browsers require a secure context (HTTPS) and often a user gesture (like a click) before allowing clipboard access.

clipboard-api.js 
// Copying text to the clipboard
async function copyText(text) {
  try {
    await navigator.clipboard.writeText(text);
    console.log("Copied to clipboard!");
  } catch (err) {
    console.error("Copy failed:", err);
  }
}

// Usage on a button click
document.querySelector("#copyBtn").addEventListener("click", () => {
  copyText("Hello, clipboard!");
});

// Reading text from the clipboard (needs user permission)
async function pasteText() {
  const text = await navigator.clipboard.readText();
  console.log("Pasted:", text);
}

Common Use Cases

"Copy link" or "Copy code" buttons, copying generated coupon codes, pasting content into custom rich-text editors, and sharing content quickly without manual selection.

✅ Best for: Copy-to-clipboard buttons, sharing links or codes, and custom paste handling in web apps.
⚠️ Watch out: Requires a secure context (HTTPS or localhost) and, in most browsers, must be triggered directly from a user action like a click — it won't work from a background timer.
Pros
  • Simple async API for copy/paste
  • More reliable than execCommand
  • Supports both text and rich data (images, HTML)
  • Built-in permission handling
Cons
  • Requires HTTPS/secure context
  • Usually requires a user gesture to trigger
  • Reading clipboard may prompt a permission popup
  • Browser support varies for non-text formats

❓ Frequently Asked Questions
Common Questions

1. Does fetch() reject the promise on a 404 or 500 response?

No. Fetch only rejects on network-level failures (like no internet connection or a DNS error). You must manually check response.ok or response.status to detect HTTP errors.

2. How do I add a timeout to a fetch request?

Fetch has no built-in timeout. Combine it with AbortController: start a timer with setTimeout that calls controller.abort() after N milliseconds, and pass controller.signal into the fetch options.

3. Can one AbortController cancel multiple fetch requests?

Yes. If multiple fetch calls are given the same signal from one controller, calling .abort() once cancels all of them simultaneously.

4. Can an AbortController be reused after calling abort()?

No. Once aborted, that controller's signal stays in the aborted state permanently. A new AbortController instance must be created for further requests.

5. What's the advantage of URLSearchParams over manually building a query string?

URLSearchParams automatically handles proper URL encoding of special characters and spaces, and provides convenient methods like .get(), .set(), and .append() instead of manual string concatenation.

6. Why does navigator.clipboard.writeText() sometimes fail silently or throw an error?

Clipboard access typically requires a secure context (HTTPS) and must usually be triggered by a direct user action such as a click, not from background code or timers. It may also fail if the page lacks clipboard permission.

7. Is the Clipboard API supported in all browsers?

Support is good in modern Chrome, Firefox, and Edge, but some features — especially reading non-text data or older Safari versions — have more limited or inconsistent support.
