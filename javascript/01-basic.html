1. Variables (var, let, const)
Declaring Variables Core Concept

JavaScript gives you three ways to declare a variable, and each behaves differently around scope, reassignment, and hoisting.

variables.js 
var name = "Alice";   // function-scoped, can be redeclared
let age = 25;         // block-scoped, can be reassigned
const PI = 3.14159;  // block-scoped, cannot be reassigned

age = 26;      // ✅ works
PI = 3.14;     // ❌ TypeError: Assignment to constant variable
KeywordScopeReassignableHoisted
varFunctionYesYes (initialized as undefined)
letBlockYesYes (in Temporal Dead Zone)
constBlockNoYes (in Temporal Dead Zone)
Best practice: Default to const. Use let only when you know a value will change. Avoid var in modern code.

Hoisting — var vs let/const

All three are "hoisted" (JavaScript registers the variable name before running the code), but they behave very differently before their declaration line is reached.

hoisting.js
console.log(a);  // undefined (not an error!)
var a = 5;

console.log(b);  // ❌ ReferenceError: Cannot access 'b' before initialization
let b = 10;

console.log(c);  // ❌ ReferenceError: Cannot access 'c' before initialization
const c = 15;
ConceptExplanation
var hoistingDeclaration moves to the top of its function and is auto-initialized to undefined. Reading it early gives undefined, not an error.
Temporal Dead Zone (TDZ)let/const are hoisted too, but stay uninitialized from the top of the block until their declaration line runs. Accessing them there throws a ReferenceError.
Why it mattersThe TDZ turns "used a variable before defining it" from a silent bug (var) into an immediate, loud error (let/const).
var's function-scope leak: var ignores block boundaries entirely — it leaks out of if/for blocks into the whole function, while let/const stay properly contained.
scope-leak.js
if (true) {
  var x = 1;
  let y = 2;
}
console.log(x); // 1 — leaked out of the if-block
console.log(y); // ❌ ReferenceError: y is not defined

const — Reassignment vs Mutation

const only freezes the binding (the name-to-value link) — not the value itself. If that value is an object or array, its contents can still be changed.

❌ Reinitializing (blocked)
const arr = [1, 2, 3];
arr = [4, 5];
// ❌ TypeError: Assignment to
//    constant variable.
✅ Mutating (allowed)
const arr = [1, 2, 3];
arr.push(4);      // ✅ [1,2,3,4]
arr[0] = 99;     // ✅ [99,2,3,4]
arr.pop();         // ✅ [99,2,3]

Same rule applies to objects:

const-object.js
const user = { name: "Sam" };
user.name = "Alex";   // ✅ mutation — allowed
user.age = 30;       // ✅ adding a new property — allowed
user = { name: "Max" }; // ❌ reassigning the binding — blocked
Want a truly frozen object? Combine const with Object.freeze(obj). const alone stops you from swapping the reference; Object.freeze() additionally stops you from mutating its contents.

JavaScript has 8 data types: 7 primitive types and 1 non-primitive (object).

typeof.js
typeof "hi";        // "string"
typeof 42;          // "number"
typeof true;        // "boolean"
typeof undefined;   // "undefined"
typeof null;        // "object" — famous historical bug!

Note: typeof null === "object" is a long-standing bug baked into JavaScript from its earliest versions — it can never be fixed without breaking the web.
3. Primitive vs Reference Types
How Values Are Stored & Copied

This distinction explains a huge share of "why did my object change unexpectedly" bugs.

🔹 Primitive Types
  • String, Number, Boolean, Undefined, Null, Symbol, BigInt
  • Stored by value
  • Copying creates an independent copy
  • Immutable — operations create new values
🔸 Reference Types
  • Object, Array, Function, Date, Map, Set
  • Stored by reference (memory address)
  • Copying copies the reference, not the data
  • Mutable — same object can change from any reference
reference.js
// Primitive — independent copy
let a = 10;
let b = a;
b = 20;
console.log(a); // 10 (unchanged)

// Reference — shared object
let obj1 = { value: 10 };
let obj2 = obj1;
obj2.value = 20;
console.log(obj1.value); // 20 (changed!)
Remember: To truly copy an object, use spread ({...obj}) or structuredClone(obj) — assignment alone just copies the reference.
4. Type Conversion
Implicit vs Explicit Conversion

JavaScript converts values between types either automatically (coercion) or when you request it (explicit conversion).

Explicit Conversion

conversion.js
String(123);      // "123"
Number("123");    // 123
Number("abc");    // NaN
Boolean(1);       // true
Boolean(0);       // false
parseInt("42px");  // 42
parseFloat("3.14m");// 3.14

Implicit Conversion (Coercion)

coercion.js
"5" + 1;    // "51"  (number → string)
"5" - 1;    // 4     (string → number)
"5" * "2";  // 10    (both → number)
1 + true;  // 2     (boolean → number)
"5" + null; // "5null"
Gotcha: + favors string concatenation if either operand is a string, but -, *, / always coerce to numbers. This asymmetry causes many subtle bugs.
5. Truthy & Falsy Values
What Counts as True or False

Every value in JavaScript is "truthy" or "falsy" when evaluated in a boolean context, like an if statement.

❌ Falsy Values (only 8)
  • false
  • 0 and -0
  • 0n (BigInt zero)
  • "" (empty string)
  • null
  • undefined
  • NaN
✅ Truthy Values (everything else)
  • "0", "false" (non-empty strings)
  • [] (empty array!)
  • {} (empty object!)
  • Any function
  • Any number except 0 and NaN
Q: Is an empty array [] truthy or falsy? A: Truthy! if ([]) runs the block. This surprises many beginners coming from other languages.
Tip: Use Boolean(value) or !!value to explicitly check a value's truthiness.

const user = { name: "Sam" };

// Optional chaining — avoids errors on missing properties
console.log(user?.address?.city); // undefined, no crash

// Nullish coalescing — only falls back on null/undefined
const count = 0 ?? 10;   // 0 (0 is not null/undefined)
const count2 = 0 || 10;  // 10 (0 is falsy)
Note: ?? and || look similar but behave differently — ?? only triggers on null/undefined, while || triggers on any falsy value.
7. Equality (== vs ===)
Loose vs Strict Equality

JavaScript offers two ways to compare values, and choosing the right one avoids a whole class of bugs.

== (Loose Equality)
  • Coerces types before comparing
  • "5" == 5 → true
  • null == undefined → true
  • Unpredictable in edge cases
=== (Strict Equality)
  • No type coercion — compares type + value
  • "5" === 5 → false
  • null === undefined → false
  • Predictable, recommended default
equality.js
0 == false;         // true
"" == 0;           // true
null == undefined;   // true
NaN == NaN;         // false (NaN never equals itself!)

0 === false;        // false
"" === 0;          // false
Object.is(NaN, NaN); // true (use for NaN checks)
Remember: Always default to === and !==. Only reach for == in the rare, deliberate case of treating null and undefined as equal.
8. Strict Mode
Writing Safer JavaScript

Strict mode turns silent mistakes into visible errors and disables some error-prone features.

strict.js
"use strict";

x = 10; // ❌ ReferenceError: x is not defined
             // (without strict mode, this silently creates a global)

What Strict Mode Changes

BehaviorEffect
Undeclared varsThrows an error instead of creating a leaking global
Silent failuresAssignment to read-only properties now throws
this bindingthis is undefined in plain function calls
DuplicatesDuplicate parameter names throw errors

ES6 Modules and Classes — both are strict mode by default, no directive needed.

Note: Place "use strict"; at the very top of a file or function to enable it. Modern ES modules and classes are automatically strict.
9. Interview Questions & Answers
Commonly Asked in Interviews 12 Q&A
QuestionAnswer
What is the difference between var, let, and const?var is function-scoped, hoisted with a default of undefined, and can be redeclared. let/const are block-scoped and live in the TDZ until initialized. let can be reassigned; const cannot (but its contents can still be mutated).
What is hoisting?JavaScript registers variable/function declarations in memory before running the code. var is initialized to undefined; let/const stay uninitialized in the TDZ and throw if accessed early.
Can you reassign a const array or object?No — you can't point the variable to a new array/object. But you can mutate the existing one (push, pop, change properties) since only the binding is locked.
What is the Temporal Dead Zone (TDZ)?The period between entering a block and the line where a let/const variable is declared. Accessing the variable during this window throws a ReferenceError.
What are the primitive data types in JavaScript?String, Number, BigInt, Boolean, Undefined, Null, and Symbol. Everything else falls under the single non-primitive type: Object.
What is the difference between primitive and reference types?Primitives are copied by value — each variable holds an independent copy. Reference types are copied by reference — multiple variables can point to the same object.
What is the difference between == and ===?== coerces types before comparing (e.g. "5" == 5 is true). === compares type and value with no conversion ("5" === 5 is false). Prefer ===.
Why does typeof null return "object"?It's a bug from the first version of JavaScript, kept for backward compatibility since fixing it would break existing code.
What are falsy values in JavaScript?Exactly 8: false, 0, -0, 0n, "", null, undefined, NaN. Everything else — including [] and {} — is truthy.
What does "use strict" do?Enables strict mode, which throws errors for actions that would otherwise fail silently, disables some legacy features, and makes this default to undefined in plain function calls.
What is the difference between null and undefined?undefined means a variable is declared but not yet assigned (set automatically). null is an intentional "no value" set deliberately by the developer.
How do you deeply copy an object instead of copying its reference?Use spread ({...obj}) for a shallow copy, or structuredClone(obj) / JSON.parse(JSON.stringify(obj)) for a deep copy of nested structures.
