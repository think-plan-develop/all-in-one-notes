🔗 Scope, Lexical Scope, Lexical Environment & Scope Chain

How JavaScript decides where a variable lives, and how it looks one up when you use it

What is Scope?

Definition

Scope defines where a variable can be accessed in your program. JavaScript has three kinds: Global, Function, and Block scope.
📝 Interview Definition: Scope defines the visibility and accessibility of variables in different parts of a program.
Types of Scope

Global Scope

Variables declared outside any function or block belong to the global scope and can be accessed from anywhere in the program.

global-scope.js
let name = "Shivam";

function show() {
    console.log(name); // Accessible
}

show();
console.log(name); // Accessible

Function Scope

Variables declared with var inside a function are accessible only within that function.

function-scope.js
function demo() {
    var age = 25;
    console.log(age); // ✅
}

demo();
console.log(age); // ❌ ReferenceError

Block Scope

Variables declared with let and const are accessible only inside the block ({}) where they are declared.

block-scope.js
{
    let city = "Delhi";
    const country = "India";

    console.log(city);     // ✅
    console.log(country);  // ✅
}

console.log(city);     // ❌
console.log(country);  // ❌

Combined Example — All Three Together

combined-scope.js
let global = "I am Global";

function demo() {
    var functionVar = "Function Scope";

    if (true) {
        let blockVar = "Block Scope";

        console.log(global);      // ✅
        console.log(functionVar); // ✅
        console.log(blockVar);    // ✅
    }

    console.log(global);      // ✅
    console.log(functionVar); // ✅
    console.log(blockVar);    // ❌
}

demo();

console.log(global);      // ✅
console.log(functionVar); // ❌

Lexical Scope (Static Scope)

What is Lexical Scope?

Lexical Scope means a function's scope is determined by where it is written (defined) in the source code — not where it is called. JavaScript decides this during code creation.
lexical-scope.js
let a = 10;

function outer() {
    let b = 20;

    function inner() {
        console.log(a); // 10
        console.log(b); // 20
    }

    inner();
}

outer();

Here, inner() is defined inside outer(), so it can access:

  • Its own variables
  • Variables of outer()
  • Global variables

The Classic Gotcha Example

gotcha.js
let a = 10;

function first() {
    console.log(a);
}

function second() {
    let a = 20;
    first();
}

second();
// Output: 10
⚠️ Why? Although first() is called inside second(), it was defined in the global scope. So it only has access to the global lexical scope, not second()'s local variables.
📝 Interview Definition: Lexical Scope means JavaScript determines variable accessibility based on where functions are defined, not where they are called.
Lexical Environment

What is a Lexical Environment?

A Lexical Environment is an internal memory structure created whenever JavaScript enters the Global Execution Context, a function, or a block (let/const).

It contains two parts:

  • Environment Record — stores variables and functions
  • Outer Reference — points to the parent lexical environment
lexical-env.js
let a = 10;

function outer() {
    let b = 20;
}

Global & Outer Lexical Environment

📝 Interview Definition: Lexical Environment is the internal memory structure where JavaScript stores variables and maintains a reference to its parent scope.
Scope Chain

What is the Scope Chain?

The Scope Chain is the mechanism JavaScript uses to resolve variables. It searches the current Lexical Environment, then the parent, then the grandparent, and so on — until it reaches the Global Lexical Environment or finds the variable.
scope-chain.js
let a = 10;

function outer() {
    let b = 20;

    function inner() {
        let c = 30;

        console.log(a);
        console.log(b);
        console.log(c);
    }

    inner();
}

outer();

Variable Lookup — Searching for 'a'

JavaScript checks:

  1. Is a in inner()? ❌
  2. Is a in outer()? ❌
  3. Is a in Global? ✅
💡 Interview Definition: Scope Chain is the mechanism JavaScript uses to resolve variables by searching the current scope and then moving through parent scopes until the variable is found or the global scope is reached.

Interview Summary

Key Points to Remember

  • Scope defines where a variable is visible and accessible.
  • There are three kinds: Global, Function, and Block scope.
  • Lexical Scope is fixed by where a function is written, not where it is called from.
  • Every Global Execution Context, function call, and block creates a Lexical Environment.
  • A Lexical Environment has an Environment Record and an Outer Reference to its parent.
  • The Scope Chain is how JS walks outward — current → parent → global — to resolve a variable.
  • If a variable isn't found anywhere in the chain, JavaScript throws a ReferenceError.
💡 Common misconception: People often confuse "where a function is called from" with its scope. Remember — JavaScript is lexically (statically) scoped, so it's always about where the function was defined in the source code.
Interview Q&A — Scope
💡 Interview Q&A
What's the difference between scope and lexical scope?
"Scope" is the general concept of where a variable is accessible. "Lexical scope" describes how that scope gets determined in JavaScript — by the physical location of the code as written, not by the call stack at runtime.
Is JavaScript lexically scoped or dynamically scoped?
JavaScript is lexically (statically) scoped. A function's access to outer variables is decided at the time it's written, based on its surrounding code — not by which function happened to call it.
What is a Lexical Environment made of?
Two parts: an Environment Record, which holds the actual variables and functions declared in that scope, and an Outer Reference, a pointer to the parent Lexical Environment used for the scope chain lookup.
How does the Scope Chain relate to closures?
A closure works because of the scope chain — when an inner function is returned or passed around, it keeps a reference to its outer Lexical Environment, so it can still resolve variables from where it was originally defined, even after the outer function has finished running.
