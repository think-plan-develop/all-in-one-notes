Variables (var, let, const)
📦

Definition

A variable is a named container used to store data in memory. JavaScript provides three keywords to declare variables: var, let, and const. They differ in scope, hoisting, redeclaration, reassignment, and lifetime.

Interview Definition: Variables are identifiers that hold values. JavaScript supports var, let, and const, each with different scoping rules and behavior during hoisting.
🏷️

Declaring Variables

JavaScript offers three ways to declare variables. Choosing the correct one improves readability, prevents bugs, and makes code easier to maintain.

variables.js
var name = "Alice";     // Function-scoped, can be redeclared & reassigned
let age = 25;           // Block-scoped, can be reassigned
const PI = 3.14159;    // Block-scoped, cannot be reassigned

age = 26;      // ✅ Allowed
PI = 3.14;     // ❌ TypeError

📤

Hoisting

Hoisting is JavaScript's behavior of moving variable and function declarations to the top of their scope before code execution.

hoisting.js
console.log(a);
var a = 5;
// undefined — var is hoisted and pre-initialized

console.log(b);
let b = 10;
// ❌ ReferenceError — b is in the TDZ, see below
Interview Tip: Every variable is hoisted. The difference is that var is initialized as undefined, while let and const stay inside the Temporal Dead Zone (TDZ).
⏳

Temporal Dead Zone (TDZ)

let and const are hoisted but remain uninitialized until execution reaches their declaration line. Accessing them earlier throws a ReferenceError.

tdz.js
console.log(c);
const c = 15;
// ❌ ReferenceError: Cannot access 'c' before initialization
Why it exists: the TDZ prevents accidental use of a variable before it's initialized, making bugs easier to catch instead of silently returning undefined like var does.
🧱

Scope

var is function-scoped, whereas let and const are block-scoped. Block scope includes if, for, while, and any { }.

scope.js
if (true) {
    var x = 10;
    let y = 20;
}

console.log(x); // 10
console.log(y); // ❌ ReferenceError
Important: var ignores block scope, which is why it can leak outside loops and if blocks.
🔐

const — Reassignment vs Mutation

const makes the reference immutable, not the object itself. Objects and arrays declared with const can still be modified.

❌ Reassignment
const arr = [1, 2, 3];

arr = [4, 5];   // ❌ TypeError
✅ Mutation
const arr = [1, 2, 3];

arr.push(4);
arr[0] = 99;
arr.pop();

Same applies to objects:

object.js
const user = { name: "Sam" };

user.name = "Alex";
user.age = 30;

user = { name: "Max" };   // ❌ TypeError
Interview Note: const does not make objects or arrays immutable. It only prevents changing the variable's reference. Use Object.freeze() if you want to prevent modifications to an object's properties.
✅

Best Practices

  • Prefer const by default — it signals intent and prevents accidental reassignment.
  • Use let only when a value genuinely needs to change (loop counters, accumulators, reassigned state).
  • Avoid var in modern JavaScript — its function scope and hoisting behavior are common bug sources.
  • Declare variables as close as possible to where they're used, inside the smallest scope that needs them.
Truthy & Falsy Values
🚫

Falsy Values

Every value in JavaScript is "truthy" or "falsy" when evaluated in a boolean context, like an if statement. There are only 8 falsy values in the entire language:

  • false
  • 0 and -0
  • 0n (BigInt zero)
  • "" (empty string)
  • null
  • undefined
  • NaN
✅

Truthy Values

Everything that isn't in the falsy list above is truthy — including several values that surprise beginners:

  • "0", "false" (non-empty strings, regardless of content)
  • [] — an empty array is truthy!
  • {} — an empty object is truthy!
  • Any function
  • Any number except 0 and NaN
Q: Is an empty array [] truthy or falsy? A: Truthy! if ([]) runs the block. This trips up a lot of people coming from other languages.
🔁

Boolean Conversion

Use Boolean(value) or the double-negation shorthand !!value to explicitly convert any value to its truthy/falsy boolean equivalent.

boolean-conversion.js
Boolean(0);       // false
Boolean("");      // false
Boolean(null);    // false

Boolean([]);      // true
Boolean({});      // true
Boolean("0");    // true — non-empty string

!!42;             // true — shorthand for Boolean(42)
!!"";             // false
Operators
➕

Arithmetic

Perform math operations: + - * / % **.

arithmetic.js
10 + 5;   // 15
10 % 3;   // 1 — remainder
2 ** 10;  // 1024 — exponent
✍️

Assignment

Assign or update a variable's value: = += -= *= /=.

assignment.js
let total = 10;
total += 5;   // total = 15
total *= 2;   // total = 30
⚖️

Comparison

Compare two values: == === != !== > <.

comparison.js
5 > 3;      // true
"5" === 5;  // false — no coercion
See the dedicated Equality section below for the full == vs === breakdown.
🔗

Logical

Combine boolean logic: && || !.

logical.js
true && false;   // false
true || false;   // true
!true;            // false
❓

Ternary

A compact inline if/else: condition ? valueIfTrue : valueIfFalse.

ternary.js
const age = 20;
const status = age >= 18 ? "Adult" : "Minor";
// "Adult"
🧷

Optional Chaining (?.)

Safely accesses a nested property without throwing when something along the path is null/undefined.

optional-chaining.js
const user = { name: "Sam" };

console.log(user?.address?.city);
// undefined — no crash, even though address doesn't exist
🎯

Nullish Coalescing (??)

Provides a fallback value, but only when the left side is null or undefined — unlike ||, which reacts to any falsy value.

nullish-coalescing.js
const count = 0 ?? 10;   // 0 — 0 is not null/undefined
const count2 = 0 || 10;  // 10 — 0 is falsy, so || replaces it
Note: ?? and || look similar but behave differently — ?? only triggers on null/undefined, while || triggers on any falsy value.
Equality (== vs ===)
🔓

Loose Equality (==)

== coerces types before comparing, which can produce results that aren't always intuitive.

loose-equality.js
"5" == 5;          // true
0 == false;         // true
"" == 0;           // true
null == undefined;   // true
🔒

Strict Equality (===)

=== compares both type and value, with no coercion — the predictable, recommended default.

strict-equality.js
"5" === 5;         // false
0 === false;        // false
"" === 0;          // false
null === undefined;  // false
Remember: Always default to === and !==. Only reach for == in the rare, deliberate case of treating null and undefined as equal.
⚠️

Common Pitfalls

A few equality quirks that come up often in interviews:

pitfalls.js
NaN == NaN;    // false — NaN never equals itself
NaN === NaN;   // false — same result, still surprising

[] == [];      // false — different object references
[] == "";      // true — [] is coerced to ""
🧪

Object.is()

Object.is() behaves almost exactly like ===, except it correctly handles the two edge cases === gets "wrong": NaN and -0.

object-is.js
Object.is(NaN, NaN);   // true
NaN === NaN;           // false

Object.is(0, -0);     // false
0 === -0;             // true
💡 Use case: reach for Object.is() specifically when you need a reliable NaN check.
Strict Mode
🔒

Definition

Strict Mode is a special JavaScript mode that enables a stricter set of rules. It helps catch common coding mistakes, prevents accidental global variables, improves code security, and makes JavaScript easier to optimize.

Interview Definition: Strict Mode is an opt-in feature that changes JavaScript from a forgiving language into a stricter one by converting many silent errors into runtime errors.
🚀

Enabling Strict Mode

Place "use strict"; at the beginning of a JavaScript file or function.

strict.js
"use strict";

let name = "John";

console.log(name);
Important: ES6 Modules (import/export) and Classes always run in Strict Mode. You don't need to write "use strict";.
📊

🫥

this Behavior

"use strict";

function show() {
    console.log(this);
}

show();
// undefined

In normal mode, this refers to the global object (window in browsers). In Strict Mode, this becomes undefined in a plain function call.

🌍

Accidental Globals

"use strict";

x = 10;

// ❌ ReferenceError: x is not defined

Without Strict Mode, JavaScript automatically creates x as a global variable, which often causes hard-to-trace bugs.

🚧

Restrictions

A few actions that are silently allowed normally become hard errors under strict mode:

restrictions.js
"use strict";

function add(a, a) {}
// ❌ SyntaxError — duplicate parameter names

let age = 25;
delete age;
// ❌ SyntaxError — can't delete a variable

const obj = {};
Object.defineProperty(obj, "id", { value: 1, writable: false });
obj.id = 2;
// ❌ TypeError — assigning to a read-only property
✅

Best Practices

  • Always write modern JavaScript in Strict Mode.
  • Prefer ES Modules — they automatically enable Strict Mode.
  • Avoid relying on old JavaScript behaviors that Strict Mode disallows.
  • Treat any Strict Mode error as a signal of a real bug, not just noise to silence.
Interview Questions
💡 Interview Q&A
Difference between var, let, and const?
var is function-scoped, hoisted with a default of undefined, and can be redeclared. let/const are block-scoped and live in the TDZ until initialized. let can be reassigned; const cannot (but its contents can still be mutated).
What is hoisting?
JavaScript registers variable and function declarations in memory before running the code. var is initialized to undefined; let/const stay uninitialized until their declaration line runs.
What is the TDZ?
The Temporal Dead Zone is the period between entering a block and the line where a let/const variable is declared. Accessing the variable during this window throws a ReferenceError.
Can you modify a const object?
Yes — const only locks the variable's reference, not its contents. You can freely change properties or push into an array; you just can't reassign the variable to a completely new object or array.
What are truthy and falsy values?
Every value acts as either truthy or falsy in a boolean context. There are exactly 8 falsy values — false, 0, -0, 0n, "", null, undefined, and NaN — everything else, including [] and {}, is truthy.
Difference between == and ===?
== coerces types before comparing (e.g. "5" == 5 is true). === compares type and value with no conversion ("5" === 5 is false).
When should you use ===?
Essentially always — it's predictable and avoids the surprising coercion rules of ==. Reach for == only in the rare, deliberate case where you want null and undefined to be treated as equal.
What does "use strict" do?
It enables strict mode, which turns many silent failures into thrown errors — undeclared variables, duplicate function parameters, deleting a variable, and writing to a read-only property all become errors instead of being ignored.
How does Strict Mode change this?
In a plain function call, this normally defaults to the global object. Under strict mode, it stays undefined instead, which helps catch accidental global object mutation.
Difference between ?? and ||?
|| falls back to its right-hand value for any falsy left-hand value, including 0 and "". ?? only falls back when the left-hand value is specifically null or undefined, so legitimate falsy values like 0 are preserved.
