JavaScript Objects 📦

1–4. The Basics
1. Object Creation

Objects store data as key-value pairs. Created using literal syntax {} or the new Object() constructor.

creation.js
const user = {
  name: "Aria",
  age: 25
};
✅ Object literals {} are the standard, preferred way to create objects.
2. Property Access

Read or set object properties using dot notation or bracket notation.

access.js
user.name;        // "Aria" (dot notation)
user["age"];    // 25 (bracket notation)
🔎 Use bracket notation when the key is dynamic or not a valid identifier, e.g. user["first-name"].
3. Add, Update & Delete Properties ⭐⭐⭐

Properties can be added or updated any time using dot/bracket assignment, and removed using delete.

crud.js
// add / update
user.email = "abc@gmail.com";
user["country"] = "India";

// delete
const user2 = { name: "John", age: 25 };
delete user2.age;
console.log(user2); // { name: "John" }
💡 Assigning to a new key adds it; assigning to an existing key updates it. delete removes the key entirely (not just sets it to undefined).
4. Methods

A method is simply a function stored as an object property.

methods.js
const user = {
  name: "Aria",
  greet() {
    return `Hi, I'm ${this.name}`;
  }
};
user.greet(); // "Hi, I'm Aria"
💡 Inside a regular method, this refers to the object the method was called on.
5–6. Context & Structure
5. this Keyword

this refers to the object that is currently calling the method — not where the function was defined.

this.js
const user = {
  name: "Aria",
  greet() { console.log(this.name); }
};
user.greet(); // "Aria" — `this` = user
⚠️ Arrow functions don't have their own this — they inherit it from the surrounding scope, so avoid arrow functions as object methods that need this.
6. Nested Objects

An object property can itself be another object, creating nested structures accessed by chaining.

nested.js
const user = {
  name: "John",
  address: {
    city: "Delhi",
    pin: 110001
  }
};
user.address.city; // "Delhi"
🔎 Deeply nested data is common in real-world APIs (JSON responses). Use ?. to access it safely — see the Interview Questions section for optional chaining.
7–9. Copying & Merging
7. Object Destructuring ES6

Unpacks object properties into individual variables in one line.

destructuring.js
const { name, age } = user;
console.log(name, age); // "Aria" 25
✅ Cleaner than writing const name = user.name for every property.
8. Spread Operator ...

Copies or merges an object's own properties into a new object using ....

spread.js
const updated = { ...user, age: 26 };
// { name: "Aria", age: 26 }
🔎 Great for immutable updates — the original user object stays unchanged (but see Shallow Copy, #10).
9. Object.assign()

Copies properties from one or more source objects into a target object.

assign.js
const merged = Object.assign({}, user, { age: 30 });
💡 The older, pre-spread-operator way to merge or clone objects — still useful and widely supported.
10–12. Copies, Loops & Locking
10. Shallow Copy vs Deep Copy ⭐⭐⭐⭐⭐ Very Common

Both { ...obj } and Object.assign() only make a shallow copy — nested objects are still shared by reference.

shallow.js
const user = {
  name: "John",
  address: { city: "Delhi" }
};

const copy = { ...user };
copy.address.city = "Mumbai";

console.log(user.address.city); // "Mumbai"
⚠️ Why: The spread only copies the top-level keys. address is copied as a reference, so copy.address and user.address point to the same nested object — editing one edits both.

Real deep copies

deep.js
const deep1 = structuredClone(user);
const deep2 = JSON.parse(JSON.stringify(user));
✅ structuredClone() is the modern, built-in way to deep-clone — it handles dates, arrays, Maps, etc. JSON.parse(JSON.stringify()) is an older trick that works for plain data but drops functions, undefined, and dates (converts them to strings).
11. Object Iteration ⭐⭐⭐⭐ Very Important

There are several ways to loop through or extract data from an object.

iteration.js
for (const key in user) {
  console.log(key, user[key]);
}

Object.keys(user);    // ["name", "age"]
Object.values(user);  // ["Aria", 25]
Object.entries(user); // [["name","Aria"], ["age",25]]
MethodReturns
for...inLoops over keys directly (including inherited enumerable ones)
Object.keys()Array of own property names
Object.values()Array of own property values
Object.entries()Array of own [key, value] pairs
💡 Prefer Object.keys/values/entries over for...in in most cases — they only include the object's own properties, not inherited ones.
12. Freeze vs Seal

Object.freeze() makes an object fully immutable (no adding, removing, or editing). Object.seal() prevents adding/removing properties, but existing properties can still be edited.

freeze-seal.js
const config = Object.freeze({ mode: "dark" });
config.mode = "light"; // fails silently

const user = Object.seal({ name: "Aria" });
user.name = "Sam";    // works
user.age = 25;        // ignored
Object.freeze()Object.seal()
No add, remove, or editNo add/remove, but edit is allowed
⚠️ Use freeze for constants/config that should never change; use seal when the shape should stay fixed but values can still update.
13–14. Serializing & Templates
13. JSON.stringify() / JSON.parse()

Convert an object to a JSON string (to send/store it), and back to an object (to read it).

json.js
const str = JSON.stringify(user);
// '{"name":"John","age":25}'

const obj = JSON.parse(str);
// { name: "John", age: 25 }
🔎 Used for API payloads, localStorage, and (as seen in #10) a quick deep-clone trick — though it drops functions, undefined, and dates.
14. Constructor Function

A regular function used with new to create multiple similar objects, acting as a reusable template.

constructor.js
function User(name, age) {
  this.name = name;
  this.age = age;
}
const u1 = new User("John", 25);
💡 new creates an empty object, binds this to it, runs the function body, and returns the object — largely replaced by class syntax today, but still common in older code.
15. Interview Questions
15. Interview Questions (with Answers)
📗 Basic

1. What is an object in JavaScript?
A data structure that stores related data and behavior as key-value pairs. Keys are strings (or symbols) and values can be any type, including functions.

2. How do you create an object?
Most commonly with an object literal { key: value }. Also possible via new Object(), a constructor function with new, or Object.create().

3. Difference between dot notation and bracket notation.
Dot notation (user.name) is shorter but requires a fixed, valid identifier. Bracket notation (user["name"]) accepts a string expression, so it works with dynamic keys, variables, or keys with special characters/spaces.

4. What are object methods?
Functions stored as properties of an object. They define behavior the object can perform, e.g. user.greet().

5. What is this inside an object?
Inside a regular method, this refers to the object the method was called on — it's determined by how the function is called, not where it's defined. Arrow functions don't get their own this; they use the value from their surrounding scope.

📘 Intermediate

1. Difference between Object.freeze() and Object.seal().
freeze() blocks adding, removing, and editing properties — full immutability. seal() blocks adding/removing properties, but existing properties can still be edited.

2. Difference between Spread Operator and Object.assign().
Both perform a shallow copy/merge and behave almost identically. The spread operator ({ ...obj }) is newer, more concise syntax; Object.assign(target, ...sources) mutates and returns the target object, which can be useful (or risky) when you deliberately want to modify an existing object.

3. Difference between shallow copy and deep copy.
A shallow copy (spread, Object.assign()) copies only the top-level properties — nested objects are still shared by reference, so changing a nested value in the copy changes the original too. A deep copy (structuredClone(), or JSON.parse(JSON.stringify())) recursively copies nested objects too, so the copy is fully independent.

4. Difference between Object.keys(), Object.values(), and Object.entries().
Object.keys() returns an array of property names, Object.values() returns an array of property values, and Object.entries() returns an array of [key, value] pairs — all cover only the object's own enumerable properties.

📕 Advanced

1. Difference between Object.create() and object literals.
An object literal {} creates an object whose prototype is automatically Object.prototype. Object.create(proto) lets you explicitly choose the new object's prototype — even null, for an object with no inherited properties at all.

create.js
const animal = { speak() { console.log("..."); } };
const dog = Object.create(animal);
dog.speak(); // inherited from animal

2. Explain object references with an example.
Objects are assigned and passed by reference, not by value — a variable holds a pointer to the object in memory, not the object itself.

reference.js
const obj1 = { name: "John" };
const obj2 = obj1;
obj2.name = "Sam";
console.log(obj1.name); // "Sam" — same object, two names

3. Why does {} === {} return false?
Because === compares objects by reference, not by contents. Each {} creates a brand-new object at a different memory location, so even with identical (empty) properties they aren't the same reference.

comparison.js
{} === {};              // false — different objects
const a = {};
const b = a;
a === b;                // true — same reference

4. How does prototype inheritance work?
Every object has an internal link to a prototype object. When a property isn't found directly on an object, JavaScript looks it up on the prototype, then the prototype's prototype, and so on up the prototype chain, until it's found or the chain ends at null.

prototype.js
function User(name) { this.name = name; }
User.prototype.greet = function() {
  return `Hi, ${this.name}`;
};
const u = new User("John");
u.greet(); // found on User.prototype, not on u itself

5. Explain getters and setters.
Special methods that run automatically when a property is read (get) or written (set), while still looking like a plain property from the outside — useful for computed values or validating/transforming data on write.

getset.js
const user = {
  firstName: "John",
  get greeting() { return `Hello, ${this.firstName}`; },
  set firstName(val) { this._firstName = val.trim(); }
};

6. Explain computed property names.
Wrapping an expression in [] as a key lets you build a property name dynamically from a variable, instead of hardcoding it.

computed.js
const key = "age";
const user = { name: "John", [key]: 25 };
// { name: "John", age: 25 }

7. Explain optional chaining.
?. safely accesses a nested property, returning undefined instead of throwing a TypeError if a part of the chain is null/undefined — avoiding manual checks like user.address && user.address.city.

optional.js
user.address.city;         // throws if address is undefined
user.address?.city;        // safe — returns undefined
user.address?.city ?? "Unknown"; // with a fallback

8. Explain hasOwnProperty() vs in.
"key" in obj checks both the object's own properties and its inherited (prototype chain) properties. obj.hasOwnProperty("key") checks only the object's own properties, ignoring inherited ones.

existence.js
const user = { name: "John" };
"toString" in user;              // true (inherited)
user.hasOwnProperty("toString"); // false (not own)

9. Explain Object.defineProperty().
Defines or modifies a single property with fine-grained control over its behavior — value, writable (can it be changed), enumerable (does it show up in loops/Object.keys()), and configurable (can it be deleted/redefined). It's the low-level API that features like getters/setters and freeze/seal are built on.

defineproperty.js
const user = {};
Object.defineProperty(user, "id", {
  value: 101,
  writable: false,
  enumerable: false
});
user.id;              // 101
Object.keys(user);   // [] — hidden from enumeration
