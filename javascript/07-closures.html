What is a Closure?

Definition

A closure is a function bundled together with its lexical environment. It's a function that remembers the variables from the scope in which it was created, even after that outer function has finished executing.

A closure is the combination of:

  • Function Code
  • Its Lexical Environment (Lexical Scope)

When a function is returned from another function, or passed around and executed later, JavaScript does not discard the variables that function depends on. Instead, it preserves the required lexical environment so the function can keep accessing those variables whenever it's invoked.

Key Points to Remember

  • A closure is Function + Lexical Environment.
  • It remembers variables, not just their values.
  • The variables are referenced, not copied.
  • The preserved lexical environment remains in memory only as long as the closure is reachable.
  • Closures are possible because JavaScript uses lexical scoping.

Why Are Closures Needed?

Normally, when a function finishes execution, its Execution Context is popped off the Call Stack, and its local variables are expected to be cleaned up.

If an inner function still needs those variables, JavaScript keeps them alive in memory instead of destroying them. This preserved lexical environment is exactly what a closure is.

Without closures, a returned function would lose access to its outer variables the moment the outer function completed.

How Closures Work — Step by Step

Example: A Counter That Remembers

closure-counter.js
function outer() {
    let count = 0;

    function inner() {
        count++;
        console.log(count);
    }

    return inner;
}

const counter = outer();

counter(); // 1
counter(); // 2
counter(); // 3

Diagram — What the Engine Does Internally

Step 1–2 — outer() runs, inner() is created

Step 3 — outer() returns inner; its stack frame pops

Step 4–5 — counter() is called, again and again

💡 Key idea: The variable count is not recreated on every call. The closure keeps the exact same reference alive across calls — that's why the counter keeps incrementing instead of resetting.
Important Characteristics

What Makes a Closure Tick

  • A closure remembers its lexical environment, not just the function code.
  • Variables inside a closure are referenced, not copied.
  • If a captured variable changes, the closure sees the updated value — it's a live link.
  • Multiple closures from the same outer function can either share or have separate state, depending on how they're created.
  • Closures continue to exist as long as there's at least one reference to the inner function.
  • Every function in JavaScript automatically forms a closure with the scope it was created in.
  • Closures work because JavaScript uses lexical scoping.

Advantages & Disadvantages

Trade-offs

✅ Advantages
  • Preserve data even after a function has finished executing
  • Enable private variables and data encapsulation
  • Allow stateful functions without global variables
  • Improve code modularity and reusability
  • Form the foundation of many JS patterns and frameworks
❌ Disadvantages
  • Captured variables remain in memory as long as the closure exists
  • Unnecessary closures can increase memory usage
  • Debugging deeply nested closures can get difficult
  • Retaining large objects inside closures can lead to memory leaks
Classic Interview Examples

The Counter Factory — Independent State

counter-factory.js
function createCounter() {
  let count = 0;
  return {
    increment: () => ++count,
    reset: () => (count = 0)
  };
}

const counterA = createCounter();
const counterB = createCounter();

counterA.increment(); counterA.increment();
counterB.increment();

console.log(counterA.increment()); // 3
console.log(counterB.increment()); // 2 — independent closures
Why don't they share state? Each call to createCounter() creates a brand-new execution context, so each returned object closes over its own separate count.

Closure Inside a Loop (Most-Asked) ⭐

loop-var.js
for (var i = 1; i <= 3; i++) {
  setTimeout(() => console.log(i), 1000);
}
// Output: 4, 4, 4 — all callbacks share the same "i"
Why? var is function-scoped, so every callback closes over the exact same variable. After the loop ends, i = 4, so every callback prints 4.
loop-fix.js
// Fix 1: use let — creates a new binding per iteration
for (let j = 1; j <= 3; j++) {
  setTimeout(() => console.log(j), 1000);
}
// 1, 2, 3

// Fix 2 (pre-ES6): wrap in an IIFE to capture the value
for (var k = 1; k <= 3; k++) {
  (function(captured) {
    setTimeout(() => console.log(captured), 1000);
  })(k);
}
// 1, 2, 3
This is the single most-asked closure question in interviews — it tests whether you understand that var is function-scoped, so all iterations share one variable unless you deliberately create a new scope per iteration.

once() — A Function That Runs Only One Time

once.js
function once(fn) {
  let called = false;
  let result;

  return function(...args) {
    if (!called) {
      result = fn(...args);
      called = true;
    }
    return result;
  };
}

const initialize = once(() => console.log("Initializing..."));
initialize(); // "Initializing..."
initialize(); // (nothing — already ran)
The called and result variables persist across calls because the returned function closes over them — that's what makes "run only once" possible without a global flag.
Practice Problems

Private Variable

Question: Create a private variable using closure.

private-variable.js
function createUser(name) {
  let password = "123456";
  return {
    getName() {
      return name;
    },
    checkPassword(pass) {
      return pass === password;
    }
  };
}
const user = createUser("John");
console.log(user.getName());          // John
console.log(user.checkPassword("123456")); // true
console.log(user.password);          // undefined — password is private

Function Factory (Currying-lite)

Question: Create reusable multiplication functions.

function-factory.js
function multiply(x) {
  return function (y) {
    return x * y;
  };
}
const double = multiply(2);
const triple = multiply(3);
console.log(double(5)); // 10
console.log(triple(5)); // 15

Module Pattern

Question: Build a Calculator module that hides its internal state.

calculator-module.js
const Calculator = (function () {
  let result = 0;
  return {
    add(value) {
      result += value;
    },
    subtract(value) {
      result -= value;
    },
    getResult() {
      return result;
    }
  };
})();
Calculator.add(10);
Calculator.add(5);
Calculator.subtract(2);
console.log(Calculator.getResult()); // 13

Guess the Output — Shared Closure

shared-closure.js
function outer() {
  let x = 10;
  return {
    increment() {
      x++;
    },
    print() {
      console.log(x);
    }
  };
}
const obj = outer();
obj.print();     // 10
obj.increment();
obj.print();     // 11
Both methods share the same closure over x — that's how two different methods on the same object can read and update one shared private variable.
