📌 In short: Every DOM event travels in three phases — capturing (top → down), target, then bubbling (bottom → up). addEventListener listens on the bubbling phase by default; pass true (or React's *Capture handlers) to listen during capturing instead. stopPropagation() halts that travel, preventDefault() cancels the browser's built-in action — they're independent. 🔑 Key Terms at a Glance
🌐
DOM (Document Object Model): A tree-like representation of an HTML document where each HTML element becomes a node that JavaScript can access, modify, and listen for events on.
📡
Event Propagation: The complete path an event follows through the DOM. It consists of three phases: capturing → target → bubbling.
⬆️
Event Bubbling: The default propagation phase where an event starts at the target element and then moves upward through its parent elements to the document.
⬇️
Event Capturing: The first propagation phase (enabled explicitly) where an event travels from the document down through parent elements until it reaches the target.
🪣
Event Delegation: A technique where a single event listener is attached to a parent element to handle events for its child elements using event.target and event bubbling.
Event Basics

Event, Listener & Event Object

An event is a signal that something happened in the browser — a click, a keypress, a page load. An event listener is a function that "listens" for a specific event on an element and runs when it occurs.
listener.js
button.addEventListener("click", () => console.log("Clicked!"));

Event Object

When an event fires, the browser automatically passes an event object to the handler function, containing details about the event.

event-object.js
button.addEventListener("click", function(e) {
  console.log(e.type);          // "click"
  console.log(e.target);        // the exact element clicked
  console.log(e.currentTarget); // element the listener is attached to
  console.log(e.clientX, e.clientY); // mouse coordinates
  console.log(e.timeStamp);     // when it happened
});
PropertyMeaning
targetThe actual element that triggered the event
currentTargetThe element the listener is bound to

key / codeFor keyboard events
preventDefault()Method to stop default behavior
stopPropagation()Method to stop event flow

Event Propagation ⭐

The Three-Phase Journey

Deep Dive
Event propagation describes how an event travels through the DOM tree when it occurs on a nested element. It happens in three phases: capturing down, target, then bubbling back up.

Setup used throughout this guide — three nested divs:

nested-divs.html
<div id="grandparent">
  Grandparent
  <div id="parent">
    Parent
    <div id="child">
      Child (click here)
    </div>
  </div>
</div>

By default, addEventListener listens during the bubbling phase. You opt into capturing with a third argument:

phase-toggle.js
element.addEventListener("click", handler, false); // bubbling (default)
element.addEventListener("click", handler, true);  // capturing
📌 This dual-phase system exists so developers can intercept an event either on the way down (capturing — "gatekeeping" before children react) or on the way up (bubbling — powers event delegation).
Event Bubbling ⭐

Definition & Vanilla JS Example

Deep Dive
Bubbling is the phase where, after an event reaches its target, it travels back upward through every ancestor — like a fizzy bubble rising to the surface. It's the default behavior of addEventListener (third argument false or omitted).
bubbling.js
const grandparent = document.getElementById("grandparent");
const parent = document.getElementById("parent");
const child = document.getElementById("child");

grandparent.addEventListener("click", () => console.log("1. Grandparent (bubble)"));
parent.addEventListener("click", () => console.log("2. Parent (bubble)"));
child.addEventListener("click", () => console.log("3. Child (bubble)"));

// Click on #child → console output:
// 3. Child (bubble)
// 2. Parent (bubble)
// 1. Grandparent (bubble)

Innermost fires first, then it bubbles outward level by level, until it reaches document/window.

React — onClick = bubbling

React's normal onClick maps to the bubbling phase (React attaches listeners at the root and simulates bubbling through its synthetic event system).

Bubbling.jsx
function App() {
  return (
    <div onClick={() => console.log("1. Grandparent (bubble)")}>
      Grandparent
      <div onClick={() => console.log("2. Parent (bubble)")}>
        Parent
        <div onClick={() => console.log("3. Child (bubble)")}>
          Child (click me)
        </div>
      </div>
    </div>
  );
}
// Same order as vanilla JS — onClick behaves like a bubbling addEventListener
Mental model: think of the DOM as a stack of transparent sheets. Clicking punches through the topmost (innermost) sheet first. The "impact" then ripples outward through every sheet wrapped around it.

Unwanted Bubbling & What Doesn't Bubble

Real consequence of unwanted bubbling — clicking inside a modal accidentally closes it:

unwanted-bubbling.js
document.getElementById("modal-overlay").addEventListener("click", () => {
  console.log("Overlay clicked → closing modal");
});

document.getElementById("modal-btn").addEventListener("click", () => {
  console.log("Button inside modal clicked");
});

// Click the button → BOTH logs fire, because the click bubbles
// from #modal-btn → #modal-box → #modal-overlay
// This accidentally closes the modal even though you clicked INSIDE it!
⚠️ This is exactly the problem stopPropagation() is designed to fix.

Events that do NOT bubble

focus, blur, mouseenter, mouseleave, load (on some elements) don't bubble. Use their bubbling equivalents when needed: focusin, focusout, mouseover, mouseout.

✅ Why bubbling matters: it's the foundation of event delegation — a single listener on a parent can catch events from all its children (present or future) simply because those events bubble up to it.
Event Capturing ⭐

Definition & Vanilla JS Example

Deep Dive
Capturing (also called "trickling") is the first phase of propagation — the event starts at window and travels downward, from the outermost ancestor toward the target, before the target phase even happens. It's the opposite direction of bubbling: "outside-in" instead of "inside-out."
capturing.js
// third argument = true → capturing mode
grandparent.addEventListener("click", () => console.log("1. Grandparent (capture)"), true);
parent.addEventListener("click", () => console.log("2. Parent (capture)"), true);
child.addEventListener("click", () => console.log("3. Child (capture)"), true);

// Click on #child → console output:
// 1. Grandparent (capture)
// 2. Parent (capture)
// 3. Child (capture)

Reversed order compared to bubbling — outermost fires first, then it drills down toward the actual target.

React — onClickCapture = capturing

React exposes the capturing phase via the special Capture suffix: onClickCapture instead of onClick.

Capturing.jsx
function App() {
  return (
    <div onClickCapture={() => console.log("1. Grandparent (capture)")}>
      Grandparent
      <div onClickCapture={() => console.log("2. Parent (capture)")}>
        Parent
        <button onClickCapture={() => console.log("3. Child (capture)")}>
          Click
        </button>
      </div>
    </div>
  );
}
// Click the button → fires top-down, exactly mirroring native capturing
📌 Why capturing exists: before an event ever reaches the element you clicked, the browser first has to walk the DOM tree from the root down to that element — that's just how it locates the target. The spec lets you "tap into" the event during that downward walk, before the target or any bubbling handlers ever run. This gives an ancestor the power to inspect or intercept an event before any descendant — including the target itself — gets a chance to react.

Combined: Capturing + Bubbling Together

combined.js
grandparent.addEventListener("click", () => console.log("Grandparent - CAPTURE"), true);
parent.addEventListener("click", () => console.log("Parent - CAPTURE"), true);
child.addEventListener("click", () => console.log("Child - CAPTURE"), true);

grandparent.addEventListener("click", () => console.log("Grandparent - BUBBLE"), false);
parent.addEventListener("click", () => console.log("Parent - BUBBLE"), false);
child.addEventListener("click", () => console.log("Child - BUBBLE"), false);

React produces the identical pattern using onClickCapture (down) and onClick (up) on the same elements — the target element fires twice: once ending capture, once starting bubble.

Practical use case: a "gatekeeper" ancestor

gatekeeper.js
document.getElementById("form-wrapper").addEventListener("click", (e) => {
  if (e.target.closest("[data-disabled='true']")) {
    e.stopPropagation(); // stop it during capture — button's own listener never runs
    console.log("Blocked: section is disabled");
  }
}, true); // capturing mode — runs BEFORE the button's bubbling listener

document.getElementById("submit-btn").addEventListener("click", () => {
  console.log("Form submitted!"); // never runs, because capture stopped it first
});
✅ Because the wrapper's listener runs in the capturing phase, it gets first refusal — it can stop the click dead before it even reaches the button, let alone bubble back up. Bubbling alone could never do this.

stopPropagation()

Halting the Event's Journey

Medium
Stops the event from continuing its journey through the DOM (either capturing or bubbling), without affecting sibling listeners on the same element.
stop-propagation.js
parent.addEventListener("click", (e) => {
  e.stopPropagation(); // stops here — never reaches grandparent
  console.log("Parent clicked — won't bubble further");
});

grandparent.addEventListener("click", () => {
  console.log("Grandparent clicked"); // never runs if parent stops it
});

Use case: a dropdown menu inside a page — clicking the menu shouldn't trigger a "click outside to close" listener on document.

dropdown-example.js
menu.addEventListener("click", (e) => e.stopPropagation());
document.addEventListener("click", () => closeMenu());
stopImmediatePropagation()

Stopping Sibling Listeners Too

Medium
Like stopPropagation(), but also prevents other listeners on the same element from running — not just ancestors/descendants.
stop-immediate.js
child.addEventListener("click", (e) => {
  console.log("First listener");
  e.stopImmediatePropagation();
});

child.addEventListener("click", () => {
  console.log("Second listener"); // never runs!
});

parent.addEventListener("click", () => {
  console.log("Parent"); // also never runs
});

// Output: "First listener" only
MethodStops propagation to ancestors?Stops other listeners on same element?
stopPropagation()✅❌
stopImmediatePropagation()✅✅
preventDefault()

Cancelling the Browser's Default Action

Medium
Prevents the browser's default behavior for that event — it does not stop propagation.
prevent-default.js
// Stop a link from navigating
link.addEventListener("click", (e) => {
  e.preventDefault();
  console.log("Navigation blocked");
});

// Stop a form from submitting/reloading the page
form.addEventListener("submit", (e) => {
  e.preventDefault();
  console.log("Form submission intercepted");
});

// Stop right-click context menu
document.addEventListener("contextmenu", (e) => e.preventDefault());
📌 Key distinction:
  • preventDefault() → cancels the browser's built-in action (navigating, submitting, checking a checkbox).
  • stopPropagation() → cancels the event's travel through the DOM.
They're independent — call either, both, or neither.
Event Delegation ⭐

The Problem It Solves

Deep Dive
A pattern that leverages event bubbling: instead of attaching a listener to every individual child, attach one listener to a common parent, and use event.target to figure out which child was actually interacted with.
list.html
<ul id="list">
  <li>Item 1</li>
  <li>Item 2</li>
  <li>Item 3</li>
</ul>

Without delegation (inefficient, breaks for dynamic items)

no-delegation.js
document.querySelectorAll("#list li").forEach(li => {
  li.addEventListener("click", () => console.log(li.textContent));
});
// New 
  •  added later? It has NO listener — must re-bind manually.

    • With delegation (one listener, handles all current AND future children)

    delegation.js
    document.getElementById("list").addEventListener("click", (e) => {
  if (e.target.tagName === "LI") {
    console.log("Clicked:", e.target.textContent);
  }
});

// Add a new item dynamically — it still works, no re-binding needed!
const newItem = document.createElement("li");
newItem.textContent = "Item 4";
document.getElementById("list").appendChild(newItem);

    Realistic Example — Dynamic Todo List

    todos.html
    <ul id="todos">
  <li>Buy milk <button class="delete">X</button></li>
  <li>Walk dog <button class="delete">X</button></li>
</ul>
    todos-delegation.js
    document.getElementById("todos").addEventListener("click", (e) => {
  if (e.target.classList.contains("delete")) {
    e.target.closest("li").remove(); // remove the parent 
  • 
  }
});

    • One listener handles deletion for every todo item — present or future — no matter how many get added.

    React version of delegation

    TodoList.jsx
    function TodoList() {
  const [todos, setTodos] = React.useState(["Buy milk", "Walk dog"]);

  const handleClick = (e) => {
    if (e.target.dataset.action === "delete") {
      const index = Number(e.target.dataset.index);
      setTodos(todos.filter((_, i) => i !== index));
    }
  };

  return (
    <ul onClick={handleClick}>
      {todos.map((todo, i) => (
        <li key={i}>
          {todo} <button data-action="delete" data-index={i}>X</button>
        </li>
      ))}
    </ul>
  );
}

    One onClick on the <ul> handles deletes for every <li>, even ones added later — same delegation principle as vanilla JS, riding on React's synthetic bubbling.

    Why It's Powerful, and Its Caveats

    Why it's powerful

    • Performance — one listener instead of hundreds/thousands (huge win for big lists/tables).
    • Works with dynamic content — no re-attaching listeners when elements are added/removed.
    • Less memory usage — fewer listener objects to track.
    • Simpler code — centralized logic in one place.

    Caveats

    • Relies on bubbling — doesn't work for non-bubbling events (focus, blur) unless you use their bubbling equivalents (focusin, focusout).
    • Must carefully check e.target (often with .closest()) since it could be a deeply nested child (like an icon inside a button inside a list item).
    safer-delegation.js
    // Safer pattern using closest() to handle nested elements
container.addEventListener("click", (e) => {
  const btn = e.target.closest(".delete-btn");
  if (btn) {
    btn.closest("li").remove();
  }
});
    SyntheticEvent
    🧬

    What is SyntheticEvent?

    React
    A SyntheticEvent is React's version of the browser's event object. It wraps the native DOM event so your event-handling code works consistently across different browsers.
    📌 What "wrapper" means: React takes the original browser event, adds its own features, and gives you a new event object with a consistent API — so e inside your handler isn't the raw browser event, it's React's version of it.
    SyntheticEvent.jsx
    const handleClick = (e) => {
  console.log(e.type);          // click
  console.log(e.target);        // clicked element
  console.log(e.currentTarget); // element with onClick
  console.log(e.nativeEvent);   // original browser event
};

function Button() {
  return <button onClick={handleClick}>Click me</button>;
}

    type, target, and currentTarget are what you'll reach for day to day. nativeEvent is there for the rare case you need a property React doesn't wrap.

    📌 Note: in React 17 and earlier, SyntheticEvents were pooled and reset immediately after the handler ran, so accessing e.target inside a setTimeout or an async callback would silently return null unless you called e.persist() first. React 17 removed event pooling entirely, so on modern React the event object stays valid and persist() is a safe no-op.
    ❓

    Why React Uses SyntheticEvent

    React introduced this wrapper layer to solve real problems that come from working with the native DOM event system directly:

    • Cross-browser consistency — every browser behaves the same.
    • Event delegation — React uses a small number of listeners instead of attaching one to every element.
    • Better performance — less memory usage and fewer DOM listeners.
    • Integration with React — React can efficiently schedule and batch state updates.
    Native DOM EventReact SyntheticEvent
    Listener attachmentOne per elementDelegated near the root, one shared listener
    Cross-browser behaviorCan vary by browserNormalized to one consistent API
    Access to real event—e.nativeEvent
    Works with state batchingNoYes
    ✅ Bottom line: SyntheticEvent lets you write one handler that behaves the same everywhere, without sacrificing performance or access to the underlying native event when you truly need it.
    DOM Tree
    🌳

    DOM Tree

    The DOM (Document Object Model) is a tree-shaped representation of an HTML page that JavaScript can read and manipulate.

    Every tag becomes an element node, every piece of text becomes a text node, and the whole tree starts from a single root: document. Nodes are connected as parents, children, and siblings — exactly like a family tree.

    dom-tree.html
    <!-- This HTML... -->
<div id="app">
  <h1>Hello</h1>
  <p>World</p>
</div>
    document └── html └── body └── div#app ├── h1 → "Hello" └── p → "World"
    📌 Note: document is the entry point to the entire tree — every selection or traversal method you use ultimately starts from it.
    Selecting Elements
    🔍

    Selecting Elements

    Before you can change anything on a page, you need to grab a reference to it. Modern JS mostly relies on querySelector/querySelectorAll (CSS-selector syntax), while the older methods are still common in legacy code.

    selecting.js
    document.getElementById("app");            // single element by id
document.getElementsByClassName("card");    // live HTMLCollection
document.getElementsByTagName("li");        // live HTMLCollection
document.querySelector(".card h4");         // first match, any CSS selector
document.querySelectorAll(".card");          // static NodeList of ALL matches
    💡 Tip: getElementsBy* methods return a live collection (auto-updates as the DOM changes); querySelectorAll returns a static snapshot taken at call time.
    Traversing the DOM
    🧭

    Traversing the DOM

    Once you have one element, you often need to move to related elements — its parent, children, or siblings — without running another query.

    traversing.js
    const el = document.querySelector("#app");

el.parentElement;             // closest parent (Element only)
el.children;                  // HTMLCollection of child elements
el.childNodes;                // NodeList, includes text/comment nodes too
el.firstElementChild;         // first child element
el.lastElementChild;          // last child element
el.nextElementSibling;        // next sibling element
el.previousElementSibling;    // previous sibling element
    📌 Note: Prefer the *Element* versions (firstElementChild, nextElementSibling...) over the plain versions (firstChild, nextSibling) — the plain ones also match whitespace/text nodes, which trips people up.
    Creating Elements
    ➕

    Creating Elements

    New elements are built with document.createElement() and then attached somewhere in the tree with appendChild, append, prepend, or insertBefore.

    creating.js
    const li = document.createElement("li");
li.textContent = "New item";
li.classList.add("todo-item");

const list = document.querySelector("#todo-list");
list.appendChild(li);                 // adds at the end
list.prepend(li);                    // adds at the start
list.insertBefore(li, list.firstElementChild); // insert at a specific spot
list.insertAdjacentHTML("beforeend", "<li>Quick item</li>");
    ⚠️ Warning: insertAdjacentHTML (and setting innerHTML) with untrusted input opens the door to XSS — never inject raw user input this way.
    Removing Elements
    🗑️

    Removing Elements

    Elements can remove themselves directly with .remove(), or a parent can remove a specific child with removeChild().

    removing.js
    const item = document.querySelector(".todo-item");
item.remove();                        // modern, simplest way

const list = document.querySelector("#todo-list");
list.removeChild(list.firstElementChild); // older, needs the parent
    💡 Tip: Avoid list.innerHTML = "" to "remove everything" on large trees if you've attached listeners inside — it silently discards them without cleanup and can cause subtle memory issues in long-lived apps.
    Updating Elements
    ✏️

    Updating Elements

    You can update text, HTML, attributes, classes, or inline styles of an existing element without recreating it.

    updating.js
    el.textContent = "Plain text only";        // safe, no HTML parsing
el.innerHTML = "<b>Bold</b>";             // parses HTML, XSS risk with user input

el.setAttribute("data-id", "42");
el.getAttribute("data-id");              // "42"
el.removeAttribute("data-id");

el.classList.add("active");
el.classList.remove("active");
el.classList.toggle("active");
el.classList.contains("active");      // true/false

el.style.color = "crimson";
