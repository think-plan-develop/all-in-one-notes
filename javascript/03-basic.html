1–4. Ways to Write a Function
1. Function Declaration Hoisted

A named function defined with the function keyword as its own statement. It's hoisted — usable even before its line runs.

declaration.js
function greet(name) {
  return `Hello, ${name}!`;
}
greet("Aria"); // "Hello, Aria!"

Why use it

Gives a clear, reusable name and hoisting flexibility.

When to use it

Main/reusable functions you want available anywhere in the file.

✅ Benefit: Hoisting flexibility + self-documenting name.
2. Function Expression

A function assigned to a variable, treated like any other value. Not hoisted the same way as declarations.

expression.js
const square = function(n) {
  return n * n;
};
square(5); // 25

Why use it

Lets a function be conditionally assigned or reassigned like a variable.

When to use it

When a function should only exist after a condition, or be a dynamic object property.

🔎 Benefit: More control over timing and scope than a hoisted declaration.
3. Arrow Functions ES6

Short syntax using =>. Arrow functions don't have their own this, arguments, or super.

arrow.js
const add = (a, b) => a + b;
const sayHi = () => console.log("Hi!");

Why use it

Shorter syntax and predictable this — inherits it from the outer scope.

When to use it

Short callbacks and array methods (map/filter/reduce).

⚠️ Benefit: Less code, no this confusion — but avoid as object methods.
4. Anonymous Functions Unique case

A function with no name, typically used once, inline, where naming it adds no value.

anonymous.js
setTimeout(function() {
  console.log("runs after 1s");
}, 1000);

// as array callback
[1,2,3].forEach(function(n) {
  console.log(n * 2);
});

Why use it

Avoids naming clutter for logic that's only used once, right where it's written.

When to use it

Event handlers, setTimeout/setInterval, one-off array callbacks.

💡 Benefit: Cleaner, throwaway code — no unused function name lingering in scope.
5–8. Patterns & Roles
5. IIFE Unique case

An Immediately Invoked Function Expression — runs the moment it's defined, by wrapping it in parentheses and calling it right away.

iife.js
(function() {
  const secret = "hidden";
  console.log("IIFE ran instantly!");
})();

// arrow IIFE variant
(() => {
  console.log("arrow IIFE!");
})();

Why use it

Keeps variables private to that block so they don't leak into or clash with the global scope.

When to use it

One-time setup code, initializing a widget/library, isolating variables in non-module scripts.

✅ Benefit: Zero global namespace pollution — common before ES6 modules, still handy today.
6. Callback Functions Unique case

A function passed as an argument into another function, to be executed later — after an async task or event finishes.

callback.js
function fetchData(callback) {
  setTimeout(() => callback("data loaded"), 500);
}
fetchData((result) => console.log(result));

// event listener callback
button.addEventListener("click", () => {
  console.log("clicked!");
});

Why use it

Lets code run only after another task completes, without blocking the rest of the program.

When to use it

Async work: API calls, timers, file reads, event listeners (click, load, etc).

🔎 Benefit: Non-blocking async code — the foundation of JS before Promises/async-await.
7. Higher-Order Functions HOF

A function that either takes a function as an argument or returns a function. Array methods like map/filter/reduce are classic HOFs.

hof.js
const nums = [1, 2, 3];
const doubled = nums.map(n => n * 2);
// doubled = [2, 4, 6]

Why use it

Reuses generic logic (looping, transforming) while plugging in custom behavior.

When to use it

Transforming/filtering data, or building utilities like debounce or compose.

💡 Benefit: Cleaner, declarative, reusable code — possible because functions are first-class in JS.
8. Pure Functions

Always returns the same output for the same input and causes no side effects (no touching outside state).

pure.js
function sum(a, b) {
  return a + b; // pure — no external state touched
}

Why use it

Predictable behavior makes bugs easier to trace and functions easy to test.

When to use it

Business logic, calculations, data transforms — e.g. Redux reducers.

Pros
  • Predictable & testable
  • Safe for concurrency
Cons
  • Can't do I/O or logging directly
9–11. Function Flexibility
9. First-Class Functions

Functions are treated as values — stored in variables, passed as arguments, returned from other functions, or stored in arrays/objects.

firstclass.js
function makeMultiplier(x) {
  return (n) => n * x; // returns a function
}
const triple = makeMultiplier(3);

Why use it

Unlocks passing behavior around, not just data.

When to use it

Storing a function in a variable/array/object, passing it as an argument, or returning it.

✅ Benefit: The core property that makes callbacks, HOFs, and closures possible in JS.
10. Rest Parameters ...args

Collects all remaining arguments into a real array using ... before the last parameter.

rest.js
function sumAll(...numbers) {
  return numbers.reduce((a,b) => a+b, 0);
}
sumAll(1, 2, 3, 4); // 10

Why use it

Accepts an unknown number of arguments without listing each one.

When to use it

Sum-style utilities, logging functions, or APIs accepting variable input counts.

🔎 Benefit: Cleaner signatures + a real array (unlike old arguments).
11. Default Parameters

Lets a parameter fall back to a default value when no argument (or undefined) is passed.

default.js
function greet(name = "Guest") {
  return `Welcome, ${name}!`;
}
greet(); // "Welcome, Guest!"

Why use it

Prevents undefined errors and skips manual fallback checks in the body.

When to use it

Optional config values, function parameters with a sensible fallback, optional flags.

⭐ Benefit: Safer, shorter code. Defaults can reference earlier params, e.g. f(a, b = a * 2).
