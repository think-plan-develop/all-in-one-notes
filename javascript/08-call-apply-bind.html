call(), apply(), and bind() in JavaScript

These three methods are available on every function because every function inherits them from Function.prototype. Their main purpose is to control what this refers to when a function is executed.

Why Needed? call() apply() bind() Differences When to Use Output Questions Interview Summary
Quick Overview & Syntax
📞
call(): Executes immediately and passes arguments one by one.
fn.call(thisArg, arg1, arg2, ...)
📋
apply(): Executes immediately and passes arguments as an array.
fn.apply(thisArg, [arg1, arg2])
🔗
bind(): Returns a new function with this (and optionally some arguments) already fixed for later execution.
const newFn = fn.bind(thisArg, arg1, arg2)
🎯
Shared Purpose: All three control what this refers to when a function executes.
🤔 Why Do We Need Them?
🎯 Controlling this

Normally, this depends on how a function is called, not where it is written.

app.js
const user = {
    name: "Shivam",
    greet() {
        console.log(this.name);
    }
};

user.greet(); // Shivam

But what if we want to use greet() for another object? That's where call, apply, and bind are used.

1️⃣ call()
📞 call()
call() immediately invokes the function and lets you specify what this should be.

Syntax

function.call(thisArg, arg1, arg2, arg3...)

Example

app.js
const person1 = {
    name: "Shivam"
};

const person2 = {
    name: "Rahul"
};

function greet(city, country) {
    console.log(this.name, city, country);
}

greet.call(person1, "Delhi", "India");

greet.call(person2, "Mumbai", "India");

Output

console
Shivam Delhi India

Rahul Mumbai India

Behind the Scene

Normally:

this = window (or undefined in strict mode)

Using:

call(person1)

temporarily changes:

this = person1
This only applies for that single function execution.

Real Project Example

Suppose a reusable logging function is shared across modules.

logger.js
function logAction(action) {
    console.log(`${this.username} performed ${action}`);
}

const admin = {
    username: "Admin"
};

const customer = {
    username: "Customer"
};

logAction.call(admin, "Delete User");
logAction.call(customer, "Place Order");
💡 Instead of duplicating the function for every object, the same function is reused.
2️⃣ apply()
📋 apply()
apply() is almost identical to call(). The only difference is arguments are passed as an array.

Syntax

function.apply(thisArg, [arg1, arg2])

Example

app.js
const person = {
    name: "Shivam"
};

function greet(city, country) {
    console.log(this.name, city, country);
}

greet.apply(person, ["Delhi", "India"]);

Output

console
Shivam Delhi India

Why apply()?

Useful when arguments already exist in an array.

app.js
const numbers = [10, 50, 30, 90];

console.log(Math.max.apply(null, numbers));

Output

console
90
Today, this is usually written as: Math.max(...numbers)

Real Project Example

Suppose an API returns filter values as an array.

search.js
const filters = ["Laptop", "Electronics"];

searchProducts.apply(productService, filters);
💡 Instead of extracting each array element manually, apply() forwards the array as function arguments.
3️⃣ bind()
🔗 bind()
bind() does not execute the function immediately. It returns a new function with this permanently bound.

Syntax

const newFunction = function.bind(thisArg, arg1, arg2);

Example

app.js
const person = {
    name: "Shivam"
};

function greet(city) {
    console.log(this.name, city);
}

const fn = greet.bind(person);

fn("Delhi");

Output

console
Shivam Delhi
Notice bind() returns a function. Nothing happens until fn() is called.

Real Project Example

In React class components (and in plain JavaScript event handling), methods often lose their this context when passed as callbacks.

Dashboard.js
class Dashboard {

    constructor() {
        this.name = "Dashboard";

        this.handleClick = this.handleClick.bind(this);
    }

    handleClick() {
        console.log(this.name);
    }

}
⚠️ Without bind(), this inside handleClick could refer to the button or be undefined (depending on strict mode). In modern React functional components this issue is uncommon because arrow functions capture the surrounding this.
📊 Difference Between call(), apply(), and bind()
📋 Comparison Table
Feature call() apply() bind()
Executes immediately ✅ Yes ✅ Yes ❌ No
Returns new function ❌ No ❌ No ✅ Yes
Arguments Comma separated Array Comma separated (pre-filled if desired)
Changes this ✅ ✅ ✅ (permanently for the returned function)
🧭 When to Use Which?
🗂️ Choosing the Right Method

📞 Use call()

Borrow a method from another object • Invoke a function immediately with a different this • Pass arguments individually

Example: Shared validation function, shared logger, utility methods.

📋 Use apply()

Same as call(), but your arguments are already in an array

Example: API returns array values, dynamic argument lists.

🔗 Use bind()

Create a callback that always uses the same this • Event handlers • Delayed execution (setTimeout, promises, callbacks) • Passing object methods as callbacks

🎤 Interview Summary
💬 Quick Interview Response
call() → Executes immediately and passes arguments one by one.

apply() → Executes immediately and passes arguments as an array.

bind() → Returns a new function with this (and optionally some arguments) already fixed for later execution.
💡 In modern JavaScript, call() and bind() are encountered more frequently than apply(), since the spread operator (...) has replaced many traditional apply() use cases.
