The 'this' Keyword

One of JavaScript's trickiest concepts — what this refers to depends entirely on how a function is called, not where it's written.

Global Context Object Method Function Context Arrow Function Constructor Function Event Listener call() apply() bind() Output Questions Summary Table
Definition Start Here

The this keyword refers to the object that is executing the current function.

The value of this is not fixed. It depends on how a function is called, not where it is defined (except for arrow functions).

Interview Definition: this is a special keyword that refers to the current execution context (the object that invokes the function).
The golden rule: this is determined by how a function is called (its "call site"), not by where the function is defined. The one exception is arrow functions, which inherit this from their surrounding scope.
1. Global Context
this in the Global Scope Foundation

Outside of any function, this refers to the global object — window in browsers, globalThis everywhere. Inside a function called plainly (not as a method), it behaves the same way in non-strict mode.

global.js
console.log(this); // window (in browsers, non-strict mode)

function show() {
  console.log(this);
}
show(); // window (non-strict) — called with no owning object

"use strict";
function showStrict() {
  console.log(this);
}
showStrict(); // undefined — strict mode doesn't default to global
Strict mode changes this: In strict mode, a plain function call has this === undefined instead of falling back to the global object — one of the safety improvements strict mode provides.
2. Object Method
this Inside a Method

When a function is called as a method — object.method() — this refers to the object before the dot.

object-method.js
const user = {
  name: "Alice",
  greet() {
    console.log(`Hi, I'm ${this.name}`);
  }
};

user.greet(); // "Hi, I'm Alice" — this = user
Losing this: If you extract the method and call it separately, it loses its object context.
lost-context.js
const greetFn = user.greet;
greetFn(); // ❌ "Hi, I'm undefined" — this is no longer user
Tip: This is exactly the kind of problem bind(), call(), and apply() (covered below) exist to solve.
3. Function Context
this in a Regular Function Call

A regular (non-arrow) function's this depends entirely on how it's invoked, not where it's defined.

Call PatternValue of this
fn()Global object (non-strict) or undefined (strict)
obj.fn()obj

Arrow functionInherited from the enclosing scope, ignores call pattern
function-context.js
function whoAmI() {
  console.log(this.name);
}

const teamA = { name: "Team A", whoAmI };
const teamB = { name: "Team B", whoAmI };

teamA.whoAmI(); // "Team A"
teamB.whoAmI(); // "Team B" — same function, different this
Note: The same function reused on different objects gets a different this each time — it's the call site that decides, not the function definition.
4. Arrow Function
this in Arrow Functions Special Case

Arrow functions don't have their own this. Instead they capture this lexically — from the scope where they were defined, not where they're called.

arrow.js
const user = {
  name: "Alice",
  greet: () => {
    console.log(this.name); // ❌ undefined — this is NOT user here
  }
};
user.greet(); // arrow function ignores the call site
Where arrow functions shine: Inside a regular method, an arrow function used as a callback inherits the method's this — solving a very common bug.
arrow-fix.js
const timer = {
  seconds: 0,
  start() {
    setInterval(() => {
      this.seconds++; // ✅ this = timer, inherited from start()
      console.log(this.seconds);
    }, 1000);
  }
};
timer.start();
❌ Avoid arrow functions for
  • Object methods (greet: () => {})
  • Constructor functions
  • Event handlers needing the element as this
  • Prototype methods
✅ Great for arrow functions
  • Callbacks inside methods (setTimeout, array methods)
  • Preserving outer this in nested functions
  • Short, non-method utility functions
5. Constructor Function
this with new

When a function is called with new, JavaScript creates a brand-new empty object and sets this to point at it inside the function.

constructor.js
function Person(name, age) {
  this.name = name;
  this.age = age;
}

const p1 = new Person("Sam", 28);
console.log(p1.name); // "Sam" — this pointed at the new object
StepWhat new does
1Creates a brand-new empty object
2Sets that object's prototype to the constructor's prototype
3Binds this inside the function to the new object
4Returns the new object automatically (unless the function explicitly returns another object)
Forgetting new: Calling Person("Sam", 28) without new runs it as a plain function — this becomes the global object (or undefined in strict mode), silently corrupting globals instead of creating an object.
6. Event Listener
this in DOM Event Handlers

In a regular function passed to addEventListener, this refers to the DOM element the listener is attached to.

event-listener.js
button.addEventListener("click", function() {
  console.log(this); // the button element
  this.classList.toggle("active");
});

button.addEventListener("click", () => {
  console.log(this); // ❌ NOT the button — inherited from outer scope
});
Note: Use a regular function when you need this to be the clicked element. Use an arrow function only if you deliberately want the surrounding scope's this instead.
7. call()
Explicitly Setting this with call()

call() invokes a function immediately, letting you specify what this should be, with arguments passed individually.

call.js
function introduce(city, country) {
  console.log(`${this.name} from ${city}, ${country}`);
}

const person = { name: "Maya" };

introduce.call(person, "Mumbai", "India");
// "Maya from Mumbai, India" — this = person, args passed one by one
Tip: Use call() when you already have your arguments as separate values, not as a list.
8. apply()
Explicitly Setting this with apply()

apply() works exactly like call(), except arguments are passed as a single array instead of individually.

apply.js
function introduce(city, country) {
  console.log(`${this.name} from ${city}, ${country}`);
}

const person = { name: "Maya" };

introduce.apply(person, ["Mumbai", "India"]);
// "Maya from Mumbai, India" — same result, args as an array

// Classic use case: finding the max of an array
const nums = [3, 7, 2, 9];
Math.max.apply(null, nums); // 9
Tip: With modern spread syntax, Math.max(...nums) replaces most classic apply() use cases — but apply() is still common in older codebases and interview questions.
9. bind()
Permanently Binding this with bind()

Unlike call()/apply(), bind() doesn't call the function immediately. It returns a new function with this permanently locked to the value you provide.

bind.js
const user = {
  name: "Alice",
  greet() {
    console.log(`Hi, I'm ${this.name}`);
  }
};

const greetFn = user.greet.bind(user); // locks this = user
greetFn(); // ✅ "Hi, I'm Alice" — works even detached from user

setTimeout(greetFn, 1000); // ✅ still "Hi, I'm Alice" after 1s
MethodCalls function?ArgumentsReturns
call()ImmediatelyIndividually: fn.call(obj, a, b)Function's return value
apply()ImmediatelyAs an array: fn.apply(obj, [a, b])Function's return value
bind()Not immediatelyIndividually, can be partialA new bound function
Common use case: Binding class methods in a constructor so they keep the right this when passed as callbacks — e.g. this.handleClick = this.handleClick.bind(this);
10. Most Asked Output Questions
Question 1 ⭐⭐⭐⭐⭐
output-q1.js
const person = {
    name: "John",
    greet() {
        console.log(this.name);
    }
};
const fn = person.greet;
fn();
Output: undefined

Why?

StepWhat happens
1const fn = person.greet; — copies the function, not the object
2fn() — called with no object before the dot
3No owning object at the call site
4this = undefined (strict mode) — so this.name throws or logs undefined
Question 2 ⭐⭐⭐⭐⭐
output-q2.js
const person = {
    name: "John",
    greet() {
        return function () {
            console.log(this.name);
        };
    }
};
person.greet()();
Output: undefined

The returned regular function is called without an object before it, so this is not person — it falls back to the global object or undefined in strict mode.

Fix with Arrow Function

output-q2-fix.js
const person = {
    name: "John",
    greet() {
        return () => {
            console.log(this.name);
        };
    }
};
person.greet()();
Output: John — the arrow function inherits this from greet(), where this = person.
