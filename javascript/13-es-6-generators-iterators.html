Definition

What are Iterables, Iterators & Generators?

An iterable is an object whose elements can be accessed one at a time, because it implements Symbol.iterator. An iterator is the object that method produces — it has a next() that returns each value in turn. A generator is a special function that builds that iterator for you automatically.
📝 Interview Definition: Iterables and iterators together form JavaScript's Iterator Protocol — the mechanism behind for...of, the spread operator, destructuring, and Array.from(). Generators are the easiest way to implement that protocol yourself.
What are Iterables?

Objects Whose Elements Can Be Accessed One at a Time

In JavaScript, an object is iterable if it implements the Symbol.iterator method. An iterable can be used with:

  • for...of
  • Spread operator (...)
  • Destructuring
  • Array.from()

Built-in Iterables

  • Array
  • String
  • Map
  • Set
  • TypedArray
  • NodeList (Browser)
iterable-basic.js
const arr = [10, 20, 30];

for (const value of arr) {
    console.log(value);
}

// Output:
// 10
// 20
// 30
💡 Tip: Plain objects {} are not iterable by default — that's exactly why for...of throws on a plain object but works fine on an array.
What is an Iterator?

An Object That Returns One Value at a Time

An iterator is an object that returns one value at a time from an iterable. It follows the Iterator Protocol, meaning it has a next() method.

Each call to next() returns an object:

next-shape.js
{
    value: currentValue,
    done: false
}

When iteration finishes:

next-done.js
{
    value: undefined,
    done: true
}

Example — Getting the Iterator Manually

manual-iterator.js
const arr = [10, 20, 30];

const iterator = arr[Symbol.iterator]();

console.log(iterator.next());
console.log(iterator.next());
console.log(iterator.next());
console.log(iterator.next());

// Output:
// { value: 10, done: false }
// { value: 20, done: false }
// { value: 30, done: false }
// { value: undefined, done: true }
⚠️ Important: An iterable and an iterator are not the same object — calling arr[Symbol.iterator]() creates a brand-new iterator each time, so you can iterate the same array with two independent iterators simultaneously.

What is Symbol.iterator?

The Well-Known Symbol Behind Every Iterable

Symbol.iterator is a well-known symbol that returns an iterator for an iterable object.

symbol-iterator.js
const arr = [1, 2, 3];

const iterator = arr[Symbol.iterator]();

Every built-in iterable (Array, String, Map, Set, etc.) has this method.

✅ Benefit: Because it's a standardized symbol rather than a plain string method name, Symbol.iterator can't accidentally clash with a regular property someone names "iterator" on their own object.
How for...of Works

Syntax Sugar Over the Iterator Protocol

When we write:

for-of.js
for (const value of arr) {
    console.log(value);
}

JavaScript internally does something similar to:

for-of-desugared.js
const iterator = arr[Symbol.iterator]();

let result = iterator.next();

while (!result.done) {
    console.log(result.value);
    result = iterator.next();
}
📌 This is exactly why for...of works identically on arrays, strings, Maps, Sets, and generators — it never cares about the specific data structure, only that it implements Symbol.iterator.
Creating a Custom Iterable

Implementing Symbol.iterator Yourself

Any object becomes iterable the moment it implements Symbol.iterator and returns an object with a next() method.

custom-iterable.js
const range = {
    start: 1,
    end: 5,

    [Symbol.iterator]() {
        let current = this.start;
        let end = this.end;

        return {
            next() {
                if (current <= end) {
                    return {
                        value: current++,
                        done: false
                    };
                }

                return {
                    done: true
                };
            }
        };
    }
};

for (const value of range) {
    console.log(value);
}

// Output:
// 1
// 2
// 3
// 4
// 5
💡 Tip: Writing custom iterables by hand like this is exactly the boilerplate that generators exist to eliminate — see the next section.
What are Generators?

Functions That Can Pause & Resume

A Generator is a special function that can pause its execution and resume later. Generators automatically create an iterator, so you don't need to manually write the next() method.

A generator function is declared using function*.

generator-declaration.js
function* numbers() {
    yield 10;
    yield 20;
    yield 30;
}

The yield Keyword

The yield keyword:

  • Produces a value.
  • Pauses the generator.
  • Saves its current state.
  • Resumes from the same point when next() is called again.
⚠️ Important: Unlike return, yield does NOT end the function.

Generator Example

generator-example.js
function* numbers() {
    yield 10;
    yield 20;
    yield 30;
}

const iterator = numbers();

console.log(iterator.next());
console.log(iterator.next());
console.log(iterator.next());
console.log(iterator.next());

// Output:
// { value: 10, done: false }
// { value: 20, done: false }
// { value: 30, done: false }
// { value: undefined, done: true }

Using for...of with Generators

Since generators are iterable, they work directly with for...of.

generator-for-of.js
function* numbers() {
    yield 1;
    yield 2;
    yield 3;
}

for (const num of numbers()) {
    console.log(num);
}

// Output:
// 1
// 2
// 3
✅ Benefit: Every generator is both an iterator (it has a working next()) and an iterable (it has Symbol.iterator, which just returns itself) — that dual nature is exactly what makes for...of work on it directly.
Generator Execution Flow

Pausing and Resuming, Step by Step

generator-execution.js
function* demo() {

    console.log("Start");
    yield 1;

    console.log("Middle");
    yield 2;

    console.log("End");
}

const it = demo();

it.next();
it.next();
it.next();
📌 Notice that calling demo() alone doesn't run any code — the body only starts executing on the first call to next().
Infinite Generators

Lazy Sequences Without Infinite Memory

Generators are useful for creating infinite sequences because values are generated only when needed.

infinite-counter.js
function* counter() {
    let i = 1;

    while (true) {
        yield i++;
    }
}

const c = counter();

console.log(c.next().value);
console.log(c.next().value);
console.log(c.next().value);

// Output:
// 1
// 2
// 3
⚠️ Watch out: never call [...counter()] or use a plain for...of without a break on an infinite generator — both will loop forever trying to exhaust a sequence that never ends.

Real-World Use Cases

Where This Actually Gets Used

  • Processing large datasets.
  • Infinite sequences (IDs, Fibonacci, counters).
  • Lazy loading of data.
  • Tree or graph traversal.
  • Streaming data.
  • Reading large files chunk by chunk.
💡 Common thread: every one of these cases involves data that's either too large to hold in memory all at once, or isn't fully known upfront — generators let you produce "the next piece" on demand instead.

Interview Summary

Key Points to Remember

  • An iterable is any object with a Symbol.iterator method.
  • An iterator is an object with a next() method returning { value, done }.
  • for...of, spread, destructuring, and Array.from() all rely on the Iterator Protocol.
  • A generator (function*) automatically creates an iterator — no manual next() needed.
  • yield pauses execution and saves state; return ends it permanently.
  • Calling a generator function doesn't run its body — execution only starts on the first next().
  • Generators enable infinite, lazy sequences since values are computed only when requested.
  • Every Generator is both an Iterator and an Iterable.
💡 Common misconception: People often assume an iterable and its iterator are the same thing. They're not — the iterable is the source (e.g. an array), while the iterator is a separate, disposable object created fresh each time you call Symbol.iterator(), and it tracks its own progress independently.
Interview Q&A — Generators, Iterators & Iterables
💡 Interview Q&A
What makes an object "iterable" in JavaScript?
An object is iterable if it implements the Symbol.iterator method, which must return an iterator — an object with a next() method. Arrays, strings, Maps, and Sets are all iterable by default; plain objects are not, unless you add Symbol.iterator yourself.
What does the next() method of an iterator return?
An object shaped as { value, done }. While there are values left, done is false and value holds the current item. Once exhausted, it returns { value: undefined, done: true }, and further calls keep returning that same "done" result.
How does a generator simplify writing a custom iterator?
Without generators, you have to manually track state (like a current counter) and write your own next() method by hand. A generator handles all of that automatically — the JS engine pauses and resumes execution at each yield, remembering exactly where it left off.
manual-vs-generator.js
// Manual iterator — more code
function makeRangeIterator(start, end) {
  let current = start;
  return { next() {
    return current <= end
      ? { value: current++, done: false }
      : { done: true };
  } };
}

// Generator — same result, far less code
function* range(start, end) {
  for (let i = start; i <= end; i++) yield i;
}
Why doesn't calling a generator function run its body immediately?
Calling myGenerator() only creates a generator object (an iterator) — it does not execute any code inside the function yet. Execution only begins, and runs up to the first yield, when .next() is called for the first time.
Is it safe to use the spread operator on an infinite generator?
No. Spreading ([...gen()]) or converting with Array.from() tries to exhaust the iterator completely by calling next() until done is true — for an infinite generator that never happens, so the program hangs. Instead, pull values manually with .next() or use a bounded loop with a break.
What's the relationship between generators, iterators, and iterables?
A generator function, when called, returns a generator object that satisfies both protocols at once: it's an iterator because it has a working next(), and it's an iterable because its Symbol.iterator method just returns itself. That's exactly why a generator can be looped over directly with for...of.
