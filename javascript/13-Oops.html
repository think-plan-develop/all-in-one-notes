OOP in JavaScript

JavaScript's object-oriented model is built on prototypes, not classical classes — understanding that foundation makes everything else (classes, inheritance, encapsulation) click into place.

Definition Start Here

OOP (Object-Oriented Programming) is a way of structuring code around objects that bundle together data (properties) and behavior (methods). JavaScript's OOP is prototype-based under the hood — even class syntax is just a cleaner way of writing prototype-based code.

Interview Definition: JavaScript implements OOP through prototypal inheritance, where objects inherit directly from other objects via an internal link called the prototype, rather than through classical class-based inheritance found in languages like Java or C++.
1. Constructor Function
Building Objects with new

A constructor function is a regular function, called with new, used as a blueprint to create multiple similar objects.

constructor-function.js
function Person(name, age) {
    this.name = name;
    this.age = age;
}

const p1 = new Person("Sam", 28);
const p2 = new Person("Maya", 24);

console.log(p1.name); // "Sam"
console.log(p2.name); // "Maya"

What new Actually Does

StepAction
1Creates a brand-new empty object
2Links that object's prototype to Person.prototype
3Runs the function with this bound to the new object
4Returns the new object automatically (unless the function returns another object explicitly)
Convention: Constructor function names are capitalized (Person, not person) purely by convention, to signal "call this with new."
2. Prototype
Shared Methods Without Duplication

Every function has a prototype property — an object where you can define methods that should be shared by every instance, instead of being recreated for each one.

prototype.js
function Person(name) {
    this.name = name;
}

// Added once on the prototype — shared by ALL instances
Person.prototype.greet = function() {
    console.log(`Hi, I'm ${this.name}`);
};

const p1 = new Person("Sam");
const p2 = new Person("Maya");

p1.greet(); // "Hi, I'm Sam"
p2.greet(); // "Hi, I'm Maya"

console.log(p1.greet === p2.greet); // true — same function, not duplicated
Why it matters: If methods were defined inside the constructor instead (this.greet = function(){...}), every single instance would get its own copy of the function in memory. Putting it on the prototype means one shared copy, saving memory.
3. Prototype Chain
How Property Lookup Actually Works

When you access a property on an object, JavaScript looks on the object itself first. If it's not found, it walks up the prototype chain — checking the object's prototype, then that prototype's prototype, and so on — until it finds the property or reaches null.

prototype-chain.js
const p1 = new Person("Sam");

p1.greet();
// 1. Is "greet" on p1 itself? No.
// 2. Is it on Person.prototype? Yes — found, use it.

console.log(p1.toString());
// Not on p1, not on Person.prototype either
// → found on Object.prototype (end of the chain)

Object.getPrototypeOf(p1) === Person.prototype; // true
Object.getPrototypeOf(Person.prototype) === Object.prototype; // true
Object.getPrototypeOf(Object.prototype); // null — end of the chain

4. Classes
Syntactic Sugar Over Prototypes ES6

class syntax doesn't introduce a new inheritance model — it's a cleaner, more readable way to write the exact same constructor-function-plus-prototype pattern.

classes.js
class Person {
    constructor(name, age) {
        this.name = name;
        this.age = age;
    }

    greet() {
        console.log(`Hi, I'm ${this.name}`);
    }
}

const p1 = new Person("Sam", 28);
p1.greet(); // "Hi, I'm Sam"

console.log(typeof Person);              // "function" — still just a function under the hood
console.log(p1.greet === Person.prototype.greet); // true — same mechanism as before

5. Inheritance
extends and super

Inheritance lets one class (or constructor) build on top of another, reusing its properties and methods instead of duplicating them.

inheritance.js
class Animal {
    constructor(name) {
        this.name = name;
    }
    speak() {
        console.log(`${this.name} makes a sound.`);
    }
}

class Dog extends Animal {
    constructor(name, breed) {
        super(name); // calls Animal's constructor
        this.breed = breed;
    }
    speak() {
        super.speak();  // calls Animal's speak() too
        console.log(`${this.name} barks.`);
    }
}

const dog = new Dog("Rex", "Labrador");
dog.speak();
// "Rex makes a sound."
// "Rex barks."

console.log(dog instanceof Dog);    // true
console.log(dog instanceof Animal); // true — Dog inherits from Animal
Rule: In a subclass constructor, you must call super(...) before you can use this — skipping it throws a ReferenceError.
Under the hood: extends links Dog.prototype's prototype to Animal.prototype — it's the prototype chain from section 3, just set up automatically.
6. Encapsulation
Hiding Internal Details ES2022

Encapsulation means bundling data with the methods that operate on it, and restricting direct outside access to internal details — exposing only a controlled public interface.

encapsulation.js
class BankAccount {
    #balance = 0; // private field — only accessible inside this class

    constructor(owner) {
        this.owner = owner; // public field
    }

    deposit(amount) {
        if (amount > 0) this.#balance += amount;
    }

    getBalance() {
        return this.#balance; // controlled read access
    }
}

const acc = new BankAccount("Sam");
acc.deposit(100);
acc.getBalance(); // 100

// acc.#balance;  ❌ SyntaxError — private fields are inaccessible from outside
Why it matters: Encapsulation prevents external code from setting #balance to an invalid value directly — all changes must go through deposit(), which can enforce rules.
7. Polymorphism
One Interface, Many Behaviors

Polymorphism means different classes can be used through the same interface, but each provides its own specific behavior — most commonly via method overriding.

polymorphism.js
class Shape {
    area() {
        return 0;
    }
}

class Circle extends Shape {
    constructor(radius) { super(); this.radius = radius; }
    area() { return Math.PI * this.radius ** 2; } // overridden
}

class Square extends Shape {
    constructor(side) { super(); this.side = side; }
    area() { return this.side ** 2; } // overridden differently
}

const shapes = [new Circle(5), new Square(4)];

shapes.forEach(shape => {
    console.log(shape.area()); // each calls its OWN area() — same method name, different logic
});
// 78.54
// 16
Why it matters: The calling code (shape.area()) doesn't need to know or care whether shape is a Circle or a Square — it just calls area() and gets the correct behavior for that specific object.
8. Static Methods
Belonging to the Class, Not Instances ES6

static methods and fields live on the class itself, not on individual instances — useful for utility functions related to the class that don't need a specific object to operate on.

static-methods.js
class MathUtils {
    static PI = 3.14159; // static field (ES2022)

    static square(n) {
        return n * n;
    }

    static circleArea(radius) {
        return MathUtils.PI * MathUtils.square(radius);
    }
}

MathUtils.square(4);        // 16 — called directly on the class
MathUtils.circleArea(2);   // 12.566...

const m = new MathUtils();
// m.square(4);  ❌ TypeError — static methods don't exist on instances
Common use case: Factory methods (Array.from(), Array.isArray()) and utility/helper functions that logically belong to a class but don't need any particular instance's data.
9. Interview Questions & Answers
Constructor Function & Prototype

Q: What does the new keyword do?
A: It creates a new empty object, links its prototype to the constructor's .prototype, runs the constructor with this bound to that new object, and returns it automatically.

Q: Why put methods on the prototype instead of inside the constructor?
A: Methods defined inside the constructor are recreated for every instance, wasting memory. Methods on the prototype are created once and shared by all instances.

Q: What is the prototype chain?
A: The series of links JavaScript follows when looking up a property — from the object itself, to its prototype, to that prototype's prototype, and so on until it reaches null.

Classes & Inheritance

Q: Are JavaScript classes the same as classes in Java or C++?
A: No — under the hood they're still prototype-based. class is syntactic sugar over constructor functions and prototypes, not a separate classical inheritance system.

Q: What does super() do?
A: It calls the parent class's constructor (or a parent method, as super.methodName()), and in a subclass constructor it must be called before this can be used.

Q: What happens if you call a class without new?
A: It throws a TypeError immediately — unlike old-style constructor functions, which would silently run with the wrong this.

Encapsulation & Polymorphism

Q: How do you achieve true private fields in JavaScript?
A: Using the #fieldName syntax (ES2022) — these fields are only accessible from inside the class body and throw a syntax error if accessed from outside.

Q: What is method overriding?
A: When a subclass defines a method with the same name as one in its parent class, replacing (or extending, via super.method()) the inherited behavior — the core mechanism behind polymorphism.

Q: Give a real example of polymorphism.
A: Calling .area() on an array of different shape objects (Circle, Square, Triangle) — each executes its own version of area(), even though the calling code looks identical for all of them.
