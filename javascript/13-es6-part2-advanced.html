Object Improvements
🔤

Property Shorthand

ES6

Before ES6, when the variable name and object property name matched, you had to write both.

before.js
const name = "John";
const age = 25;

const user = {
    name: name,
    age: age
};

ES6 introduced Property Shorthand, letting you write just the variable name.

shorthand.js
const name = "John";
const age = 25;

const user = { name, age };

console.log(user);
// Output: { name: "John", age: 25 }
💡 Benefits: less code, cleaner objects, and it's the default style seen throughout React and Node.js codebases.
🧮

Computed Property Names

ES6

Normally object property names are fixed, but sometimes the name itself is stored in a variable. Wrapping it in [] evaluates the expression first and uses the result as the key.

computed-keys.js
const key = "email";

const user = {
    [key]: "john@gmail.com"
};

console.log(user);
// Output: { email: "john@gmail.com" }
🔗

Object.assign()

Copies properties from one or more source objects into a target object. Syntax: Object.assign(target, source1, source2).

object-assign.js
const user = { name: "John" };
const details = { age: 25 };

const result = Object.assign({}, user, details);

console.log(result);
// Output: { name: "John", age: 25 }
📌 Uses: merging objects, cloning objects, applying default configuration.
📋

Object.entries() & Object.values()

Object.entries() converts an object into an array of [key, value] pairs — very useful inside loops.

object-entries.js
const user = { name: "John", age: 25 };

console.log(Object.entries(user));
// Output: [ ["name","John"], ["age",25] ]

for (const [key, value] of Object.entries(user)) {
    console.log(key, value);
}

Object.values() returns only the values.

object-values.js
console.log(Object.values(user));
// Output: [ "John", 25 ]
↩️

Object.fromEntries()

The opposite of Object.entries() — converts key-value pairs back into an object. Especially handy after using map() or filter() on entries.

object-fromentries.js
const arr = [ ["name","John"], ["age",25] ];

const obj = Object.fromEntries(arr);

console.log(obj);
// Output: { name: "John", age: 25 }
🔒

Object.freeze() vs Object.seal()

Object.freeze() makes an object completely immutable — no adding, deleting, or updating properties.

object-freeze.js
const user = { name: "John" };

Object.freeze(user);

user.name = "Alex";
user.age = 25;

console.log(user);
// Output: { name: "John" } — both changes were ignored

Object.seal() allows updating existing properties, but still blocks adding or removing them.

object-seal.js
const user = { name: "John" };

Object.seal(user);

user.name = "Alex";
user.age = 25;

console.log(user);
// Output: { name: "Alex" } — new property "age" was ignored
Object.freeze()Object.seal()
Cannot add propertiesCannot add properties
Cannot delete propertiesCannot delete properties
Cannot modify existing valuesExisting values can be modified
Completely immutablePartially mutable
📌 Real-world uses: protecting API response objects, locking configuration objects, Redux state, React props, and safe object cloning/merging.
Array Improvements
📦

Array.from()

Creates a new array from an iterable or array-like object.

array-from.js
const str = "JavaScript";
console.log(Array.from(str));
// Output: ["J","a","v","a","S","c","r","i","p","t"]

const nums = Array.from({ length: 5 }, (_, index) => index + 1);
console.log(nums);
// Output: [1,2,3,4,5]
🆕

Array.of()

Creates an array from the given values — unlike the Array() constructor, a single number argument is treated as a value, not a length.

array-of.js
console.log(Array.of(10,20,30));
// Output: [10, 20, 30]

console.log(Array(3));
// Output: [ <3 empty items> ]

console.log(Array.of(3));
// Output: [3]
🔍

find() & findIndex()

find() returns the first matching element; findIndex() returns the first matching index.

find.js
const nums = [10,20,30,40];

console.log(nums.find(num => num > 25));
// Output: 30

console.log(nums.findIndex(num => num > 25));
// Output: 2
✅

includes()

Checks whether an array contains a given value, returning a boolean.

array-includes.js
const fruits = ["Apple", "Banana", "Orange"];

console.log(fruits.includes("Banana"));
// Output: true
🥞

flat() & flatMap()

flat() flattens nested arrays by a given depth (default 1).

array-flat.js
const arr = [1, [2,3], [4,[5]]];

console.log(arr.flat());
// Output: [1, 2, 3, 4, [5]]

console.log(arr.flat(2));
// Output: [1, 2, 3, 4, 5]

flatMap() performs map() and flat() in a single, more efficient pass.

array-flatmap.js
const nums = [1,2,3];

const result = nums.flatMap(num => [num, num * 2]);

console.log(result);
// Output: [1, 2, 2, 4, 3, 6]
// equivalent to nums.map(...).flat(), but more efficient
📌 Real-world uses: search with find(), permission checks with includes(), flattening API responses, transforming nested data, and converting NodeLists into arrays via Array.from().
String Improvements
📝

Helper Methods for Text

string-helpers.js
// startsWith() — checks if a string starts with specific text
console.log("JavaScript".startsWith("Java"));
// Output: true

// endsWith() — checks if a string ends with specific text
console.log("photo.jpg".endsWith(".jpg"));
// Output: true

// includes() — checks if a string contains specific text
console.log("Learn JavaScript".includes("Java"));
// Output: true

// repeat() — repeats a string multiple times
console.log("Hi ".repeat(3));
// Output: "Hi Hi Hi "

// padStart() — pads at the beginning until a target length
console.log("25".padStart(5, "0"));
// Output: "00025"

// padEnd() — pads at the end until a target length
console.log("JS".padEnd(6, "."));
// Output: "JS...."
💡 Common use case: padStart() is the go-to for formatting numbers with leading zeros (invoice IDs, timers, dates); startsWith()/endsWith()/includes() replace a lot of manual indexOf() checks.

Symbol
🧩

What is Symbol?

ES6

A Symbol is a primitive data type introduced in ES6. Every Symbol value is always unique, even if two Symbols share the same description — making it ideal for collision-free object property keys.

symbol-syntax.js
const id = Symbol();
const userId = Symbol("userId");
❓

Why Do We Need Symbols?

Normal object properties are strings, so if another developer adds a property with the same name, it silently overwrites the original. A Symbol key sidesteps that entirely.

symbol-key.js
const id = Symbol("id");

const user = { [id]: 101 };

console.log(user[id]);
// Output: 101
🆔

Unique Property Keys

Even with identical descriptions, two Symbols are never equal.

symbol-unique.js
const s1 = Symbol("user");
const s2 = Symbol("user");

console.log(s1 === s2);
// Output: false
🌐

Global Symbol Registry

Sometimes you want the same Symbol shared across your app. Symbol.for() checks a global registry first: if a Symbol already exists for that key, it returns it; otherwise it creates and registers a new one.

symbol-for.js
const s1 = Symbol.for("id");
const s2 = Symbol.for("id");

console.log(s1 === s2);
// Output: true
⭐

Well-Known Symbols

JavaScript ships predefined Symbols that customize built-in engine behavior, such as Symbol.iterator, Symbol.toPrimitive, and Symbol.toStringTag.

well-known-symbols.js
const numbers = [1,2,3];

console.log(numbers[Symbol.iterator]);
// used internally to make arrays iterable with for...of
📌 Real-world uses: unique object properties, avoiding property-name conflicts, library/framework internals, and building custom iterators.
Proxy
🕵️

What is Proxy?

A Proxy lets you intercept and customize operations performed on an object. Instead of directly touching the object, JavaScript routes the operation through the Proxy first — it acts as a middle layer between your code and the original object.

proxy-syntax.js
const proxy = new Proxy(targetObject, handler);
// target  → original object
// handler → object containing "traps"
💡 Why use it: validate data, log operations, restrict access, track changes, or build reactive systems — Vue 3 uses Proxy internally for exactly this.
👁️

The get Trap

Runs whenever a property is read.

get-trap.js
const user = { name: "John" };

const proxy = new Proxy(user, {
    get(target, property) {
        console.log("Reading:", property);
        return target[property];
    }
});

console.log(proxy.name);
// Output:
// Reading: name
// John
✏️

The set Trap

Runs whenever a value is assigned.

set-trap.js
const user = {};

const proxy = new Proxy(user, {
    set(target, property, value) {
        target[property] = value;
        return true;
    }
});

proxy.name = "Alex";

console.log(user);
// Output: { name: "Alex" }
🗑️

deleteProperty & has Traps

deleteProperty fires when a property is deleted; has fires when the in operator is used.

delete-has-trap.js
const user = { age: 25 };

const proxy1 = new Proxy(user, {
    deleteProperty(target, property) {
        console.log(property, "deleted");
        delete target[property];
        return true;
    }
});
delete proxy1.age;   // logs "age deleted"

const proxy2 = new Proxy({ name: "John" }, {
    has(target, property) {
        console.log(property);
        return property in target;
    }
});
console.log("name" in proxy2);   // logs "name" then true
🛡️

Validation & Logging Examples

The set trap is a natural place to enforce validation rules before a value is ever written.

validation.js
const user = {};

const proxy = new Proxy(user, {
    set(target, property, value) {
        if (property === "age" && value < 0) {
            throw new Error("Invalid Age");
        }
        target[property] = value;
        return true;
    }
});

proxy.age = 25;   // ✅ works
// proxy.age = -5;  ❌ throws "Invalid Age"

Combining get and set gives you a simple change-logger for free.

logging.js
const user = { name: "John" };

const proxy = new Proxy(user, {
    get(target, property) {
        console.log(`Reading ${property}`);
        return target[property];
    },
    set(target, property, value) {
        console.log(`Updating ${property}`);
        target[property] = value;
        return true;
    }
});

proxy.name;          // "Reading name"
proxy.name = "Alex";  // "Updating name"
📌 Real-world uses: form validation, state management, API logging, security/access control, and reactive frameworks.
Reflect
🪞

Why Reflect?

Reflect is a built-in object providing methods for performing object operations. Almost every Proxy trap has a matching Reflect method, so using Reflect inside a Proxy keeps your implementation cleaner and safer.

🧰

Core Reflect Methods

reflect-methods.js
const user = { name: "John" };

console.log(Reflect.get(user, "name"));
// Output: John

Reflect.set(user, "age", 25);
console.log(user);
// Output: { name: "John", age: 25 }

console.log(Reflect.has(user, "name"));
// Output: true

Reflect.deleteProperty(user, "age");
console.log(user);
// Output: { name: "John" }

Reflect.construct() creates an instance using a constructor function, passing arguments as an array.

reflect-construct.js
function Person(name) {
    this.name = name;
}

const p = Reflect.construct(Person, ["John"]);

console.log(p);
// Output: Person { name: "John" }
🤝

Proxy + Reflect Together

Using Reflect inside Proxy traps to forward the operation is considered best practice.

proxy-reflect.js
const user = { name: "John" };

const proxy = new Proxy(user, {
    get(target, property) {
        console.log("Reading", property);
        return Reflect.get(target, property);
    },
    set(target, property, value) {
        console.log("Updating", property);
        return Reflect.set(target, property, value);
    }
});

proxy.name;
proxy.name = "Alex";

📌 Real-world uses: Proxy implementations, framework internals, validation libraries, logging, and meta-programming in general.
Tagged Template Literals
🏷️

Processing a Template Before It Becomes a String

A Tagged Template Literal lets a function process a template literal before it's combined into a final string. Instead of returning the template string directly, JavaScript passes its parts to that function.

tagged-basic.js
function tag(strings, value) {
    console.log(strings);
    console.log(value);
}

const name = "John";

tag`Hello ${name}!`;

// Output:
// ["Hello ", "!"]
// John

The tag function receives an array of the literal's string parts, plus the interpolated values, so it can transform them however it likes.

tagged-transform.js
function uppercase(strings, value) {
    return strings[0] + value.toUpperCase() + strings[1];
}

const name = "john";

console.log(uppercase`Hello ${name}!`);
// Output: Hello JOHN!
💡 Real-world example: tagged templates are the mechanism behind styled-components:
styled-components.js
const Button = styled.button`
    background: blue;
    color: white;
`;
Optional Chaining (?.)
🧷

Safe Access Without Manual Null Checks

Optional Chaining safely accesses nested properties, function calls, and array indices without throwing when something along the path is null or undefined.

optional-chaining.js
// Safe property access
const user = { profile: { name: "John" } };

console.log(user.profile?.name);
console.log(user.address?.city);
// Output: John, undefined

// Function calls
const user2 = { greet() { return "Hello"; } };
console.log(user2.greet?.());
console.log(user2.sayHi?.());
// Output: Hello, undefined

// Array access
const users = [{ name: "John" }];
console.log(users?.[0]?.name);
console.log(users?.[1]?.name);
// Output: John, undefined

// Short-circuiting
const nobody = null;
console.log(nobody?.name);
// Output: undefined — stops immediately, no error
📌 Note: The moment any link in the chain is null/undefined, evaluation stops right there and the whole expression short-circuits to undefined — the rest of the chain is never touched.
Nullish Coalescing (??)
🎯

Fallback Only for null / undefined

The Nullish Coalescing Operator returns the right-hand value only when the left side is null or undefined — unlike ||, other falsy values like 0 pass through untouched.

nullish-basic.js
const name = null;

console.log(name ?? "Guest");
// Output: Guest

The key difference from ||:

or-vs-nullish.js
console.log(0 || 100);
console.log(0 ?? 100);
// Output: 100, 0

|| treats every falsy value (0, false, "", NaN) as "missing." ?? treats only null and undefined as missing.

nullish-real-world.js
const user = { age: 0 };

console.log(user.age ?? 18);
// Output: 0 — a real age of 0 is respected, not replaced
Logical Assignment Operators
⚙️

||=, &&=, and ??=

These combine a logical operator with assignment, so you can skip writing an if check just to conditionally set a variable.

or-equals.js
// ||= assigns only if the left side is falsy
let username = "";
username ||= "Guest";
console.log(username);
// Output: Guest
and-equals.js
// &&= assigns only if the left side is truthy
let isLoggedIn = true;
isLoggedIn &&= false;
console.log(isLoggedIn);
// Output: false
nullish-equals.js
// ??= assigns only if the left side is null or undefined
let city = null;
city ??= "Delhi";
console.log(city);
// Output: Delhi

A common practical pattern — filling in defaults on a config object in one pass:

config-defaults.js
let config = {};

config.theme ??= "Light";
config.username ||= "Guest";

console.log(config);
// Output: { theme: "Light", username: "Guest" }
💡 Which one to reach for: use ??= when only null/undefined should be replaced (e.g. optional config), and ||= only when any falsy value should count as "unset."
Interview Questions
💡 Interview Q&A
What is Property Shorthand?
A shorter syntax for creating object properties when the variable name and property name are the same.
Difference between Object.entries() and Object.values()?
Object.entries() returns key-value pairs; Object.values() returns only the values.
Difference between Object.freeze() and Object.seal()?
freeze() makes the object completely immutable. seal() allows updating existing properties but prevents adding or deleting them.
Difference between find() and filter()?
find() returns the first matching element; filter() returns all matching elements.
Difference between Array.from() and Array.of()?
Array.from() creates an array from an iterable or array-like object; Array.of() creates an array from the values you pass in directly.
Difference between flat() and flatMap()?
flat() only flattens nested arrays; flatMap() first maps each element and then flattens the result by one level.
Why use Symbol instead of a string?
Because a Symbol guarantees a unique property key, avoiding accidental overwrites.
Can two Symbols be equal?
Only when both are created with Symbol.for() using the exact same key.
Is Symbol a primitive?
Yes.
What is Proxy?
A wrapper around an object that intercepts operations performed on it.
Which framework heavily uses Proxy?
Vue 3.
Does Reflect replace Proxy?
No. Proxy intercepts operations; Reflect performs those operations. They're commonly used together.
Why use Reflect inside Proxy?
Because it safely forwards the operation to the original object while keeping the Proxy code clean and consistent.
