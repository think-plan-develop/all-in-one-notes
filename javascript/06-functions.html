Function Syntax — How to Write a Function

Function Declaration

Hoisted

A named function defined with the function keyword as its own statement. It's hoisted — usable even before its line runs.

declaration.js
function greet(name) {
  return `Hello, ${name}!`;
}
greet("Aria"); // "Hello, Aria!"

Why use it

Gives a clear, reusable name and hoisting flexibility.

When to use it

Main/reusable functions you want available anywhere in the file.

✅ Benefit: Hoisting flexibility + self-documenting name.

Function Expression

A function assigned to a variable, treated like any other value. Not hoisted the same way as declarations: the variable itself is hoisted, but the function value isn't initialized until that line actually executes.

expression.js
const square = function(n) {
  return n * n;
};
square(5); // 25

Calling it before the line runs

expression-hoisting.js
console.log(square); // ReferenceError (with const/let)

const square = function(n) {
  return n * n;
};

Why use it

Lets a function be conditionally assigned or reassigned like a variable.

When to use it

When a function should only exist after a condition, or be a dynamic object property.

🔎 Benefit: More control over timing and scope than a hoisted declaration.

Arrow Functions

ES6

Short syntax using =>. Arrow functions do not create their own this, arguments, super, or new.target — they inherit all of these from the surrounding lexical scope, and they cannot be used as constructors with new.

arrow.js
const add = (a, b) => a + b;
const sayHi = () => console.log("Hi!");

The "this" pitfall as an object method

❌ Arrow as method
arrow-this-bad.js
const person = {
  name: "Shivam",
  greet: () => {
    console.log(this.name);
    // undefined — "this" is
    // inherited from outer scope,
    // not the object
  }
};
person.greet();
✅ Regular method
arrow-this-good.js
const person = {
  name: "Shivam",
  greet() {
    console.log(this.name);
    // "Shivam" — "this" is
    // the object that called it
  }
};
person.greet();

Why use it

Shorter syntax and predictable this — inherits it from the outer scope instead of depending on how the function was called.

When to use it

Short callbacks and array methods (map/filter/reduce).

⚠️ Benefit: Less code, no this confusion — but avoid as object methods, and never use with new.

Anonymous Functions

Unique case

A function with no name, typically used once, inline, where naming it adds no value.

anonymous.js
setTimeout(function() {
  console.log("runs after 1s");
}, 1000);

// as array callback
[1,2,3].forEach(function(n) {
  console.log(n * 2);
});

Why use it

Avoids naming clutter for logic that's only used once, right where it's written.

When to use it

Event handlers, setTimeout/setInterval, one-off array callbacks.

💡 Benefit: Cleaner, throwaway code — no unused function name lingering in scope.
Function Patterns — How Functions Are Used

IIFE

Unique case

An Immediately Invoked Function Expression — runs the moment it's defined, by wrapping it in parentheses and calling it right away.

iife.js
(function() {
  const secret = "hidden";
  console.log("IIFE ran instantly!");
})();

// arrow IIFE variant
(() => {
  console.log("arrow IIFE!");
})();

Why use it

Keeps variables private to that block so they don't leak into or clash with the global scope.

When to use it

One-time setup code, initializing a widget/library, isolating variables in non-module scripts.

✅ Benefit: Zero global namespace pollution — common before ES6 modules, still handy today. In modern applications, ES modules usually provide better file-level scope, but IIFEs remain useful for one-time initialization and isolated, non-module scripts.

Callback Functions

Unique case

A function passed as an argument into another function, to be executed later — after an async task or event finishes.

callback.js
function fetchUser(callback) {
  setTimeout(() => {
    const user = { id: 1, name: "Shivam" };
    callback(user);
  }, 1000);
}

fetchUser((user) => {
  console.log(`Welcome ${user.name}`);
});

// event listener callback
button.addEventListener("click", () => {
  console.log("clicked!");
});
🔎 The callback isn't executed immediately — it's stored by fetchUser and later invoked by the timer/Web API once the delay finishes, which is why the rest of the program doesn't block while waiting.

Why use it

Lets code run only after another task completes, without blocking the rest of the program.

When to use it

Async work: API calls, timers, file reads, event listeners (click, load, etc).

🔎 Benefit: Non-blocking async code — the foundation of JS before Promises/async-await.

Higher-Order Functions

HOF

A function that either takes a function as an argument or returns a function. Array methods like map/filter/reduce are classic HOFs.

hof.js
const nums = [1, 2, 3];
const doubled = nums.map(n => n * 2);
// doubled = [2, 4, 6]

Writing your own HOF

HOFs aren't limited to built-in array methods — any function that accepts another function as a parameter counts:

custom-hof.js
function repeat(n, action) {
  for (let i = 1; i <= n; i++) {
    action(i);
  }
}

repeat(3, (i) => console.log(`Run ${i}`));
// Run 1
// Run 2
// Run 3

Why use it

Reuses generic logic (looping, transforming) while plugging in custom behavior.

When to use it

Transforming/filtering data, or building utilities like debounce or compose.

💡 Benefit: Cleaner, declarative, reusable code — possible because functions are first-class in JS.
Function Behavior — How a Function Behaves

Pure Functions

Always returns the same output for the same input and causes no side effects (no touching outside state).

Pure vs impure

✅ Pure
pure.js
function addTax(price, taxRate) {
  return price + price * taxRate;
}

addTax(100, 0.18); // 118
// same inputs always give 118,
// nothing outside is touched
❌ Impure
impure.js
let total = 0;

function addToTotal(amount) {
  total += amount; // modifies
  // external state
}
// same call can produce a
// different result each time

Why use it

Predictable behavior makes bugs easier to trace and functions easy to test.

When to use it

Business logic, calculations, data transforms — e.g. Redux reducers.

✔ Pros
  • Predictable & testable
  • Safe for concurrency
✘ Cons
  • Can't do I/O or logging directly
Function Features — Special Capabilities

First-Class Functions

Functions are treated as values — stored in variables, passed as arguments, returned from other functions, or stored in arrays/objects.

Simplest example — storing a function

firstclass-simple.js
function greet() {
  return "Hello";
}

const fn = greet; // store function in a variable
console.log(fn()); // "Hello"

Advanced example — returning a function

firstclass.js
function makeMultiplier(x) {
  return (n) => n * x; // returns a function
}
const triple = makeMultiplier(3);

Why use it

Unlocks passing behavior around, not just data.

When to use it

Storing a function in a variable/array/object, passing it as an argument, or returning it.

✅ Benefit: The core property that makes callbacks, HOFs, and closures possible in JS.

Parameters vs Arguments

Foundational

These two terms are often used interchangeably, but they refer to different things.

params-vs-args.js
function add(a, b) { // a and b are parameters
  return a + b;
}

add(2, 3); // 2 and 3 are arguments

Parameters are the variables listed in the function's definition. Arguments are the actual values passed in when the function is called.

🔎 Easy way to remember it: parameters are the placeholders in the recipe; arguments are the real ingredients you hand over when cooking.

Rest Parameters

...args

Collects all remaining arguments into a real array using ... before the last parameter.

rest.js
function sumAll(...numbers) {
  return numbers.reduce((a,b) => a+b, 0);
}
sumAll(1, 2, 3, 4); // 10

Why use it

Accepts an unknown number of arguments without listing each one.

When to use it

Sum-style utilities, logging functions, or APIs accepting variable input counts.

🔎 Benefit: Cleaner signatures + a real array (unlike old arguments).

Default Parameters

Lets a parameter fall back to a default value when no argument (or undefined) is passed.

default.js
function greet(name = "Guest") {
  return `Welcome, ${name}!`;
}
greet(); // "Welcome, Guest!"

Why use it

Prevents undefined errors and skips manual fallback checks in the body.

When to use it

Optional config values, function parameters with a sensible fallback, optional flags.

⭐ Benefit: Safer, shorter code. Defaults can reference earlier params, e.g. f(a, b = a * 2).
🧠 Interview Questions
💡 Output Guessing
What happens when you call a function declaration before its definition in the code?
hoisting-declaration.js
sayHi();

function sayHi() {
  console.log("Hi");
}

// Output:
// Hi
Function declarations are fully hoisted — both the name and the function body are available before execution reaches that line, so calling it earlier in the file still works.
What happens when you call a function expression before its definition?
hoisting-expression.js
sayHello();

const sayHello = function() {
  console.log("Hello");
};

// Output:
// ReferenceError: Cannot access 'sayHello' before initialization
The variable is hoisted but stays in the "temporal dead zone" until its declaration line runs — the function value isn't attached to it yet, so calling it earlier throws instead of returning undefined.
What does this refer to inside an arrow function used as an object method?
arrow-this.js
const obj = {
  name: "JS",
  method: () => console.log(this.name)
};

obj.method();

// Output:
// undefined
Arrow functions don't bind their own this — they inherit it from the surrounding lexical scope, not from obj, so this.name isn't the object's name property.
