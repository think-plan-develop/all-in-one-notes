1. var, let, const

What is the difference between var, let and const?

var is function-scoped, gets hoisted and initialized with undefined, and can be redeclared and reassigned. let is block-scoped, hoisted but kept in the "temporal dead zone" until its declaration line runs, and can be reassigned but not redeclared in the same scope. const behaves like let for scoping, but the binding cannot be reassigned after initialization (though objects/arrays assigned to a const can still be mutated).

Why is var considered risky in modern code?

Because it ignores block boundaries (if/for/while), it can leak variables outside loops, silently overwrite outer variables, and cause bugs that are hard to trace — which is why let/const are preferred today.

scope.js
function demo() {
  if (true) {
    var a = 1;
    let b = 2;
  }
  console.log(a); // 1 (leaks out of block)
  console.log(b); // ReferenceError: b is not defined
}
Tip: Use const by default, switch to let only when reassignment is needed, and avoid var entirely in new code.
2. Hoisting

What is hoisting in JavaScript?

Hoisting is the JavaScript engine's behavior of moving variable and function declarations to the top of their scope during the compile phase, before code execution begins. Only the declaration is hoisted, not the initialization/assignment.

How does hoisting differ for var, let/const, and function declarations?

var declarations are hoisted and initialized to undefined. let/const are hoisted but remain uninitialized in the temporal dead zone until their line executes, so accessing them earlier throws a ReferenceError. Function declarations are hoisted completely, including their body, so they can be called before their definition in the code; function expressions and arrow functions are not hoisted this way — only the variable holding them is.

hoisting.js
console.log(x); // undefined
var x = 5;

greet(); // "Hi" — works, function declarations are fully hoisted
function greet() { console.log("Hi"); }

console.log(y); // ReferenceError (temporal dead zone)
let y = 10;
3. Closures

What is a closure?

A closure is formed when a function "remembers" the variables from its outer (lexical) scope even after that outer function has finished executing. The inner function keeps a live reference to those variables rather than a copy.

What are closures used for in real applications?

Closures power data privacy (private counters/modules), function factories, memoization caches, event handler callbacks that need extra context, and the classic module pattern used before ES modules existed.

closure.js
function makeCounter() {
  let count = 0;
  return function() {
    count++;
    return count;
  };
}
const counter = makeCounter();
counter(); // 1
counter(); // 2 — "count" persisted between calls
Watch out: closures inside loops using var commonly capture the final loop value — a classic interview trap fixed by switching to let.
4. Scope & Scope Chain

What is scope, and what types exist in JavaScript?

Scope determines where a variable is accessible. JavaScript has global scope (accessible everywhere), function scope (visible only inside a function), and block scope (visible only inside { }, for let/const).

What is the scope chain?

When a variable is referenced, the engine looks it up in the current scope first; if not found, it walks outward through each enclosing lexical scope until it reaches the global scope. This ordered lookup path is the scope chain. If the variable isn't found anywhere in the chain, a ReferenceError is thrown.

scope-chain.js
const a = "outer";
function outer() {
  const b = "middle";
  function inner() {
    console.log(a, b); // walks up the chain to find both
  }
  inner();
}
5. this keyword

How is the value of "this" determined?

Unlike lexically-scoped variables, this is determined by how a function is called, not where it's defined. In a plain function call it's undefined in strict mode (or the global object otherwise); as a method it's the object before the dot; with new it's the newly created instance; and with call/apply/bind it's whatever is explicitly passed.

How is "this" different in arrow functions?

Arrow functions don't have their own this — they inherit it lexically from the surrounding scope where they were defined, which is why they're popular for callbacks inside methods.

this.js
const obj = {
  name: "Card",
  regular: function() { console.log(this.name); }, // "Card"
  arrow: () => console.log(this.name)      // undefined, inherits outer this
};
6. call(), apply(), bind()

What do call, apply and bind do?

All three let you explicitly set the value of this for a function. call invokes the function immediately with arguments passed one by one. apply invokes it immediately too, but arguments are passed as an array. bind does not invoke the function — it returns a new function permanently bound to the given this, which can be called later.

When would you use bind over call/apply?

Use bind when you need to pass a function as a callback (e.g. an event handler or a setTimeout callback) but still want it to run with a specific this, since call/apply execute immediately rather than returning a reusable function.

bind.js
function greet(greeting) { console.log(greeting, this.name); }
const user = { name: "Riya" };

greet.call(user, "Hi");            // Hi Riya
greet.apply(user, ["Hello"]);      // Hello Riya
const bound = greet.bind(user);
bound("Hey");                          // Hey Riya (runs later)
7. Arrow Functions

What are the key differences between arrow functions and regular functions?

Arrow functions don't bind their own this, arguments, or super — they inherit these from the enclosing scope. They cannot be used as constructors (no new), have no prototype property, and are ideal for short, non-method callbacks.

Good fit for
  • Array callbacks (map/filter/reduce)
  • Preserving "this" inside class methods/timers
  • Short one-line utilities
Avoid for
  • Object methods needing dynamic "this"
  • Constructors
  • Functions needing "arguments" object
8. Promises

What is a Promise and what states can it have?

A Promise is an object representing the eventual result of an asynchronous operation. It exists in one of three states: pending (not resolved yet), fulfilled (completed successfully with a value), or rejected (failed with a reason). Once settled (fulfilled or rejected), its state is final.

How do you chain and handle errors in Promises?

Each .then() returns a new promise, allowing chaining; a single .catch() at the end can catch errors from any step in the chain, and .finally() runs regardless of outcome.

promise.js
new Promise((resolve, reject) => {
  setTimeout(() => resolve("done"), 1000);
})
  .then(result => console.log(result))
  .catch(err => console.error(err))
  .finally(() => console.log("cleanup"));
9. async/await

What does async/await do under the hood?

It's syntactic sugar over Promises. An async function always returns a Promise, and await pauses execution of that function (without blocking the whole thread) until the awaited Promise settles, then resumes with the resolved value or throws the rejection.

How do you handle errors with async/await?

Wrap the await call in a try/catch block, which lets you handle rejected promises the same way you'd handle a thrown synchronous error.

async.js
async function getUser(id) {
  try {
    const res = await fetch(`/api/users/${id}`);
    const data = await res.json();
    return data;
  } catch (err) {
    console.error("Failed:", err);
  }
}
10. Event Loop

What is the event loop and why does JavaScript need it?

JavaScript is single-threaded, so it can only execute one thing at a time on the call stack. The event loop is the mechanism that lets JavaScript perform non-blocking asynchronous work: it continuously checks whether the call stack is empty, and if so, pushes the next pending callback (from the task queues) onto the stack to run.

Walk through what happens with a setTimeout call.

The timer is handed off to a Web API (browser) or libuv (Node); once the timer expires, its callback is placed in the macrotask queue. The event loop only moves it to the call stack once the stack is empty and all pending microtasks have run.

11. Call Stack

What is the call stack?

The call stack is a LIFO (last-in, first-out) data structure that tracks function calls. When a function is invoked, a new frame is pushed onto the stack; when it returns, its frame is popped off. It represents the current position of synchronous execution.

What causes a "Maximum call stack size exceeded" error?

It happens when the stack grows beyond its limit, most commonly from uncontrolled recursion (a function that calls itself without a proper base case to stop it).

12. Microtask vs Macrotask Queue

What is the difference between microtasks and macrotasks?

Microtasks (Promise callbacks, queueMicrotask, MutationObserver) have higher priority: the engine drains the entire microtask queue after each synchronous block finishes, before moving on. Macrotasks (setTimeout, setInterval, I/O, UI rendering) run one at a time, and only after all microtasks are cleared.

What will this code log, and in what order?

Synchronous code runs first, then all microtasks, then macrotasks — so a Promise's .then() will always log before a setTimeout callback, even if the timeout delay is 0.

order.js
console.log("1");
setTimeout(() => console.log("2 - macrotask"), 0);
Promise.resolve().then(() => console.log("3 - microtask"));
console.log("4");
// Output: 1, 4, 3 - microtask, 2 - macrotask
13. map(), filter(), reduce()

What does each of map, filter and reduce do?

map() transforms every element and returns a new array of the same length. filter() returns a new, possibly shorter, array containing only elements that pass a test. reduce() folds the whole array down into a single accumulated value (a number, object, or anything else) using a callback and a starting value.

array-methods.js
const nums = [1, 2, 3, 4];
nums.map(n => n * 2);              // [2, 4, 6, 8]
nums.filter(n => n % 2 === 0);   // [2, 4]
nums.reduce((sum, n) => sum + n, 0); // 10
14. Destructuring

What is destructuring and why is it useful?

Destructuring lets you unpack values from arrays or properties from objects into distinct variables in a single, readable statement, instead of accessing each one individually. It also supports default values, renaming, and nested patterns.

destructure.js
const [first, second] = [10, 20];
const { name, age = 18 } = { name: "Sam" };
const { user: { email } } = { user: { email: "a@b.com" } };
15. Spread vs Rest Operator

What's the difference between spread and rest, given they use the same "..." syntax?

Spread expands an iterable into individual elements — used when copying/merging arrays or objects, or passing array items as separate function arguments. Rest does the opposite: it collects multiple values into a single array — used in function parameters or destructuring to gather the "remaining" items.

spread-rest.js
// Spread — expanding
const merged = [...[1, 2], ...[3, 4]]; // [1,2,3,4]

// Rest — collecting
function sum(...nums) {
  return nums.reduce((a, b) => a + b, 0);
}
16. Prototype & Prototype Chain

What is a prototype in JavaScript?

Every JavaScript object has an internal link ([[Prototype]], accessible via __proto__ or Object.getPrototypeOf) to another object it can inherit properties and methods from. Functions also have a .prototype property used to set up that link for objects created via new.

How does the prototype chain enable inheritance?

When you access a property that doesn't exist directly on an object, the engine looks up the chain of linked prototypes until it finds the property or reaches null. This is how methods defined once on a constructor's prototype are shared across all instances without duplication.

prototype.js
function Animal(name) { this.name = name; }
Animal.prototype.speak = function() {
  console.log(this.name + " makes a sound");
};
const dog = new Animal("Rex");
dog.speak(); // found via the prototype chain
17. Debouncing

What is debouncing and when would you use it?

Debouncing delays running a function until a certain amount of time has passed without the triggering event firing again — each new call resets the timer. It's ideal for search-as-you-type inputs, resize handlers, or autosave, where you only want the final call to actually execute.

debounce.js
function debounce(fn, delay) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}
const onSearch = debounce(query => console.log(query), 300);
18. Throttling

What is throttling and how is it different from debouncing?

Throttling guarantees a function runs at most once every fixed interval, no matter how many times the event fires — unlike debouncing, which waits for the event to stop firing entirely. Throttling is used for scroll listeners, mouse-move handlers, or window resize events where you want steady, regular updates rather than a single delayed one.

throttle.js
function throttle(fn, limit) {
  let waiting = false;
  return (...args) => {
    if (!waiting) {
      fn(...args);
      waiting = true;
      setTimeout(() => waiting = false, limit);
    }
  };
}
19. Currying

What is currying?

Currying transforms a function that takes multiple arguments into a sequence of functions that each take a single argument, returning a new function until all arguments have been supplied. It enables partial application — pre-filling some arguments to create specialized, reusable functions.

curry.js
const multiply = a => b => c => a * b * c;
multiply(2)(3)(4); // 24

const double = multiply(2)(1); // partially applied
double(5); // 10
20. Memoization

What is memoization?

Memoization is an optimization technique that caches the results of expensive function calls keyed by their input arguments, so repeated calls with the same arguments return the cached result instantly instead of recomputing it. It's a direct practical application of closures.

memoize.js
function memoize(fn) {
  const cache = new Map();
  return (arg) => {
    if (cache.has(arg)) return cache.get(arg);
    const result = fn(arg);
    cache.set(arg, result);
    return result;
  };
}
21. Deep Copy vs Shallow Copy

What's the difference between a shallow copy and a deep copy?

A shallow copy (e.g. spread operator, Object.assign) copies only the top-level properties — nested objects/arrays are still shared by reference, so mutating a nested value affects both copies. A deep copy recursively duplicates every nested level so the two objects are fully independent.

How do you create a deep copy?

Common options include structuredClone(obj) (modern, handles most types including dates and circular references), JSON.parse(JSON.stringify(obj)) (simple but loses functions, undefined, and dates), or a recursive custom function / a library like Lodash's cloneDeep.

copy.js
const original = { user: { age: 25 } };
const shallow = { ...original };
shallow.user.age = 30;
console.log(original.user.age); // 30 — affected too!

const deep = structuredClone(original); // fully independent
22. Event Delegation

What is event delegation?

Instead of attaching a listener to every individual child element, event delegation attaches a single listener to a common parent and relies on event bubbling: when a child is clicked, the event bubbles up to the parent, where you inspect event.target to figure out which child triggered it.

Why is it useful?

It reduces memory usage with fewer listeners, and it automatically works for elements added dynamically later, since the listener lives on the stable parent rather than on each child.

delegation.js
document.getElementById("list").addEventListener("click", (e) => {
  if (e.target.tagName === "LI") {
    console.log("Clicked:", e.target.textContent);
  }
});
23. Promise.all() vs Promise.race()

What does Promise.all() do?

Promise.all() takes an array of promises and resolves only when all of them have resolved, returning an array of their results in order. If any single promise rejects, the whole thing rejects immediately with that reason.

What does Promise.race() do, and how does it differ?

Promise.race() settles as soon as the first promise in the array settles — whether it fulfills or rejects — ignoring the rest. It's commonly used to implement timeouts by racing a real request against a timer promise.

promise-combinators.js
Promise.all([p1, p2, p3]).then(results => ...); // waits for all
Promise.race([p1, p2, p3]).then(first => ...);   // first to settle wins
Related: Promise.allSettled() waits for all promises regardless of outcome, and Promise.any() resolves on the first fulfillment, ignoring rejections.
24. Polyfills

What is a polyfill?

A polyfill is a piece of code (usually JavaScript) that implements a feature on older browsers or environments that don't natively support it, so developers can use modern APIs without breaking backward compatibility.

Can you write a polyfill for Array.prototype.map?

Yes — a common interview exercise is reimplementing built-in methods like map, filter, bind, or Promise from scratch to demonstrate understanding of how they work internally.

polyfill.js
Array.prototype.myMap = function(callback) {
  const result = [];
  for (let i = 0; i < this.length; i++) {
    result.push(callback(this[i], i, this));
  }
  return result;
};
25. Output-Based JavaScript Programs

Why do interviewers ask output-based questions?

They test whether you truly understand execution order, closures, hoisting, and the event loop — rather than just definitions — by asking you to predict console output before running the code.

What does the following snippet print, and why?

Each iteration with var shares one single variable, so by the time the timeouts fire the loop has already finished and i is 3 for every callback. With let, each iteration gets its own fresh binding, so the values print as expected.

loop-timeout.js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// Output: 3, 3, 3

for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j), 0);
}
// Output: 0, 1, 2
Practice tip: for every topic above, try writing 2-3 short snippets and predicting the exact console output before checking — it's the fastest way to internalize these concepts.
