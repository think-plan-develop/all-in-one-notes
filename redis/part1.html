1. Redis Fundamentals ⭐

What Is Redis?

Redis is a very fast in-memory key-value data store. Instead of storing data mainly on disk like PostgreSQL, Redis keeps frequently accessed data in RAM.

Node.js ↓ Redis ↓ RAM
redis-cli
SET name "Shivam"
GET name

Here key = name, value = Shivam.

💡 Why is Redis fast? Data lives in memory, operations are simple key-value reads/writes, overhead is low, and everything is optimized specifically for speed.

Redis vs PostgreSQL/MongoDB

RedisPostgreSQL/MongoDB
Mainly memory-basedPrimarily persistent storage
Extremely fastSlower than Redis for simple key/value access
Key-value/data structuresRich database/query capabilities
Commonly used for cache, sessions, tokensCommonly used as primary database
Data can expire automaticallyUsually persistent until explicitly changed/deleted
⚠️ Important: Redis does not normally replace your PostgreSQL/MongoDB database.
Node.js ↓ Redis ──→ Fast/cache data ↓ PostgreSQL ──→ Permanent application data

Redis Server vs Redis Client

Redis Server = the actual Redis database/service. Redis Client = a tool/application that connects to it.

Node.js ── Redis Client ──→ Redis Server

redis-cli is a command-line client.

basic commands
redis-cli                       # open Redis CLI

PING                            # check Redis connection

SET name "Shivam"              # create/update value

GET name                       # read value

DEL name                       # delete key

EXISTS name                    # check whether key exists

EXPIRE name 60                 # expire key after 60 seconds

TTL name                       # check remaining time

SET token abc123 EX 300         # store token for 300 seconds
CommandWhat it does
redis-cliOpen Redis CLI
PINGCheck Redis connection
SET name "Shivam"Create/update value
GET nameRead value
DEL nameDelete key
EXISTS nameCheck whether key exists
EXPIRE name 60Expire key after 60 seconds
TTL nameCheck remaining time
✅ TTL = Time To Live. SET otp 123456 EX 300 means: store otp = 123456, then automatically delete it after 300 seconds. Very useful for OTPs, cache, sessions, refresh tokens, and password-reset tokens.
2. Redis Data Types ⭐⭐⭐

Redis supports several value types — you mainly need to know these five.

String — the simplest type

string
SET name "Shivam"
GET name

Use for: cache, token, counter, simple value. Example key shape: user:1:name → Shivam

Hash — multiple fields under one key

hash
HSET user:101 name "Shivam" role "admin"

HGET user:101 name       # read one field
HGETALL user:101          # read everything
user:101 ├── name → Shivam └── role → admin

Useful for representing small objects.

List — an ordered collection

list
LPUSH queue "job1"
LPUSH queue "job2"

RPOP queue              # remove from the other end
job2 → job1

Can be used for simple queue-like processing — though for production Node.js job processing, you'll more commonly reach for BullMQ.

Set — a collection of unique values

set
SADD users:online user1
SADD users:online user2
SADD users:online user1   # not duplicated

SMEMBERS users:online

Useful for: unique users, online users, tags, membership checking.

Sorted Set — a Set with a score

sorted set
ZADD leaderboard 100 user1
ZADD leaderboard 200 user2

ZREVRANGE leaderboard 0 10 WITHSCORES
user1 → 100 user2 → 200

Useful for: leaderboards, rankings, priority-based data.

Remember the purpose of each type:

String
Simple value / cache / token
Hash
Object-like data
List
Ordered items
Set
Unique items
Sorted Set
Unique items + score/ranking
💡 You don't need to memorize every Redis command — just which structure fits which shape of data.
3. TTL & Expiration ⭐⭐⭐

Extremely important in real backend applications — Redis can automatically remove temporary data after a specified time.

Setting expiration

ttl
SET otp:9876 123456 EX 300
Key: otp:9876 Value: 123456 TTL: 300 seconds # after 300 seconds: otp:9876 → automatically removed
CommandWhat it does
EXPIRE key 60Set expiration on an existing key
TTL keyCheck remaining time
SET key value EX 300Set value + expiration together (seconds)
SET key value PX 5000Set expiration in milliseconds
PERSIST keyRemove expiration, make the key persistent

Common backend examples

OTP ↓ Redis ↓ Expire after 5 minutes Refresh Token ↓ Redis ↓ Expire after 7 days API Cache ↓ Redis ↓ Expire after 5 minutes
✅ The core concept: Redis can automatically remove temporary data after a specified time — no cron job or cleanup script required.
4. Redis with Node.js ⭐⭐⭐⭐⭐

Install & connect

terminal
npm install redis
redis.js
import { createClient } from "redis";

const redis = createClient({
  url: process.env.REDIS_URL
});

redis.on("error", (err) => {
  console.error("Redis Error:", err);
});

await redis.connect();

Now Node.js can communicate with Redis.

Store, read, TTL, delete

store
await redis.set("name", "Shivam");
read
const name = await redis.get("name");
console.log(name);   // Shivam
store with TTL
await redis.set("otp", "123456", {
  EX: 300
});
otp ↓ 123456 ↓ expires after 300 seconds
delete
await redis.del("otp");

Where should Redis code go?

Don't put Redis operations directly inside controllers — keep a clean layered structure:

src/ │ ├── config/ │ └── redis.js │ ├── services/ │ └── cache.service.js │ ├── controllers/ │ ├── routes/ │ └── server.js
Controller ↓ Service ↓ Redis
✅ Keeping Redis calls inside a service layer (not controllers) makes your application far easier to maintain and test.
Key Takeaways
💡 What You Should Remember From These 4 Steps
The Core Four
What is Redis, in one line?
A fast in-memory data store — data lives in RAM instead of primarily on disk, which is what makes reads and writes so quick.
What are the 5 core Redis data types?
String, Hash, List, Set, Sorted Set — covering simple values, object-like data, ordered items, unique items, and ranked/scored items respectively.
What does TTL let you do?
Automatically expire temporary data — OTPs, sessions, tokens, and cache entries can all be set to disappear on their own after a fixed time, with no manual cleanup needed.
How does Node.js talk to Redis?
Through the official redis npm package — create a client with createClient(), connect() it, then use set, get, and del just like the CLI equivalents, ideally from inside a service layer rather than directly in controllers.
