HashMap vs HashSet

Hash-based structures turn many O(n²) problems into O(n) by giving fast lookups. Quick revision for DSA and JavaScript interviews.

01The big pictureMap vs Set

HashMap · Map

Stores key → value pairs.

Asks: “What is associated with this key?”

Use for: counting, lookups, caching, indexing.

"Shivam" → 25"Rahul" → 30

HashSet · Set

Stores unique values only.

Asks: “Have I seen this value?”

Use for: deduplication, membership checks, visited tracking.

One-line ruleNeed to remember something about an item → Map. Only need to know whether it exists → Set. A Set is conceptually a Map that keeps only keys.
02How hashing worksavg O(1)
key "Shivam"→hash function→bucket 7→value 25
  1. A hash function converts the key into a number.
  2. That number maps to a bucket (an index in an internal array).
  3. The entry is stored there and found again the same way.

Collisions: two keys, same bucket

  • Chaining: each bucket holds a small list of entries.
  • Open addressing: probe for the next free slot.

You don’t implement this in JavaScript, but interviewers often ask. Why average O(1) but worst-case O(n)? With a good hash function entries spread evenly, so each operation touches few items. If many keys collide, one bucket grows long and operations degrade toward O(n). In practice, treat them as O(1) average.

04HashSet (Set)unique values

Adding a duplicate is silently ignored.

set.js
const set = new Set();

set.add(101);
set.add(102);
set.add(103);
set.add(101);        // ignored, already present

console.log(set);    // Set(3) { 101, 102, 103 }
set.has(102);        // true

set.delete(103);
set.size;            // 2

// Handy: remove duplicates from an array
const unique = [...new Set([1, 2, 2, 3, 3])]; // [1, 2, 3]

05JavaScript-specific detailsgotchas
  • Insertion order is preserved. Both iterate in the order items were added.
  • Any type can be a key. Objects, functions and numbers are not converted to strings.
  • Objects and arrays compare by reference. new Set([[1,2],[1,2]]) has size 2. To dedupe by content, use a string key like JSON.stringify(arr) or arr.join(",").
  • Equality is SameValueZero: NaN equals NaN, and 0 equals -0.
  • Map vs plain {}: Map allows any key type, has size, keeps order, and has no inherited keys like "constructor".
  • Printing: JSON.stringify(new Map()) gives {}. Convert first with [...map] or Object.fromEntries(map).

06 Core patterns

Six patterns that cover most hash-based interview problems

6.1Find duplicatesSet · O(n)
findDuplicates.js
function findDuplicates(arr) {
  const seen = new Set();
  const duplicates = new Set();

  for (const num of arr) {
    if (seen.has(num)) duplicates.add(num);
    else seen.add(num);
  }
  return [...duplicates];
}

findDuplicates([1, 2, 3, 2, 4, 1]); // [2, 1]
  1. 1, 2, 3 are new → into seen.
  2. Second 2 is already seen → into duplicates.
  3. 4 is new.
  4. Second 1 is already seen → into duplicates.

Time O(n), space O(n). Result is [2, 1] because 2 is detected first.

6.2Count frequencyMap · O(n)
countFrequency.js
function countFrequency(arr) {
  const map = new Map();

  for (const num of arr) {
    map.set(num, (map.get(num) ?? 0) + 1);
  }
  return map;
}

[...countFrequency([1, 2, 3, 2, 4, 1])];
// [[1, 2], [2, 2], [3, 1], [4, 1]]

Read 1 → 2 as “1 appears twice”.

Tip: ?? vs ||Use ?? 0, not || 0. When a stored value can legitimately be 0 or "", || treats it as missing. ?? only falls back on null or undefined.
6.3Store what you’ve seen, find a match (Two Sum)Map · O(n)

Return the indices of two numbers that add up to a target.

twoSum.js
function twoSum(nums, target) {
  const indexOf = new Map(); // value -> index

  for (let i = 0; i < nums.length; i++) {
    const need = target - nums[i];
    if (indexOf.has(need)) return [indexOf.get(need), i];
    indexOf.set(nums[i], i);
  }
  return [];
}

twoSum([2, 7, 11, 15], 9); // [0, 1]

Brute force is O(n²); with a Map it’s O(n) time and O(n) space. A Set isn’t enough because you must return the index, which is extra data tied to each value.

6.4Group items by a computed key (Group Anagrams)Map

Words with the same sorted letters share a key.

groupAnagrams.js
function groupAnagrams(words) {
  const groups = new Map();

  for (const word of words) {
    const key = word.split("").sort().join("");
    if (!groups.has(key)) groups.set(key, []);
    groups.get(key).push(word);
  }
  return [...groups.values()];
}

groupAnagrams(["eat", "tea", "tan", "ate", "nat", "bat"]);
// [["eat","tea","ate"], ["tan","nat"], ["bat"]]
6.5Fast existence checks to avoid sortingSet · O(n)

Longest consecutive sequence: only start counting from numbers with no predecessor.

longestConsecutive.js
function longestConsecutive(nums) {
  const set = new Set(nums);
  let best = 0;

  for (const num of set) {
    if (!set.has(num - 1)) {          // start of a sequence
      let current = num;
      let length = 1;
      while (set.has(current + 1)) {
        current++;
        length++;
      }
      best = Math.max(best, length);
    }
  }
  return best;
}

longestConsecutive([100, 4, 200, 1, 3, 2]); // 4  (1,2,3,4)
6.6Prefix sum + Map (Subarray Sum Equals K)Map · O(n)

Count subarrays whose sum is k.

subarraySum.js
function subarraySum(nums, k) {
  const counts = new Map([[0, 1]]); // prefix sum -> times seen
  let sum = 0;
  let result = 0;

  for (const num of nums) {
    sum += num;
    result += counts.get(sum - k) ?? 0;
    counts.set(sum, (counts.get(sum) ?? 0) + 1);
  }
  return result;
}

subarraySum([1, 2, 3], 3); // 2  ([1,2] and [3])

08Common mistakesavoid these
Watch outMost hash-structure bugs fall into the six cases below.
  • arr.includes(x) or arr.indexOf(x) inside a loop is O(n) per call, so O(n²) overall. Put the data in a Set first.
  • Writing set.length or map.length. Use .size.
  • Expecting arrays or objects to dedupe by content in a Set. They compare by reference.
  • Using || instead of ?? when counting or defaulting values.
  • Using a plain {} as a map and hitting "constructor" or "__proto__", or forgetting keys become strings.
  • Forgetting the space cost: both use O(n) extra memory. State this in interviews.
09Likely interview questionstap to reveal
Difference between Map and Set?
A Map stores key-value pairs, a Set stores unique values. Both give average O(1) add, lookup and delete.
How do you handle collisions?
Chaining (each bucket stores a list) or open addressing (probe for another slot). Good hash functions and resizing keep collisions rare.
What is the worst-case time?
O(n), when many keys collide into one bucket.
Map vs object?
See section 05. Map supports any key type, preserves order, has .size, and avoids prototype-key issues.
Is the order of a Set guaranteed in JavaScript?
Yes, insertion order. This isn’t true of hash sets in every language (for example, Java’s HashSet).

11Test your understandingquiz

You have an array of 1 million numbers. You need to check whether a number has already appeared, without storing its frequency. Which data structure fits best?

A. HashMap (Map)B. HashSet (Set)C. Nested loopsD. Sorting is always required
Show answer
B (HashSet). A Set gives average O(1) membership checks and stores only the values you need. A Map works but stores unused values. Nested loops are O(n²), far too slow for a million items. Sorting isn’t required and costs O(n log n).
