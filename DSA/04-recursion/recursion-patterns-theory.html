1Check if an Array Is Sorted

1.1Concept

An array is sorted in ascending order if every element is less than or equal to the element immediately after it.

[1, 2, 3, 4, 5]Sorted
[1, 3, 2, 4, 5]Not sorted
[5]Sorted
[ ]Sorted by convention
Idea

Compare two adjacent elements, then recursively check the remaining array.

1.2JavaScript recursive approach

function isSorted(arr, index = 0) {
  // Base case: reached the last element
  if (index >= arr.length - 1) {
    return true;
  }

  // If the current pair is out of order
  if (arr[index] > arr[index + 1]) {
    return false;
  }

  // Check the remaining elements
  return isSorted(arr, index + 1);
}

console.log(isSorted([1, 2, 3, 4, 5])); // true
console.log(isSorted([1, 3, 2, 4, 5])); // false

1.3Base case and recursive condition

Base caseindex >= arr.length - 1

No more adjacent pairs need checking, so return true.

Failure conditionarr[index] > arr[index + 1]

The array is not sorted, so return false immediately.

Recursive callisSorted(arr, index + 1)

Move one position forward.

1.4Trace the execution

For isSorted([1, 2, 3]):

1 ≤ 2 ✓→2 ≤ 3 ✓→Base case→returns true

If any comparison fails, the function returns false without checking the remaining elements.

1.5Time and auxiliary space complexity

CaseTimeAuxiliary space
Best case (first pair fails)O(1)O(1)
Worst case (all pairs checked)O(n)O(n)
Extra array allocatedNo
Why is auxiliary space O(n)?

Each recursive call adds a stack frame, and in the worst case there are about n frames. The input array is not counted as auxiliary space.

2Divide and Conquer

2.1Concept

An algorithm design technique that breaks a problem into smaller subproblems, solves them, and combines their results when necessary.

1 · Divide

Break the problem into smaller parts.

2 · Conquer

Solve the smaller problems, often recursively.

3 · Combine

Combine subproblem results if required.

Remember

Not every divide-and-conquer algorithm needs a substantial combine step. Binary search discards one half and continues searching the other half.

2.2Example: Pow(x, n) — LeetCode 50

Calculate xn efficiently. Instead of multiplying x by itself n times, use these rules:

  • If n = 0, return 1.
  • If n is even, xn = xn/2 × xn/2.
  • If n is odd, xn = xn−1 × x.

A more efficient implementation squares the half-result.

function myPow(x, n) {
  if (n === 0) return 1;

  // Handle negative exponents
  if (n < 0) return 1 / myPow(x, -n);

  const half = myPow(x, Math.floor(n / 2));

  if (n % 2 === 0) {
    return half * half;
  }

  return half * half * x;
}

console.log(myPow(2, 10)); // 1024
console.log(myPow(2, -2)); // 0.25
Edge case

For the full LeetCode constraints, the minimum signed 32-bit exponent needs special handling because negating it exceeds the signed 32-bit range. The approach above illustrates the core recursion.

For 210, the exponent shrinks quickly, so the number of calls grows logarithmically rather than linearly:

10→5→2→1→0
ComplexityResult
TimeO(log |n|)
Auxiliary spaceO(log |n|) due to recursion

2.3Example: Merge Two Sorted Lists — LeetCode 21

Given two sorted linked lists, merge them into one sorted linked list.

Divide

Compare the current nodes of both lists.

Conquer

Recursively merge the remaining nodes.

Combine

Attach the smaller current node to the merged result.

function mergeTwoLists(list1, list2) {
  if (list1 === null) return list2;
  if (list2 === null) return list1;

  if (list1.val <= list2.val) {
    list1.next = mergeTwoLists(list1.next, list2);
    return list1;
  }

  list2.next = mergeTwoLists(list1, list2.next);
  return list2;
}

This reuses the existing nodes instead of allocating a new node for each value.

  • Time: O(n + m), where n and m are the list lengths.
  • Auxiliary space: O(n + m) for the recursive call stack in the worst case.
Strictly speaking

This is a recursive merging algorithm. It is not the classic divide-and-conquer pattern of splitting one input into independent halves, as in merge sort.

3Call Stack — Theory

3.1How recursive function calls are stored

Whenever a function is called, JavaScript creates a stack frame to track that function's execution. A frame can contain parameters, local variables, and the information needed to resume execution after another function returns.

The call stack follows LIFO (Last In, First Out):

  • The most recently called function is the first one to finish.
  • A recursive call creates another stack frame.
  • When the base case is reached, the functions return in reverse order.

3.2Example: Recursive countdown

function countdown(n) {
  if (n === 0) {
    console.log("Done");
    return;
  }

  console.log(n);
  countdown(n - 1);
}

countdown(3);
3
2
1
Done

How the call stack changes

Phase 1 — calls are added

countdown(3)waiting
countdown(2)waiting
countdown(1)waiting
countdown(0)base case

Phase 2 — calls finish in reverse

countdown(0)1st returns
countdown(1)2nd returns
countdown(2)3rd returns
countdown(3)4th returns

Each call waits for the next call to finish before it can continue. Here there is no extra work after the recursive call, but the stack still keeps track of the active calls.

3.3Function call and return order

function sum(n) {
  if (n === 0) return 0;

  return n + sum(n - 1);
}

console.log(sum(3)); // 6

The calls go downward until the base case, and the addition happens while returning:

StageCalculationResult
Base casesum(0)0
Returnsum(1) = 1 + sum(0)1
Returnsum(2) = 2 + sum(1)3
Returnsum(3) = 3 + sum(2)6
Key distinction

Recursive calls happen on the way down. Pending operations such as n + ... are completed on the way back up.

3.4Stack space complexity

Recursive patternMaximum stack space
One call per elementO(n)
Halve the input each callO(log n)
Constant number of nonrecursive callsO(1)

For example, sum(n) uses O(n) stack space because it can have n + 1 active calls before returning.

3.5Stack overflow

A stack overflow happens when the call stack exceeds the runtime's supported capacity. It often occurs when:

  • The recursion has no reachable base case.
  • The input is very large and recursion is too deep.
  • Each recursive call fails to make progress toward termination.
function badRecursion(n) {
  return badRecursion(n - 1); // No base case
}

This eventually throws a RangeError in typical JavaScript environments.

Interview rule

Always identify a valid base case and prove that each recursive call moves toward it.

4Memoization — Theory and Problem

4.1What is memoization?

An optimization technique that stores the results of previously solved subproblems so they can be reused instead of recalculated. It is particularly useful when a recursive problem has overlapping subproblems.

  1. Check whether the answer is already stored.
  2. If it is, return the stored answer.
  3. Otherwise, calculate the answer recursively.
  4. Save the result and return it.

4.2Overlapping subproblems

Fibonacci numbers: F(n) = F(n−1) + F(n−2), with F(0) = 0 and F(1) = 1.

The naive recursive version calculates the same smaller values repeatedly: fib(5) needs both fib(4) and fib(3), and fib(4) needs fib(3) again. Here is how many times each value is computed in fib(5):

fib(5)
1×
fib(4)
1×
fib(3)
2×
fib(2)
3×
fib(1)
5×
fib(0)
3×

15 calls for only 6 distinct values. That repeated work is why naive Fibonacci takes exponential time.

4.3Fibonacci without memoization

function fib(n) {
  if (n <= 1) return n;

  return fib(n - 1) + fib(n - 2);
}

console.log(fib(6)); // 8
  • Time: O(2n) as a common upper bound.
  • Auxiliary space: O(n) due to maximum recursion depth.

The exact number of calls follows a Fibonacci-like growth pattern, so the runtime is exponential.

4.4Fibonacci with memoization

Use a cache to remember the results of previously calculated values.

function fib(n, memo = {}) {
  if (n <= 1) return n;

  if (memo[n] !== undefined) {
    return memo[n];
  }

  memo[n] = fib(n - 1, memo) + fib(n - 2, memo);

  return memo[n];
}

console.log(fib(6)); // 8

Here, memo[n] stores the answer for each Fibonacci index. Once fib(4) has been calculated, later calls can reuse that answer.

4.5Time and auxiliary space comparison

FeatureWithout memoizationWith memoization
Time complexityO(2n) upper boundO(n)
Recursion stackO(n)O(n)
Cache memoryNone (O(1))O(n)
Repeated calculationsYesAvoided for cached states
Best useUnderstanding recursionEfficient overlapping subproblems
Important

With memoization the auxiliary space remains O(n), counting both the cache and the recursion stack. The cache stores up to n − 1 non-base results, and the stack depth is also linear.

4.6When should you use memoization?

  • The same subproblem is solved multiple times.
  • The result of a subproblem depends on smaller subproblems.
  • Previously calculated answers can be stored and reused.

Examples: Fibonacci, climbing stairs, and regular expression matching.

Not always useful

Memoization does not help every recursive problem. Checking whether an array is sorted usually has no overlapping subproblems to eliminate.
