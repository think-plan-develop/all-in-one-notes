1 Fundamentals

Time vs space, Big O, input size, execution time and auxiliary space

01.01★ What are time complexity and space complexity?O(n) time · O(1) space▼

Time complexity describes how the amount of work grows as the input size increases.

Space complexity describes how the memory required grows as the input size increases.

Consider this JavaScript function:

sumArray.js
function sumArray(arr) {
  let total = 0;

  for (let i = 0; i < arr.length; i++) {
    total += arr[i];
  }

  return total;
}

sumArray([10, 20, 30, 40]); // 100

Let n represent the number of elements in arr.

Input sizeLoop iterations
4 elements4
100 elements100
1,000 elements1,000
⏱ Time complexityO(n)
💾 Auxiliary spaceO(1)

The loop visits every element once. Therefore, time complexity is O(n).

The function uses only a fixed number of extra variables: total and i. Therefore, auxiliary space is O(1).

RememberUpdating total 1,000 times does not create 1,000 variables. The same variable is reused.
01.02★ What is Big O, and how do we simplify complexity?upper bound▼
DefinitionBig O describes an upper bound on how an algorithm’s work or memory grows for large inputs. In everyday complexity analysis, we usually give the closest useful bound.
NotationMeaningSimple example
O(1)Constant growth: work stays bounded independently of input sizeRead arr[0]
O(n)Linear growth: work grows proportionally to input sizeVisit every array element
O(n²)Quadratic growth: work grows proportionally to the square of input sizeAn n-iteration loop inside another n-iteration loop
CarefulO(1) does not mean exactly one operation. A fixed sequence of 10 operations can also be O(1).

Big O ignores constant multipliers and lower-order terms:

Work expressionBig O
5O(1)
2n + 3O(n)
n² + n + 5O(n²)

For example, two separate full-array loops perform roughly n + n = 2n iterations. Their combined time complexity is O(n).

Not the same as worst caseAlso, Big O does not automatically mean worst case. We can describe best-case, average-case, or worst-case growth using Big O; specify which case you mean when it matters.
01.03Why do we calculate complexity?4 reasons▼

We calculate it to:

  • ⚖️
    Compare approaches:understand which one scales better.
  • 🔮
    Predict performance:identify code that may become slow with large inputs.
  • 💾
    Estimate memory needs:avoid creating unnecessarily large arrays or other structures.
  • 🔄
    Understand trade-offs:using extra memory can sometimes reduce the amount of work.

Suppose two approaches perform approximately n and n² operations. For n = 10,000:

Linear: n10,000operations
vs
Quadratic: n²100,000,000operations

This difference becomes significant as the input grows. However, complexity alone does not guarantee which implementation is faster for a small input.

01.04How do input size and growth rate relate?n, m▼

n means the size of the input being processed. Its meaning depends on the problem.

input size
const numbers = [10, 20, 30, 40, 50];
// n = 5 elements

const word = "hello";
// n = 5 characters

A problem with two arrays may use n and m for their separate lengths.

Growth rate describes how quickly the amount of work increases as the input grows.

The following numbers illustrate growth patterns, rather than exact operation counts:

Growth patternn = 10n = 100n = 1,000
Constant: 1111
Linear: n101001,000
Quadratic: n²10010,0001,000,000
10× larger inputWhen the input becomes 10 times larger, linear work becomes roughly 10 times larger, while quadratic work becomes roughly 100 times larger.
01.05Time complexity vs execution time: what is the difference?not seconds▼
Time complexityExecution time
Describes how work growsMeasures how long a particular run takes
Expressed as O(1), O(n), O(n²), etc.Expressed in milliseconds, seconds, etc.
Derived by analysing the algorithmMeasured by running the code
Does not change just because the computer is fasterDepends on hardware, runtime, input, and other conditions

The sumArray() function remains O(n) on both a slow laptop and a fast laptop, although its execution time may differ.

RememberO(n) does not mean “n seconds.”
01.06★ Auxiliary space vs total space: what should we count?O(1) vs O(n)▼

Auxiliary space is the extra working memory an algorithm needs beyond its input.

Total space includes the input’s memory as well as the additional memory used during execution. Output memory, when relevant, may be reported separately; state the convention you use.

For the earlier sumArray() example:

Memory componentSpace required
Input array containing n numbersO(n)
Extra variables total and iO(1)
Auxiliary spaceO(1)
Total spaceO(n)

The calculation is:

calculation
Total space = input space + extra space
            = O(n) + O(1)
            = O(n)

Now suppose the function creates a working copy before processing the array:

working copy
const workingCopy = [...arr];

That copy stores another n elements, so auxiliary space becomes O(n). Total space is still O(n) because n + n = 2n, and Big O ignores the constant multiplier.

Say it clearlyIn DSA discussions, “space complexity” often refers to auxiliary space. For clarity, say: “O(n) time and O(1) auxiliary space.”

2 Growth classes

Count how many times the work happens as the input grows

The main rule: count how many times the work happens as the input grows. A for loop and a while loop can have the same complexity. In these examples, n is a positive input size, and simple operations such as count++ take constant time.
02.01★ Understand O(1) — constant time.O(1)▼
getFirst.js
function getFirst(arr) {
  return arr[0];
}

Whether the array contains 10 elements or 10 lakh elements, we access only its first element.

CarefulO(1) does not mean exactly one operation. A fixed number of operations is still constant.
getEnds.js
function getEnds(arr) {
  const first = arr[0];
  const last = arr[arr.length - 1];

  return first + last;
}

This is also O(1).

02.02★ Understand O(log n) — logarithmic time.O(log n)▼

Think of repeatedly halving a collection until only one item remains. For 16 items:

16÷28÷24÷22÷21

That takes 4 halvings, so log₂(16) = 4.

Doubling a counter produces the same logarithmic pattern:

doubling.js
let count = 0;

for (let i = 1; i < n; i *= 2) {
  count++;
}

For n = 16, the loop runs at:

values of i
i = 1, 2, 4, 8

When i becomes 16, the condition fails. There are 4 iterations.

Input sizeIterations
164
325
646
RememberDoubling the input adds only one iteration.

Binary search follows this idea: each comparison removes about half of the remaining search area.

We generally write O(log n) without a base because changing between fixed logarithm bases only changes a constant factor.

02.03★ Understand O(n) — linear time.O(n)▼
sumArray.js
function sumArray(arr) {
  let total = 0;

  for (let i = 0; i < arr.length; i++) {
    total += arr[i];
  }

  return total;
}

The loop visits each element once.

  • 10 elements → 10 iterations.
  • 100 elements → 100 iterations.
  • 1,000 elements → 1,000 iterations.
RememberDouble the input → roughly double the work.
02.04★ Understand O(n log n) — linearithmic time.O(n log n)▼
nested-doubling.js
let count = 0;

for (let i = 0; i < n; i++) {
  for (let j = 1; j < n; j *= 2) {
    count++;
  }
}

The outer loop runs n times. For every outer iteration, the inner loop starts again at 1 and runs about log₂(n) times.

total work
Total work = n × log₂(n)

For n = 8, the inner loop visits 1, 2, 4: three iterations.

count
8 outer iterations × 3 inner iterations = 24

Therefore, the complexity is O(n log n). Merge sort is a common algorithm with this time complexity.

02.05★ Understand O(n²) — quadratic time.O(n²)▼
nested.js
let count = 0;

for (let i = 0; i < n; i++) {
  for (let j = 0; j < n; j++) {
    count++;
  }
}

For each outer iteration, the inner loop runs n times.

total work
Total work = n × n = n²

With n = 4, the body runs 16 times.

RememberDouble the input → roughly four times the work.
02.06Understand O(2ⁿ) — exponential time.O(2ⁿ)▼
explore.js
function explore(n) {
  if (n === 0) return;

  explore(n - 1);
  explore(n - 1);
}

Each non-base call makes two more calls.

Recursion depthCalls at that depth
01
12
24
38

The recursion continues down to depth n. The total number of calls is:

total calls
1 + 2 + 4 + ... + 2ⁿ

This grows as O(2ⁿ).

RememberIncreasing n by just 1 roughly doubles the work.

This differs from O(n²): in 2ⁿ, the input is the exponent.

02.07Understand O(n!) — factorial time.O(n!)▼

Factorial means:

factorial
4! = 4 × 3 × 2 × 1 = 24

For example, arranging four distinct items gives four choices for the first position, three for the next, then two, then one.

1st4choices

2nd3choices

3rd2choices

orders244!

This code demonstrates factorial growth:

exploreOrders.js
function exploreOrders(n) {
  if (n <= 1) return;

  for (let i = 0; i < n; i++) {
    exploreOrders(n - 1);
  }
}

Each call makes n smaller calls; those make n − 1 calls each, and so on.

Two different thingsCalculating the value n! is different from doing factorial amounts of work. You can calculate n! using one loop in O(n) time under the usual constant-time arithmetic model.

There are n! permutations of n distinct items. Explicitly copying or printing all n items of every permutation adds another factor of n.

For sufficiently large inputs, the growth functions increase in this order:
1<log n<n<n log n<n²<2ⁿ<n!

3 Reading loops

Single and consecutive loops use the same counting approach

03.01★ Calculate the complexity of a single loop.O(n)▼
while.js
let i = 0;
let total = 0;

while (i < n) {
  total += i;
  i++;
}

i visits 0 through n - 1, so there are n iterations. Each iteration does constant work:

work
n iterations × O(1) work = O(n)

Writing this as a for loop would not change its complexity.

CarefulAlso, one loop does not automatically mean O(n). The doubling loop shown earlier is O(log n).
03.02★ Calculate the complexity of consecutive loops.O(n + n) = O(n)▼
consecutive.js
let count = 0;

for (let i = 0; i < n; i++) {
  count++;
}

for (let j = 0; j < n; j++) {
  count++;
}

The first loop finishes before the second starts:

sum
n + n = 2n → O(n)

These loops are O(n), not O(n²).

ArrangementWorkComplexity
Two consecutive n-iteration loopsn + nO(n)
Three consecutive n-iteration loopsn + n + nO(n)
An n-iteration loop inside anothern × nO(n²)
An O(n) loop followed by O(n²) workn + n²O(n²)
03.03Analyse loops with different step sizes.step size▼

Assuming constant work inside each loop:

LoopApproximate iterationsComplexity
for (let i = 0; i < n; i++)nO(n)
for (let i = 0; i < n; i += 2)n / 2O(n)
for (let i = 0; i < n; i += 10)n / 10O(n)
for (let i = n; i > 0; i--)nO(n)
for (let i = 1; i < n; i *= 2)log₂ nO(log n)
for (let i = 1; i < n; i *= 3)log₃ nO(log n)
Rule of thumbAdding a fixed amount usually gives linear growth. Multiplying by a fixed factor greater than 1 usually gives logarithmic growth.

For example:

step2.js
for (let i = 0; i < n; i += 2) {
  // Constant work
}

This processes about half the indices, but n / 2 still grows proportionally to n.

Be careful when the step depends on the input:

step-n.js
for (let i = 0; i < n; i += n) {
  // Runs once for positive n
}

This is O(1).

03.04★ Analyse early break and return statements.best vs worst▼
findIndex.js
function findIndex(arr, target) {
  for (let i = 0; i < arr.length; i++) {
    if (arr[i] === target) {
      return i;
    }
  }

  return -1;
}
SituationElements checkedComplexity
Target is first1Best case: O(1)
Target is lastnWorst case: O(n)
Target is absentnWorst case: O(n)
Key ideaAn early return can improve a particular run without changing the worst-case complexity.

A guaranteed fixed stopping point is different:

fixed-break.js
for (let i = 0; i < n; i++) {
  if (i === 3) break;
}

This loop executes at most four times, regardless of how large n becomes. It is O(1).

break exits the loop; return exits the function.

03.05Calculate array and string traversal complexity.O(n)▼

Array:

array.js
let total = 0;

for (const value of arr) {
  total += value;
}

Time: O(n), where n is the number of array elements.

String:

string.js
let count = 0;

for (const char of text) {
  if (char === "a") {
    count++;
  }
}

Time: O(n) in the string’s length.

Watch the bodyHowever, if the loop body calls another function, include that function’s cost. A function call is not automatically O(1).
03.06Analyse two independent inputs: O(n + m).O(n + m)▼
sumBoth.js
function sumBoth(arr1, arr2) {
  let total = 0;

  for (const value of arr1) {
    total += value;
  }

  for (const value of arr2) {
    total += value;
  }

  return total;
}

Here, n = arr1.length and m = arr2.length.

work
Total work = n + m
Time complexity = O(n + m)

Keep both variables because the arrays can have different lengths.

Compare that with nested loops:

pairs.js
let comparisons = 0;

for (const a of arr1) {
  for (const b of arr2) {
    comparisons++;
  }
}

Every element of the first array is paired with every element of the second:

work
Total work = n × m
Time complexity = O(nm)
