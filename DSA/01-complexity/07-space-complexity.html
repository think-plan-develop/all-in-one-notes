Notes: Space complexity in JavaScript

Quick-reference notes with examples and practice

1. Types of space complexity ★

Space complexity measures how much memory an algorithm uses as the input size n grows, just as time complexity measures the growth of operations.

TypeMeaningExample
Input spaceMemory occupied by the input dataInput array of n elements
Auxiliary space ★Extra memory used by the algorithm while processingVariables, Map, Set, temporary arrays, recursion stack
Output spaceMemory occupied by the generated resultNew array returned by a function
Total Space = Input Space + Auxiliary Space

In DSA interviews, “space complexity” usually means auxiliary space unless total space is explicitly requested.

2. O(1) — constant space ★★★

Memory use does not increase with input size.

sum.js
function sum(arr) {
  let total = 0;
  for (let i = 0; i < arr.length; i++) {
    total += arr[i];
  }
  return total;
}
  • arr is the input array, not counted in auxiliary space.
  • total and i are single variables; there is no extra array, Map or Set.

Time: O(n) · Auxiliary space: O(1)

3. O(n) — linear space ★★★

Extra memory grows in proportion to input size.

doubleArray.js
function doubleArray(arr) {
  let result = [];
  for (let i = 0; i < arr.length; i++) {
    result.push(arr[i] * 2);
  }
  return result;
}
// [1, 2, 3, 4] → [2, 4, 6, 8]

Input sizes 5, 10, 100, 1,000 produce result arrays of 5, 10, 100, 1,000. The returned array is O(n) output space; the loop counter and constant-sized bookkeeping use O(1) auxiliary space.

4. O(n²) — quadratic space ★★

createMatrix.js
function createMatrix(n) {
  let matrix = [];
  for (let i = 0; i < n; i++) {
    let row = [];
    for (let j = 0; j < n; j++) row.push(0);
    matrix.push(row);
  }
  return matrix;
}
SpaceComplexityReason
InputO(n)arr contains n elements
AuxiliaryO(1)Only i and constant-sized bookkeeping
OutputO(n)result stores n elements
TotalO(n)Combined memory grows linearly
State your conventionSome definitions include output space within auxiliary space. Others report output space separately. Here, result is reported as output, separately from the O(1) auxiliary variables.

n = 2, 3, 10, 100 store 4, 9, 100, 10,000 elements. Time: O(n²) · Space: O(n²).

5. Nested loops do NOT always mean O(n²) space ★★★

printPairs.js
function printPairs(arr) {
  for (let i = 0; i < arr.length; i++) {
    for (let j = 0; j < arr.length; j++) {
      console.log(arr[i], arr[j]);
    }
  }
}

Only two loop counters exist and no data structure grows. Time: O(n²) · Auxiliary space: O(1).

RememberTime complexity counts operations. Space complexity counts memory usage.

6. Map and Set ★★★

mapSet.js
function removeDuplicates(arr) {
  let unique = new Set(arr);
  return [...unique];
}

function frequencyCount(arr) {
  let map = new Map();
  for (let num of arr) {
    map.set(num, (map.get(num) || 0) + 1);
  }
  return map;
}

With k distinct values (k ≤ n), each structure uses O(k) additional space, which is O(n) in the worst case.

7. Recursion and call-stack space ★★★

Even without an extra array, recursion consumes stack memory: every call adds a frame until the base case.

countdown.js
function countdown(n) {
  if (n === 0) return;
  console.log(n);
  countdown(n - 1);
}
countdown(4); // 5 active calls at max depth (4,3,2,1,0)

function countdownLoop(n) {
  for (let i = n; i > 0; i--) console.log(i);
}

Recursive: time O(n), auxiliary space O(n). Iterative: time O(n), auxiliary space O(1).

9. Practice: identify the space complexity

Q1. let a = 10; let b = 20; let c = a + b;
O(1) — fixed variables.
Q2. let result = []; for (i < n) result.push(i);
O(n) — the array grows with n.
Q3. Two nested loops over n that only console.log(i, j)
O(1) — nothing grows; only O(n²) time.
Q4. Array.from({ length: n }, () => Array(n).fill(0))
O(n²) — n independent rows of n cells.
Q5. function solve(n){ if (n <= 1) return; solve(Math.floor(n/2)); }
O(log n) — stack depth halves each call.

10. Simple trick to remember

  • O(1): fixed extra variables, regardless of n.
  • O(log n): stack depth grows by repeatedly halving input.
  • O(n): extra array, Map, Set, or recursion depth grows with n.
  • O(n²): extra 2D matrix with n × n elements.
Interview ruleIdentify the extra variables, arrays, objects, Map/Set entries and recursion stack, then check how their total memory grows with n. Do not decide from the number of loops alone.

07.03O(n²): how much space does a matrix or 2D array use?O(rows × cols)

A dense matrix with n rows and n columns contains n × n = n² cells.

07-03-1.js
const n = 4;
const grid = Array.from(
  { length: n },
  () => Array(n).fill(0)
);

grid[0][0] = 9;

console.log(grid[0][0]); // 9
console.log(grid[1][0]); // 0 — a different row

The outer array also stores n row references. The dominant storage is n² cells:

n² cells + n row references + fixed overhead → O(n²)

A 2D array is not always O(n²). Keep independent dimensions separate:

07-03-2.js
const rows = 3;
const cols = 5;
const grid = Array.from(
  { length: rows },
  () => Array(cols).fill(0)
);

console.log(grid.length * grid[0].length); // 15
ShapeNumber of cellsStorage for positive dimensions
n × nn²O(n²)
rows × colsrows × colsO(rows × cols)
n × 33nO(n)
Working memory or output?A newly created matrix used internally counts as auxiliary space. If the matrix is the returned result, classify its storage as output under this guide’s convention. An already-supplied matrix is input space.

JavaScript pitfall: sharing one row.

07-03-3.js
const n = 4;
const wrong = Array(n).fill(Array(n).fill(0));

wrong[0][0] = 9;

console.log(wrong[1][0]); // 9 — the row is shared!

Here, every outer slot points to the same inner array. The separate arrays contain n outer references and one row of n cells: O(n) storage, but not n independent rows. The earlier Array.from callback creates a fresh row each time. [1]

07.06★ Input space vs auxiliary space: what should be included?State the convention

Use three separate buckets:

BucketWhat belongs here?Example
Input spaceData supplied to the algorithmThe original array
Auxiliary spaceExtra working data and active call framesA temporary Set or a working copy
Output spaceNew storage allocated for the returned resultA newly built result array

This guide excludes both the supplied input and the final output from auxiliary space. Other explanations may include output in “extra space.” State which convention you use.

For sumArray(arr):

ComponentSpace
Input array of n fixed-size numbersO(n)
Extra counters and running totalO(1)
Returned numberO(1)
Total storage including the supplied inputO(n)
Total accounted storage = input + auxiliary + newly allocated output

Count distinct allocations once. An output reference that aliases the input is not another copy of the same storage.

Even a large matrix input can be processed with O(1) auxiliary space:

07-06-1.js
function sumMatrix(matrix) {
  let total = 0;

  for (const row of matrix) {
    for (const value of row) {
      total += value;
    }
  }

  return total;
}

console.log(sumMatrix([[1, 2], [3, 4]])); // 10

For an already-supplied n × n matrix, the input takes O(n²) storage. This function creates no second matrix, so its auxiliary space is O(1).

Interview answer“This solution uses O(1) auxiliary space. The supplied n-element input itself occupies O(n) space.”

Measure peak live working storage: the maximum working memory needed at one time. A loop’s total allocation count is a different measurement. JavaScript garbage collection and retained capacity can make measured heap usage differ from this abstract analysis. [2]

Four questions to ask

  • Create?What new storage does this algorithm allocate?
  • Grow?How does each collection grow with n?
  • Live?How much must exist at the same time?
  • Return?Which storage belongs to the final output?

A precise interview answer

“The solution uses O(n) time, O(1) auxiliary space excluding output, and O(n) output space because it returns a newly built array.”
