★ Priority topic · Learn = concept · Pattern = worked example

The main ruleCount the maximum memory that must exist at the same time as the input grows. Include temporary collections and active call frames.
Convention used in this guide

Auxiliary space excludes the supplied input and the final output. We report newly allocated output separately. “Extra space including output” combines working and output storage.

Assume dense arrays, fixed-size numbers and references, and ordinary collection implementations. These are asymptotic DSA estimates, not exact JavaScript heap measurements. Variable-sized payloads must be counted when they matter.

07.01★ O(1): what is constant extra space?O(1)▼

Space complexity describes how the memory required by an algorithm grows with its input. For auxiliary space, count the extra working storage.

An algorithm uses O(1) auxiliary space when this storage stays bounded by a fixed amount as the input grows.

07-01-1.js
function sumArray(arr) {
  let total = 0;

  for (let i = 0; i < arr.length; i++) {
    total += arr[i];
  }

  return total;
}

console.log(sumArray([10, 20, 30, 40])); // 100

The reference to the input, loop counter, and running total use a fixed amount of working storage. The supplied array is input space.

Input length Extra working variables Auxiliary space
4 A fixed number O(1)
1,000 The same fixed number O(1)
10,00,000 The same fixed number O(1)
Auxiliary · excludes outputO(1)
New output storageO(1)
RememberUpdating total a million times reuses the same variable. It does not store a million separate totals.

Time and space can grow differently. This example visits all n elements, so it takes O(n) time and O(1) auxiliary space.

Even a nested loop can use constant auxiliary space:

07-01-2.js
function countPairs(arr) {
  let count = 0;

  for (let i = 0; i < arr.length; i++) {
    for (let j = i + 1; j < arr.length; j++) {
      count++;
    }
  }

  return count;
}

console.log(countPairs([10, 20, 30, 40])); // 6

It performs n(n − 1)/2 increments: O(n²) time. It still keeps only a fixed number of counters: O(1) auxiliary space.

O(1) is a growth rateO(1) does not mean exactly one variable, one byte, or zero memory. Ten fixed-size variables also take O(1) space.
07.02★ O(n): when does extra space grow linearly?O(n)▼

O(n) auxiliary space means the extra working storage grows in proportion to the input size.

Compare this with the previous sum function:

07-02-1.js
function sumUsingCopy(arr) {
  const working = arr.slice();
  let total = 0;

  for (const value of working) {
    total += value;
  }

  return total;
}

console.log(sumUsingCopy([10, 20, 30, 40])); // 100

The function creates a new array containing n elements and uses it as working memory. Only the final number is returned.

Extra working storage = n elements + fixed variables → O(n)
Auxiliary · excludes outputO(n)
New output storageO(1)
  • If n doubles, the copy contains twice as many elements.
  • Two working arrays of n elements each use 2n slots: still O(n) auxiliary space.
  • Working arrays of independent lengths n and m use O(n + m) space.
Why make this copy?This is a memory comparison example. Summing an array does not require a copy; the previous approach uses less auxiliary space.
07.03O(n²): how much space does a matrix or 2D array use?O(rows × cols)▼

A dense matrix with n rows and n columns contains n × n = n² cells.

07-03-1.js
const n = 4;
const grid = Array.from(
  { length: n },
  () => Array(n).fill(0)
);

grid[0][0] = 9;

console.log(grid[0][0]); // 9
console.log(grid[1][0]); // 0 — a different row

The outer array also stores n row references. The dominant storage is n² cells:

n² cells + n row references + fixed overhead → O(n²)

A 2D array is not always O(n²). Keep independent dimensions separate:

07-03-2.js
const rows = 3;
const cols = 5;
const grid = Array.from(
  { length: rows },
  () => Array(cols).fill(0)
);

console.log(grid.length * grid[0].length); // 15
Shape Number of cells Storage for positive dimensions
n × n n² O(n²)
rows × cols rows × cols O(rows × cols)
n × 3 3n O(n)
Working memory or output?A newly created matrix used internally counts as auxiliary space. If the matrix is the returned result, classify its storage as output under this guide’s convention. An already-supplied matrix is input space.

JavaScript pitfall: sharing one row.

07-03-3.js
const n = 4;
const wrong = Array(n).fill(Array(n).fill(0));

wrong[0][0] = 9;

console.log(wrong[1][0]); // 9 — the row is shared!

Here, every outer slot points to the same inner array. The separate arrays contain n outer references and one row of n cells: O(n) storage, but not n independent rows. The earlier Array.from callback creates a fresh row each time. [1]

07.04Variables vs arrays: count the stored data, not just the names.Data & references▼

One variable can refer to a collection containing millions of elements. Count the storage that the algorithm creates or retains, not just the number of variable names.

Code or structure Additional storage under the stated model
A few numbers, booleans or references O(1)
A fixed array of 5 numbers O(1)
A newly filled array with n numbers O(n)
A new object with n fixed-size entries O(n)
An alias to an existing array O(1) for the reference; no new array
A shallow copy of an n-element array O(n) new slots
07-04-1.js
const arr = [{ id: 1 }, { id: 2 }];

const alias = arr;
const copy = [...arr];

console.log(alias === arr);    // true
console.log(copy === arr);     // false
console.log(copy[0] === arr[0]); // true
  • alias: another reference to the existing array.
  • copy: a new outer array. Its two slots refer to the same existing objects.
  • A shallow copy does not duplicate every nested object. [2]
Variable-sized valuesThe usual O(n)-array analysis assumes fixed-size values or references. If you allocate strings or nested data whose sizes also grow, include that payload. For example, n separately allocated strings of length m can require O(nm) character storage.

Reassignment is different from retaining every value. Reusing one running total takes constant space. Appending every intermediate total to an array can take O(n) space.

07.05How much memory do Map and Set use?O(k) entries▼

For normal DSA analysis, a Map with k fixed-size entries or a Set with k stored values uses O(k) collection storage, including ordinary implementation overhead. Exact byte usage depends on the JavaScript engine.

Let n be the number of input elements and k the number of distinct values. Then k ≤ n.

07-05-1.js
function countDistinct(arr) {
  const seen = new Set(arr);
  return seen.size;
}

console.log(countDistinct([2, 2, 3, 4, 4, 4])); // 3
Auxiliary · excludes outputO(k)
New output storageO(1)

The Set is working memory because the returned result is a number. If every input value is different, k = n and the auxiliary space is O(n). If all values are equal, the Set has one entry.

A Map can track counts while returning a scalar result:

07-05-2.js
function mostFrequentCount(arr) {
  const counts = new Map();
  let highest = 0;

  for (const value of arr) {
    const count = (counts.get(value) ?? 0) + 1;
    counts.set(value, count);
    highest = Math.max(highest, count);
  }

  return highest;
}

console.log(mostFrequentCount([2, 2, 3, 4, 4, 4])); // 3

Updating an existing Map key replaces its value; adding an existing Set value does not create another entry. Count distinct stored entries, not how many times set() or add() runs. [3]

Account for the values tooO(k) assumes fixed-size keys, values or references. If you create large arrays or objects as Map values, include their newly allocated storage. A collection holding references does not automatically deep-copy the referenced objects.
07.06★ Input space vs auxiliary space: what should be included?State the convention▼

Use three separate buckets:

Bucket What belongs here? Example
Input space Data supplied to the algorithm The original array
Auxiliary space Extra working data and active call frames A temporary Set or a working copy
Output space New storage allocated for the returned result A newly built result array

This guide excludes both the supplied input and the final output from auxiliary space. Other explanations may include output in “extra space.” State which convention you use.

For sumArray(arr) from 07.01:

Component Space
Input array of n fixed-size numbers O(n)
Extra counters and running total O(1)
Returned number O(1)
Total storage including the supplied input O(n)
Total accounted storage = input + auxiliary + newly allocated output

Count distinct allocations once. An output reference that aliases the input is not another copy of the same storage.

Even a large matrix input can be processed with O(1) auxiliary space:

07-06-1.js
function sumMatrix(matrix) {
  let total = 0;

  for (const row of matrix) {
    for (const value of row) {
      total += value;
    }
  }

  return total;
}

console.log(sumMatrix([[1, 2], [3, 4]])); // 10

For an already-supplied n × n matrix, the input takes O(n²) storage. This function creates no second matrix, so its auxiliary space is O(1).

Interview answer“This solution uses O(1) auxiliary space. The supplied n-element input itself occupies O(n) space.”

Measure peak live working storage: the maximum working memory needed at one time. A loop’s total allocation count is a different measurement. JavaScript garbage collection and retained capacity can make measured heap usage differ from this abstract analysis. [4]

07.07Output space: does a returned array count?Report output separately▼

Output space is the additional storage allocated for the result. Returning an array does not make its allocated memory disappear.

07-07-1.js
function doubleValues(arr) {
  const result = [];

  for (const value of arr) {
    result.push(value * 2);
  }

  return result;
}

console.log(doubleValues([10, 20, 30])); // [20, 40, 60]

The result stores n numbers. The loop itself needs only fixed-size working variables.

Auxiliary · excludes outputO(1)
New output storageO(n)
Reporting convention What to say
Auxiliary excludes final output O(1) auxiliary space and O(n) output space
Extra space includes final output O(n) additional space
Avoid an incomplete answerSaying only “O(1) space” hides the n-element result. Say “O(1) auxiliary space, excluding the O(n) output.”

Returning the original array is different:

07-07-2.js
function reverseInPlace(arr) {
  let left = 0;
  let right = arr.length - 1;

  while (left < right) {
    const temp = arr[left];
    arr[left] = arr[right];
    arr[right] = temp;
    left++;
    right--;
  }

  return arr;
}

const values = [10, 20, 30];
const result = reverseInPlace(values);
console.log(result);           // [30, 20, 10]
console.log(result === values); // true

This function modifies the input and returns a reference to it. It uses O(1) auxiliary space and allocates no new n-element output array. Additional output storage is O(1), even though the returned array contains n elements.

07.08★ Recursion call-stack space: count the active calls.O(depth)▼

Recursive calls normally keep active call frames. Each frame retains the state needed to finish its call, such as arguments, local values and where execution must continue.

With O(1) storage per frame, stack space grows with the maximum number of simultaneously active calls.

07-08-1.js
function sumTo(n) {
  if (n === 0) return 0;
  return n + sumTo(n - 1);
}

console.log(sumTo(4)); // 10

Assume n is a non-negative integer. While sumTo(4) waits, sumTo(3) must finish, which waits for sumTo(2), and so on.

Deepest point for n = 4 Why the frame is still active
sumTo(4) Waiting to add 4
sumTo(3) Waiting to add 3
sumTo(2) Waiting to add 2
sumTo(1) Waiting to add 1
sumTo(0) Executing the base case

There are n + 1 active frames at the deepest point, including the base case. Each frame uses fixed-size state in our model:

(n + 1) frames × O(1) per frame → O(n) auxiliary space
Auxiliary · excludes outputO(n)
New output storageO(1)

The iterative version keeps a running total instead:

07-08-2.js
function sumToIterative(n) {
  let total = 0;

  for (let i = 1; i <= n; i++) {
    total += i;
  }

  return total;
}

console.log(sumToIterative(4)); // 10
Implementation Time Auxiliary space New output storage
Recursive sumTo O(n) O(n) stack O(1)
Iterative sumToIterative O(n) O(1) O(1)

Recursion is not always O(n) space. A halving chain has logarithmic depth:

07-08-3.js
function halveUntilOne(n) {
  if (n <= 1) return 0;
  return 1 + halveUntilOne(Math.floor(n / 2));
}

console.log(halveUntilOne(16)); // 4

For positive integer n = 16, the calls use values 16, 8, 4, 2, 1. That is 5 active frames, so auxiliary space is O(log n) as n grows.

Depth, not total callsFor branching recursion, many calls may run one after another. Count the longest active chain, and include any extra data held by those active calls. If each frame creates a growing array, the O(1)-per-frame assumption no longer applies.

Very deep recursion can exceed the JavaScript runtime’s stack limit. A base case stops the recursion logically but does not make an arbitrarily deep call chain safe. [5]

Four questions to ask

  • Create?What new storage does this algorithm allocate?
  • Grow?How does each collection grow with n?
  • Live?How much must exist at the same time?
  • Return?Which storage belongs to the final output?

A precise interview answer

“The solution uses O(n) time, O(1) auxiliary space excluding output, and O(n) output space because it returns a newly built array.”

That answer applies to doubleValues() in 07.07. State the memory convention before comparing solutions.
