★ Priority topic · Learn = concept · Pattern = worked example

The main ruleCount all work for time. Count the maximum memory needed at once for space. Mutating data, storing lookup entries, and making recursive calls have different memory costs.
How this guide counts complexity

Auxiliary space excludes the supplied input and final output. Returned collections are reported separately. “Extra space including output” counts both working and output storage.

Assume fixed-size numbers and references, constant-cost arithmetic, dense arrays, and ordinary stack frames without tail-call elimination. Hash-based Map/Set analyses use average constant-time access; JavaScript does not promise that exact bound. n is the input size, and k is the number of distinct keys unless a rotation explicitly uses k.

8 In-place algorithms vs. extra space ★★★

Change existing data, account for new storage, and compare common array patterns.

08.01What is an in-place algorithm?O(1)▼

An in-place algorithm modifies data directly in its original memory location without requiring another array or data structure proportional to the input size.

An in-place algorithm typically uses O(1) auxiliary space, although some definitions permit a small amount of additional space, such as a logarithmic recursion stack.

Example: Swapping two elements in an array.

08-01-1.js
let arr = [10, 20, 30, 40, 50];

[arr[0], arr[4]] = [arr[4], arr[0]];

console.log(arr); // [50, 20, 30, 40, 10]

The original array is modified. No additional array of size n is created.

Complexity: Time O(1), auxiliary space O(1).

What makes this constant?The destructuring swap holds just two values temporarily. Its storage does not grow with n. Modifying the input alone does not prove that an entire algorithm uses O(1) auxiliary space.

08.02★ Array reversal using two pointersO(n) time · O(1) space▼

The Two Pointer technique uses two indices (left and right) that move toward each other.

08-02-1.js
function reverseArray(arr) {
  let left = 0;
  let right = arr.length - 1;

  while (left < right) {
    [arr[left], arr[right]] = [arr[right], arr[left]];
    left++;
    right--;
  }

  return arr;
}

console.log(reverseArray([10, 20, 30, 40, 50]));
// [50, 40, 30, 20, 10]

Step through the reversal in the array explorer.

Complexity:

  • Time: O(n) — exactly ⌊n/2⌋ swaps.
  • Auxiliary space: O(1) — only two pointer variables and temporary swap storage.
Five elements, two swapsSwap indices 0 and 4, then 1 and 3. The middle element stays in place. The loop stops when left >= right. Empty and single-element arrays need no swaps.

08.03★ Array rotation using the reversal techniqueO(n) time · O(1) space▼

Array rotation can be performed without creating a second array.

Example: Left rotate by k = 2.

08-03-1.js
function rotateLeft(arr, k) {
  const n = arr.length;
  if (n === 0) return arr;

  k = ((k % n) + n) % n;

  function reverse(left, right) {
    while (left < right) {
      [arr[left], arr[right]] = [arr[right], arr[left]];
      left++;
      right--;
    }
  }

  reverse(0, k - 1);
  reverse(k, n - 1);
  reverse(0, n - 1);

  return arr;
}
Approach Time Extra space
Create another array O(n) O(n)
Reversal technique O(n) O(1)

Remember:

  • Left rotation: First K → Remaining → All.
  • Right rotation: All → First K → Remaining.
Normalize the rotationAssume k is an integer. The normalization maps it into 0…n − 1; for n = 5, k = 7 becomes 2 and k = −1 becomes 4. The empty-array guard prevents division by zero. All three reversals together take O(n) time.

Try left and right rotation in the array explorer.

08.04Sorting in-place vs using another arrayAlgorithm dependent▼

Some sorting algorithms modify the original array, while others allocate additional storage.

Sorting algorithm Time (worst) Auxiliary space In-place?
Bubble Sort O(n²) O(1) Yes
Selection Sort O(n²) O(1) Yes
Insertion Sort O(n²) O(1) Yes
Merge Sort (standard array implementation) O(n log n) O(n) No
Heap Sort (iterative sift-down) O(n log n) O(1) Yes
Quick Sort (standard recursive version) O(n²) O(log n) average stack, O(n) worst Commonly called in-place apart from stack

JavaScript example:

08-04-1.js
let arr = [5, 2, 8, 1];

arr.sort((a, b) => a - b);

sort() mutates the original array. However, mutation does not guarantee O(1) auxiliary space because JavaScript engines may allocate working memory internally.

Mutation and memory are different questionsThe sorting table describes the named algorithms, not a JavaScript engine’s choice. Built-in sort() has implementation-dependent time and space complexity. MDN reference.

08.05★ Frequency counting using a MapO(k) output▼

A Map stores each distinct value and its frequency.

08-05-1.js
function countFrequency(arr) {
  const map = new Map();

  for (const num of arr) {
    map.set(num, (map.get(num) || 0) + 1);
  }

  return map;
}

console.log(countFrequency([1, 2, 2, 3, 3, 3]));
// Map(3) { 1 => 1, 2 => 2, 3 => 3 }

Time: O(n) average with hash-based Map operations.

The Map holds k entries, where k is the number of distinct elements and k ≤ n.

What is counted? Space
Returned frequency Map (new output) O(k), worst case O(n)
Working storage excluding that output O(1)
Extra storage including output O(k), worst case O(n)

A Map improves lookup efficiency but uses additional memory.

Use the same convention as Topic 7This function returns the Map, so it is output storage. If a Map is used internally and only a number or boolean is returned, its entries count as auxiliary storage instead.

08.06★ Two Sum: nested loops vs MapO(n²) → O(n) average▼

Problem: Find indices of two numbers whose sum equals a target.

Input: [2, 7, 11, 15], target 9.

Approach 1 — Nested loops

08-06-1.js
function twoSum(arr, target) {
  for (let i = 0; i < arr.length; i++) {
    for (let j = i + 1; j < arr.length; j++) {
      if (arr[i] + arr[j] === target) {
        return [i, j];
      }
    }
  }

  return [];
}

Time O(n²) worst case, auxiliary space O(1).

Approach 2 — Hash Map

08-06-2.js
function twoSum(arr, target) {
  const map = new Map();

  for (let i = 0; i < arr.length; i++) {
    const complement = target - arr[i];

    if (map.has(complement)) {
      return [map.get(complement), i];
    }

    map.set(arr[i], i);
  }

  return [];
}

Time O(n) average, auxiliary space O(n).

The Map stores previously visited values, avoiding repeated pair comparisons.

Trace the Map approach

Index Value Needed complement Action
0 2 7 Not seen; store 2 → 0
1 7 2 Found at index 0; return [0, 1]

The example exits early. The O(n) average bound describes a full scan under average constant-time hash operations; the brute-force O(n²) bound is its worst case.

Check before insertingChecking the complement before map.set() keeps the two indices distinct. For [3, 3] with target 6, the second 3 finds the first 3. The returned pair uses O(1) output space.

08.07Mutating the original array vs copying itMutation vs. new storage▼

Compare both approaches from the same starting values:

08-07-1.js
const original = [10, 20, 30];
const copied = [...original].reverse();

console.log(original); // [10, 20, 30] — unchanged
console.log(copied);   // [30, 20, 10] — new array

// A separate input for the mutating example
const mutable = [10, 20, 30];
const sameArray = mutable.reverse();

console.log(mutable);              // [30, 20, 10]
console.log(sameArray === mutable); // true
Feature Mutating Copying
Original array changes Yes No
New array allocated No Yes
Additional array storage O(1) O(n)
Suitable for immutable array updates No Yes
Example reverse() toReversed() or [...arr].reverse()

Both reversal approaches take O(n) time for ordinary dense arrays. If the new array is the final returned result, its n slots are output space; if it is a temporary working copy, they are auxiliary space.

In React, create a new array when updating array state. A spread copy is shallow: objects inside it are still shared. Copy any nested object you intend to change, too. React documentation.

Read sequential code carefullyIf you call arr.reverse() first and then [...arr].reverse(), the second operation reverses the already-reversed values. The copied array ends up in the original order.

9 Time–space trade-offs ★★

Use memory deliberately to avoid repeated work, then choose an approach that fits the constraints.

09.01What is a time–space trade-off?Time ↔ memory▼

A time–space trade-off occurs when an algorithm uses more memory to reduce execution time, or uses less memory at the cost of additional computation.

Example:

  • Brute force: compare elements repeatedly.
  • Hashing: remember previously processed elements.

Sometimes using more memory makes an algorithm substantially faster.

Remember work you would otherwise repeatA lookup structure, cache, or index stores useful information. Building and retaining it costs memory, but later queries can avoid rescanning the original data.

09.02Improve time complexity using extra memoryO(n²) → O(n) average▼

Consider finding whether an array contains duplicates.

A nested-loop approach compares pairs, requiring up to O(n²) time but only O(1) auxiliary space.

With a Set, we can remember previously visited elements and detect duplicates in O(n) average time, using O(n) extra space.

A baseline without a lookup structure:

09-02-1.js
function hasDuplicatesBrute(arr) {
  for (let i = 0; i < arr.length; i++) {
    for (let j = i + 1; j < arr.length; j++) {
      if (arr[i] === arr[j]) return true;
    }
  }
  return false;
}

With no duplicates, all n(n − 1)/2 pairs are checked. For n = 16, that is 120 equality checks. The Set version visits each element once and stores up to n distinct values. See the Set implementation.

09.04★ Duplicate detection using SetO(n) average▼
09-04-1.js
function hasDuplicates(arr) {
  const seen = new Set();

  for (const num of arr) {
    if (seen.has(num)) return true;

    seen.add(num);
  }

  return false;
}

console.log(hasDuplicates([1, 2, 3, 2])); // true
  • Time O(n) average.
  • Extra space O(n) worst case.
  • Early return is possible when a duplicate is detected.

Alternative:

09-04-2.js
function hasDuplicates(arr) {
  return new Set(arr).size !== arr.length;
}

Both versions use additional memory, but the first permits early termination.

The compact version still builds the Setnew Set(arr) consumes the whole input before comparing sizes. The loop can stop as soon as it sees a duplicate. With no duplicate, the loop stores all n values.

09.05Frequency counting using MapO(k) working storage▼

When we need to count repeated values, a Map lets us process the input once rather than repeatedly scanning it.

09-05-1.js
const arr = ["a", "b", "a", "c", "b", "a"];
const freq = new Map();

for (const ch of arr) {
  freq.set(ch, (freq.get(ch) ?? 0) + 1);
}

For n elements with k unique keys:

  • Time O(n) average.
  • Space O(k).
  • Worst-case auxiliary space O(n) when all values are unique.

For this input, the Map is a → 3, b → 2, c → 1: six elements, three keys.

Here we count the Map as a retained working structure. If a function returns this Map as its final result, classify the same O(k) storage as output instead, as in 08.05. The total additional storage is O(k) either way.

09.06★ Sorting vs hashingSorting vs. lookup▼

Suppose you want to find duplicates.

Sorting approach: Sort the array, then compare adjacent elements.

09-06-1.js
function hasDuplicates(arr) {
  const sorted = [...arr].sort((a, b) => a - b);

  for (let i = 1; i < sorted.length; i++) {
    if (sorted[i] === sorted[i - 1]) return true;
  }

  return false;
}

The copy alone uses O(n) space. If the chosen sorting implementation takes O(n log n) time, the copy + sort + scan also takes O(n log n) time. JavaScript’s built-in sort() does not promise a particular time or auxiliary-space bound. MDN reference.

The copy is working memory here because the result is a boolean. Count any sorting workspace in addition to the copy.

Hashing approach: Use a Set, taking O(n) average time and O(n) auxiliary space.

If mutation is allowed, iterative heapsort + an adjacent scan gives O(n log n) worst-case time and O(1) auxiliary space. This trades the average linear time of hashing for a smaller memory bound.

Memory is highly constrained In-place algorithm

Input is already sorted Two pointers or binary search, when applicable

Interview tip: Always explain both time and space complexity. An O(n) solution is not automatically better than an O(n log n) solution if memory limits are strict.

A useful interview answer“I can use a Set for O(n) average time and O(n) auxiliary space. If memory is restricted and mutation is allowed, I can sort in place with heapsort and scan in O(n log n) worst-case time and O(1) auxiliary space.”

10 Recursion complexity ★★★

Count total work for time and the deepest active call path for stack space.

10.01What is a recursive call?Base + recursive case▼

Recursion happens when a function calls itself to solve a smaller version of the same problem.

A recursive algorithm usually contains:

  1. Base case: When recursion stops.
  2. Recursive case: The function calls itself with a smaller problem.
10-01-1.js
function countdown(n) {
  if (n === 0) return; // Base case

  console.log(n);
  countdown(n - 1);    // Recursive case
}

countdown(3);
// 3, 2, 1
State the input domainFor countdown and sum examples, n is a nonnegative integer. Each recursive step moves toward the base case. Count one constant-size operation per visit; actual console output is outside the simple cost model.

10.02★ Base case and recursive caseO(n) time & stack▼

Consider factorial:

10-02-1.js
function factorial(n) {
  if (n <= 1) return 1;

  return n * factorial(n - 1);
}

console.log(factorial(4)); // 24

For positive integer n:

  • Time O(n).
  • Auxiliary space O(n) due to recursive calls.

↑ Back to topic index

10.03★ Recursion call stackPeak active frames▼

Each active recursive function call creates a stack frame containing information such as parameters, local variables and where execution should resume.

Example:

10-03-1.js
function fun(n) {
  if (n === 0) return;
  fun(n - 1);
}

fun(3);

The maximum number of simultaneously active frames is the recursion depth.

A linear recursion with depth n typically needs O(n) stack space.

Calls over time vs. frames at onceTime counts all calls that execute. Stack space counts the largest number of calls active simultaneously, multiplied by the storage per frame. Our examples assume ordinary stack frames without tail-call elimination.

10.04Time complexity of linear recursionO(n) time▼
10-04-1.js
function printNumbers(n) {
  if (n === 0) return;

  console.log(n);
  printNumbers(n - 1);
}

The function makes n + 1 calls, including printNumbers(0). It prints n values. Each frame does O(1) work under the model used here.

Recurrence:

T(n) = T(n − 1) + O(1) → O(n)
Time complexity: O(n).

10.05Space complexity of linear recursionO(n) auxiliary▼

Even without creating an array or Map, recursion consumes memory.

10-05-1.js
function sum(n) {
  if (n === 0) return 0;
  return n + sum(n - 1);
}

The calls remain active until the base case returns.

  • Time O(n).
  • Auxiliary space O(n).

Important: No extra array does not mean O(1) space.

↑ Back to topic index

10.06★ Binary recursionO(2ⁿ) time · O(n) space▼

Binary recursion happens when a function makes two recursive calls.

Example:

10-06-1.js
function binaryRecursion(n) {
  if (n <= 0) return;

  binaryRecursion(n - 1);
  binaryRecursion(n - 1);
}

For this example:

T(n) = 2T(n − 1) + O(1) → O(2ⁿ)
- Time O(2ⁿ). - Auxiliary space O(n), because there are at most n + 1 active frames, including the base case.

Although two recursive calls are written, they normally execute sequentially, so the stack does not hold all O(2ⁿ) calls simultaneously.

For integer n ≥ 0, the total number of invocations is:

1 + 2 + 4 + … + 2ⁿ = 2ⁿ⁺¹ − 1

For n = 3: 15 calls in total, but only 4 active frames at once.

Two calls do not always mean exponential timeSubproblem size matters. Two calls of size n − 1 with constant work give O(2ⁿ). Two calls of size n/2 with constant work per call give O(n).

10.07★ Fibonacci recursionExponential → linear▼

The naive Fibonacci implementation repeats many calculations.

10-07-1.js
function fibonacci(n) {
  if (n <= 1) return n;

  return fibonacci(n - 1) + fibonacci(n - 2);
}

console.log(fibonacci(5)); // 5

f(2) is calculated more than once. Repeated subproblems cause exponential growth.

The recurrence is:

T(n) = T(n − 1) + T(n − 2) + O(1)
| Approach | Time | Extra space | | ------------------------ | -------------------------------- | ----------- | | Naive recursion | O(2ⁿ) upper bound; tighter Θ(φⁿ) | O(n) | | Memoization | O(n) | O(n) | | Bottom-up DP array | O(n) | O(n) | | Iterative, two variables | O(n) | O(1) |

Memoization stores already-computed results, exchanging O(n) additional memory for a substantial reduction in time.

Memoization counts both cache and stackThe cache holds O(n) results and the recursive stack can hold O(n) frames. Add them: O(n) + O(n) = O(n). Do not multiply the number of calls by the peak stack depth. Here φ ≈ 1.618.

An iterative version can retain only the previous two values:

10-07-2.js
function fibonacciIterative(n) {
  let previous = 0;
  let current = 1;

  for (let i = 0; i < n; i++) {
    [previous, current] = [current, previous + current];
  }

  return previous;
}

console.log(fibonacciIterative(5)); // 5

This uses O(n) time and O(1) auxiliary space under fixed-size arithmetic. As with factorial, these small JavaScript Number examples illustrate the algorithm; arbitrary-precision arithmetic has different costs.

10.08★ Recursive binary searchO(log n) time & stack▼

Binary search discards half the search range on every step.

10-08-1.js
function binarySearch(arr, target, left = 0, right = arr.length - 1) {
  if (left > right) return -1;

  const mid = left + Math.floor((right - left) / 2);

  if (arr[mid] === target) return mid;

  if (target < arr[mid]) {
    return binarySearch(arr, target, left, mid - 1);
  }

  return binarySearch(arr, target, mid + 1, right);
}

Each call reduces the problem size by approximately half.

T(n) = T(n/2) + O(1) → O(log n)
- Time O(log n). - Auxiliary space O(log n) due to recursive calls.

An iterative implementation retains O(log n) time while reducing auxiliary space to O(1).

Keep bounds, not copied slicesThe input must be sorted in ascending order. This version passes indices into the original array, so each call uses constant-size local storage. Copying subarrays with slice() would require a different analysis.

The stated bounds are worst-case bounds for n ≥ 2 without tail-call elimination. Finding the target at the first midpoint is O(1) time and O(1) stack space. An empty array returns −1 immediately.

10.09★ Recursion vs iterationSame time, different space▼
Feature Recursion Iteration
Mechanism Function calls itself Loops
Termination Base case Loop condition
Stack memory Depends on depth Usually O(1) for simple loops
Function-call overhead Present Usually lower
Readability Useful for trees, DFS, divide-and-conquer Useful for linear traversal
Stack overflow risk Yes, with excessive depth Not from loop iteration alone

Important: Recursion is not always slower in asymptotic time complexity. A recursive and iterative solution can have identical time complexity but different space requirements.

Iteration can still need growing memoryA loop using an explicit stack, queue, Map, or DP array may use O(n) or more auxiliary space. O(1) applies to simple loop versions with a fixed number of working values, not to every iterative algorithm.

10.10How to calculate recursion complexity in interviewsBuild a recurrence▼

Use these three questions:

  1. How many recursive calls are made per invocation? One, two, or more?
  2. How much smaller is each subproblem? n - 1, n / 2, etc.
  3. How much additional work happens per invocation? Constant, linear, or something else?

Common patterns:

Recurrence Typical time
T(n) = T(n−1) + O(1) O(n)
T(n) = T(n/2) + O(1) O(log n)
T(n) = 2T(n/2) + O(1) O(n)
T(n) = 2T(n/2) + O(n) O(n log n)
T(n) = 2T(n−1) + O(1) O(2ⁿ)

These assume appropriate base cases and that the recurrence accurately represents the algorithm.

Then answer a fourth question for space: What is the deepest active call path, and how much working storage exists along that path?

Example Calls per invocation Smaller input Work per invocation Result
Sum from n to 1 1 n − 1 O(1) O(n) time, O(n) stack
Binary search At most 1 About n/2 O(1) O(log n) time and stack
Two branches of n − 1 2 n − 1 O(1) O(2ⁿ) time, O(n) stack

Use a base case such as T(0) or T(1) = Θ(1). The listed time bounds assume the displayed recurrence accurately captures the work.

08 · Mutation is only one clue

Ask whether any extra structure grows with n. A built-in method can mutate its input and still allocate working memory.

09 · Explain both costs

A Map or Set can replace repeated comparisons with lookups. State the average-time assumption and the memory cost.

10 · Total calls vs. active calls

Time counts all executed work. Stack space counts the maximum simultaneously active frames and their storage.
