3 Reading loops

Single and consecutive loops use the same counting approach

03.01★ Calculate the complexity of a single loop.O(n)▼
while.js
let i = 0;
let total = 0;

while (i < n) {
  total += i;
  i++;
}

i visits 0 through n - 1, so there are n iterations. Each iteration does constant work:

work
n iterations × O(1) work = O(n)

Writing this as a for loop would not change its complexity.

CarefulAlso, one loop does not automatically mean O(n). The doubling loop shown earlier is O(log n).
03.02★ Calculate the complexity of consecutive loops.O(n + n) = O(n)▼
consecutive.js
let count = 0;

for (let i = 0; i < n; i++) {
  count++;
}

for (let j = 0; j < n; j++) {
  count++;
}

The first loop finishes before the second starts:

sum
n + n = 2n → O(n)

These loops are O(n), not O(n²).

ArrangementWorkComplexity
Two consecutive n-iteration loopsn + nO(n)
Three consecutive n-iteration loopsn + n + nO(n)
An n-iteration loop inside anothern × nO(n²)
An O(n) loop followed by O(n²) workn + n²O(n²)
03.03Analyse loops with different step sizes.step size▼

Assuming constant work inside each loop:

LoopApproximate iterationsComplexity
for (let i = 0; i < n; i++)nO(n)
for (let i = 0; i < n; i += 2)n / 2O(n)
for (let i = 0; i < n; i += 10)n / 10O(n)
for (let i = n; i > 0; i--)nO(n)
for (let i = 1; i < n; i *= 2)log₂ nO(log n)
for (let i = 1; i < n; i *= 3)log₃ nO(log n)
Rule of thumbAdding a fixed amount usually gives linear growth. Multiplying by a fixed factor greater than 1 usually gives logarithmic growth.

For example:

step2.js
for (let i = 0; i < n; i += 2) {
  // Constant work
}

This processes about half the indices, but n / 2 still grows proportionally to n.

Be careful when the step depends on the input:

step-n.js
for (let i = 0; i < n; i += n) {
  // Runs once for positive n
}

This is O(1).

03.04★ Analyse early break and return statements.best vs worst▼
findIndex.js
function findIndex(arr, target) {
  for (let i = 0; i < arr.length; i++) {
    if (arr[i] === target) {
      return i;
    }
  }

  return -1;
}
SituationElements checkedComplexity
Target is first1Best case: O(1)
Target is lastnWorst case: O(n)
Target is absentnWorst case: O(n)
Key ideaAn early return can improve a particular run without changing the worst-case complexity.

A guaranteed fixed stopping point is different:

fixed-break.js
for (let i = 0; i < n; i++) {
  if (i === 3) break;
}

This loop executes at most four times, regardless of how large n becomes. It is O(1).

break exits the loop; return exits the function.

03.05Calculate array and string traversal complexity.O(n)▼

Array:

array.js
let total = 0;

for (const value of arr) {
  total += value;
}

Time: O(n), where n is the number of array elements.

String:

string.js
let count = 0;

for (const char of text) {
  if (char === "a") {
    count++;
  }
}

Time: O(n) in the string’s length.

Watch the bodyHowever, if the loop body calls another function, include that function’s cost. A function call is not automatically O(1).
03.06Analyse two independent inputs: O(n + m).O(n + m)▼
sumBoth.js
function sumBoth(arr1, arr2) {
  let total = 0;

  for (const value of arr1) {
    total += value;
  }

  for (const value of arr2) {
    total += value;
  }

  return total;
}

Here, n = arr1.length and m = arr2.length.

work
Total work = n + m
Time complexity = O(n + m)

Keep both variables because the arrays can have different lengths.

Compare that with nested loops:

pairs.js
let comparisons = 0;

for (const a of arr1) {
  for (const b of arr2) {
    comparisons++;
  }
}

Every element of the first array is paired with every element of the second:

work
Total work = n × m
Time complexity = O(nm)
