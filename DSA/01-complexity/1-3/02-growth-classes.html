2 Growth classes

Count how many times the work happens as the input grows

The main rule: count how many times the work happens as the input grows. A for loop and a while loop can have the same complexity. In these examples, n is a positive input size, and simple operations such as count++ take constant time.
02.01★ Understand O(1) — constant time.O(1)▼
getFirst.js
function getFirst(arr) {
  return arr[0];
}

Whether the array contains 10 elements or 10 lakh elements, we access only its first element.

CarefulO(1) does not mean exactly one operation. A fixed number of operations is still constant.
getEnds.js
function getEnds(arr) {
  const first = arr[0];
  const last = arr[arr.length - 1];

  return first + last;
}

This is also O(1).

02.02★★★ O(log n) - Logarithmic Time ComplexityO(log n)▼

O(log n) means the number of operations grows slowly as the input gets larger. A common reason is that each step reduces the remaining problem by a fixed factor, usually by half.

1. Understand repeated halving

Imagine searching for a value in a sorted array of 16 elements. Binary search can discard half the remaining elements after each comparison:

StepRemaining elementsWhat happened?
Start16All elements are possible.
18Discard one half.
24Discard half of what remains.
32Repeat the halving.
41One possible element remains.

Four halvings take 16 elements down to one: 16 → 8 → 4 → 2 → 1.

Why logarithms?After k halvings, n / 2k = 1. Therefore n = 2k, so k = log2 n. For 16 elements, log2 16 = 4.

When the input doubles, logarithmic work increases by about one step. Big O usually omits the logarithm base because changing between fixed bases only changes a constant factor.

3. Multiplication loop

When a loop variable doubles each time, it reaches n after about log2 n iterations:

doubling-loop.js
function example(n) {
  for (let i = 1; i < n; i *= 2) {
    console.log(i);
  }
}

example(16);

Output: 1, 2, 4, 8. The next value is 16, so i < 16 is false. The loop runs four times, giving O(log n).

4. Division loop

A loop that halves its input each time has the same logarithmic pattern:

halving-loop.js
function example(n) {
  while (n > 1) {
    console.log(n);
    n = Math.floor(n / 2);
  }
}

example(16);

The values are 16, 8, 4, 2, so the loop takes O(log n) time. Both doubling and halving produce logarithmic iteration counts when the loop stops at a bound proportional to its input.

5. Binary search

Binary search requires a sorted array. Each comparison discards about half of the remaining search range.

binary-search.js
function binarySearch(arr, target) {
  let left = 0;
  let right = arr.length - 1;

  while (left <= right) {
    const mid = Math.floor((left + right) / 2);

    if (arr[mid] === target) return mid;
    if (arr[mid] < target) left = mid + 1;
    else right = mid - 1;
  }

  return -1;
}

binarySearch([10, 20, 30, 40, 50, 60, 70, 80], 70); // 6

Searching for 70 checks the middle value, then narrows to the right-hand range:

StepCurrent rangeMiddle valueDecision
110–804070 is larger; search right.
250–806070 is larger; search right.
370–8070Target found at index 6.
  • Best case: O(1), when the first middle value is the target.
  • Average case: O(log n).
  • Worst case: O(log n).
  • Auxiliary space: O(1) for this iterative implementation.

6. Recognize O(log n) in code

Code patternTypical complexity

Interview reminderO(1) is a fixed amount of work; O(log n) repeatedly shrinks or grows a value by a constant factor; O(n) processes elements one by one. Always check the loop bounds and stopping condition; the update expression alone does not determine complexity.
02.03★ Understand O(n) — linear time.O(n)▼
sumArray.js
function sumArray(arr) {
  let total = 0;

  for (let i = 0; i < arr.length; i++) {
    total += arr[i];
  }

  return total;
}

The loop visits each element once.

  • 10 elements → 10 iterations.
  • 100 elements → 100 iterations.
  • 1,000 elements → 1,000 iterations.
RememberDouble the input → roughly double the work.
02.04★ Understand O(n log n) — linearithmic time.O(n log n)▼
nested-doubling.js
let count = 0;

for (let i = 0; i < n; i++) {
  for (let j = 1; j < n; j *= 2) {
    count++;
  }
}

The outer loop runs n times. For every outer iteration, the inner loop starts again at 1 and runs about log₂(n) times.

total work
Total work = n × log₂(n)

For n = 8, the inner loop visits 1, 2, 4: three iterations.

count
8 outer iterations × 3 inner iterations = 24

Therefore, the complexity is O(n log n). Merge sort is a common algorithm with this time complexity.

02.05★ Understand O(n²) — quadratic time.O(n²)▼
nested.js
let count = 0;

for (let i = 0; i < n; i++) {
  for (let j = 0; j < n; j++) {
    count++;
  }
}

For each outer iteration, the inner loop runs n times.

total work
Total work = n × n = n²

With n = 4, the body runs 16 times.

RememberDouble the input → roughly four times the work.
02.06Understand O(2ⁿ) — exponential time.O(2ⁿ)▼
explore.js
function explore(n) {
  if (n === 0) return;

  explore(n - 1);
  explore(n - 1);
}

Each non-base call makes two more calls.

Recursion depthCalls at that depth

12
24
38

The recursion continues down to depth n. The total number of calls is:

total calls
1 + 2 + 4 + ... + 2ⁿ

This grows as O(2ⁿ).

RememberIncreasing n by just 1 roughly doubles the work.

This differs from O(n²): in 2ⁿ, the input is the exponent.

02.07Understand O(n!) — factorial time.O(n!)▼

Factorial means:

factorial

For example, arranging four distinct items gives four choices for the first position, three for the next, then two, then one.

This code demonstrates factorial growth:

exploreOrders.js
function exploreOrders(n) {
  if (n <= 1) return;

  for (let i = 0; i < n; i++) {
    exploreOrders(n - 1);
  }
}

Each call makes n smaller calls; those make n − 1 calls each, and so on.

Two different thingsCalculating the value n! is different from doing factorial amounts of work. You can calculate n! using one loop in O(n) time under the usual constant-time arithmetic model.

There are n! permutations of n distinct items. Explicitly copying or printing all n items of every permutation adds another factor of n.

For sufficiently large inputs, the growth functions increase in this order:
1<log n<n<n log n<n²<2ⁿ<n!
