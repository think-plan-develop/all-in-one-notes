★ Priority topic · Learn = concept · Pattern = worked example

The main ruleCount the total work done across all iterations. Two nested loops give O(n²) when both run n times and the innermost work takes constant time.

In the examples, n is a positive integer and count++ takes O(1) time.

4 Complexity of nested loops ⭐⭐⭐

Count the innermost work — check the bounds and whether the pointer resets.

04.01★ Calculate two full nested loops: O(n²).O(n²)▼
example-4.1-1.js
let count = 0;

for (let i = 0; i < n; i++) {
  for (let j = 0; j < n; j++) {
    count++;
  }
}

For every single iteration of the outer loop, the inner loop starts again at j = 0.

If n = 4:

Outer loop: i Inner loop: j Inner iterations
0 0, 1, 2, 3 4
1 0, 1, 2, 3 4
2 0, 1, 2, 3 4
3 0, 1, 2, 3 4

Total work:

4 + 4 + 4 + 4 = 4 × 4 = 16

Generally, n × n = n² → O(n²).

04.02Calculate three nested loops: O(n³).O(n³)▼
example-4.2-1.js
let count = 0;

for (let i = 0; i < n; i++) {
  for (let j = 0; j < n; j++) {
    for (let k = 0; k < n; k++) {
      count++;
    }
  }
}

For each i, all values of j are visited. For each pair of i and j, all values of k are visited.

Total: n × n × n = n³ → O(n³).

If n = 4, the innermost statement runs 64 times.

04.03★ Analyse nested loops with different input sizes: O(n × m).O(n × m)▼

Suppose one array has n elements and another has m elements:

example-4.3-1.js
let count = 0;

for (let i = 0; i < arr1.length; i++) {
  for (let j = 0; j < arr2.length; j++) {
    count++;
  }
}

If arr1.length = 3 and arr2.length = 5, total work is:

3 × 5 = 15
ResultTime: O(n × m).
Independent inputsKeep both variables because the arrays can grow independently. If both lengths are n, this becomes O(n²).
04.04★ Analyse triangular loops where j = i + 1.O(n²)▼

This pattern compares each element with the elements after it:

example-4.4-1.js
let count = 0;

for (let i = 0; i < n; i++) {
  for (let j = i + 1; j < n; j++) {
    count++;
  }
}

For n = 5:

i Starting j Values visited by j Inner iterations
0 1 1, 2, 3, 4 4
1 2 2, 3, 4 3
2 3 3, 4 2
3 4 4 1
4 5 None 0

Total:

4 + 3 + 2 + 1 + 0 = 10

Generally:

(n − 1) + (n − 2) + … + 1 = n(n − 1)/2 = (n² − n)/2

Ignore the constant factor and lower-order term: O(n²).

Although it does roughly half as much work as the full double loop, its growth is still quadratic.

04.05Analyse dependent loop boundaries where j < i.Add the work▼

A boundary is dependent when it uses another loop’s variable:

example-4.5-1.js
let count = 0;

for (let i = 1; i <= n; i++) {
  for (let j = 0; j < i; j++) {
    count++;
  }
}

Here, the inner loop runs:

  • i = 1 → 1 time.
  • i = 2 → 2 times.
  • i = 3 → 3 times.
  • …
  • i = n → n times.

Therefore:

1 + 2 + 3 + … + n = n(n + 1)/2
ResultTime: O(n²).
How to analyse itThe useful habit is: write the inner-loop counts, then add them. A dependent boundary does not automatically mean O(n²).
04.06★ When can nested loops take O(n)?Two exceptions▼

For example, an inner loop with a fixed limit:

example-4.6-1.js
let count = 0;

for (let i = 0; i < n; i++) {
  for (let j = 0; j < 3; j++) {
    count++;
  }
}

Total work: 3n → O(n).

Another example uses a pointer that does not reset:

example-4.6-2.js
let j = 0;
let count = 0;

for (let i = 0; i < n; i++) {
  while (j < n) {
    count++;
    j++;
  }
}

During the first outer iteration, j moves from 0 to n. For all remaining outer iterations, j < n is already false.

  • Outer loop: n iterations.
  • Inner loop: n iterations across the entire execution.

Total work grows like n + n → O(n).

This is useful when analysing two-pointer and sliding-window algorithms: check how many times each pointer can move in total.

5 Logarithmic complexity ⭐⭐

Understand doubling, halving, binary search and dependent loop boundaries.

05.01★ Calculate a doubling loop: i *= 2.O(log n)▼
example-5.1-1.js
let count = 0;

for (let i = 1; i < n; i *= 2) {
  count++;
}

For n = 16:

Iteration i
1 1
2 2
3 4
4 8
Stop 16

Only 4 iterations.

After k doublings, the value is 2k. To reach n:

2ᵏ = n ⇒ k = log₂ n
ResultTime: O(log n).
Avoid an infinite loopStart this loop at 1: starting at 0 would keep it at 0 forever.
05.02★ Calculate a halving loop: i /= 2.O(log n)▼
example-5.2-1.js
let count = 0;

for (let i = n; i > 1; i /= 2) {
  count++;
}

For n = 16, the body runs with:

i = 16, 8, 4, 2

At i = 1, it stops. Again, 4 iterations.

After k halvings:

n/2ᵏ = 1 ⇒ k = log₂ n

Multiplication or division by another fixed factor greater than 1, such as 3, also gives logarithmic growth. Different fixed logarithm bases differ only by a constant factor.

05.03★ Analyse binary search on a sorted array.O(log n) worst▼

Binary search works on a sorted array. Each comparison with the middle element eliminates approximately half of the remaining search range. cs.princeton.edu

example-5.3-1.js
function binarySearch(arr, target) {
  let left = 0;
  let right = arr.length - 1;

  while (left <= right) {
    const mid = left + Math.floor((right - left) / 2);

    if (arr[mid] === target) {
      return mid;
    }

    if (arr[mid] < target) {
      left = mid + 1;
    } else {
      right = mid - 1;
    }
  }

  return -1;
}

Example:

example-5.3-2.js
binarySearch([10, 20, 30, 40, 50, 60, 70, 80], 70);
Step Middle value Decision
1 40 Search values greater than 40
2 60 Search values greater than 60
3 70 Found

The search itself takes O(log n) in the worst case. Sorting an unsorted input would be additional work. algs4.cs.princeton.edu

This iterative implementation uses O(1) auxiliary space.

05.04Compare O(n) and O(log n) as input grows.Compare growth▼

Compare these two loop patterns:

n i = 0; i < n; i++ i = 1; i < n; i *= 2
16 16 iterations 4 iterations
1,024 1,024 iterations 10 iterations
1,048,576 1,048,576 iterations 20 iterations

When the input size doubles:

  • O(n): the work grows by approximately a factor of two.
  • O(log n): a doubling or halving loop needs approximately one additional iteration.
05.05Analyse two nested logarithmic loops.O((log n)²)▼
example-5.5-1.js
let count = 0;

for (let i = 1; i < n; i *= 2) {
  for (let j = 1; j < n; j *= 2) {
    count++;
  }
}

The inner loop resets to j = 1 for every outer iteration.

  • Outer: approximately log₂ n iterations.
  • Inner: approximately log₂ n iterations per outer iteration.

Total:

log n × log n = (log n)²

For n = 16: 4 × 4 = 16 executions of count++.

Common confusionO((log n)²) is different from O(log(n²)); the latter simplifies to O(log n).
05.06★ Analyse a linear loop containing a logarithmic loop.O(n log n)▼
example-5.6-1.js
let count = 0;

for (let i = 0; i < n; i++) {
  for (let j = 1; j < n; j *= 2) {
    count++;
  }
}

Total:

n × log n

For n = 16: 16 × 4 = 64 executions.

If these loops ran one after another, their costs would add instead:

O(n + log n) = O(n)
05.07★ Why can a doubling outer loop still give O(n)?O(n)▼

Consider this dependent boundary:

example-5.7-1.js
let count = 0;

for (let i = 1; i < n; i *= 2) {
  for (let j = 0; j < i; j++) {
    count++;
  }
}

For n = 16:

Outer i Inner iterations
1 1
2 2
4 4
8 8

Total: 1 + 2 + 4 + 8 = 15.

For powers of two, this sum is n - 1; generally it grows linearly.

ResultTime: O(n). The inner loop’s changing length matters.
Remember the sum1 + 2 + 4 + 8 = 15. Add the changing row lengths; multiplying n by log n would overcount.

    6 Best, average and worst cases ⭐⭐

    Keep the input size fixed. Compare the work for different inputs or targets.

    Case Meaning
    Best Minimum work among inputs of size n
    Average Expected work under a stated assumption about which inputs occur
    Worst Maximum work among inputs of size n
    Keep the input size fixedBest case does not mean “a small array,” and worst case does not mean “a large array.” Keep n fixed and consider different contents or search targets.
    06.01★ What are best, average and worst cases? See linear search.O(1) → O(n)▼
    example-6.1-1.js
    function linearSearch(arr, target) {
  for (let i = 0; i < arr.length; i++) {
    if (arr[i] === target) {
      return i;
    }
  }

  return -1;
}

    Using:

    example-6.1-2.js
    const arr = [10, 20, 30, 40, 50];
    Case Situation Comparisons Complexity
    Best Search for 10 1 O(1)
    Average Each stored value is equally likely to be searched 3 on average O(n)
    Worst Search for 50 or an absent value 5 O(n)

    For the average case, assume the target exists and each position is equally likely:

    (1 + 2 + … + n)/n = (n + 1)/2

    That grows linearly, so O(n).

    RememberAverage case is not simply “searching for the middle element.” It is an average across possible inputs, weighted by their probabilities.
    06.02Compare the best, average and worst cases of binary search.Best: O(1)▼

    For the binary-search code above:

    Case Situation Complexity
    Best Target equals the first middle element O(1)
    Average Target is equally likely to be any stored distinct value O(log n)
    Worst Search follows one of the longest paths O(log n)

    With [10, 20, 30, 40, 50, 60, 70, 80], searching for 40 finishes on the first comparison.

    An absent target also requires following the search until the remaining range becomes empty.

    06.03★ What complexity should we use for Map and Set lookups?Average: O(1)▼

    For typical hash-table implementations, assuming constant-time hashing and key comparison:

    Operation Average lookup time
    map.get(key) O(1)
    map.has(key) O(1)
    set.has(value) O(1)

    Hashing helps locate the relevant storage position without scanning every element.

    However, in a conventional hash table, many keys colliding at the same location can make a lookup take O(n). The precise worst case depends on the implementation.

    JavaScript detailFor JavaScript specifically, the language specification requires average access time to be sublinear—growing more slowly than n. It does not guarantee O(1) access for every implementation. tc39.es

    For DSA interviews, a precise statement is:

    Interview answer

    “Assuming a typical hash-table implementation, Map and Set lookups take O(1) on average.”

    Also distinguish one lookup from building the collection: inserting n elements takes O(n) expected total time under the usual hash-table assumptions.

    06.04★ Why analyse the worst case, and does Big O mean worst case?Big O ≠ worst▼

    For example, linear search may find the first element immediately. But if the target is missing from an array of one million elements, it must examine all one million.

    Worst-case analysis helps you:

    • Estimate the maximum growth in work for an input size.
    • Compare algorithms without relying on favourable inputs.
    • Judge whether a solution is likely to fit a DSA problem’s constraints.
    Important distinctionBig O itself does not mean “worst case.” It describes an upper bound. You can state a Big O bound for best-case, average-case or worst-case running time—so name the case when it matters.

    How to read a loop

    • BoundsHow many values can each counter visit?
    • ResetDoes the inner counter restart every time?
    • SumIf row lengths change, add those lengths.
    • SimplifyDrop fixed factors and lower-order terms.

    How to name the case

    • BestMinimum work for a fixed input size.
    • AverageExpected work under stated assumptions.
    • WorstMaximum work for a fixed input size.
    • Big OAn upper bound; it does not name a case.
