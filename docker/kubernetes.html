# Kubernetes — After Docker **Goal:** Move from single-host containers to orchestrated, multi-node clusters. - **Kubernetes Fundamentals** — Cluster architecture: control plane (API server, scheduler, controller manager, etcd) + worker nodes (kubelet, kube-proxy). - **Pods** — Smallest deployable unit; one or more tightly-coupled containers sharing network/storage. - **Deployments** — Manage ReplicaSets, rolling updates, and desired state for stateless apps. - **Services** — Stable networking abstraction (ClusterIP, NodePort, LoadBalancer) to reach a set of pods. - **ConfigMaps** — Externalize non-sensitive configuration from container images. - **Secrets** — Store sensitive data (base64-encoded, ideally combined with a secrets manager/encryption at rest). - **Ingress** — HTTP(S) routing rules into the cluster (path/host-based routing, TLS termination). - **Helm** — Package manager for Kubernetes; templated manifests ("charts") for repeatable deployments. - **Autoscaling** — Horizontal Pod Autoscaler (HPA) based on CPU/memory/custom metrics; Cluster Autoscaler for nodes. - **Rolling Deployments** — Zero-downtime updates, readiness/liveness probes controlling rollout pace. - **Production Kubernetes** — RBAC, namespaces for isolation, resource requests/limits, network policies, observability stack (Prometheus/Grafana), GitOps (ArgoCD/Flux). **Practice:** Take your Node.js + Postgres + Redis stack from Compose and rewrite it as Kubernetes manifests (Deployment + Service + ConfigMap + Secret), deploy locally with `minikube` or `kind`.
