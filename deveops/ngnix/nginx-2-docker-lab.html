Note: what is WSL?

WSL stands for Windows Subsystem for Linux. It lets you run Linux environments, such as Ubuntu, inside Windows. The “2” means version 2 of WSL.

VersionHow it works
WSL 1Translates Linux system calls into operations Windows understands
WSL 2Runs a real Linux kernel inside a lightweight virtual machine, providing better Linux compatibility
For your setupWindows is your operating system, WSL 2 provides the Linux environment, and Ubuntu is the Linux distribution you use.

📝 Note — what does mkdir -p mean?

In mkdir -p, the -p means “parents.” It does two things:

  1. Creates missing parent folders.
  2. Doesn’t give an error if the folder already exists.

Example: mkdir -p nginx/conf.d — if neither folder exists, it creates nginx first, then conf.d inside it. Without -p, mkdir nginx/conf.d fails if the parent folder nginx doesn’t exist.

Remembermkdir -p = “Create the whole folder path, and accept folders that already exist.”
4.1Image vs container
An image is a package; a container is an instance created from that package.
TermBetter explanationExample
ImageContains application files, libraries, configuration and startup instructionsnginx:stable-alpine contains Nginx and its supporting files
ContainerAn isolated environment created from an image; it can run or remain stoppedA container named nginx-practice running a web server
DockerfileA text file describing how to build your own imageStart with Nginx, then copy your website into the image
Docker ComposeA tool that reads a YAML file to manage related containersStart Nginx, Auth and Property services together
Bind mountExposes an existing file or directory from your computer inside a containerMake your local HTML files available to Nginx

One image can create several containers. Each container has its own writable filesystem layer; modifying a container does not modify the original image.

4.4Port mapping
Port mapping connects your browser to the application inside the container.

👆 Click each part of the mapping to see what it means.

::
PositionValueMeaning
Host IP127.0.0.1Accept connections through your computer’s loopback address
Host port8080Port you use in your browser
Container port80Port where Nginx listens inside the container

Open http://localhost:8080. Docker receives the connection on your computer’s port 8080 and forwards it to Nginx on container port 80.

Two containers can both use port 80 internally, but they need different published host ports if they use the same host IP:

ContainerPort mappingBrowser address
First Nginx127.0.0.1:8080:80http://localhost:8080
Second Nginx127.0.0.1:8081:80http://localhost:8081

Binding to 127.0.0.1 keeps these published entry points local to your computer.

4.10Stop, start, restart, remove
Stopping, starting, restarting and removing are different operations.

These examples apply to the container we created without --rm:

CommandWhat happens
docker stop nginx-practiceStops its processes; retains the container
docker start nginx-practiceStarts that existing stopped container
docker restart nginx-practiceStops and starts the existing container
docker rm nginx-practiceRemoves the stopped container and its writable layer

Stopping normally gives the application time to shut down before Docker forcibly terminates it if necessary.

Try:

Ubuntu
docker stop nginx-practice
docker ps -a
docker start nginx-practice
curl -I http://localhost:8080
run vs startrun creates a new container; start reuses an existing one.
About --rmYour original command included --rm. With that option, stopping the container automatically removes it, so it can no longer be started again. You would use docker run to create another one.

4.11Bind mount
A bind mount lets Nginx serve files you edit on your computer.

From your workspace:

Ubuntu
cd ~/nginx-lab
mkdir -p web

Create web/index.html in your editor:

web/index.html
<h1>Hello from Shivam's Nginx lab</h1>

Start a second container on port 8081:

Ubuntu
docker run -d --name nginx-site -p 127.0.0.1:8081:80 --mount "type=bind,source=$PWD/web,target=/usr/share/nginx/html,readonly" nginx:stable-alpine
Mount optionMeaning
type=bindUse a directory from your computer
source=$PWD/webUse the web folder in your current directory
target=/usr/share/nginx/htmlMake it visible at Nginx’s website directory
readonlyThe container can read the files but cannot modify them through this mount

$PWD contains your current directory’s full path.

Open http://localhost:8081. Edit the HTML and refresh the browser.

PersistenceThe mounted files stay on your computer when the container is removed. Changes to HTML are available without rebuilding an image; Nginx configuration changes generally need a reload.

4.12Dockerfile
A Dockerfile packages your files into an image.

For example, create a file named Dockerfile in the workspace:

Dockerfile
FROM nginx:stable-alpine
COPY web/ /usr/share/nginx/html/
InstructionMeaning
FROMChoose the base image
COPYCopy your local website files into the new image

Build it:

Ubuntu
docker build -t my-nginx:1.0 .
  • build: build an image.
  • -t my-nginx:1.0: give it a name and tag.
  • .: use the current directory as the build context.

The build context supplies files that instructions such as COPY can use. Building creates an image; it does not start a container.

ApproachWhat happens when you edit local HTML?
Bind mountThe container sees the changed files
Dockerfile COPYRebuild the image and recreate the container to use the changes

4.13Docker Compose
Compose becomes useful when your lab has several services.

Your future compose.yaml will describe:

  • 🖼️Which image or Dockerfile each service uses
  • 🔌Published ports
  • 🔑Environment variables
  • 💾Mounts and networks

Once that file exists, run these from the project directory:

CommandPurpose
docker compose configValidate and display the resolved configuration
docker compose up -dCreate/start the application in the background
docker compose up -d --buildBuild applicable service images before starting
docker compose psShow project container status
docker compose logs -fFollow project logs
docker compose stopStop the project’s containers
docker compose startStart existing stopped project containers
docker compose downStop and remove project containers and its managed networks
Careful with -vOrdinary down keeps named volumes; adding -v also removes applicable volumes, so that option can delete stored database data.
