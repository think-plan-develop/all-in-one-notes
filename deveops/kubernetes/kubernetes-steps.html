0. Why This Setup

For your situation, the recommendation is Windows + WSL2 + Docker Desktop — not a separate Linux install. You're already on Windows and learning Docker, so this gets you a real Linux environment without dual-booting anything.

Windows 11 │ ├── WSL2 │ │ │ └── Ubuntu │ │ │ ├── kubectl │ ├── kind │ └── Helm │ └── Docker Desktop │ └── Docker Engine │ └── kind Kubernetes cluster

This mirrors the Linux-based environment you'll meet in real development jobs almost exactly.

Step 1 — Install WSL2
PowerShell (Admin)
wsl --install

Restart your computer when Windows asks. Afterward, verify:

verify
wsl --status
wsl -l -v

NAME      STATE    VERSION
Ubuntu    Running  2
✅ VERSION 2 confirms you're running WSL2, not the older WSL1.
Step 2 — Install Ubuntu
PowerShell
wsl --install -d Ubuntu

Start Ubuntu from the Windows Start menu. You'll land in a Linux terminal:

Ubuntu
username@computer:~$ ls
username@computer:~$ pwd
username@computer:~$ cd

From this point on, you're genuinely working inside Linux.

Step 3 — Install Docker Desktop

Install Docker Desktop for Windows, open it, and make sure the WSL 2 based engine is enabled in its settings.

Windows ↓ Docker Desktop ↓ Docker Engine ↓ WSL2 ↓ Ubuntu

Verify from inside Ubuntu:

Ubuntu (WSL2)
docker --version
docker ps
✅ If both commands work, you're ready to move on to kind.
Step 4 — Install kubectl Inside Ubuntu
💬 kubectl is the command-line tool used to communicate with Kubernetes.
Your terminal ↓ kubectl ↓ Kubernetes API Server ↓ Kubernetes Cluster

kubectl get pods simply means: "Kubernetes, show me the Pods."

4.1 — Update Ubuntu packages first

apt
sudo apt update
sudo apt install -y curl
sudoRun this command with administrator (root) privileges. You may be asked for your Ubuntu password.
aptUbuntu's package manager — installs, updates, and removes software.
updateRefreshes the package catalog from configured repositories — does NOT upgrade installed software itself.
Ubuntu ↓ apt update ↓ Refresh package information ↓ Know which versions are available
CommandWhat it does
sudo apt updateRefreshes the package list (catalog)
sudo apt upgradeUpgrades already-installed packages
sudo apt install <package>Installs a specific package

Running update before install is just: refresh the catalog, then install from it — here, to get the tools Kubernetes work needs.

4.2 — Install kubectl

install kubectl
curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"

sudo install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl

kubectl version --client
Client Version: v1.xx.x

Because kubectl lives inside Ubuntu (the bottom of your WSL2 stack), typing kubectl get nodes there talks directly to whatever Kubernetes cluster you point it at.

⏸️ Don't create the cluster yet. For now, just confirm the tool exists: kubectl version --client. If it says "command not found," run the install commands above first.
Step 5 — Install kind
💬 kind means Kubernetes IN Docker — it creates a local Kubernetes cluster using Docker.
Docker Desktop ↓ kind ↓ Kubernetes Cluster ↓ Kubernetes Nodes ↓ Pods ↓ Your Node.js app
install kind
# 1. Download kind
curl -Lo ./kind https://kind.sigs.k8s.io/dl/latest/kind-linux-amd64

# 2. Give it permission to execute
chmod +x ./kind

# 3. Put it somewhere available system-wide
sudo mv ./kind /usr/local/bin/kind

# 4. Verify
kind version
kind v0.30.0 go1.24.4 linux/amd64
chmod +x ./kind"Linux, this file is a program — allow me to run it." Without this: Permission denied.
mv ./kind /usr/local/bin/kindMoves the file into a folder that's already on your PATH, so kind works from any directory.
kind versionVerification only — confirms download, execute permission, and PATH placement all worked.
Download ✅ ↓ Executable ✅ ↓ Moved to PATH ✅ ↓ kind command ✅
💡 Important distinction: chmod does not install kind — it only makes the downloaded file executable. mv is what puts it on your PATH, letting you run kind from anywhere. Since you may already be root in some WSL setups, sudo can sometimes be dropped — check your prompt.

Step 6 — Install Helm
Ubuntu (WSL2)
curl -fsSL https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash

helm version
Ubuntu / WSL2 │ ├── docker ├── kubectl ├── kind └── helm
💬 Helm is a package manager for Kubernetes — the same relationship Docker has to images, Helm has to full sets of Kubernetes config.
ToolRole
DockerPackages your application into an image
KubernetesRuns and manages your application
HelmPackages and installs Kubernetes configuration

Without Helm, one app might mean four separate YAML files applied one by one:

without Helm
kubectl apply -f deployment.yaml
kubectl apply -f service.yaml
kubectl apply -f configmap.yaml
kubectl apply -f secret.yaml

With Helm, the same resources become one chart, installed in a single command:

with Helm
helm install my-app ./my-chart

The value multiplies fast once you have several services:

Without Helm With Helm auth-service auth-service ├── deployment.yaml └── Helm Chart ├── service.yaml ├── configmap.yaml payment-service └── secret.yaml └── Helm Chart payment-service ├── deployment.yaml ├── service.yaml ├── configmap.yaml └── secret.yaml

You customize values per service instead of duplicating whole YAML files.
