1. Why TypeScript Exists & Setup

Why TypeScript Exists

JavaScript is dynamically typed — a variable can silently change type:

plain.js
let age = 25;
age = "hello"; // allowed

TypeScript adds static typing, so many mistakes are caught before running the code:

typed.ts
let age: number = 25;
age = "hello"; // ❌ compile-time error
⚠️ Important: TypeScript types disappear after compilation. The runtime is still plain JavaScript.

Setup: tsc & tsconfig.json

tsc is the TypeScript compiler — it converts .ts → .js.

terminal
tsc            # compile the project
tsc --init     # create a tsconfig.json
tsconfig.json
{
  "compilerOptions": {
    "strict": true,
    "target": "ES2022",
    "module": "NodeNext",
    "outDir": "./dist"
  }
}
OptionMeaning
strictEnables strong, comprehensive type checking ⭐
targetThe JavaScript version TypeScript should generate
moduleWhich module system is used (e.g. import/export)
outDirWhere compiled JS files are written
✅ Interview point: strict: true is generally recommended for production TypeScript projects.
2. Basic Types

Primitives, Arrays & Tuples

basics.ts
let name: string = "Shivam";
let age: number = 25;
let active: boolean = true;

let skills: string[] = ["Node", "React"];

let user: [string, number] = ["Shivam", 25]; // tuple
ConceptExample
Primitivestring, number, boolean
Arraylet names: string[] or Array<string>
Tuple[string, number] — fixed structure, fixed type per position

Special Types: any, unknown, void, never

special-types.ts
let value: any = "hello";       // disables most type checking
let data: unknown = "hello";    // safer than any
function log(): void {}         // returns nothing
function fail(): never {
  throw new Error("Error");
}

Using unknown safely requires narrowing first:

narrow-unknown.ts
let data: unknown = "hello";

if (typeof data === "string") {
  console.log(data.toUpperCase());
}
TypeMeaning
anyNo type safety — everything is allowed
unknownType-safe — must narrow before use
voidFor functions that don't return a value
neverA value that never occurs — e.g. a function that always throws or never returns
💡 Interview point: prefer unknown over any when the type is genuinely unknown — unknown still forces you to narrow the type before using it.
3. Type Inference & type vs interface

Type Inference vs Explicit Typing

TypeScript can automatically understand a type from the assigned value:

inference.ts
let name = "Shivam";
// inferred as string — no need for: let name: string = "Shivam";

Explicit typing earns its place when the type isn't obvious — most commonly on function parameters:

explicit.ts
function add(a: number, b: number): number {
  return a + b;
}
✅ Rule: let TypeScript infer simple, obvious types; explicitly type function parameters, public APIs, and complex objects.

type vs interface

type
type User = {
  id: number;
  name: string;
};
interface
interface User {
  id: number;
  name: string;
}

⚠️ Interview answer: don't say one is always better — for plain object shapes, both work; the choice depends on the use case.
4. Union & Intersection, Literal Types, Enums

Union | and Intersection &

Union = OR

union.ts
let id: string | number;

id = 10;       // ✅
id = "abc";    // ✅

Meaning: the value can be string OR number.

Intersection = AND

intersection.ts
type User = { name: string; };
type Admin = { permissions: string[]; };

type AdminUser = User & Admin;

const user: AdminUser = {
  name: "Shivam",
  permissions: ["read", "write"]
};

AdminUser must satisfy both types at once.

Literal Types

A literal type allows only a specific set of exact values:

literal.ts
let role: "user" | "admin";

role = "user";  // ✅
role = "admin"; // ✅
role = "guest"; // ❌

Very useful for fixed sets of values:

status.ts
type Status = "pending" | "success" | "failed";

This is often preferred over enums for simple fixed values.

Enums

enum.ts
enum Role {
  USER = "user",
  ADMIN = "admin"
}

let role: Role = Role.ADMIN;

Enums work, but many modern TypeScript projects prefer a string union instead:

preferred.ts
type Role = "user" | "admin";

Because string unions are simpler and don't introduce an additional runtime enum object.

⚠️ Interview point: don't claim enums are wrong — they're valid; the choice depends on project requirements.
Interview Q&A — All 26 Questions
💡 TypeScript Stage 1 — Interview Q&A
Fundamentals
1. What is TypeScript?
TypeScript is a superset of JavaScript that adds static typing and other features. It helps detect type-related errors during development/compilation, before the code runs.
example.ts
let age: number = 25;
age = "hello"; // ❌ TypeScript error
2. What is static typing?
Static typing means variable types are checked during compile time rather than relying only on runtime behavior. TypeScript rejects let name: string = "John"; name = 10; — plain JavaScript would allow it silently.
3. What is compile-time checking?
TypeScript checks the code for type errors before converting it to JavaScript. Calling add(10, "20") when both parameters are typed number fails at compile time, helping catch errors before the application runs.
4. What is tsc?
tsc is the TypeScript compiler. It converts TypeScript code into JavaScript: app.ts → tsc → app.js.
5. What is tsconfig.json?
It contains the configuration for the TypeScript compiler — options like strict, target, module, and outDir — telling TypeScript how to compile the project.
6. What does strict mean in TypeScript?
strict enables a group of strict type-checking rules — it helps catch issues such as using a variable before it's definitely assigned. In production TypeScript projects, strict: true is generally recommended.
7. What is target in TypeScript?
target specifies the JavaScript version that TypeScript should generate — e.g. "target": "ES2022" compiles down to ES2022-flavored JavaScript.
8. What is module in TypeScript?
module determines how TypeScript handles JavaScript modules such as import and export. Modern Node.js projects commonly use "module": "NodeNext".
9. What is outDir?
outDir specifies where the compiled JavaScript files should be generated, e.g. src/server.ts → tsc → dist/server.js with "outDir": "./dist".
Basic Types
10. What are the basic types in TypeScript?
The common primitive types are string, number, and boolean — e.g. let name: string = "John"; let age: number = 25; let active: boolean = true;
11. How do you define an array in TypeScript?
let names: string[] = ["John", "Sam"]; or equivalently let names: Array<string> = ["John", "Sam"];
12. What is a tuple?
A tuple is an array with a fixed structure and types at specific positions: let user: [string, number] = ["John", 25]; — index 0 must be a string, index 1 must be a number.
13. What is any?
any disables TypeScript's type checking for that value — it can be reassigned to a string, number, boolean, or object with no errors. Avoid it when possible because it removes type safety.
14. What is unknown?
unknown represents a value whose type isn't known yet, but unlike any, TypeScript requires you to check the type (e.g. with typeof) before using it. any vs unknown: any has no type safety; unknown is type-safe and must be narrowed before use. Prefer unknown when the actual type is genuinely unknown.
15. What is void?
void is generally used for functions that don't return a value — the function performs an action but produces no result, e.g. function logMessage(message: string): void { console.log(message); }
16. What is never?
never represents a value that never occurs — commonly used for functions that never successfully finish, such as one that always throws an error, or one containing an infinite loop that never returns.
Type Inference
17. What is type inference?
TypeScript can automatically determine the type based on the assigned value — let name = "John"; is automatically understood as string, with no need to write let name: string = "John";.
18. When should you use type inference?
Use inference when the type is obvious, e.g. const age = 25; or const name = "John";. Use explicit types when they improve clarity or are required — especially for function parameters, public APIs, complex structures, and external data.
type vs interface
19. What is a type alias?
A type gives a name to a type — it can describe an object shape like type User = { id: number; name: string; };, or represent a union like type ID = string | number;
20. What is an interface?
An interface defines the structure/contract of an object: interface User { id: number; name: string; }
21. What is the difference between type and interface?
type can represent many kinds of types (unions, intersections, primitives, tuples) and is good for flexible composition — e.g. type Status = "active" | "inactive"; can't be directly replaced by a plain interface. interface is mainly used for object/class contracts, and supports extension plus declaration merging. For plain objects, both work fine. Interview answer: don't say one is always better — the choice depends on the use case.
Union & Intersection
22. What is a union type?
A union (symbol |) means a value can be one of multiple types — think "OR." let id: string | number; id = 10; // ✅ id = "abc"; // ✅ id = true; // ❌
23. What is an intersection type?
An intersection (symbol &) combines multiple types — the result must satisfy all of them. Think "AND." type AdminUser = User & Admin; requires every field from both User and Admin.
Literal Types & Enums
24. What is a literal type?
A literal type restricts a value to specific exact values: type Role = "user" | "admin"; — assigning "guest" would be a compile error. Very useful for statuses, roles, and actions.
25. What is an enum?
An enum defines a set of named constants: enum Role { USER = "user", ADMIN = "admin" } let role: Role = Role.ADMIN;
26. Enum vs string union — which should you use?
For simple fixed values, many modern TypeScript projects prefer string unions (type Role = "user" | "admin";) over enums, since string unions are simpler and don't create a runtime enum object. Interview point: don't claim enums are wrong — they are valid, and the choice depends on project requirements.
