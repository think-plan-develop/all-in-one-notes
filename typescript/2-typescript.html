TypeScript — Stage 2 Reference

Functions & Objects — function typing, overloads, index signatures, and structural typing for Node.js/TypeScript work.

Function Typing Overloads & this Object Types Index Signatures & Structural Typing Quick Revision Interview Q&A
💡 Important framing: Stage 2 is where TypeScript stops being "add some annotations" and starts shaping real API design — function contracts, object shapes, and how TypeScript decides two differently-declared things are actually compatible.
🔑 Key Terms at a Glance
🎯
Function overload: Multiple declared signatures for one function, backed by a single implementation — gives callers precise, input-dependent return types.
🔑
Index signature: [key: string]: type — describes an object with dynamic, not-known-in-advance property names.
🚫
Excess property check: TypeScript flags extra properties only on fresh object literals assigned directly to a typed variable.
🧩
Structural typing: TypeScript cares about an object's shape, not the name of the type used to declare it.
🔒
readonly vs const: const locks a variable binding; readonly locks a single property on a type.
🪞
readonly is shallow: It blocks reassigning the property itself, but nested object properties underneath can still be mutated.
1. Function Parameters, Return Types & Defaults

Function Parameters & Return Types

params.ts
function add(a: number, b: number): number {
  return a + b;
}

add(10, 20);

// Wrong: add("10", 20); → error, "10" is a string

Typing every parameter prevents incorrect data from ever entering your function.

Return types, void, and Promise

return-types.ts
function getUserName(id: number): string {
  return "Shivam";
}

function logMessage(message: string): void {
  console.log(message);
}

async function getUser(): Promise<string> {
  return "Shivam";
}

In backend development you'll frequently see the async pattern typed against a real model:

async-user.ts
async function getUser(): Promise<User> {
  // ...
}

Optional Parameters & Default Parameters

optional.ts
function greet(name: string, age?: number) {
  console.log(name, age);
}

greet("Shivam");
greet("Shivam", 25);

age?: number is internally treated approximately as age: number | undefined.

⚠️ Important rule: optional parameters must come after required parameters. function test(age?: number, name: string) {} is invalid.

Default parameters

default.ts
function greet(name: string, role = "user") {
  console.log(name, role);
}

greet("Shivam"); // Shivam user

TypeScript usually infers the type from the default value — role = "user" is inferred as string automatically.

OptionalDefault
function test(a?: number) {}function test(a = 10) {}
a can be undefinedIf nothing is passed, a becomes 10

Rest Parameters

rest.ts
function sum(...numbers: number[]): number {
  return numbers.reduce((total, num) => total + num, 0);
}

sum(10, 20, 30);
printNames.ts
function printNames(...names: string[]): void {
  names.forEach(name => console.log(name));
}

printNames("Shivam", "Rahul", "Amit");
🚨 Important: the rest parameter must be the last parameter — function test(name: string, ...scores: number[]) {} is valid; the reverse order is not.
2. Function Overloads & this Typing ⭐⭐⭐⭐⭐

Function Overloads

Function overloads let one function support different parameter combinations while giving callers precise types.

overloads.ts
function getValue(id: number): string;
function getValue(name: string): number;

function getValue(value: number | string): string | number {
  if (typeof value === "number") {
    return "User";
  }
  return 100;
}

const a = getValue(10);        // string
const b = getValue("Shivam");  // number
PartRole
Overload signaturesDescribe what callers are allowed to do — no body
Implementation signatureThe single real function body — not directly exposed as a callable overload

Real-world example: lookup by ID or email

get-user.ts
function getUser(id: number): User;
function getUser(email: string): User;

function getUser(value: number | string): User {
  // database logic
}
✅ When to reach for overloads: the same function behaves differently based on the input type, and you want precise, input-dependent return types rather than a vaguer union.

this Typing in Functions

this-typing.ts
interface User {
  name: string;
}

function printName(this: User) {
  console.log(this.name);
}

The special this: User parameter exists purely for TypeScript's type checking — it isn't a normal runtime argument.

A more practical example

counter.ts
interface Counter {
  count: number;
  increment(this: Counter): void;
}

const counter: Counter = {
  count: 0,
  increment() {
    this.count++;
  }
};
⚠️ Arrow functions behave differently — they don't have their own this. For object methods, use normal functions when you need the object's own this.
arrow-vs-normal.ts
const obj = {
  name: "Shivam",

  normal() {
    console.log(this.name); // works — has its own `this`
  },

  arrow: () => {
    console.log(this.name); // doesn't behave the same way
  }
};
3. Object Types ⭐⭐⭐⭐⭐

Describing Object Structure

inline-object.ts
function createUser(user: {
  id: number;
  name: string;
  age: number;
}) {
  console.log(user.name);
}

createUser({ id: 1, name: "Shivam", age: 25 });

This works, but for reusable structures, prefer a named interface/type instead:

named-type.ts
interface User {
  id: number;
  name: string;
  age: number;
}

function createUser(user: User) {
  console.log(user.name);
}

Optional Properties & Readonly

optional-props.ts
interface User {
  id: number;
  name: string;
  age?: number;
}

const user1: User = { id: 1, name: "Shivam" };
const user2: User = { id: 2, name: "Rahul", age: 25 };

age is effectively number | undefined.

Readonly properties

readonly.ts
interface User {
  readonly id: number;
  name: string;
}

const user: User = { id: 1, name: "Shivam" };

user.name = "Rahul"; // allowed
user.id = 2;         // ❌ error
⚠️ Important: readonly is mainly a compile-time restriction and is shallow — it doesn't automatically make the object deeply immutable.
shallow-readonly.ts
interface User {
  readonly profile: { name: string };
}

user.profile = {};             // ❌ can't replace it
user.profile.name = "Rahul"; // ✅ but this is allowed
4. Index Signatures, Excess Checks & Structural Typing ⭐⭐⭐⭐⭐

Index Signatures

Used when you don't know the exact property names beforehand — syntax: [key: string]: type

user-roles.ts
interface UserRoles {
  [username: string]: string;
}

const roles: UserRoles = {
  shivam: "admin",
  rahul: "user",
  amit: "user"
};
scores.ts
interface Scores {
  [student: string]: number;
}

const scores: Scores = { Shivam: 90, Rahul: 85, Amit: 95 };
scores["John"] = 80; // any string key allowed

Number index signature — array-like structures

users-by-index.ts
interface Users {
  [index: number]: string;
}

const users: Users = { 0: "Shivam", 1: "Rahul" };

Combining known properties with an index signature

config-valid.ts
interface Config {
  name: string;
  [key: string]: string;
}

const config: Config = {
  name: "API",
  environment: "production",
  region: "ap-south-1"
};
config-invalid.ts
interface Config {
  name: string;
  port: number;                 // ❌ conflicts with the index signature below
  [key: string]: string;
}

port is number, but the index signature demands every string-keyed value be a string — the two conflict.

Excess Property Checks

excess-error.ts
interface User { name: string; age: number; }

const user: User = {
  name: "Shivam",
  age: 25,
  email: "shivam@example.com" // ❌ not defined in User
};

Why does the same shape work through a variable, though?

excess-ok.ts
const data = {
  name: "Shivam",
  age: 25,
  email: "shivam@example.com"
};

const user: User = data; // ✅ works

Excess property checking applies mainly to fresh object literals. Once data is inferred as its own type, TypeScript checks structural compatibility instead — and data already has everything User needs.

Three ways to resolve it

OptionApproach
1. Add the property to the typeBest when the property is genuinely valid — add email: string;
2. Use an index signatureIf arbitrary additional properties are expected: [key: string]: unknown;
3. Store the object firstAssign through a variable rather than an inline literal
🚨 Don't use Option 3 as a trick just to bypass errors. If email is genuinely part of the model, update the type instead of routing around the check.

Structural Typing

TypeScript generally cares about structure, not the explicit name of the type used to declare a value.

structural.ts
interface User { name: string; }

const person = { name: "Shivam", age: 25 };

const user: User = person; // ✅ works
the-logic
// User requires:    name
// person has:       name + age
// Therefore →        compatible

Real-world Node.js pattern

create-user-input.ts
interface CreateUserInput {
  name: string;
  email: string;
  age?: number;
}

function createUser(data: CreateUserInput): User {
  // database logic
}

This one function combines object typing, required properties, optional properties, function parameter typing, and return typing — a pattern that appears constantly in backend TypeScript.

⭐ Important Interview Q&A
💡 TypeScript Stage 2 — Interview Q&A
1. What is the difference between optional and default parameters?
Optional: function test(age?: number) {} — the argument can be omitted and becomes undefined.
Default: function test(age = 25) {} — if omitted, age becomes 25.
2. How do you type a rest parameter?
function sum(...numbers: number[]) {} — every extra argument is collected into a typed array.
3. What are function overloads?
Multiple function signatures for the same function name, backed by one implementation:
overload-recap.ts
function get(id: number): User;
function get(email: string): User;
function get(value: number | string): User {
  // implementation
}
4. What is an index signature?
It defines the type of dynamically named properties on an object: interface Dictionary { [key: string]: string; }
5. What is an excess property check?
TypeScript checks object literals for properties that aren't defined in the target type:
excess-recap.ts
interface User { name: string; }

const user: User = {
  name: "Shivam",
  age: 25 // Error
};
6. What is structural typing?
TypeScript checks whether an object's structure/shape satisfies the required type — not what name was used to declare it:
structural-recap.ts
interface User { name: string; }

const person = { name: "Shivam", age: 25 };

const user: User = person; // OK
7. Difference between readonly and const?
const prevents reassigning the variable binding — const user = {}; user = {}; is an error, but properties on that object can still change: user.name = "Shivam"; is fine.

readonly prevents changing a particular property on a type: interface User { readonly id: number; }.

Interview line: const applies to a variable binding; readonly applies to a property/type member.
