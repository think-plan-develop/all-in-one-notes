Stage 5 — Classes & OOP in TypeScript
1

Access Modifiers

Control where a property/method can be accessed.

ts
class User {
  public name = "Shivam";      // accessible everywhere
  private password = "123";   // only inside User
  protected role = "user";    // User + child classes
}
  • public → anywhere
  • private → only same class
  • protected → same class + subclasses
2

readonly + Parameter Properties

readonly means value cannot be reassigned after initialization.

ts
class User {
  readonly id: number;

  constructor(id: number) {
    this.id = id;
  }
}

Parameter property = shortcut for declaring and assigning constructor properties.

ts — shortcut
class User {
  constructor(
    public name: string,
    private age: number
  ) {}
}

Instead of:

ts — verbose
class User {
  public name: string;
  private age: number;

  constructor(name: string, age: number) {
    this.name = name;
    this.age = age;
  }
}
3

Abstract Classes

A base class that cannot be directly instantiated.

ts
abstract class Animal {
  abstract sound(): void;

  move() {
    console.log("Moving");
  }
}

class Dog extends Animal {
  sound() {
    console.log("Bark");
  }
}

Useful when multiple classes share common behavior but must implement some methods differently.

4

Interfaces Implemented by Classes

A class can implement an interface.

ts
interface Payment {
  pay(amount: number): void;
}

class CardPayment implements Payment {
  pay(amount: number) {
    console.log(`Paid ${amount}`);
  }
}
  • interface → defines contract
  • implements → class follows that contract
5

Static Members

Belong to the class itself, not an object.

ts
class MathUtil {
  static add(a: number, b: number) {
    return a + b;
  }
}

MathUtil.add(10, 20);

You don't need const obj = new MathUtil();

Common for utility functions/constants.

6

Generics in Classes

Makes a class reusable with different types.

ts
class Box<T> {
  constructor(public value: T) {}
}

const userBox = new Box<User>(user);
const numberBox = new Box<number>(100);

T is determined when the class is used.

Practice:

Shape ├── Circle └── Rectangle

Use:

  • Abstract class
  • Interface
  • private
  • protected
  • readonly
Stage 6 — Modules, Namespaces & Declaration Files
1

ES Modules

Use export and import to share code between files.

user.ts
export interface User {
  id: number;
}
app.ts
import { User } from "./user.js";

This is the preferred modern approach.

2

Module Resolution

TypeScript determines where an imported module exists.

ts
import { User } from "./models/User";

TypeScript needs to find User.ts. Common strategies include:

  • node
  • NodeNext
  • bundler

For modern Node.js projects, you'll commonly see NodeNext.

3

.d.ts Declaration Files

Used to provide TypeScript types for JavaScript code that doesn't have types.

Example untyped JS:

math.js
function add(a, b) {
  return a + b;
}

module.exports = { add };

Create:

math.d.ts
export function add(a: number, b: number): number;

Now TypeScript understands the JS module.

4

declare

Tells TypeScript: "This exists somewhere at runtime; just give me its type."

ts
declare const API_URL: string;

TypeScript doesn't generate JavaScript for the declaration.

5

Global Augmentation

Used to add types to existing global/library types.

ts
declare global {
  interface Window {
    userId: string;
  }
}

Now window.userId is understood by TypeScript.

6

@types

Community-provided TypeScript definitions.

bash
npm install -D @types/express

This gives TypeScript types for libraries that don't provide their own types.

📌 DefinitelyTyped is the major repository for these definitions.
7

Namespaces

Older TypeScript organization mechanism:

ts
namespace Utils {
  export function add(a: number, b: number) {
    return a + b;
  }
}

Know it for interviews, but for modern applications:

  • ES Modules > Namespaces

Practice:

legacy-library.js legacy-library.d.ts app.ts

and add types for the JS library.

Stage 7 — TypeScript with Real Tools

Node.js / Express

Type request, response, middleware, etc.

ts
import { Request, Response } from "express";

function getUser(req: Request, res: Response) {
  res.json({ name: "Shivam" });
}

Custom request properties can also be typed. req.user requires extending Express types.

Environment Variables

process.env values are generally string | undefined.

ts
const PORT = process.env.PORT;

if (!PORT) {
  throw new Error("PORT missing");
}
⚠️ Don't blindly assume environment variables exist.

React

Props

tsx
interface UserProps {
  name: string;
  age: number;
}

function User({ name, age }: UserProps) {
  return <div>{name}</div>;
}

State

tsx
const [count, setCount] = useState<number>(0);

Event

tsx
const handleChange = (
  e: React.ChangeEvent<HTMLInputElement>
) => {
  console.log(e.target.value);
};

useReducer — type state and actions:

tsx
useReducer(reducer, initialState);

Very useful for complex state.

Testing

Type mocks and test utilities so incorrect mock data is caught at compile time.

ts
const mockUser: User = {
  id: 1,
  name: "Shivam"
};

Practice: take one small Node/Express or React project and convert it completely to:

tsconfig.json
{
  "strict": true
}
✅ This is one of the best ways to learn practical TypeScript.
Stage 8 — Tooling & Best Practices
1

strictNullChecks

Prevents treating null/undefined as normal values.

ts
let name: string | undefined;

name.toUpperCase(); // Error

You must check first:

ts
if (name) {
  name.toUpperCase();
}
2

noImplicitAny

Prevents TypeScript from silently treating values as any.

Bad

function add(a, b) { return a + b; }

Better

function add(a: number, b: number): number { return a + b; }

3

Path Aliases

Instead of:

ts
import User from "../../../models/User";

you can configure aliases:

ts
import User from "@/models/User";

Configured in tsconfig.json.

4

ESLint + TypeScript

@typescript-eslint provides ESLint rules specifically for TypeScript.

Helps detect:

  • Unsafe code
  • Unused variables
  • Bad patterns
  • Unnecessary any
5

import type

Used when importing something only for TypeScript types.

ts
import type { User } from "./types.js";

This makes the intention clear and can avoid unnecessary runtime imports.

6

Avoid any

any basically disables TypeScript checking. Prefer unknown for data whose type you don't know.

ts
function process(data: unknown) {
  if (typeof data === "string") {
    console.log(data.toUpperCase());
  }
}

any

Use without checking

unknown

Must check before using

7

Type Complexity

Don't create extremely complicated generic/conditional types unless necessary.

Too much type-level programming can:

  • Slow compilation
  • Make errors difficult to understand
  • Make code harder to maintain
  • Prefer simple, readable types.
