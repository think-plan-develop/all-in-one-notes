🔑 Key Terms at a Glance
📦
tsx: Runs TypeScript files directly without a separate compile step — great for quick practice.
🧩

🔀

⏳

🧬

🔗

Practice 3 — Objects & Why Interfaces Exist

Inline Object Types

object.ts
const user: {
  name: string;
  age: number;
} = {
  name: "John",
  age: 25
};

Optional field — add ?:

optional-field.ts
const user: {
  name: string;
  age: number;
  phone?: string;
} = {
  name: "John",
  age: 25
};

Nested object + array — closer to real application data:

nested.ts
const user: {
  id: number;
  name: string;
  email: string;
  skills: string[];
  address: {
    city: string;
    country: string;
  };
} = {
  id: 101,
  name: "John",
  email: "john@example.com",
  skills: ["Node.js", "TypeScript"],
  address: { city: "Hyderabad", country: "India" }
};

Completely valid — but writing large object types this way over and over gets annoying fast. That's exactly where interfaces earn their keep.

Why Interfaces Are Useful

Suppose you have 10 users. Without an interface, the same shape gets typed out again and again:

repetitive.ts
const user1: { id: number; name: string; age: number; } = {
  id: 1, name: "John", age: 25
};

const user2: { id: number; name: string; age: number; } = {
  id: 2, name: "Alex", age: 30
};

With an interface, the shape is named once and reused everywhere:

with-interface.ts
interface User {
  id: number;
  name: string;
  age: number;
}

const user1: User = { id: 1, name: "John", age: 25 };
const user2: User = { id: 2, name: "Alex", age: 30 };
Practice 4 — Functions

The Full Range of Function Signatures

functions.ts
function add(a: number, b: number): number {
  return a + b;
}

// Parameters
function add(a: number, b: number)

// Return type
function add(a: number, b: number): number

// Object parameter
function getUser(user: User): User

// Array parameter
function getTotal(numbers: number[]): number

// Array return
function getUsers(): User[]

// No useful return
function printUser(user: User): void

// Optional parameter
function greet(name?: string)

// Default parameter
function greet(name: string = "Guest")

// Rest parameter
function sum(...numbers: number[]): number

// Arrow function
const add2 = (a: number, b: number): number => a + b;

// Async function
async function getUser(): Promise<User>
Signature shapeWhat it means
(a: number, b: number)Both parameters must be numbers
: numberThe return value must be a number
user: UserParameter must match the User shape
numbers: number[]Parameter is an array of numbers
(): User[]Returns an array of User
: voidNo useful return value
name?: stringParameter is optional
name: string = "Guest"Falls back to "Guest" when omitted
...numbers: number[]Accepts any number of number arguments
: Promise<User>An async function that eventually resolves to a User
Practice 5 — Interfaces & Types

What Is an Interface?

interface.ts
interface User {
  id: number;
  name: string;
  email: string;
}

const user: User = {
  id: 1,
  name: "John",
  email: "john@test.com"
};

An interface defines the structure/shape of an object. You could write the same shape inline instead:

inline-equivalent.ts
const user: {
  id: number;
  name: string;
  email: string;
} = {
  id: 1,
  name: "John",
  email: "john@test.com"
};

The interface version is better whenever the same structure is used in multiple places.

Interfaces With an Async API Response

get-user.ts
async function getUser(): Promise<User> {
  // API/database logic
}

What does Promise<User> mean?

User ↓ actual user object — I have it now Promise<User> ↓ promise of getting a user — I will get it asynchronously

Two parts of the signature carry two different meanings:

PartMeaning
async function getUser()This function is asynchronous
: Promise<User>This asynchronous function will eventually return a User

Interface Extension & Interface vs Type

Interfaces can be extended — this becomes important later for shared base shapes:

extends.ts
interface User {
  id: number;
  name: string;
}

interface Admin extends User {
  permissions: string[];
}

const admin: Admin = {
  id: 1,
  name: "John",
  permissions: ["read", "write"]
};
User ↓ extends Admin Admin gets everything from User, plus its own properties.

Interface vs Type — basic idea

interface-vs-type.ts
interface User { id: number; name: string; }

type User2 = { id: number; name: string; };
interfacetype
Commonly used for object/class contractsMore flexible — unions, intersections, primitives, tuples, etc.

For simple object structures, both work fine — you'll see the real differences once you dig into unions and intersections directly.

Practice 6 — Union Types

Basic Unions & Union Return Types

union-variable.ts
let id: number | string;

id = 101;
id = "USR101";
union-return.ts
function getId(): number | string {
  return 101;
}

Union With Arrays — Parentheses Matter

string-or-array.ts
let data: string | number[];

// means: string  OR  array of numbers

data = "hello";       // ✅
data = [10, 20, 30]; // ✅
data = [10, "hello"]; // ❌ mixed array not allowed

If you actually want an array that can mix strings and numbers, wrap the union in parentheses first:

mixed-array.ts
let data2: (string | number)[];

data2 = [10, "hello", 20, "world"]; // ✅ valid
Written asMeans
string | number[]Either a plain string, OR an array of numbers
(string | number)[]An array where every element can be a string OR a number
🚨 The parentheses change everything. Missing them is one of the easiest union mistakes to make.
Practice 7 — Generics

Basic Generic Function

Generics let you write reusable code while still keeping the actual type information — heavily used for API responses, reusable functions, database utilities, services, repositories, and collections.

generic-value.ts
function getValue<T>(value: T): T {
  return value;
}

const name = getValue<string>("John");
const age = getValue<number>(25);

Instead of writing a separate near-identical function per type:

without-generics.ts
function getNumber(value: number): number {
  return value;
}

...one generic function covers every type:

with-generics.ts
function getValue<T>(value: T): T {
  return value;
}
💡 T is a generic type parameter. Think of it as: "I don't know the type yet — tell me when this function is used."

Constraints — When T Alone Isn't Enough

fails.ts
function exampFunc<T>(a: T, b: T): T {
  return a + b; // ❌ TypeScript doesn't know T supports +
}

This fails because TypeScript has no guarantee that whatever T ends up being actually supports the + operator. Adding a constraint fixes it:

constrained.ts
function calculateTotal<T extends { price: number; quantity: number; }>(
  item: T
): number {
  return item.price * item.quantity;
}

The constraint explicitly tells TypeScript that T must have price: number and quantity: number — so item.price * item.quantity is now known to be valid. This is where generics + constraints become genuinely useful.

Generic Arrays & Generic API Responses

generic-array.ts
function getFirst<T>(items: T[]): T {
  return items[0];
}

Compare to writing one function per type:

per-type-versions.ts
function getFirstNumber(items: number[]): number {
  return items[0];
}

function getFirstString(items: string[]): string {
  return items[0];
}

// vs. one generic version covering both:
function getFirst<T>(items: T[]): T {
  return items[0];
}

A generic shape for any API response

Real responses vary in what data holds:

response-a.json
{
  "success": true,
  "data": [ { "id": 1, "name": "John" } ]
}
response-b.json
{
  "success": true,
  "data": 500
}

One generic interface covers every shape data could take:

api-response.ts
interface ApiResponse<T> {
  success: boolean;
  data: T;
}
✅ ApiResponse<User[]>, ApiResponse<number>, or ApiResponse<User> all reuse the exact same interface — only the generic parameter changes per endpoint.
Practice 8 — Advanced Types
1

Partial<T>

Makes all properties optional.

ts
interface User {
  id: number;
  name: string;
  email: string;
}

const update: Partial<User> = {
  name: "Shivam"
};
  • Use: very common for PATCH/update APIs.
2

Readonly<T>

Makes properties readonly.

ts
const user: Readonly<User> = {
  id: 1,
  name: "Shivam",
  email: "x@test.com"
};
🚫 Not allowed: user.name = "Rahul"
  • Use: when an object should not be modified.
3

Pick<T, K>

Select only specific properties.

ts
type PublicUser = Pick<User, "id" | "name">;
// { id: number; name: string; }
  • Pick = choose
4

Omit<T, K>

Remove specific properties.

ts
type PublicUser = Omit<User, "email">;
  • Omit = remove

Very useful for removing fields like password, refreshToken from API types.

5

Record<K, T>

Creates an object type with specific keys and a value type.

ts
type Role = "admin" | "user";

const permissions: Record<Role, string[]> = {
  admin: ["create", "delete"],
  user: ["read"]
};
  • Record<Key, Value>
6

Conditional Types

Conditional types are basically if/else at the type level.

ts
type IsString<T> =
  T extends string ? true : false;

IsString<string> // true
IsString<number> // false
  • T extends U ? X : Y means: if T extends U → X, otherwise → Y.
7

infer

infer lets TypeScript extract a type.

ts
type ArrayElement<T> =
  T extends Array<infer U>
    ? U
    : never;

type Result = ArrayElement<string[]>; // string
  • infer = extract a type
8

Template Literal Types

Used to create specific string types.

ts
type Direction = "top" | "bottom";

type Margin = `margin-${Direction}`;
// "margin-top" | "margin-bottom"
  • It's like JavaScript template strings, but at the type level.
9

Discriminated Unions

A union where one common property identifies which type you have.

ts
type Result =
  | { status: "success"; data: User; }
  | { status: "error"; message: string; };

if (result.status === "success") {
  result.data; // TS knows this is the success type
}

status is the discriminator.

Very useful for:

  • API states
  • Redux actions
  • Loading / success / error states
  • Event handling
10

Type Guards

Type guards help TypeScript narrow a type.

  • typeof — checks primitive types.
  • instanceof — checks class/object instances.
  • in — checks property existence.
typeof
function print(value: string | number) {
  if (typeof value === "string") {
    value.toUpperCase();
  }
}
instanceof
if (value instanceof User) {
  value.name;
}
in
if ("email" in value) {
  value.email;
}
11

Custom Type Predicate — is

You can create your own type guard.

ts
function isString(value: unknown): value is string {
  return typeof value === "string";
}

if (isString(value)) {
  value.toUpperCase();
}
  • value is string tells TypeScript: if this function returns true, treat value as a string.
12

in Operator

Used to check whether an object contains a property.

ts
type Admin = { permissions: string[]; };
type User = { email: string; };

function handle(account: Admin | User) {
  if ("permissions" in account) {
    account.permissions;
  } else {
    account.email;
  }
}
13

never and Exhaustiveness

never represents something that should never happen.

Common pattern:

ts
function assertNever(value: never): never {
  throw new Error("Unexpected value");
}

Used with a discriminated union:

ts
switch (action.type) {
  case "login":
    break;
  case "logout":
    break;
  default:
    assertNever(action);
}

If you later add a new action but forget to handle it, TypeScript can catch the problem.

  • never = impossible/unhandled state
