Stage 3 — Generics
1

Why Generics Exist

Generics let you write reusable code that remains type-safe.

Without generics:

ts
function identity(value: any) {
  return value;
}

With generics:

ts
function identity<T>(value: T): T {
  return value;
}

T represents the type provided by the caller.

ts
identity("hello"); // string
identity(100);     // number
  • Generic = reusable + type-safe.
2

Generic Functions

A function that can work with different types.

ts
function getFirst<T>(items: T[]): T {
  return items[0];
}

getFirst([1, 2, 3]);        // number
getFirst(["a", "b", "c"]);  // string

TypeScript automatically infers T.

3

Generic Interfaces

An interface that can work with different types.

ts
interface ApiResponse<T> {
  success: boolean;
  data: T;
}

Use it:

ts
ApiResponse<User>
ApiResponse<Product>
ApiResponse<User[]>

Very common for API response structures.

4

Generic Classes

A class that can work with different types.

ts
class Box<T> {
  constructor(private value: T) {}

  getValue(): T {
    return this.value;
  }
}

const box = new Box<string>("Hello");
const numberBox = new Box<number>(100);
5

Generic Constraints — extends

Restricts what types can be passed.

ts
function getLength<T extends { length: number }>(value: T) {
  return value.length;
}

Works

getLength("hello")
getLength([1, 2, 3])

Doesn't work

getLength(100)

  • T extends X means T must satisfy X.
6

keyof with Generics

keyof gets the keys of a type.

ts
interface User {
  id: number;
  name: string;
}

type Keys = keyof User; // "id" | "name"

Common generic pattern:

ts
function getProperty<T, K extends keyof T>(
  obj: T,
  key: K
) {
  return obj[key];
}

Now invalid keys are rejected.

7

Default Generic Types

You can give a generic a default.

ts
interface ApiResponse<T = string> {
  data: T;
}

So ApiResponse means ApiResponse<string>, but you can override it with ApiResponse<number>.

8

Generic ApiResponse<T>

Very important for backend/frontend projects.

ts
interface ApiResponse<T> {
  success: boolean;
  data: T;
  message: string;
}

Then: ApiResponse<User>, ApiResponse<Product>, ApiResponse<User[]> — one structure works for multiple response types.

9

Generic fetchData<T>

Common API pattern:

ts
async function fetchData<T>(url: string): Promise<T> {
  const response = await fetch(url);
  return response.json() as Promise<T>;
}

Usage:

ts
const user = await fetchData<User>("/api/user");
⚠️ Generics provide compile-time typing. They do not validate actual API data at runtime.
Stage 4 — Advanced Types
1

Partial<T>

Makes all properties optional.

ts
interface User {
  id: number;
  name: string;
  email: string;
}

const update: Partial<User> = {
  name: "Shivam"
};
  • Use: very common for PATCH/update APIs.
2

Readonly<T>

Makes properties readonly.

ts
const user: Readonly<User> = {
  id: 1,
  name: "Shivam",
  email: "x@test.com"
};
🚫 Not allowed: user.name = "Rahul"
  • Use: when an object should not be modified.
3

Pick<T, K>

Select only specific properties.

ts
type PublicUser = Pick<User, "id" | "name">;
// { id: number; name: string; }
  • Pick = choose
4

Omit<T, K>

Remove specific properties.

ts
type PublicUser = Omit<User, "email">;
  • Omit = remove

Very useful for removing fields like password, refreshToken from API types.

5

Record<K, T>

Creates an object type with specific keys and a value type.

ts
type Role = "admin" | "user";

const permissions: Record<Role, string[]> = {
  admin: ["create", "delete"],
  user: ["read"]
};
  • Record<Key, Value>
6

Conditional Types

Conditional types are basically if/else at the type level.

ts
type IsString<T> =
  T extends string ? true : false;

IsString<string> // true
IsString<number> // false
  • T extends U ? X : Y means: if T extends U → X, otherwise → Y.
7

infer

infer lets TypeScript extract a type.

ts
type ArrayElement<T> =
  T extends Array<infer U>
    ? U
    : never;

type Result = ArrayElement<string[]>; // string
  • infer = extract a type
8

Template Literal Types

Used to create specific string types.

ts
type Direction = "top" | "bottom";

type Margin = `margin-${Direction}`;
// "margin-top" | "margin-bottom"
  • It's like JavaScript template strings, but at the type level.
9

Discriminated Unions

A union where one common property identifies which type you have.

ts
type Result =
  | { status: "success"; data: User; }
  | { status: "error"; message: string; };

if (result.status === "success") {
  result.data; // TS knows this is the success type
}

status is the discriminator.

Very useful for:

  • API states
  • Redux actions
  • Loading / success / error states
  • Event handling
10

Type Guards

Type guards help TypeScript narrow a type.

  • typeof — checks primitive types.
  • instanceof — checks class/object instances.
  • in — checks property existence.
typeof
function print(value: string | number) {
  if (typeof value === "string") {
    value.toUpperCase();
  }
}
instanceof
if (value instanceof User) {
  value.name;
}
in
if ("email" in value) {
  value.email;
}
11

Custom Type Predicate — is

You can create your own type guard.

ts
function isString(value: unknown): value is string {
  return typeof value === "string";
}

if (isString(value)) {
  value.toUpperCase();
}
  • value is string tells TypeScript: if this function returns true, treat value as a string.
12

in Operator

Used to check whether an object contains a property.

ts
type Admin = { permissions: string[]; };
type User = { email: string; };

function handle(account: Admin | User) {
  if ("permissions" in account) {
    account.permissions;
  } else {
    account.email;
  }
}
13

never and Exhaustiveness

never represents something that should never happen.

Common pattern:

ts
function assertNever(value: never): never {
  throw new Error("Unexpected value");
}

Used with a discriminated union:

ts
switch (action.type) {
  case "login":
    break;
  case "logout":
    break;
  default:
    assertNever(action);
}

If you later add a new action but forget to handle it, TypeScript can catch the problem.

  • never = impossible/unhandled state
