⚛️ 1. React Fundamentals — 10 min
JSX, Props/State, Components & Rendering
These check the basics: what JSX compiles to, the props-vs-state distinction, controlled vs uncontrolled inputs, why keys matter, how data flows up, and the three ways to render conditionally.
  • Q1. What is JSX? How is it different from HTML?
  • Q2. What is the difference between props and state?
  • Q3. What are controlled and uncontrolled components?
  • Q4. Why do we use key when rendering lists? Why can an array index cause problems?
  • Q5. How can a child component pass data to its parent?
  • Q6. What is conditional rendering? Explain using if, the ternary operator, and &&.
💡 What a strong answer covers: Q2 — props are read-only and passed down; state is owned and mutated by the component itself. Q4 — index-as-key breaks when items are reordered, inserted, or removed, causing React to misattribute state/DOM to the wrong row. Q5 — the parent passes a callback down as a prop; the child calls it with data.
🪝 2. Hooks & State — 15 min
useState, useEffect, useRef, Context & Custom Hooks
  • Q7. What does useState do? When should you use its functional updater?
Q7-functional-update.jsx
setCount(prev => prev + 1);
📝 Expected answer: use the functional updater whenever the new state depends on the previous state — especially inside loops, timers, or multiple calls in the same event handler — since count in a closure can be stale.
  • Q8. How would you update one property in an object stored in state without removing the other properties?
  • Q9. How would you add, delete, and update an item in an array stored in state?
  • Q10. What is the difference between these three effects?
Q10-effects.jsx
useEffect(() => {
  // ...
});

useEffect(() => {
  // ...
}, []);

useEffect(() => {
  // ...
}, [userId]);
📝 Expected answer: no array → after every render; [] → once, after the first render; [userId] → after the first render and again whenever userId changes.
  • Q11. What is the purpose of the cleanup function in useEffect? Give an example involving a timer.
  • Q12. How does useRef differ from useState? How would you focus an input using a ref?
  • Q13. What is prop drilling, and how can Context help?
  • Q14. What is a custom hook? When would you create one?
💡 What a strong answer covers: Q11 — cleanup runs before the next effect and on unmount; for a timer it's clearInterval/clearTimeout, preventing leaks and duplicate timers. Q12 — updating a ref does not trigger a re-render and its value persists across renders; focusing an input means attaching the ref via ref= and calling ref.current.focus().
🔍 3. Code Understanding — 10 min
Question 15 — State Updates (5 min)
Assume count starts at 0. What appears on the button after one click?
Q15-counter.jsx
function Counter() {
  const [count, setCount] = useState(0);

  function handleClick() {
    setCount(count + 1);
    setCount(count + 1);
  }

  return <button onClick={handleClick}>{count}</button>;
}
  • Why does this happen?
  • How would you make one click increase the count by two?
⚠️ Answer: the button shows 1, not 2. Both calls close over the same count value from that render (0), so both schedule "set to 0 + 1" — the second call doesn't see the first's result.
Q15-fixed.jsx
function handleClick() {
  setCount(prev => prev + 1);
  setCount(prev => prev + 1);
}
✅ Fix: use the functional updater form so each call sees the latest pending value, giving a correct +2.
Question 16 — Event Handlers (5 min)
Which examples call deleteTodo during rendering, and which call it when clicked?
Q16-handlers.jsx
// A
<button onClick={deleteTodo(id)}>Delete</button>

// B
<button onClick={() => deleteTodo(id)}>Delete</button>

// C
<button onClick={deleteTodo}>Delete</button>
  • Which would you use to pass a task ID?
  • What argument does React pass to the handler in example C?
⚠️ Answer: A calls deleteTodo(id) immediately during render — its return value (likely undefined) becomes the handler, so clicking does nothing. B and C only run on click.
✅ Answer: use B to pass an ID — the arrow function defers the call until the click happens. In C, React passes the native SyntheticEvent object as the argument, not an ID.
⌨️ 4. React Coding — 25 min
Task 1 — Search and Filter a List (10 min)
Tests controlled search input, derived/filtered rendering, and an empty state.
users-data.js
const users = [
  { id: 1, name: "Shivam" },
  { id: 2, name: "Amit" },
  { id: 3, name: "Neha" },
  { id: 4, name: "Anil" },
];

📋 Requirements

  • Display all users initially.
  • Add a search input.
  • Filter users by name as the user types.
  • Make the search case-insensitive.
  • Show "No users found" when nothing matches.
  • Use stable keys.
🔁 Follow-up: Do you need separate state for the filtered list? Explain your choice.
💡 Expected reasoning: no — filter the original users array on every render based on the search text (derived value), rather than keeping a second "filteredUsers" state that can drift out of sync.
Task 2 — Build a Simple Registration Form (15 min)
Tests controlled inputs, field-level validation, and handling submit without a page reload.

📋 Create a form with

  • Name input.
  • Email input.
  • Password input.
  • Submit button.

✅ Requirements

  • Use controlled inputs.
  • Make all fields required.
  • Reject a name containing only spaces.
  • Require a password of at least eight characters.
  • Display validation errors beside the relevant fields.
  • Prevent the default page reload on submission.
  • Show a success message when the form is valid.
  • Clear the inputs after successful submission.
📝 No API integration is required.
🔁 Follow-ups: How would you handle several inputs using one onChange handler? How would you disable the submit button while an API request is pending?
