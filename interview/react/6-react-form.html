💻 Full Working Example
One Handler for Text, Radio, Checkbox & Select
A single dynamic handleChange updates every field type by reading e.target.name and e.target.type — no separate handler per field. Options for gender, city and language are each driven by a small array and rendered with .map(), so adding a new option never touches the JSX.
App.jsx
import { useState } from "react";

const genderOptions = [
  { label: "Male", value: "male" },
  { label: "Female", value: "female" },
  { label: "Other", value: "other" },
];

const cityOptions = [
  { label: "Delhi", value: "delhi" },
  { label: "Mumbai", value: "mumbai" },
  { label: "Hyderabad", value: "hyderabad" },
];

const languageOptions = [
  { label: "English", value: "english" },
  { label: "Hindi", value: "hindi" },
  { label: "Telugu", value: "telugu" },
];

function App() {
  const [form, setForm] = useState({
    name: "",
    email: "",
    gender: "",
    city: "mumbai",
    language: [],
  });

  const handleChange = (e) => {
    const { name, value, type, checked } = e.target;

    setForm((prev) => ({
      ...prev,
      [name]:
        type === "checkbox"
          ? checked
            ? [...prev[name], value]
            : prev[name].filter((item) => item !== value)
          : value,
    }));
  };

  const handleSubmit = (e) => {
    e.preventDefault();
    console.log("form", form);
  };

  return (
    <form onSubmit={handleSubmit}>
      <div>
        <label htmlFor="name">Name</label>
        <input
          id="name"
          type="text"
          name="name"
          value={form.name}
          onChange={handleChange}
          required
        />
      </div>

      <div>
        <label htmlFor="email">Email</label>
        <input
          id="email"
          type="email"
          name="email"
          value={form.email}
          onChange={handleChange}
          required
        />
      </div>

      <fieldset>
        <legend>Gender</legend>

        {genderOptions.map(({ label, value }) => (
          <label key={value}>
            <input
              type="radio"
              name="gender"
              value={value}
              checked={form.gender === value}
              onChange={handleChange}
            />
            {label}
          </label>
        ))}
      </fieldset>

      <fieldset>
        <legend>Language</legend>

        {languageOptions.map(({ label, value }) => (
          <label key={value}>
            <input
              type="checkbox"
              name="language"
              value={value}
              checked={form.language.includes(value)}
              onChange={handleChange}
            />
            {label}
          </label>
        ))}
      </fieldset>

      <div>
        <label htmlFor="city">Select city</label>
        <select
          id="city"
          name="city"
          value={form.city}
          onChange={handleChange}
        >
          {cityOptions.map(({ label, value }) => (
            <option key={value} value={value}>
              {label}
            </option>
          ))}
        </select>
      </div>

      <button type="submit">Submit</button>
    </form>
  );
}

export default App;
💡 Interview answer: one object in state (form) holds every field. The change handler branches only on type === "checkbox" because that's the one input type where a field can hold multiple values at once; everything else — text, email, radio, select — just overwrites form[name] with the new value.
📋 The 7 Rules
Rule 1 — Use fieldset, legend & label Correctly
fieldset groups related inputs (all gender radios together); legend names the whole group ("Gender"); label names one individual input ("Male", "Female").
ElementPurpose
<fieldset>Groups related inputs, such as all gender radio buttons.
<legend>Names the entire group, such as "Gender."
<label>Names an individual input, such as "Male" or "Female."
Rule 2 — Match label's htmlFor with the Input's id
This is what lets a screen reader announce the label when the input receives focus, and lets clicking the label text focus the input.
label-id-match.jsx
<label htmlFor="name">Name</label>
<input
  id="name"
  type="text"
  name="name"
  value={form.name}
  onChange={handleChange}
  required
/>
📝 Note: htmlFor is JSX's name for the HTML for attribute, since for is a reserved word in JavaScript.
Rule 3 — checked Controls Selection, value Identifies the Option
For radio and checkbox inputs, React reads checked to decide what's selected on screen. value never changes the visual state by itself — it only tells the handler which option this input represents.
checked-vs-value.jsx
// Radio
value={value}
checked={form.gender === value}

// Checkbox
value={value}
checked={form.language.includes(value)}
⚠️ Gotcha: an input with checked but no onChange becomes read-only and React logs a warning — always pair checked with a handler that updates the backing state.
Rule 4 — Render One Input per Option with .map()
Driving radios/checkboxes from an options array — rather than hand-writing each <input> — means three options automatically produce three inputs, and adding a fourth option needs no JSX changes.
Rule 5 — Input Inside Its Own Label Can Skip htmlFor/id
When the <input> is nested directly inside its <label> (as in the gender and language fieldsets above), the association is implicit — htmlFor and id become optional, though still valid to add. Related controls can be grouped together inside one <fieldset>.
Rule 6 — onChange Goes on select, Never on option
A dropdown is one controlled input — the <select> element itself. Its value comes from form.city, and the individual <option> elements never carry their own change handler.
select-onchange.jsx
<select name="city" value={form.city} onChange={handleChange}>
  <option value="mumbai">Mumbai</option>
</select>
Rule 7 — Array State for Checkboxes: Spread to Add, filter() to Remove
Because a checkbox group can have multiple selected values at once, its state is an array. Checking a box spreads the new value in; unchecking filters that value out — both return a brand-new array, keeping the update immutable.
checkbox-array.jsx
checked
  ? [...prev[name], value]
  : prev[name].filter((item) => item !== value)
✅ Why it matters: mutating the array in place (e.g. prev[name].push(value)) keeps the same array reference, so React won't detect the state actually changed.
