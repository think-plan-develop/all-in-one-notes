🧱 2. Custom Error Class
utils/AppError.js
Purpose: creates reusable errors with a custom message and HTTP status code.
utils/AppError.js
class AppError extends Error {
  constructor(message, statusCode = 500) {
    super(message);
    this.statusCode = statusCode;
  }
}

export default AppError;

📍 Where to use it

Inside controllers, services, and middleware whenever you need to throw an error.

usage-examples.js
// Controller
if (!user) {
  throw new AppError("User not found", 404);
}

// Authentication middleware
if (!token) {
  throw new AppError("Unauthorized", 401);
}

// Authorization middleware
if (user.role !== "ADMIN") {
  throw new AppError("Access denied", 403);
}
📝 Note: super(message) calls the parent Error constructor, while statusCode adds an HTTP status to the error.
🔁 3. Async Error Handler
utils/asyncHandler.js
Purpose: automatically forwards rejected promises from async controllers to the global error middleware.
utils/asyncHandler.js
const asyncHandler = (fn) => (req, res, next) =>
  Promise.resolve(fn(req, res, next)).catch(next);

export default asyncHandler;

📍 Where to use it

Wrap asynchronous route controllers.

routes/userRoutes.js
router.get("/users/:id", asyncHandler(getUser));
📝 Note: Express 5 automatically forwards rejected promises from async route handlers. Express 4 generally needs this wrapper.
🧯 4. Global Error Middleware
middleware/errorHandler.js
Purpose: handles API errors centrally and returns consistent JSON responses.
middleware/errorHandler.js
const errorHandler = (err, req, res, next) => {
  if (res.headersSent) return next(err);

  const statusCode = err.statusCode || 500;

  res.status(statusCode).json({
    success: false,
    message: statusCode >= 500
      ? "Internal server error"
      : err.message,
  });
};

export default errorHandler;

📍 Where to use it

Register after all API routes in app.js.

app.js
app.use("/api/users", userRoutes);

// Handle unknown routes
app.use((req, res, next) => {
  next(new AppError("Route not found", 404));
});

// Must be last
app.use(errorHandler);
🧩 5. Complete API Example — Using All Three
controllers/userController.js
controllers/userController.js
import AppError from "../utils/AppError.js";
import asyncHandler from "../utils/asyncHandler.js";
import User from "../models/User.js";

export const getUser = asyncHandler(async (req, res) => {
  const user = await User.findById(req.params.id);

  // Custom error
  if (!user) {
    throw new AppError("User not found", 404);
  }

  res.status(200).json({
    success: true,
    data: user,
  });
});
routes/userRoutes.js
routes/userRoutes.js
import { Router } from "express";
import { getUser } from "../controllers/userController.js";

const router = Router();

router.get("/:id", getUser);

export default router;
app.js
app.js
import express from "express";
import AppError from "./utils/AppError.js";
import errorHandler from "./middleware/errorHandler.js";
import userRoutes from "./routes/userRoutes.js";

const app = express();

app.use(express.json());
app.use("/api/users", userRoutes);

app.use((req, res, next) => {
  next(new AppError("Route not found", 404));
});

✕ Programming Error

An unexpected bug — e.g. calling .name on undefined. Not something you anticipated or can give the user a clean message for.

✓ Operational Error

An expected failure you planned for — e.g. "user not found." Safe to describe to the client via AppError.

✅ 9. Production Best Practices
  • Validate req.body, req.params, and req.query with Zod.
  • Use AppError for expected application errors.
  • Use global error middleware instead of repeating try...catch.
  • Handle MongoDB validation, cast and duplicate-key errors.
  • Use Pino or Winston for structured error logging.
  • Never expose stack traces or sensitive details in production responses.
  • Gracefully shut down and restart after fatal uncaught exceptions.
🎤 Interview summary: Node.js API error handling commonly uses three components: AppError for custom errors, asyncHandler for async error forwarding, and global error middleware for consistent HTTP responses. In Express 5, async route error forwarding is built in.
