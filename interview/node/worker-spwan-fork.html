Worker threads Run JavaScript on another thread within the same process. Use for CPU-heavy JavaScript, such as calculating sales totals from lakhs of eCommerce orders. 
import { Worker } from "node:worker_threads";
new Worker(new URL("./worker.mjs", import.meta.url));
console.log("Running on a worker thread");
spawn() Start an external program in a separate process. Use to run tools such as FFmpeg for LMS video compression or Python scripts. 
import { spawn } from "node:child_process";
spawn("python", ["-c", "print('Hello')"], { stdio: "inherit" });
fork() Start another Node.js process, with built-in messaging support. Use to run a Node.js task separately, such as a property document processor outside the API process. 
import { fork } from "node:child_process";
fork("./child.mjs");
console.log("Running in a child process");
What Is Cluster?

The Cluster module allows multiple Node.js processes to run simultaneously and share the same server port, utilizing multiple CPU cores.

What Is a Child Process?

A Child Process allows a Node.js application to create a new operating system (OS) process to execute another program or command independently of the main Node.js process.

That program could be:

Another Node.js applicationA Python scriptA Java programA Shell/Bash scriptA Git commandFFmpegDocker CLIAWS CLI
spawn()

Imagine your Node.js application needs to run Python scripts. Instead of executing these itself, Node.js asks the operating system:

“Please start this program in a separate process.” That is exactly what spawn() does.

sum.py

for i in range(20): print(i)
import { spawn } from "child_process";

// Start a Python process
const python = spawn("python", ["sum.py"]);

// Receive output from Python
python.stdout.on("data", (data) => {
  console.log(data.toString());
});
fork()

fork() is a function in Node.js’s child_process module that runs another JavaScript file in a separate Node.js process.

  • It also creates a communication channel so parent and child can exchange messages using .send().

Compare process.pid, which is the ID of the running process.

import { fork } from "node:child_process";

console.log("Parent process:", process.pid);

fork("./child.mjs");
console.log("Child process:", process.pid);
console.log("My parent:", process.ppid);

Run node parent.mjs:

Parent process: 12000 Child process: 12001 My parent: 12000
The different process IDs prove they are separate processes. Actual numbers will vary.
BullMQ Worker vs Worker Thread
Important: A BullMQ Worker is not a Node.js worker thread.
  • BullMQ Worker: A job consumer that runs your processing function.
  • Worker thread: A separate thread that executes JavaScript.

BullMQ answers: “Which job runs next, and should it retry?”

Worker threads / spawn() / fork() answer: “Where and how does the work execute?”

For example, in an LMS video-upload flow:

1
The user uploads a video
2
Your API adds a “compress video” job to BullMQ, stored in Redis
3
A BullMQ Worker picks up the job
4
Inside the job handler, spawn() starts FFmpeg to compress the video
5
The handler waits for FFmpeg to finish, then completes the jobIf it fails, BullMQ can retry when configured.
