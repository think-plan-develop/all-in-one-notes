🧩 Key Terms at a Glance
⏭️
nextTick: its own queue — runs after sync code, before promise microtasks (CommonJS top level).
🧬
Promise handlers: .then() schedules a microtask; the executor itself is synchronous.
⏲️
setTimeout(0): a timers-phase callback — never runs before sync code or microtasks.
⚡
setImmediate: check phase, after poll — beats setTimeout(0) inside I/O callbacks.
🪆
nextTick in a promise: waits for the current microtask drain to finish.
🚧
Starvation: endless nextTicks or microtasks can block I/O and timers.

API / conceptDefinition and queueExecution / key difference
Synchronous codeRuns immediately on the call stack: ordinary statements, loops, and the new Promise() executorRuns first, in code order
process.nextTick() ⭐Schedules a callback in Node’s separate next-tick queueAfter current synchronous code; before promise microtasks in CommonJS top-level examples
Promise handlers ⭐.then(), .catch(), .finally() schedule microtasks when their promise settlesHandlers execute asynchronously; the Promise executor is synchronous
queueMicrotask()Adds a callback to the microtask queue, shared with promise handlersMicrotasks run in enqueue order; newly added ones join the queue
setTimeout(fn, delay) ⭐Schedules a one-time macrotask/event-loop callback in the timers phaseRuns after the delay threshold when the thread is available; cancel with clearTimeout()
setInterval(fn, delay)Schedules repeated macrotask/event-loop callbacks in the timers phaseRepeats until clearInterval(); does not await async callbacks
setImmediate() ⭐Schedules a macrotask/event-loop callback in the check phase, after pollCancel with clearImmediate(); no guaranteed order against top-level setTimeout(0)
I/O callbacksCallbacks for file reads and network activity; commonly grouped as macrotasksRun when ready through the relevant event-loop processing
Microtasks are drained at checkpoints before normal event-loop work continues. Macrotask is an informal category here—Node has different phase queues, not one shared macrotask queue.

2️⃣ Example 2 — Inside an I/O Callback ⭐
setImmediate Beats setTimeout(0) Here

  console.log("IO");

  setTimeout(() => console.log("Timeout"), 0);
  setImmediate(() => console.log("Immediate"));
  Promise.resolve().then(() => console.log("Promise"));
  process.nextTick(() => console.log("NextTick"));

3️⃣ Example 3 — Microtask Schedules Another Microtask
The Microtask Queue Finishes Before the Timer

queueMicrotask(() => console.log("C"));

4️⃣ Example 4 — nextTick Inside a Promise ⭐
nextTick Does Not Interrupt the Current Microtask Drain
Promise.resolve().then(() => {
  console.log("A");

  process.nextTick(() => console.log("B"));
});

Promise.resolve().then(() => console.log("C"));

console.log("D");

Output: D → A → C → B

Reason: D is synchronous. The nextTick scheduled inside A does not interrupt the microtask queue currently being drained, so C runs before B.
5️⃣ Example 5 — Blocking Code Delays a Timer
A 500 ms Loop vs a 100 ms Timer
console.log("Start");

setTimeout(() => console.log("Timer"), 100);

Promise.resolve().then(() => console.log("Promise"));

process.nextTick(() => console.log("NextTick"));

const start = Date.now();

while (Date.now() - start < 500) {
  // Blocks the main thread
}

console.log("End");

Reason: The loop prevents callbacks from running. Even though the timer’s delay has elapsed, synchronous code and the queued nextTick/microtask callbacks run first.
6️⃣ Example 6 — Interval with a Promise Callback
clearInterval Does Not Cancel a Queued Promise Handler
let count = 0;

const timer = setInterval(() => {
  count++;
  console.log("Tick", count);

  Promise.resolve().then(() => {
    console.log("Promise", count);
  });

  if (count === 2) {
    clearInterval(timer);
    console.log("Stopped");
  }
}, 100);

console.log("Start");

Output:

Start
Tick 1
Promise 1
Tick 2
Stopped
Promise 2
Reason: Each interval callback finishes before its promise microtask runs. Clearing the interval stops future ticks, but does not cancel the already queued promise handler.
🚧 Interview Traps to Remember
  • 0 delay is not immediate: callbacks cannot interrupt synchronous code.
  • Promise executors run synchronously; promise handlers run as microtasks.
  • Top-level setTimeout(0) versus setImmediate() has no guaranteed order.
  • nextTick is not always first: one scheduled inside a promise handler waits for the current microtask drain.
  • Module type matters: ES-module top-level ordering differs from these CommonJS examples.
  • Endless nextTicks or microtasks can starve I/O and timers.
