1️⃣ Q1 · Why Express.js?
Why do we use Express.js when Node.js already provides the http module?

Why do we use Express.js when Node.js already provides the http module?

Answer:

Node.js provides the built-in http module, so we can create a server without Express. However, as the application grows, using only the HTTP module requires us to manually handle things like:

RoutingRequest body parsingQuery parsingError handlingAuthentication and validation flowStatic files and cookies

For example, with the HTTP module we may need multiple if/else conditions for routing:

if (req.url === "/users") {
  // users
} else if (req.url === "/products") {
  // products
}

Express is a lightweight web framework built on top of Node.js's HTTP module that simplifies these tasks.

app.get("/users", (req, res) => {
  res.send("Users");
});

app.get("/products", (req, res) => {
  res.send("Products");
});

Express provides features such as:

RoutingMiddlewareBody ParsingError HandlingStatic File ServingCookie Parsing

So Express helps us build applications that are cleaner, modular, scalable, and easier to maintain.

Express.js is a lightweight framework built on top of Node.js's HTTP module that simplifies server development by providing routing, middleware, request parsing, response utilities, and centralized error handling.
2️⃣ Q2 · Middleware
What is middleware in Express?

What is middleware in Express? Explain next(), middleware order, body parsing, and error-handling middleware.

Answer:

Middleware is a function that runs during the request-response lifecycle, usually before the final route handler.

A middleware receives:

(req, res, next)

Example:

const logger = (req, res, next) => {
  console.log(req.method, req.url);

  next();
};

app.use(logger);

Middleware can:

Execute common logicModify req or resEnd the requestPass control to the next middleware

next() tells Express to continue processing the request.

const auth = (req, res, next) => {
  // check authentication

  next();
};
If neither next() nor a response such as res.send() is called, the request will stop there.

Why middleware order matters

Express processes middleware in registration order.

✅ Correct 
app.use(express.json());

app.use(authMiddleware);

app.post("/users", (req, res) => {
  console.log(req.body);
});

Here:

Request
→
express.json()
→
authMiddleware
→
Route Handler
express.json() must execute before a route that needs req.body.

Error-handling middleware

Express also supports centralized error handling.

NORMAL MIDDLEWARE(req, res, next)

A normal middleware has:

ERROR MIDDLEWARE(err, req, res, next)

An error middleware has four parameters:

Example:

app.get("/user", (req, res, next) => {
  try {
    throw new Error("Something went wrong");
  } catch (error) {
    next(error);
  }
});

app.use((err, req, res, next) => {
  res.status(500).json({
    message: err.message,
  });
});
throw in route
→
next(error)
→
Error-handling middleware
→
res.status(500).json()

next(error) forwards the error to the error-handling middleware.

Middleware is a function with access to req, res, and next that executes during the request-response cycle. Express executes middleware in order, so parsing, authentication, and validation middleware must be registered before routes that depend on them.
3️⃣ Q3 · Routing, Router, Params & Lifecycle
Routing, Router, route vs query parameters, and the request lifecycle

Explain routing in Express, Router, route parameters vs query parameters, and the complete Express request lifecycle.

Answer:

Express routing maps an HTTP method and URL to a handler.

app.get("/users", (req, res) => {
  res.send("Users");
});

app.post("/users", (req, res) => {
  res.send("User created");
});

For larger applications, Express provides express.Router() so related routes can be separated into modules.

const router = express.Router();

router.get("/", (req, res) => {
  res.send("All Users");
});

router.get("/:id", (req, res) => {
  res.send(`User: ${req.params.id}`);
});

export default router;

Then mount it:

app.use("/users", userRoutes);

So:

router.get("/")
→
GET /users
router.get("/:id")
→
GET /users/101

This makes the application more modular, maintainable, and scalable.

Route parameter vs query parameter

A route parameter identifies a specific resource.

/users/101
app.get("/users/:id", (req, res) => { console.log(req.params.id);});

Access it using:

req.params

A query parameter is generally used for filtering, searching, sorting, or pagination.

/users?page=2&limit=10

Access it using:

4️⃣ Q4 · app.use() vs app.get() vs router.get()
app.use() vs app.get() vs router.get()

What is the difference between app.use(), app.get(), and router.get()?

app.use() — registers middleware or mounts a router
app.use(express.json());app.use("/users", userRouter);
app.get() — handles a GET request directly on the main app
app.get("/users", (req, res) => { res.send("Users");});
router.get() — handles a GET request inside an express.Router() 
const router = express.Router();

router.get("/:id", (req, res) => {
  res.send(req.params.id);
});

Mounted as:

app.use("/users", router);

So router.get("/:id") becomes:

GET /users/:id
5️⃣ Q5 · Add a Request Timeout
Add a Request Timeout

Fetch data from an external API and abort the request if it takes longer than three seconds.

async function fetchWithTimeout(url) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), 3000);

  try {
    const response = await fetch(url, {
      signal: controller.signal,
    });

    return await response.json();
  } finally {
    clearTimeout(timer);
  }
}

async function main() {
  try {
    const data = await fetchWithTimeout(
      "https://jsonplaceholder.typicode.com/users"
    );

    console.log(data);
  } catch (error) {
    console.log("Request failed:", error.message);
  }
}

main();
