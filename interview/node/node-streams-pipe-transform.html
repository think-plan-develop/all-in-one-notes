🌊 What Is a Stream?
Data Piece by Piece, Not All at Once
A stream processes data piece by piece (in chunks) instead of loading the entire data into memory at once.

Streams are useful for:

📁 Large files🎬 Video/audio⬆️⬇️ File uploads/downloads🌐 Network data📜 Large logs

1️⃣ readFile()
Waits for the Complete File
import fs from "fs";

const pathName = new URL("./large-file.txt", import.meta.url);

fs.readFile(pathName, "utf8", (err, data) => {
  if (err) {
    console.log(err);
    return;
  }

  console.log("Complete data length:", data.length);
});

readFile() waits until the complete file has been read and then executes the callback.

Flow
File
→
Complete file loaded
→
Callback runs once
2️⃣ createReadStream()
Creates a Readable Stream

createReadStream() creates a Readable Stream.

It reads the file gradually in chunks.

import fs from "fs";

const pathName = new URL("./large-file.txt", import.meta.url);

const stream = fs.createReadStream(pathName, "utf8");

let chunkCount = 0;

stream.on("data", (chunk) => {
  chunkCount++;

  console.log(
    "Chunk:",
    chunkCount,
    "Size:",
    chunk.length
  );
});

stream.on("end", () => {
  console.log("Total chunks:", chunkCount);
});

stream.on("error", (err) => {
  console.log("Error:", err);
});

Flow

File
→
Chunk 1
→
Chunk 2
→
Chunk 3
→
...
→
end
📡 Readable Stream Events
data, end, error, close
EventPurpose
dataRuns whenever a chunk is available
endRuns when all data has been read
errorRuns if reading fails
closeRuns when the resource is closed

data

stream.on("data", (chunk) => { console.log(chunk);});

The data event may run many times.

end

stream.on("end", () => { console.log("Reading completed");});

Runs after the entire stream has been consumed.

🔢 chunkCount
Counting data Events, Not Lines
let chunkCount = 0;

stream.on("data", (chunk) => {
  chunkCount++;
});

chunkCount tells you:

how many times the data event fired.
It does not mean:
  • number of lines
  • number of words
  • number of characters
🪣 highWaterMark
Approximate Chunk Size

highWaterMark controls the approximate amount of data buffered/read per chunk.

const stream = fs.createReadStream(pathName, {
  encoding: "utf8",
  highWaterMark: 100
});

Here Node tries to process roughly:

100 bytes per chunk

Example:

stream.on("data", (chunk) => { console.log(chunk.length);});

You may see:

100
→
100
→
100
→
100
→
...
📝 Normally, you can let Node use its default value.

3️⃣ createWriteStream()
Creates a Writable Stream

createWriteStream() creates a Writable Stream.

It allows data to be written gradually in chunks.

import { createWriteStream } from "fs";

const writeStream = createWriteStream("./output.txt");

writeStream.write("Hello\n");
writeStream.write("Node.js\n");
writeStream.write("Streams\n");

writeStream.end();

The file becomes:

HelloNode.jsStreams

write()

writeStream.write("Hello\n");

Writes one chunk.

end()

writeStream.end();

Means:

No more data will be written.

You can also write the final chunk:

writeStream.end("Last line\n");

finish

writeStream.on("finish", () => { console.log("Writing completed");});

Important difference:

→ method you call

→ event Node emits

drain

If data is written faster than the destination can handle, the internal buffer can become full.

const canContinue = writeStream.write(data);

If it returns:

false

wait for:

writeStream.once("drain", () => { console.log("Buffer available again");});
4️⃣ pipe()
Connect Readable to Writable

pipe() connects a Readable Stream to a Writable Stream.

The normal direction is:

✅ Normal direction
Readable
→
Writable
❌ Not this
Writable
→
Readable

because the source of pipe() must be able to produce readable data.

Example 1 — Readable → Writable

import fs from "fs";

const pathName = new URL("./large-file.txt", import.meta.url);
const pathWrite = new URL("./write-test-file.txt", import.meta.url);

const readStream = fs.createReadStream(pathName, {
  encoding: "utf8"
});

const writeStream = fs.createWriteStream(pathWrite);

readStream.pipe(writeStream);

writeStream.on("finish", () => {
  console.log("File copied successfully");
});

readStream.on("error", (err) => {
  console.log("Read error:", err);
});

writeStream.on("error", (err) => {
  console.log("Write error:", err);
});

Flow

large-file.txt
→
Readable Stream
→
pipe()
→
Writable Stream
→
write-test-file.txt

Here:

readStream.pipe(writeStream);

means:

Take every chunk produced by readStream and send it to writeStream.

Example 2 — Readable → Transform → Writable

A Transform stream can receive chunks, modify them, and pass the transformed chunks forward.

const fs = require("fs");
const zlib = require("zlib");

const readStream = fs.createReadStream("input.txt");
const gzip = zlib.createGzip(); // Transform stream
const writeStream = fs.createWriteStream("input.txt.gz");

readStream
  .pipe(gzip)
  .pipe(writeStream);

Flow

input.txt
→
Readable Stream
→
pipe()
→
gzip Transform Stream
→
pipe()
→
Writable Stream
→
input.txt.gz

Here:

readStream.pipe(gzip)

sends file chunks to the gzip transform stream.

Then:

gzip.pipe(writeStream)

sends the compressed output to the writable stream.

So:

Readable
→
Transform
→
Writable

is a very common stream pipeline.

A Transform stream is special because it can both:

receive data
→
+ modify data
→
+ produce output
🔧 Manual Read + Write vs pipe()
Why pipe() Is Better

Without pipe():

readStream.on("data", (chunk) => {
  writeStream.write(chunk);
});

readStream.on("end", () => {
  writeStream.end();
});

With pipe():

readStream.pipe(writeStream);

pipe() automatically:

  • receives chunks from the readable stream
  • writes them to the next stream
  • ends the destination when the source finishes
  • helps manage backpressure
So pipe() is generally better than manually calling write() for every chunk.

🚫 Can We Pipe Writable → Readable?
Wait for finish, Then Create a New Readable
Normally, no.

This is invalid conceptually:

❌ Invalid
Writable Stream
→
pipe()
→
Readable Stream

because a normal Writable stream does not produce readable output.

If you want to:

Write file
→
finish
→
Read same file

wait for finish and create a new readable stream.

const writeStream = fs.createWriteStream("./test.txt");

writeStream.write("Hello Node.js");
writeStream.end();

writeStream.on("finish", () => {
  const readStream = fs.createReadStream("./test.txt", {
    encoding: "utf8"
  });

  readStream.on("data", (chunk) => {
    console.log(chunk);
  });
});
