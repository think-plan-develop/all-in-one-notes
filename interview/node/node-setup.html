🏷️ What Are @types/... Packages?
Types Describe — They Do Not Implement

You mean @types/node and other @types/... packages.

@types packages describe JavaScript APIs to TypeScript. They help TypeScript check your code and provide autocomplete; they don’t implement the functionality.
PackageProvides
expressActual Express functionality
@types/expressType definitions for Express
corsActual CORS middleware
@types/corsType definitions for CORS
@types/nodeType definitions for the Node.js runtime APIs

Why @types/node when you haven’t installed a node package?

You installed Node.js itself on your computer. It provides APIs such as:

processBufferfspathhttp

These are built into Node.js, so you don’t install them using npm.

import fs from "node:fs";

const content = fs.readFileSync("notes.txt", "utf8");

console.log(process.version);

Here:

  • Node.js provides fs and process and executes the code.
  • @types/node tells TypeScript what readFileSync() accepts, what it returns, and that process.version is a string.
NODE.JS@types/node

describes Node.js

EXPRESS@types/express

describes the Express package

Remember: @types/node describes Node.js, while @types/express describes the Express package.

About node --watch

node --watch src/index.ts

can watch files in modern Node.js, but for a normal TypeScript project:

tsx watch src/index.ts
is usually simpler because it handles TypeScript execution cleanly during development.

9️⃣ Basic Express Setup
src/app.ts

src/app.ts

import express from "express";
import cors from "cors";

const app = express();

app.use(cors());

app.use(express.json());

app.get("/", (req, res) => {
  res.json({
    message: "API working"
  });
});

export default app;

Important middleware

app.use(cors());

enables CORS.

app.use(express.json());

allows Express to parse JSON request bodies.

1️⃣1️⃣ MongoDB Connection
src/config/db.ts

src/config/db.ts

import mongoose from "mongoose";

export const connectDB = async () => {
  try {
    await mongoose.connect(process.env.MONGO_URI!);

    console.log("MongoDB connected");
  } catch (err) {
    console.error("MongoDB connection failed:", err);

    process.exit(1);
  }
};

Use it in:

src/index.ts

import dotenv from "dotenv";
import app from "./app.js";
import { connectDB } from "./config/db.js";

dotenv.config();

const PORT = process.env.PORT || 4000;

await connectDB();

app.listen(PORT, () => {
  console.log(`Server running on port ${PORT}`);
});
