1️⃣ Callback Functions
Functions Passed to Functions
A callback is a function passed as an argument to another function, which invokes it at the right time.
function greet(name, callback) {
  console.log("Hello", name);
  callback();
}

greet("Shivam", () => console.log("Callback executed"));
Callback Hell: Deeply nested, dependent asynchronous callbacks that make code difficult to read, debug, and maintain. This is commonly called the “Pyramid of Doom.”
createOrder(cart, function (orderId) {
  proceedToPayment(orderId, function (payment) {
    showOrderSummary(payment, function () {
      updateWallet();
    });
  });
});
Inversion of Control: When you pass your callback to an external function, that function decides when, whether, and how many times your callback runs.

Error-first Callback: A pattern where the first argument contains the error and the second contains the successful result.

getUser((err, user) => {
  if (err) return console.error(err);
  console.log(user);
});

📝 Once a Promise becomes fulfilled or rejected, its state cannot change again.
const promise = new Promise((resolve, reject) => {
  setTimeout(() => resolve("Success"), 1000);
});

promise
  .then(value => console.log(value))
  .catch(error => console.error(error))
  .finally(() => console.log("Hide loader"));
  • .then() handles success and returns a new Promise.
  • .catch() handles rejection and can return a fallback value so the chain continues.
  • .finally() runs after settlement, whether fulfilled or rejected, and is used for cleanup.
  • The Promise executor runs synchronously; Promise handlers run through the microtask queue.
3️⃣ Promise Chaining
Flat Chains, One catch()
Promise chaining connects asynchronous steps using successive .then() calls, keeping the code flat and allowing one .catch() to handle errors from the connected steps.
getUser(1)
  .then(user => getPosts(user.id))
  .then(posts => getComments(posts[0].id))
  .then(comments => console.log(comments))
  .catch(error => console.error(error));

Any error in the chain
Any step rejects

Always return the next Promise to keep the chain connected. Without returning it, the next .then() does not wait for that operation and receives undefined if nothing is returned.
Promise Hell: Nesting .then() calls inside each other instead of chaining them, recreating the readability problems of callback hell.

Error Recovery: A .catch() can return a fallback value and allow the following .then() to execute.

fetchData() .catch(() => []) .then(data => console.log(data));
4️⃣ Promise Types
all, allSettled, race, any
TypeDefinitionWhen to use
Promise.all()Waits for every Promise to fulfill and returns an array of results in input order. Rejects immediately if one rejects.When you need all results
Promise.allSettled()Waits for every Promise to settle and returns status objects: { status, value } or { status, reason }.When partial failure is acceptable
Promise.race()Settles as soon as the first Promise settles, whether fulfilled or rejected.First outcome or timeout
Promise.any()Resolves on the first fulfillment; rejects with AggregateError if every Promise rejects.When you need one successful result

5️⃣ Async / Await
Promises That Read Like Sync Code
async/await is syntax built on top of Promises that makes asynchronous code look synchronous and easier to read.

async: A keyword that makes a function always return a Promise, even when it returns a plain value.

async function getValue() {
  return "Hello";
}

getValue().then(console.log); // Hello

await: Suspends the async function until the Promise settles. It provides the fulfilled value or throws the rejection reason.

What await does
await promise
→
Function suspended · main thread free
→
Promise settles
→
Resumes via microtask queue
  • It does not block the main thread.
  • Execution after await resumes through the microtask queue.
  • Even an already fulfilled Promise resumes asynchronously after await.
  • It works inside async functions and at the top level of ES modules.
  • Use try/catch around awaited operations to handle rejections.
async function checkout(cart) {
  try {
    const order = await createOrder(cart);
    const payment = await proceedToPayment(order.id);
    console.log(payment);
  } catch (error) {
    console.error(error);
  }
}
6️⃣ Sequential vs Concurrent Execution
Await One by One vs Together
// Sequential: approximately 4 seconds
const a = await fetchA(); // 2 seconds
const b = await fetchB(); // 2 seconds

// Concurrent: approximately 2 seconds
const [a, b] = await Promise.all([fetchA(), fetchB()]);
Sequential · ≈ 4 seconds

→

Concurrent · ≈ 2 seconds

Use sequential execution when operations depend on previous results. Start independent operations together and await them with Promise.all().
