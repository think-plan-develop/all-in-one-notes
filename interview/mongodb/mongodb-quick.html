🗄️ 1. Database & Collection Basics
Create, Drop & Find Missing Keys
MongoDB creates databases and collections lazily — use and first insert are enough — but you can also create a collection explicitly. Dropping removes everything inside, so double-check the target first.
basics.js
// create / switch to a db (created on first write)
use shop

// create a collection explicitly
db.createCollection("products")

// drop a collection
db.products.drop()

// drop the current database
db.dropDatabase()

// find documents where a key is missing
db.users.find({ email: { $exists: false } })
📝 Note: $exists: false matches documents where the key is absent entirely. A key set to null still "exists".
✍️ 2. Modern Write Methods
insert / update / delete — Use the One/Many Versions
The legacy insert(), update() and remove() are deprecated (and removed in mongosh). Use insertOne / insertMany, updateOne / updateMany and deleteOne / deleteMany.
DeprecatedUse Instead
insert()insertOne() / insertMany()
update()updateOne() / updateMany()
remove() / deletedeleteOne() / deleteMany()
update-set.js
// ❌ Error: "Update document requires atomic operators"
db.users.updateOne({ name: "Shivam" }, { age: 27 })

// ✅ Wrap changes in an update operator such as $set
db.users.updateOne({ name: "Shivam" }, { $set: { age: 27 } })
⚠️ Gotcha: the error text Update document requires atomic operators always means you passed a plain object instead of an operator like $set.

🪶 4. lean()
lean() — Plain Objects Instead of Mongoose Documents
lean() is a Mongoose method, not a MongoDB shell method. It returns a plain JavaScript object, which uses less memory and is usually faster because Mongoose doesn't build a full document instance.

✅ Use it for

  • Fetching data for an API response
  • Showing lists
  • Dashboards and reports
  • Read-only operations
lean.js
const user  = await User.findOne({ email }).lean();
const users = await User.find({ isActive: true }).lean();

🚫 Avoid it when you'll modify and save

no-lean.js
const user = await User.findById(id);   // full Mongoose document

user.name = "Shivam";
await user.save();                      // .save() only exists on real documents
💡 Rule: lean for reading, full documents for editing. A lean result has no .save(), virtuals or getters.
🔍 5. Query Operators
Comparison & Logical Operators
Comparison operators ($gte, $in) filter a single field; logical operators ($not, $and, $or) combine or negate conditions.
operators.js
// $gte — greater than or equal
db.users.find({ age: { $gte: 18 } })

// $in — matches any value in the list
db.products.find({ model: { $in: ['A', 'O', 'C'] } })

// $not — negates an operator expression
db.users.find({ age: { $not: { $gte: 18 } } })

// $and — all conditions must match
db.products.find({
  $and: [
    { _id: ObjectId("6aba948ea1ea3917c3caddae") },
    { quantity: 10 }
  ]
})

// $or — at least one condition must match
db.products.find({
  $or: [
    { _id: ObjectId("6aba9c80a1ea3917c3caddb0") },
    { _id: ObjectId("6aba948ea1ea3917c3caddae") }
  ]
})
💡 Tip: $not also matches documents where the field is missing. { age: { $lt: 18 } } is often the tighter query.
📚 6. Array Operators
$in vs $all vs $size vs $elemMatch
$in needs any one value to match; $all needs every listed value present. $elemMatch makes sure multiple conditions hit the same array element.
OperatorPurpose
$inAny value from a list can match
$allArray must contain all specified values
$sizeArray must have exact length
$elemMatchOne array element must satisfy multiple conditions

🔎 How $in matches

in-example.js
// document
{ name: 'onePlus', model: ['A', 'O', 'L'] }

// query values:    A, O, C
// document values: A, O, L  → at least one matches, so it IS returned
db.products.find({ model: { $in: ['A', 'O', 'C'] } })
all-elemMatch.js
// $all — must contain both A and O
db.products.find({ model: { $all: ['A', 'O'] } })

// $elemMatch with a single condition
db.products.find({ model: { $elemMatch: { $eq: "A" } } })

// $elemMatch — both conditions on the SAME element
db.users.find({
  experience: {
    $elemMatch: {
      company: "B",
      years: { $gte: 3 }
    }
  }
})
📝 Why $elemMatch: without it, company: "B" could match one element and years >= 3 a different one. $elemMatch forces both onto the same element.
📦 7. bulkWrite()
Many Write Operations in One Call
bulkWrite() takes an array of operations and runs them in one MongoDB call. Each array item is one write operation such as insertOne, updateOne or deleteOne.
bulkWrite.js
db.users.bulkWrite([
  {
    insertOne: {
      document: { name: "Rakesh", age: 26 }
    }
  },
  {
    updateOne: {
      filter: { name: "Shivam" },
      update: { $set: { age: 27 } }
    }
  },
  {
    deleteOne: {
      filter: { name: "Anil" }
    }
  }
])

This performs three writes: insert a new document, update one matching document, and delete one matching document.

🛠 Fixing a common mistake

bulkWrite-fixed.js
db.products.bulkWrite([
  { insertOne: { document: { name: "apple" } } },
  {
    updateOne: {
      filter: { _id: "03033" },
      update: { $set: { name: "shivam" } }
    }
  }
])
⚠️ Mistakes to avoid: insertOne needs document; updateOne needs both filter and update; and you can't place { _id: ... } and { $set: ... } directly inside updateOne without those keys.
