📋 1. Operator Syntax Table
Which Pattern for Which Job
Replace $op with the operator you need. These patterns are for query filters (e.g. inside find()).
UseSyntaxOperators
Compare a value{ field: { $op: value } }$eq, $ne, $gt, $gte, $lt, $lte
Check a list of values{ field: { $op: [value1, value2] } }$in, $nin, $all
Check existence, type, pattern or array length{ field: { $op: value } }$exists, $type, $regex, $size
Negate a field condition{ field: { $not: { $op: value } } }$not
Match one element in an array of values{ field: { $elemMatch: { $gte: min, $lte: max } } }$elemMatch
Match one object in an array of objects{ field: { $elemMatch: { child1: value, child2: { $op: value } } } }$elemMatch
Combine conditions{ $op: [ { field1: value }, { field2: { $gt: value } } ] }$and, $or, $nor
💻 2. Examples
Field First vs Operator First

1. Comparison → Field first

comparison.js
db.users.find({
  age: { $gte: 18 }
})

2. $in → Field first

in.js
db.users.find({
  city: { $in: ["Delhi", "Hyderabad"] }
})

3. $exists → Field first

exists.js
db.users.find({
  name: { $exists: false }
})

4. $and → Operator first

and.js
db.users.find({
  $and: [
    { age: { $gte: 18 } },
    { city: "Hyderabad" }
  ]
})

5. $or → Operator first

or.js
db.users.find({
  $or: [
    { city: "Delhi" },
    { city: "Hyderabad" }
  ]
})
💡 3. Easy Rule
Where Does the Operator Go?
Operator works on one field → field name first.
Operator combines multiple conditions → operator first.
rule.js
{ quantity: { $gte: 5 } }        // ✅ Field first
{ model: { $in: ["A", "B"] } }  // ✅ Field first

{ $and: [{...}, {...}] }         // ✅ Operator first
{ $or:  [{...}, {...}] }         // ✅ Operator first
✅ Remember: $and, $or and $nor take an array of conditions and sit at the top level. Everything else lives inside a field.
