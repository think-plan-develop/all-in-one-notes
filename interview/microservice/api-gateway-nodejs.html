1Architecture and Request Flow

An API Gateway is a single entry point that receives client requests and forwards them to the appropriate microservice. A reverse proxy performs the actual HTTP request forwarding.

Important terms

🚪

API Gateway

Single entry point for multiple microservices

🔀

Reverse Proxy

4Create Two Microservices

4.1 Auth Service

auth-service/server.js
import express from "express";

const app = express();
app.use(express.json());

app.get("/auth", (req, res) => {
  res.json({
    service: "Auth Service",
    message: "Auth service working"
  });
});

app.post("/auth/login", (req, res) => {
  res.json({
    message: "Login request received",
    data: req.body
  });
});

app.listen(3001, () => {
  console.log("Auth Service running on port 3001");
});

4.2 Property Service

property-service/server.js
import express from "express";

const app = express();

app.get("/properties", (req, res) => {
  res.json({
    service: "Property Service",
    properties: ["Apartment", "Villa"]
  });
});

app.get("/properties/:id", (req, res) => {
  res.json({
    propertyId: req.params.id,
    title: "Apartment"
  });
});

app.listen(3002, () => {
  console.log("Property Service running on port 3002");
});
RememberBoth services are separate Node.js applications running independently.
5Create API Gateway ⭐ Important

Instead of repeating proxy middleware for every service, use a configuration-driven approach.

5.1 Environment Configuration

api-gateway/.env
PORT=8080

AUTH_SERVICE_URL=http://localhost:3001
PROPERTY_SERVICE_URL=http://localhost:3002
Why use environment variables?Because backend addresses may differ between development, testing, and production environments. Changing the .env file avoids changing source code.

5.2 Route Configuration

config/services.js
export const services = [
  {
    path: "/api/auth",
    target: process.env.AUTH_SERVICE_URL,
  },
  {
    path: "/api/properties",
    target: process.env.PROPERTY_SERVICE_URL,
  },
];

Each configuration object defines which public API path belongs to which microservice. Adding a new microservice requires a new route entry rather than duplicating middleware logic.

5.3 Reusable Proxy

middleware/proxy.js
import { createProxyMiddleware } from "http-proxy-middleware";

export const createServiceProxy = ({ path, target }) => {
  if (!target) {
    throw new Error(`Missing target for ${path}`);
  }

  new URL(target);

  return createProxyMiddleware({
    pathFilter: (url) =>
      url === path || url.startsWith(`${path}/`),

    target,
    changeOrigin: true,

    pathRewrite: {
      "^/api(?=/|$)": ""
    },

    proxyTimeout: 5000,
    timeout: 5000,

    on: {
      error: (error, req, res) => {
        console.error("Proxy error:", error.message);

        if (res.headersSent) {
          return res.destroy();
        }

        res.writeHead(502, {
          "Content-Type": "application/json"
        });

        res.end(JSON.stringify({
          success: false,
          message: "Backend service unavailable"
        }));
      }
    }
  });
};

Understand the proxy configuration

PropertyExplanation
pathFilterChecks whether an incoming request belongs to the configured service
targetSpecifies where to forward the request
changeOrigin: trueChanges the upstream Host header to match the target
pathRewriteRemoves /api before forwarding
proxyTimeoutLimits waiting for activity from the upstream server
timeoutConfigures the proxy request timeout
on.errorHandles proxy errors such as connection failures

The gateway is using http-proxy-middleware to forward requests and stream responses. It does not need to create a separate fetch() call manually for every incoming request.

5.4 Main Gateway

api-gateway/server.js
import "dotenv/config";
import express from "express";

import { services } from "./config/services.js";
import { createServiceProxy } from "./middleware/proxy.js";

const app = express();

// Gateway health check
app.get("/health", (req, res) => {
  res.json({
    status: "OK",
    service: "API Gateway"
  });
});

// Register microservice proxies
for (const service of services) {
  app.use(createServiceProxy(service));
}

// Handle unknown routes
app.use((req, res) => {
  res.status(404).json({
    success: false,
    message: "Route not found"
  });
});

const PORT = Number(process.env.PORT) || 8080;

app.listen(PORT, () => {
  console.log(`API Gateway running on port ${PORT}`);
});
ImportantWe intentionally do not add express.json() before the gateway proxy because it can consume the incoming request body before proxy forwarding.

8Understand One Complete Request

Suppose you request:

request
GET http://localhost:8080/api/properties/P101
  1. Frontend / PostmanGET /api/properties/P101
  2. API GatewayMatches /api/properties
  3. Reverse ProxyRemoves /api and forwards to port 3002
  4. Property ServiceHandles GET /properties/P101
  5. API GatewayForwards the response to the client
RememberThe client never needs to know that Property Service runs on port 3002.
9What Happens If a Service Fails?

Suppose Property Service is stopped, but API Gateway is still running. The client requests:

request
GET http://localhost:8080/api/properties

The gateway attempts to forward the request to port 3002, but the service is unavailable.

The proxy's error handler can return:

response — 502 Bad Gateway
{
  "success": false,
  "message": "Backend service unavailable"
}

With the sample configuration, the status code is 502 Bad Gateway. Other timeout conditions may require more detailed handling in production.

Health check caveatThe gateway's /health endpoint only indicates that the gateway process is responding; it does not prove that every upstream service is healthy.
10Proxy vs API Gateway vs Microservice
ComponentResponsibility
API GatewayMain entry point that manages client-facing API routes and shared policies
Reverse ProxyForwards HTTP requests and responses between clients and backend services
MicroserviceExecutes business logic and manages its own data
Service ConfigurationStores routes and backend destination URLs
Load BalancerDistributes requests across multiple service instances
NoteAn API Gateway can use reverse-proxy functionality internally, as we implemented using http-proxy-middleware.
11What Would You Add in Production?

Our setup demonstrates routing, but a production API Gateway normally needs further controls.

12Interview Questions
1What is an API Gateway?▼
A single entry point that receives client requests and forwards them to the appropriate microservice. It manages client-facing API routes and shared policies.
2What is a reverse proxy?▼
A component that forwards incoming HTTP requests to backend services and passes the responses back. The gateway uses reverse-proxy functionality internally.
3Why use http-proxy-middleware?▼
It forwards requests and streams responses for you, so you do not write a separate fetch() call for every incoming request. It also provides pathFilter, target, pathRewrite, timeouts, and error handling.
4What is path rewriting?▼
Modifying the request path before forwarding. Here pathRewrite removes /api, so /api/properties reaches the Property Service as /properties.
5Why use dynamic route configuration?▼
Each service is just a config entry (path and target). Adding a microservice means adding a route entry rather than duplicating middleware logic, and target URLs come from environment variables.
6What happens if a backend service is unavailable?▼
The proxy error handler returns a JSON "Backend service unavailable" response with status 502 Bad Gateway. Other timeout conditions may need more detailed handling in production.
7Does the API Gateway need a database?▼
No — a database is not required for this practice. The gateway only routes requests; each microservice handles its own business logic and database access.
8Can an API Gateway handle authentication?▼
Yes. JWT validation is a typical production gateway feature. Business logic, domain validation, and resource-level authorization still belong in the owning microservices.
9Should microservices communicate through the public API Gateway?▼
Your notes do not answer this directly. They describe the gateway as the entry point for client traffic (Frontend → Gateway → services), so service-to-service calls are a separate design decision.
10Can API Gateway become a single point of failure?▼
Yes, it can. That is why production setups run multiple gateway instances to reduce gateway failure risk. Remember /health only shows the gateway process is responding.

Five things to remember

  1. API Gateway is the single client-facing entry point.
  2. A reverse proxy forwards requests to backend services.
  3. pathFilter selects requests, while target defines the destination.
  4. pathRewrite modifies the URL before forwarding.
  5. Microservices independently handle business logic and database access.

Interview-ready answer

I can implement an API Gateway in Node.js using Express and http-proxy-middleware. I maintain service routes in configuration, dynamically register reusable reverse-proxy middleware, and configure path rewriting, environment-based service URLs, timeouts, and proxy error handling.

The frontend communicates with the gateway, which forwards requests to the appropriate backend service. Each service independently manages its business logic and database.

For production, I would extend this architecture with authentication, rate limiting, service discovery, observability, and high availability.
