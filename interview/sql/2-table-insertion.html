📌 Important: In PostgreSQL, string values use single quotes '...'. Double quotes "..." are used for identifiers such as table or column names.
Part 1 — Basic INSERT Statements
Departments table
departments.sql
CREATE TABLE departments (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name VARCHAR(100) NOT NULL UNIQUE,
    location VARCHAR(100) DEFAULT 'Noida',
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);
Identity and defaults: You normally omit id, location, and created_at; PostgreSQL generates or fills them.
1. Single-row insertion
single-row.sql
INSERT INTO departments (name)
VALUES ('Shivam');

You can provide more columns when needed:

single-row-with-location.sql
INSERT INTO departments (name, location)
VALUES ('Alok', 'Hyderabad');
2. Multiple-row insertion
multiple-rows.sql
INSERT INTO departments (name)
VALUES
    ('Shivam'),
    ('Alok'),
    ('Rakesh'),
    ('Anil');

Multiple rows with more than one column:

multiple-rows-with-location.sql
INSERT INTO departments (name, location)
VALUES
    ('Shivam', 'Noida'),
    ('Alok', 'Hyderabad'),
    ('Rakesh', 'Delhi'),
    ('Anil', 'Pune');
Part 2 — INSERT Rules
1. Strings use single quotes

Correct string insertion:

strings.sql
INSERT INTO departments (name, location)
VALUES ('Sumit', 'Hyderabad');
'text' → string value "text" → identifier such as a column/table name
Wrong: ("Sumit", "Hyderabad") for string values.
2. Date and NULL values

Use the date format YYYY-MM-DD:

date.sql
INSERT INTO employees (name, joining_date)
VALUES ('Sumit', '2026-09-27');

For an empty or unknown value, use the actual NULL keyword:

null.sql
INSERT INTO projects (name, end_date)
VALUES ('Project A', NULL);
NULL → actual null value 'NULL' → text containing the word NULL
3. Column order, value count, and column names

Always prefer specifying the column names:

recommended.sql
INSERT INTO departments (name, location)
VALUES ('Sumit', 'Hyderabad');
name → 'Sumit' location → 'Hyderabad'

The number of columns and values must match.

wrong-count.sql
-- Wrong: two columns but only one value
INSERT INTO departments (name, location)
VALUES ('Sumit');

Avoid INSERT INTO departments VALUES (...) because it depends on the exact table column order and can break after the table changes.

Best practice: INSERT INTO table_name (column1, column2) VALUES (value1, value2);
Part 3 — Practice Tasks
1. Update status and budget in one query
Task: Update a project's status from 'planned' to 'active' and increase its budget by 15% in the same query.
your-task.sql
UPDATE projects
SET status = 'active',
    budget = budget * 1.15
WHERE id = 1;
2. Test ON DELETE CASCADE
Task: Create a temporary department with two projects and no employees. Delete the department, then check whether its projects were automatically deleted by ON DELETE CASCADE.
cascade-practice.sql
-- 1. Create a department
INSERT INTO departments (name, location)
VALUES ('Temporary Department', 'Noida')
RETURNING id;

-- 2. Use that returned id for two projects
INSERT INTO projects (name, project_code, department_id, budget, start_date)
VALUES
    ('Temp Project A', 'TEMP-A', <department_id>, 10000, '2026-09-27'),
    ('Temp Project B', 'TEMP-B', <department_id>, 15000, '2026-09-27');

-- 3. Delete the department
DELETE FROM departments
WHERE id = <department_id>;

-- 4. Check whether projects were deleted
SELECT * FROM projects
WHERE project_code IN ('TEMP-A', 'TEMP-B');
Expected result: zero rows, because ON DELETE CASCADE removes the related projects automatically. No employee rows are created for this department.
