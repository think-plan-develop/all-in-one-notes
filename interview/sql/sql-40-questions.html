🧱 DDL & Keys
Q1What is the difference between DELETE, TRUNCATE, and DROP?
CommandWhat it removesTable remains?
DELETESelected rows using WHERE, or all rowsYes
TRUNCATEAll rows; does not support WHEREYes
DROPThe entire table, including its definitionNo

In PostgreSQL, TRUNCATE can be rolled back inside a transaction. It does not reset identity sequences unless you request RESTART IDENTITY.

Q2What is the difference between a primary key, foreign key, and unique key?
KeyEasy meaning
Primary keyIdentifies each row. Values must be unique and cannot be NULL.
Foreign keyConnects tables and prevents references to nonexistent records.
Unique keyPrevents duplicate values or combinations of values.

Example: employees.id is a primary key, employees.department_id is a foreign key, and employees.email can have a unique constraint.

A table has one primary key, which can contain multiple columns. It can have several unique constraints. NULL handling for unique constraints depends on the database.

🔍 Filtering & Grouping
Q3What is the difference between WHERE and HAVING?

WHERE filters individual rows before grouping. HAVING filters groups after aggregation.

SELECT department_id, COUNT(*) AS employee_count
FROM employees
WHERE salary > 30000
GROUP BY department_id
HAVING COUNT(*) > 5;

This finds departments with more than five employees earning above 30,000.

Q6What is the difference between GROUP BY and ORDER BY?

GROUP BY puts rows into groups, usually to calculate totals, counts, or averages. ORDER BY sorts the result.

Example: group employees by department to calculate average salary, then order departments by that average.

Q7What is the difference between COUNT(*), COUNT(column), and COUNT(DISTINCT column)?

For values 100, 100, NULL, 200:

ExpressionResultReason
COUNT(*)4Counts every row
COUNT(column)3Ignores NULL
COUNT(DISTINCT column)2Counts different non-NULL values
Q8How does SQL handle NULL, and what is COALESCE()?

NULL means a value is missing or unknown — different from zero or an empty string. Use IS NULL / IS NOT NULL, never = NULL.

COALESCE() returns the first non-NULL value:

SELECT COALESCE(phone, 'Not provided') AS phone
FROM customers;
Q9What is the logical execution order of a SQL query?

FROM/JOIN → WHERE → GROUP BY/aggregation → HAVING → window calculations → SELECT → DISTINCT → ORDER BY → OFFSET/LIMIT

This explains why you generally cannot use a SELECT alias inside WHERE — the alias is created later. This is the logical order; the optimizer can use a different physical execution strategy.

Q10What is the difference between UNION and UNION ALL?

Both combine rows from multiple queries. UNION removes duplicate rows. UNION ALL keeps duplicate rows and usually requires less work. The queries must return the same number of columns with compatible data types.

🔗 Joins
Q4Explain INNER JOIN, LEFT JOIN, RIGHT JOIN, and FULL OUTER JOIN.
JoinRows returned
INNER JOINMatching rows from both tables
LEFT JOINAll left-table rows, plus matching right-table rows
RIGHT JOINAll right-table rows, plus matching left-table rows
FULL OUTER JOINAll matching and unmatched rows from both tables

For unmatched rows, columns from the missing side contain NULL.

Q5What is a self join?

A self join joins a table with itself, using different aliases. Example: employees and their managers are stored in the same employees table. Match an employee's manager_id with another employee's id.

SELECT e.name AS employee, m.name AS manager
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.id;
Q34How does filtering in ON versus WHERE affect a LEFT JOIN?

A condition in ON controls which right-side rows match. A condition in WHERE filters the joined result.

This keeps every customer, even those without a paid order:

SELECT c.id, o.id AS order_id
FROM customers c
LEFT JOIN orders o
  ON o.customer_id = c.id
 AND o.status = 'paid';

This keeps only customers with matching paid orders (the WHERE removes unmatched rows because their o.status is NULL):

SELECT c.id, o.id AS order_id
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.status = 'paid';
🧩 Subqueries & CTEs
Q11What is the difference between a subquery and a correlated subquery?

A subquery is a query inside another query. A non-correlated subquery can run independently (e.g. the company's average salary). A correlated subquery refers to the current outer row (e.g. that employee's department average). The database may optimize how these execute; correlated isn't automatically slower.

Q12What is the difference between IN and EXISTS? How does NULL affect NOT IN?

IN checks whether a value belongs to a list or query result. EXISTS checks whether a subquery returns at least one row.

⚠️ If a NOT IN subquery contains NULL, comparisons can become unknown, causing expected rows to disappear. For "no matching record," a correlated NOT EXISTS is often safer.
Q13What is a CTE, and how does it differ from a subquery?

A CTE (Common Table Expression) is a named query written using WITH. It helps break a complex query into readable steps and can be referenced multiple times within the same statement. A subquery is written directly inside another query. A CTE is not a permanent table and isn't automatically faster than a subquery.

Q19How would you find customers who have never placed an order?

Return customers for whom no matching order exists:

SELECT c.id, c.name
FROM customers c
WHERE NOT EXISTS (
  SELECT 1
  FROM orders o
  WHERE o.customer_id = c.id
);

SELECT 1 is sufficient because EXISTS only checks whether a row exists.

🪟 Window Functions
Q14What are window functions, and how do they differ from GROUP BY?

Window functions calculate across related rows while keeping each row visible. GROUP BY gives one result row per group; a window function keeps individual rows with an extra calculated value.

SELECT name, salary,
       AVG(salary) OVER (
         PARTITION BY department_id
       ) AS department_average
FROM employees;

PARTITION BY separates the calculation by department.

Q16How would you find the second-highest or Nth-highest distinct salary?

Use DENSE_RANK() so duplicate salaries share the same position:

WITH ranked AS (
  SELECT salary,
         DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk
  FROM employees
  WHERE salary IS NOT NULL
)
SELECT DISTINCT salary
FROM ranked
WHERE rnk = 2;

Replace 2 with the required N. If that rank doesn't exist, the query returns no rows.

Q17How would you find the highest-paid employees in each department, including ties?

Rank employees separately inside each department:

WITH ranked AS (
  SELECT id, name, department_id, salary,
         DENSE_RANK() OVER (
           PARTITION BY department_id
           ORDER BY salary DESC
         ) AS rnk
  FROM employees
  WHERE salary IS NOT NULL
)
SELECT id, name, department_id, salary
FROM ranked
WHERE rnk = 1;

If two employees share the highest salary, both are returned.

Q36What do LAG() and LEAD() do?

LAG() reads a value from an earlier row. LEAD() reads a value from a later row.

SELECT month, revenue,
       LAG(revenue) OVER (ORDER BY month) AS previous_revenue,
       revenue - LAG(revenue) OVER (ORDER BY month) AS change
FROM monthly_sales
ORDER BY month;

This compares each month's revenue with the previous month. The first month has no previous row, so its previous value is NULL.

🧹 Dedup, Latest Row & Pagination
Q18How would you find and delete duplicate records while keeping one row?

First define "duplicate" — here, same email address. Find duplicates:

SELECT email, COUNT(*) AS occurrences
FROM employees
GROUP BY email
HAVING COUNT(*) > 1;

Keep the row with the smallest id and delete the others:

WITH duplicates AS (
  SELECT id,
         ROW_NUMBER() OVER (
           PARTITION BY email
           ORDER BY id
         ) AS rn
  FROM employees
)
DELETE FROM employees
WHERE id IN (
  SELECT id
  FROM duplicates
  WHERE rn > 1
);
Q20How would you retrieve the latest order for each customer?

Use ROW_NUMBER() with the newest timestamp first:

WITH ranked AS (
  SELECT id, customer_id, created_at,
         ROW_NUMBER() OVER (
           PARTITION BY customer_id
           ORDER BY created_at DESC NULLS LAST, id DESC
         ) AS rn
  FROM orders
)
SELECT id, customer_id, created_at
FROM ranked
WHERE rn = 1;

If timestamps are equal, the larger id wins, making the selection predictable.

Q37What is offset pagination versus keyset pagination?

Offset pagination skips a number of rows:

SELECT id, amount
FROM orders
ORDER BY id
LIMIT 10 OFFSET 20;

Keyset pagination starts after the last value already displayed:

SELECT id, amount
FROM orders
WHERE id > 125
ORDER BY id
LIMIT 10;

Keyset pagination usually scales better for deep pages because it avoids skipping all earlier results. Use a unique ordering (or a tie-breaker) so page boundaries stay predictable.

📊 Aggregation Patterns
Q21How would you calculate a running total?

A running total adds the current amount to all earlier amounts:

SELECT id, amount,
       SUM(amount) OVER (
         ORDER BY created_at, id
         ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) AS running_total
FROM orders
ORDER BY created_at, id;

For amounts 100, 200, 50, the running totals are 100, 300, 350. The frame means "include every row from the beginning through the current row."

Q35How do you use CASE for conditional aggregation?

CASE chooses a value based on a condition. Combine it with an aggregate to calculate separate totals or counts.

SELECT
  COUNT(CASE WHEN status = 'pending' THEN 1 END) AS pending,
  COUNT(CASE WHEN status = 'completed' THEN 1 END) AS completed,
  COUNT(CASE WHEN status = 'cancelled' THEN 1 END) AS cancelled
FROM orders;

Each CASE returns 1 for matching rows and NULL otherwise. COUNT() ignores those nulls.

⚡ Indexing & Performance
Q22What is an index, and how does it affect performance?

An index is like a book's index: it helps the database locate data without searching every row. It can speed up filtering, joins, and sorting. The trade-off is extra storage and extra work during inserts, updates, and deletes because indexes must also be maintained.

Q23What is a composite index, and why does column order matter?

A composite index contains multiple columns:

CREATE INDEX idx_department_salary
ON employees (department_id, salary);

For a B-tree index, this is generally most useful when filtering by department_id, optionally followed by salary conditions. Filtering only by salary may be less efficient. Column order affects how much of the index the database must examine — it doesn't mean other combinations can never use the index.

Q24How do you identify and optimize a slow SQL query?

Use an execution plan to see where the database spends time:

EXPLAIN ANALYZE
SELECT id, name
FROM employees
WHERE department_id = 10;

Look for expensive scans, joins, sorting, and large differences between estimated and actual row counts. Then improve the relevant indexes, filter unnecessary rows, return only needed columns, and compare performance again.

⚠️ EXPLAIN ANALYZE actually executes the query.
Q40What are clustered and nonclustered indexes in SQL Server?
IndexEasy meaning
ClusteredThe index's leaf level contains the actual table rows, organized by the index key
NonclusteredA separate structure stores index keys and references to the table rows

A table can have one clustered index because its rows can have only one clustered organization, but it can have multiple nonclustered indexes. Even with a clustered index, use ORDER BY when you need results in a guaranteed order.

🏗️ Normalization & Views
Q25What is normalization? Explain 1NF, 2NF, and 3NF.

Normalization organizes tables to reduce repeated information and avoid inconsistent updates.

FormEasy meaning
1NFAvoid repeating groups; each cell contains one value for its column
2NFFollow 1NF; non-key information must depend on the whole key
3NFFollow 2NF; non-key information should not depend on another non-key attribute

Example: store a department's name once in departments, rather than repeating it in every employee row. Employees store department_id.

🔄 Transactions & Concurrency
Q27What is a transaction? Explain ACID, COMMIT, and ROLLBACK.

A transaction groups related database operations into one unit of work. Example: transferring money requires both a debit and a credit — if the credit fails, the debit should also be undone.

ACID propertyEasy meaning
AtomicityAll changes succeed together, or none remain
ConsistencyChanges preserve defined database rules
IsolationConcurrent transactions interact according to their isolation level
DurabilityCommitted changes survive failures under the database's durability guarantees

COMMIT makes the transaction's changes permanent. ROLLBACK cancels its uncommitted changes.

Q28What are isolation levels and common read problems?

Isolation controls what a transaction can see while other transactions change data.

  • Dirty read: reading another transaction's changes before they commit.
  • Non-repeatable read: reading the same row twice and seeing a changed value.
  • Phantom read: repeating a condition-based query and seeing a different set of matching rows.
LevelStandard minimum protection
Read UncommittedDirty reads may occur
Read CommittedPrevents dirty reads
Repeatable ReadAlso prevents non-repeatable reads
SerializableResults must be equivalent to transactions running one at a time

In PostgreSQL, Read Uncommitted behaves like Read Committed, and Repeatable Read also prevents phantom reads. Serializable transactions may need retries when conflicts occur.

Q29What is a deadlock, and how do you handle it?

A deadlock happens when transactions wait for locks held by each other, so neither can continue. Example: Transaction A locks row 1 and waits for row 2; Transaction B locks row 2 and waits for row 1.

✅ Reduce deadlocks by accessing rows in a consistent order and keeping transactions short. If the database aborts a transaction to resolve a deadlock, roll it back and retry the complete transaction.
Q38What is optimistic versus pessimistic locking?
ApproachEasy meaning
OptimisticRead normally, then check whether someone changed the record before saving
PessimisticLock the record before working on it, making conflicting operations wait

Optimistic locking commonly uses a version column:

UPDATE users
SET name = 'Shivam',
    version = version + 1
WHERE id = 10
  AND version = 3;

If zero rows are updated, the record was removed or its version changed — handle that conflict instead of overwriting blindly. For pessimistic locking in PostgreSQL, use SELECT ... FOR UPDATE inside a transaction; the row lock remains until the transaction ends.

🔐 Security & Constraints
Q30What is SQL injection, and how do parameterized queries prevent it?

SQL injection happens when user input becomes part of the SQL command itself. Parameterized queries send SQL and input values separately, so input is treated as data.

await pool.query(
  "SELECT id, name FROM users WHERE email = $1",
  [email]
);

Use an allowlist for dynamic column names or sort directions — value parameters do not replace SQL identifiers.

Q31What do constraints and foreign-key actions do?
RuleMeaning
NOT NULLA value must be provided
CHECK (salary > 0)Rejects a salary that fails the condition
ON DELETE CASCADEDeleting a parent also deletes its matching child rows
ON DELETE RESTRICTPrevents deleting a parent while child rows reference it
ON DELETE SET NULLSets the child's foreign-key column to NULL

In PostgreSQL, a CHECK condition that evaluates to unknown because of NULL passes — add NOT NULL when the value is required. SET NULL requires the affected column to allow nulls.

⚙️ Procedures, Functions & Triggers
Q32What is a stored procedure versus a user-defined function?

Both are reusable pieces of logic stored in the database. In PostgreSQL: a procedure performs a workflow and is invoked using CALL, and can return information through output parameters. A function returns a value or rows and can be used within a query.

Example: a procedure might process a monthly payroll; a function might calculate tax for one salary.

Q33What are triggers, and what problems can they introduce?

A trigger automatically runs database logic when an event occurs, such as an insert, update, or delete. Example: after an employee's salary changes, a trigger records the old and new salary in an audit table.

⚠️ Triggers help automate rules, but can introduce hidden behavior, slower writes, difficult debugging, or accidental recursive execution.
➕ UPSERT
Q39What is an UPSERT?

An UPSERT means insert a row if it does not exist; update it if it already exists. Assuming users.email has a unique constraint:

INSERT INTO users (email, name)
VALUES ('shivam@example.com', 'Shivam')
ON CONFLICT (email)
DO UPDATE SET name = EXCLUDED.name;

EXCLUDED.name means the name from the attempted insert. PostgreSQL handles this insert-or-update operation atomically, including when requests arrive concurrently.
