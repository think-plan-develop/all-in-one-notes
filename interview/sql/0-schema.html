1. What is a Schema?
Schema = a folder inside a database

A schema is a logical container inside a database that organizes database objects. It can contain:

TablesViewsIndexesFunctionsSequencesTriggers

Database structure

structure
my_database
│
├── public (Default Schema)
│   ├── users
│   ├── products
│   └── orders
│
└── sql_practice (Custom Schema)
    ├── users
    ├── employees
    └── orders

Why do we use schemas?

1. OrganizationKeep related tables together.
2. IsolationSeparate practice tables from production or other project tables.
3. No naming conflictsMultiple schemas can contain tables with the same name.
4. SecurityPermissions can be managed at the schema level.
Same table name in different schemas

PostgreSQL allows the same table name in different schemas.

same-name.sql
SELECT * FROM public.users;

SELECT * FROM sql_practice.users;

Although both tables are named users, they are different tables because their schema names are different. The complete table name is called a fully qualified table name:

fully-qualified.sql
schema_name.table_name
2. DROP SCHEMA IF EXISTS
Purpose: delete an existing schema

Syntax

syntax.sql
DROP SCHEMA [IF EXISTS] schema_name [CASCADE | RESTRICT];

Example

drop-schema.sql
DROP SCHEMA IF EXISTS sql_practice CASCADE;

Explanation

KeywordDescription
DROP SCHEMADeletes a schema.
IF EXISTSPrevents an error if the schema does not exist.
sql_practiceName of the schema to delete.
CASCADEAlso deletes objects inside the schema and handles dependent objects.
What does CASCADE mean?

Suppose your schema contains:

structure
sql_practice
│
├── employees
├── customers
├── orders
└── products

When you execute:

cascade.sql
DROP SCHEMA sql_practice CASCADE;

PostgreSQL deletes:

  • The sql_practice schema.
  • All tables inside it.
  • Other objects inside it, such as views and functions.
  • Dependent objects outside the schema where necessary.
⚠️ Important: CASCADE can permanently delete data and dependent objects. Use it carefully.
What is RESTRICT?

RESTRICT prevents deletion if the schema contains objects.

restrict.sql
DROP SCHEMA IF EXISTS sql_practice RESTRICT;
It is the default behavior when neither CASCADE nor RESTRICT is specified.

Difference

CASCADE

Deletes dependent objects too.
Useful for resetting practice environments.

RESTRICT

Prevents deletion if the schema contains objects.
Useful for safer deletion.
3. CREATE SCHEMA
Purpose: create a new schema in the current database

Syntax

syntax.sql
CREATE SCHEMA schema_name;

Example

create-schema.sql
CREATE SCHEMA sql_practice;

This creates a schema named sql_practice. Your database structure now looks like:

structure
my_database
│
├── public
│
└── sql_practice

You can now create tables inside this schema.

Create a table inside a schema
create-table-in-schema.sql
CREATE TABLE sql_practice.employees (
    employee_id SERIAL PRIMARY KEY,
    employee_name VARCHAR(100),
    salary NUMERIC(10, 2)
);

Notice sql_practice.employees. Here:

  • sql_practice = Schema name
  • employees = Table name
You can also create tables without specifying the schema if you configure the search path.
4. SET search_path
Purpose: choose which schemas PostgreSQL searches by default

Syntax

syntax.sql
SET search_path TO schema_name;

Example

set-search-path.sql
SET search_path TO sql_practice;

Now PostgreSQL searches the sql_practice schema first when you refer to a table without specifying its schema.

Without SET search_path

You must specify the schema name explicitly.
sql
SELECT * FROM sql_practice.employees;

With SET search_path

You can directly use the table name.
sql
SELECT * FROM employees;

PostgreSQL looks for employees in the schemas listed in your search path.

Multiple schemas in search_path
multiple-schemas.sql
SET search_path TO sql_practice, public;

PostgreSQL searches in this order:

  1. sql_practiceSearched first.
  2. publicSearched second.

If both schemas contain a table named users, PostgreSQL uses sql_practice.users when you write:

lookup.sql
SELECT * FROM users;

You can still explicitly access the other table:

explicit.sql
SELECT * FROM public.users;
5. Complete Practice Setup Script
A common script for starting a new SQL practice session
practice-setup.sql
-- Step 1: Delete the existing practice schema
DROP SCHEMA IF EXISTS sql_practice CASCADE;

-- Step 2: Create a fresh practice schema
CREATE SCHEMA sql_practice;

-- Step 3: Set the default schema
SET search_path TO sql_practice;

-- Step 4: Create a table
CREATE TABLE employees (
    employee_id SERIAL PRIMARY KEY,
    employee_name VARCHAR(100),
    salary NUMERIC(10, 2)
);

-- Step 5: Insert sample data
INSERT INTO employees (employee_name, salary)
VALUES
    ('John', 50000),
    ('David', 60000);

-- Step 6: Retrieve records
SELECT * FROM employees;

What happens when you execute this script?

  1. DROP SCHEMARemoves the previous practice schema and its objects.
  2. CREATE SCHEMACreates a fresh sql_practice schema.
  3. SET search_pathMakes sql_practice the default schema for the current session.
  4. CREATE TABLECreates the employees table inside sql_practice.
  5. INSERTAdds sample employee records.
  6. SELECTRetrieves records from the employees table.

7. Common Interview Questions
Q1. What is the difference between a database and a schema?
  • Database: The main container that holds data and schemas.
  • Schema: A logical container inside a database that organizes tables and other objects.
Q2. Can two schemas have tables with the same name?

Yes.

sql
public.users
sql_practice.users
Q3. What happens if you don't set the search_path?

PostgreSQL uses its default search path, commonly "$user", public, subject to configuration.

Q4. Does SET search_path create a schema?

No. It only changes the schema lookup order for the current session.

Q5. What is the difference between CASCADE and RESTRICT?
  • CASCADE: Deletes dependent objects.
  • RESTRICT: Prevents deletion when the schema contains objects.
Q6. Does SET search_path permanently change the database?

No. Regular SET applies to the current session. It does not permanently change the database configuration.
