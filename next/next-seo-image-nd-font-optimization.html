🔄 Next.js — Data Fetching, Caching, Loading & Error Handling

Four App Router conventions that work together: fetching data in Server Components, controlling cache/revalidation, loading.tsx, and error.tsx boundaries.

1. Data Fetching 2. Caching 3. Loading 4. Error Handling
🧩 At a Glance
📡
async/await in Server Components: no useEffect needed to fetch data.
🗂️
cache / next.revalidate: explicit fetch options control freshness.
⏳
loading.tsx: automatic fallback UI while a route's data loads.
🚨
error.tsx: a Client Component boundary with a reset() retry.
1️⃣ Data Fetching — Get Data from an API
In a Server Component, use async/await directly
app/products/page.tsx
export default async function ProductsPage() {
  const response = await fetch("https://dummyjson.com/products");

  if (!response.ok) {
    throw new Error("Failed to fetch products");
  }

  const data = await response.json();

  return <h1>Total products: {data.total}</h1>;
}
📝 Note: No useEffect is needed for this server fetch.
2️⃣ Caching & Revalidation
Caching → reuse data; revalidation → refresh cached data

These are explicit server-side fetch options:

RequirementExample
Fetch fresh data when the request runsfetch(url, { cache: "no-store" })
Cache and reuse the responsefetch(url, { cache: "force-cache" })
Cache with a 60-second revalidation intervalfetch(url, { next: { revalidate: 60 } })
⚠️ Revalidation is not a timer that fetches every 60 seconds. After that interval, a subsequent request can trigger a refresh.

After updating data, you can invalidate a path from server code:

revalidate-path.ts
import { revalidatePath } from "next/cache";

// After saving a product, inside a Server Action or Route Handler:
revalidatePath("/products");
📝 Note: Caching behavior varies by Next.js version and whether Cache Components are enabled, so avoid relying on defaults.
3️⃣ Loading — Show Something While Content Loads
Create this file alongside your products page
app/products/loading.tsx
export default function Loading() {
  return <p>Loading products...</p>;
}
✅ Automatic: Next.js automatically uses it as a loading fallback for that route — no wiring required.
4️⃣ Error Handling — Fallback When Rendering Fails
error.tsx must be a Client Component
app/products/error.tsx
"use client";

export default function ErrorPage({
  reset,
}: {
  reset: () => void;
}) {
  return (
    <div>
      <p>Something went wrong.</p>
      <button onClick={() => reset()}>Try again</button>
    </div>
  );
}
📝 Note: reset() attempts to render the failed content again.
FileResponsibility
page.tsxFetch and display data
loading.tsxLoading fallback
error.tsxFallback for uncaught rendering errors
⚠️ Limitation: these error boundaries don't automatically catch errors in event handlers — handle those with try/catch.
