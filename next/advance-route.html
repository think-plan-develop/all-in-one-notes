🔀 1. App Router vs Pages Router
Two Routing Systems
Next.js ships two routing systems. Pages Router is still supported, but for a refresher or a new project, focus on the App Router — the older data-fetching functions (getServerSideProps, getStaticProps, getStaticPaths) aren't used inside app/.
FeaturePages RouterApp Router
Main folderpages/app/
Page examplepages/about.tsxapp/about/page.tsx
Shared layoutsUsually _app.tsx or custom patternsBuilt-in layout.tsx
Server data fetchinggetServerSideProps, getStaticPropsAsync Server Components
Generate static dynamic pathsgetStaticPathsgenerateStaticParams
Backend endpointspages/api/route.ts
Router hook importnext/routernext/navigation

🏠 2. Root Layout — app/layout.tsx
The Outermost Wrapper for Every Page
The root layout must provide <html> and <body>. Next.js supplies children automatically — it's the page or nested layout slotted into this wrapper.
app/layout.tsx
// app/layout.tsx
import "./globals.css";

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  );
}
PartMeaning
<html>Root HTML element
<body>Contains the visible application
childrenThe page or nested layout Next.js inserts here
React.ReactNodeTypeScript type for content React can render
import "./globals.css"Loads global styles
✅ If you leave the generated layout unchanged: your pages still work, using its existing fonts, styles, and default metadata.
⚠️ If you add a header here: every page beneath this root layout — including login and signup — receives it. A page cannot cancel a parent layout.
header-in-root.tsx
<body>
  <header>Header for all pages</header>
  {children}
</body>
💡 Rule of thumb: place shared UI lower in the folder structure when only selected pages need it.
🪆 3. Nested Layouts
A Layout That Wraps Only What's Below It
A nested layout wraps only the pages underneath its own folder. Nested layouts add to parent layouts — they never replace them.
FileResponsibility
app/layout.tsxRoot HTML structure
app/dashboard/layout.tsxShared dashboard structure
app/dashboard/page.tsxDashboard content
app/dashboard/settings/page.tsxSettings content
app/dashboard/layout.tsx
// app/dashboard/layout.tsx
export default function DashboardLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <div>
      <aside>Dashboard Sidebar</aside>
      <section>{children}</section>
    </div>
  );
}
📝 Opening /dashboard/settings applies: Root layout → Dashboard layout → Settings page. The dashboard layout sits inside the root layout's children; the settings page sits inside the dashboard layout's children.
⚠️ Don't: repeat <html> and <body> in a nested layout, or manually import it into each page — Next.js wires it up automatically from the folder structure.
🎭 4. Dashboard with Header/Footer — Login & Signup Without
Keeping the Root Layout Minimal
Keep the root layout minimal (just <html>, <body>, children) and move the header/footer into the dashboard's own nested layout. Login and signup, sitting outside the dashboard/ folder, never see it.
FileWhat It Contains
app/layout.tsx<html>, <body>, and children
app/dashboard/layout.tsxDashboard header and footer
app/dashboard/page.tsxDashboard page
app/login/page.tsxLogin page
app/signup/page.tsxSignup page
app/dashboard/layout.tsx
// app/dashboard/layout.tsx
export default function DashboardLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <>
      <header>Dashboard Header</header>
      <main>{children}</main>
      <footer>Dashboard Footer</footer>
    </>
  );
}
pages.tsx
// app/dashboard/page.tsx
export default function DashboardPage() {
  return <h1>Dashboard</h1>;
}

// app/login/page.tsx
export default function LoginPage() {
  return <h1>Login</h1>;
}

// app/signup/page.tsx
export default function SignupPage() {
  return <h1>Signup</h1>;
}
URLVisible Content
/dashboardDashboard Header + Dashboard + Dashboard Footer
/loginLogin only
/signupSignup only
✅ Why this works: login and signup still use the root layout — they simply avoid the dashboard layout because they live outside its folder.
🗂️ 5. Route Groups — Share a Layout Across Many Routes
(main) — A Folder Name That Doesn't Touch the URL
When dashboard, products, orders, profile and many other routes need the same header/footer, place them inside (main). The parentheses mark a route group — its name never becomes part of the URL.
FileURL
app/(main)/page.tsx/
app/(main)/dashboard/page.tsx/dashboard
app/(main)/products/page.tsx/products
app/(main)/orders/page.tsx/orders
app/(main)/profile/page.tsx/profile
app/login/page.tsx/login
app/signup/page.tsx/signup

➕ One shared layout for all of them

app/(main)/layout.tsx
// app/(main)/layout.tsx
export default function MainLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <>
      <header>Website Header</header>
      <main>{children}</main>
      <footer>Website Footer</footer>
    </>
  );
}
📝 Result: all pages inside (main) receive this header and footer. Login and signup remain outside and are unaffected. Use this instead of repeating the same header/footer markup in every route's own layout.
Folder PatternExample URL
app/main/products/page.tsx/main/products
app/(main)/products/page.tsx/products

📋 Things to remember

  • The group name can be (main), (website), or another meaningful name.
  • Keep the root layout minimal if login/signup should have no shared header.
  • After moving dashboard into (main), remove duplicated header/footer markup from its own layout.
  • Two groups cannot define the same URL — e.g. (main)/about/page.tsx and (other)/about/page.tsx conflict.
📝 Source: nextjs.org — Route Groups.
📁 6. Folders & Files That Aren't Routes
page.tsx and route.ts Are the Only Trigger Files
You can keep components and utilities inside app/. Ordinary files do not automatically become browser-accessible pages — only page.tsx exposes page UI and route.ts exposes a request handler.
FileResult
app/components/Header.tsxReusable component; no route
app/utils/formatPrice.tsUtility function; no route
app/products/ProductCard.tsxProduct component; no route
app/products/page.tsxPage at /products
app/api/products/route.tsRequest endpoint at /api/products
app/components/Header.tsx
// app/components/Header.tsx
export default function Header() {
  return <header>My Website</header>;
}

📥 Import it into a shared layout

app/(main)/layout.tsx
import Header from "../components/Header";

export default function MainLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <>
      <Header />
      <main>{children}</main>
      <footer>My Footer</footer>
    </>
  );
}
💡 Two valid layouts for shared files:
LocationUse
components/Header.tsxShared UI components (outside app/)
utils/formatPrice.tsReusable helper functions (outside app/)
app/Pages, layouts, and route-specific files
✅ Both arrangements are valid. Choose one consistent structure so components and utilities stay easy to find. Next.js also has special metadata conventions such as favicon.ico.
