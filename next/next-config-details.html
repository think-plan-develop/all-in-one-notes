⚙️ 1. Understanding next.config.ts
Where It Lives & What It's For
It lives alongside package.json, outside app/. Next.js reads this file during its build and server setup — it is not a React component. An empty configuration is valid because Next.js provides defaults.
next.config.ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  // Configuration options
};

export default nextConfig;
CodePurpose
import type { NextConfig }Gives TypeScript information about valid Next.js options
nextConfig: NextConfigChecks your configuration and provides autocomplete
export default nextConfigMakes the configuration available to Next.js
📝 Source: nextjs.org — next.config.js options.
🖼️ 2. Allow External Images
remotePatterns for next/image
When using next/image, configure the external image locations you allow — this setting is only for image loading. It does not allow or configure general API requests.
next.config.ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  images: {
    remotePatterns: [
      {
        protocol: "https",
        hostname: "images.example.com",
        pathname: "/products/**",
      },
    ],
  },
};

export default nextConfig;
PropertyMeaning
protocolAllow HTTPS
hostnameAllow this image host
pathnameAllow images under /products/, including subfolders
app/products/page.tsx
import Image from "next/image";

export default function Product() {
  return (
    <Image
      src="https://images.example.com/products/shirt.jpg"
      alt="Blue shirt"
      width={300}
      height={300}
    />
  );
}
↪️ 3. Redirects — Move Visitors to Another URL
The Browser URL Changes
Add redirects inside nextConfig. Opening /old-products changes the browser URL to /products.
next.config.ts
async redirects() {
  return [
    {
      source: "/old-products",
      destination: "/products",
      permanent: true,
    },
  ];
},
OptionMeaning
sourceURL being requested
destinationURL to send the visitor to
permanent: truePermanent redirect, HTTP 308
permanent: falseTemporary redirect, HTTP 307
💡 Rule: use permanent redirects when a URL has permanently moved.
🔁 4. Rewrites — Serve Another Destination, Same URL
The Browser URL Stays the Same
The visitor opens /shop and receives the /products page, while the browser still shows /shop. Rewrites can also forward requests to an external backend — a rewrite is not authentication or secret storage.
next.config.ts
async rewrites() {
  return [
    {
      source: "/shop",
      destination: "/products",
    },
  ];
},
FeatureBrowser URL Changes?Example
RedirectYesOld page moved to a new address
RewriteNoAlternative address or proxy to another backend

🧩 Combined — all three settings in one file

next.config.ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  images: {
    remotePatterns: [
      { protocol: "https", hostname: "images.example.com", pathname: "/products/**" },
    ],
  },

  async redirects() {
    return [
      { source: "/old-products", destination: "/products", permanent: true },
    ];
  },

  async rewrites() {
    return [
      { source: "/shop", destination: "/products" },
    ];
  },
};

export default nextConfig;
📝 Note: only add options your project actually needs.
🔑 5. Where to Store Environment Variables
.env.local Beside package.json
Create .env.local beside package.json, even when your code uses a src/ folder. Next.js automatically loads environment files — you normally don't need dotenv.config().
.env.local
# Server-side values — placeholders only
API_BASE_URL=https://api.example.com
API_SECRET_KEY=replace-with-your-secret
DATABASE_URL=replace-with-your-database-url
JWT_SECRET=replace-with-a-random-secret

# Public value
NEXT_PUBLIC_APP_NAME=My Next App

Access values using:

usage.ts
process.env.API_BASE_URL
process.env.API_SECRET_KEY
Variable NameIntended Availability
API_SECRET_KEYServer only
DATABASE_URLServer only
NEXT_PUBLIC_APP_NAMEServer and browser
NEXT_PUBLIC_API_BASE_URLServer and browser; only for a public API address
⚠️ NEXT_PUBLIC_ values are public and embedded at build time. Changing them in production requires a new build. Never use this prefix for secrets.
🛰️ 6. How to Call an API That Requires a Secret
Do the Authenticated Call on the Server
Make the authenticated API call on the Next.js server — a Server Component (no "use client") — so the secret never reaches the browser. The page renders only the resulting product names, never the key.
app/products/page.tsx
// app/products/page.tsx
// Server Component — no "use client"

type Product = {
  id: number;
  name: string;
};

export default async function ProductsPage() {
  const baseUrl = process.env.API_BASE_URL;
  const apiKey = process.env.API_SECRET_KEY;

  if (!baseUrl || !apiKey) {
    throw new Error("Missing API configuration");
  }

  const response = await fetch(`${baseUrl}/products`, {
    headers: {
      Authorization: `Bearer ${apiKey}`,
    },
    cache: "no-store",
  });

  if (!response.ok) {
    throw new Error("Failed to fetch products");
  }

  // Assumes the API returns an array of products.
  const products: Product[] = await response.json();

  return (
    <ul>
      {products.map((product) => (
        <li key={product.id}>{product.name}</li>
      ))}
    </ul>
  );
}
📝 If a Client Component needs the data: it can call your Next.js Route Handler, which calls the external service using the secret — the browser only ever talks to your own server.
⚠️ Never: render secrets, pass them as props to Client Components, or return them in API responses. A server-only variable can still leak if your code explicitly sends its value to the browser.
🚫 7. Don't Put Secrets in next.config.ts's env Option
The env Option Bundles Values Into JavaScript
next.config.ts
// ❌ Do not do this
const nextConfig = {
  env: {
    API_SECRET_KEY: process.env.API_SECRET_KEY,
  },
};
⚠️ Why it's dangerous: the env configuration makes configured values available for inclusion in JavaScript bundles — even without the NEXT_PUBLIC_ prefix.
✅ Instead: read secrets directly from process.env in server code. You don't need to copy them into next.config.ts at all.
📝 Source: nextjs.org — env option.
🚀 8. Local Development & Deployment
Where Values Live at Each Stage
SituationWhat to Do
Local developmentStore values in .env.local
Git repositoryKeep real environment files ignored; commit an .env.example containing placeholders
ProductionConfigure secrets through your hosting platform or secret manager
After changing local configurationRestart npm run dev if changes aren't picked up
⚠️ Remember: .env.local is a plain-text file, not encrypted storage. Keep it out of Git and outside public/.
