Data Fetching & Caching Reference

Mastering the App Router's native data lifecycle: from async server components to fine-grained cache revalidation.

1. Async Server Components
Direct Fetching in Server Components

By declaring a component as async, you can perform data fetches directly at the component level, eliminating the need for useEffect or complex loading states.

app/products/page.js
export default async function ProductsPage() {
  const res = await fetch("https://dummyjson.com/products");
  const data = await res.json();

  return (
    <>
      <h1>Products</h1>
      {data.products.map(p => <p key={p.id}>{p.title}</p>)}
    </>
  );
}

3. Server Actions & Revalidation
Mutating Data Without API Routes

Server Actions allow you to define mutation logic (Create, Update, Delete) directly in the server environment.

actions.js
"use server";
import { revalidatePath } from "next/cache";

export async function addProduct(formData) {
  // await db.insert(...)
  revalidatePath("/products"); // Clear cache for the specific route
}
4. revalidateTag() vs revalidatePath()
Granular Cache Control

While revalidatePath targets a route, revalidateTag targets any data marked with a specific tag across the entire application.

fetch() with tags
fetch(url, { next: { tags: ["products"] } });

Calling revalidateTag("products") will update every page in your app that displays product data, regardless of the route.
