⚖️ Server Component vs Client Component
What Each One Can and Can't Do
Every component is a Server Component by default in the App Router. You opt a component into the client by adding the "use client" directive at the very top of the file.
Server ComponentClient Component
Main purposeFetch data and render content on the serverHandle user interaction
useState, useEffect❌ Cannot use✅ Can use
onClick, onChange❌ Cannot handle directly✅ Can handle
Database and secrets✅ Can access on the server❌ Keep these out of client code
DirectiveNone neededAdd "use client" at the top
✅ Remember: use Server Components for server work; use Client Components when you need state, effects, or events.
📝 Important nuance: a Client Component can still have its initial HTML rendered on the server. "use client" enables browser interactivity — it does not mean "render only in the browser." Source: nextjs.org.
🖥️ Server Component — No Directive Needed
app/page.tsx
// app/page.tsx
export default function Home() {
  return <h1>Welcome</h1>;
}
🖱️ Client Component — "use client" at the Top
app/components/Counter.tsx
"use client";

import { useState } from "react";

export default function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      Count: {count}
    </button>
  );
}
📦 1. Server Component — Display Products from an API
Fetch on the Server, No useEffect Needed
This fetches data on the server. No state or click handlers are needed — the page simply renders once the data has arrived.
app/products/page.tsx
// app/products/page.tsx
export default async function ProductsPage() {
  const response = await fetch("https://dummyjson.com/products");

  if (!response.ok) {
    throw new Error("Failed to load products");
  }

  const data = await response.json();

  return (
    <ul>
      {data.products.map((product: { id: number; title: string }) => (
        <li key={product.id}>{product.title}</li>
      ))}
    </ul>
  );
}
✅ Why Server Component? it fetches and displays data without browser interaction. You don't need useEffect for this server fetch — the async function body does it directly.
🔒 2. Client Component — Show/Hide a Password
Needs State and a Button Click → "use client"
This needs state and a button click, so it must be a Client Component.
app/components/PasswordInput.tsx
// app/components/PasswordInput.tsx
"use client";

import { useState } from "react";

export default function PasswordInput() {
  const [showPassword, setShowPassword] = useState(false);

  return (
    <div>
      <input
        type={showPassword ? "text" : "password"}
        placeholder="Enter password"
      />

      <button
        type="button"
        onClick={() => setShowPassword((prev) => !prev)}
      >
        {showPassword ? "Hide" : "Show"}
      </button>
    </div>
  );
}
✅ Why Client Component? clicking the button updates state and changes the input type.
Real RequirementSuitable Component
Fetch and display a product listServer Component
Toggle password visibilityClient Component
💡 Both can work together: a Server Component page can render a Client Component such as <PasswordInput /> — composition isn't all-or-nothing.
