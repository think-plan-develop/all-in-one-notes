Next.js Routing Basics

Project structure

When you create a modern Next.js app, you normally have:

my-app/ ├── app/ │ ├── page.tsx │ ├── layout.tsx │ └── ... ├── public/ ├── package.json └── ...

The important folder is:

  • app/
  • page.tsx = route

File → URL mapping

For example:

app/ ├── page.tsx ├── about/ │ └── page.tsx └── contact/ └── page.tsx

This automatically creates:

/ → app/page.tsx /about → app/about/page.tsx /contact → app/contact/page.tsx

So app/about/page.tsx means:

http://localhost:3000/about
✅ No react-router-dom is required.
Nested Routes ⭐⭐⭐⭐⭐

This is one of the most important parts. Suppose you need:

/products /products/mobile /products/laptop

Folder structure:

app/ └── products/ ├── page.tsx ├── mobile/ │ └── page.tsx └── laptop/ └── page.tsx

Mapping:

URLFile
/productsproducts/page.tsx
/products/mobileproducts/mobile/page.tsx
/products/laptopproducts/laptop/page.tsx
1. Normal Route

URL:

/products

Folder structure:

app/ └── products/ └── page.tsx

page.tsx:

app/products/page.tsx
export default function Products() {
  return <h1>Products Page</h1>;
}
app/products/page.tsx
↓
/products
2. Dynamic Route ⭐

Used when part of the URL changes.

URLs:

/products/101 /products/102 /products/103

Folder structure:

app/ └── products/ └── [id]/ └── page.tsx

page.tsx:

app/products/[id]/page.tsx
export default async function Product({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;

  return <h1>Product ID: {id}</h1>;
}

Now:

URLid
/products/101"101"
/products/102"102"
/products/103"103"

Key difference:

Normal

products/page.tsx → /products

Dynamic

products/[id]/page.tsx → /products/101, /products/102, /products/103

  • [id] means dynamic value from the URL.
Slug in Next.js

What is a slug?

A slug is a dynamic value used in the URL, usually a readable name instead of an ID.

For example:

/products/iphone-15 /products/macbook-pro /products/samsung-s24

Here, iphone-15, macbook-pro, and samsung-s24 are slugs.

Folder structure & page.tsx

app/ └── products/ └── [slug]/ └── page.tsx

[slug] means the URL value is dynamic.

app/products/[slug]/page.tsx
export default async function Product({
  params,
}: {
  params: Promise<{ slug: string }>;
}) {
  const { slug } = await params;

  return <h1>Product: {slug}</h1>;
}
URLslug
/products/iphone-15"iphone-15"
/products/macbook-pro"macbook-pro"
[id] vs [slug]

Both are dynamic routes. The difference is what the value represents.

/products/[id]

Example: /products/101 — usually identifies a record by ID.

/products/[slug]

Example: /products/iphone-15 — usually identifies a resource using a human-readable URL name.

⚠️ Important: slug is not a special Next.js keyword. You could name it [productName], [username], [anything]. The name simply becomes the parameter name.
