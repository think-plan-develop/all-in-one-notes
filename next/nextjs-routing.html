📁 1. File-Based Routing Basics
Folder Structure Mapping to Route URL Paths
Folders inside the app/ directory define URL path routes. A route is made public only by placing a page.js inside the path folder.

Directory Blueprint

Folder Tree 
app/
├── page.js          // Maps to: /
├── about/
│   └── page.js      // Maps to: /about
└── contact/
    └── page.js      // Maps to: /contact

Component Code Examples

app/page.js 
export default function HomePage() {
  return <h1>Home Page</h1>;
}
app/about/page.js 
export default function AboutPage() {
  return <h1>About Page</h1>;
}
app/contact/page.js 
export default function ContactPage() {
  return <h1>Contact Page</h1>;
}
🏷️ 2. Dynamic Routes [id]
Extracting Path variables using brackets
Brackets ([id]) create dynamic route parameters. You extract the value by referencing the property on the awaited params object.

Directory Blueprint

Folder Tree 
app/
└── products/
    └── [id]/
        └── page.js  // Maps to: /products/:id

Component Code

app/products/[id]/page.js 
export default async function ProductDetails({ params }) {
  const { id } = await params; // Resolve params dynamically

  return (
    <>
      <h1>Product Details</h1>
      <p>Product ID : {id}</p>
    </>
  );
}

Sample Resolutions

Visited URL Parsed id Parameter Rendered Content
/products/1 "1" Product ID : 1
/products/20 "20" Product ID : 20
/products/abc "abc" Product ID : abc
📚 3. Catch-All & Optional Catch-All Routes
Parsing Nested Route Segments with slug Arrays
[...slug] matches all nested layers below its parent, returning them in an array. [[...slug]] does the same, but *also* matches the parent root layout path when no child segment parameters exist.

Directory Blueprint

Folder Tree 
app/
└── docs/
    ├── [...slug]/             // Catch-All
    │   └── page.js
    └── [[...optionalSlug]]/   // Optional Catch-All (Covers /docs baseline too)
        └── page.js

Catch-All Component Implementation

app/docs/[...slug]/page.js 
export default async function Docs({ params }) {
  const { slug } = await params;

  return (
    <>
      <h2>Documentation</h2>
      <p>{JSON.stringify(slug)}</p>
    </>
  );
}

Optional Catch-All Component Implementation

app/docs/[[...slug]]/page.js 
export default async function DocsOptional({ params }) {
  const { slug } = await params;

  if (!slug) {
    return <h1>Documentation Home</h1>;
  }

  return (
    <>
      <h2>Documentation Page</h2>
      <p>{JSON.stringify(slug)}</p>
    </>
  );
}

Resolution Rules

Routing Method Visited URL Resulting slug Parameter Array
Catch-all [...slug] /docs/react ["react"]
Catch-all [...slug] /docs/react/hooks/useState ["react", "hooks", "useState"]
Optional Catch-all [[...slug]] /docs undefined (falls back to Documentation Home)
🔒 4. Folder Structure Control (Groups & Private)
Route Groups (group) & Private Folders _folder

You can group folders with parentheses to keep structures organized without appending those folder names directly to public-facing routes. Prefixing folder names with an underscore declares them private, preventing them from matching routes entirely.

Directory Blueprint

Folder Tree 
app/
├── (marketing)/       // Route Group (omitted from dynamic routing)
│   ├── about/
│   │   └── page.js    // Resolves: /about
│   └── pricing/
│       └── page.js    // Resolves: /pricing
├── _components/       // Private Folder (completely skipped by routing system)
│   ├── Navbar.jsx
│   └── Footer.jsx
└── page.js

Private Utility Usage Code

app/page.js 
import Navbar from "./_components/Navbar";

export default function Home() {
  return (
    <>
      <Navbar />
      <h1>Home</h1>
    </>
  );
}
Key Takeaway: Attempting to navigate to /marketing/about or /_components will return a 404 Route Not Found error.
🔀 5. Advanced Layout Patterns
Parallel Slots (@slot) & Intercepted Segments ((.))
Parallel routing streams independent dynamic views inside a single combined layout. Intercepting routes capture local page navigation to load dynamic templates inside modal containers while keeping URLs stable for users.

Parallel Routing Setup

Folder Tree 
app/
└── dashboard/
    ├── layout.js
    ├── page.js
    ├── @analytics/
    │   └── page.js
    └── @notification/
        └── page.js
app/dashboard/layout.js 
export default function DashboardLayout({ children, analytics, notification }) {
  return (
    <>
      <header>Dashboard Header</header>
      <div style={{ display: "flex", gap: "20px" }}>
        <div>{analytics}</div>
        <div>{children}</div>
        <div>{notification}</div>
      </div>
    </>
  );
}

Intercepting Sibling Route Layout

Folder Tree (Intercepting) 
app/
├── feed/
│   ├── page.js
│   └── (.)photo/          // Intercepts /photo/:id sibling route on client click
│       └── [id]/
│           └── page.js
└── photo/
    └── [id]/
        └── page.js        // Full direct page reload fallback
app/feed/(.)photo/[id]/page.js 
export default async function PhotoModal({ params }) {
  const { id } = await params;
  return (
    <div className="modal">
      Photo Preview {id}
    </div>
  );
}
📐 6. Nested Routing & Layouts
Preserving Component Layouts State Globally

A nested layout template wraps around dynamic page views. As you navigate between sibling routes (like users to settings), only the page child view swap is executed. The parent wrapper component remains intact, preserving structural layout state and visual focus.

Directory Blueprint

Folder Tree 
app/
└── dashboard/
    ├── layout.js
    ├── page.js
    ├── users/
    │   └── page.js
    └── settings/
        └── page.js

Layout Shell Code

app/dashboard/layout.js 
export default function DashboardLayout({ children }) {
  return (
    <>
      <aside>Sidebar</aside>
      <main>{children}</main>
    </>
  );
}
When navigating from /dashboard/users to /dashboard/settings, only the content inside the <main> element updates. The sidebar's state, scroll position, and inputs are preserved because DashboardLayout does not re-render.
