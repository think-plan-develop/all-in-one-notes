Overview

Definition

A global object (no require() needed) that gives access to information about, and control over, the currently running Node.js process.

Interview Definition: process is a built-in global object in Node.js that provides information about, and control over, the current process — environment variables, command-line arguments, working directory, and the ability to terminate execution.
process.exit() vs return

The Key Difference

That's a very common interview question. The key difference is return exits a function, while process.exit() exits the entire Node.js process.

Using return

return-example.js
function startApp() {
    if (!fs.existsSync("config.json")) {
        console.log("Configuration file not found");
        return;
    }

    console.log("Application Started");
}

startApp();

console.log("Program End");
Output
Configuration file not found
Program End

What happened?

  • return exited only startApp().
  • The Node.js process continued.
  • Remaining code still executed.

Using process.exit()

exit-example.js
if (!fs.existsSync("config.json")) {
    console.log("Configuration file not found");
    process.exit(1);
}

console.log("Application Started");

console.log("Program End");
Output
Configuration file not found

The entire Node.js process stops.

  • "Application Started" is never printed.
  • "Program End" is never printed.
  • Any remaining code is skipped.

Real-World Example

Imagine your server requires a database connection before starting.

server-start.js
connectToDatabase()
    .then(() => {
        app.listen(3000);
    })
    .catch(() => {
        console.log("Database connection failed");
        process.exit(1);
    });

If the database isn't available:

  • There is no point in keeping the application running.
  • process.exit(1) terminates the process, allowing tools like Docker, PM2, or Kubernetes to detect the failure and potentially restart it.

Why Not Just Use return?

Suppose your application looks like this:

init-return.js
function init() {
    if (!fs.existsSync("config.json")) {
        console.log("Missing config");
        return;
    }
}

init();

setInterval(() => {
    console.log("Server is running...");
}, 1000);
Output
Missing config
Server is running...
Server is running...
Server is running...

Even though initialization failed, the process is still alive because return only exited init().

Using process.exit(1) instead:

init-exit.js
function init() {
    if (!fs.existsSync("config.json")) {
        console.log("Missing config");
        process.exit(1);
    }
}

init();

setInterval(() => {
    console.log("Server is running...");
}, 1000);
Output
Missing config

The process ends immediately.

When to Use Each

Use return when:

  • You only want to stop the current function.
  • The rest of the application should continue.

Use process.exit() when:

  • A fatal error occurs (missing configuration, database connection failure, invalid startup state).
  • The application cannot continue safely.
  • You intentionally want to terminate the entire Node.js process.
Interview Answer (30 seconds): return only exits the current function, so the Node.js process continues running and other code may still execute. process.exit() terminates the entire Node.js process immediately. It's typically used for unrecoverable startup errors, such as missing configuration files or failed database connections, where continuing to run the application doesn't make sense.
process.env

What is it?

process.env is an object containing all environment variables. Environment variables store configuration values like a database URL, API keys, JWT secret, or port number.

Interview Definition: process.env provides access to environment variables, allowing applications to store configuration outside the source code.

Basic Usage

env-basic.js
console.log(process.env.NODE_ENV);    // "development" / "production"
console.log(process.env.PORT);        // "3000" (or undefined if not set)
console.log(process.env.DB_PASSWORD); // your secret, loaded from .env
Use case: store API keys, database URLs, port numbers — usually loaded via a .env file with the dotenv package.

Logging the whole object returns something like:

process.env
{
  PATH: "...",
  HOME: "...",
  PORT: "5000"
}

Using a .env File

.env
PORT=5000
DB_URL=mongodb://localhost
JWT_SECRET=mysecret
index.js
import "dotenv/config";

console.log(process.env.PORT);
console.log(process.env.DB_URL);
Output
5000
mongodb://localhost

Why Use Environment Variables?

❌ Hardcoding: const password = "mypassword";
✅ Better: const password = process.env.DB_PASSWORD;
process.argv

Simple Explanation

process.argv is an array that stores the values passed to a Node.js program from the command line.

When you run:

terminal
node app.js Shivam 25

Node automatically creates this array:

argv.js
[
  "path/to/node",   // process.argv[0]
  "path/to/app.js", // process.argv[1]
  "Shivam",         // process.argv[2]
  "25"              // process.argv[3]
]
  • process.argv[0] → Path of the Node.js executable.
  • process.argv[1] → Path of the JavaScript file being executed.
  • process.argv[2] onwards → Arguments provided by the user.
This allows your program to accept input at runtime without changing the code.

Quick Summary

Command:

terminal
node app.js Shivam 25
process.argv [0] node executable [1] app.js [2] Shivam [3] 25
Remember: Your own command-line arguments always begin at process.argv[2].
process.cwd()

What is it?

Returns the Current Working Directory (CWD). It tells you from which folder the Node.js process was started, not necessarily where the current file is located.

Interview Definition: process.cwd() returns the absolute path of the current working directory from which the Node.js process was executed.

Example

Project structure:

project/ │ ├── app.js └── data.txt
app.js
console.log(process.cwd());
Output
C:\Users\Shivam\project

cwd() vs __dirname

Suppose:

project/ │ ├── app.js └── src/ └── index.js

Run:

terminal
node src/index.js

Inside index.js:

index.js
console.log(process.cwd());
// "project"

console.log(__dirname);
// "project/src"

Interview Questions
💡 Interview Q&A
What's the difference between return and process.exit()?
return only exits the current function, so the Node.js process continues running and other code may still execute. process.exit() terminates the entire Node.js process immediately — used for unrecoverable startup errors like a missing config file or a failed database connection.
What status codes does process.exit() accept?
0 indicates success, while any non-zero value (commonly 1) indicates an error. Tools like Docker, PM2, or Kubernetes read this exit code to decide whether to restart the process.
What is process.env used for?
It's an object containing all environment variables, used to store configuration like database URLs, API keys, and secrets outside the source code — typically loaded from a .env file via the dotenv package.
Why are the first two elements of process.argv reserved?
Because Node.js automatically includes process.argv[0] (the path to the Node.js executable) and process.argv[1] (the path to the script being executed). Your own custom arguments always start from process.argv[2].
Why is process.argv useful?
It lets you pass input to your program at runtime without modifying the source code, making scripts flexible, reusable, and ideal for building CLI (Command Line Interface) applications.
What's the difference between process.cwd() and __dirname?
process.cwd() returns the directory from which the Node.js process was started, while __dirname returns the directory of the current JavaScript file. They can differ if you run the application from a different location or from inside nested folders.
