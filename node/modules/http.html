http Module
🌐

What it does

Lets Node.js act as a web server (receive requests, send responses) or a client (make requests to other servers) — without any framework like Express.

Interview Definition: The http module is a built-in Node.js module used to create HTTP servers and clients, handling raw requests and responses without any external framework.
🧰

Core Methods & Properties

MethodOne-Line Explanation
http.createServer()Creates an HTTP server.
server.listen()Starts listening for requests on a port.
res.writeHead(status, headers)Sets the status code and headers together in a single call.
res.setHeader()Sets a single HTTP response header (can be called multiple times).
res.write()Writes a chunk of data to the response.
res.end()Ends the response and sends it to the client.
req.urlGets the requested URL.
req.methodGets the HTTP request method (GET, POST, etc.).
req.headersObject of incoming headers — Node lowercases all header names.
Why do we need the http module? It allows Node.js to communicate over the web — create a web server, handle client requests, send responses, and build APIs (before Express).
1️⃣

Creating a Basic Server

server.js
const http = require("http");

const server = http.createServer((req, res) => {
  res.writeHead(200, { "Content-Type": "text/plain" });
  res.end("Hello World");
});

server.listen(3000, () => {
  console.log("Server running on port 3000");
});
Use case: this is the foundation every Node backend framework (Express, Koa, etc.) is built on top of.

Alternative Form

http.createServer()'s callback is just a shortcut for attaching a listener to the server's "request" event. These are equivalent:

alternative.js
const server = http.createServer();

server.on("request", (req, res) => {
  res.end("Hello World");
});

res.writeHead() vs res.setHeader()

  • res.writeHead(statusCode, headersObject) — sets the status code and one or more headers in a single call. Must be called before any res.write().
  • res.setHeader(name, value) — sets a single header at a time; can be called multiple times before the response is sent. Pair it with res.statusCode = 200 if you're not using writeHead().
📥

The req Object (Incoming Request)

request.js
const server = http.createServer((req, res) => {
  console.log(req.method);   // "GET", "POST", etc.
  console.log(req.url);      // "/users?id=5"
  console.log(req.headers);  // { host: '...', 'user-agent': '...' }

  res.end("Received");
});
Use case: read method/URL to route requests, read headers for auth tokens, content-type, etc.
⚠️ Gotcha: Node.js automatically lowercases all incoming header names. A client sending Content-Type: application/json is read as req.headers['content-type'], not req.headers['Content-Type'].
📤

The res Object (Outgoing Response)

response.js
const server = http.createServer((req, res) => {
  res.statusCode = 200;
  res.setHeader("Content-Type", "application/json");
  res.end(JSON.stringify({ message: "Hello" }));
});
Use case: set status codes, headers, and send back data (text, JSON, HTML).
🧭

Basic Routing (Manual, No Framework)

routing.js
const server = http.createServer((req, res) => {
  if (req.url === "/" && req.method === "GET") {
    res.end("Home Page");
  } else if (req.url === "/about") {
    res.end("About Page");
  } else {
    res.statusCode = 404;
    res.end("Not Found");
  }
});
Use case: shows why Express exists — this gets messy fast, so frameworks handle routing for you.
📨

Reading POST Data (Request Body)

Request bodies arrive as a stream of Buffer chunks — you have to collect them manually.

post-body.js
const server = http.createServer((req, res) => {
  if (req.method === "POST") {
    let body = "";

    req.on("data", (chunk) => {
      body += chunk.toString();
    });

    req.on("end", () => {
      console.log("Body:", body);
      res.end("Data received");
    });
  }
});
Use case: this is exactly what express.json() does behind the scenes.
📡

Making HTTP Requests (Client Side)

GET Request

client.js
const http = require("http");

http.get("http://example.com", (res) => {
  let data = "";

  res.on("data", (chunk) => {
    data += chunk;
  });

  res.on("end", () => {
    console.log(data);
  });
});
Use case: fetch data from another API/server without external libraries like axios.

POST Request

http.get() only handles GET requests. For POST (or any other method), use http.request() and write the body yourself:

client-post.js
const http = require("http");

const postData = JSON.stringify({ name: "Shivam" });

const options = {
  hostname: "example.com",
  path: "/users",
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Content-Length": Buffer.byteLength(postData),
  },
};

const req = http.request(options, (res) => {
  let data = "";
  res.on("data", (chunk) => (data += chunk));
  res.on("end", () => console.log(data));
});

req.on("error", (err) => console.error(err));

req.write(postData);
req.end();
Use case: send data to another API/server (e.g. form submissions, webhooks) without axios.

The https Module

The https module has an identical API to http — same createServer(), req, res — but requires an SSL/TLS certificate and key to run.

https-server.js
const https = require("https");
const fs = require("fs");

const options = {
  key: fs.readFileSync("key.pem"),
  cert: fs.readFileSync("cert.pem"),
};

https.createServer(options, (req, res) => {
  res.end("Secure Hello World");
}).listen(443);
💡 Use case: serving traffic over SSL/TLS (HTTPS) directly from Node, without a reverse proxy handling encryption.
Interview Questions
💡 Interview Q&A
Why do we need the http module?
It allows Node.js to communicate over the web — create a web server, handle client requests, send responses, and build APIs (before Express existed as an abstraction on top of it).
Why do we need the http module if Express exists?
Express is built directly on top of http — it just adds routing, middleware, and body parsing. Understanding raw http shows you what's actually happening under the hood, and lets you build a server or API without any framework at all.
How do you read a POST request body in raw Node.js?
Since req is a Readable stream, you listen for "data" events to accumulate Buffer chunks into a string, then listen for the "end" event to know the full body has arrived — this is exactly what express.json() automates.
What's the difference between res.write() and res.end()?
res.write() sends a chunk of data and can be called multiple times since res is a Writable stream. res.end() sends the final chunk (optional) and signals that the response is complete — it must always be called or the client hangs waiting for more data.
How do you make an outgoing HTTP request from a Node.js server?
Use http.get(url, callback) for GET requests, or http.request(options, callback) for POST/PUT/DELETE — writing the request body with req.write() and finishing with req.end(). Collect the response body via the "data" and "end" events on the returned response stream.
Why does manual routing with the http module get messy?
Because every route requires checking req.method and req.url manually with a chain of if...else statements. As routes grow, this becomes hard to read and maintain — which is exactly the problem frameworks like Express solve with clean route definitions like app.get() and app.post().
Create an HTTP server that handles both GET and POST requests.
Check req.method to branch logic. For GET, respond immediately. For POST, collect the body via the "data"/"end" events (since req is a stream) before responding.
get-post-server.js
const http = require("http");

const server = http.createServer((req, res) => {
  // Handle GET request
  if (req.method === "GET" && req.url === "/") {
    res.writeHead(200, { "Content-Type": "text/plain" });
    res.end("GET request received — Home Page");

  // Handle POST request
  } else if (req.method === "POST" && req.url === "/users") {
    let body = "";

    req.on("data", (chunk) => {
      body += chunk.toString();
    });

    req.on("end", () => {
      let parsedData;
      try {
        parsedData = JSON.parse(body);
      } catch (err) {
        res.writeHead(400, { "Content-Type": "application/json" });
        return res.end(JSON.stringify({ error: "Invalid JSON" }));
      }

      res.writeHead(201, { "Content-Type": "application/json" });
      res.end(JSON.stringify({
        message: "User created",
        data: parsedData,
      }));
    });

  // Fallback for unknown routes
  } else {
    res.writeHead(404, { "Content-Type": "text/plain" });
    res.end("Not Found");
  }
});

server.listen(3000, () => {
  console.log("Server running on http://localhost:3000");
});

Testing it:

terminal
# GET request
curl http://localhost:3000/

# POST request
curl -X POST http://localhost:3000/users \
  -H "Content-Type: application/json" \
  -d '{"name":"Shivam","age":25}'

Expected POST output:

{ "message": "User created", "data": { "name": "Shivam", "age": 25 } }
⚡ Interview talking point: Notice GET is handled synchronously in one step, while POST requires an asynchronous two-step flow ("data" → "end") because the body arrives as a stream. This asymmetry — and having to hand-roll JSON parsing and routing — is precisely why frameworks like Express exist.
