What is a Buffer?

Definition

A Buffer is a built-in Node.js object used to store and manipulate raw binary data (bytes). JavaScript normally works with strings and objects, but files, network communication, streams, images, videos, and encrypted data are all stored as binary data. Buffer allows Node.js to work with this binary data efficiently.

buffer-basic.js
const buffer = Buffer.from("Hello");

console.log(buffer);
// <Buffer 48 65 6c 6c 6f>

console.log(buffer.toString());
// Hello

Why Do We Need Buffer?

Node.js frequently works with:

  • Files (fs)
  • Network requests (http, tcp)
  • Streams
  • Images, videos, PDFs
  • Encryption (crypto)
💡 All of these deal with raw bytes, not JavaScript strings. Buffer provides a temporary memory area to store these bytes without modifying them.

Common Buffer Methods

MethodPurpose
Buffer.from(data)Creates a buffer from a string, array, or another buffer
Buffer.alloc(size)Creates a buffer of a fixed size filled with zeros
Buffer.isBuffer(obj)Checks whether a value is a Buffer instance
Buffer.byteLength(string, encoding)Returns the byte length of a string under a given encoding — not the same as string.length for non-ASCII text
buffer.toString()Converts the buffer back into a string
buffer.write(string)Writes a string into an existing buffer at a given offset
buffer.lengthReturns the size of the buffer in bytes
⚠️ Deprecated & unsafe: new Buffer(string) / new Buffer(size) still work in older code but are deprecated and considered a security risk — new Buffer(size) behaved like allocUnsafe() without warning, and interviewers may ask why. Always use Buffer.from() or Buffer.alloc() instead.

Why Buffer.byteLength() Matters

string.length counts characters, not bytes — for multi-byte UTF-8 characters (emoji, accented letters, non-Latin scripts) these differ. This trips people up when manually setting a Content-Length header.

byte-length.js
const str = "héllo";

console.log(str.length);                 // 5 (characters)
console.log(Buffer.byteLength(str));      // 6 (bytes — 'é' takes 2 bytes in UTF-8)
💡 Use Case: Always use Buffer.byteLength(), not .length, when setting Content-Length in raw http responses.
Why Node Uses Buffer When Reading Files

Files Are Read as Raw Bytes by Default

read-image.js
const fs = require("fs");

fs.readFile("image.png", (err, data) => {
    console.log(Buffer.isBuffer(data)); // true
});

data is returned as a Buffer, not a string.

Why?

A file on disk is stored as raw bytes. Node.js doesn't know whether those bytes represent text, an image, a video, a PDF, or encrypted data.

✅ So, by default, it returns the bytes exactly as they are inside a Buffer, preventing any corruption of binary data.

Suppose an image begins with these bytes:

89 50 4E 47 0D 0A 1A 0A

Node.js returns:

Output
<Buffer 89 50 4e 47 0d 0a 1a 0a>
💡 These are the exact bytes stored in the file.
What Does Encoding Do?

Definition

An encoding tells Node.js how to convert a Buffer (raw bytes) into readable text.

Without Encoding

no-encoding.js
const fs = require("fs");

fs.readFile("text.txt", (err, data) => {
    console.log(data);
});
⚠️ Output: <Buffer 48 65 6c 6c 6f> — Node.js returns the raw bytes inside a Buffer.

With UTF-8 Encoding

with-encoding.js
const fs = require("fs");

fs.readFile("text.txt", "utf8", (err, data) => {
    console.log(data);
});
✅ Output: Hello — Node.js automatically decodes the Buffer into a JavaScript string using UTF-8.

What Actually Happens?

Suppose the file contains Hello. Internally, the computer stores it as bytes:

48 65 6C 6C 6F

The flow looks like this:

File │ ▼ 48 65 6C 6C 6F (Bytes) │ ├── Without Encoding │ ▼ │ <Buffer 48 65 6c 6c 6f> │ └── With "utf8" ▼ "Hello" (JavaScript String)

Why is Encoding Needed?

A computer stores everything as bytes. Encoding defines how those bytes should be interpreted as characters.

Bytes: 48 65 6C 6C 6F UTF-8 Decodes To: Hello
💡 Without an encoding, Node.js simply returns the Buffer because it cannot assume the bytes represent text.

Common Encodings

EncodingPurpose
utf8Most common encoding for text files
asciiEnglish characters only
base64Represents binary data as text
base64urlURL-safe variant of base64 (no +, /, or padding =) — used in JWTs, URLs
hexRepresents bytes as hexadecimal values
latin1 (binary)One byte per character (0–255) — legacy encoding, rarely needed today

Check if an encoding is valid with Buffer.isEncoding():

is-encoding.js
console.log(Buffer.isEncoding("utf8"));   // true
console.log(Buffer.isEncoding("utf9"));   // false
💡 Modern alternative: Outside of Node-specific APIs, the web-standard TextEncoder/TextDecoder classes (also available globally in Node) do string ↔ bytes conversion using Uint8Array instead of Buffer — useful if you want code portable to the browser.
text-encoder.js
const encoder = new TextEncoder();
const bytes = encoder.encode("Hello"); // Uint8Array
const decoder = new TextDecoder();
console.log(decoder.decode(bytes));    // "Hello"
Creating Buffers

Buffer.from() — Different Sources

Buffer.from() can build a buffer from a string, an array of byte values, another buffer, or an ArrayBuffer.

buffer-from.js
// From a string (utf8 by default)
Buffer.from("Hello");
// <Buffer 48 65 6c 6c 6f>

// From an array of byte values
Buffer.from([72, 101, 108, 108, 111]);
// <Buffer 48 65 6c 6c 6f>

// From a string with an explicit encoding
Buffer.from("SGVsbG8=", "base64");
// <Buffer 48 65 6c 6c 6f>

Buffer.alloc() vs Buffer.allocUnsafe()

Buffer.alloc(size) creates a buffer of the given size and fills it with zeros — safe, but slightly slower since it has to zero out memory first.

Buffer.allocUnsafe(size) creates a buffer of the given size without initializing the memory — faster, but the buffer may contain old, leftover data from previous memory usage until you overwrite it.

alloc.js
const safe = Buffer.alloc(10);
console.log(safe);
// <Buffer 00 00 00 00 00 00 00 00 00 00> — always zeroed

const unsafe = Buffer.allocUnsafe(10);
console.log(unsafe);
// <Buffer ?? ?? ?? ...> — may contain old memory contents
⚠️ Security note: Never send an allocUnsafe() buffer over a network or write it to disk before fully overwriting it — it can leak sensitive leftover memory from other parts of the process.
Combining & Slicing Buffers

Buffer.concat()

Joins an array of buffers into a single new buffer.

concat.js
const buf1 = Buffer.from("Hello ");
const buf2 = Buffer.from("World");

const combined = Buffer.concat([buf1, buf2]);

console.log(combined.toString());
// Hello World
💡 Use Case: Reassembling chunks of data received from a stream (e.g. an HTTP request body arriving in pieces).

buffer.subarray() / buffer.slice()

Returns a portion of a buffer. Unlike an array slice, this does not copy the data — it returns a view into the same underlying memory, so changes to the slice affect the original.

subarray.js
const buf = Buffer.from("Hello World");

const hello = buf.subarray(0, 5);
console.log(hello.toString()); // Hello

hello[0] = 74; // 'J'
console.log(buf.toString()); // Jello World — original buffer changed too!
⚠️ This is a common interview trap — buffer slices share memory with the original, they don't copy it.
Comparing Buffers

Buffer.compare() & buffer.equals()

Buffers can't be compared with === the way strings can, since two separate buffer objects are always different object references even with identical bytes.

compare.js
const a = Buffer.from("abc");
const b = Buffer.from("abc");

console.log(a === b);          // false — different object references
console.log(a.equals(b));      // true — same bytes
console.log(Buffer.compare(a, b)); // 0 — equal (like a sort comparator)
💡 Buffer.compare() returns -1, 0, or 1, making it useful for sorting an array of buffers.
More Interview Facts About Buffer

Buffer is a Subclass of Uint8Array

Node.js's Buffer class extends JavaScript's built-in Uint8Array, adding Node-specific methods like .toString(), .write(), and encoding support on top of the standard typed array behavior.

💡 This is why a Buffer can be indexed like an array (buf[0]) and iterated with a for...of loop, just like any typed array.

Buffer Length is Fixed

Once a Buffer is created, its size cannot be resized. You can overwrite the bytes it holds, but you can't grow or shrink it in place — to get a different size, you create a new buffer (often via Buffer.concat()).

JSON.stringify() on a Buffer

When you serialize a Buffer to JSON (e.g. sending it in an API response), it doesn't become a string — it becomes an object with a type and a data array of byte values.

json-stringify.js
const buf = Buffer.from("Hi");

console.log(JSON.stringify(buf));
// {"type":"Buffer","data":[72,105]}
⚠️ A common bug: accidentally sending a raw Buffer in a JSON API response instead of calling .toString() first — the client receives this {type, data} shape instead of readable text.

Complete Flow — From File on Disk to JavaScript String

File on Disk │ ▼ Raw Binary Data (Bytes) │ fs.readFile("file.txt") │ ▼ Returns Buffer by Default │ <Buffer 48 65 6c 6c 6f> │ If "utf8" Encoding is Provided │ ▼ Decode Buffer Using UTF-8 │ ▼ JavaScript String ("Hello")

How Do Buffers Relate to Streams?

Node's Readable and Writable streams (used by fs, http, net, etc.) emit and accept data as Buffer chunks by default. When you listen to a stream's "data" event without setting an encoding, each chunk arrives as a Buffer — which is why patterns like req.on("data", chunk => body += chunk) implicitly call Buffer.prototype.toString() during the string concatenation. Buffer.concat() is the standard way to reassemble multiple chunks into one buffer once a stream ends.

Bottom Line

Bottom line: Buffer exists because not everything Node.js handles is text — files, streams, and network data are raw bytes first. Encoding is the bridge that turns those bytes into readable strings only when you explicitly ask for it, keeping binary data safe from corruption by default.
Interview Questions
💡 Interview Q&A
What is a Buffer?
A Buffer is a built-in Node.js object used to store and manipulate raw binary data (bytes). It is commonly used while working with files, streams, network communication, and binary data.
Why does Node.js use Buffer?
Node.js uses Buffer because files, streams, and network data are handled as raw bytes. Returning a Buffer preserves the exact binary data without corruption and allows efficient processing.
What is Encoding?
Encoding tells Node.js how to convert a Buffer (raw bytes) into readable text. Without an encoding, Node.js returns a Buffer. With an encoding such as utf8, it returns a JavaScript string.
If you read the same file twice — once without encoding and once with "utf8" — what changes?
The underlying bytes on disk never change — only what Node.js hands back to your callback changes. Without an encoding you get the raw Buffer object; with "utf8" you get those same bytes decoded into a plain JavaScript string.

fs.readFile("text.txt", cb) → <Buffer 48 65 6c 6c 6f>
fs.readFile("text.txt", "utf8", cb) → "Hello"
Why can't Node.js just always decode file contents into a string automatically?
Because not every file is text. Images, videos, PDFs, and encrypted data are binary — forcing a text decoding on them would corrupt the data (bytes that don't map to valid UTF-8 characters would be mangled or lost). Returning a Buffer by default keeps the data intact regardless of what type of file it is; you opt in to decoding only when you know the content is text.
What's the difference between Buffer.alloc() and Buffer.allocUnsafe()?
Buffer.alloc(size) zero-fills the memory before handing it to you, so it's always safe and predictable. Buffer.allocUnsafe(size) skips that zeroing step for speed, which means the buffer may contain leftover data from previous memory usage until you overwrite every byte — never expose an unsafe buffer externally before fully writing to it.
If you slice a Buffer with .subarray(), and then modify the slice, does the original change?
Yes — this is a classic interview trap. subarray()/slice() returns a view into the same underlying memory rather than a copy, so writing to the sliced buffer also changes the original buffer's bytes at that position.
Can you compare two Buffers with ===?
No. === compares object references, and two separately created buffers are always different objects even with identical byte contents. Use buffer.equals(otherBuffer) for a boolean equality check, or Buffer.compare(a, b) if you need an ordering result (-1, 0, 1) for sorting.
Is Buffer related to Uint8Array?
Yes — Node's Buffer class is a subclass of JavaScript's standard Uint8Array. It inherits typed-array behavior (indexing, iteration, fixed length) and adds Node-specific conveniences on top, like .toString(encoding) and built-in support for encodings such as utf8, base64, and hex.
What's the difference between string.length and Buffer.byteLength(string)?
string.length counts JavaScript characters (UTF-16 code units), while Buffer.byteLength() counts the actual bytes the string would occupy once encoded (UTF-8 by default). They're identical for plain ASCII text but diverge for emoji, accented characters, or non-Latin scripts, where a single character can take 2–4 bytes. This matters when manually setting a Content-Length header in raw http responses.
Why shouldn't you use new Buffer()?
new Buffer(string) and new Buffer(size) are deprecated. The size-based form behaved like Buffer.allocUnsafe() without any indication that the memory wasn't zeroed — a real security foot-gun if that buffer was ever exposed before being fully overwritten. Modern code should always use Buffer.from() (from existing data) or Buffer.alloc() (for a new zeroed buffer) instead.
How do Buffers relate to Streams?
Node's Readable and Writable streams (used by fs, http, net, etc.) emit and accept data as Buffer chunks by default. When you listen to a stream's "data" event without setting an encoding, each chunk arrives as a Buffer. Buffer.concat() is the standard way to reassemble multiple chunks into one buffer once a stream ends.
