What is the events Module?

Definition

The events module is a built-in Node.js module used to create and handle custom events. It follows the Event-Driven Architecture: an event is emitted, and one or more listeners respond to it.

Node.js relies on this module internally in many core APIs — Streams, HTTP servers, the File System, and process events all emit and listen to events under the hood.

import.js
const EventEmitter = require("events"); // focus on the name: "events"

const emitter = new EventEmitter();
Event Flow

How an Event Travels

Every custom event in Node.js follows the same simple lifecycle, regardless of how many listeners are attached.

EventEmitter │ ▼ emit("event") │ ▼ on("event", callback) │ ▼ Execute callback
💡 Key idea: Listeners must be registered with .on() before .emit() is called, or they'll miss that emission — EventEmitter doesn't queue past events for late listeners.
Core Methods

Quick Summary

MethodPurpose
.on(event, fn)Listen for an event (runs every time it fires)
.emit(event, data)Trigger an event, optionally passing data
.once(event, fn)Listen only for the first occurrence
.off(event, fn) / .removeListener()Stop listening
extends EventEmitterBuild custom classes that emit their own events

1. on()

Registers a listener that runs every time the named event is emitted.

on.js
const EventEmitter = require("events");

const emitter = new EventEmitter();

emitter.on("login", () => {
  console.log("User logged in");
});
💡 Use Case: Recurring notifications — request logging, connection events, repeated user actions.

2. emit()

Triggers an event, calling every listener registered for it, in the order they were added.

emit.js
emitter.emit("login");

// Output: User logged in

3. Passing Data

Any extra arguments given to .emit() are forwarded straight to the listener's callback.

pass-data.js
emitter.on("order", (id, amount) => {
  console.log(id, amount);
});

emitter.emit("order", 101, 500);

// Output: 101 500
💡 Use Case: Pass IDs, payloads, or metadata (e.g. order ID + amount) along with the event.

4. once()

Registers a listener that fires only the first time the event occurs, then automatically removes itself.

once.js
emitter.once("start", () => {
  console.log("Started");
});

emitter.emit("start");
emitter.emit("start");

// Output: Started   (only once — the second emit is ignored)
💡 Use Case: One-time setup events like "start", first-connection handshakes, initialization logic.

5. off() / removeListener()

Removes one specific listener from an event. Requires a reference to the original named function (not an anonymous inline one).

off.js
function login() {
  console.log("User logged in");
}

emitter.on("login", login);

emitter.off("login", login);
// "login" listener is now removed

6. removeAllListeners()

Removes every listener registered for an event (or all events, if called without an argument).

remove-all.js
emitter.removeAllListeners("login");
⚠️ Watch out: Forgetting to remove listeners you no longer need is a common source of memory leaks in long-running Node processes.

Putting It All Together

on · emit · once

A single file combining events, path, and os to show how these built-in modules are typically used side by side.

app.js
import event from "events";
import path from "path";
import os from "os";

const res = path.join("image", "ddd", "dkdkdk");
console.log("res", res);

console.log(os.networkInterfaces());

const emitter = new event();

emitter.on("message", () => {
  console.log("register an event");
});

emitter.emit("message");

emitter.once("login", (id, name) => {
  console.log("use with id:" + id + "name" + name + "login successfully");
});

emitter.emit("login", 4, "shivam");
emitter.emit("login", 5, "hello"); // ignored — once() already fired
⚡ Interview Tip: The second emit("login", ...) call is silently ignored because once() auto-removes its listener after the first trigger — a classic "what's the output?" trick question.

Custom Class with extends EventEmitter

Real-World Pattern

Any class can gain event-emitting powers by extending EventEmitter — a common real-world pattern.

order-service.js
const EventEmitter = require("events");

class OrderService extends EventEmitter {
  placeOrder(id, amount) {
    // ...business logic...
    this.emit("orderPlaced", id, amount);
  }
}

const service = new OrderService();

service.on("orderPlaced", (id, amount) => {
  console.log(`Order ${id} placed for $${amount}`);
});

service.placeOrder(101, 500);
💡 Use Case: Domain services (orders, payments, uploads) that other parts of the app can subscribe to, without tight coupling.
Interview Q&A — events Module
💡 Interview Q&A
Basic Questions
What is the events module?
A built-in Node.js module used to create and handle custom events, following the Event-Driven Architecture: an event is emitted, and listeners respond to it.
How do you import and use EventEmitter?
import.js
const EventEmitter = require("events");
const emitter = new EventEmitter();
Where does Node.js use the events module internally?
In Streams, HTTP servers, the File System module, and process events — all built on top of EventEmitter.
Core Methods
What is the difference between on() and once()?
on() runs every time the event is emitted. once() runs only for the first emission, then automatically removes itself.
What does emit() do?
It triggers a named event synchronously, calling every registered listener in order and passing along any extra arguments as data.
How do you pass data with an event?
Extra arguments to .emit(event, ...args) are passed straight through to the listener's callback parameters.
How do you remove a listener?
Use emitter.off(event, listenerFn) (or the older removeListener()) with a reference to the same named function that was passed to on().
What's the difference between off() and removeAllListeners()?
off() removes one specific listener. removeAllListeners() removes every listener for an event (or all events if called with no argument).
Scenario / Tricky Questions
What happens if you emit() an event before calling on() for it?
Nothing — EventEmitter doesn't queue or replay past emissions. Any listener registered after the emit simply never sees that occurrence.
Can an anonymous function passed to on() be removed with off()?
Not directly — since off() matches by function reference, an inline anonymous callback can't be targeted. Use a named function reference if you'll need to remove it later.
How would you make a custom class emit its own events?
Have the class extend EventEmitter, then call this.emit(...) from inside its methods.
Are Node.js events synchronous or asynchronous?
Synchronous — listeners are invoked in the same tick, in registration order, before emit() returns.
