📁 The fs (File System) Module

Sync vs Async vs Promise APIs, the top 7 methods you'll actually use, file descriptors, flags, and interview questions

Definition Sync Methods Async Methods Best Practice Flags & Options Low-Level API Interview Q&A Coding Questions
📌 In short: The fs module is Node's built-in way to create, read, update, delete, rename, and copy files/directories. It ships in three flavors — Sync (blocks the Event Loop), Async/Callback, and Promise-based (fs/promises). In production request handlers, always prefer async or Promise APIs; keep Sync methods for startup scripts, CLI tools, and config loading.
🔑 Key Terms at a Glance
📁
fs module: A built-in Node.js module for creating, reading, updating, deleting, renaming, and copying files and directories.
⏸️
Sync methods: Block the Event Loop until the operation finishes — simple, but unsuitable for production servers.
🔑
File descriptor (FD): A unique integer the OS returns when a file is opened — used by low-level methods like fs.read()/fs.write().
🚩
Flags ('r', 'w', 'a', '+'): Control whether a file open is for reading, writing, appending, or both.

Synchronous Methods

Why Sync Blocks

Each operation completes before the next one starts, which is why synchronous methods block the Event Loop until they finish. This makes them simple to understand but generally unsuitable for handling file operations in production web servers.

1. readFileSync()

Reads the entire file synchronously.

read-sync.js
const fs = require("fs");

const data = fs.readFileSync("file.txt", "utf8");

console.log(data);
💡 Use Case: Load config files, read templates, load small data files at startup.

2. writeFileSync()

Creates a new file or overwrites an existing one.

write-sync.js
const fs = require("fs");

fs.writeFileSync("file.txt", "Hello World");

console.log("File created");
💡 Use Case: Generate reports, save logs, write config or output files.

3. appendFileSync()

Appends data to the end of a file.

append-sync.js
const fs = require("fs");

fs.appendFileSync("file.txt", "\nWelcome to Node.js");

console.log("Content appended");
💡 Use Case: Add log entries, append records without overwriting existing data.

4. existsSync()

Checks whether a file or directory exists.

exists-sync.js
const fs = require("fs");

const exists = fs.existsSync("file.txt");

console.log(exists);
💡 Use Case: Validate a path before reading/writing, avoid overwrite errors.

5. statSync()

Returns metadata about a file or directory.

stat-sync.js
const fs = require("fs");

const stats = fs.statSync("file.txt");

console.log(stats.isFile());
console.log(stats.isDirectory());
console.log(stats.size);
💡 Use Case: Check file size before upload, verify file vs folder type.

6. mkdirSync()

Creates a directory.

mkdir-sync.js
const fs = require("fs");

fs.mkdirSync("uploads", {
  recursive: true,
});

console.log("Folder created");
💡 Use Case: Set up upload/output folders, scaffold project directories.
Asynchronous (Promise-Based) Methods

1. readFile()

Reads the entire file asynchronously.

read-file.js
const fs = require("fs/promises");

const data = await fs.readFile("file.txt", "utf8");
console.log(data);

2. writeFile()

Creates a new file or overwrites an existing one.

write-file.js
const fs = require("fs/promises");

await fs.writeFile("file.txt", "Hello World");
console.log("File created");

3. appendFile()

Appends data to the end of a file.

append-file.js
const fs = require("fs/promises");

await fs.appendFile("file.txt", "\nWelcome Node");
console.log("Content appended");

4. access()

Checks whether a file or directory exists. There's no direct async exists() — use access() with try/catch.

access.js
const fs = require("fs/promises");

try {
  await fs.access("file.txt");
  console.log(true);
} catch {
  console.log(false);
}
💡 Output: true if it exists, false otherwise.

5. stat()

Returns metadata about a file or directory.

stat.js
const fs = require("fs/promises");

const stats = await fs.stat("file.txt");
console.log(stats.isFile());
console.log(stats.isDirectory());
console.log(stats.size);

6. mkdir()

Creates a directory.

mkdir.js
const fs = require("fs/promises");

await fs.mkdir("uploads", {
  recursive: true,
});
console.log("Folder created");

7. readdir()

Reads all files and folders inside a directory.

readdir.js
const fs = require("fs/promises");

const files = await fs.readdir("./");
console.log(files);
💡 Output: ["app.js", "file.txt", "package.json", "node_modules"]
Best Practice — Sync vs Async

Interview Tip

In production servers, always prefer async/Promise-based methods over their Sync counterparts inside request handlers — they don't block the Event Loop, so the server can keep handling other requests while I/O completes.

Wrap calls in try/catch (or .catch()) since Promise-based fs methods throw/reject on errors instead of returning error-first callbacks. Sync methods still have a place — startup scripts, CLI tools, config loading — but async is the default for anything handling concurrent traffic.

Flags & Options

recursive: true

Allows the operation to work on folders that aren't empty (or, in mkdirSync, to create nested folders that don't exist yet).

  • Without it, rmSync() on a non-empty folder throws an error.
  • Without it, mkdirSync("a/b/c") fails if a and b don't already exist.
recursive.js
// mkdir example
fs.mkdirSync("uploads/images/2026", { recursive: true });
// creates uploads, then images, then 2026 — all in one go

// rm example
fs.rmSync("uploads", { recursive: true });
// deletes uploads folder AND everything inside it (files, subfolders)

force: true (rmSync / rm only)

Tells it to not throw an error if the path doesn't exist. It just silently does nothing in that case.

force.js
fs.rmSync("uploads", { recursive: true, force: true });
// if "uploads" doesn't exist, nothing happens, no error thrown

fs.rmSync("uploads", { recursive: true });
// if "uploads" doesn't exist, this throws: ENOENT: no such file or directory

fs.open() / fs.close()

fs.open() opens a file and returns a file descriptor (FD), used to perform low-level file operations.

open.js
fs.open("file.txt", "r", callback);

fs.close() closes the opened file descriptor and releases the system resources.

close.js
fs.close(fd, callback);

fs.read() / fs.write()

fs.read() reads a specific number of bytes from an already opened file using its file descriptor.

read.js
fs.read(fd, buffer, offset, length, position, callback);

fs.write() writes data to an already opened file using its file descriptor.

write.js
fs.write(fd, "Hello World", callback);

Why should we avoid synchronous methods in production?
Because they block the event loop, preventing Node.js from handling other requests until the operation completes.
File Operations
What is the difference between readFile() and readFileSync()?
readFile() → Asynchronous, non-blocking. readFileSync() → Synchronous, blocks execution.
What is the difference between writeFile() and appendFile()?
writeFile() → Creates or overwrites a file. appendFile() → Adds data to the end of the file.
What happens if writeFile() is called on an existing file?
The existing content is overwritten.
What is existsSync() used for?
It checks whether a file or directory exists and returns true or false.
What does stat() return?
It returns a Stats object containing metadata such as file size, creation time, modification time, and whether it's a file or directory.
File Descriptors
What is a file descriptor?
A file descriptor is a unique integer returned by the operating system when a file is opened. It is used by low-level methods like fs.read() and fs.write().
Path Module
Why do we use the path module?
To create platform-independent file paths and avoid hardcoded / or \.
Difference between path.join() and path.resolve()?
join() joins path segments. resolve() returns an absolute path.

Why is 'utf8' passed to readFile()?
It tells Node.js to decode the file contents into a JavaScript string. Without it, a Buffer is returned.
