util.promisify()

promisify.js
const util = require("util");
const fs = require("fs");

const readFile = util.promisify(fs.readFile);

const data = await readFile("file.txt", "utf8");
console.log(data);

How it works internally:

internal.js
function readFile(path, encoding) {
  return new Promise((resolve, reject) => {
    fs.readFile(path, encoding, (err, data) => {
      if (err) reject(err);
      else resolve(data);
    });
  });
}
Interview answer: util.promisify() wraps a callback-style function (err, data) inside a Promise — resolve(data) on success, reject(err) on failure — allowing async/await instead of nested callbacks.

Modern alternative: for file operations specifically, you usually don't need this — Node ships a Promise-based API directly.

modern.js
import { readFile } from "fs/promises";
const data = await readFile("file.txt", "utf8");

util.callbackify()

callbackify.js
const util = require("util");

async function getData() {
  return "Hello Node.js";
}

const getDataCallback = util.callbackify(getData);

getDataCallback((err, data) => {
  if (err) return console.log(err);
  console.log(data); // "Hello Node.js"
});

How it works internally:

internal.js
function getDataCallback(callback) {
  getData()
    .then((result) => callback(null, result))
    .catch((err) => callback(err));
}
Use case: making a modern async function compatible with old callback-only code.

fs vs fs/promises vs util.promisify()

No, fs/promises is not a separate package. It's a built-in Node.js module — no installation needed — and it's the Promise-based version of the fs module.

1. fs (Callback API)

fs-callback.js
import fs from "fs";

fs.readFile("file.txt", "utf8", (err, data) => {
  console.log(data);
});
  • Uses callbacks
  • Older API

2. fs/promises (Promise API)

fs-promises.js
import { readFile } from "fs/promises";

const data = await readFile("file.txt", "utf8");
console.log(data);
  • Uses Promises
  • Works directly with async/await
  • Recommended in modern Node.js

3. util.promisify()

util-promisify.js
import fs from "fs";
import util from "util";

const readFile = util.promisify(fs.readFile);

const data = await readFile("file.txt", "utf8");
  • Converts a callback API into a Promise API
  • Mainly needed for other callback-based functions or third-party libraries that don't provide a Promise version — fs already has fs/promises, so you rarely need this specifically for file operations
ModuleBuilt-in?Uses
fs✅ YesCallback-based file operations
fs/promises✅ YesPromise-based file operations
util✅ YesUtility functions like promisify() and callbackify()
Rule of thumb: use fs/promises directly for file work. Reach for util.promisify() only when wrapping a callback-based API (often third-party) that has no native Promise version.
url Module

Anatomy of a URL

https://example.com:8080/users/profile?id=10&name=John#about │ ├── protocol → "https:" ├── hostname → "example.com" ├── port → "8080" ├── host → "example.com:8080" ├── pathname → "/users/profile" ├── search → "?id=10&name=John" ├── hash → "#about" ├── origin → "https://example.com:8080" └── href → full URL string

⭐ new URL()

new-url.js
const url = new URL("https://example.com:3000/products?id=5&category=shoes");
Creates the URL object — the starting point for everything below.

searchParams.get()

search-params.js
url.searchParams.get("id");       // "5"
url.searchParams.get("category"); // "shoes"
Reads individual query parameters. Other methods: .set(), .append(), .delete(), .has().

pathname

pathname.js
url.pathname; // "/products/shoes"
Path only — no domain, no query string. Used for routing.

protocol

protocol.js
url.protocol; // "https:"
Scheme used — check if a request is secure.

port

port.js
const url = new URL("https://example.com:8080/products");
url.port; // "8080"
Just the port number, as a string. Empty string if none specified.

Interview Questions
💡 Interview Q&A
What does util.promisify() do?
It wraps a callback-style function that follows the (err, data) pattern inside a Promise — calling resolve(data) on success and reject(err) on failure — so it can be used with async/await instead of nested callbacks.
Do you need util.promisify() for fs operations?
Usually not. Node ships a native Promise-based API at fs/promises, so you can import { readFile } from "fs/promises" directly. util.promisify() is mainly useful for other callback-based APIs — often third-party — that don't offer a Promise version.
What's the difference between promisify() and callbackify()?
They go in opposite directions. util.promisify() converts a callback-based function into one that returns a Promise. util.callbackify() does the reverse — it converts an async function into one that accepts a Node-style (err, data) callback, useful for making modern code compatible with legacy callback consumers.
Is fs/promises a separate package?
No — it's a built-in Node.js module, no installation needed. It's simply the Promise-based version of the fs module, and is the recommended way to do file operations in modern Node.js.
What is util.inspect() used for?
It's used for debugging deeply nested objects that console.log() truncates or displays poorly, producing a more complete and readable string representation.
How do you parse a URL and read its query parameters in Node.js?
Create a new URL(urlString) instance, then use its searchParams property — e.g. url.searchParams.get("id") — to read individual query parameters, or properties like pathname, protocol, and hostname for the other parts.
Difference between url.host and url.hostname?
hostname returns just the domain (e.g. example.com), while host returns the domain plus the port if one is specified (e.g. example.com:8080).
Difference between url.search and url.searchParams?
search is the raw query string as text (e.g. "?id=10&name=John"), while searchParams is a parsed, mutable object with methods like .get(), .set(), .append(), .delete(), and .has() for working with individual parameters.
What does url.origin return, and what is it used for?
It returns the protocol, hostname, and port combined (e.g. "https://example.com:3000"), without the path or query string. It's commonly used for CORS origin checks.
