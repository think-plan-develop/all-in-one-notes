04

User Schema

💡

Design note: The User schema uses embedded sub-documents for address and socialLinks (rarely queried independently), while posts uses references (ObjectId) to allow pagination and independent post queries without loading the entire user document.

TypeScript 
import mongoose from "mongoose";

const userSchema = new mongoose.Schema({

  // ── Identity ──────────────────────────────────
  firstName: {
    type: String,
    required: true,
    trim: true,
    minlength: 2,
    maxlength: 50
  },
  lastName: { type: String, required: true },

  email: {
    type: String,
    required: true,
    unique: true,
    lowercase: true           // stored as lowercase always
  },

  // ── Auth & Access ──────────────────────────────
  role: {
    type: String,
    enum: ["ADMIN", "USER", "MANAGER"],
    default: "USER"
  },
  isActive: { type: Boolean, default: true },

  // ── Profile ───────────────────────────────────
  age:        { type: Number,  min: 18, max: 100 },
  birthDate:  { type: Date },
  salary:     { type: mongoose.Schema.Types.Decimal128 },
  profileImage: { type: Buffer },    // raw binary (or use URL string)

  // ── Collections ───────────────────────────────
  skills:       [{ type: String }],
  phoneNumbers: [{ type: Number }],

  // ── Embedded Sub-Documents ────────────────────
  address: {
    city:    String,
    state:   String,
    country: String,
    zipCode: Number
  },

  socialLinks: {
    github:   String,
    linkedin: String,
    website:  String
  },

  // ── Dynamic K-V Map ───────────────────────────
  settings: { type: Map, of: String },
  // usage: user.settings.get("theme") → "dark"

  // ── References (Normalized) ───────────────────
  posts: [{
    type: mongoose.Schema.Types.ObjectId,
    ref: "Post"
  }]

}, {
  timestamps: true   // auto-adds createdAt, updatedAt
});

export const User = mongoose.model("User", userSchema);
05

Post Schema

💡

Design note: comments are embedded as sub-documents (commentSchema) because they're always fetched with the post. author and commentedBy use ObjectId references to avoid data duplication and enable population.

TypeScript 
import mongoose from "mongoose";

// ── Embedded Comment Sub-Document ──────────────
const commentSchema = new mongoose.Schema({
  message: String,
  commentedBy: {
    type: mongoose.Schema.Types.ObjectId,
    ref: "User"
  }
}, { _id: true, timestamps: true });

// ── Main Post Schema ───────────────────────────
const postSchema = new mongoose.Schema({

  title: {
    type: String,
    required: true,
    trim: true,
    maxlength: 200
  },

  description: {
    type: String,
    required: true
  },

  author: {
    type: mongoose.Schema.Types.ObjectId,
    ref: "User",
    required: true
  },

  tags:  [{ type: String, lowercase: true, trim: true }],
  likes: { type: Number, default: 0, min: 0 },

  comments: [commentSchema]   // embedded array

}, { timestamps: true });

// ── Indexes for performance ─────────────────────
postSchema.index({ author: 1, createdAt: -1 });
postSchema.index({ tags: 1 });

export const Post = mongoose.model("Post", postSchema);

Zod Validation

TypeScript 
// src/validators/user.validator.ts
import { z } from "zod";

export const createUserSchema = z.object({

  firstName:  z.string().min(2).max(50),
  lastName:   z.string().min(1),
  email:      z.string().email(),
  age:        z.number().int().min(18).max(100),
  role:       z.enum(["ADMIN", "USER", "MANAGER"]).default("USER"),
  skills:     z.array(z.string()).optional(),

  address: z.object({
    city:    z.string(),
    state:   z.string(),
    country: z.string(),
    zipCode: z.number()
  }).optional(),

  socialLinks: z.object({
    github:   z.string().url().optional(),
    linkedin: z.string().url().optional(),
    website:  z.string().url().optional()
  }).optional()

});

// Infer TypeScript type automatically from schema
export type CreateUserInput = z.infer<typeof createUserSchema>;

Validation Middleware

TypeScript 
// src/middleware/validate.ts
import { Request, Response, NextFunction } from "express";
import { ZodSchema } from "zod";

export const validate =
  (schema: ZodSchema) =>
  (req: Request, res: Response, next: NextFunction) => {

    const result = schema.safeParse(req.body);

    if (!result.success) {
      return res.status(400).json({
        success: false,
        errors:  result.error.flatten().fieldErrors
      });
    }

    req.body = result.data;   // replace with sanitised + typed data
    next();
  };

// Usage in routes:
// router.post("/", validate(createUserSchema), userController.create);
08

CRUD Operations

🔁

Request flow: Every request follows the same pipeline — Route → Validation Middleware → Controller → Service → Model → MongoDB.

Route → Validation → Controller → Service → Model → MongoDB
POST

Create Resource  POST /users

Creates a new document. Accepts full body. Returns 201 Created with the saved document.

const user = await User.create(req.body);
res.status(201).json({ success: true, data: user });
GET

Read Resources  GET /users  |  GET /users/:id

Fetch all documents or a single one by ID. Supports filtering, sorting, and pagination via query params.

// All users
const users = await User.find({ isActive: true })
  .sort({ createdAt: -1 })
  .limit(20)
  .skip(page * 20);

// Single user
const user = await User.findById(req.params.id)
  .populate("posts", "title createdAt");
PUT

Replace Resource  PUT /users/:id

Replaces the entire document. Fields not included in the body are removed (full overwrite).

const user = await User.findByIdAndUpdate(
  req.params.id,
  req.body,
  { new: true, overwrite: true, runValidators: true }
);
PATCH

Partial Update  PATCH /users/:id

Updates only the provided fields. Other fields remain unchanged. Most commonly used update method.

const user = await User.findByIdAndUpdate(
  req.params.id,
  { $set: req.body },          // $set ensures partial update
  { new: true, runValidators: true }
);
DELETE

Remove Resource  DELETE /users/:id

Permanently removes a document by ID. Returns 204 No Content on success.

await User.findByIdAndDelete(req.params.id);
res.status(204).send();

Population

🔗

What is populate? Mongoose populate() replaces an ObjectId reference with the actual referenced document at query time — similar to a SQL JOIN. Use field projection as the second argument to limit what is fetched.

TypeScript 
// ── Basic population ───────────────────────────
const post = await Post.find()
  .populate("author");

// ── Select specific fields only ────────────────
const post = await Post.findById(id)
  .populate("author", "firstName lastName email");

// ── Nested population ──────────────────────────
const post = await Post.findById(id)
  .populate({
    path: "comments.commentedBy",
    select: "firstName lastName"
  });

// ── Result shape after populate("author") ──────
// Before: { author: "6851abc123" }
// After:  { author: { firstName: "Shivam", email: "..." } }

Common Schema Options

required: true

Field must be present; throws ValidationError if missing.

unique: true

Creates a unique index in MongoDB. Not a validator — use with care on optional fields.

default: value

Fallback value when field is not provided. Accepts literals or functions.

trim: true

Strips leading/trailing whitespace from strings before saving.

lowercase / uppercase

Normalises string casing before save. Useful for emails, tags.

min / max

Numeric range validation. Throws if value is out of bounds.

minlength / maxlength

String length validation.

enum: []

Restricts value to a defined list. Perfect for roles, statuses.

validate: fn

Custom validator function. Return true to pass, false to fail.

immutable: true

Prevents field from being changed after the document is created.

select: false

Excludes field from query results by default (useful for passwords).

index: true

Creates a single-field index to speed up queries on that field.
