🟠 Old Way — ts-node + nodemon
⚠️
Archived — No Longer Recommended
ts-node-dev was archived in December 2025. ts-node hasn't been updated in 2+ years. This approach still works but should only be used on existing / legacy projects. For new projects use tsx.
📦 Install Commands
terminal 
mkdir node-ts-app
cd node-ts-app
npm init -y
npm install express
npm install -D typescript ts-node nodemon @types/node @types/express
npx tsc --init
💡 Remember: -D means devDependency — these packages are only needed during development, not in production.
📁 Project Structure
node-ts-app/ ├── src/ │ └── app.ts ← write code here ├── dist/ ← compiled JS output ├── package.json ├── tsconfig.json ← TS config └── .gitignore
⚙️ package.json Scripts
package.json 
{
  "scripts": {
    "dev":   "nodemon --exec ts-node src/app.ts",
    "build": "tsc",
    "start": "node dist/app.js"
  }
}
🔄 Dev Flow (Old Way)
npm run dev ↓ nodemon ← watches files ↓ ts-node src/app.ts ↓ App Starts ✅ ── Save a file ── ↓ nodemon detects change ↓ ts-node recompiles ↓ App Restarts
🏗️ Build Flow (Production)
src/app.ts ↓ npm run build ↓ tsc ← TypeScript compiler ↓ dist/app.js ← plain JS file ↓ npm start ↓ node dist/app.js ✅
💡 Production never uses ts-node. Always compile first then run with plain node.
🔵 New Way — tsx (2025/26 Recommended)
🚀
Recommended for All New Projects
tsx replaces both ts-node AND nodemon in a single package. Powered by esbuild — significantly faster, ESM-ready, actively maintained, and watch mode is built right in. Less config, less packages, faster restarts.
📦 Install Commands
terminal 
mkdir node-ts-app
cd node-ts-app
npm init -y
npm install express
npm install -D tsx typescript @types/node @types/express
npx tsc --init
✅ Notice: No ts-node. No nodemon. Just tsx — one package does both jobs.
📁 Project Structure
node-ts-app/ ├── src/ │ └── app.ts ← write code here ├── dist/ ← compiled JS output ├── package.json ├── tsconfig.json └── .gitignore
✅ Same structure as old way — just fewer packages installed.
⚙️ package.json Scripts
package.json 
{
  "scripts": {
    "dev":   "tsx watch src/app.ts",
    "build": "tsc",
    "start": "node dist/app.js"
  }
}
💡 Only the "dev" script changes. Build and start remain identical.
🔄 Dev Flow (New Way)
npm run dev ↓ tsx watch src/app.ts ← one command ↓ esbuild strips types ← super fast ↓ App Starts ✅ ── Save a file ── ↓ tsx detects instantly ↓ App Restarts (faster ⚡)
🏗️ Build Flow (Production)
src/app.ts ↓ npm run build ↓ tsc ← same as before ↓ dist/app.js ↓ npm start ↓ node dist/app.js ✅
✅ Production flow is exactly the same as old way.
⚡ Bonus — Node 22+ Native TypeScript
🟣 Zero Dependencies Option (Node 22+)
🎯 What is it? Node.js 22+ can strip TypeScript types natively using a built-in flag. No tsx, no ts-node, no transpiler package needed at all.
package.json 
{
  "scripts": {
    "dev":   "node --watch --experimental-strip-types src/app.ts",
    "build": "tsc",
    "start": "node dist/app.js"
  }
}
✅ Install only:
npm install -D typescript @types/node @types/express
No tsx, no nodemon needed!
⚠️ Limitation: Requires Node 22+. Still experimental. Some advanced TS syntax not supported. Best for simple projects / scripts.

💡 Why @types/* packages? Express and Node.js are written in JavaScript — they don't have built-in TypeScript types. @types/* packages are community-maintained type definitions that tell TypeScript what shape these APIs have.
🎯 Interview Questions & Answers
💬 15 Must-Know Questions
Q01 What is TypeScript?
TypeScript is a superset of JavaScript that adds static typing, interfaces, enums, generics, and compile-time error checking. It must be compiled to JavaScript before Node.js can run it — Node only understands JS.
Q02 Difference between ts-node and tsc?
tsc — TypeScript compiler. Converts .ts → .js files on disk. Used for production builds.
ts-node — Compiles TypeScript in memory and immediately runs it. No files written to disk. Used only in development.
tsc: app.ts → compile → dist/app.js (file on disk) ts-node: app.ts → compile in memory → execute (no file)
Q03 Why do we use nodemon?
Nodemon watches your files for changes and auto-restarts the app — replacing the manual stop/start cycle.

Without nodemon: change code → manually Ctrl+C → manually run again
With nodemon: change code → save → auto restarts

In the new approach, tsx watch replaces nodemon entirely.
Q04 Why is @types/node required?
TypeScript doesn't know about Node.js built-ins like process, fs, path, Buffer, or http. Without @types/node, TypeScript will throw errors saying these don't exist. This package provides the type definitions + IntelliSense for all Node.js APIs.
Q05 What does ts-node do internally?
ts-node hooks into Node's module loading system. When you run a .ts file, it intercepts the require/import, compiles it using the TypeScript compiler in memory, then passes the JavaScript to Node for execution. No files are written to disk.
app.ts → ts-node intercepts → tsc compiles in RAM → Node executes JS
Q06 What does tsx do internally?
tsx works similarly but uses esbuild instead of tsc. esbuild simply strips TypeScript type annotations — it does not type-check. This is why it's 10–100× faster. For type checking during development, run tsc --noEmit separately.
app.ts → tsx intercepts → esbuild strips types → Node executes JS (no type checking — just fast!)
Q07 What is the purpose of tsconfig.json?
Configuration file for the TypeScript compiler. Key settings:

target — which JS version to compile to (ES2020, ESNext)
module — module system (CommonJS, ESM)
rootDir — where your source .ts files are
outDir — where to put compiled .js files
strict — enable strict type checking rules
Q08 Difference between npm run dev and npm start?
npm run devnpm start
Development modeProduction mode
Uses tsx / ts-nodeUses plain node
Has file watching / auto-restartNo watcher — runs once
Runs .ts files directlyRuns compiled .js from dist/
Q09 What is rootDir and outDir in tsconfig?
rootDir: "./src" — tells TypeScript where your source .ts files live.
outDir: "./dist" — tells TypeScript where to output compiled .js files.

This ensures the folder structure is mirrored: src/app.ts → dist/app.js
Q10 Why do we generate the dist folder?
Node.js can only execute JavaScript. The dist/ folder holds the compiled JS that gets deployed to production servers. TypeScript files (.ts) never go to production — only the compiled output does.
Q11 Why can't Node.js run TypeScript directly?
Node.js is a JavaScript runtime — it only understands valid JavaScript syntax. TypeScript's type annotations are not valid JavaScript:
const age: number = 25; ← invalid JS (TypeScript) const age = 25; ← valid JS (after compilation)
The colon syntax must be removed before Node can run it. Tools like tsx/ts-node do this on the fly; tsc writes the output to disk.
Q12 What is strict mode in TypeScript?
Enabling "strict": true in tsconfig turns on a bundle of type safety rules:

• noImplicitAny — variables can't silently be any type
• strictNullChecks — null / undefined must be handled explicitly
• strictFunctionTypes — safer function parameter checking

It catches more bugs at compile time before they reach production.
Q13 What is moduleResolution?
Tells TypeScript how to find imported modules when you write import express from 'express'.

node — classic Node.js resolution (looks in node_modules)
node16 / bundler — modern ESM-aware resolution

Wrong setting causes "cannot find module" errors even when the package is installed.
Q14 Why use esModuleInterop?
Express is a CommonJS module (old format). Without esModuleInterop you must write ugly imports:
import * as express from 'express'

With "esModuleInterop": true you can write clean ES6 style:
import express from 'express'

It adds a compatibility wrapper so CJS default exports work with ES import syntax.
Q15 Explain complete Node.js + TypeScript startup flow
── DEVELOPMENT (Old) ────────────────── npm run dev → nodemon → ts-node → app.ts runs in memory ── DEVELOPMENT (New) ────────────────── npm run dev → tsx watch → esbuild strips types → runs ── PRODUCTION (Both same) ───────────── npm run build → tsc → dist/app.js created npm start → node dist/app.js
