Interview Answers

1. What is TypeScript?

TypeScript is a superset of JavaScript that adds static typing, interfaces, enums, generics, and compile-time error checking. It improves code quality and maintainability.

2. Difference between ts-node and tsc?

tsc
Compiles TypeScript into JavaScript. 
src/app.ts
   ↓
tsc
   ↓
dist/app.js
ts-node
Compiles TypeScript in memory and immediately executes it without creating JavaScript files.

3. Why do we use nodemon?

Nodemon watches files for changes and automatically restarts the application. Without nodemon: 
Change code
↓
Stop Server
↓
Start Server
With nodemon: 
Change code
↓
Save
↓
Auto Restart

4. Why is @types/node required?

TypeScript does not understand Node.js globals and built-in modules. Examples: 
process
Buffer
fs
path
http
@types/node provides type definitions, autocomplete, and IntelliSense for these APIs.

5. What does ts-node do internally?

It combines compilation and execution. 
app.ts
   ↓
ts-node
   ↓
Compile in Memory
   ↓
Execute
No JavaScript file is generated.

6. What is the purpose of tsconfig.json?

tsconfig.json is the configuration file for the TypeScript compiler. It defines:
  • Compilation target
  • Module system
  • Output directory
  • Strict mode rules
  • Included files

7. Difference between npm run dev and npm start?

npm run dev npm start
Development Production
Uses ts-node Uses node
Uses nodemon No nodemon
Runs .ts files Runs compiled .js files

8. What is rootDir and outDir?

src/
 └─ app.ts
rootDir tells TypeScript where source files exist. 
dist/
 └─ app.js
outDir tells TypeScript where compiled files should be generated.

9. Why do we generate the dist folder?

Node.js executes JavaScript, not TypeScript. The dist folder stores generated JavaScript files used in production. 
src/app.ts
     ↓
tsc
     ↓
dist/app.js

10. Explain the complete TypeScript build process.

Write TypeScript
      ↓
npm run build
      ↓
tsc
      ↓
Generate JavaScript
      ↓
dist folder
      ↓
node dist/app.js

11. Why can't Node.js run TypeScript directly?

Node.js understands JavaScript only. TypeScript syntax such as: 
const age: number = 25;
is not valid JavaScript. Therefore TypeScript must be compiled first.

12. What is strict mode in TypeScript?

Strict mode enables additional type checking. Examples:
  • No implicit any
  • Null checking
  • Undefined checking
  • Safer type inference
It helps catch bugs during development.

13. What is moduleResolution?

moduleResolution determines how TypeScript locates imported files and packages. Example: 
import express from "express";
TypeScript uses moduleResolution rules to find the express package.

14. Why use esModuleInterop?

Allows CommonJS modules to work with ES Module import syntax. Without: 
import * as express from "express";
With: 
import express from "express";
This makes imports cleaner and more readable.
