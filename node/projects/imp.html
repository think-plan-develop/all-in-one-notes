🧩 Express Middleware Essentials

express.json() · helmet() · cookie-parser() — what they do and why you use them

📦 express.json() Body Parser

Parses incoming JSON request bodies and makes them available on req.body. Without it, req.body stays empty for normal JSON requests.

Frontend sends
{ "email": "abc@gmail.com", "password": "123456" }
You access
req.body.email req.body.password
app.use(express.json());
✅

Use it because APIs commonly receive JSON data — this is what turns the raw request body into a usable JS object.

🛡️ helmet() Security Headers

Browsers support several security-related HTTP headers. Configuring each one manually is tedious — Helmet sets/configures a collection of them with sensible defaults in one call.

Headers it manages
Content-Security-Policy X-Content-Type-Options Strict-Transport-Security X-Frame-Options
app.use(helmet());
✅

Use it because it provides a basic security-hardening layer for your Express app with one line.

⚠️

It does NOT replace authentication, authorization, validation, or rate limiting.

🍪 cookie-parser() Cookie Access

Browsers can send cookies with requests. cookie-parser() parses that header and makes cookies easily available through req.cookies.

Cookie: sessionId=abc123 → req.cookies.sessionId → "abc123"
Commonly stored in cookies
session ID access token refresh token
✅

Use it because it makes reading cookies from incoming requests — key for authentication systems — convenient.

🔐 argon2 Password Hashing

Argon2id is generally the preferred choice for a new password-storage system — it won the Password Hashing Competition and is the current OWASP-recommended algorithm.

npm install argon2
Hash password
import argon2 from "argon2"; this.password = await argon2.hash(this.password);
Verify password
await argon2.verify(user.password, password);
Why it's a strong choice
🧠 Memory-hard 🛡️ GPU/ASIC resistant ⚙️ Configurable cost 🧂 Auto salt handling

Memory-hard: Argon2 deliberately uses significant memory as well as CPU, making password cracking more expensive for attackers using GPUs or specialized hardware.

Resistant to GPU/ASIC attacks: traditional fast hashes are easier to attack with highly parallel hardware — Argon2's memory requirements shrink that advantage.

Configurable cost: you can tune memory usage, number of iterations, and degree of parallelism:

const hash = await argon2.hash(password, { type: argon2.argon2id, memoryCost: 19456, timeCost: 2, parallelism: 1, });

Automatic salt handling: you don't need to manually create a salt — argon2.hash(password) handles it internally.

✅

Use it because it's the current best-practice algorithm for storing passwords securely, with sensible defaults out of the box.

✅ zod Schema Validation

Validates req.body against a schema and infers a matching TypeScript type — common mistakes below.

import { z } from "zod"; export const registerSchema = z.object({ name: z.string().trim().min(1, "Name is required").max(35), password: z.string().min(8, "Min 8 characters"), email: z.string().trim().toLowerCase().email().endsWith("@techmahindra.com"), }); export type RegisterInput = z.infer<typeof registerSchema>;
❌ Common mistakes
registerSchema(req.body) data: registerSchema z.string() // "" allowed
✅ Correct
registerSchema.parse(req.body) data: RegisterInput z.string().min(1) // "" rejected

Validation ≠ transformation: .email() only checks format. Chain .trim().toLowerCase() to actually transform the value.

parse() — throws
const data = registerSchema.parse(req.body);
safeParse() — no throw
const r = registerSchema.safeParse(req.body); if (!r.success) return r.error.issues;
✅

Use parse() with centralized error middleware (throws → converted to JSON). Use safeParse() when you want to handle success/error inline.

app.use("/auth", authRouter); app.use(errorMiddleware); // ZodError → JSON response
