1. app.js vs server.js

Separation of Concerns

★★★★★
FileResponsibility
app.jsWhat the server does — routes, middleware, business logic
server.jsThat the server runs — listening, port, startup
📌 Keeping these separate means app.js can be imported into tests without ever binding to a port.

terminal

    "module": "NodeNext",

}

4. Password Hashing — Always Use a pre Hook

Hash in the Schema

★★★★★

Never hash a password manually in the service layer — do it in the schema so it's impossible to forget:

user.model.ts
userSchema.pre("save", async function (next) {
  if (!this.isModified("password")) {
    return next();
  }
  this.password = await argon2.hash(this.password);
  next();
});
✅ isModified("password") prevents re-hashing an already-hashed password on unrelated updates (e.g. updating name).
5. Notes — Express + JWT TypeScript Gotchas

5.1 Request Type vs Request Data

★★★★★
  • req: Request → the Express request object
  • req.body → the request payload
auth.controller.ts
const data = registerSchema.parse(req.body);

5.2 req.user Needs Express Augmentation

user is not a built-in Express property. Using req.user.userId requires a custom type declaration:

types/express.d.ts
declare global {
  namespace Express {
    interface Request {
      user: {
        userId: string;
      };
    }
  }
}

5.3 jwt.verify() Type Assertion

★★★★★
auth.middleware.ts
const decoded = jwt.verify(
  token,
  process.env.JWT_SECRET!
) as JwtPayload;

decoded.userId;
⚠️ as JwtPayload is a TypeScript-only type assertion — not runtime validation. jwt.verify() guarantees the token's signature is valid, not that its payload matches JwtPayload's shape.

5.4 ! After an Environment Variable

any file
process.env.JWT_SECRET!
🚫 Tells TypeScript: "assume this exists." It does not create the env variable — it only silences the type error. If the variable is actually missing at runtime, this will fail elsewhere (e.g. jwt.verify throwing), not here.

5.5 Cookie vs Authorization Header

★★★★★

Cookie-based

middleware
const token = req.cookies.accessToken;

Bearer-based

middleware
const authHeader = req.headers.authorization;
const [scheme, token] = authHeader.split(" ");
🚫 Don't mix the two approaches in one project — pick one auth transport and use it consistently across every protected route.
