1. Mistakes to Remember — Mongoose User Schema

Common Schema Mistakes

★★★★★
1. required, not require
schema
required: true   // ✅
// ❌ require: true
2. Use maxlength for string length
schema
maxlength: 35   // ✅
// ❌ maxLength: 35
3. Add unique: true for unique email
schema
email: {
  type: String,
  required: true,
  unique: true
}
4. Schema and Model are different

Schema → defines document structure
Model → interacts with MongoDB

5. Create Schema using mongoose.Schema()
user.model.ts
const userSchema = new mongoose.Schema({...});
6. Create Model using mongoose.model()
user.model.ts
const User = mongoose.model("User", userSchema);

// ❌ Don't use: new mongoose.Model(...)
7. Use a meaningful Model name
user.model.ts
const User = mongoose.model("User", userSchema);  // ✅
// Not: const userSchema = ... for the model variable
8. timestamps: true is a Schema option
schema
{ timestamps: true }

// Automatically creates: createdAt, updatedAt
9. For email fields — use trim and lowercase
schema
email: {
  type: String,
  required: true,
  unique: true,
  trim: true,
  lowercase: true
}
10. Password should never be stored as plain text
Plain password
↓
bcrypt.hash()
↓
Hashed password
↓
MongoDB
🚫 Your biggest mistakes were: require → required, new mongoose.Model() → mongoose.model(), and forgetting unique: true for email.

Easy Pattern to Remember

mongoose.Schema()
↓
Schema definition
↓
mongoose.model()
↓
Model
↓
MongoDB operations
2. Mongoose Schema & Model — Mistakes to Remember

Capital S vs Small m

★★★★★

Schema — capital S

Schema is imported as a constructor/class.

schema
const userSchema = new Schema({
  // fields
});

model — small m

It is the function used to create a Mongoose model.

model
const User = model("User", userSchema);
user.model.ts
import { Schema, model } from "mongoose";

const userSchema = new Schema({
  // fields
});

const User = model("User", userSchema);

export default User;
3. InferSchemaType — Common Mistakes

Don't Forget typeof

★★★★

❌ Wrong

error
InferSchemaType<UserSchema>  // ❌
// Using it with a TypeScript interface

✅ Correct

ok
InferSchemaType<typeof UserSchema>  // ✅
💡 Write the model like this:
const UserModel = model<User>("User", UserSchema);
4. JWT + Cookie Authentication — Common Mistakes

14 Pitfalls to Avoid

★★★★★
1. Reading from the wrong place
middleware
req.headers.authorization  // ❌ if using cookies
req.cookies.accessToken    // ✅
2. Forgetting cookie-parser
app.ts
app.use(cookieParser());  // ✅ otherwise req.cookies is undefined
3. Forgetting to set the cookie during login
auth
res.cookie("accessToken", token);  // ✅
4. Using different cookie names
mismatch
res.cookie("token", token);      // set as "token"
req.cookies.accessToken;          // ❌ read as "accessToken" — names must match
5. Putting a cookie token in Authorization
wrong
Authorization: Bearer <token>  // ❌ if middleware expects req.cookies.accessToken
6. Forgetting Bearer prefix
header
Authorization: <token>         // ❌
Authorization: Bearer <token>  // ✅
7. Not checking if token exists
middleware
jwt.verify(undefined, secret);  // ❌ crashes

if (!token) return res.status(401).json(...);  // ✅ check first
8. Mismatched JWT secret
jwt
jwt.sign(payload, SECRET_A);
jwt.verify(token, SECRET_B);  // ❌ must match
9. Forgetting JWT_SECRET
env
process.env.JWT_SECRET  // may be undefined if .env not loaded
10. Misusing as JwtPayload
types
const decoded = jwt.verify(...) as JwtPayload;
// only tells TS the shape — no runtime validation of userId
11. Not storing user on req
middleware
req.user = { userId: decoded.userId };
// without this, the controller doesn't know who's authenticated
12. Wrong property name
access
req.userId       // ❌
req.user.userId  // ✅
13. Forgetting Express type augmentation
types
interface Request {
  user: { userId: string };
}
// without it: Property 'user' does not exist on type 'Request'
14. Returning password from user API
query
UserModel.findById(userId);                     // ⚠️ leaks password
UserModel.findById(userId).select("-password");  // ✅
5. Controller vs Service — What to Add

Controller

★★★★★

✅ What to add

controller
export const registerController = async (
  req: Request,
  res: Response
) => {
  const requestData = registerSchema.parse(req.body);
  const result = await registerUser(requestData);
  res.status(201).json(result);
};

❌ Don't add

wrong
// ❌ Don't add database queries
userModel.findOne();
userModel.create();

// ❌ Don't add password hashing
argon2.hash();

// ❌ Don't add JWT generation
jwt.sign();

// ❌ Don't add business logic
if (existingUser) { /* ... */ }

Service

✅ What to add

service
export const registerUser = async (
  userData: RegisterInput
) => {
  const existingUser = await userModel.findOne({
    email: userData.email,
  });

  if (existingUser) {
    throw new Error("User already exists");
  }

  return await userModel.create(userData);
};

❌ Don't add

wrong
// ❌ Don't handle HTTP response
res.status(201).json();

// ❌ Don't access req/res
req.body;
res.json();

// ❌ Don't do request validation
registerSchema.parse(req.body);

Simple Rule

Controller

HTTP + request validation + response

Service

Business logic + database operations
