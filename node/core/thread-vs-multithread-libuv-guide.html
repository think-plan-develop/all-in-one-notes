What is a Thread?

Thread = A Worker

A thread is the smallest unit of execution inside a process. Think of a thread as a worker that executes your program's instructions.

If there is one worker, tasks are executed one at a time. If there are multiple workers, several tasks can be executed simultaneously.

Single Thread vs Multi Thread

Single Thread

A single-threaded application has only one main thread to execute code.

Multi Thread

A multi-threaded application has multiple threads working together, able to execute several tasks at once.

Is Node.js Single-Threaded or Multi-Threaded?

Short Answer

Node.js is single-threaded for JavaScript execution, but multi-threaded internally. This is the most accurate interview answer.

Why Do People Say "Single-Threaded"?

Your JavaScript code runs on one main thread.

single-thread.js
console.log("Start");
console.log("Middle");
console.log("End");
Main Thread │ ▼ Start │ ▼ Middle │ ▼ End
💡 Only one JavaScript statement executes at a time. So from a JavaScript developer's perspective, Node.js is single-threaded.

Then Why Do People Say "Multi-Threaded"?

Because Node.js doesn't do everything on the main thread. When your code performs slow operations like:

  • Reading files
  • Database queries
  • DNS lookups
  • Encryption
  • Compression

Node.js delegates these operations to libuv, which uses:

  • Operating System asynchronous APIs
  • A Worker Thread Pool (default size: 4 threads, configurable via UV_THREADPOOL_SIZE)
delegated-read.js
const fs = require("fs");

console.log("Start");

fs.readFile("data.txt", () => {
    console.log("File Read");
});

console.log("End");

Internally:

Main Thread │ ▼ fs.readFile("data.txt") │ ▼ libuv Worker Thread │ Reads the file │ ▼ Callback Queue │ ▼ Event Loop │ ▼ Main Thread Executes Callback
⚠️ Notice that the main thread never reads the file itself.
What Exactly Runs on the Main Thread?

Main Thread Responsibilities

The main thread executes:

  • JavaScript code
  • Event Loop
  • Callback execution
  • Promise callbacks
  • Timers (setTimeout, setInterval)
💡 Everything here runs one task at a time.

Why Doesn't Node.js Create a Thread for Every Request?

Traditional servers often handled requests like this:

Request 1 → Thread 1 Request 2 → Thread 2 Request 3 → Thread 3

Node.js instead uses:

1000 Requests │ ▼ One Main Thread │ Event Loop │ Background I/O
✅ This reduces memory usage, context switching, and thread management overhead.
libuv

What is libuv?

libuv is a cross-platform C library used internally by Node.js to implement the Event Loop, asynchronous I/O, and a worker thread pool.

In simple words: libuv is the component that makes Node.js asynchronous and non-blocking. Without libuv, Node.js would not be able to efficiently handle file operations, timers, networking, and many other asynchronous tasks.

Why Was libuv Needed?

JavaScript is single-threaded. Imagine you write:

why-libuv.js
fs.readFile("data.txt", () => {
    console.log("Done");
});

JavaScript itself cannot read files. It simply says: "I need this file. Someone please read it."

💡 That "someone" is libuv.

How Does libuv Work?

Your JavaScript Code │ ▼ Node.js APIs (fs, http, crypto, timers...) │ ▼ libuv │ ┌───────┴─────────┐ │ │ Operating System Worker Thread Pool │ Operation Completes │ ▼ Callback Queue │ ▼ Event Loop │ ▼ JavaScript Callback Executes

What Does libuv Actually Do?

  • ✅ Event Loop
  • ✅ Worker Thread Pool
  • ✅ File System operations (fs)
  • ✅ Timers (setTimeout, setInterval)
  • ✅ DNS lookups
  • ✅ TCP/UDP networking
  • ✅ Cross-platform asynchronous I/O
Does libuv Handle Every Task?

No — Only Asynchronous I/O

⚠️ This is where many developers get confused. libuv mainly handles asynchronous I/O tasks, not CPU-intensive JavaScript code.

Asynchronous I/O tasks are handled by libuv, while CPU-intensive JavaScript calculations are executed on the main thread (unless you use Worker Threads).

Example 1 — File Reading (Handled by libuv)

io-task.js
fs.readFile("data.txt", () => {
  console.log("Done");
});
✅ Even if the file is 10 GB (a heavy file read), it is still an I/O operation, so libuv handles it.

Example 2 — Heavy Calculation (NOT Handled by libuv)

cpu-task.js
let sum = 0;

for (let i = 0; i < 10000000000; i++) {
  sum += i;
}
⚠️ This is a CPU-bound JavaScript task. It runs on the main thread and blocks the Event Loop.

Do We Manage libuv?

No. Node.js manages libuv automatically.

💡 Note: libuv is part of the Node.js runtime, not the V8 engine.
libuv is the internal library that powers Node.js's Event Loop and asynchronous I/O. It automatically manages I/O operations in the background, allowing the main JavaScript thread to remain non-blocking, while CPU-intensive JavaScript code continues to run on the main thread unless Worker Threads are used.

Why Does Node.js Need libuv?

JavaScript runs on a single main thread. If Node.js had to wait for every slow operation:

  • Reading files
  • Database queries
  • Network requests
  • Timers

...the application would freeze.

✅ libuv solves this by handling these operations asynchronously.
Interview Q&A — Threads & libuv
💡 Interview Q&A
Is Node.js single-threaded or multi-threaded?
Node.js is single-threaded for JavaScript execution, but multi-threaded internally. Your JS code, the Event Loop, and callbacks all run on one main thread, while libuv delegates slow I/O work to the operating system and a worker thread pool.
What exactly runs on the main thread, and what doesn't?
The main thread runs JavaScript code, the Event Loop, callback execution, Promise callbacks, and timers. It does not run file reads, DNS lookups, encryption, or compression directly — those are delegated to libuv's worker thread pool or the OS.

JavaScript codefs.readFile()
Event Loopcrypto.pbkdf2()
Promise callbackszlib compression
TimersDNS lookups
Why doesn't Node.js create a new thread for every incoming request?
Because that model (one thread per request) doesn't scale — thousands of requests mean thousands of threads, which costs huge memory and expensive context switching. Node.js instead uses one main thread plus the Event Loop, delegating I/O to the background, which drastically reduces memory usage and thread management overhead.
What is libuv, and why does Node.js need it?
libuv is a cross-platform C library that implements Node.js's Event Loop, asynchronous I/O, and worker thread pool — it's the component that makes Node.js non-blocking. JavaScript itself has no ability to read files or talk to the network; libuv is the "someone" that actually performs those operations and reports back via the Callback Queue.
JS Code → Node.js APIs (fs, http, crypto) → libuv → OS / Worker Pool → Callback Queue → Event Loop → JS Callback
Does libuv handle CPU-heavy JavaScript, like a large loop or sorting algorithm?
No. libuv only handles asynchronous I/O tasks — file access, networking, DNS, timers. A CPU-bound task like a billion-iteration loop runs entirely on the main thread and blocks the Event Loop until it finishes, since there's no I/O for libuv to offload. To parallelize CPU-heavy work, you need Worker Threads instead.
What is UV_THREADPOOL_SIZE?
It's an environment variable that controls the size of libuv's worker thread pool, which defaults to 4 threads. Operations like fs calls, crypto.pbkdf2(), and DNS lookups queue up on this pool — if you have more concurrent I/O-bound work than threads, extra tasks wait for a free thread, so increasing this value can help under heavy concurrent file/crypto load.
Is libuv part of the V8 engine?
No. This is a common point of confusion. V8 only executes JavaScript and has nothing to do with I/O. libuv is a separate part of the Node.js runtime responsible for the Event Loop, async I/O, and the thread pool — Node.js combines both V8 and libuv together.
