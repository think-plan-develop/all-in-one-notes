What It Is

JWT — signed, self-contained identity

A JWT (JSON Web Token) proves a user's identity and role without a database lookup on every request.

Why It Exists

Cheap proof of “I already logged in”

Without a token, every API request would re-verify the password or hit the database — slow, and credentials would be sent repeatedly.

Without access token

Re-check password or DB identity on every request. Slow. Credentials sent again and again.

With access token

Cryptographic signature verification. Fast. No DB round-trip. Proves who you are cheaply.

⚠️ JWT payloads are base64, not encrypted. Anyone can decode and read them. Never put passwords or secrets in the payload.
Code — Generating the Token

token.service.ts

src/modules/auth/token.service.ts
import jwt from "jsonwebtoken";
import { randomUUID } from "crypto";
import { env } from "../../config/env.js";

interface AccessTokenPayload {
  sub: string;
  role: string;
}

export function generateAccessToken(payload: AccessTokenPayload) {
  return jwt.sign(payload, env.JWT_ACCESS_SECRET, {
    expiresIn: env.ACCESS_TOKEN_EXPIRES_IN, // "15m"
    jwtid: randomUUID(),
  });
}
Code — Verifying the Token

authenticate middleware

src/middleware/authenticate.ts
import { Request, Response, NextFunction } from "express";
import jwt from "jsonwebtoken";
import { env } from "../config/env.js";

interface AccessTokenPayload {
  sub: string;
  role: string;
}

declare global {
  namespace Express {
    interface Request {
      user?: AccessTokenPayload;
    }
  }
}

export function authenticate(req: Request, res: Response, next: NextFunction) {
  const authHeader = req.headers.authorization;

  if (!authHeader?.startsWith("Bearer ")) {
    return res.status(401).json({ success: false, message: "Missing token" });
  }

  const token = authHeader.split(" ")[1];

  try {
    const payload = jwt.verify(token, env.JWT_ACCESS_SECRET) as AccessTokenPayload;
    req.user = payload;
    next();
  } catch {
    return res.status(401).json({ success: false, message: "Invalid or expired token" });
  }
}
💡 declare global teaches TypeScript that req.user exists on Express Request.

Code — Role-Based Access

requireRole factory

requireRole
export function requireRole(...roles: string[]) {
  return (req: Request, res: Response, next: NextFunction) => {
    if (!req.user || !roles.includes(req.user.role)) {
      return res.status(403).json({ success: false, message: "Forbidden" });
    }
    next();
  };
}

Common Pitfalls

Don't do these

  1. Storing it in localStorage — XSS can steal it. Keep it in memory (JS variable / React state). Lost on refresh by design — that's what the refresh token is for.
  2. Same secret for access and refresh — compromising one type shouldn't compromise the other. Use two secrets.
  3. Forgetting tokens don't reflect live role changes — after a promote, the current token still says "role": "user" until they log in again.
  4. Making the token too long-lived — defeats pairing it with a revocable refresh token.
🚫 Never localStorage. Never a cookie for the access token in this project. Memory only.
