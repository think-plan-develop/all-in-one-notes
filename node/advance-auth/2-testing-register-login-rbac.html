Prerequisites

  • Server running: npm run dev
  • Database migrated + seeded (user and admin roles exist)
  • One bootstrap admin account already seeded

Step 0 — Confirm Bootstrap Admin Exists

Need at least one working admin

seed
BOOTSTRAP_ADMIN_EMAIL=admin@example.com BOOTSTRAP_ADMIN_PASSWORD=adminPass123 npx prisma db seed

npx prisma studio

Check the User table — confirm admin@example.com exists with role admin.

Step 1 — Register a Normal User

Valid registration

201
POST /auth/register
curl -i -X POST http://localhost:4000/auth/register \
  -H "Content-Type: application/json" \
  -d '{"name":"Test User","email":"test@example.com","password":"yourpassword123"}'
expect body
{
  "id": "some-uuid",
  "email": "test@example.com",
  "role": "user"
}
  • role is "user" — never anything else, regardless of what you send.
  • No password_hash anywhere in the response.

Client cannot self-assign admin

201 · still user
injected role ignored
curl -i -X POST http://localhost:4000/auth/register \
  -H "Content-Type: application/json" \
  -d '{"name":"Hacker","email":"hacker@example.com","password":"pass12345","role":"admin"}'

Still 201 with "role": "user". Extra role is not in registerSchema, so Zod strips it.

Duplicate email

409

Register test@example.com again → 409 Conflict.

CaseExpected
Valid registration201, role: "user"
Registration with "role":"admin" in body201, role: "user" (ignored)
Duplicate email409
Step 2 — Login as the New User

Get USER_TOKEN

200
POST /auth/login
curl -i -X POST http://localhost:4000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"test@example.com","password":"yourpassword123"}'

export USER_TOKEN=""

echo $USER_TOKEN | cut -d '.' -f2 | base64 -d 2>/dev/null | python3 -m json.tool

Decoded payload must contain "role": "user".

Step 3 — User Cannot Access Admin Routes Yet

RBAC is blocking before promotion

403
GET /admin/users
curl -i http://localhost:4000/admin/users \
  -H "Authorization: Bearer $USER_TOKEN"
✅ 403 proves RBAC is actively blocking non-admins.
Step 4 — Login as Bootstrap Admin

Get ADMIN_TOKEN

200
POST /auth/login
curl -i -X POST http://localhost:4000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@example.com","password":"adminPass123"}'

export ADMIN_TOKEN=""

echo $ADMIN_TOKEN | cut -d '.' -f2 | base64 -d 2>/dev/null | python3 -m json.tool

Decoded payload must contain "role": "admin".

Step 5 — Get the Target User's ID

Read sub from USER_TOKEN

decode JWT
echo $USER_TOKEN | cut -d '.' -f2 | base64 -d 2>/dev/null | python3 -m json.tool

# { "sub": "abc-123-uuid", "role": "user", ... }

export TARGET_USER_ID="abc-123-uuid"

Alternatively: GET /admin/users as admin and find them in the list.

Step 6 — Promote the User to Admin

Happy path

200
PATCH /admin/users/:id/role
curl -i -X PATCH http://localhost:4000/admin/users/$TARGET_USER_ID/role \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"role":"admin"}'

Body: { "id": "...", "email": "test@example.com", "role": "admin" }

Negative tests

CaseExpected
Admin promotes another user200, role: "admin"
Non-admin attempts promotion ($USER_TOKEN)403
Admin tries to change own role400 — Cannot change your own role
Invalid role value (superuser)400 — fails z.enum(["user","admin"])
Nonexistent target user404
Step 7 — Verify the Promotion Actually Worked

Old token is frozen

The database is updated, but the user's old token still has role: "user".

Old token (stale)

USER_TOKEN on /admin/users → 403. Correct — not a bug. Tokens don't update live.

New token (fresh login)

PROMOTED_TOKEN decoded "role": "admin" → /admin/users → 200 + user list.

re-login then retry
curl -i http://localhost:4000/admin/users \
  -H "Authorization: Bearer $USER_TOKEN"
# 403 — expected

curl -i -X POST http://localhost:4000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"test@example.com","password":"yourpassword123"}'

export PROMOTED_TOKEN=""

curl -i http://localhost:4000/admin/users \
  -H "Authorization: Bearer $PROMOTED_TOKEN"
# 200
