0. Theory — The Core RBAC Rule

Hold onto this before any code

Public signup
↓
USER only
↓
Admin action
↓
Change role to admin
✅ Public signup can only ever create a normal user. The client cannot choose or submit a role. Only an already-authorized admin can change another user's role.

Never allow this

Frontend
↓
"role": "admin" in registration body
↓
Backend accepts it → RBAC bypassed

If a registration endpoint reads role from the client and trusts it, anyone can register as admin. The fix is not "validate that role is a real value" — it's never accept role from the client at all during signup. The server decides the role, always.

Wrong

role_id: input.role_id — client-controlled. Anyone can send admin.

Correct

Lookup name: "user" on the server. Never from the request.

signup — server decides role
// ❌ WRONG — never do this
const user = await prisma.user.create({
  data: {
    email: input.email,
    password_hash: hash,
    role_id: input.role_id, // client-controlled
  },
});

// ✅ CORRECT — server decides, always
const userRole = await prisma.role.findUniqueOrThrow({ where: { name: "user" } });
const user = await prisma.user.create({
  data: {
    email: input.email,
    password_hash: hash,
    role_id: userRole.id, // hardcoded lookup
  },
});
📌 Zod omitting role strips unknown keys by default — still don't rely on that alone. The service layer should never read input.role.
1. Authentication Middleware

Verify JWT · attach req.user

src/middleware/authenticate.ts
import { Request, Response, NextFunction } from "express";
import jwt from "jsonwebtoken";
import { env } from "../config/env.js";

interface AccessTokenPayload {
  sub: string;
  role: string;
}

declare global {
  namespace Express {
    interface Request {
      user?: AccessTokenPayload;
    }
  }
}

export function authenticate(req: Request, res: Response, next: NextFunction) {
  const authHeader = req.headers.authorization;

  if (!authHeader?.startsWith("Bearer ")) {
    return res.status(401).json({ success: false, message: "Missing token" });
  }

  const token = authHeader.split(" ")[1];

  try {
    const payload = jwt.verify(token, env.JWT_ACCESS_SECRET) as AccessTokenPayload;
    req.user = payload;
    next();
  } catch {
    return res.status(401).json({ success: false, message: "Invalid or expired token" });
  }
}
💡 declare global teaches TypeScript that req.user exists. Without it, req.user errors as unknown.
⚠️ Role in the JWT is a snapshot at login time, not a live DB read. Role changes don't take effect until the user logs in again. Expected — not a bug. Promoted users still get 403 until they re-authenticate.
2. First Protected Route — /users/me

Any logged-in user can fetch their own data

src/modules/user/user.routes.ts
import { Router } from "express";
import { authenticate } from "../../middleware/authenticate.js";
import { prisma } from "../../config/db.js";

const router = Router();

router.get("/me", authenticate, async (req, res) => {
  const user = await prisma.user.findUnique({
    where: { id: req.user!.sub },
    include: { role: true },
  });

  if (!user) return res.status(404).json({ success: false, message: "User not found" });

  return res.json({
    id: user.id,
    name: user.name,
    email: user.email,
    role: user.role.name,
  });
});

export default router;

Wire in app.ts: app.use("/users", userRoutes);

4. Role Middleware

Runs after authenticate

src/middleware/requireRole.ts
import { Request, Response, NextFunction } from "express";

export function requireRole(...roles: string[]) {
  return (req: Request, res: Response, next: NextFunction) => {
    if (!req.user || !roles.includes(req.user.role)) {
      return res.status(403).json({ success: false, message: "Forbidden" });
    }
    next();
  };
}

Factory: requireRole("admin") or requireRole("admin", "moderator"). Order is fixed:

authenticate()
↓
requireRole("admin")
↓
controller
⚠️ If you swap the order, req.user is always undefined and every request gets 403 — including valid admin tokens. Common "admin route always fails" bug.

  });
  return res.json(users);
});

6. How Does the First Admin Get Created?

Bootstrap — chicken and egg

The role-change endpoint requires an existing admin. On a new system, zero admins exist. Solve it with one controlled, manual bootstrap — never a public endpoint.

seed
↓
Create "user" role
↓
Create "admin" role
↓
Create ONE initial admin, manually
prisma/seed.ts
const adminEmail = process.env.BOOTSTRAP_ADMIN_EMAIL;
if (adminEmail) {
  const adminRole = await prisma.role.findUniqueOrThrow({ where: { name: "admin" } });
  await prisma.user.upsert({
    where: { email: adminEmail },
    update: { role_id: adminRole.id },
    create: {
      email: adminEmail,
      name: "Bootstrap Admin",
      password_hash: await argon2.hash(process.env.BOOTSTRAP_ADMIN_PASSWORD!),
      role_id: adminRole.id,
    },
  });
}

7. Admin Promotes / Demotes Another User

Schema

src/modules/user/user.schema.ts
import { z } from "zod";

export const roleChangeSchema = z.object({
  role: z.enum(["user", "admin"]),
});

export type RoleChangeInput = z.infer;

Service

src/modules/user/user.service.ts
export async function changeUserRole(targetUserId: string, newRoleName: "user" | "admin") {
  const targetUser = await prisma.user.findUnique({ where: { id: targetUserId } });
  if (!targetUser) throw new Error("USER_NOT_FOUND");

  const newRole = await prisma.role.findUniqueOrThrow({ where: { name: newRoleName } });

  const updated = await prisma.user.update({
    where: { id: targetUserId },
    data: { role_id: newRole.id },
    include: { role: true },
  });

  return { id: updated.id, email: updated.email, role: updated.role.name };
}

Controller — self-demotion guard

src/modules/user/user.controller.ts
export async function changeRoleController(req: Request, res: Response) {
  const parsed = roleChangeSchema.safeParse(req.body);
  if (!parsed.success) {
    return res.status(400).json({ success: false, message: "Invalid input" });
  }

  const targetUserId = req.params.id;

  if (targetUserId === req.user!.sub) {
    return res.status(400).json({ success: false, message: "Cannot change your own role" });
  }

  try {
    const updated = await changeUserRole(targetUserId, parsed.data.role);
    return res.status(200).json(updated);
  } catch (err) {
    if (err instanceof Error && err.message === "USER_NOT_FOUND") {
      return res.status(404).json({ success: false, message: "User not found" });
    }
    return res.status(500).json({ success: false, message: "Something went wrong" });
  }
}
⚠️ Without the self-demotion guard, the only admin could demote themselves and lock the system with no admin left.

9. Summary — Pattern to Reuse

WHO vs ALLOWED

authenticate

Proves WHO the caller is. Valid JWT → req.user

requireRole("X", "Y")

Proves the caller is ALLOWED. req.user.role is one of X, Y

any route
router.get("/public", handler);
router.get("/private", authenticate, handler);
router.get("/admin-only", authenticate, requireRole("admin"), handler);
router.get("/staff", authenticate, requireRole("admin", "moderator"), handler);
