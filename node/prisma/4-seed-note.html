🌱 Prisma Seed Steps

Configuring, generating, and running a seed with the prisma-client generator

Migration vs Seed Configure Seed File Generate Client Run Seed Troubleshooting
📌 In short: Register the seed command in prisma.config.ts, import PrismaClient from the generated output (not @prisma/client), run npx prisma generate, then npx prisma db seed — always from inside the project directory.
🔑 Key Terms at a Glance
🏗️
Migration: Creates or changes database structure — e.g. the Role and User tables.
🌱
Seed: Inserts initial or default records — e.g. the default user and admin roles.
📦
prisma-client generator: A custom generator whose output path means PrismaClient must be imported from the generated folder, not @prisma/client.
🔁
upsert: Used in the seed so running it more than once never creates duplicate roles.
1. Migration and Seed Are Different
1

Two Different Jobs

The migration creates the Role and User tables. The seed inserts the default roles:

default roles
user
admin
2. Configure the Seed Command
2

Register the Seed File

In sql-auth/prisma.config.ts, register the seed file under migrations:

prisma.config.ts
migrations: {
    path: "prisma/migrations",
    seed: "tsx prisma/seed.ts",
},
💡 The path is relative to the sql-auth project directory.
3. Create the Seed File
3

File Location

The seed file is:

path
sql-auth/prisma/seed.ts
📦

Uses the prisma-client Generator

This project uses the newer prisma-client generator in schema.prisma:

schema.prisma
generator client {
    provider = "prisma-client"
    output   = "../src/generated/prisma"
}

Therefore, import PrismaClient from the generated output:

seed.ts
import { PrismaClient } from "../src/generated/prisma/client.js";
⚠️ Do not use this import with the custom prisma-client generator:
❌ wrong
import { PrismaClient } from "@prisma/client";
✅ The seed uses upsert, so running it more than once does not create duplicate roles.
4. Generate the Prisma Client
4

Run prisma generate

Open PowerShell in the project directory:

PowerShell
cd D:\VERY_IMPORTANT\sql-auth
npx prisma generate

This creates the generated client in:

output
sql-auth/src/generated/prisma
5. Run the Seed
5

Run db seed

Run the command from sql-auth, where package.json, prisma.config.ts, and node_modules exist:

PowerShell
cd D:\VERY_IMPORTANT\sql-auth
npx prisma db seed

Expected output:

Output
Seed completed successfully
The seed command has been executed.
6. Important Troubleshooting
⭐ Important — Common Gotcha
⚠️

Wrong Working Directory

If PowerShell is in D:\VERY_IMPORTANT instead of D:\VERY_IMPORTANT\sql-auth, npx prisma may ask to install Prisma again.

Change into the project directory first:

PowerShell
cd D:\VERY_IMPORTANT\sql-auth
🔑

Check .env

Also confirm that .env contains a valid DATABASE_URL, because both prisma.config.ts and prisma/seed.ts use it.
