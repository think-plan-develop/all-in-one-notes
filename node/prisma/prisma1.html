1. Prisma Fundamentals

What is an ORM?

An ORM (Object-Relational Mapper) lets you interact with a relational database using objects/methods in your programming language instead of raw SQL.

Raw SQL

SELECT * FROM users WHERE id = 1

Prisma

prisma.user.findUnique({ where: { id: 1 } })

It maps tables → models, rows → objects, columns → properties — better readability, type safety, fewer SQL typos. Trade-off: less low-level query control.

Prisma Architecture

Prisma Schema

schema.prisma — single source of truth for your data model and DB connection.

Prisma Migrate

Converts schema changes into SQL. Not covered in this doc.

Prisma Client

Auto-generated, type-safe query builder used in app code to talk to the database.

Prisma Client translates JS/TS method calls into SQL sent to PostgreSQL — via the query engine, or (Prisma 7+) driver adapters like @prisma/adapter-pg.

schema.prisma

The central config file with three parts:

schema.prisma
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

generator client {
  provider = "prisma-client-js"
}

model User {
  id Int @id @default(autoincrement())
}

prisma.config.ts

A TypeScript config file (newer Prisma versions) for programmatic setup — custom driver adapters, dynamic env loading — supplementing the declarative schema.prisma.

Prisma Client

The generated, type-safe API (prisma.user.findMany(), etc.) reflecting your exact schema.

⚠️ Must run prisma generate after every schema change, or TypeScript types will be out of sync.

Prisma vs Raw SQL

Raw SQL

Full control, but verbose, no compile-time type checking, easy typos/bugs.

Prisma

Type-safe, autocomplete, automatic relations. Less suited for extremely complex hand-tuned queries — $queryRaw is the escape hatch.

Prisma vs Sequelize / TypeORM

Sequelize

JS-first, weaker type safety even with TS, more implicit / "magic" behavior.

TypeORM

Decorator/class-based. Historically less stable with complex relations.

Prisma

Schema-first (not code-first). Strongest type safety. Cleanest query API and tooling (Studio, schema diffing).

2. Prisma Schema

Learn these

★★★★★
model fields & types @id @default() @unique @updatedAt @map @@map ? optional [] arrays enums relations

Example

schema.prisma
model User {
  id           Int      @id @default(autoincrement())
  email        String   @unique
  passwordHash String   @map("password_hash")
  roleId       Int      @map("role_id")
  role         Role     @relation(fields: [roleId], references: [id])
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt
}

3. PostgreSQL + Prisma

Type mapping

Prisma TypePostgreSQL Type
Stringtext / varchar
Intinteger
BigIntbigint
Booleanboolean
DateTimetimestamp
Decimalnumeric
Jsonjsonb
Bytesbytea
Floatdouble precision

Type details

  • String — defaults to text unless @db.VarChar(255) is specified.
  • Int — 32-bit integer. BigInt — 64-bit, for high-volume IDs or large counters.
  • Boolean — maps directly to PostgreSQL native boolean.
  • DateTime — timestamp (or timestamptz) — used for createdAt / updatedAt.
  • Decimal — precise values like money (avoids float rounding). Control with @db.Decimal(precision, scale).
  • Json — maps to jsonb (binary, indexable, queryable).

Enums, UUID, native overrides

A Prisma enum creates a native PostgreSQL ENUM — enforced at the database level:

schema.prisma
enum Role {
  ADMIN
  USER
  GUEST
}

UUID as an alternative to auto-increment IDs:

schema.prisma
id String @id @default(uuid()) @db.Uuid
AttributePurpose
@db.VarChar(100)Length-limited string column
@db.Decimal(10, 2)Exact precision/scale (currency)
@db.UuidNative PostgreSQL uuid instead of text

Keys, constraints, indexes

ConceptHow in Prisma
Primary key@id (single) or @@id([...]) (composite)
Foreign key@relation — column referencing another table's PK
Unique@unique or @@unique([...])
Index@@index([...]) — speeds filtered/sorted columns
Composite index@@index([firstName, lastName])
📌 NULL in PostgreSQL = "no value." Mark a field ? in Prisma to allow NULL. Without ?, the column is NOT NULL — Prisma validates this before the query reaches the database.
4. Prisma Client — Core CRUD

Create

★★★★★
create
const user = await prisma.user.create({
  data: {
    email: "test@example.com",
    passwordHash: "hashed_pw",
    roleId: 1,
  },
});

Inserts a new row and returns the created record (all fields, by default).

Read

read
prisma.user.findUnique({ where: { id: 1 } });
prisma.user.findUniqueOrThrow({ where: { id: 1 } }); // throws P2025 if not found
prisma.user.findFirst({ where: { email: { contains: "gmail" } } });
prisma.user.findFirstOrThrow({ where: { roleId: 2 } });
prisma.user.findMany();
  • findUnique — needs a unique field (id, email, or @@unique) in where.
  • findFirst — any filter, first match or null.
  • findMany — returns an array (all rows if no filter).
  • OrThrow — missing record raises an error instead of a manual null check.

Update

update
prisma.user.update({ where: { id: 1 }, data: { email: "new@example.com" } });
prisma.user.updateMany({ where: { roleId: 2 }, data: { roleId: 3 } });
  • update — exactly one record (unique where); throws P2025 if missing.
  • updateMany — all matches; returns only { count }, not the records.

Atomic numeric updates (avoids race conditions):

increment
prisma.user.update({
  where: { id: 1 },
  data: { loginCount: { increment: 1 } },
});

Other operators: decrement, multiply, divide, set.

Delete

delete
prisma.user.delete({ where: { id: 1 } });
prisma.user.deleteMany({ where: { roleId: 2 } });
  • delete — one record by unique id; throws P2025 if not found.
  • deleteMany — all matches; returns a count.

Upsert

★★★★★

Creates a record if it doesn't exist, or updates it if it does — one atomic insert-or-update:

upsert
prisma.user.upsert({
  where: { email: "test@example.com" },
  update: { lastLoginAt: new Date() },
  create: {
    email: "test@example.com",
    passwordHash: "hashed_pw",
    roleId: 1,
  },
});
💡 Common for "sync external user on login" or "create settings row if missing."

Query modifiers

ModifierWhat it does
whereFilters records by conditions
selectReturns only specified fields (smaller payload, hide secrets)
includeFetches related data (like a JOIN)
orderBySorts results (single or multi-field)
skipSkips N records (offset pagination)
takeLimits records (SQL LIMIT); negative takes from the end
distinctRemoves duplicates on specified fields
modifiers
prisma.user.findMany({ select: { id: true, email: true } });
prisma.user.findMany({ include: { role: true } });
prisma.user.findMany({ orderBy: { createdAt: "desc" } });
prisma.user.findMany({ orderBy: [{ roleId: "asc" }, { createdAt: "desc" }] });
prisma.user.findMany({ distinct: ["roleId"] });
⚠️ select and include cannot be used together at the same level. Nest select inside include to shape relation fields.
5. Aggregations & Grouping

count

★★★★
count
const total = await prisma.user.count({ where: { roleId: 1 } });

prisma.user.count({ select: { _all: true, email: true } });

aggregate

Runs _sum, _avg, _min, _max, _count in one query:

aggregate
const stats = await prisma.order.aggregate({
  where: { userId: 1 },
  _sum: { amount: true },
  _avg: { amount: true },
  _min: { amount: true },
  _max: { amount: true },
  _count: true,
});

groupBy

Groups records and applies aggregates per group — SQL GROUP BY:

groupBy
const results = await prisma.order.groupBy({
  by: ["userId"],
  _sum: { amount: true },
  _count: true,
  having: {
    amount: { _sum: { gt: 1000 } }, // like SQL HAVING
  },
  orderBy: { userId: "asc" },
});
📌 Useful for reports like "total spend per user" or "count of users per role."
