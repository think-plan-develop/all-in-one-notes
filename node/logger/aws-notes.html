3. ECS Task Execution Role

What it is

The ECS Task Execution Role is an IAM role that gives ECS/Fargate permission to perform certain AWS actions on behalf of your container.

For your project, the two important things are:

ECS/Fargate │ ├── Pull Docker image from ECR │ └── Send container logs to CloudWatch

Without the appropriate execution role, ECS may not be able to pull your private ECR image or send logs to CloudWatch.

1

Why do we need it?

You have already done:

Your PC
↓
AWS CLI
↓
IAM Access Key
↓
ECR

That access key is for you/your computer.

But later, when AWS starts your Docker container, AWS itself needs permission:

AWS ECS ↓ "I need to pull this image from ECR" ↓ "I need to send these logs to CloudWatch"

The Task Execution Role provides those permissions.

2

Access Key vs Execution Role

This distinction is very important:

CredentialUsed byPurpose
IAM Access KeyYou / local AWS CLIUpload image to ECR
ECS Task Execution RoleECS/FargateStart and manage your container

So:

LOCAL

You → AWS CLI → Access Key → ECR

AWS

ECS/Fargate → Task Execution Role → ECR pull image + CloudWatch send logs

3

Create the Role

Go to:

AWS Console → IAM → Roles → Create role

Step 1 — Trusted entity

Choose:

Trusted entity type: AWS service

Then service/use case:

Elastic Container Service → Elastic Container Service Task

This means:

ECS tasks are allowed to use this role.
4

Add the Permission Policy

Search for:

AmazonECSTaskExecutionRolePolicy

Select it.

This is an AWS-managed policy designed for ECS task execution.

It provides permissions needed for things such as:

ECR ↓ Pull container image CloudWatch Logs ↓ Create/write log streams and events

For your current setup, this is exactly what you need.

5

Name the Role

Use:

ecsTaskExecutionRole

Then: Create role

You should now have:

IAM └── Roles └── ecsTaskExecutionRole
6

How it will be used later

You don't manually give this role to Docker.

You'll select it in your ECS Task Definition:

ECS Task Definition │ ├── Container image │ ↓ │ ECR │ ├── Execution role │ ↓ │ ecsTaskExecutionRole │ └── Logging ↓ CloudWatch

When ECS launches your task:

ECS │ │ uses ecsTaskExecutionRole │ ├──────────────→ ECR │ └── Pull pino-logger-demo:latest │ └──────────────→ CloudWatch └── Write container logs
7

Don't confuse it with Task Role

ECS has two different concepts:

Task Execution Role — used by ECS infrastructure:

ECS ├── Pull image from ECR └── Send logs to CloudWatch

Task Role — used by your application inside the container:

Node.js application ↓ AWS API ↓ S3 / DynamoDB / SQS / etc.

For your current Pino + CloudWatch project, you primarily need:

✅ Task Execution Role ❌ Task Role — not required unless your application itself needs AWS permissions

Final setup

Create:

Role name: ecsTaskExecutionRole Trusted entity: Elastic Container Service Task Policy: AmazonECSTaskExecutionRolePolicy

Once this role is created, your next step is ECS Cluster creation.

Find the public IP (task already RUNNING)

Method 1 — ECS Console

Since your ECS task is already RUNNING, you can find its public IP from the ECS console.

Go to:

AWS Console → ECS → Clusters → acclaimed-elephant-fx97jh → Services → pino-logger-service → Tasks → click the RUNNING task

Then find the Networking section.

You should see something like:

Network VPC: vpc-xxxxxxxx Subnet: subnet-xxxxxxxx Security group: sg-xxxxxxxx Public IP: 54.xxx.xxx.xxx

Copy the Public IP.

Method 2 — Use it to call your API

If your public IP is:

54.123.45.67

and your Node.js app listens on port 3000, call:

powershell
curl http://54.123.45.67:3000

Or:

http://54.123.45.67:3000

in your browser.

If you don't see a Public IP

Check your ECS Service/Task networking configuration and make sure:

Public IP → ON

Also make sure the task is running in a subnet that has internet connectivity.

And your Security Group needs an inbound rule allowing the application port, e.g.:

Type: Custom TCP Port: 3000 Source: Your IP

For testing, you can use 0.0.0.0/0, but don't leave that open in a production setup.

Once you find the IP, you can use it to call your API and watch the Pino request logs appear in CloudWatch Live Tail.
