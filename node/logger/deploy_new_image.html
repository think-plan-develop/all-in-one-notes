Phase 1–2 · Code + local Node test
1

Change your code

app
app.get('/', (req, res) => {
  req.log.info('Handling root route');
  res.send('Hello from version 2');
});
2

Test Node locally first

powershell
npm start
curl http://localhost:3000/

Expect Hello from version 2. Also hit /error if you have it.

Phase 3–4 · Build + test Docker locally
3–4

Build image

powershell
docker build --no-cache -t pino-logger-app .
docker images

--no-cache guarantees a rebuild for learning. Production deploys don't always need it.

5–7

Run the new image locally — checkpoint

powershell
docker run --rm -p 3000:3000 pino-logger-app

# other window
curl http://localhost:3000/
curl http://localhost:3000/error

See Pino in the Docker terminal. Then Ctrl+C to stop.

🚫 Don't push to AWS if the new Docker image doesn't work locally.
Phase 5–8 · Tag · login · push · verify ECR
8–10

Tag + login + push

Local: pino-logger-app:latest · ECR: pino-logger-demo · account 133889910939 · us-east-1

powershell
docker tag pino-logger-app:latest 133889910939.dkr.ecr.us-east-1.amazonaws.com/pino-logger-demo:latest

aws ecr get-login-password --region us-east-1 |
docker login --username AWS --password-stdin 133889910939.dkr.ecr.us-east-1.amazonaws.com

docker push 133889910939.dkr.ecr.us-east-1.amazonaws.com/pino-logger-demo:latest

Expect Login Succeeded then latest: digest: sha256:…

11

Verify ECR

Console → ECR → pino-logger-demo → Images: tag latest, new Created at, new digest. Local → Docker → ECR is done. ECS is not necessarily running this image yet.

Phase 9 · New task-definition revision
12

This is the part that caused the earlier problem

Even if ECR latest changed, ECS can still be pinned to the old digest. Create a new revision.

ECS → Task definitions → pino-logger-task → Create new revision Image: …/pino-logger-demo:latest Keep: 0.25 vCPU · 0.5 GiB · port 3000 · ecsTaskExecutionRole · existing logs → Create → pino-logger-task:4
📌 Previous task may still be on sha256:339da032…. A new revision is a new deployment config.
Phase 10–11 · Update service + watch deploy
13–17

Update service

Cluster → Services → Update service Task definition: pino-logger-task: ← not :1 Desired tasks: 1 Force new deployment: ON Keep VPC / SG / port 3000 / Public IP ON → Update service

Force new deployment = replace the running task with this config. Don't recreate networking every deploy.

18

Watch deployments

New deployment
↓
Pending
↓
Running
↓
Old task stops · 1 Running · 0 Pending
Phase 12–16 · New task · new IP · API · logs
19–21

Verify the NEW running task

Don't use the old task ID. Check: Task definition = pino-logger-task:4. Containers → Image URI = new digest. Compare with ECR. Best check that ECS is actually running the new image.

22–23

New public IP — don't reuse yesterday's

RUNNING task → Networking → Public IP. Fargate can assign a different IP. Old 54.163.55.191 may be dead.

powershell
Test-NetConnection NEW_PUBLIC_IP -Port 3000

Want TcpTestSucceeded : True. If False, don't debug the app yet — check task → public IP → SG → port 3000 → subnet → route table → IGW.

24–26

API + CloudWatch

powershell
curl http://NEW_PUBLIC_IP:3000/          # Hello from version 2
curl http://NEW_PUBLIC_IP:3000/error     # HTTP 500 Internal error

CloudWatch → /ecs/pino-logger-task → new task's stream: Server started · Handling root route · request completed · error log.

Final checks + 22-step checklist

All four must match

#CheckLook for
1ECRNew image digest
2ECSNew task-definition revision
3FargateNew RUNNING task + that digest
4CloudWatchLogs from the new task

Never skip these 5

  1. Docker — docker run --rm -p 3000:3000 pino-logger-app — new code works?
  2. ECR — latest has new time/digest?
  3. Task definition — service using the new revision?
  4. Running task — new image digest?
  5. CloudWatch — logs from the new task?

① works, ④ old digest

ECS deployment problem

④ new digest, API old

Docker / build / code problem

④ correct but port 3000 unreachable → networking / security group.
