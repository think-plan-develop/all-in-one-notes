1. Create your Node.js application
1

Example project

pino-demo/ │ ├── app.js ├── logger.js ├── package.json ├── package-lock.json └── Dockerfile

Your application must listen on the container port:

app.js

  logger.info('Server started on port 3000');
});

Important

2. Create Dockerfile
2

Example

Dockerfile
FROM node:20-alpine

WORKDIR /app

COPY package*.json ./

RUN npm install --production

COPY . .

EXPOSE 3000

CMD ["node", "app.js"]

5–9. ECR — repository, login, tag, push, verify
5

Create ECR repository

ECR = Elastic Container Registry.

Think of ECR as:

GitHub

stores source code

ECR

stores Docker images

Your repository:

pino-logger-demo

Your ECR address is:

133889910939.dkr.ecr.us-east-1.amazonaws.com/pino-logger-demo
6

Login Docker to ECR

First configure AWS CLI if you haven't already.

Then:

powershell
aws sts get-caller-identity

This confirms that your AWS CLI is authenticated.

Then:

powershell
aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin 133889910939.dkr.ecr.us-east-1.amazonaws.com

Expected:

Login Succeeded

This means:

Docker
↓
authenticated with
↓
AWS ECR
7

Tag your Docker image

Your local image:

pino-logger-app:latest

Needs an ECR tag:

powershell
docker tag pino-logger-app:latest 133889910939.dkr.ecr.us-east-1.amazonaws.com/pino-logger-demo:latest

Check:

powershell
docker images

You should now see something like:

pino-logger-app 133889910939.dkr.ecr.us-east-1.amazonaws.com/pino-logger-demo
8

Push Docker image to ECR

powershell
docker push 133889910939.dkr.ecr.us-east-1.amazonaws.com/pino-logger-demo:latest

Now the architecture is:

Your PC Docker Image ↓ docker push ↓ ECR ↓ pino-logger-demo:latest

Verify image in ECR

AWS Console:

ECR ↓ Repositories ↓ pino-logger-demo

You should see:

latest

Check the Created at time and image digest.

For example:

This confirms your new image reached ECR.

10. Create ECS cluster
10

Serverless Fargate cluster

Go to:

AWS Console ↓ ECS ↓ Clusters ↓ Create cluster

Choose:

Cluster type: Serverless (AWS Fargate)

Give it a name, for example:

pino-logger-cluster

Create the cluster.

Why cluster?

A cluster is a logical place where ECS services/tasks run.

ECS Cluster │ ├── Service │ │ │ ├── Task │ └── Task │ └── Other services

16

Very important — Task Definition vs Docker Image

This is where you previously had the problem with old code.

Suppose ECR contains:

latest → NEW IMAGE

but your ECS task definition points to:

old image digest

ECS can still run the old image.

So understand:

Docker Image
↓
ECR
↓
Task Definition
↓
ECS Service
↓
Task

For reliable production deployments, using an immutable image tag such as a Git commit SHA is even better than relying only on latest.

Example:

pino-logger-demo:abc123

instead of:

pino-logger-demo:latest

19

Security Group

For your current testing setup, inbound:

Type: Custom TCP Port: 3000 Source: 0.0.0.0/0

allows:

Anyone on Internet ↓ your-public-IP:3000

For a learning/demo environment this works.

But don't keep this in production

For a real production architecture, normally you would use:

Internet
↓
Application Load Balancer : 80/443
↓
ECS
↓
Container : 3000

and restrict the ECS security group so that port 3000 is reachable only from the ALB.

20

Network requirements

Your subnet should have a route like:

Destination Target 172.31.0.0/16 local 0.0.0.0/0 Internet Gateway

You already have this.

Therefore:

Fargate
↓
Subnet
↓
Route Table
↓
Internet Gateway
↓
Internet

Your Network ACL also needs to allow the traffic.

Your existing NACL showed:

Inbound 100 → All traffic → Allow Outbound 100 → All traffic → Allow

So that part was not blocking your port 3000.

22–25. Check task, public IP, test API
22

Check ECS task

Go to:

ECS ↓ Clusters ↓ Your cluster ↓ Services ↓ Your service ↓ Tasks

You want:

Desired: 1 Running: 1 Pending: 0

23

Find the public IP

Inside the running task:

Networking

You'll see:

Public IP Private IP ENI Security Group Subnet

Example:

Public IP: 54.163.55.191

The public IP can change whenever the Fargate task is recreated.

So don't permanently assume:

54.163.55.191

is your API address.

with HTTP status:

500
