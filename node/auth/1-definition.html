Authentication vs Authorization

Two commonly confused security concepts — clearly explained.

Authentication Authorization Side-by-Side User → Role → Permission Code Example Interview One-Liner
💡 The core distinction: Authentication happens first and answers "who are you?" Authorization happens after and answers "what are you allowed to do?"
🔑 Key Terms at a Glance
🔐
Authentication: Verifying identity — confirming a user is who they claim to be.
🛡️
Authorization: Checking what actions or resources an already-authenticated user is permitted to access.
🚫
401 Unauthorized: "I don't know who you are" — an authentication failure.
⛔
403 Forbidden: "I know who you are, but you're not allowed" — an authorization failure.
🏷️
RBAC: Role-Based Access Control — the common pattern for bundling permissions into roles.
1. Authentication — "Who Are You?"

🔐 Definition

★★★★★

The process of verifying identity — confirming that a user is who they claim to be.

Logging in with email + password. If credentials match → "Yes, you are Shivam."

Common Mechanisms

  • Username / Password
  • OTP Verification
  • JWT / Session Cookies
  • OAuth (Google / GitHub)
  • Biometrics
2. Authorization — "What Are You Allowed to Do?"

🛡️ Definition

★★★★★

Happens after authentication. Checks what actions or resources the user is permitted to access.

Once logged in → Can this user delete posts? Access admin dashboard? View billing?

Common Mechanisms

  • Role-Based Access (RBAC)
  • Permission Flags
  • Middleware Checks
  • isAdmin / hasPermission
🧠 Quick Memory Trick:

Login = Authentication — proving who you are
Permission Checking = Authorization — checking what you can do

4. The Hierarchy: User → Role → Permission

How Authorization Is Usually Modeled

★★★★★
User
"Shivam"
↓
Role
Admin · Editor · Viewer

can delete posts · can edit users
📌 A User is assigned one or more Roles. Each Role bundles a set of Permissions. Systems usually check "does this user's role include permission X?" — much easier to manage at scale.
5. Code Example (Express Middleware)

Auth Check → Authz Check

★★★★★
middleware.js
// Authentication check
if (!req.user) return res.status(401).send("Please log in");

// Authorization check
if (req.user.role !== "admin") return res.status(403).send("Forbidden");
