📌 In short: Every custom error extends one base class (AppError). Middleware and services throw it, asyncHandler catches it, and a single errorHandler at the bottom of the app responds to it. Reading this doc file-by-file traces every throw and every catch in the whole app.

01 · AppError.ts & Subclasses

📁 src/errors/AppError.ts

DEFINED HERE

The single base error class for the whole app. Every custom error extends it. Adds statusCode, isOperational (true = known/expected error, not a bug), and an optional errors payload for field-level detail. Nothing throws raw new Error() — everything uses this.

Imported By

IMPORTED BY → auth.ts authorise.ts user.service.ts errorHandler.ts user.routes.ts (via MW) handleMongooseError.ts

Code

src/errors/AppError.ts
// DEFINED HERE — imported by every other layer

// ── Base class ─────────────────────────────────────────────
export class AppError extends Error {
  public readonly statusCode:    number;
  public readonly isOperational: boolean;   // true = known/expected error
  public readonly errors?:       unknown;

  constructor(message: string, statusCode: number = 500, errors?: unknown) {
    super(message);
    this.name          = this.constructor.name;
    this.statusCode    = statusCode;
    this.isOperational = true;
    this.errors        = errors;
    Error.captureStackTrace(this, this.constructor);
  }
}

// ── Subclasses — no magic status codes needed ──────────────
export class NotFoundError extends AppError {
  constructor(resource = "Resource") { super(`${resource} not found`, 404); }
}

export class ValidationError extends AppError {
  constructor(errors: unknown) { super("Validation failed", 400, errors); }
}

export class UnauthorizedError extends AppError {
  constructor(message = "Unauthorized") { super(message, 401); }
}

export class ForbiddenError extends AppError {
  constructor(message = "Forbidden") { super(message, 403); }
}

export class ConflictError extends AppError {
  constructor(field: string) { super(`${field} already exists`, 409); }
}

📍 Where Each Class Gets Called

🔐auth.tsTHROWS 401
throw new UnauthorizedError("No token provided") when the Authorization header is missing entirely. throw new UnauthorizedError("Token expired") when JWT verification fails. Both are passed via next(err) → errorHandler responds 401.
🛡️authorise.tsTHROWS 403
throw new ForbiddenError("Role not allowed") when the authenticated user's role is not in the allowed list → errorHandler → 403.
⚙️user.service.tsPRIMARY THROW LAYER
throw new NotFoundError("User") when findById returns null → 404
throw new ConflictError("email") when email already taken → 409
throw new ForbiddenError(...) on ownership checks → 403
🍃handleMongooseError.tsBYPASSES AppError
Does NOT import AppError. Returns a plain { statusCode, body } object that errorHandler sends directly. Mongoose errors bypass the class hierarchy entirely.
🎯errorHandler.tsREADS AppError
Checks err instanceof AppError and reads err.statusCode, err.message, err.errors to build the JSON response. This is the only consumer that reads AppError — everyone else only throws it.
02 · errorHandler.ts

📁 src/middleware/errorHandler.ts

REGISTERED LAST

The single Express error middleware registered last in app.ts. Every unhandled error in the app flows here via next(err). Detects error type in 4 steps and formats a consistent JSON response. It never throws — it only responds.

Receives Errors From

REGISTERED IN → app.ts (LAST middleware) RECEIVES FROM → asyncHandler (via next) auth.ts (via next) authorise.ts (via next) validate.ts (via next)

Code

src/middleware/errorHandler.ts
import { Request, Response, NextFunction } from "express";
import { ZodError }           from "zod";
import { AppError }          from "../errors/AppError";
import { handleMongooseError } from "./handleMongooseError";

const isDev = process.env.NODE_ENV === "development";

export const errorHandler = (
  err: unknown, _req: Request, res: Response, _next: NextFunction
): void => {

  // ── Step 1: Zod validation error → 400 ────────────────────
  if (err instanceof ZodError) {
    res.status(400).json({ success: false, message: "Validation failed", errors: err.flatten().fieldErrors });
    return;
  }

  // ── Step 2: Known AppError → its statusCode ────────────────
  if (err instanceof AppError) {
    res.status(err.statusCode).json({
      success: false, message: err.message,
      ...(err.errors && { errors: err.errors }),
      ...(isDev      && { stack:  err.stack  })   // only in dev
    });
    return;
  }

  // ── Step 3: Mongoose errors (CastError, ValidationError, 11000) ─
  const mongoResult = handleMongooseError(err);
  if (mongoResult) { res.status(mongoResult.statusCode).json(mongoResult.body); return; }

  // ── Step 4: Unknown / programmer bug → 500 ─────────────────
  console.error("[UNHANDLED]", err);
  res.status(500).json({
    success: false,
    message: isDev ? (err instanceof Error ? err.message : "Unknown") : "Internal server error"
  });
};

// ── src/app.ts — registration order ───────────────────────
app.use("/users", userRouter);
app.use(notFound);       // 404 for unknown routes — AFTER all routes
app.use(errorHandler);  // ← MUST be last (4-param signature)

📍 Call Sites

🚀app.tsREGISTERS IT
app.use(errorHandler) — registered as the very last middleware. Express recognises the 4-argument (err, req, res, next) signature and routes all next(err) calls here automatically.
🔄asyncHandler.tsAUTO-FORWARDS
.catch(next) inside asyncHandler forwards any thrown error from controllers or services directly here — no manual try/catch needed.
🔐auth.tsEXPLICIT next(err)
return next(new UnauthorizedError(...)) — explicit forwarding from the middleware. Express skips all remaining handlers and jumps straight to errorHandler.
✅validate.tsZOD ERRORS
return next(zodError) — Zod errors are passed to next() and Step 1 of errorHandler catches them as ZodError instanceof → formats field-level error map → 400.
⚠️ Critical: Express identifies error middleware by exactly 4 parameters. If you remove _next, it silently stops working. Order matters — errorHandler must be the absolute last app.use().
03 · handleMongooseError.ts

📁 src/middleware/handleMongooseError.ts

DB ERROR NORMALISER

Mongoose throws its own error types that don't extend AppError. This helper detects them by class or error code and converts to a plain { statusCode, body } object. Called only by errorHandler. Returns null when the error isn't a Mongoose error.

Called By

CALLED ONLY BY → errorHandler.ts (Step 3 only)

Three Mongoose Errors It Handles

Mongoose ErrorTriggered WhenHTTP Response
MongoServerError 11000Unique index violated (e.g. duplicate email)409 Conflict
ValidationErrorSchema constraint violated (required, min, max)400 Bad Request
CastErrorInvalid ObjectId format in URL param400 Bad Request

Code

src/middleware/handleMongooseError.ts
import mongoose from "mongoose";

interface NormalisedError {
  statusCode: number;
  body: { success: false; message: string; errors?: unknown };
}

export const handleMongooseError = (err: unknown): NormalisedError | null => {

  // Duplicate key — User.create({ email: "taken@mail.com" }) → code 11000
  if (err instanceof Error && "code" in err && (err as any).code === 11000) {
    const field = Object.keys((err as any).keyValue ?? {})[0] ?? "field";
    return { statusCode: 409, body: { success: false, message: `${field} already exists` } };
  }

  // Schema ValidationError — User.create({ age: 5 }) violates min: 18
  if (err instanceof mongoose.Error.ValidationError) {
    const errors = Object.fromEntries(Object.entries(err.errors).map(([k, v]) => [k, v.message]));
    return { statusCode: 400, body: { success: false, message: "Validation failed", errors } };
  }

  // CastError — User.findById("not-a-valid-objectid")
  if (err instanceof mongoose.Error.CastError) {
    return { statusCode: 400, body: { success: false, message: `Invalid ${err.path}: "${err.value}"` } };
  }

  return null;  // not a Mongoose error — fall through to 500
};
04 · asyncHandler.ts

📁 src/utils/asyncHandler.ts

ASYNC WRAPPER

Wraps every async controller function. Without it, a rejected promise silently disappears — Express doesn't catch async errors. .catch(next) forwards the rejection to errorHandler automatically. No try/catch boilerplate needed in any controller.

Used In

IMPORTED BY → user.controller.ts post.controller.ts auth.controller.ts FORWARDS ERRORS TO → errorHandler.ts

Code

src/utils/asyncHandler.ts
import { Request, Response, NextFunction, RequestHandler } from "express";

type AsyncFn = (req: Request, res: Response, next: NextFunction) => Promise<void>;

export const asyncHandler =
  (fn: AsyncFn): RequestHandler =>
  (req, res, next) =>
    fn(req, res, next).catch(next);
//                    ^^^^^^^^^^^
//  This one .catch(next) replaces try/catch in EVERY controller

// ── WITHOUT asyncHandler (bad) ─────────────────────────────
router.get("/:id", async (req, res, next) => {
  try {
    const user = await userService.getUserById(req.params.id);
    res.json(user);
  } catch (err) { next(err); }  // have to remember every time
});

// ── WITH asyncHandler (good) ───────────────────────────────
router.get("/:id", asyncHandler(async (req, res) => {
  const user = await userService.getUserById(req.params.id);
  res.json(user);
  // throws NotFoundError → .catch(next) → errorHandler → 404
}));
🎯 Interview point: Without asyncHandler, unhandled async errors in Express 4 crash silently or hang the request. Express 5 handles it natively, but Express 4 requires this wrapper on every async handler.
05 · auth.ts + authorise.ts

📁 src/middleware/auth.ts · authorise.ts

AUTH MIDDLEWARE

authenticate runs before every protected route. Reads JWT from Authorization: Bearer <token>, verifies it, attaches payload to req.user. authorise checks req.user.role is in the allowed list. Both call next(err) — never respond directly.

src/middleware/auth.ts + authorise.ts
// ── auth.ts — throws UnauthorizedError (401) ──────────────
import jwt from "jsonwebtoken";
import { UnauthorizedError } from "../errors/AppError";

export const authenticate = (req, _res, next) => {
  const token = req.headers.authorization?.split(" ")[1];

  // THROW POINT A — no token
  if (!token) return next(new UnauthorizedError("No token provided"));

  try {
    (req as any).user = jwt.verify(token, process.env.JWT_SECRET!);
    next();
  } catch (err) {
    // THROW POINT B — expired
    if (err instanceof jwt.TokenExpiredError)
      return next(new UnauthorizedError("Token expired"));
    // THROW POINT C — tampered
    return next(new UnauthorizedError("Invalid token"));
  }
};

// ── authorise.ts — throws ForbiddenError (403) ────────────
import { ForbiddenError } from "../errors/AppError";

export const authorise = (...roles: UserRole[]) =>
  (req, _res, next) => {
    const role = (req as any).user?.role;
    // THROW POINT D — wrong role
    if (!roles.includes(role))
      return next(new ForbiddenError(`Role '${role}' cannot access this`));
    next();
  };

src/services/user.service.ts
import { NotFoundError, ConflictError, ForbiddenError, AppError } from "../errors/AppError";

export const userService = {

  createUser: async (dto: CreateUserDTO) => {
    const existing = await User.findOne({ email: dto.email });
    if (existing) throw new ConflictError("email");          // THROW 1 → 409

    const hashed = await bcrypt.hash(dto.password, 12);
    return User.create({ ...dto, password: hashed });
  },

  getUserById: async (id: string) => {
    const user = await User.findById(id);
    if (!user) throw new NotFoundError("User");            // THROW 2 → 404
    return user;
  },

  updateUser: async (id, dto, requesterId) => {
    const user = await User.findById(id);
    if (!user) throw new NotFoundError("User");            // THROW 3 → 404

    if (user._id.toString() !== requesterId)
      throw new ForbiddenError("You can only edit your own profile"); // THROW 4 → 403

    if (dto.role && dto.role !== user.role)
      throw new AppError("You cannot change your own role", 403);  // THROW 5 → 403

    return User.findByIdAndUpdate(id, { $set: dto }, { new: true, runValidators: true });
  },

  deleteUser: async (id: string) => {
    const deleted = await User.findByIdAndDelete(id);
    if (!deleted) throw new NotFoundError("User");         // THROW 6 → 404
  },
};

📍 Call Sites

🎮user.controller.tsCALLS SERVICE
Every method calls a service function inside asyncHandler: e.g. const user = await userService.getUserById(req.params.id). If the service throws, .catch(next) forwards it to errorHandler. The controller never sees the error at all.

📁 src/routes/user.routes.ts

Connects every error-handling piece in the correct order per route. The route layer never throws itself — it just attaches the right middleware chain. Reading this file shows the complete error path for any endpoint at a glance.

Imports / Mounted In

Code

src/routes/user.routes.ts
import { Router } from "express";
import { validate }       from "../middleware/validate";
import { authenticate }   from "../middleware/auth";
import { authorise }      from "../middleware/authorise";
import { userController } from "../controllers/user.controller";
import { createUserSchema, updateUserSchema } from "../validators/user.validator";

const router = Router();

// POST /users — Zod bad body → 400  |  duplicate email → 409
router.post("/",
  validate(createUserSchema),    // 1. Zod check → 400
  userController.create         // 2. service: duplicate → 409
);

// GET /users/:id — no JWT → 401  |  bad ID → 400  |  not found → 404
router.get("/:id",
  authenticate,                  // 1. JWT missing/bad → 401
  userController.getById        // 2. service → 404
);

// PATCH /users/:id — 401 → 403 → 400 → 404/403
router.patch("/:id",
  authenticate,                        // 1. JWT → 401
  authorise("ADMIN", "MANAGER", "USER"), // 2. role → 403
  validate(updateUserSchema),          // 3. Zod → 400
  userController.update               // 4. service → 404/403
);

// DELETE /users/:id — 401 → 403 (ADMIN only) → 404
router.delete("/:id",
  authenticate,          // 1. JWT → 401
  authorise("ADMIN"),    // 2. ADMIN only → 403
  userController.remove // 3. service → 404
);

export { router as userRouter };

📍 Call Sites

🚀app.tsMOUNTS ROUTER
app.use("/users", userRouter) — mounts the router. After all routers: app.use(notFound) then app.use(errorHandler). The order is critical — errorHandler must always be the very last call.
🧠 Remember: Middleware order in Express is sequential. If authenticate calls next(err), Express immediately jumps to errorHandler — skipping authorise, validate, and the controller entirely.
